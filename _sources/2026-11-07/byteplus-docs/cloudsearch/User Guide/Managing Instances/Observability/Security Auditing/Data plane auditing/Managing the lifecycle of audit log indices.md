After data plane auditing is enabled, two parameters are added to the **Parameter management ** page: `AuditOpenDays` controls the number of days during which control plane audit log indices are enabled; `AuditKeepDays` controls the number of days during which control plane audit log indices are retained.

<span id="c0877708"></span>
## Background information

On the **Parameter management** page of the Cloud Search instance, view the settings of `AuditOpenDays` and `AuditKeepDays`.


* AuditOpenDays: the number of days during which an audit log index is enabled. The default value is 7 days.

* AuditKeepDays: the number of days during which an audit log index is retained. The value cannot be smaller than the value of AuditOpenDays. The default value is 30 days.


You can manage the lifecycle of audit log indices by configuring `AuditOpenDays` and `AuditKeepDays`.

On the **Index Management \> Index Policies** page of Kibana, you can view the lifecycle policy for indices. The policy named `recycle_auditlog_policy` is generated by default.

The content of `recycle_auditlog_policy` is as follows:


* The specified index pattern is `.security-auditlog-*`, so this policy applies to all indices that match the index pattern.

* The initial state of an index is **fresh**.

* After 7 days, the index enters the **trash** state in which the index will be disabled.

* After 30 days, the index enters the **delete** state in which the index will be deleted.

```JSON
{
    "policy_id": "recycle_auditlog_policy",
    "description": "recycle auditlog index workflow",
    "last_updated_time": 1700449535942,
    "schema_version": 1,
    "error_notification": null,
    "default_state": "fresh",
    "states": [
        {
            "name": "fresh",
            "actions": [],
            "transitions": [
                {
                    "state_name": "trash",
                    "conditions": {
                        "min_index_age": "7d"
                    }
                }
            ]

}
```

## Precautions

Any modification to the `AuditOpenDays` and `AuditKeepDays` parameters does not trigger an instance restart, and the modification takes effect the next day after 00:00:00 in UTC time.

<span id="1e497c60"></span>
## Procedure


1. On the **Instances** page, click the name of the desired instance.

2. On the left navigation bar of **Instance details** page, select **Instance management \>**  **Parameter management ** tab, and then click **Modify parameters**.

   <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/66bcdf08aaea462ea310c851ed7e676b~tplv-goo7wpa0wc-image.image) </span>

3. Modify the values of `AuditOpenDays` and `AuditKeepDays` as needed, and then click **Submit**.

   <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/e5c6f9aab6534a069f06d602d8be6814~tplv-goo7wpa0wc-image.image) </span>

4. In the dialog box that appears, click **OK**.
