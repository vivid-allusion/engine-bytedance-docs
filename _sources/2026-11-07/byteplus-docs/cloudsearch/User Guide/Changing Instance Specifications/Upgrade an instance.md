When your instance size does not match actual business needs due to increased data volume and traffic, you can dynamically adjust the instance configuration, including node specification, storage type, storage specifications, and number of nodes.

## Precautions

* Only instances in the **Running** (green) status support upgrading. Instances in other states do not support upgrading.

* If upgrading increases the instance specification, it will cause the instance nodes to restart. It is recommended to change the instance configuration during off\-peak business hours.

* If upgrading only changes the storage type, storage capacity, or number of nodes, it will not trigger a node restart. This only changes the instance node configuration and does not affect business.

* Single\-node instance supports upgrading The single\-node instance used for testing is recommended to be upgraded to 3 nodes or more for production use. Increasing the number of nodes in a single\-node instance will trigger an instance restart.

* During the upgrade, enabling coordinating nodes, warm data nodes, and cold data nodes is supported. Restarting nodes will not trigger an instance restart. It only involves instance configuration changes. However, enabling a dedicated master node is not supported during the upgrade process. To enable a dedicated master node, you must add one. For specific instructions, see [Add a dedicated master node](https://docs.byteplus.com/docs/cloudsearch/adding-master-nodes).

## Procedure

1. Log on to the [Cloud Search console](https://console.byteplus.com/es).

2. In the top navigation bar, select the target project and region.

3. On the **Instances** page, click the More button in the target instance’s Actions column, then select **Upgrade**.

4. On the **Upgrade** page, modify the specification configuration of different node types, then click **Confirm order**.

5. If the node specifications change, a prompt will appear. Other changes will not trigger a prompt. After viewing the prompt, click **OK**.

   > **warning**

   * > If the upgrade process involves increasing the instance specifications of the nodes, it will cause the corresponding nodes to restart. We recommend changing instance configurations during off\-peak hours.

   * > If upgrading only changes the storage type, storage capacity, or number of nodes, it will not trigger a node restart. This only changes the instance node configuration and does not affect business.

6. On the **Order details** page, confirm the instance change details, read and check the relevant agreements, then click **Buy now**.

   You can return to the instances page, where the current instance running state shows **Changing**. If the instance status shows **Running**, the upgrade succeeds.
