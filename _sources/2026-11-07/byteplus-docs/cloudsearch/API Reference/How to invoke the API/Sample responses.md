This topic introduces information on API responses for Cloud Search.

<span id="返回结果示例"></span>
## Sample responses

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>



* <div data-tips="true" data-tips-type="tip">An HTTP status code of 200 indicates that the API request was successful.</div>


* <div data-tips="true" data-tips-type="tip">Any non\-200 HTTP status code indicates that the API request failed. Specific error messages are returned in JSON format.</div>


* **Sample success response**

   ```JSON
   {
       "ResponseMetadata": {
           "RequestId": "202310231017313****A60DADB80BE85",
           "Action": "DescribeZones",
           "Version": "2023-01-01",
           "Service": "ESCloud",
           "Region": "ap-southeast-1"
       },
       "Result": {
           "Zones": [
               {
                   "RegionId": "ap-southeast-1",
                   "ZoneId": "ap-southeast-1a",
                   "ZoneName": "ap-southeast-1a",
                   "ZoneStatus": "AVAILABLE"
               }
           ]
       }
   }
   ```
   

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">ResponseMetadata and its internal fields RequestId, Action, Version, Service, and Region are fixed fields. They are always returned as long as an API request is made, regardless of whether the API request is successful or not.   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">RequestId is the unique identifier of the API request. If an API error occurs, you can submit a ticket to contact technical support and provide the request ID for troubleshooting.   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">Result is a fixed field, and the content of this field is defined by different products. This field is not returned if the request fails.   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">Except for the fixed fields, the rest are fields defined by each specific API action. For details of the fields returned by various API actions, refer to the related document for each API action.   </div>
   

* **Sample error response**

   ```JSON
   {
       "ResponseMetadata": {
           "RequestId": "2023102***54A5A338FA49A",
           "Action": "DescribeInstance",
           "Version": "2023-01-01",
           "Service": "ESCloud",
           "Region": "ap-southeast-1",
           "Error": {
               "Code": "0012",
               "Message": "wrong id"
           }
       }
   }
   ```
   


<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">When a request fails, the Error field is returned, containing the Code and Message fields, where:</div>



* <div data-tips="true" data-tips-type="tip">Code indicates the specific error code. You can refer to the list of common error codes and those specific to the current API action to find the corresponding causes and solutions.</div>


* <div data-tips="true" data-tips-type="tip">Message provides the specific cause for the error. The message text may change over time as the service evolves or to improve user experience.</div>



<span id="API幂等"></span>
## API idempotency

When you call API actions to create instances, it is crucial to ensure that retrying a failed request does not create multiple instances, which helps reduce financial loss.

By including a `ClientToken` parameter in the request parameters of the related API action, the uniqueness of the request can be identified. When an error occurs, the same `ClientToken` can be used to authenticate the same business request.

`ClientToken` is a unique, case\-sensitive string of up to 64 ASCII characters generated by the user, such as `123e4567-e89b-12d3-a456-426655440000`. It is valid for 24 hours. If you use the same account to resend a request with the same `ClientToken` within 24 hours to call a specific API action, the system recognizes it as a repeat of the original request to avoid duplicate operations.

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">This feature is available only for create and delete API actions.</div>
