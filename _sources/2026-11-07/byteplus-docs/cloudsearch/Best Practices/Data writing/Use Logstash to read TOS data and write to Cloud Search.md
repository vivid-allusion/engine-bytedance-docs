This topic describes how to use Logstash pipelines to read log data from TOS buckets and write it to Cloud Search indexes.

<span id="2qNPF2uR"></span>
## Background

TOS (Torch Object Storage) is a massive, secure, low\-cost, easy\-to\-use, highly reliable, and highly available distributed cloud storage service provided by BytePlus. Object Storage provides full compatibility with the AWS S3 protocol. For details, see [AWS S3 protocol compatibility description](https://docs.byteplus.com/en/docs/tos/docs-compatibility-with-amazon-s3?lang=en). Therefore, the Logstash S3 plugin can read data from TOS in Logstash.

## Precautions

To ensure network access security, the cloud product services used in this article adopt internal network access methods. Therefore, both the object storage and the Cloud Search service instances must reside within the same Region and the same VPC.

You can create a Virtual Private Cloud before creating cloud resources. For specific procedures, refer to [Creating VPC](https://docs.byteplus.com/en/docs/vpc/Creating-a-VPC) and [Creating subnet](https://docs.byteplus.com/en/docs/vpc/Creating-a-subnet).

<span id="MscIXQiS"></span>
## Step 1: Prepare the object storage bucket

Before writing object storage data into Cloud Search through the Logstash pipeline, you need to complete the following preparations for object storage:


1. Create a bucket. For more information, see [Creating buckets](https://docs.byteplus.com/en/docs/tos/docs-create-a-bucket).

2. Obtain the S3 endpoint of the bucket. For detailed steps, see [Viewing bucket details](https://docs.byteplus.com/en/docs/tos/docs-exporting-bucket-information#93b5a01b).


<span id="YaIhMaKB"></span>
## Step 2: Prepare the data destination Cloud Search index

To consume TLS logs using the Logstash pipeline, you need to prepare a data destination. This article uses the cloud search service index as the destination. Follow these steps to create an instance and obtain its access address.


1. Create a Cloud Search service instance. For more information, see [Create an instance](https://docs.byteplus.com/en/docs/cloudsearch/creating-instance).

2. Obtain the instance's private network address. For detailed operations, see [View instance details](https://docs.byteplus.com/en/docs/cloudsearch/instance-details).

3. (Optional) You can also enable public network access for Kibana, then select the public IPs to bind, allowing Kibana to have public network access to log in and query data in the index via the Kibana web page. If you do not have a public IP available, you can create one in the console. For detailed operations, see [Apply for public IP](https://docs.byteplus.com/en/docs/eip/Applying-for-an-EIP).


<span id="Q8hW0zsk"></span>
## Step 3: Create a Logstash pipeline


1. Create a Logstash instance in the same region and VPC as the Cloud Search service instance in Step 2. For detailed operations, see [Create a Logstash instance](https://docs.byteplus.com/en/docs/cloudsearch/Create_a_Logstash_instance).

2. Create a Logstash pipeline and modify its content as needed. For detailed operations, see [Create a pipeline](https://docs.byteplus.com/en/docs/cloudsearch/Create_a_pipeline). Example configuration is as follows.

   ```Ruby
   input {
     s3 {
       "access_key_id" => "**"
       "secret_access_key" => "**"
       "endpoint" => "https://tos-s3-cn-beijing.volces.com"
       "bucket" => "**"
       additional_settings => {
         "ssl_verify_peer" => false
       }
       codec => "json"
     }
   }
   filter {
     # Delete original JSON fields automatically generated by S3 input
     mutate {
       remove_field => ["event"]
     }
   }
   output {
     opensearch {
      # Target instance access address
       hosts => "https://opensearch-o-**.escloud.ivolces.com:9200"
       # Target instance basicAuth authentication info, if available
       user => "admin"
       password => "**"
       # Name of the index to write to
       index => "tos_test"
       # Whether to request using only https links in the `hosts` configuration array
       ssl => false
       ssl_certificate_verification => false
     }
   }
   ```
   

   <div data-tips="true" data-tips-type="default" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   * <div data-tips="true" data-tips-type="default" data-wrapper-indent="1"><code>access_key_id</code> and <code>secret_access_key</code> are obtained referring to <a href="https://docs.byteplus.com/en/docs/IAM/about-access-keys">API keys (Access Key and API Key)</a>.   </div>
   

   * <div data-tips="true" data-tips-type="default" data-wrapper-indent="1">Fill in <code>bucket</code> and <code>endpoint</code> with the bucket name and endpoint created in step 1.   </div>
   

   * <div data-tips="true" data-tips-type="default" data-wrapper-indent="1">In <code>additional_settings</code>, <code>ssl_verify_peer</code> can be used to skip certificate verification for HTTPS access.   </div>
   

   * <div data-tips="true" data-tips-type="default" data-wrapper-indent="1"><code>input.s3.codec</code> and <code>filter</code> are examples only and should be modified according to the actual data format.   </div>
   

   * <div data-tips="true" data-tips-type="default" data-wrapper-indent="1"><code>sincedb_path</code> defaults to <code>/logstash-data/system/plugins/inputs/s3/sincedb_*</code>, which is the persistence path ensuring data is retained after instance restarts. Keep the default unless special requirements arise.   </div>
   

3. (Optional) To debug data format and content, configure the Logstash pipeline as follows. For detailed steps, see [Using debugging functions](https://docs.byteplus.com/en/docs/cloudsearch/Use_the_debugging_feature).


```Ruby
input {
  s3 {
    "access_key_id" => "**"
    "secret_access_key" => "**"
    "endpoint" => "https://tos-s3-cn-beijing.volces.com"
    "bucket" => "**"
    additional_settings => {
      "ssl_verify_peer" => false
    }
    codec => "json"
  }
}
filter {
  ruby {
    code => '
      require "time"
      require "json"
      local_time = Time.now.getlocal.strftime("%Y-%m-%dT%H:%M:%S.%3N")
      event.set("rfc3339_local", local_time) # rfc3339_local 是字段名
      event.set("message", event.to_hash.to_json)
    '
  }
}
output {
    file {
        path => "/logstash-logs/user-debug.log"
        codec => line {
            format => "[%{rfc3339_local}] %{message}"
        }
    }
}
```

## Verify results

After the consumer task runs normally, log in to the Kibana web page to check if the object storage data is written in the example index **tos_test**. This topic explains how to log on to [Kibana/Dashboards](https://docs.byteplus.com/en/docs/cloudsearch/logging-tool).

On the left sidebar of the Kibana web page, select **Dev Tools**, then in the code area to the left of **Console**, enter `GET /tos_test/_search` and click the execute button.
