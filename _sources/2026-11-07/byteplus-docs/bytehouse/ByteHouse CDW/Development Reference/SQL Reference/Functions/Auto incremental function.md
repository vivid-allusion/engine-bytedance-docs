ByteHouse CDW provides the auto\-increment ID function `generateSnowflakeID`, which achieves the auto\-increment ID effect similar to the `auto_increment` function in MySQL dialect systems. If the data source cannot provide an ID or requires direct writing scenarios, ByteHouse recommends using the `generateSnowflakeID` function. This article introduces the implementation logic and usage of the auto\-increment function.

<span id="01f98104"></span>
# Implementation Logic

Under ByteHouse's ClickHouse dialect system, the `generateSnowflakeID` function offers a self\-increasing, unique ID based on SnowflakeID (not guaranteed to be continuous and compact).

In ByteHouse CDW’s ClickHouse dialect system, the `generateSnowflakeID` function uses SnowflakeID to provide auto\-incremented, unique IDs (not guaranteed to be continuous or compact).

In the MySQL dialect system, ByteHouse CDW ignores the `auto_increment` keyword by default. You can enable it manually by setting `set enable_auto_increment=1`. After enabling, the system rewrites `auto_increment` as `generateSnowflakeID()` in the DDL. You can also manually change the column’s function to `generateSnowflakeID()`. For detailed usage, refer to the following [Usage Method](https://docs.byteplus.com/docs/bytehouse/auto-incremental-function#75512c75).

<div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div>



* <div data-tips="true" data-tips-type="warning">In the MySQL dialect system, <code>auto_increment</code> is rewritten as <code>generateSnowflakeID</code>. The auto\-increment ID does not start from 1, 2, 3, etc., but only guarantees incrementality.</div>


* <div data-tips="true" data-tips-type="warning">In the ClickHouse dialect system, the sequence generated by <code>generateSnowflakeID</code> ensures it is increasing and unique, but does not guarantee sequential growth.</div>



The structure of SnowflakeID is a 64\-bit binary number (actually using 63 bits to accommodate signed integers), composed as follows:


* The head 41 digits represent the timestamp, measured in ms, starting from a specified epoch.

* The following 10 digits represent the machine ID to avoid conflicts.

* The next 12 digits represent the sequence number of each machine, allowing multiple Snowflake IDs to be generated within the same millisecond.

* Ultimately, this number is usually serialized in decimal form.


SnowflakeID is order by time, as it is based on the time of generation. Furthermore, the generation time can be extracted from SnowflakeID, used for obtaining SnowflakeIDs (and their associated objects) created before or after a specific date.

# Usage Method


* Command Format

   ```SQL
   generateSnowflakeID();
   ```
   

* Command Description

   According to the logic mentioned above, it returns a string of decimal\-serialized self\-increasing ID data.

* Example

   * Search

      ```SQL
      SELECT generateSnowflakeID();
      ```
      

   * Create Table

      * ClickHouse Dialect System:

         ```SQL
         set dialect_type='CLICKHOUSE';
         CREATE TABLE t1(id Int64 DEFAULT generateSnowflakeID(), val1 String) 
         Engine=CnchMergeTree() Order by id;
         ```
