DataFinder provides you with page access\-related preset events and preset properties, including page referrer\-related properties (referer_type \- source type, referer_site_name \- source website name), whose attribute values are further processed according to the collected access page URL. This article describes the processing logic of the DataFinder for related properties.

<span id="736e1ff2"></span>
# Logic description

The values of referer_type and referer_site_name are determined by the values of the `referrer`and `url`attributes.

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip"><code>The referrer</code>is a URL that consists of three main parts: <code>protocol://host [: port]/path</code>. The host is generated by parsing the string into a java.net . URL object and calling the getHost () method.</div>



|Scenario judge |referer_type value |referer_site_name value |
|---|---|---|
|`The url`and `referrer`host are the same |**inner** |Do not build referer_site_name |
|When parsing the `referrer`field, the protocol is invalid (parsing to a java.net . URL object failed), or the host is empty |**direct** |Constructed as: "" |
|`The referrer`parsed host (without `the www.`prefix) is in the following table |Fixed enumeration values:<br><br><br>* **search_engine**<br><br>* **social_network**<br><br>* **referring_site**<br><br><br>Details are shown in the table below |Fixed value, as shown in the table below |
|Other scenarios |**referring_site** |The parsed value assigned to host |
