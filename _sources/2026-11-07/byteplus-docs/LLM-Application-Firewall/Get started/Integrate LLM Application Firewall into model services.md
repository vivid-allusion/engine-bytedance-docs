If your business uses specific model services, the LLM Application Firewall can redirect business traffic to a protection access point for inspection and protection based on information such as the model service domain name and protection path. This helps address issues faced by large model applications, including malicious attacks, sensitive data leakage, and compute resource abuse, ensuring secure and stable business operations. This article describes the specific steps for integrating model services with the LLM Application Firewall.

<span id="d53372d7"></span>
## Background information

After integrating the LLM Application Firewall, the business traffic handling process is as follows:


* Request phase: Client\-initiated business requests first undergo a security check by the LLM Application Firewall. Only after passing the check are they forwarded to the model server for processing.

* Response phase: The response content generated by the server must also undergo a security check by the LLM Application Firewall and will only be returned to the client after the check is complete.


<span id="c13ba8e8"></span>
## Prerequisites


* Your business has already integrated with the relevant model service platform.

* You have created a protection instance. For related operations, please refer to [Create an LLM Application Firewall instance](https://docs.byteplus.com/docs/LLM-Application-Firewall/create_an_LLM_Application_Firewall_instance).


<span id="81bd0c98"></span>
## Important note

The API Key must follow the `Authorization: Bearer <API Key>` format; otherwise, authentication will fail and traffic will not pass through.

<span id="e0de49fc"></span>
## Step 1: Obtain the model service domain name and API Key


* **Machine learning platform**: You need to obtain the model service domain name. The service domain name is the public access address of the service you have deployed on the BytePlus Machine Learning Platform. In a public network environment, you can use this address to call the service. For details, refer to [Obtain the model service domain name and API Key](https://docs.byteplus.com/docs/LLM-Application-Firewall/Obtain_the_model_service_domain_name_and_API_Key).

* **Ark platform**: The API Key for your Ark application is required. The API Key serves as your credential for requesting the BytePlus Ark service. Therefore, you must first obtain the API Key for the model service, and then provide it to the LLM Application Firewall service to enable interaction between your business and the LLM Application Firewall. For details, refer to [Obtain the model service domain name and API Key](https://docs.byteplus.com/docs/LLM-Application-Firewall/Obtain_the_model_service_domain_name_and_API_Key).

* **Other model services**: You need to obtain the API Key and the domain name for the model service. For details, please refer to the relevant documentation related to specific model services.


<span id="5097edb4"></span>
## Step 2: Configure access parameters

After obtaining the relevant service domain name and API Key, you can simply configure your settings to protect your business with the LLM Application Firewall.


1. Log in to the [LLM Application Firewall console](https://console.byteplus.com/omni-shield/llm-shield/).

2. In the top bar, select the region of the instance.

3. In the left navigation, select **Asset management**, then click **Add asset**.

4. Select **Model service integration** as the access method, and configure application information, model parameters, and origin server configuration.

   For detailed configuration, see [Configure model integration parameters](https://docs.byteplus.com/docs/LLM-Application-Firewall/Configure_model_integration_parameters).

   <span>![图片](https://p9-arcosite.byteimg.com/obj/tos-cn-i-goo7wpa0wc/1a59f195cc7c4916b2b5e84948d9463e) </span>

5. Click **Next**.


<span id="b60d6856"></span>
## Step 3: Configure protection policy

After configuring the access parameters, you can directly set a protection policy for the current asset. The platform displays the default configuration of the protection policy, and the configuration is enabled.


* If no changes are required, you can submit the current configuration directly to complete the configuration in the console.

* To make changes, you can adjust the relevant settings directly on the current page. Your changes are saved as the default configuration for future integrations.


Refer to [Introduction to protection policies](https://docs.byteplus.com/docs/LLM-Application-Firewall/introduction_to_protection_policy) for the detailed introduction and configuration instructions.

<span id="7d07c93b"></span>
## Step 4: Replace model access path

Replace the original model access domain name with the protection domain name provided by the LLM Application Firewall, and redirect access traffic to the LLM Application Firewall for protection. For reference, see the method for replacing the Ark Service access path: [What to do next](https://docs.byteplus.com/docs/LLM-Application-Firewall/Configure_model_integration_parameters#48e7c8db).

<span id="200220ec"></span>
## What to do next


* **View protection data**: You can view security protection data on the **homepage**, including the number of requests, number of protection events, as well as the corresponding request trend chart, and attack distribution chart. For more information, see [View the security overview](https://docs.byteplus.com/docs/LLM-Application-Firewall/View_the_security_overview).

* **Analyze attack events**: If a request or response matches a protection rule, the LLM Application Firewall generates corresponding log entries in the **Attack details** list to facilitate tracing and analyzing attack events. You can adjust or add protection rules based on attack event details and protection data to make the detection results of the LLM Application Firewall better align with your business scenario. For example, requests that match non\-high\-risk detection categories are only monitored and not directly blocked, in order to avoid false positives. For more information, see [View details of attack events](https://docs.byteplus.com/docs/LLM-Application-Firewall/View_details_of_attack_events).
