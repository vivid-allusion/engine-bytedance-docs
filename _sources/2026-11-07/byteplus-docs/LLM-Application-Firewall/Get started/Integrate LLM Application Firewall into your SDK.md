You can quickly integrate the service into your application via the SDK, without changing the deployment structure of the large model application, to enable content validation, optimized response generation, and other functions. This article describes the steps to integrate the LLM Application Firewall service into your business SDK to achieve model security.

<span id="d2c52a2f"></span>
## Background information

The SDK integration method is flexible and straightforward, requiring no changes to your application's deployment structure. After integration, traffic from your client still accesses your origin server directly. You can directly call SDK interfaces in the business system to obtain detection results or responses from the large model's protection policy, and then process them as needed based on business requirements. For example, intercepting content that matches the prompt injection protection policy, or responding to the user with the optimized answers.

<span id="51c3dd4c"></span>
## Applicable scenarios


* Monitor the content of user\-entered prompts in real time to identify potential attack risks or sensitive information that violates regulations.

* Review the responses generated by the large model, promptly identify and block non\-compliant sensitive information, and prevent misuse of the model or leakage of sensitive information.

* Optimize the model's response content to address potential risks and ensure that the output is legal and compliant.


<span id="04837189"></span>
## Prerequisites

You have created an LLM Application Firewall. For more details, see [Create an LLM Application Firewall instance](https://docs.byteplus.com/docs/LLM-Application-Firewall/create_an_LLM_Application_Firewall_instance).

<span id="cf57b0a3"></span>
## Important note

Before invoking the SDK on the server side, you need to obtain the asset's AppID in the console and complete the relevant policy configuration. The large model will return the corresponding detection results based on the AppID and the configured policy content.

<span id="afe56657"></span>
## Step 1: Create an application

You need to enter the basic information of the application in the LLM Application Firewall console to distinguish between different application assets.


1. Log in to the [LLM Application Firewall console](https://console.byteplus.com/omni-shield/llm-shield/).

2. Select the region of the instance in the top bar.

3. Select **Asset management** in the left navigation, and then click **Add assets**.

4. Select **SDK integration** as the integration method, and enter the basic application information, including the application name and description.

## Step 2: Configure protection policy

After completing the basic application information, you can set a protection policy for the current application. The platform displays the default protection policy, which is enabled by default.


* To proceed without changing the default policy, submit the current configuration directly.

* To make modifications, directly adjust the relevant configuration on the current page. Your modified and confirmed settings will become the default for future integrations.


Refer to [Introduction to protection policies](https://docs.byteplus.com/docs/LLM-Application-Firewall/introduction_to_protection_policy) for a detailed introduction and configuration instructions of the corresponding policy.

<span id="a18e6937"></span>
## Step 3: Download and integrate the SDK

Integrate the SDK into your large model application. According to the SDK documentation, call the service interface to obtain the detection results for the corresponding content.


1. Refer to [SDK overview](https://docs.byteplus.com/docs/LLM-Application-Firewall/SDK_overview) to download the SDK file for the corresponding language from the download address.

2. Refer to the documentation in [SDK overview](https://docs.byteplus.com/docs/LLM-Application-Firewall/SDK_overview) to integrate the SDK into large model applications.

3. Call the SDK to obtain the result returned by the corresponding interface. For detailed information about relevant interfaces, see:

   * [Check whether input or output content is compliant](https://docs.byteplus.com/docs/LLM-Application-Firewall/Check_whether_input_or_output_content_is_compliant)

   * [Generate content for secure responses](https://docs.byteplus.com/docs/LLM-Application-Firewall/Generate_content_for_optimized_answers)

## What to do next


* View protection details: On the homepage, you can view security protection data, including the number of requests and the number of protection events. You can also see the corresponding request trend chart and attack distribution chart. For more information, see .

* **Analyze attack events**: When a request or response matches a protection rule, the LLM Application Firewall generates a corresponding log entry in the **Attack log** list, making it easier for you to trace and analyze attack events. You can adjust or add protection rules based on attack event details and protection data to make the detection results of the LLM Application Firewall better align with your business scenario. For example, request content that matches non\-high\-risk detection categories is only monitored and not directly blocked, to avoid false positives. For more information, see [View details of attack events](https://docs.byteplus.com/docs/LLM-Application-Firewall/View_details_of_attack_events).
