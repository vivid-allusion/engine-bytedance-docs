Before using the LLM Application Firewall to protect your assets, you must first integrate your service with the platform's protection instance. Three integration methods are supported: SDK integration, traffic integration, and model service integration. You can select the most suitable one based on your existing business requirements.

The following table compares the integration methods, detailing how they work, their use cases, and their limitations.


|**Integration methods** |**SDK integration** |**Traffic integration** |**Model service integration** |
|---|---|---|---|
|How to integrate |Integrate the SDK on the server side and read data by specifying fields and using the OpenAPI interface. Business traffic flows directly from the client to the origin server. After the server calls the SDK, it uses the returned result to determine the next action. |Point the domain's DNS resolution to the CNAME address of the protection instance to redirect the domain's web traffic to the platform. The platform will block attack requests and forward normal business requests back to the origin server. |Replace the original business access domain name with the LLM Application Firewall access point domain name. After traffic is inspected by the LLM Application Firewall, it is returned to the origin server, ensuring model security and uninterrupted service. |
|Applicable scenarios |SDK integration does not restrict the origin server's deployment location. |The deployment location of the origin server is not restricted. |The service is deployed on the Ark Platform, Machine Learning Platform, or other model service platforms |
|Prerequisites |* An LLM Application Firewall instance has been created.<br><br>* The domain to be protected has been registered. |* An LLM Application Firewall instance has been created.<br><br>* The domain to be protected has been registered. |* An LLM Application Firewall instance has been created.<br><br>* Your service has been deployed on the model platform. |
|Important notes |Integrate the access point domain name generated by the platform into the SDK. |After domain integration, you need to allowlist the origin IP address range and update DNS records. |* Ark Platform: For the Ark Platform, replace the entire `base_url` value with the provided endpoint, which has the format `a00d4f9ab2dbc92d564ed6644cdb*****.com/api/v3`.<br><br>* Machine Learning Platform: When integrating, make sure to enter the model service domain name in the appropriate format. For example, if you copied `https://scv8****.com/mlp/s-20250311190045-rbjcf/` from the MLP console, enter`scv8****.com`. |
