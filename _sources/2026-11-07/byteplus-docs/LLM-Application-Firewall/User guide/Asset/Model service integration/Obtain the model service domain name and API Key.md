To integrate your model service with the LLM Application Firewall, you must provide the service domain name and API Key for authentication. This guide provides instructions on how to obtain the API Key from ModelArk and the service domain name from the Machine Learning Platform (MLP), enabling the firewall to protect your business traffic.

<span id="2628f811"></span>
## Prerequisites


* Integrate via ModelArk platform: Your business has already been integrated with the ModelArk platform. For related operations, see [ModelArk Quick Start](https://docs.byteplus.com/en/docs/ModelArk/1399008).

* Integration via MLP: Your service has already been deployed on the machine learning platform and public network access is enabled. For related operations, see [MLP Quick Start](https://docs.byteplus.com/en/docs/mlp/Quick_Access_Guide_Enterprise_Edition).

* Integrate via other model services: Your business has already been integrated into the corresponding model service platform.


<span id="40025b62"></span>
##  Important note

The API Key must follow the `Authorization: Bearer <API Key>` format; otherwise, authentication will fail and traffic will not be allowed through.

<span id="a0f3291d"></span>
## Obtain an API key for ModelArk

The API Key is the credential for requesting the ModelArk service. Therefore, you must first obtain the API Key from the Ark service and then provide it to the LLM Application Firewall service to enable interaction between your business and the LLM Application Firewall.


1. Log in to [API Key Management](https://console.byteplus.com/ark/region:ark-stg+ap-southeast-1/apiKey?apikey=%7B%7D) of ModelArk Console.

2. In the API Key list, select an API Key that has the required permissions, and click the view icon to the right of the API Key.

3. Copy API key.

   You will use this API Key later when configuring the LLM Application Firewall to communicate with your application.


<span id="f35eef19"></span>
## Get the domain name of MLP

The service domain name is the public network access address for the service deployed on the machine learning platform. In a public network environment, you can use this address to invoke the service.


1. Log in to the Machine Learning Platform console.

2. In the top bar, select the instance's region.

3. In the left navigation bar, select **Model Services \> Inference Services**.

4. Select the deployed service from the service list, and click **Invoke service**.

5. Copy the public network access address and the request path in the sample code.

   You will use this access address and request path to configure the LLM Application Firewall, ensuring it can correctly communicate with your MLP service.

## What to do next


* **Modify access domain name**: Replace the model's access domain name with the protected domain name generated by the LLM Application Firewall, so that when accessing the model service, traffic is forwarded to the LLM Application Firewall for protection.

* **View protection details**: You can view security protection data on the **homepage**, including the number of requests, the number of protection events, as well as the corresponding request trend chart and attack distribution chart. For more information, see[View the security overview](https://docs.byteplus.com/docs/LLM-Application-Firewall/View_the_security_overview).

* **Analyze attack events**: When a request or response triggers a protection rule, the LLM Application Firewall generates a corresponding log entry in the **attack details** list to facilitate tracing and analysis of attack events. You can adjust or add protection rules based on attack event details and protection data, so that the LLM Application Firewall's detection results are better tailored to your business needs. For example, request content that matches non\-high\-risk detection categories is only observed and not directly blocked, in order to prevent false positives. For more information, see[View details of attack events](https://docs.byteplus.com/docs/LLM-Application-Firewall/View_details_of_attack_events).
