## What is XID?

XID, referred to as "X Error ID," is an error code generated by a NVIDIA driver to identify errors that occur during GPU operations. XIDs are typically related to errors in GPU hardware or driver, such as memory errors, power problems, or overheating.

<span id="zD5h9cUU"></span>
## Issue description

When a GPU error is detected, an XID is generated and recorded in the log of the operating system kernel or event log. A sample XID information is shown below:

```Bash
<GpuIds>;<TS>;<Xid>;MSG=An nvidia xid 13 error has occurred.
```



* `<GpuIds>`: GPU device identifier.

* `<TS>`: The time when the error event occurs.

* `<Xid>`: XID error code.

* `MSG`: XID error description.

### View XID information


1. [Log in to the instance](https://docs.byteplus.com/en/docs/ecs/Overview-1).

2. Execute the following commands.

   ```Bash
   cat /var/log/messages | grep "Xid (PCI"
   cat /var/log/kern.log | grep "Xid (PCI"
   ```

## Common XID handling methods


|**XID error code** |**Description** |**Whether a fault event exists** |**Handling suggestions** |
|---|---|---|---|
|13 |* This event can be used to record common faults in user applications. The event trigger is typically an out\-of\-bounds program access (Graphics Engine Exception), but may also be an illegal instruction, an illegal register access, or other exceptions.<br><br>* In rare cases, hardware faults or system software errors may also cause XID 13.<br><br><br> |No<br><br> |* If XID 31 occurs only once, we recommend restarting the application to restore normal operation.<br><br>* If this error repeatedly occurs on a specific node while other nodes operate normally, we recommend collecting the relevant bug report and [submitting a ticket](https://console.byteplus.com/ticket/createTicketV2/) for further troubleshooting.<br><br><br> |
|31 |* When an application unit on the chip triggers an MMU error (GPU memory page fault) due to illegal address access or other actions, this event is recorded in the system.<br><br>* An error of this type is typically caused by defects at the application layer, and may also be caused by driver faults or hardware issues. |No<br><br> |* If XID 31 occurs only once, we recommend restarting the application to restore normal operation.<br><br>* If this error repeatedly occurs on a specific node while other nodes operate normally, we recommend collecting the relevant bug report and [submitting a ticket](https://console.byteplus.com/ticket/createTicketV2/) for further troubleshooting and handling. |
|43 |* This event is recorded when the user application triggers a software fault and must be terminated (GPU stopped processing). At this time, the GPU still runs normally.<br><br>* In most cases, this event is not caused by a program defect but by a user application error. |No |No action is required |
|45 |* This event is triggered when the user application is terminated and the kernel driver clears the corresponding application processes on the GPU. This event can be generated when an application is terminated due to the following scenarios: the user presses Control\-C, a GPU reset is performed, the application process receives a SIGKILL signal, or other triggers.<br><br>* In most cases, this event is not caused by a program defect but by user actions or system operations. |No |No action is required |
|48 |When the GPU detects an uncorrectable ECC error (DBE, Double Bit ECC Error), this event is recorded and reported to the application. |No |* If XID 48 occurs only once, we recommend restarting the GPU instance to restore normal operation.<br><br>* If this error repeatedly occurs on a specific node while other nodes operate normally, we recommend collecting the relevant bug report and [submitting a ticket](https://console.byteplus.com/ticket/createTicketV2/) for further troubleshooting. |
|63 |When an application triggers a GPU memory error, the self\-correction mechanism of NVIDIA performs page retirement (Retire) or row remapping (Remap) operations on the faulty memory region. Since the configuration information for Retire and Remap must be written to infoROM to take permanent effect, this event (ECC page retirement or row remapping recording event) indicates that the Retire or Remap information for the faulty region is successfully recorded in infoROM. |No |No action is required |
|64 |The trigger of XID 64 is similar to that of XID 63. XID 63 indicates Retirement and Remapped information was successfully recorded in InfoROM, while XID 64 indicates the recording operation failed (ECC page retirement or row remapper recording failure). |No |Restart the GPU instance to recover. |
|74 |* When the GPU detects a connection issue via NVLink with another GPU or NVSwitch (Fatal NVLINK Error), the event is recorded in the system.<br><br>* This event may indicate a hardware fault in the link itself or an issue with a remote device on it.<br><br><br> |Yes |* This XID error has been determined to be caused by a hardware failure. Cloud Monitor can automatically detect and handle such errors. Upon receiving user authorization, automatic cold migration can be performed to complete the recovery for the event.<br><br>* If the faulty machine does not have the Cloud Monitor service installed or enabled, [submit a ticket](https://console.byteplus.com/ticket/createTicketV2/) for solutions.<br><br><br> |
|79 |This indicates the GPU\-related hardware has fallen off the bus and can no longer be detected. If you receive this event (GPU has fallen off the bus), a serious GPU\-related hardware fault has occurred, which requires offline repair. |Yes |* This XID error has been determined to be caused by a hardware failure. Cloud Monitor can automatically detect and handle such errors. Upon receiving user authorization, automatic cold migration can be performed to complete the recovery for the event.<br><br>* If the faulty machine does not have the Cloud Monitor service installed or enabled, [submit a ticket](https://console.byteplus.com/ticket/createTicketV2/) for solutions. |
|94<br><br> |* When an application triggers an uncorrectable ECC error in GPU memory, the NVIDIA error containment mechanism suppresses the error within the affected application and prevents it from impacting other applications on the GPU.<br><br>* When the containment mechanism successfully suppresses the error, an XID 94 event is generated. This indicates only the application that triggered the uncorrectable ECC error (Contained ECC error) is affected. |No |* If XID 94 occurs only once, we recommend restarting the application to restore normal operation.<br><br>* If this error repeatedly occurs on a specific node while other nodes operate normally, we recommend collecting the relevant bug report and [submitting a ticket](https://console.byteplus.com/ticket/createTicketV2/) for further troubleshooting. |
|95<br><br> |This is the same event type as XID 94, indicating a suppression failure. At this point, all applications running on the affected GPU are impacted. The affected GPU must be reset to restart applications (Uncontained ECC error). |No |* If XID 95 occurs only once, we recommend restarting the GPU instance to restore normal operation.<br><br>* If this error repeatedly occurs on a specific node while other nodes operate normally, we recommend collecting the relevant bug report and [submitting a ticket](https://console.byteplus.com/ticket/createTicketV2/) for further troubleshooting. |
|109 |* The Xid 109 error is defined as a GPU context switch timeout. It indicates that an exception alert is triggered when the context switch between different GPU tasks takes longer than the predefined threshold at the driver or hardware level.<br><br>* When this error occurs, it may lead to application crashes, GPU driver auto\-resets, or other exceptions. In severe cases, it can interrupt ongoing compute or rendering tasks. Assess the actual impact of the error on your applications (for example, whether it caused task interruption, and what the scope of service availability impact is). Then, implement targeted troubleshooting solutions. |No |* If an Xid 109 error occurs only once and does not affect the operation of your application processes, no specific action is required. Simply continue monitoring the running status.<br><br>* If the Xid 109 error coincides with critical exceptions such as application crashes or startup failures, restart the GPU instance to restore normal operation.<br><br>* If this error repeatedly occurs on a specific node while other nodes operate normally, we recommend collecting the relevant bug report and [submitting a ticket](https://console.byteplus.com/ticket/createTicketV2/) for further troubleshooting. |
|119 |A timeout occurs while waiting for the GSP core to respond to the RPC request (GSP RPC Timeout). |No |* If XID 119 occurs only once, we recommend restarting the GPU instance to restore normal operation.<br><br>* If this error repeatedly occurs on a specific node while other nodes operate normally, we recommend collecting the relevant bug report and [submitting a ticket](https://console.byteplus.com/ticket/createTicketV2/) for further troubleshooting. |
|120 |An error occurred during code execution of the GSP core of the GPU (GSP Error). |No |* If XID 120 occurs only once, we recommend restarting the GPU instance to restore normal operation.<br><br>* If this error repeatedly occurs on a specific node while other nodes operate normally, we recommend collecting the relevant bug report and [submitting a ticket](https://console.byteplus.com/ticket/createTicketV2/) for further troubleshooting. |
|140 |This event (Unrecovered ECC Error) may occur when the GPU driver detects an uncorrectable error in GPU memory that prevents it from marking pages for dynamic page retirement or row remapping.<br><br> |No |* If XID 140 occurs only once, we recommend restarting the GPU instance to restore normal operation.<br><br>* If this error repeatedly occurs on a specific node while other nodes operate normally, we recommend collecting the relevant bug report and [submitting a ticket](https://console.byteplus.com/ticket/createTicketV2/) for further troubleshooting. |

## Other XID handling methods

When an atypical XID error occurs, we recommend first referring to [Xid Error](https://docs.nvidia.com/deploy/xid-errors/index.html) documentation on the official NVIDIA website for troubleshooting. If the issue is not solved, collect the bug\-report file and then [submit a ticket](https://console.byteplus.com/ticket/createTicketV2/) for feedback.
