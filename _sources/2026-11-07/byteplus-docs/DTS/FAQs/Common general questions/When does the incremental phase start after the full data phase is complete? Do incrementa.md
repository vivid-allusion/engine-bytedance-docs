Incremental data migration tasks do not stop automatically. After verifying all data has been migrated to the target database, you can manually terminate the migration task. For termination methods, refer to [Terminating a migration task](https://docs.byteplus.com/en/docs/DTS/terminating_a_migration_task).


* ## **Is there a delay when transitioning from the full data phase to the incremental phase?**  <span id="OmgG4Tbp"></span>

   Completing the full data phase does not mean zero delay. Whether delay exists depends on the volume of new data generated by the source end during the full data phase. The specific reasons are as follows:

   DTS captures the source end’s incremental logs (Binlog/Redo Log, etc.) continuously while executing the full data phase.

   * **Ideal scenario:**  if the full data execution is fast and source end writes are minimal, the incremental data backlog at the end of the full phase is small, allowing the task to quickly catch up with minimal delay.

   * **Common scenarios:**  if the elapsed time of the full data is long or the write pressure on the source end is high, a large backlog of incremental data will remain to be processed when the full data stage ends. Although the task has entered the incremental stage, it needs to catch up with this backlog of historical data first, which results in some delay.

   * Influencing factors: the length of delay is affected by multiple factors:

      * The data scale and elapsed time of the full data stage.

      * The write pressure (QPS/TPS) of the source end business.

      * The link specifications and network conditions.

      * The write performance of the destination.

* ## Why does the incremental migration or synchronization task continue to show in progress and not end automatically? <span id="auSsPmTr"></span>

   This is the normal design mechanism of DTS. The essence of incremental migration or synchronization is real\-time synchronization; as long as the source end has data changes, the task keeps running. DTS tasks consist of two distinct stages:

   * Full amount stage (migrating existing data): The goal is to migrate historical data; once completed, it automatically ends.

   * Incremental stage (tracking real\-time): The goal is to continuously track newly added changes from the source end (`Insert`, `Update`, `Delete`). As long as the source database runs and generates new data, DTS must keep running to synchronize these changes.

   Therefore, continuous operation means the task is working normally, not stuck or abnormal. When is manual stopping of incremental migration or synchronization tasks needed?

   The system does not automatically determine when the business ends; you must manually operate based on your business scenario:

   * The business has completed cutover: Confirm that all traffic has fully switched to the new database, and rollback or bidirectional synchronization is no longer needed.

   * No longer need synchronization: the temporary synchronization task has ended, or the source database is about to go offline.

   At this time, you can manually release or stop the DTS task to save resources.
