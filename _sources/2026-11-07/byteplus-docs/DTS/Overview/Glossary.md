This topic describes the related terms in Database Transmission Service (DTS).


|Term |Description |
|---|---|
|Pre\-check |DTS provides the pre\-check feature to ensure the smooth operation of data migration, synchronization, or subscription tasks. You need to execute a pre\-check before starting a task. After fixing the corresponding issues based on the pre\-check prompts, start the migration, synchronization, or subscription task. For details about the pre\-check, refer to [Pre-check items](https://docs.byteplus.com/en/docs/DTS/consumption_checkpoint_items_mysql). |
|Schema migration or synchronization |DTS splits the schema definitions of objects to be migrated or synchronized from the source database. It first migrates or synchronizes the schema of objects (e.g., tables) that are essential for data migration or synchronization to the target database. After the data migration or synchronization is completed, the schema of the remaining objects (e.g., stored procedures) is then migrated or synchronized to the target database. |
|Full migration or synchronization |Migrate or synchronize the existing data from the source database to the target database, up to the point when the migration or synchronization task is initiated. |
|Incremental migration or synchronization |DTS captures the incremental data generated in the source database and synchronizes it to the target database in real\-time. Before you manually end the migration task, the real\-time synchronization of incremental data is maintained. For how to manually end the task, refer to [Ending the migration task](https://docs.byteplus.com/en/docs/DTS/terminating_a_migration_task).<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><br>* <div data-tips="true" data-tips-type="tip">If <strong>Incremental migration</strong> is not selected when you configure the migration task, only the existing data is migrated. If non\-static data exists in the source database, data consistency cannot be guaranteed.</div><br><br><br>* <div data-tips="true" data-tips-type="tip">If <strong>Incremental migration</strong> is selected when you configure the migration task, the data generated during migration will be recorded. After the full migration of the data is complete, the data will be gradually replayed according to the transaction completion time to ensure data consistency.</div><br><br><br>* <div data-tips="true" data-tips-type="tip">When you configure a synchronization task, the system selects <strong>IncrementalI synchronization</strong> by default. Therefore, you do not need to select it. After the pre\-check is completed, DTS initializes the full data of the objects to be synchronized from the source database into the target database, serving as the foundation for subsequent incremental data synchronization.</div><br> |
|User migration |Migrates specified non\-system accounts and their associated permissions from the source database to the target database. You can also modify the passwords of migrated accounts based on your business needs. If no modification is made, the account passwords in the target database will remain consistent with those in the source database.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><br>* <div data-tips="true" data-tips-type="tip">Supports <strong>User migration</strong> type only when the target database integrated mode is <strong>MySQL connected over public network</strong> or <strong>BytePlus edition MySQL</strong>.</div><br><br><br>* <div data-tips="true" data-tips-type="tip">If <strong>User migration</strong> is required but some accounts in the source database can not be migrated, ensure that your business operations will not be affected by the absence of these accounts. For more information, refer to <a href="https://docs.byteplus.com/en/docs/DTS/creating_and_initiating_a_migration_task">Creating and starting a migration task</a>.</div><br> |
|Post\-schema migration |To ensure the performance of data migration and the stability of the migration task, some database migration objects will be created after the incremental migration is completed. The objects that need to undergo post\-schema migration include:<br><br><br>* RDS for MySQL: trigger, event.<br><br>* PostgreSQL: ordinary trigger, event trigger, RULE, exclusive constraint, foreign key constraint, check constraint, Domain constraint, and Sequence value setting. |
|&nbsp;<br><br>Unidirectional synchronization |Unidirectionally synchronize data from one source database to one or more target databases, or unidirectionally synchronize data from multiple source databases to one target database. |
|Bidirectional synchronization |DTS currently only supports one\-to\-one bidirectional synchronization between two RDS for MySQL databases. In a bidirectional synchronization topology, you need to configure both a forward synchronization task and a reverse synchronization task separately. For configuration methods, refer to [Configuring a forward task](https://docs.byteplus.com/en/docs/DTS/configuring_forward_synchronization) and [Configuring a reverse task](https://docs.byteplus.com/en/docs/DTS/configuring_reverse_synchronization). |
|Consumer group |A consumer group is a group of consumers that has the same Group ID. When a Topic is consumed by multiple consumers in the same consumer group, each message is delivered to only one consumer to achieve load balancing of consumption. With consumer groups, you can ensure that the messages of a Topic are consumed in parallel. |
|Data range |The timestamp range of incremental data stored in the subscription channel. |
