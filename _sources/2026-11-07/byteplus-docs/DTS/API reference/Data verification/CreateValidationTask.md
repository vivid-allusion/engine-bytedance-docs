Call the CreateValidationTask interface to create a data verification task.

<span id=".6K-35rGC57G75Z6L"></span>
## Request type

Synchronous request.

<span id=".5rOo5oSP5LqL6aG5"></span>
## Precautions


* When a data verification task is being performed, only one verification task can be running. Multiple verification tasks may cause a load on the source database and target database.

* During the migration or synchronization process, do not perform the following operations, or the verification result may be inconsistent:

   * Perform DDL operations on the source database.

   * Do not perform write operations on the target database.

* The verification task starts verifying data only when the task completes full migration or full initialization.

* DTS does not verify the data that has neither primary key constraint nor unique constraint.

* If a synchronization or migration task is restarted (for example, starting a paused task), the data verification task in the task is automatically terminated, and the task status changes to completed. If you need to perform data verification on the data, you need to create a data verification task again.

* Before performing the verification task, you need to evaluate the source database and target database performance. It is recommended that you perform data verification during off\-peak hours (for example, the CPU load of the source database and target database is below 30%). Because DTS will occupy certain read resources of the source database and target database during data verification, which may cause the database load to increase. In the case of poor database performance, low specifications, or large business volume, it may increase the pressure on the database, or even cause the database service to be unavailable.

* Refer to [data verification billing information](https://docs.byteplus.com/en/docs/DTS/Data_verification_billing_method) for the billing information of data verification.
