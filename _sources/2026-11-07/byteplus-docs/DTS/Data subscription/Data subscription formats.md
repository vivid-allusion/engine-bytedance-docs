This topic introduces the data subscription formats supported by Database Transmission Service (DTS).

<span id=".6K6i6ZiF5qC85byP"></span>
## Subscription format

Database Transmission Service (DTS) supports the subscription formats shown in the following table.

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip"><strong>Avro format</strong> and <strong>Debezium JSON format</strong> are currently in beta testing. To use it, <a href="https://console.byteplus.com/workorder/create">submit a ticket</a> for technical support.</div>



|**Subscription format** |**Description** |
|---|---|
|**BytePlus Proto** |For examples of the BytePlus Proto format, refer to [Volc Proto](https://github.com/volcengine/volc-sdk-golang/blob/main/example/dts/data-subscription-demo/proto/volc.proto). |
|**Canal Proto** |DTS can parse the database's incremental logs and package the incremental data into Canal Proto format to synchronize to the data middleware, enabling incremental data subscription and consumption. For examples of the Canal Proto format, refer to [Canal Proto](https://github.com/alibaba/canal/blob/canal-1.1.6/protocol/src/main/java/com/alibaba/otter/canal/protocol/EntryProtocol.proto). |
|**Canal JSON** |Canal JSON is a data storage format defined by Canal for parsing incremental database logs. DTS can package incremental data into Canal JSON format and synchronize it to middleware, enabling incremental data subscription and consumption. For field information and corresponding examples of the Canal JSON format, refer to [Canal JSON](https://github.com/volcengine/volc-sdk-golang/blob/main/example/dts/data-subscription-demo/canal_json/canal_json.go). |
|**Avro format** |Avro subscription format is a data serialization format that converts data schemas or objects into a format suitable for transmission. It is mainly used in big data processing and complex distributed system scenarios. For examples of the Avro format, refer to [Avro](https://github.com/volcengine/volc-sdk-golang/blob/main/example/dts/data-subscription-demo/avro/record.avsc). |
|**Debezium JSON format** |Debezium is an open\-source distributed platform that captures database changes and sends them as event streams to message queues such as Kafka. For more information on the Debezium JSON format, refer to [Debezium JSON](https://debezium.io/documentation/reference/stable/connectors/mysql.html#how-the-mysql-connector-works). |

## Debezium JSON format

<span id=".5a2X5q616K-05piO"></span>
### Field description

The Debezium JSON format consists of the following two field parts:


* **`schema`**: Represents the architecture of the event, including field types and schema. It is used to understand the data schema on the consumer side.

* **`payload`**: Represents the actual event data. DML events include the key fields shown in the following table:

   
   |**Subfield** |**Description** |
   |---|---|
   |**before** |Represents the before\-image, containing row data before update or delete operations. If it is an insert operation, this field is null. |
   |**after** |Represents the after\-image, containing row data after insert or update operations. If it is a delete operation, this field is null. |
   |**source** |Represents data source information, namely the information related to the data source. |
   |**op** |Represents the type of DML. |
   |**ts_ms** |Represents the timestamp (in milliseconds) when the DTS processes the event, used to record the actual occurrence time of the event. |
   


For more information on fields, refer to [Debezium JSON](https://debezium.io/documentation/reference/stable/connectors/mysql.html#how-the-mysql-connector-works).

<span id=".56S65L6L"></span>
### Example

The following uses RDS for MySQL as an example to illustrate how DTS parses DML operations into Debezium JSON format:

An example of the table schema is as follows.

```sql
create table score_table(id int primary key, namr varchar(32), score double);
```



* Insert into table:

   ```sql
   insert into score_table values(1, 'tom', 86.0);
   ```
   

   Expected output:

   ```sql
   {
       "schema": {...},
       "payload": {
           "before": null,
           "after": {
               "id": 1,
               "name": "tom",
               "score": 86.0
           },
           "source": {...},
           "op": "c",
           "ts_ms": 1731068683523,
           "transaction": null
       }
   }
   ```
   

* Update table:

   ```sql
   update score_table set score = 95.0 where id = 2;
   ```
   

   Expected output:

   ```sql
   {
       "schema": {...},
       "payload": {
           "before": {
               "id": 1,
               "name": "tom",
               "score": 86.0
           },
           "after": {
               "id": 1,
               "name": "tom",
               "score": 95.0
           },
           "source": {...},
           "op": "u",
           "ts_ms": 1731068693523,
           "transaction": null
       }
   }
   ```
   

* Delete from table:

   ```sql
   delete from score_table where id = 1;
   ```
   

   Expected output:

   ```sql
   {
       "schema": {...},
       "payload": {
           "before": {
               "id": 1,
               "name": "tom",
               "score": 86.0
           },
           "after": null,
           "source": {...},
           "op": "d",
           "ts_ms": 1731068713052,
           "transaction": null
       }
   }
   ```
