Call the ModifyInstanceSpec API to change the instance's computing specification, storage specification, and other product specifications.

<span id=".5L2_55So6K-05piO"></span>
## Instructions

As your business grows, if the instance specifications no longer meet your needs, you can appropriately upgrade the instance's specifications. This API changes the RabbitMQ instance specifications, including computing specifications, storage capacity, and other configurations.

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>



* <div data-tips="true" data-tips-type="tip">Before calling this API, confirm the instance status is Running.</div>


* <div data-tips="true" data-tips-type="tip">Currently, only upgrading instance configurations is supported. Downgrading computing specifications or reducing storage space is not supported.</div>


* <div data-tips="true" data-tips-type="tip">Different computing specifications correspond to different storage capacity ranges. When upgrading the instance's computing specification, the storage capacity must be upgraded synchronously.</div>

## Request parameters

Only the unique request parameters of this API and some common parameters are listed below. For more information, see [common parameters](https://docs.byteplus.com/en/docs/byteplus-platform/reference-common-parameters).



**Action** <span data-label="purple">string</span> <span data-api-tag="require|gm8kvr">必选</span> `Example value: ModifyInstanceSpec`

Action to perform: ModifyInstanceSpec.



**Version** <span data-label="purple">string</span> <span data-api-tag="require|mkg3vE">必选</span> `Example value: 2022-01-01`

API version, value: 2022\-01\-01.



**ClientToken** <span data-label="purple">string</span> `No` `Example value: 123e4567-e89b-12d3-a456-426655440000`

Identifier to ensure the idempotency of client requests.

The identifier must be a 1 to 64 character ASCII string, case\-sensitive, generated by the client, and must be unique across different requests.

For how to use the idempotency key, refer to [request idempotency](https://docs.byteplus.com/en/docs/rabbitmq/Request_idempotency).



**InstanceId** <span data-label="purple">string</span> <span data-api-tag="require|inJUqp">必选</span> `Example value: rbtmq-5b293870****`

Instance ID.



**ComputeSpec** <span data-label="purple">string</span> `No` `Example value: rabbitmq.n3.x2.medium`

Instance specification after modification.


* Only instance specification upgrades are supported; downgrades are not supported.

* The list of computing specifications provided by the Message Queue RabbitMQ edition instance. Please refer to [Product Specifications](https://docs.byteplus.com/en/docs/rabbitmq/Product_specifications).



**StorageSpace** <span data-label="purple">integer</span> `No` `Example value: 300`

Storage space after instance modification.

Unit is set as GiB. The value must be specified as a multiple of 100. The value range depends on the currently specified compute specification. You can check the supported storage space range and default storage size for the specified compute specification through the DescribeComputeSpecsInfo API.

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>



* <div data-tips="true" data-tips-type="tip">Only instance specification upgrades are supported. Downgrades are not supported.</div>


* <div data-tips="true" data-tips-type="tip">You can query the storage space range for a specified instance specification using DescribeComputeSpecsInfo.</div>


* <div data-tips="true" data-tips-type="tip">When upgrading specifications, you usually need to upgrade storage space simultaneously. The minimum storage capacity after upgrade is calculated as (original single\-node capacity / original node count) \* new node count. For example, an original n3 specification with 3 nodes and 300 GiB storage upgraded to n5 (5 nodes) requires at least 500 GiB.</div>
