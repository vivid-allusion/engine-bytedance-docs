When calling the Message Queue for RabbitMQ OpenAPI, if a request timeout or internal server error occurs, the client may retry multiple times. To ensure request idempotency, set the ClientToken parameter when calling the OpenAPI to avoid creating duplicate resources due to repeated retries.

<span id="ba6ce3a0"></span>
## How to ensure request idempotency    

Request idempotency means that executing the same request once has the same effect as executing it multiple times consecutively. In other words, an idempotent method has no side effects beyond statistical use. When creating cloud resources through OpenAPI, if request timeouts or internal server errors occur, the client may retry repeatedly. If both the original request and subsequent retries succeed, each request creates a resource, resulting in more resources created than expected. The Message Queue for RabbitMQ supports OpenAPI request idempotency identifiers. The backend service performs a series of checks on the idempotency identifier set by the client in the request to recognize whether the current request is a retry and then proceeds accordingly. Clients can add the optional ClientToken parameter as an idempotency identifier in request parameters when sending requests. If the client retries after encountering errors like 500, the server will check the idempotency identifier to determine whether the request is a retry. The basic information of the idempotency identifier is as follows:


|Name |Type |Required |Example value |Description |
|---|---|---|---|---|
|ClientToken |String |No |testClientToken |Identifier ensuring idempotency of client requests. The identifier is an ASCII string of 1 to 64 characters. It is case\-sensitive and generated by the client. The uniqueness across different requests should be ensured. |


Idempotency identifier usage instructions:


* Uniqueness: The idempotency identifier must be unique for each request. If you provide an already used identifier with different request parameters, the server returns the InvalidIdempotency error code.

* Validity period: The idempotency identifier is valid for 8 hours. If you provide an expired identifier, the server returns the InvalidIdempotency error code.

* After retrying with the idempotency identifier:

   * If the response status code is 2xx, the client receives exactly the same result as the previous request, such as instance ID returned when the Create Instance request succeeds.

   * If the response status code is 4xx, the client retry fails. It is recommended to diagnose the issue based on the error message before retrying the request.
