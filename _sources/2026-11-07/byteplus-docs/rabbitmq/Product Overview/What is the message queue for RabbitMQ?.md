The Message Queue for RabbitMQ is a distributed, high\-availability message queue that supports AMQP (Advanced Message Queuing Protocol). It is fully compatible with the RabbitMQ open\-source ecosystem and multi\-language clients. It offers diverse message features and flexible message routing. Besides, it features distributed architecture, high throughput, low latency, and scalable cloud messaging services. It allows easy and fast cloud migration, without requiring users to deploy or maintain the system.

<span id="产品功能"></span>
## Product function


* Multiple message consumption types: supports the AMQP protocol and various message types, including normal messages, broadcast messages, dead\-letter messages, and delayed messages.

* Extension ecosystem: the message queue for RabbitMQ supports various extensions that enable delayed message functionality and compatibility with MQTT (Message Queuing Telemetry Transport) protocol using both TCP and WebSocket methods.

* Task management: allows viewing execution records of background tasks; shows the execution status, details, start, and end times of tasks like instance restarts.

* Monitoring and alarms: via BytePlus cloud monitoring service, you can monitor data such as instance status, resource usage, and message send/receive latency around the clock. It detects anomalies such as consumption delay and backlog to help users identify problems promptly.


<span id="应用场景"></span>
## Application scenarios

<span id="异步解耦"></span>
### Asynchronous decoupling

Data generated by application systems may need to be accessed by multiple downstream systems, each with different message processing logic. However, the application system cannot accommodate every related business individually. The message queue for RabbitMQ enables efficient asynchronous communication and effectively decouples upstream and downstream systems to reduce dependencies. Even if one system becomes unavailable or crashes, it will not affect the normal operation of other systems, ensuring continuous business processes for both sides. Asynchronous decoupling significantly shortens the data chain length and improves message processing efficiency. Therefore, the stability of upstream and downstream systems is ensured.

<span id="削峰填谷"></span>
### Peak shaving and valley filling

When the system handles large\-scale events like flash sales or new product launches, it experiences temporary traffic surges. Without proper protection mechanisms, the system may become overloaded or crash and eventually affect user experience. The message queue for RabbitMQ can serve as a buffer. Through peak shaving and valley filling, it collects sudden spikes of requests from upstream systems. Downstream systems can process these request messages according to their actual capacity so they can operate in a smooth and stable condition within safe limits. This prevents overwhelming traffic impact and maintains upstream and downstream system availability. Besides, it ensures fast user response and enhances user experience.
