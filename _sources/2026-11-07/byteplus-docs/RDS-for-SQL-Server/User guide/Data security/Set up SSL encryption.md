RDS for SQL Server provides an SSL (Secure Sockets Layer) encryption service to enhance the confidentiality and security of your data during transmission. This topic describes how to set up SSL encryption in the RDS for SQL Server console.

<span id=".6IOM5pmv5L-h5oGv"></span>
## Description

SSL encryption encrypts network connections at the transport layer to enhance data communication security and ensure data integrity.

<span id=".5rOo5oSP5LqL6aG5"></span>
## Precautions


* Enabling SSL encryption increases the network response time for RDS for SQL Server. Enable SSL encryption only when necessary, for example, when connecting to an RDS for SQL Server instance over the public network.

* Modifying the SSL configuration for an instance, such as enabling or disabling SSL encryption, enabling or disabling forced encryption, or updating an SSL certificate, will restart the instance. Proceed with caution.

* An SSL certificate automatically generated by BytePlus is valid for 1 year by default; the validity of a custom certificate is determined by its own settings. **Before an SSL certificate expires, update its validity period and re\-download and configure the CA certificate. Failure to do so will result in the following:** 

   * **The RDS for SQL Server instance will fail to restart, which will affect normal business operations.** 

   * **Applications or clients using SSL\-encrypted connections will be unable to connect to the SQL Server instance.**  You can add the trust server certificate parameter to the connection string to temporarily restore service connectivity.

* Database Workshop does not support operations on instances with forced SSL encryption enabled. If you rely on Database Workshop, enable this feature with caution.

* When you restore a backup to a new instance or rebuild an instance with SSL encryption enabled, the new instance does not inherit the SSL encryption feature by default.

* To modify the public or private domain name of an instance, first disable SSL encryption. After the domain name is modified, re\-enable it and download and configure the SSL CA certificate.

* SSL uses the TLS 1.2 protocol by default. Ensure that the client's connection configuration and operating system support the TLS 1.2 protocol. The operating system and client requirements are as follows:

   * **Client**: The client requirements are as follows.

## Procedure


1. Log on to the [RDS for SQL Server console](https://console.byteplus.com/db/sql-server).

2. In the upper\-left corner of the top menu bar, select the project and region where the instance is located.

3. On the **Instances** page, click the name of the target instance.

4. On the Instance details page, click **Security**.

5. On the **Security** tab, click **SSL**.

   1. Enable SSL encryption

      1. On the **SSL** sub\-tab, click the switch in the **SSL ccertificate** section.

      2. In the **Enable SSL** pane, configure the following settings:

   3. Configure an SSL CA certificate

      After you enable SSL encryption for an RDS for SQL Server instance, your application or client must configure an SSL CA certificate to connect to the SQL Server instance. This topic uses the SSMS client as an example to describe how to install an SSL CA certificate. If you use other applications or clients, refer to their official documentation.

      1. Install the RDS for SQL Server client. For more information, see [How to install SQL Server Management Studio](https://learn.microsoft.com/en-us/sql/ssms/download-sql-server-management-studio-ssms?view=sql-server-ver16).

      2. In the search box in the lower\-left corner of the desktop, enter `certmgr.msc` and press Enter.

      3. In the **certmgr** dialog box, right\-click **Trusted Root Certification Authorities**.

      4. Select **All Tasks** \> **Import**.

         <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_c22666811214e15a2e1447b26d7908bf.png) </span>

      6. Click **Next**.

         <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_3fefd06a8536529d267f2bf27828cf72.png) </span>

      7. In the **Certificate Import Wizard** dialog box, click **Browse...** . Import the downloaded SSL CA certificate and click **Next**.

         <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_424bd9a333816796b8ed3b4b9bd6018d.png) </span>

      8. Select a storage location for the certificate and click **Next**.

      9. Click **Finish**.

   4. Configure SSMS.

      1. Open SSMS. In the **Connect to Server** dialog box, click **Options**.

         <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_387cf328e4eb9710e97a252f79978eec.png) </span>

      2. In the **Connection Security** section of the **Connect to Server** dialog box, click the **Encryption** drop\-down list, select **Mandatory**, and select the **Trust server certificate** checkbox.

         <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_f4fa7845e2fc614d9b8974ccf5b916db.png) </span>

      3. Click **Connect**.

      4. Run the following command to check that the connection is encrypted.

         ```sql
         SELECT ENCRYPT_OPTION FROM SYS.DM_EXEC_CONNECTIONS WHERE SESSION_ID = @@SPID
         ```
