An RDS for SQL Server instance provides a connection address and port that you can use to specify connection parameters when connecting to the instance. This topic describes how to view the connection addresses and ports of primary and read\-only instances in the RDS for SQL Server console.

<span id=".6IOM5pmv5L-h5oGv"></span>
## **Description**


* RDS for SQL Server provides private and public network addresses, allowing you to select the appropriate address to access and manage your SQL Server instance based on your business needs. Public network access is disabled by default and must be enabled manually.

   
   |**Connection address type** ||**Can the connection address prefix be modified?**  |**Description** |**Precautions** |
   |---|---|---|---|---|
   |Private network access |Private network address |Supported. For detailed steps, see [Modify the connection address prefix](https://docs.byteplus.com/en/docs/RDS-for-SQL-Server/modify-the-connection-address-prefix?lang=zh). |Accessing SQL Server instances through a private network connection address provides maximum security and performance. |A private network address is generated by default when you create an SQL Server instance. This address cannot be deleted. |
   |Public network access |Public network address |Supported. For detailed steps, see [Modify the connection address prefix](https://docs.byteplus.com/en/docs/RDS-for-SQL-Server/modify-the-connection-address-prefix?lang=zh). |If you need to access an SQL Server instance from outside the VPC, you can apply for a public network address for it. |* Public network connections pose security risks, so RDS for SQL Server disables public network access by default. You must manually request access in the console. To apply for a public network address, see [Enable public network access](https://docs.byteplus.com/en/docs/RDS-for-SQL-Server/enabling-public-network-access).<br><br>* We recommend promptly releasing the public network address when devices outside the VPC no longer need to access the SQL Server instance. To release a public network address, see [Disable public network access](https://docs.byteplus.com/en/docs/RDS-for-SQL-Server/disabling-public-network-access). |
   

* The public and private network addresses of an instance can be used for all connection scenarios.

* A read\-only instance is useful when the primary instance has a high read load. By configuring the connection addresses for the primary instance and the read\-only cluster endpoint in your application, you can reduce the read pressure on the primary instance and improve the system's overall processing capability.

## **View an instance's connection address and port**

RDS for SQL Server provides private and public network addresses to access your SQL Server instances. The public network address is disabled by default and must be enabled manually.

<span id=".5YmN5o-Q5p2h5Lu2"></span>
### **Prerequisites**


* An instance has been created and is in the **Running** state. For more information, see [Create an instance](https://docs.byteplus.com/en/docs/RDS-for-SQL-Server/creating-instance-for-user-guide).

* To view the public network address and port, you must enable public network access. For more information, see [Enable public network access](https://docs.byteplus.com/en/docs/RDS-for-SQL-Server/enabling-public-network-access).


<span id=".5pON5L2c5q2l6aqk"></span>
### **Procedure**


1. Log on to the [RDS for SQL Server console](https://console.byteplus.com/db/sql-server).

2. In the upper\-left corner of the top menu bar, select the project and region of the instance.

3. In the left navigation bar, click **Instances**.

4. On the **Instances** page, click the name of the target instance.

5. On the instance details page, click **Connection management**.

6. On the **Connection management** tab, you can view the node details in the **Connection topology** area:

   * View the ID, availability zone and IP address of the primary and secondary nodes.:

      * Hover over the primary node area to view its ID, availability zone, and IP address in the pop\-up window.

      * Hover over the secondary node area to view its ID, availability zone, and IP address. In the secondary node area, click **Switch to primary node** to switch between the primary and secondary nodes. For more information, see [Switching primary node](https://docs.byteplus.com/en/docs/RDS-for-SQL-Server/switching-master-node?lang=zh).

      <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="2">tip      </div>
      

      * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="2">The node IP is primarily used to establish network connectivity between instances via Elastic Network Interfaces (ENIs), enabling you to connect to instances with DBLINK and perform cross\-database queries and operations. For detailed instructions, see <a href="https://docs.byteplus.com/en/docs/RDS-for-SQL-Server/adding-linked-server-to-rds-for-sql-server">Add a linked server for RDS for SQL Server</a>.      </div>
      

      * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="2">If a primary instance has read\-only instances, its <strong>Connection management</strong> tab displays the specifications and read weights of all read\-only nodes. To configure these weights, see Configure read weights for read\-only instances. Hover over the read\-only node area to view the ID, availability zone, and IP address of the secondary node.      </div>
      

   * View the primary node endpoint: hover over the primary node endpoint card to view the private and public network addresses and ports for the current instance in the pop\-up window.

      <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="2">tip      </div>
      

      <div data-tips="true" data-tips-type="tip" data-wrapper-indent="2">If a primary instance includes read\-only instances, you can view the unified read\-only cluster connection address for all read\-only instances on its <strong>Connection management</strong> tab. You can also view the private and public network addresses and ports of the read\-only node on the <strong>Connection management</strong> tab of the read\-only instance.      </div>

## **View connection addresses and ports of read\-only instances**

After a read\-only instance is created, the system generates a unified read\-only cluster connection address by default. It also provides a separate connection address for each read\-only instance.

<span id=".5YmN5o-Q5p2h5Lu2"></span>
### **Prerequisites**

An RDS for SQL Server primary instance and read\-only instances have been created, and the primary instance must meet the following conditions:


* Compatible versions: **SQL Server 2019 Enterprise Edition** and **SQL Server 2022 Enterprise Edition**.

* Instance type: **Cluster edition**.

* Status: **Running**.


<span id=".5rOo5oSP5LqL6aG5"></span>
### **Precautions**


* After a read\-only instance is created, the system creates a unified read\-only cluster connection address by default. The connection address of the unified read\-only cluster endpoint is fixed and does not change as you add or remove read\-only instances. This eliminates the need to modify your application repeatedly, reducing maintenance costs.

* The system creates a separate read\-only node endpoint connection address for each read\-only instance by default.

* Read\-only addresses are free of charge. You are only billed for the read\-only instances.


<span id=".5pON5L2c5q2l6aqk"></span>
### **Procedure**

<span id=".5p-l55yL5aSa5Liq5Y-q6K-75a6e5L6L57uf5LiA5Y-q6K-76ZuG576k6L-e5o6l5Zyw5Z2A"></span>
#### **View the unified read\-only cluster connection address**


1. Log on to the [RDS for SQL Server console](https://console.byteplus.com/db/sql-server).

2. In the upper\-left corner of the top menu bar, select the project and region of the instance.

3. In the left navigation bar, click **Instances**.

4. On the **Instances** page, click the name of the primary instance for the target read\-only instance.

5. On the **Instance information** page of the target instance, click **Connection management**.

6. In the **Connection topology** section of the **Connection management** tab, move your pointer over the **Read\-only cluster endpoint** card.

7. In the pop\-up window, you can view the unified private network address and port for all read\-only instances under the current primary instance.


<span id=".5p-l55yL5Y2V5Liq5Y-q6K-75a6e5L6L55qE6L-e5o6l5Zyw5Z2A"></span>
#### **View the connection address for a single read\-only instance**


1. Log on to the [RDS for SQL Server console](https://console.byteplus.com/db/sql-server).

2. In the upper\-left corner of the top menu bar, select the project and region of the instance.

3. In the left navigation bar, click **Instances**.

4. On the **Instances** page, click the plus icon before the target instance name, and then click the name of the target read\-only instance.

5. On the **Instance information** page for the target read\-only instance, click **Connection management**.

6. On the **Connection management** tab, in the **Connection topology** section, hover over the **Read\-only node** card.

7. The pop\-up window shows the private network address, public network address, and port of the read\-only instance.
