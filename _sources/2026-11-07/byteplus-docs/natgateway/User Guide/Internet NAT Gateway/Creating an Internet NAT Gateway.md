This topic describes how to create an Internet NAT Gateway.

<span id=".5pON5L2c6K-05piO"></span>
## Instructions


* Elastic IP Address (EIP) has a higher priority than the route table. If an Elastic Computing Services (ECS) instance is bound to an EIP, its traffic will be forwarded through that EIP and cannot utilize the functions of the Internet NAT Gateway.

* A single VPC supports the creation of up to 3 NAT Gateways (including both Internet and VPC NAT Gateways).

* Supports creating both NAT Gateways and IPv4 gateways within a single VPC simultaneously.

   > The IPv4 Gateway is currently in Beta stage. If you need a trial, please contact your account manager. [Learn more](https://docs.byteplus.com/en/docs/vpc/IPv4-Gateway-Overview)

## What to do next


* After creating your first public NAT Gateway, the system automatically adds a custom route to the VPC route table with a destination CIDR block of 0.0.0.0/0 and the Internet NAT Gateway instance as the next hop. If route forwarding fails, see [Why is NAT Gateway traffic not flowing](https://docs.byteplus.com/en/docs/natgateway/NAT-gateway-FAQ#bG3m29ZX).

* After creating an additional Internet NAT Gateway, you must manually configure routes for the gateway. For more details, see [Deploying multiple Internet NAT Gateways in a single VPC](https://docs.byteplus.com/en/docs/natgateway/Configuring-multiple-Internet-NAT-Gateways-in-a-VPC).

* **Network Access Control List (ACL) traffic control** is automatically configured after NAT Gateway creation. To modify the Network ACL traffic control settings, please contact your account manager and submit a ticket. [Learn more](https://docs.byteplus.com/en/docs/natgateway/NAT-gateway-FAQ#gQrzZ123)
