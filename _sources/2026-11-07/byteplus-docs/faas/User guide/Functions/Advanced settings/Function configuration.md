FaaS allows you to configure multiple advanced attributes for each function to meet different business requirements. After a function is created, you can update its configuration items as needed on the "Function settings" tab. This topic describes each configuration item and its valid values.

<div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div>



* <div data-tips="true" data-tips-type="warning">Only the configuration of the latest version of a function can be updated.</div>


* <div data-tips="true" data-tips-type="warning">After you update the configurations of a function, you need to release the function again to make the updated configurations take effect.</div>




|Parameter |Configuration description |Supported function types |Related document |
|---|---|---|---|
|CPU allocation mode |* **CPU is provisioned only upon request**: This mode only applies to **event functions**, **web app functions**, and **task functions**. Instances are automatically allocated and released based on requests, and can be scaled down to zero. Resource usage and function invocations are only billed for the request processing duration.<br><br>* **Always allocate CPU**: This mode applies to **microservices application functions**. After applications start, they cannot be scaled down to zero, and you are charged for the container lifecycle. |All types |None |
|Compute mode |The GPU instance and the CPU instance are independent of each other. After a function is created, switching between the instances is not supported.<br><br><br>* **CPU instance**: Traditional functions use CPU instances, which support basic computing scenarios.<br><br>* **GPU acceleration**: [[Beta - apply for trial]](https://docs.byteplus.com/en/docs/faas/How_do_I_apply_for_beta_features) This mode is good at executing highly\-threaded tasks that are processed in parallel (large\-scale computing tasks). It applies to scenarios such as AI model inference, AI model training, accelerated audio and video production, and graphics and image acceleration. |All types |[Serverless GPU](https://docs.byteplus.com/en/docs/faas/Serverless_GPU) |
|Instance specification |You can specify this parameter only when you set the **Compute mode** parameter of the function to **CPU instance**. Select appropriate specifications of a single CPU instance, including the vCPU and memory, based on the on\-screen prompts and your business requirements. |All types |None |
|GPU model |[[Beta - apply for trial](https://docs.byteplus.com/en/docs/faas/How_do_I_apply_for_beta_features)] You can specify this parameter only if you set the **Compute mode** parameter of the function to **GPU acceleration**. Select a GPU specification for a single GPU instance from the GPU types provided by FaaS. |All types |[Serverless GPU](https://docs.byteplus.com/en/docs/faas/Overview_of_serverless_GPU?lang=en) |
|Asynchronous tasks |You can enable the asynchronous task feature.<br><br><div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div><br><br><br><div data-tips="true" data-tips-type="warning">After a function is created, switching between synchronous and asynchronous modes is not supported.</div><br><br><br><br>* **Asynchronous task**:<br><br>   * Enable: The function responds to events in asynchronous execution mode. In this mode, event invocations do not need to block and wait for processing results. The maximum function execution duration is 3 hours.<br><br>      After you enable the asynchronous task feature, you can specify the **Retries for failed async task** parameter. When an asynchronous task fails to be executed, the task will be retried within the limit.<br><br>   * Disable: The function responds to events in synchronous execution mode. In this mode, event invocations synchronously wait for the function to execute and return results. The maximum function execution duration is 15 minutes.<br><br>* **Retries for failed async task**: After you enable the asynchronous task feature, you can specify this parameter, which indicates the number of retries after an asynchronous task fails to be executed. You can set the value to 0 to 3. The default value is 0, which indicates that an asynchronous task will not be retried after failure. |* Event function<br><br>* Web app function<br><br>* Task function |[Asynchronous tasks](https://docs.byteplus.com/en/docs/faas/Asynchronous_task) |
|Execution timeout |Specify the maximum execution duration for a single request. If the request exceeds the limit, an error is returned.<br><br><br>* Valid values for the execution timeout for a synchronous invocation: 1 to 3600 seconds.<br><br>* Valid values for the execution timeout for an asynchronous task: 10 to 10800 seconds. |* Event function<br><br>* Web app function<br><br>* Task function |None |
|Single\-instance multi\-concurrency |Select whether to enable a single instance to process multiple concurrent requests.<br><br><br>* Enable: Each instance can handle multiple concurrent requests, and memory usage is calculated only once, which significantly reduces resource costs. After you enable this feature, you need to specify the maximum number of concurrent requests that a single function instance can process. For synchronous invocations, an instance can process 10 to 1,000 concurrent requests. For asynchronous tasks, an instance can process 2 to 10 concurrent requests.<br><br>* Disable: Each instance can process only one request at a time. |* Event function<br><br>* Web app function<br><br>* Task function |None |
|VPC |After enabling **VPC**, configure the corresponding VPC, subnets, and security groups.<br><br><div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div><br><br><br><div data-tips="true" data-tips-type="warning">To modify the VPC or subnet of a function, you must first disable or delete all MQ triggers.</div><br><br><br><br>* **VPC**: Select a VPC to be accessed.<br><br>* **Subnet**: Select a subnet to be accessed. You can select multiple subnets, but you can select only one subnet in each availability zone. We recommend that you select subnets across multiple availability zones. The function instance will be deployed in the selected availability zones to ensure high availability of your business.<br><br>* **Security group**: Select a security group to which the function will be bound. A security group is a logical group that provides access policies for NICs with the same security protection requirements and mutual trust within the same VPC. |All types |None |
|Default network interface card to access the public network |The function uses the platform\-provided public NAT and EIP to access the Internet by default.<br><br><br>* Enabled: The function can access resources in the VPC. The function can access the Internet via the default network interface. veFaaS will charge for outbound Internet traffic.<br><br>* Disabled: After enabling **VPC**, you can disable the **Default network interface card to access the public network** feature. The function can access resources in the VPC but cannot access the Internet via the default network interface. To access the Internet, configure a NAT gateway in the VPC. For detailed steps, see [Creating public NAT gateways](https://docs.byteplus.com/en/docs/natgateway/Creating-an-Internet-NAT-gateway). veFaaS does not charge for outbound Internet traffic in this case. |* Event function<br><br>* Web app function<br><br>* Task function |None |
|Storage |Configure remote storage for the function. After configuration, the function can access remote storage as it accesses the local system, which achieves persistent data storage and sharing across multiple functions. |All types |* [Mounting FileNAS](https://docs.byteplus.com/en/docs/faas/Mount_FileNAS)<br><br>* [Mounting TOS](https://docs.byteplus.com/en/docs/faas/Mount_TOS) |
|Logging |Specify whether to enable the logging feature. After you enable the logging feature, the stdout and stderr logs of the function will be collected into the specified log project and log topic in Torch Log Service (TLS). You can view the execution logs of the function to check its running status and to troubleshoot.<br><br><br>* **Default log project**: If you select Default log project, FaaS will automatically create the default log project and topic **tls\-vefaas/tls\-vefaas\-logstore** within your account. Logs will be delivered to the log project and topic.<br><br>* **Custom log project**: If you select Custom log project, you can specify a custom log project. Logs will be delivered to the target log project and topic. |All types |[Logs management](https://docs.byteplus.com/en/docs/faas/Log_management) |
|Environment variables |Configure custom environment variables, which can be directly read during the runtime of the function code. Enter a **key** and a **value** based on the prompts to add an environment variable.<br><br>* **Edit in JSON**: Configure environment variables by using a JSON file.<br><br>   The JSON file needs to be in the following format:<br><br>   ```json```<br>```   {```<br>```     "envKey1":"envValue1",```<br>```     "envKey2":"envValue2"```<br>```   }```<br>```   ```<br>   <br><br>   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div><br>   <br><br>   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">Enter key\-value pairs in a JSON file as required in the console when you select <strong>Edit with form</strong>.   </div><br>   <br><br>   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">You can click <strong>Reset</strong> in the JSON editor to revert the content back to the last parsed JSON data.   </div><br>   <br><br>   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">You can click <strong>Formatting</strong> in the JSON editor to convert the content to standardized JSON format, remove duplicate key\-value pairs, and preserve only the key\-value pair that occurred last time.   </div><br>    |All types |None |
|Health check |The microservice function supports the health check feature, which takes effect after the function is configured and released.<br><br><br>* Check method: Select a method of performing health checks. The following methods are supported.<br><br>   * HTTP request check: Send an HTTP request to an instance for health checks. If the HTTP status code 200 is returned, it indicates that the instance is healthy.<br><br>   * TCP port check: Check the health status of an instance by establishing a connection between the instance and a TCP socket. If a connection can be established, it indicates that the instance is healthy.<br><br>* HTTP request check: This parameter is available after you set the **Check method** parameter to **HTTP request check** **.**  Enter the request path, port, and request header information.<br><br>* TCP port check: This parameter is available after you set the **Check method** parameter to **TCP port check** **.**  Enter the TCP port.<br><br>* Delay: The time period after which the first health check is performed after the function starts.<br><br>* Timeout: The maximum wait time for a single health check request. If the function does not start within the timeout period, it is deemed to fail the health check.<br><br>* Check interval: The interval at which health checks are performed.<br><br>* Healthy threshold: The minimum number of consecutive successful checks.<br><br>* Unhealthy threshold: The minimum number of consecutive check failures. |Microservices app function |None |
|Project |BytePlus allows you to manage resources by project. After functions are added to projects, you can manage the functions by project in a centralized manner, which helps maintain resource independence and ensures data security. If you do not specify a specific project, the function will be added to the default project. |All types |[Project management](https://docs.byteplus.com/en/docs/faas/Project_management) |
|Label |Consisting of a key\-value pair, a label is used to identify resources, which facilitates searching and aggregating resources. Click **Add label**, and add appropriate labels to the function based on the prompts. |All types |[Tag management](https://docs.byteplus.com/en/docs/faas/Label_management) |
