This article introduces how to deploy your own Browser Use Agent applications with one click through the Function Service Application Center.

<span id="background-information"></span>
## Background information


* **Application introduction**

   Browser Use Agent is a Browser as a Service promoted by BytePlus Function Service (FaaS) based on the open\-source browser\-use project and facing end users and AI suite developers. Only by entering the retrieval task, you can analyze and disassemble the task by the large model, call the browser to search the task in real time, and finally integrate and output the task result. During the whole operation process, the procedure planning of the big model and browser operation can be viewed in real time, meanwhile manual intervention in browser operation is supported, for example, entering verification code, receiving Cookies, and entering username and password.

   This service mainly supports the browser automation business, and can be used as a real\-time retrieval tool for the large model itself or the large model application expansion.

<span id="prerequisites"></span>
## Prerequisites


* All the cloud services associated with this application have been activated.

* IAM users need to ensure that they have authorized the **VeFaaSFullAccess**, **APIGFullAccess**, and **STSAssumeRoleAccess** policies. If any of the above policies is missing, contact the root user or the administrator for authorization. For specific operations, refer to [Editing a user](https://docs.byteplus.com/en/docs/byteplus-platform/docs-editing-a-user).

* An API gateway instance of the Serverless gateway type has been created. For detailed operations, refer to [Creating an instance](https://docs.byteplus.com/en/docs/apig/Creating_an_instance).

* When using Function Service for the first time, make sure that the cross\-service authorization is completed. If authorization is not done, the console will pop up the cross\-service authorization page to guide you to complete authorization.

<span id="call-agent-through-api"></span>
## Call Agent through API

This section mainly introduces the method of calling API to experience Browser Use Agent through the local curl command.

<span id="create-task"></span>
### Create task

Invoke the API with the local curl command to create a dialog task with the Browser Use Agent.


* **Request method**

   ```bash
   post ${framework apig url}/tasks
   ```
   

   Among which ${framework apig url} is the access address of the Agent. Assume that the access address of the Agent is: https://\*\*\*\*.com, then the complete POST command is as follows:

   ```bash
   post https://****.com/tasks
   ```
   

* **Sample request**

   ```json
   {
       "messages": [
           {
               "role": "user",
               "content": "Compare with the prices of the iPhone 15 on the Apple official website and the Amazon official website"
           }
       ]
   }
   ```
   

   Among which:

   * `role`: The role that calls the API, and can maintain the parameter value as user.

   * `content`: Enter the contents you want to have a dialog with the Browser Use Agent

* **Sample response**

   ```json
   {
       "task_id": "c2c2adcf-ade0-41b8-b195-******",
       "status": "queued"
   }
   ```
   

   Among which:

   * `task_id`: Task ID. Properly store it for later querying the task.

   * status: Task execution status. There are the following status values:

   * `queued`: In line

   * `starting`: Start execution

   * `browser_initialized`: Browser initialization

   * `running`: In progress

   * `conversation_update`: Conversation updates

   * `failed`: Failed

   * `agent_initialized`: Agent initialization

   * `completed`: Completed


<span id="query-task"></span>
### Query task

Invoke the API with the local `curl` command to query the conversation task with the Browser Use Agent.


* **Request method (Method)** 

   ```bash
   get ${framework apig url}/tasks/${task_id}/stream
   ```
   

   Among which:

   * `${Framework apig url}`: The access address of the Agent.

   * `${task_id}`: Task ID, which is the Task ID returned when creating the task.

   Assume that the access address of the Agent is: `https://****.com`, and the Task ID is: `c2c2adcf-ade0-41b8-b195-******`, then the complete POST command is as follows:

   ```bash
   get https://****.com/tasks/c2c2adcf-ade0-41b8-b195-******/stream
   ```
   

* **Sample response (Response)** 

   ```json
   [
     {
       "task_id": "c2c2adcf-ade0-41b8-b195-******",
       "data": "data: {\"task_id\": \"c2c2adcf-ade0-41b8-b195-******\", \"status\": \"conversation_update\", \"metadata\": {\"type\": \"message\", \"data\": {\"message\": \"Taking action #1: {'input_text': {'index': 2, 'text': 'iPhone 15 Apple'}}\"}}}\n\n"
     },
     {
       "task_id": "c2c2adcf-ade0-41b8-b195-******",
       "data": "data: {\"task_id\": \"c2c2adcf-ade0-41b8-b195-******\", \"status\": \"conversation_update\", \"metadata\": {\"type\": \"message\", \"data\": {\"message\": \"Taking action #2: {'click_element': {'index': 3}}\"}}}\n\n"
     },
     {
       "task_id": "c2c2adcf-ade0-41b8-b195-******",
       "data": "data: {\"task_id\": \"c2c2adcf-ade0-41b8-b195-******\", \"status\": \"conversation_update\", \"metadata\": {\"type\": \"message\", \"data\": {\"message\": \"Start planning step 10...\"}}}\n\n"
     }
   ]
   ```
   

   Among which the parameter description is as follows:

   
   |**Parameter** ||**Description** |
   |---|---|---|
   |task_id ||Task ID, which is returned by creating task. |
   |data |status |The status of the task includes:<br><br><br>* queued: In line<br><br>* starting: Start execution<br><br>* browser_initialized: Browser initialization<br><br>* running: In progress<br><br>* conversation_update: Conversation updates<br><br>* failed: Failed<br><br>* agent_initialized: Agent initialization<br><br>* completed: Completed |
   ||conversation_update |Conversation update refers to the detailed information of the large\-model\-driven Browser Use, which contains four fields:<br><br><br>* goal: Define the task.<br><br>* step: Push forward the task gradually.<br><br>* memory: Store history and results for subsequent use.<br><br>* evaluation: Score the execution performance of each step and determine whether to continue or make modifications. |
   ||metadata |the detailed metadata of conversation_update |
   ||type |The detailed metadata type of conversation_update<br><br><br>* planning_step: Planning steps.<br><br>* message: Specific conversation information. |
   ||message |Specific conversation information. |
   ||data |Specific conversation information structure. |
   ||message |Specific operation information, e.g. Start planning step 11.... |
   ||choices |When the status is completed, this field will be displayed, indicating the result of the task |
