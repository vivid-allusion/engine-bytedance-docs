## Introduction​

A Virtual Private Cloud (VPC) provides an isolated, self\-configured virtual network environment for cloud resources. Within your VPC, you can customize network features including IP address ranges, security groups, and routing policies, enabling simple, efficient, and secure management of cloud resources.

||Subnet |A subnet is a segment of a VPC CIDR block allocated within a specific Availability Zone, providing private IP addresses for cloud resources (e.g., ECS instances and Cassic Load Balancers.). |
||[Subnet route table](https://docs.byteplus.com/en/docs/vpc/Route-table-overview) |A subnet route table consists of a series of route entries that specify the next\-hop cloud resource for traffic within the VPC. Each subnet must be associated with one and only one subnet route table, enabling resources within the subnet to forward traffic according to the route table. A single subnet route table can be associated with multiple subnets, and resources within these subnets forward traffic through the associated subnet route table. |
||[Network interface](https://docs.byteplus.com/en/docs/vpc/Network-interface-overview) |A network interface is also called a virtual network interface (vENI). In the Virtual Private Cloud (VPC), a network interface is a network interface mounted on cloud resources like Elastic Compute Service (ECS) or Classic Load Balancer. It serves as an essential component for enabling network communication. |
|VPC Security |[Security group](https://docs.byteplus.com/en/docs/vpc/Security-group-overview) |Security groups control inbound and outbound traffic for ECSs' network interfaces, operating on an allowlist basis. Users can add security group rules according to their requirements to allow specific traffic through the network interface.<br><br>For example, when an ECS instance provides services externally through port 80, its associated security group must include an inbound rule allowing traffic on port 80. This ensures external clients can properly access the services on that ECS. |
||[Network ACL](https://docs.byteplus.com/en/docs/vpc/Network-ACL-overview) |Network ACLs (Access Control Lists) control inbound and outbound traffic at the subnet level. Each subnet can be associated with only one Network ACL. As Network ACLs operate on an allow\-list principle, traffic must be explicitly permitted to flow through. |
|VPC operations |[Flow Log](https://docs.byteplus.com/en/docs/vpc/Flow-log-overview) |After the flow log aggregates and processes the log data of outbound and inbound traffic for network interfaces as needed, it delivers the data to the TLS for storage and search analysis. You can analyze flow logs to monitor network traffic, troubleshoot network issues, and optimize network architecture. |
||[Traffic Mirror](https://docs.byteplus.com/en/docs/vpc/Traffic-mirror-overview) |Through traffic mirroring, you can replicate the traffic of a network interface based on custom Mirror Filters and privately forward the replicated traffic to a target service for monitoring and analysis. |
|Internet Access ||To meet the internet needs of resources in a Virtual Private Cloud (VPC), you can combine the following products as needed:<br><br><br>* [EIP](https://docs.byteplus.com/en/docs/eip/What-is-EIP): Associating an EIP to a single ECS enables two\-way communication with the IPv4 internet.<br><br>* [NAT gateway](https://docs.byteplus.com/en/docs/natgateway/What-is-NAT-Gateway): Multiple ECS instances can share a single EIP for internet access.<br><br>* [CLB](https://docs.byteplus.com/en/docs/clb/Product-Overview-01): Internet traffic can be distributed to multiple backend servers through the CLB.<br><br>* [IPv6 gateway](https://docs.byteplus.com/en/docs/IPv6/What_is_IPv6_Gateway): By enabling Internet IPv6 bandwidth for an ECS's IPv6 address, it can communicate with the IPv6 internet. |
