When creating pods in VCI via virtual nodes in a Kubernetes cluster, you can add annotations to pods as needed. This allows you to fully utilize VCI's features without changing Kubernetes semantics. This topic describes the annotations supported by VCI and provides configuration examples.

## Annotations supported for instance creation

|vci.vke.volcengine.com/kube\-proxy\-enabled |false |Proxy can be disabled to reduce overhead and accelerate startup. Valid values:<br><br><br>* `false`: Do not install the proxy.<br><br>* `true`: (Default) Install the proxy. |no |No |
|vci.vke.volcengine.com/preferred\-instance\-family |vci.u1 |The **instance family** of the VCI.<br><br>You can specify multiple instance families (annotation values) with commas (`,`) as separators. |vci.vke.volcengine.com/stdlog\-max\-size |10Mi |The maximum capacity of container log files that can be stored in case of collecting standard output logs via a sidecar.<br><br><br>* Value range: 1 MiB to 1 GiB (that is, 1 MiB to 1024 MiB).<br><br>* The value format is `number + binary unit`. |vci.vke.volcengine.com/stdlog\-max\-line\-size |16384 |Maximum length for a single line of container standard output when collecting logs via a sidecar.<br><br><br>* Value range: 4096 to 1048576 bytes.<br><br>* The value follows the `number` or `number+binary unit` format. An example of the `number+binary unit` form is `100Ki`, which means 100 KiB.<br><br>* Default value: 16384. |no |[Collecting VCI container logs by using a sidecar](https://docs.byteplus.com/en/docs/vke/Collecting-VCI-container-logs-using-a-sidecar) |
|vci.volcengine.com/tls\-enable |false |Whether to collect VCI logs to TLS. |vke.volcengine.com/eviction\-grace\-period\-seconds |50 |Grace period for pod eviction. The value is in seconds. It is an integer from 1 to 60. |no |No |
|vci.vke.volcengine.com/resource\-tags |"cluster\-id:ccq\*\*\*\*,env:test" |Specify custom tags for the VCI to enable bill splitting of VCI resources by tag. The requirements for custom tags are as follows:<br><br><br>* The supported format is string.<br><br>* Each tag consists of a key\-value pair in the `key:value` format. Multiple tags are separated by commas (`,`). For example, `"cluster-id:****,env:test"` means that two tags are set for the VCI: `cluster-id:****` and `env:test`.<br><br>* The requirements for a tag key are as follows:<br><br>   * It must not start with `volc:` in any case.<br><br>   * It can only contain characters, digits, spaces, and special characters `_.:/=+-@`.<br><br>   * The length is limited to 1 to 128 characters.<br><br>* The requirements for a tag value are as follows:<br><br>   * This can be left blank.<br><br>   * Can only contain alphabetic characters, digits, spaces, and special symbols `_.:/=+-@`.<br><br>   * Its length does not exceed 256 characters.<br><br>* A single VCI supports up to 50 tags.<br><br>* Adding a tag with the same key as an existing tag key by using the annotation will overwrite the original tag value.<br><br>* Tag keys and values do not allow leading or trailing spaces. |no |[Tag-based bill splitting](https://docs.byteplus.com/en/docs/vke/Tag-based-bill-splitting-for-instances) |
|vci.vke.volcengine.com/project\-name |default |The name of the project to which the VCI belongs. |no |[Project-based bill splitting](https://docs.byteplus.com/en/docs/vke/Project-based-bill-splitting-for-instances) |
|vci.vke.volcengine.com/sysctls | |Modify VCI kernel parameters. Valid values:<br><br><br>* The valid value type is Map[String]String.<br><br>* Only the `vm.watermark_scale_factor` parameter is supported:<br><br>   * The kernel parameter `watermark_scale_factor` adjusts the differences between the `min`,` low`, and` high` values to handle situations where the service suddenly requests memory. For more information, see the [kernel documentation](https://sysctl-explorer.net/vm/watermark_scale_factor/).<br><br>   * Default value: 10.<br><br>   * A valid value is a positive integer from 1 to 1000. |no |[Creating general-purpose instances by specifying container vCPUs and memory](https://docs.byteplus.com/en/docs/vke/Creating-a-general-purpose-instance-based-on-specified-container-vCPUs-and-memory) |
|vci.volcengine.com/insecure\-registries |"registry1,registry:5000,registry:80" |Specify container registries for which TLS authentication is skipped. If you specify multiple container registries, separate them with commas (`,`). If the address of the image registry contains a port number, you also need to enter the port number. |no |[Pulling images from self-built image registries during the creation of instances](https://docs.byteplus.com/en/docs/vke/Pull_images_from_a_self-hosted_Container_Registry_when_creating_an_instance) |
|vci.volcengine.com/plain\-http\-registries |"registry1\-http,registry\-http:5000,registry\-http:80" |Specify image registries that are accessed via HTTP and separate multiple image registries by commas (`,`). If the address of the image registry contains a port number, you also need to enter the port number. |no |[Pulling images from self-built image registries during the creation of instances](https://docs.byteplus.com/en/docs/vke/Pull_images_from_a_self-hosted_Container_Registry_when_creating_an_instance) |
|vci.vke.volcengine.com/image\-cache\-id |imc\-3uqroqkx0i3j\*\*\*\*\*\*\*\* |Image cache ID specified for creating the VCI. |no |[Creating VCIs by using manually created image caches](https://docs.byteplus.com/en/docs/vke/Creating-a-VCI-instance-using-Manual-Image-Cache) |
|vci.vke.volcengine.com/ignore\-image\-cache\-unavailable |false |During VCI creation, if the image cache identified by the image cache ID does not exist or is unavailable, the image cache configuration will be ignored.<br><br><br>* **true**: (Default) Ignore it.<br><br>* **false**: Do not ignore it. If the image cache with the corresponding ID does not exist or is unavailable, the VCI creation will fail. |no |[Creating VCIs by using manually created image caches](https://docs.byteplus.com/en/docs/vke/Creating-a-VCI-instance-using-Manual-Image-Cache) |
|vci.vke.volcengine.com/kernel\-transparent\-hugepage |madvise |Whether the kernel uses Transparent Huge Pages.
