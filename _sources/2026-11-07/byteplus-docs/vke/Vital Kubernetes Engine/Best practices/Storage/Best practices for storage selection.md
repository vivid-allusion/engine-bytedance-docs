This topic mainly describes the method and considerations for selecting storage types, including TOS, FileNAS, and EBS, when you use VKE.

<span id=".5a2Y5YKo6K-05piO"></span>
## Storage description

Required storage types vary based on different types of businesses. The following content describes the differences and major usage scenarios of storage types provided by the  platform.


|**StorageClass type** |**Description** |**Advantages** |
|---|---|---|
|EBS |EBS provides block storage devices with high availability, high reliability, high performance, and elastic scalability. EBS devices can be used as extended disks for ECS and VCI.  For more information, see [EBS](https://docs.byteplus.com/en/docs/ecs/Overview-of-elastic-block-storage). |* **Superior performance**: All EBS service series are built on NVMe SSD hardware and accelerated with SPDK, with a single disk delivering tens of thousands of IOPS and sub\-millisecond latency to meet the high\-performance requirements of your business.<br><br>* **Elastic scaling**: EBS supports on\-demand adjustment of cloud disk capacity for elastic scale\-out, which meets the requirements of rapidly growing businesses.<br><br>* **Efficient management**: EBS provides multiple management methods, such as the console and OpenAPI. These methods enable users to easily use and manage cloud disks and effectively reduce labor costs.<br><br>* **Stability and reliability**: Cloud disks adopt a multi\-replica redundancy mechanism to prevent single points of failure for data, which provides data reliability of 99.9999999% (nine 9's). This ensures data security and reliability. |
|FileNAS |FileNAS provides a high\-performance, cost\-effective cloud file storage service with shared access, continuous online availability, elastic scalability, and cross\-region access for elastic computing, container services, and AI applications. In addition, FileNAS provides easy\-to\-use APIs, supports the pay\-as\-you\-go billing method, eliminates deployment and maintenance costs, and maximizes business efficiency.  For more information, see [FileNAS](https://docs.byteplus.com/en/docs/nas/What-is-FileNAS). |* **Multi\-scenario support**: It meets multiple storage I/O requirements, including OPS for hundreds of billions of files, high\-bandwidth read/write for large files, and low\-latency access for small I/O operations, which makes it applicable to various business applications and services.<br><br>* **Protocol compatibility**: It is compatible with POSIX semantics and supports NFSv3 and v4 protocols, which enables you to use the cloud storage system in the same way as local storage.<br><br>* **Shared access**: It supports application\-level data sharing and enterprise\-grade data management, which achieves collaboration across multiple terminals and data sharing.<br><br>* **Access security**: It provides various permissions and multiple back\-end data protection mechanisms to ensure overall data access security.<br><br>* **Supreme performance**: Built on distributed architecture, its performance is nearly linearly improved, which meets the storage requirements for high IOPS, low latency, and high bandwidth.<br><br>* **Dynamic monitoring**: It provides basic service metrics, which help you know service access situations in a timely manner and perform dynamic monitoring. |
|TOS |TOS provides distributed cloud storage that is unlimited, secure, low\-cost, easy to use, highly reliable, and highly available. You can use TOS by using various methods, such as RESTful APIs, SDKs, and tools. You can manage and access data in TOS over the network without limits on applications, time, and places. For more information, see [TOS](https://docs.byteplus.com/en/docs/tos/docs-what-is-tos). |* **Massive scale**: Leveraging self\-developed distributed object storage technology and advanced architecture and technical support, TOS has deployed tens of thousands of object storage machines, with a total storage capacity exceeding the EB level. Traditional self\-built TOS systems have limited scalability in terms of the number of nodes, which makes it difficult to meet scalability requirements at the 100 PB level. In addition, metadata management for buckets and objects encounters issues, such as low concurrent write performance per bucket and a limited number of objects per bucket. TOS provides unlimited storage capacity for each bucket, which helps you manage and store massive amounts of data in an easy way.<br><br>* **High durability**: TOS adopts a distributed architecture, where data of each object is redundantly stored across multiple facilities and devices in the same region, which ensures high data durability in the event of hardware failure. The system periodically verifies data integrity by using methods, such as validation, to promptly detect data corruption caused by issues, such as hardware failures. When data corruption or loss is detected, the system uses redundant data to reconstruct and repair the corrupted data. In addition, TOS supports cross\-region data replication for geo\-disaster recovery. TOS provides data reliability of 99.999999999% (eleven 9's).<br><br>* **High security**: For data access, TOS provides multi\-layered security protection. All buckets and objects can be configured with IAM policies such as ACLs. Connections support SSL encryption. The system performs identity verification on users. These ensure data security. |

## Scenario selection


|Item |FileNAS |EBS |TOS |
|---|---|---|---|
|Usage method |It is compliant with standard file protocols. Users can mount file systems to ECS instances and use the file systems in the same way as using local file directories. |Users can perform operations in the same way as using traditional server disks, such as formatting block storage (disks) mounted to ECS instances, and creating file systems. |TOS provides standard RESTful APIs to enable users to access TOS through programming or third\-party tools. |
|Sharing method |Data sharing is supported across multiple servers. Multiple servers can mount the same file system, which achieves shared operations and access to the data. |Data is not shared, or multiple servers share a volume in special cases. Each server uses independent block storage (disk), and data is isolated between servers. |Data sharing is not restricted by device type. Servers, embedded devices, and IoT devices can access shared TOS data by calling the same path. |
|Scenario comparison |FileNAS applies to scenarios, such as enterprise OA, AI training, portal websites, gaming, DevOps, container microservices, and rendering. |EBS applies to scenarios, such as relational databases, NoSQL databases, ELK distributed log search, enterprise OA applications, data warehouses, and high\-performance computing. |TOS applies to scenarios, such as Internet applications, OTT videos, video surveillance, backup/archiving, and big data/IoT. |
