## Overview

To end users, personalized recommendations often feel like a black box. They see "You may also like" but have no idea why this particular batch of items was picked, so if nothing catches their eye they just scroll past, and there's no second chance to win them over. Operations teams are in a similar spot: they can only tune results indirectly through broad A/B tests and have no way to attribute an individual recommendation.

The Recommendation Assistant uses a large language model (LLM) to write a short, easy\-to\-read analysis of why a batch of items was recommended, and suggests questions the user can ask next:


* **For end users:**  A personalized analysis card appears on the recommendation results page.

   * It opens with 1–2 sentences summarizing what the items in this batch have in common (category, use case, audience, price range, etc.), then groups them into bullet points by use case, audience, or key need, so users can quickly spot what fits them.

   * The bottom of the card offers 3 progressive follow\-up questions. Tapping one opens a conversation where the user can keep narrowing down their choice.

* **For operations teams:**  Configure the assistant's identity, response style, and follow\-up tendency visually in the console. Adjust persona, tone, and follow\-up logic without shipping a new release, and check the result instantly in the preview pane.

* **For developers:**  The analysis is returned on demand through a separate streaming API. Item cards render first and the analysis streams in afterwards, so item exposure is never blocked. See [RecReason - Recommendation Assistant](https://docs.byteplus.com/docs/undefined/6abcbeb045a6760556079235).

## How it relates to item\-level recommendation reasons

The Recommendation Assistant and [Item-based Recommendation Reason](https://docs.byteplus.com/docs/viking-aisearch/Item-based_Recommendation_Reason) are complementary and can be enabled together. The assistant looks at the whole batch and groups and summarizes it, helping users understand the recommendation logic and narrow their options. Item\-level reasons explain how each individual item matches the user's needs, giving users more confidence to buy.


|**Dimension** |**Item\-level recommendation reason (Template mode)**  |**Recommendation Assistant (LLM mode)**  |
|---|---|---|
|Granularity |One short line per item (20 characters or fewer recommended) |One analysis for the whole batch + 3 follow\-up questions |
|How it's generated |Preset templates per recall channel + variable filling |Generated by an LLM from a prompt; personalized and more natural |
|How it's returned |Embedded in the Recommend API response; no extra call |Separate streaming API, fetched asynchronously after item cards render |
|Main inputs |Recall channel, item metadata, trigger entity |User profile, item info, recall channels and reasons, scenario, operations context |
|Latency |Milliseconds; computed together with the main recommendation pipeline |Streamed |
|Billing |No extra charge |Billed per conversation (each successful generation counts as 1 conversation) |
|Failure handling |Returns generic fallback text when no template matches |Returns the matching fallback text on rate limiting, errors, content moderation, or timeout; item cards already shown are unaffected |
|Configuration guide |[Item-based Recommendation Reason](https://docs.byteplus.com/docs/viking-aisearch/Item-based_Recommendation_Reason) |This page |

## Scope

The Recommendation Assistant is configured on top of an existing recommendation scenario. Before you start, make sure that:


* You have completed the [Prerequisites and setup](https://docs.byteplus.com/docs/viking-aisearch/Configuration_Setup) and created a working recommendation scenario (home page, item detail page, etc.).

* The scenario is linked to an item dataset. For personalized analysis based on user profiles, we recommend also linking and activating a user behavior dataset.


The Recommendation Assistant is configured per scenario: each scenario has its own toggle and its own persona configuration.

&nbsp;

**The feature is off by default. ** 

Once enabled, it is billed per conversation, so evaluate it against your business needs before turning it on.

## Glossary


|**Term** |**Description** |
|---|---|
|Recommendation Assistant |An LLM\-powered assistant on the recommendation results page that explains why items were recommended. It only explains items already recommended in this round. It never adds or re\-ranks items. |
|Trigger Recommendation Assistant |Toggle inside a recommendation scenario in the console that controls whether LLM recommendation analysis is enabled. Off by default. |
|Assistant identity |One of the persona settings. Defines who the assistant is and the limits of its role (e.g. "a neutral, professional shopping analyst"). |
|Response style |One of the persona settings. Defines the language, tone, opening, grouping dimensions, and anything the assistant must not say. |
|Follow\-up tendency |One of the persona settings. Defines the tone, number, progression logic, and binding requirements of the follow\-up questions (`suggestions`) at the bottom of the card. |
|Recommendation follow\-up |The multi\-turn conversation that starts when a user taps a follow\-up question. The chat API answers based on the current batch of recommended items and does not trigger search recall. |
|`session_id` |Session ID returned by the Recommendation Assistant. Pass it to the chat API to continue the conversation with the same recommendation context. |
|SSE |Server\-Sent Events, a streaming protocol. The analysis is pushed chunk by chunk over SSE so clients can render it token by token. |
|Fallback text |Safe text returned when the model is rate\-limited, fails, triggers content moderation, or times out, so users always see something useful. |

### Trigger Recommendation Assistant

Located at the top of the configuration area. Off by default. **This setting only affects the console preview. I**t does not affect API calls or responses.


* **When turning it on:**  A prompt explains that the assistant's recommendation analysis will be returned and billed per conversation. When turning it off, the prompt explains that the analysis will no longer be returned.

* **When it's off:**  The  **✨ Smart analysis of your preferences** card is hidden, the streaming API isn't called, and no charges apply.


<span id="662892fd"></span>
### Persona configuration

The three settings are "supplementary slots" layered on top of the built\-in system prompt. Underlying rules such as the JSON output format, citation rules, language locking, compliance guardrails, and fallback strategy are handled by the system. You only need to focus on persona, tone, explanation angle, and follow\-up quality.

To add extra business requirements, logic, or knowledge, click **Edit** in the bottom\-right corner of a block.


|**Block** |**Purpose** |
|---|---|
|Assistant identity |Defines who the assistant is, what it can do, and what it can't do. |
|Response style |Defines the language and writing conventions for the analysis. |
|Follow\-up tendency |Defines how the follow\-up questions at the bottom are generated. |

### Setup steps


1. In the console, go to **Experience Configuration \> Recommendation Experience**, select the target recommendation scenario, and open the **Recommendation Assistant** tab on the left.

2. Turn on **Trigger Recommendation Assistant**, then read and confirm the billing notice.

3. (Optional) Expand **Assistant identity**, **Response style**, and **Follow\-up tendency**, click **Edit** to adjust the text for your business, then save.

4. Check the result in the preview pane in the middle. A  **✨ AI\-driven recommendation reason** card appears below the results page title, with the analysis streaming in token by token.


<div style="text-align: center">
<img src="https://p9-arcosite.byteimg.com/obj/tos-cn-i-goo7wpa0wc/9b14941caa284678a1bb33205abb2521" width="550px" /></div>


The card contains the following elements:


|**Element** |**Description** |
|---|---|
|Analysis |Opens with what the batch has in common (1–2 sentences on category / use case / audience / price range), then groups items into bullet points by use case and differences. <br><br>The text streams in token by token and includes inline citation tags when it mentions specific items. |
|Follow\-up questions |Progress from category/use case → specific attributes → comparison/decision, e.g. "Show more ladylike work bags", "Cowhide leather work bags", "Compare bags by material". <br><br>Tapping one opens the chat experience and passes the context to the chat assistant automatically. |



   * Click **Regenerate** in the title area to generate a new analysis and follow\-up questions.

   * Click any follow\-up question at the bottom of the card to open the **Q&A** experience. The system fills in the `sessionId` and the question and sends it automatically. The answer is based on the current batch of recommended items.

   * Click **Collapse** to fold the analysis card.

   * Open **Call History** on the left to view request logs for the streaming API, which helps with troubleshooting.

5. When everything looks right, click **Update Configuration** in the top\-right corner to publish. The configuration only takes effect for production API requests after you publish.

## API integration

> **Note:**  For full fields and examples, see [RecReason - Recommendation Assistant](https://docs.byteplus.com/docs/undefined/6abcbeb045a6760556079235)


The core integration flow:


1. The client calls the [Recommend](https://docs.byteplus.com/docs/viking-aisearch/Recommendation) API to get the item list and renders the item cards first.

2. If the Recommendation Assistant is enabled for the scenario, the client then calls the Recommendation Assistant streaming API asynchronously. The request body carries the user ID, the recommended items returned in the previous step, and optional business context.

3. The API streams back, in order: session init (`session_id`) → reply start → content chunks → follow\-up suggestions → end marker.

4. When the user taps a follow\-up question, call the [ChatSearch](https://docs.byteplus.com/docs/viking-aisearch/ChatSearch) API with `is_recommend=true`, the dataset ID, and the list of recommended items to start a multi\-turn conversation.


<span id="39511bca"></span>
### Handling follow\-up questions (chat integration)

> **Note:**  For API parameters and integration details, see [RecReason - Recommendation Assistant](https://docs.byteplus.com/docs/undefined/6abcbeb045a6760556079235)


When the user taps a follow\-up question, the page switches to the **Q&A** chat view and automatically carries:


* The follow\-up question

* A flag indicating that the recommended items should be used as the reference source for context

* The current batch of recommended items and their recall information


Once the chat API recognizes a recommendation follow\-up request, it skips search recall and uses the recommended items passed in as the reference source, combined with the conversation history. Answers therefore always stay focused on the current batch and never drift to unrelated items.

Later turns can reuse the returned `sessionId` so the conversation keeps its context.

## Billing and performance

<span id="31b7d19b"></span>
### Billing

The Recommendation Assistant is billed per conversation. Each successful call to the streaming API that starts generating content counts as 1 conversation. It is not billed by token. When the toggle is off, the API isn't called and no charges apply.

Requests where the model produces no content, for example because of rate limiting or timeouts, don't count as valid conversations and are not charged.

Recommendation follow\-ups use the chat API's existing per\-conversation billing.

<span id="311cf3d8"></span>
### Fallback and error handling

In the cases below, the Recommendation Assistant doesn't throw an error or block the main recommendation pipeline. Instead, it returns the corresponding fallback text in the analysis area.


|**Case** |**Fallback text** |
|---|---|
|Model rate\-limited |Lots of people are asking right now. Try again in a bit, or check out the recommendations below. |
|Model call error |Sorry, I lost my train of thought there and couldn't answer properly. Try asking another way, or take a look at the items picked for you below. |
|Content moderation triggered |Take a look at the items we picked for you below! |
|Timeout / generic fallback |Sorry, I couldn't answer properly this time. Take a look at the items picked for you below. |
|No recommended items, or not enough information |Returns generic fallback text and only 1 generic follow\-up question (e.g. "See more categories"), rather than forcing an analysis. |

## FAQ

**Q: How does the Recommendation Assistant relate to item\-level recommendation reasons? Do I have to pick one?** 

A: They complement each other and can be enabled together. 


* An item\-level reason is a short template line under each item card, returned with the main Recommend API at no extra charge. 

* The Recommendation Assistant is an LLM analysis card plus follow\-up questions for the whole batch, returned through a separate streaming API and billed per conversation. 

* Turning off the Recommendation Assistant doesn't affect item\-level reasons.


&nbsp;

**Q: Can I still call the API after turning off the toggle in the console experience page?** 

A: Yes. The setting only affects the console experience page. It doesn't affect API calls or responses.

&nbsp;

**Q: Why isn't the "Smart analysis of your preferences" card showing on the client?** 

A: Check the following in order:


1. Is **Trigger Recommendation Assistant** turned on for the scenario, and did you click **Update Configuration** to publish?

2. Does the client call the `rec_reason` streaming API after the Recommend API returns?

3. Did the request hit a rate\-limit, content\-moderation, or timeout fallback? In that case, fallback text is shown instead of the analysis.

4. Has the account's conversation quota run out?


&nbsp;

**Q: Does the Recommendation Assistant add or re\-rank recommended items?** 

A: No. It only explains the items already returned by the Recommend API. It doesn't add items or change their order, and it never makes up information that isn't in the item data, such as price, stock, reviews, or specs.

&nbsp;

**Q: How long do persona changes take to apply?** 

A: Edits apply to the console preview immediately. Production API requests only use the new configuration after you click **Update Configuration** to publish.

&nbsp;

**Q: Why don't follow\-up questions trigger a new search?** 

A: Tapping a follow\-up question starts a "recommendation follow\-up". When the chat API receives `is_recommend=true` and the current batch of recommended items, it skips search recall and answers using those items as the reference source, so the answer stays focused on the current recommendations.

&nbsp;

**Q: Am I charged on every refresh?** 

A: Each successful analysis counts as 1 conversation. Clicking **Regenerate** calls the API again and is billed. Requests that produce no content because of rate limiting or timeouts are not charged.

&nbsp;

**Q: Which languages does the analysis support?** 

A: Chinese, English, Japanese, Korean, and Hindi are supported by default. The output language follows the application language automatically or prompt requirements.
