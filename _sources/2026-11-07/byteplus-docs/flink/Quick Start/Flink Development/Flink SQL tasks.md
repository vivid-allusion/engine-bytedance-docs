In the Flink console, you can create Flink SQL tasks to continually process and output results by expressing business logic through simple SQL statements.

This article demonstrates how to develop Stream\-type SQL tasks using a simple example. For information on Batch SQL tasks, please refer to [Develop Flink Batch SQL tasks.](https://docs.byteplus.com/docs/flink/Create_Flink_SQL_Job#e5e4a6a7)

<span id="0d153096"></span>
## Prerequisites

The project administrator (Project_Admin) has already created a Flink resource pool within the project, please refer to [创建资源池](https://docs.byteplus.com/docs/flink/Create_Resource_Pool).

<span id="9372c9a6"></span>
## Experience process

The development process of Flink SQL tasks is generally divided into two phases: the development phase and the operations phase, each with distinct members and primary responsibilities.


* **The development phase**: Typically, developers (Project_Dev) are responsible for developing SQL tasks, and after completion of development and debugging, they launch the tasks into the production environment.

* **The operations phase**: Typically, operations staff (Project_OPS) are responsible for starting the tasks and monitoring their execution.


<span id="e6902550"></span>
## Step one: Develop SQL tasks.


1. Log into [BytePlus Flink Console](https://console.byteplus.com/flink/region:flink+cn-hongkong).

2. Select the target region from the top menu bar.

3. In the left sidebar, select **Project Management**, search for projects by project name using the search box, and then click on the project block to enter the project.

4. Select **Job Development** in the project's left sidebar.

5. In the **Job Development** page, click the plus button to create a task.

   You can also choose the target folder and directly create a task within it; or simply click under **Flink Task** on **Flink SQL**.


<span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/f09baec4f03f4f18b90dbe78161a4a81~tplv-goo7wpa0wc-image.image) </span>


1. In the **create task** dialog, set task name, task type, assigned folder, engine version, and other parameters, then click **OK**


<span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/a4f4b27ef20c45ddb0956b741cbc725e~tplv-goo7wpa0wc-image.image) </span>


|**Configuration** |**Description** |
|---|---|
|Task Name |Set a custom name for the task.<br><br>The name must be 1 to 48 characters in length, supporting numbers, uppercase and lowercase letters, underscores (_), hyphens (\-), and periods (.). It must start and end with a letter or number. |
|Task Type |Select **Flink task \> Flink Stream \> SQL**.<br><br>If you want to experience the development process of a JAR task, please refer to [开发JAR 作业](https://docs.byteplus.com/docs/flink/Flink_JAR_Tasks). |
|Parent Folder |The system provides folder management functionality to categorize and manage tasks. During the task development experience, you can directly choose the **Data Development Folder** that already exists in the system.<br><br>If you have requirements to manage tasks with custom folders, click the create folder button, then create the folder. |
|Engine Version |Currently supported versions include BytePlus Flink 1.11\-byted, BytePlus Flink 1.16\-byted, and BytePlus Flink 1.17\-byted. Please choose as needed. |
|Task Description |Enter a description of the task, typically describing the functionality it implements. |



3. Edit the business logic code of SQL tasks in the task editing area.

   Here is a sample SQL task code. The code means: Create a new datagen source table that generates random data, count the occurrences of words in the word field generated by the datagen source table, and write the results to the data result table.

   ```SQL
   create table doc_source (word varchar)
       WITH (
           'connector' = 'datagen',
           'rows-per-second' = '5',                
           'fields.word.length' = '30'         
           );
   create table doc_result (word varchar, cnt bigint)
       WITH (
           'connector' = 'print'
           );
   insert into
       doc_result
   select
       t.word,
       count (1)
   from
       doc_source t
   group by
       t.word;
   ```
   

4. Click the **format** button to automatically adjust the SQL code format.

   The system will automatically beautify your SQL statements, making them more aesthetically pleasing, neat, and readable.

5. After editing the SQL task code, click the **verify** button.

   The system will automatically verify the correctness of your SQL statements. If there are errors, please modify the SQL statements according to the prompts independently. After passing the check, the system will display `success`.

6. After completing code editing and verification, click the **save** button to save the task code.

## Step Two: Debug SQL Tasks

The system verification function can only validate the correctness of SQL syntax, not entirely prevent potential errors during code execution. Hence, debugging tasks before going live is strongly recommended.

The Session cluster is used for debugging tasks in a development environment. Supports using online data and offline files. Please choose the debugging method as needed.

<span id="e926bc18"></span>

1. At the top of the task editing area, click **Session** .

2. On the **Session Resource Pool** page, click **Create Resource Pool**.

3. In the **Create Resource Pool** panel, set the parameters for **Basic Configuration** and **Resource Configuration**, then click **Confirm**.

## Step Three: Launch SQL tasks.

Development is isolated from the production environment. Once the development personnel complete the task development and debugging, they can deploy the task to the production environment.


1. In the **Task Development** section, find and click the target task, then select the correct **execution method** and **engine version** above the editing area, and finally click **deploy**.

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">Flink Stream type tasks are set to execute as <strong>STREAMING</strong>; Flink Batch type tasks are set to execute as <strong>BATCH</strong>.   </div>
   

2. In the **Task Deployment Settings** dialog, select the runtime resource pool, set the task priority and scheduling strategy, then click **confirm**.

   The system will notify that the task has been successfully deployed, and you can go to the **Task Management** page to view it.


<span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/50c911cb7eba47af9c543399c6412e85~tplv-goo7wpa0wc-image.image) </span>


|**Configuration** |**Description** |
|---|---|
|Runtime Resource Pool |Select the Flink resource pool for the task to run from the dropdown list.<br><br><div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div><br><br><br><div data-tips="true" data-tips-type="warning">If the task you submitted is enabled for automatic tuning, it must run on a pay\-as\-you\-go type resource pool.</div><br> |
|Task Priority |The system’s default preset priority is L3. You can set the task priority as needed; the smaller the number, the higher the priority.<br><br>Task priority determines the internal scheduling order of the tasks, where tasks with higher priorities are scheduled first, meaning L3 is scheduled before L4. |
|Scheduling Strategy |Configure the task scheduling strategy according to needs:<br><br><br>* GANG: Ensures that all instances of a task are scheduled together, i.e., allocation only occurs when remaining resources meet the resources needed for normal operation of the task; if not, resources are not allocated.<br><br>   This strategy prevents the issue of resources being allocated but the task failing to start, thereby solving resource deadlock problems.<br><br>   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div><br>   <br><br>   <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">Flink Batch tasks do not support the GANG scheduling strategy, only the DRF scheduling strategy. Execution method is selected as Batch, and the online configuration page will not display the GANG strategy.   </div><br>   <br><br>* DRF: Considers multi\-dimensional resources to more fairly distribute resources among tasks in the resource pool, thereby enhancing utilization.<br><br>   For example: remaining resources of 10 cores and 40 GB, Task A requires 10 cores and 20 GB; Task B requires 2 cores and 8 GB. If allocated to Task A, the remaining 0 cores and 20 GB cannot be utilized; the DRF policy would choose to allocate to Task B, leaving 8 cores and 32 GB for subsequent tasks. |
|Scheduling Duration |When set to GANG scheduling policy, it is necessary to set a scheduling duration. Scheduling duration refers to the interval between rescheduling attempts, meaning if a task fails to start, it will be retried.<br><br>If the scheduling duration is exceeded, the task will fail to schedule. If set to 0, it will retry indefinitely. |
|Additional Configuration |SQL tasks support skipping in\-depth checks before going live, allowing tasks to be forcibly launched.<br><br>Not selected by default. Selecting **Skip Pre\-Launch Check** indicates that SQL code in\-depth checks will be bypassed, and the task will be deployed directly. |

## Step Four: Start the SQL Task

Development is isolated from the production environment. After deploying the task to the production environment, the operations personnel will start the task.


1. In the left navigation bar of the project, select **Task Operations \> Task Management**.

2. On the **Task List** page, click **operate** in the **start** column.

3. In the **Start Task** dialog, select the task start method, then click **confirm**.

   Starting the task will take some time, please be patient. After successful startup, the status is **running**.

## Step Five: View Flink UI

After the task is running normally in the production environment, you can view detailed information about the task runtime, TaskManager, and JobManager on the Flink UI interface.


1. From the left navigation bar of the project, select **Task Operations & Management \> Task Management**.

2. On the **Task List** page, filter the target task and click under the **Actions** column on **Flink UI**.

   The browser will automatically open the Apache Flink Dashboard page.

3. In the left navigation bar of Apache Flink Dashboard, select **Task Managers**, and then click on the task ID.

   <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_bd42e006b174cc37b4bd767d59c18a0b.png) </span>

4. On the Task Manager details page for the task, click the **Stdout** tab, and then search for `successfully` in the logs to view the task execution results.

   <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_b479b6aa71786511e2ad320bb80b180e.png) </span>
