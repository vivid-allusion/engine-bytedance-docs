Google Protocol Buffer (commonly abbreviated as Protobuf) is an internal hybrid\-language data standard of Google, mainly used in RPC systems and persistent data storage systems. Protobuf format can read and write Protobuf data based on classes generated by Protobuf.

<span id="dd0f2d10"></span>
## How to Create a Table Using Protobuf Format

Here is an example of creating a table with Kafka connectors and Protobuf format.

Here is the proto definition file:

```ProtoBuf
syntax = "proto2";
package com.example;
option java_package = "com.example";
option java_multiple_files = true;

message SimpleTest {
    optional int64 uid = 1;
    optional string name = 2;
    optional int32 category_type = 3;
    optional bytes content = 4;
    optional double price = 5;
    map<int64, InnerMessageTest> value_map = 6;
    repeated  InnerMessageTest value_arr = 7;
    optional Corpus corpus_int = 8; 
    optional Corpus corpus_str = 9; 
    
    message InnerMessageTest{
          optional int64 v1 =1;
          optional int32 v2 =2;
    }
    
    enum Corpus {
        UNIVERSAL = 0;
        WEB = 1;
        IMAGES = 2;
        LOCAL = 3;
        NEWS = 4;
        PRODUCTS = 5;
        VIDEO = 7;
      }
}
```



1. Use the `protoc` command to compile `.proto`files into Java classes.

2. Then compile and package these classes (without packaging the original Java into a jar).

3. Finally, you should provide the `jar` package in the classpath, for example, use `-j`to pass it in the sql\-client.


```SQL
CREATE TABLE simple_test (
  uid BIGINT,
  name STRING,
  category_type INT,
  content BINARY,
  price DOUBLE,
  value_map map<BIGINT, row<v1 BIGINT, v2 INT>>,
  value_arr array<row<v1 BIGINT, v2 INT>>,
  corpus_int INT,
  corpus_str STRING
) WITH (
 'connector' = 'kafka',
 'topic' = 'user_behavior',
 'properties.bootstrap.servers' = 'localhost:9092',
 'properties.group.id' = 'testGroup',
 'format' = 'protobuf',
 'protobuf.message-class-name' = 'com.example.SimpleTest',
 'protobuf.ignore-parse-errors' = 'true'
)
```

## Format parameter


|Parameter |Required |Backward Compatible |Default Value |Type |Description |
|---|---|---|---|---|---|
|<span id="c08b92fc"></span><br>##### format |Required |no |(none) |String |Declare the format used, here it should be `'protobuf'`. |
|<span id="1d91e6d7"></span><br>##### protobuf.message\-class\-name |Required |no |(none) |String |Full name of the Protobuf generated class. The name must match the message name in the proto definition file. Inner class name supports `$`, such as "com.exmample.OuterClass$MessageClass" |
|<span id="c4def59f"></span><br>##### protobuf.ignore\-parse\-errors |Optional |no |false |Boolean |Optional flag used to skip records that encounter parsing errors, instead of failing. |
|<span id="1183f689"></span><br>##### protobuf.read\-default\-values |Optional |yes |false |Boolean |This option is only effective when the generated class version is proto2. If this value is set to true, the format will read null values as default values defined in the proto file. If this value is set to false, the format will produce null values when the data element is absent in the binary protobuf message. If the proto syntax is proto3, this value will be forcibly set to true, as the standard in proto3 is to use default values. |
|<span id="d0b7fb31"></span><br>##### protobuf.write\-null\-string\-literal |Optional |no |"" |String |This is an optional configuration when serializing to protobuf data, used to specify a string literal in Protobuf's array/map when a null value occurs. |

## Data Type Mapping

The table below lists the mappings from Flink types to Protobuf types.


|Flink SQL data type |Protobuf data type |Description |
|---|---|---|
|`CHAR / VARCHAR / STRING` |`string` | |
|`BOOLEAN` |`bool` | |
|`BINARY / VARBINARY` |`bytes` | |
|`INT` |`int32` | |
|`BIGINT` |`int64` | |
|`FLOAT` |`float` | |
|`DOUBLE` |`double` | |
|`ARRAY` |`repeated` |Elements cannot be empty and a default string value can be specified through `write-null-string-literal`. |
|`MAP` |`map` |Keys or values cannot be null, and a default string value can be specified through `write-null-string-literal`. |
|`ROW` |`message` | |
|`VARCHAR / CHAR / TINYINT / SMALLINT / INTEGER / BIGINT` |`enum` |The enum values in protobuf can be correspondingly mapped to strings or flink rows. |

## Precautions


* Cannot be empty.

   Since protobuf does not allow null values in mappings and arrays, default values are auto\-generated when converting from Flink Rows to Protobuf.

   
   |Protobuf data type |Default value |
   |---|---|
   |int32 / int64 / float / double |0 |
   |string |"" |
   |bool |false |
   |enum |first element of enum |
   |binary |ByteString.EMPTY |
   |message |MESSAGE.getDefaultInstance() |
   

* OneOf Type Fields.

   "oneof" is a special field type in protobuf that allows a message to be defined with only one non\-zero field. For example, in the message definition below, a Person can only have one type (email or phone):

   ```ProtoBuf
   message Person {
     oneof contact_info {
       string email = 1;
       string phone = 2;
     }
   }
   ```
   

   During serialization, it is not guaranteed that the Flink fields in the same oneof group contain at most one valid value. During serialization, each field is set according to the order of the Flink schema, so in the same oneof group, higher\-positioned fields are prioritized over lower\-positioned fields.
