Database Workshop (DBW) provides SQL insights and auditing, which helps you improve database performance and stability by capturing, reviewing, and analyzing all SQL statements. This topic describes the precautions, advantages, and operation steps for enabling, disabling, and viewing SQL insights and auditing.

## Background

SQL insights and audit includes database audit and full SQL insights. SQL insights and auditing is based on database audit. Therefore, when full SQL insight is enabled, database audit is enabled by default.

The SQL insights and auditing function supports automatically recording and analyzing SQL statements generated by the database kernel, including information such as the execution account, IP address, and implementation details. SQL statement types include `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `ALTER`, `CREATE`, `DROP`, `RENAME`, `TRUNCATE`, and `OTHER` (all other SQL types).

Currently, database audit has been launched in all regions, while the full SQL insight feature is only available in China regions China (Beijing), China (Shanghai), China (Guangzhou), and overseas region Asia Pacific (Johor). For billing information about SQL insights and auditing, see [Billing items and prices](https://docs.byteplus.com/en/docs/DBW/postgresql-billing-items-and-price#.6K6h6LS56KeE5YiZ).

## Advantages

* **Low CPU consumption**: SQL statements are generated by the database kernel, resulting in very low CPU resource consumption on the system.

* **Comprehensive perspective**: Full SQL insight captures and analyzes all SQL statements running in the database instance, providing you with a comprehensive perspective that can be used to identify performance bottlenecks in the database instance.

* **Problem locating and diagnosis**: By analyzing real\-time monitoring and historical trends, full SQL insight helps you locate and diagnose problems in database instances, such as slow queries and concurrent deadlocks.

* **Database structure optimization**: The full SQL Insight feature provides information such as which tables are frequently used and which SQL statements consume the most resources, thereby helping you improve the structure of your database.

* **Database availability and stability improvement**: Full SQL insight can help you better understand the overall operating status of the database instance, thereby improving the availability and stability of the database.

## Precautions

* Prerequisites for enabling the feature

   * Disable the legacy database audit feature before enabling SQL insights and auditing.

   * If you have enabled "Database audit" or "Full SQL insight" separately, first disable "Full SQL insight" in the service settings, then re\-enable the "SQL insights and auditing" feature to ensure consistent configuration.

* Data Accuracy Description

   * SQL insights and auditing data is generated from database kernel analysis and may be affected by the following factors:

      * Limitations of the kernel collection mechanism itself;

      * When the query result set is too large, it may lead to incomplete or inaccurate statistical information.

   * Actions such as deleting databases or users executed in the Database engine console are not recorded in DBW's SQL Audit; only actions executed through the DBW console are recorded.

* Storage resources

   * Storage location: SQL audit data is stored by DBW and does not occupy the storage space of the database instance itself.

   * Hierarchical storage policy

      Audit logs beyond the standard retention period are automatically moved to infrequent access storage:

      * Infrequent access storage is much cheaper than standard storage. It is designed for long\-term archiving and historical logs that are rarely accessed.

      * While there may be minor Retrieval fees when accessing the data, the total cost remains far lower than maintaining it in standard storage over the long term.

      * Ensures data accessibility while effectively lowering long\-term storage expenses.

* Data retention and deletion risks

   * After disabling SQL insights and auditing, all historical data will be permanently cleared.

      Download required data to your local device before disabling to prevent irreversible loss.

   * If a database instance is deleted, its associated database audit and full SQL insight features will be automatically disabled and data will be cleared.

* SQL statement length limit

   The system records a maximum of 8 KB (8,192 bytes) for an SQL statement. Any content beyond this limit is truncated. The actual recorded length is controlled by the instance parameters:

   * If the parameter value is ≤ 8 KB, it serves as the upper limit.

   * If the parameter value is \> 8 KB, the upper limit remains 8 KB.

   Because the system adds an internal prefix identifier during collection, the actual length of SQL that can be recorded is slightly less than the set value.

## FAQs

**Q: What is the relationship between database audit, SQL insights and auditing, and full SQL insight?**

The relationship between the three is as follows:

   |**Function** |**Description** |
   |---|---|
   |**Database audit** |The SQL detail in the database audit function is not the full SQL. |
   |**Full SQL insight** |Full SQL insight can collect all SQLs and perform analysis based on all SQLs. With a greater focus on performance, see DBW's full SQL insights into analytics practices for more value. |
   |**SQL insights and auditing** |SQL insights and audit includes database audit and full SQL insights. SQL insights and auditing is based on database audit. Therefore, when full SQL insight is enabled, database audit is enabled by default. |

Q: **Before enabling SQL insights and auditing, why do I need to disable the old or V1 version of database audit?**

The old version of database audit (V1) is charged by TLS, while the new version of database audit (V2) is charged by DBW. Since the new version of database audit (V2) must be enabled when enabling SQL insights and auditing, you need to disable the V1 version of data audit to avoid being charged for both V1 and V2 versions of database audit.

Q: **In SQL insights and auditing, I have only enabled database audit. If I want to enable Full SQL insight, how do I do it?**

You can enable the full SQL insight function through service settings. For more information, see [Set SQL insights and auditing](https://docs.byteplus.com/en/docs/DBW/SQL_insights_and_auditing#NO2qCfaP).
