Database audit provides fine\-grained recording and real\-time monitoring of all database operations, supporting the viewing of core indicators such as execution level, execution time, and operation type. This feature helps you fully understand the database running status, quickly locate anomalies, and accurately trace non\-compliant operations. It enables full\-link traceability of data access and changes, effectively ensuring data security and meeting compliance management and risk prevention requirements.

<span id="7a1j3sX2"></span>
## Prerequisites

An instance for Cache for Redis has been created. For detailed steps, see [Creating an instance](https://docs.byteplus.com/en/docs/redis/create-instance?lang=en).

<span id="uxLtJybl"></span>
## Precautions


* This feature is currently in the beta testing phase. To use it, [Submit ticket](https://console.byteplus.com/workorder/create/).

* To upgrade the proxy of an instance, [Submit ticket](https://console.byteplus.com/workorder/create).

* Data node audit and proxy node audit cover different scopes. They are complementary and cannot replace each other. It is recommended to enable both for complete audit coverage.

* If the client directly connects to the data engine (bypassing the Proxy), the related commands and data operation logs will not be audited by the proxy node, which may result in incomplete audit coverage.

* Modify the audit node scope: After canceling the audit of a single node, the audit logs generated by that node will be permanently deleted and cannot be recovered. If the audit of all nodes is canceled, the database audit function of the instance will be disabled and all audit data will be emptied. This action is irreversible. Proceed with caution.

* Disable database auditing: After disabling, all audit logs of data nodes and proxy nodes will be immediately deleted and cannot be recovered. It is recommended to export and back up important logs before proceeding.

* The default retention period for audit logs is 30 days. You can adjust it as needed.

## Enable database audit


1. Log on to the [DBW console](https://console.byteplus.com/dbw).

2. On the top menu bar, select the region.

3. On the left navigation bar, select **Operation and maintenance management** \> **Observation and diagnosis**.

4. On the observation and diagnosis page, click **Database audit**, and switch the database type and instance:

   1. In the upper\-right corner of the page, switch the database type to **Cache for Redis**.

   2. In the upper left corner of the page, switch the target instance. You can search for target instances using the instance ID.

5. On the **Database audit** tab, configure the following information:

## Modify database audit


1. Log on to the [DBW console](https://console.byteplus.com/dbw).

2. On the top menu bar, select the region.

3. On the left navigation bar, select **Operation and maintenance management** \> **Observation and diagnosis**.

4. On the observation and diagnosis page, click **Database audit**, and switch the database type and instance:

   1. In the upper\-right corner of the page, switch the database type to **Cache for Redis**.

   2. In the upper left corner of the page, switch the target instance. You can search for target instances using the instance ID.

5. On the **Database audit** tab, click **Service settings**.

6. In the **Service settings** dialog box, configure the following parameters:

   * **Audit node scope**: Add or remove data node audit or proxy node audit, and modify the audit log retention period for both types of nodes.

      After audit is disabled for a single node, the audit logs generated by that node are permanently deleted and cannot be recovered. If audit is disabled for all nodes, the database audit function of the instance is disabled and all audit data is emptied. This action is irreversible. Proceed with caution.
