Database Workshop (DBW) provides a slow log diagnosis feature, which analyzes the Top 200 slow logs generated on the previous day and offers diagnostic results and optimization suggestions to help improve database performance and stability.

This topic describes how to enable the slow log diagnosis feature and view the diagnostic results and optimization suggestions on the DBW console.

<span id="DQi8cY88"></span>
## Function introduction

In slow log analysis, DBW collects slow log information from the database every day. The slow log diagnosis feature analyzes the Top 200 slow log information collected on the previous day around 8:00 A.M. every day and provides diagnostic results.

In the diagnostic results, DBW provides suggestions for index creation and SQL rewriting, as well as recommendations.

<div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div>



* <div data-tips="true" data-tips-type="default">The total time consumption ratio is the percentage of the current SQL query time to the total SQL query time in all slow logs collected on the previous day.</div>


* <div data-tips="true" data-tips-type="default">Estimated performance improvement times after optimizing a single SQL template = Execution time before optimizing the current SQL template/Execution time after optimizing the current SQL template.</div>


* <div data-tips="true" data-tips-type="default">Total time consumption ratio income = Estimated performance improvement times after optimizing a single SQL template \* Total time consumption ratio before optimizing the current SQL template.</div>




|**Recommendation level** |**Description** |
|---|---|
|Extremely high |If the estimated total time consumption income after optimization is 15% or more, the recommendation level is extremely high. |
|High |If the estimated total time consumption income after optimization is 10% or more, the recommendation level is high. |
|Medium |If the estimated total time consumption income after optimization is 5% or more, the recommendation level is medium. |
|Low |If the estimated total time consumption after optimization is less than 5%, the recommendation level is low. |


You can refer to the recommendation level and the total time consumption ratio in the SQL list to make decisions on whether to create indexes and rewrite SQL statements.


|**Optimization suggestion** |**Reference factor** |
|---|---|
|Index creation suggestion |Recommendation level, estimated average execution time after optimization(s), estimated performance improvement times after optimization, and total time consumption ratio. |
|SQL rewrite suggestions |Recommendation level and total time consumption ratio |

## Precautions


* The slow log diagnosis feature can not analyze slow log information generated on the current day. Therefore, after you enable the slow log diagnosis feature, you can view the diagnosis results after 8:00 A.M. on the next day.

* Slow log diagnosis analyzes and diagnoses only the Top 200 slow logs (including `SELECT`, `UPDATE`, and `DELETE` SQL statements) generated by the current instance on a specific day.

* The slow log diagnosis feature needs to use SQL information in the database. Therefore, if you enable the slow log diagnosis feature, you are agreeing to collect SQL information in the database by default.

## Enable slow log diagnosis

You can enable slow log diagnosis for a single instance on the slow log diagnosis page, or batch enable slow log diagnosis for instances of the same type in the instance list.


<Tabs>
<Tab zoneid="XtwCtpaw17" title="Enable slow log diagnosis for a single instance">
<TabTitle>Enable slow log diagnosis for a single instance</TabTitle>

1. Log on to the [DBW console](https://console.byteplus.com/dbw).

2. On the top menu bar, select the project and region.

3. On the left navigation bar, select **Operation and maintenance management** \> **Observation and diagnosis**.

4. In the upper\-left corner of the **Operation observability** page, click the drop\-down icon and select the target instance.

   <div data-tips="true" data-tips-type="default" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   <div data-tips="true" data-tips-type="default" data-wrapper-indent="1">You can switch to the target instance by searching for the instance ID.   </div>
   

5. On the target instance page, click **Log management**.

6. On the **Log management** tab, click **Slow log diagnosis**.

   If slow log diagnosis is not enabled for the current instance, the page prompts you to enable it immediately.

7. Click **Enable now**.

8. In the **Slow log diagnosis form** dialog box, set the following parameters.

   
   |**Parameter** |**Description** |
   |---|---|
   |**Enable slow log diagnosis** |Click **Enable** to enable slow log diagnosis. |
   |**Diagnosis frequency** |Once a day and can not be modified. After enabling slow log diagnosis, DBW diagnoses the Top 200 slow logs generated on the previous day around 8 o'clock every day. |
   |**Diagnosis scope** |All slow logs from the previous day.<br><br>DBW automatically diagnoses the Top 200 slow logs of the previous day. For example, on June 25, 2025, DBW automatically diagnoses the Top 200 slow logs generated on June 24, 2025, and provides diagnosis results and optimization suggestions. |
   |**Diagnostic history retention period** |The retention period of the slow log diagnosis result is 30 days by default, and can not be modified. |
   |**Retention period for performance tracking** |After optimizing SQL based on optimization suggestions in the slow log diagnosis result, DBW continues to track the performance changes before and after SQL optimization. The performance change data before and after SQL optimization is retained for 30 days by default and can not be modified. |
   

9. Click **OK**.


</Tab>
<Tab zoneid="AwLNThBhx5" title="Batch enable slow log diagnosis">
<TabTitle>Batch enable slow log diagnosis</TabTitle>

1. Log on to the [DBW console](https://console.byteplus.com/dbw).

2. On the top menu bar, select the project and region.

3. On the left navigation bar, select **Instance list**.

4. On the **Instance list** page, select RDS for MySQL instances for which you want to enable slow log diagnosis, and click **Slow log diagnostic settings**.

   <div data-tips="true" data-tips-type="default" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   <div data-tips="true" data-tips-type="default" data-wrapper-indent="1">Currently, DBW only supports batch enabling of slow log diagnosis for databases of the same type.   </div>
   

5. In the **Slow log diagnosis form** dialog box, set the following parameters.

   
   |**Parameter** |**Description** |
   |---|---|
   |**Slow log diagnosis** |Click **Enable** to enable slow log diagnosis. |
   |**Diagnosis frequency** |Once a day and can not be modified. After enabling slow log diagnosis, DBW performs a daily diagnosis of the Top 200 slow logs generated the previous day. |
   |**Diagnosis scope** |All slow logs from the previous day (including `Select`, `Update`, and `Delete` SQL statement types).<br><br>DBW automatically diagnoses the Top 200 slow logs of the previous day. For example, if the current day is June 25, 2025, DBW automatically diagnoses the Top 200 slow logs generated on June 24, 2025, and provides diagnostic results and optimization suggestions. |
   |**Diagnostic history retention period** |The retention period of the slow log diagnosis result is 30 days by default, and can not be modified. |
   |**Retention period for performance tracking** |After optimizing SQL based on optimization suggestions in the slow log diagnosis result, DBW continues to track the performance changes before and after SQL optimization. The performance change data before and after SQL optimization is retained for 30 days by default and can not be modified. |
   

6. Click **OK**.


</Tab>

## Disable slow log diagnosis


1. Log on to the [DBW console](https://console.byteplus.com/dbw).

2. On the top menu bar, select the project and region.

3. On the left navigation bar, select **Operation and maintenance management** \> **Observation and diagnosis**.

   1. In the upper\-right corner of the page, locate the drop\-down list and select the target database type \- **RDS for MySQL**.

   2. In the upper\-right corner of the page, locate the drop\-down list and select the target instance.

4. On the **Operation observability** page, click **Log management**.

5. On the **Log management** tab, click **Slow log diagnosis**.

6. On the **Operation observability** tab, click **Service settings**.

7. In the **Service settings** dialog box, you can perform the following operations:

   
   |**Parameter** |**Description** |
   |---|---|
   |**Slow log diagnosis** |Click **Disable** to disable the slow log diagnosis. |
   

8. Click **OK**.

## View optimized performance tracking data

After the slow log diagnosis report is generated, DBW continues to track performance changes of slow logs within 7 days. If you optimize SQL following the optimization suggestions in the slow log diagnosis result, you can view the performance improvement after SQL optimization. SQL optimize performance tracking data is retained for 30 days by default and cannot be modified.


1. Log on to the [DBW console](https://console.byteplus.com/dbw).

2. On the top menu bar, select the project and region.

3. On the left navigation bar, select **Operation and maintenance management** \> **Observation and diagnosis**.

   1. In the upper\-right corner of the page, locate the drop\-down list and select the target database type \- **RDS for MySQL**.

   2. In the upper\-right corner of the page, locate the drop\-down list and select the target instance.

4. On the **Operation observability** page, click **Log management**.

5. On the **Log management** tab, click **Slow log diagnosis**. The slow log diagnosis page displays the slow log diagnosis results of the previous day by default. You can also set the slow log diagnosis range to view the slow log diagnosis results of a certain day.

   
   |**Actions** |**Description** |
   |---|---|
   |Set the slow log diagnosis range |DBW displays slow log diagnostic results from the previous day by default. You can filter slow log diagnosis data for a specific date as needed. |
   |View optimized performance tracking data |After the slow log diagnosis report is generated, DBW continues to track performance changes of slow logs within 7 days. If you optimize SQL following the optimization suggestions in the slow log diagnosis result, you can view the performance improvement after SQL optimization. You can view **inspection execution time**, **Instance ID**, **SQL template**, **suggestion**, **optimization execution**, **whether an index is created**, **whether slow SQL still exists**, **actual performance improvement multiple after optimization**, **difference in execution times before and after optimization**, **difference in CPU usage (%) before and after optimization**, and **difference in average execution time before and after optimization** in the optimize performance tracking list.<br><br><div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div><br><br><br><br>* <div data-tips="true" data-tips-type="default"><strong>Actual performance improvement multiple after optimization</strong> greater than 1 indicates a positive gain after optimization.</div><br><br><br>* <div data-tips="true" data-tips-type="default"><strong>Difference in execution times before and after optimization</strong> being negative indicates that the number of SQL statements classified as slow logs decreases after optimization.</div><br><br><br>* <div data-tips="true" data-tips-type="default"><strong>Difference in CPU usage before and after optimization</strong> being negative indicates that the 24\-hour average CPU usage of the instance decreases after optimization.</div><br><br><br>* <div data-tips="true" data-tips-type="default"><strong>Difference in average execution time before and after optimization</strong> being negative indicates that the average execution time of SQL decreases after optimization.</div><br> |
