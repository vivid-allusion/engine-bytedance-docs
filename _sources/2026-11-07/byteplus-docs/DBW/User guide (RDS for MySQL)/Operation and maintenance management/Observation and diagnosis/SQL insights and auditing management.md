Database Workshop (DBW) provides SQL insights and auditing, which helps you improve database performance and stability by capturing, reviewing, and analyzing all SQL statements. This topic describes the precautions, advantages, and operation steps for enabling, disabling, and viewing SQL insights and auditing.

## Background

SQL insights and audit includes database audit and full SQL insights. SQL insights and auditing is based on database audit. Therefore, when full SQL insight is enabled, database audit is enabled by default.

The SQL insights and auditing function supports automatically recording and analyzing SQL statements generated by the database kernel, including information such as the execution account, IP address, and implementation details. SQL statement types include `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `ALTER`, `CREATE`, `DROP`, `RENAME`, `TRUNCATE`, and `OTHER` (all other SQL types).

Currently, database audit has been launched in all regions, while the full SQL insight feature is only available in China regions China (Beijing), China (Shanghai), China (Guangzhou), and overseas region Asia Pacific (Johor). For billing information about SQL insights and auditing, see [Billing items and prices](https://docs.byteplus.com/en/docs/DBW/mysql-billing-items-and-price).

## Advantages

* **Low CPU consumption**: SQL statements are generated by the database kernel, resulting in very low CPU resource consumption on the system.

* **Provide a comprehensive perspective**: SQL insights and auditing can capture and analyze all SQL statements running in the database instance, providing you with a comprehensive perspective that can be used to identify performance bottlenecks in the database instance.

* **Problem locating and diagnosis**: By analyzing real\-time monitoring and historical trends, SQL insights and auditing can help you locate and diagnose problems with database instances, such as slow queries and concurrent deadlocks.

* **Optimize the database structure**: The SQL insight and auditing feature provides information such as which tables are frequently used and which SQL statements consume the most resources, thereby helping you improve the structure of your database.

* **Improve the availability and stability of the database**: SQL insight and auditing can help you better understand the overall operating status of the database instance, thereby improving the availability and stability of the database.

## Precautions

* Feature overview and dependencies

   * SQL insights and auditing generate operation information based on database kernel analysis. Data accuracy may be affected by the following factors:

      * Inherent limitations of kernel analysis itself;

      * When the data volume for a query is too high, it may lead to inaccurate statistics.

   * This feature is only supported for MySQL instances with a kernel version ≥ 20240415.

      You can use the command `SELECT @@byte_rds_version;` to check the current kernel version. Manual upgrade is required for older versions.

* Enable and disable mechanism

   * Enable conditions: Automatically enabled only when instance load is low; enabling may be delayed under high load.

   * Correlation:

      * When SQL insights and auditing is enabled, V2 auditing is automatically enabled.

      * When this feature is disabled, V2 auditing is also disabled.

   * Impact of disabling:

      * All stored SQL audit data will be completely cleared.

      * It is recommended to manually download important data before closing to avoid data loss.

   * Instance deletion: Automatically disables this feature and clears related data.

* Storage resources

   * Storage location: SQL audit data is stored by DBW and does not occupy the storage space of the database instance itself.

   * Hierarchical storage policy

      Audit logs beyond the standard retention period are automatically moved to infrequent access storage:

      * Infrequent access storage is much cheaper than standard storage. It is designed for long\-term archiving and historical logs that are rarely accessed.

      * While there may be minor Retrieval fees when accessing the data, the total cost remains far lower than maintaining it in standard storage over the long term.

      * Ensures data accessibility while effectively lowering long\-term storage expenses.

* SQL statement length limit

   The maximum SQL length recorded depends on the minor version of the instance kernel:

   |Kernel version requirements |Maximum recording length |Description |
   |---|---|---|
   |≥ MySQL 5.7.32_20250615 or MySQL 8.0.32_20250615<br><br> |8KB (8192 bytes) |* If the relevant parameter ≤ 8K, it is limited by the parameter value.<br><br>* If the parameter \> 8K, the upper limit remains 8K.<br><br>* The actual recordable length is slightly less than the set value (due to the system adding a prefix). |
   |Below the above versions |4096 bytes |* If the relevant parameter ≤ 4096, it is limited by the parameter value.<br><br>* If the parameter \> 4096, the upper limit remains 4096.<br><br>* The actual length is also slightly less than the set value. |

   > **tip**

   > You can view the minor version on the [Instance information](https://docs.byteplus.com/en/docs/RDS_for_MySQL/viewing_instance_details?lang=en) page. For more information, see the [Minor version release notes](https://docs.byteplus.com/en/docs/RDS_for_MySQL/kernal_version_release_notes?lang=en).

* Suggestions for use

   * Upgrade to a supported version to enable longer SQL recording (up to 8K).

   * Under high load conditions, there may be a delay in enabling the feature. This is normal behavior.

   * Before shutting down or deleting an instance, make sure to export critical audit data.

* Download filesDownload file

   * The full SQL file downloaded by the system is compressed in the `.gz` (Gzip) format. For macOS users, please extract the downloaded file using the steps below:

      * Decompress using the built\-in gzip or gunzip command\-line tools:Open the Terminal and run the gzip or gunzip commands provided by the system to extract the files. The command format is `gzip -d your_filename.gz` or `gunzip your_filename.gz`.

      * To decompress the file using the tar tool: Download and install the tar tool to decompress the file. The command format is `tar -xz --force-local -f file_name.gz`.

## FAQs

**Q: What is the relationship between database audit, SQL insights and auditing, and full SQL insight?**

A: The relationship between the three is as follows:

   |**Function** |**Description** |
   |---|---|
   |**Database audit** |The SQL detail in the database audit function is not the full SQL. |
   |**Full SQL insight** |Full SQL insight can collect all SQLs and perform analysis based on all SQLs. With a greater focus on performance, see DBW's full SQL insights into analytics practices for more value. |
   |**SQL insights and auditing** |SQL insights and audit includes database audit and full SQL insights. SQL insights and auditing is based on database audit. Therefore, when full SQL insight is enabled, database audit is enabled by default. |

Q: **In SQL insights and auditing, I have only enabled database audit. If I want to enable Full SQL insight, how do I do it?**

A: You can enable full SQL insights through service settings. For more information, see [Set SQL insights and auditing](https://docs.byteplus.com/en/docs/DBW/full-SQL-explorer#.6K6-572u5YWo6YePLXNxbC3mtJ7lr58=).
