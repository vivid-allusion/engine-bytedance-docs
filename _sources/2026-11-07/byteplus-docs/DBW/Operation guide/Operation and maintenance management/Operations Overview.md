The Operations Overview page of Database Workshop (DBW) centralizes convenient entry points for managing database operations, including Instance Overview, Performance Monitoring, Security Rate Limiting, Usage Statistics, Storage Alerts, and more. It helps you shift from reactive response to proactive operations.

<span id="AbBmdsPd"></span>
## Main feature modules


|**Module** |**Description** |
|---|---|
|Instance overview |The Instance Overview section provides a comprehensive view of your database assets, helping you quickly understand the overall scale, security coverage, and distribution of database types in your current DBW\-managed environment. This facilitates resource planning, security governance, and operational decision\-making. In this section, you can intuitively view the following key information:<br><br><br>* Total Managed Instances: The number of database instances currently managed by DBW.<br><br>* Instances with Security Control Enabled: The number of instances where security policies such as SQL audit and access control are enabled.<br><br>* Security Control Coverage: The proportion of security\-controlled instances to total instances, reflecting the overall security level.<br><br>* Database Type Distribution: A chart showing the percentage of instances for each database type, including MySQL, PostgreSQL, Redis, MongoDB, and SQL Server.<br><br>* Instance Details by Type: A breakdown of the specific number of instances categorized by database engine.<br><br><br><div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="default">This overview helps you quickly identify instances not under security control, assess the complexity of your multi\-engine environment, and provides data support for subsequent standardization and governance efforts.</div><br> |
|Performance Overview |Performance overview provides a global perspective on database operation status and performance health analysis, helping you quickly identify system load fluctuations, abnormal peaks, high\-risk instances, and potential performance bottlenecks for proactive operations and issue localization. In this area, you can intuitively view key information for each database type within the specified time period, including sessions and slow logs, as detailed below:<br><br><br>* Session information:<br><br>   * Current number of sessions: Counts the total number of active connections across all database instances within the specified time period, reflecting system concurrency pressure.<br><br>   * Session trend chart: Displays the change curve of session count over time, supporting click\-to\-view instance details via operations observability.<br><br>   * TOP10 instance ranking: A list of high\-load instances sorted by maximum number of sessions, including instance name/ID, specification configuration, running state (Running), maximum session trend chart, and operations observability action entry.<br><br><br><div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div><br><br><br><br>   * <div data-tips="true" data-tips-type="default">When a sudden increase in sessions occurs, you can locate the specific time point by combining it with the trend chart.</div><br><br><br>   * <div data-tips="true" data-tips-type="default">Quickly focus on high\-load instances through the TOP10 list for in\-depth diagnosis (such as viewing slow queries, lock waits, etc.).</div><br><br><br>   * <div data-tips="true" data-tips-type="default">Regularly check for instances with persistently high sessions to assess whether scaling out or optimizing application logic is needed.</div><br><br><br>* Slow log information:<br><br>   * Total number of slow logs: Counts the number of slow queries generated by all database instances within a specified time period, reflecting overall SQL execution efficiency.<br><br>   * Slow log trend chart: Displays the curve of slow log quantity over time. Supports viewing instance details via operations observability and intelligent diagnosis with a single click.<br><br>   * TOP 10 instance ranking: A list of high\-risk instances sorted by the maximum number of slow logs. Includes instance name/ID, specification configuration, running state (Running), slow log trend chart (recent changes), maximum number of slow logs, and entry points for operations observability and intelligent diagnosis actions.<br><br><br><div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div><br><br><br><br>   * <div data-tips="true" data-tips-type="default">When a sudden increase in slow logs occurs, use the trend chart to pinpoint the specific time and investigate whether it was caused by a business peak or abnormal SQL.</div><br><br><br>   * <div data-tips="true" data-tips-type="default">Focus on instances with the most slow queries via the TOP 10 list to prioritize high\-risk issues.</div><br><br><br>   * <div data-tips="true" data-tips-type="default">Regularly check for instances with consistently high slow log volumes and assess whether SQL optimization or index addition is needed.</div><br> |
|Rate limited task list |The Rate\-Limited task area displays the top 10 database instances in the current system that are executing rate\-limiting tasks, sorted from highest to lowest by the number of running tasks. Through this area, you can achieve the following key benefits:<br><br><br>* Quickly identify high\-risk instances.<br><br>* Proactively detect abnormal operations or potential attack behaviors.<br><br>* Evaluate the reasonableness of existing security rules and optimize policy configuration.<br><br>* Develop higher\-priority operation and maintenance response plans based on task load.<br><br><br><div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="default">Centralize and visualize scattered security events, facilitating a shift from "passive response" to "active governance."</div><br> |
|Usage statistics |The Usage Statistics area displays your usage of log and index resources within the current billing cycle, covering key metrics including log standard storage, log infrequent\-access storage usage, log collection volume, standard index storage, infrequent\-access index storage usage, index traffic, and total aggregation analysis volume. Through this area, you can achieve the following key benefits:<br><br><br>* Cost visualization: Clearly understand the consumption proportion of each resource and quickly identify high\-cost items. Estimate costs based on the platform's billing model and receive early warnings for budget overrun risks.<br><br>* Optimize storage strategies:<br><br>   * If the infrequent\-access storage ratio is high, you can archive cold data to infrequent\-access storage.<br><br>   * If standard storage continues to grow, check for invalid logs, duplicate collection, or uncleaned temporary data.<br><br>* Improve query performance:<br><br>   * High index traffic indicates frequent queries. Consider optimizing SQL statements or introducing a caching mechanism.<br><br>   * A large index storage suggests possible over\-indexing. Regularly review the necessity of index fields and remove redundant indexes.<br><br>* Evaluate analysis load: A high total aggregation analysis volume typically indicates intensive report generation, monitoring tasks, or custom analysis. Optimize analysis logic, reduce full table scans, or adjust task scheduling frequency.<br><br>* Support decision\-making: Provide data basis for key decisions such as scaling out, architecture migration, and cost optimization, and serve as objective evidence when communicating with business teams about reasonable resource allocation.<br><br><br><div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div><br><br><br><br>* <div data-tips="true" data-tips-type="default">Through this section, you can clearly grasp trends, plan resources scientifically, control costs effectively, and shift from passive response to proactive management.</div><br><br><br>* <div data-tips="true" data-tips-type="default">You can also click <strong>View full bill</strong> in the upper\-right corner of this section to see more detailed billing information. For more information, see <a href="https://docs.byteplus.com/en/docs/DBW/Viewing_fee_information?lang=en">Fee information</a>.</div><br> |
|Storage space remaining available days ranking |The storage space remaining available days ranking area displays the top 10 instances among the currently managed database instances that are expected to exhaust their storage space first, sorted by the fewest remaining available days (a smaller number indicates higher risk). This area helps identify storage bottlenecks in advance, avoiding service interruptions due to full disks. Through this area, you can achieve the following key benefits:<br><br><br>* Proactive alerting to prevent issues before they occur<br><br>   * The system automatically calculates and sorts in real time based on historical growth trends, eliminating the need for manual checks.<br><br>   * Identify high\-risk instances early to effectively avoid sudden outages or read\-only failures.<br><br>* Accurately set operations priorities<br><br><br>Use available days as the core metric to quickly determine the processing order:<br><br><br>   * 0 days: Immediate intervention (scale out, clean up, or rate limit).<br><br>   * Less than 3 days: Prioritize handling to ensure continuity of core business.<br><br>* Drive resource governance and optimization<br><br>   * Identify instances with long\-term rapid growth and investigate potential issues, such as unarchived historical logs or binary logs, duplicate writes or bloated large tables, and leftover temporary files.<br><br>   * Combine usage statistics by region to analyze storage consumption composition and develop targeted optimization strategies.<br><br>* Enhance cross\-team collaboration efficiency<br><br>   * Serve as an effective supplement to automated alerts, reducing reliance on manual reporting.<br><br>   * Provide a unified risk view for roles such as Database Administrators (DBAs), application developers, and Site Reliability Engineers (SREs), supporting efficient collaborative handling.<br><br><br><div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="default">Centralize and visualize dispersed storage risks, helping you shift from reactive response to proactive prevention and control, ensuring stable, reliable, and sustainable database operation.</div><br> |
|Low score inspection report ranking |The Low\-Score Inspection Report Ranking area displays the top 10 database instances with the lowest inspection scores in the past 24 hours, sorted from lowest to highest score (lower scores indicate more issues). This area helps you quickly identify instances with security risks, performance bottlenecks, or configuration issues in the current system, enabling timely fixes and optimizations to improve overall database health. Through this area, you can achieve the following key benefits:<br><br><br>* Quickly locate problematic instances<br><br>   * The system automatically aggregates inspection results and highlights low\-scoring instances.<br><br>   * Focus on high\-risk targets without reviewing reports one by one.<br><br>* Promote proactive operations<br><br>   * Inspection scores are a quantifiable metric for health checks, helping you shift from reactive response to proactive governance.<br><br>   * Regularly review this list to establish a routine operations and maintenance mechanism.<br><br>* Accurately identify risk types<br><br><br>When an instance score is below 100, you can click View all to enter the Database Inspection page and analyze specific issues with the instance in detail.<br><br><br>* Support team collaboration and closed\-loop management<br><br>   * As an output of automated inspection, it reduces the cost of manual troubleshooting.<br><br>   * Supports roles such as Database Administrators (DBAs), application developers, and Site Reliability Engineers (SREs) in jointly handling issues, achieving a closed loop from discovery to analysis to repair to verification.<br><br>* Improve overall database quality<br><br>   * Continuously monitor low\-score instances to promote the implementation of standardized configurations.<br><br>   * Foster a team culture of health awareness and enhance system stability. |
|Instances with error logs |This area displays the top 10 database instances with the highest number of ERROR\-level log entries in their error logs over the past 24 hours, sorted in descending order by error count. Quickly identify instances with frequent anomalies and failures in the system, pinpoint the root cause of issues promptly, and ensure service stability. Through this area, you can achieve the following key benefits:<br><br><br>* Quickly locate high\-risk instances: The system automatically aggregates ERROR\-level logs and centrally presents the instances with the most concentrated issues. You can focus on high\-risk targets directly without manually sifting through logs.<br><br>* Proactively discover potential failures: ERROR logs often correspond to critical issues such as runtime exceptions and configuration errors, allowing for early intervention to prevent minor problems from escalating into online failures.<br><br>* Accurately analyze the problem type:<br><br><br>Based on specific ERROR content, quickly identify typical failure scenarios, including:<br><br><br>   * Connection timeout: Network fluctuations or improper connection pool configuration<br><br>   * Permission denied: Insufficient application account permission configuration<br><br>   * Table does not exist / Structure mismatch: SQL does not match the actual Schema<br><br>   * Primary\-replica replication anomaly: Replication interruption, high latency, or Binlog loss<br><br>   * Resource bottleneck: Disk full or insufficient memory causing service anomalies. Combined with log analysis, you can further filter keywords and locate exception stacks and context.<br><br>* Support rapid response and closed\-loop management<br><br><br>As an important supplement to automated monitoring, it reduces manual inspection costs. Supports collaborative handling by DBAs, developers, and SREs, achieving a full\-process closed loop from discovery → location → repair → verification.<br><br><br>* Continuously improve system stability<br><br><br>Continuously track high\-error instances, promote root cause analysis (RCA) and long\-term optimization, enhance team awareness of log health, and overall improve service reliability. |
