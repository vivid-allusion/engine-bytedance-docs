本文件介紹如何在 BytePlus CDN 中設定來源伺服器請求路徑改寫。該設定允許對 CDN 的來源伺服器請求路徑進行改寫。

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">該功能目前以白名單的方式對外開放。如果您需要此功能，請 <a href="https://console.byteplus.com/workorder/create">提交工單</a>。</div>


在來源伺服器上，假設某些使用者經常存取的檔案路徑發生了變更。此時，有以下幾種解決方案：


* 在來源伺服器設定 301 或 302 重新導向，將內容的原 URL 重新導向到新的 URL。同時，在 CDN 中啟用 [來源伺服器重新導向跟隨](https://docs.byteplus.com/en/docs/byteplus-cdn/redirect-follow_zh-tw) 功能。

* 不在來源伺服器做任何變更，而是在 CDN 中設定 [URL 重新導向改寫](https://docs.byteplus.com/en/docs/byteplus-cdn/docs_cn-url-redirect-cn-tw)功能。如果使用者請求了原 URL，CDN 會回應 301 或者 302 狀態碼，指示使用者瀏覽器向新的 URL 發送請求。

* 不在來源伺服器做任何變更，而是在 CDN 設定 **來源伺服器請求路徑改寫**。如果使用者請求了原 URL，CDN 在來源伺服器請求中會使用新的 URL。


本文件介紹的是第三種解決方案。

<span id="請求流程"></span>
## **請求流程**

在您對某個檔案設定了來源伺服器請求路徑改寫後，請求的流程如下：


1. 使用者請求檔案。

2. 如果該檔案未被快取，CDN 根據設定，在來源伺服器請求中將來自使用者請求 URL 中的路徑改寫成新的路徑。

3. CDN 取得檔案後，將該檔案回傳給使用者並快取該檔案。需要留意的是，該檔案的快取鍵中的 URL 是使用者請求中的 URL。


<span id="操作步驟"></span>
## 操作步驟


1. 打開 **來源伺服器請求路徑改寫** 設定頁面。操作步驟參見 [網域名稱設定](https://docs.byteplus.com/en/docs/byteplus-cdn/domain-management_zh-tw)。

2. 在 **來源伺服器請求路徑改寫** 下方，點擊 **新增規則**。

   您最多可以新增 50 條規則。

3. 參照以下設定說明。

4. 設定完成後，點擊 **儲存**。



|**設定** |**說明** |
|---|---|
|優先順序 |表示規則的優先順序。數字 1 的規則優先順序最高。在收到請求時，CDN 按規則的優先順序，從高到低嘗試將請求與規則匹配。如果請求匹配了某一條規則，CDN 就停止匹配其餘規則。您可以透過拖曳調整規則的優先順序。 |
|用戶請求路徑 |表示使用者請求 URL 中的路徑，長度不超過 1,024 個字元。路徑不包含協定、網域名稱和參數。<br><br>&nbsp;<br><br>您可以在該設定中使用正規表達式。此時，該設定表示一個匹配規則。同時，您可以在正規表達式中指定群組，群組是由 `()` 包裹的。這些群組可以在 **來源伺服器請求路徑** 設定中被引用。例如，`^/aaa/bbb/(.*)` 表示路徑 `/aaa/bbb/` 下的所有目錄和檔案。該例子包含了一個群組。 |
|來源伺服器請求路徑 |表示在來源伺服器請求 URL 中替換 **用戶請求路徑** 的路徑。該設定的要求如下：<br><br><br>* 長度不超過 1,024 個字元。<br><br>* 必須以斜線（/）開頭。<br><br>* 不能包含連續斜線（//）、百分號（%）、空格、問號（?）。<br><br>* 不包含協定、網域名稱和查詢字串。<br><br><br>預設情況下，CDN 會將請求 URL 中的查詢字串新增到實際的來源伺服器 URL 中。<br><br>如果 **用戶請求路徑** 設定中包含了正規表達式並且正規表達式包含了一個或者多個群組，您可以在 **來源伺服器請求路徑** 設定中使用 `$<n>` 指定需要使用的群組。`$1` 表示第一個群組，`$2` 表示第二個群組，以此類推。此時，該設定表示一個匹配規則。<br><br>&nbsp;<br><br>就基於 **用戶請求路徑** 設定中的例子，假設您指定的來源伺服器請求路徑是 `/ccc/$1`。`/ccc/$1` 表示的路徑是以 `/ccc/` 開頭。路徑的其餘部分就是 **用戶請求路徑** 中由 `.*` 所表示的部分。如果使用者請求 URL 是 `https://www.example.com/aaa/bbb/test/myfile.png`，來源伺服器請求 URL 會被改寫為 `https://www.example.com/ccc/test/myfile.png`。 |
