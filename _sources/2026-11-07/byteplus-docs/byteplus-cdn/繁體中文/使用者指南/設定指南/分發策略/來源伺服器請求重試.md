當回源請求失敗時，CDN 會嘗試其他已設定的來源伺服器，本文件描述了回源重試的流程。

<span id="5d62f28e"></span>
## 回源重試發生時，CDN 的來源伺服器選擇流程

<span id="cda8b20a"></span>
### 核心邏輯

回源時，CDN 基於權重選擇一個主要來源伺服器進行存取。如果回源失敗，CDN 會重試另一個主要來源伺服器。如果回源仍然失敗，CDN 會重試一次備用來源伺服器。

<span id="184e37d1"></span>
### 如何選擇來源伺服器位址

如果存在備用來源伺服器設定，CDN 會優先選擇主要來源伺服器。如果存在多個主要來源伺服器，CDN 會按權重選擇主要來源伺服器。

回源失敗時，如果當前選擇的主要來源伺服器是網域名稱並且可以被解析到多個 IP 位址，CDN 會透過輪詢選擇另一個可用的 IP 位址進行嘗試。否則，CDN 會按權重選擇另一個主要來源伺服器。如果無可用的主要來源伺服器，CDN 才會選擇備用來源伺服器。

<span id="b8337914"></span>
### 來源伺服器 IP 位址不可用的判定機制

如果連續 10 次無法與一個來源伺服器 IP 位址建立 TCP 連線，CDN 會將該位址標記為不可用。

在選擇來源伺服器時，如果選中的來源伺服器 IP 位址被標記為不可用，CDN 除了繼續選擇來源伺服器，還會對該 IP 位址進行非同步探測。如果非同步探測的結果是 TCP 連線成功，CDN 會移除該 IP 位址的不可用標記。

<span id="86674273"></span>
### 回源失敗的判斷依據


* TCP 連線逾時和 TCP 連線失敗。

* HTTP 請求逾時。

* 來源伺服器回應狀態碼是 5xx。


<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">預設情況下，TCP 連線逾時時間是 2 秒，HTTP 請求逾時時間是 60 秒。如果您要修改這些逾時時間的設定，請參考 <a href="https://docs.byteplus.com/en/docs/byteplus-cdn/request-timeout_zh-tw">設定逾時時間的設定</a>。</div>


<span id="d775f124"></span>
## 條件式來源伺服器場景下的回源重試

如果請求符合條件式來源伺服器中的規則，則 CDN 在回源時選擇規則中設定的來源伺服器。否則，CDN 基於基礎來源伺服器的設定選擇來源伺服器。

如果 CDN 無法存取規則中設定的來源伺服器，則：


* 當來源伺服器是網域名稱並且可以被解析到多個 IP 位址時，CDN 會透過輪詢選擇另一個 IP 位址進行嘗試，並且僅嘗試一次。

* 否則，CDN 會判定回源失敗。
