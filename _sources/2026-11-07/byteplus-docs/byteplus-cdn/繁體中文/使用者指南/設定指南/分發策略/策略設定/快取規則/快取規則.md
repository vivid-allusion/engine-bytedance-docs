本文件介紹 BytePlus CDN 中的快取規則。

<span id="快取規則概述"></span>
## 快取規則概述

快取規則決定了 CDN 如何快取從來源伺服器獲取的檔案。預設情況下，CDN 遵循來源伺服器回應標頭中對於快取的指示来快取收到的檔案，參見 [預設快取規則](https://docs.byteplus.com/en/docs/18/36289#%E9%A0%90%E8%A8%AD%E5%BF%AB%E5%8F%96%E8%A6%8F%E5%89%87)。來源伺服器回應標頭指示 CDN 是否需要快取收到的檔案，以及快取的時長。

如果您需要修改 CDN 對特定請求的快取行為，可以在 CDN 中建立快取規則。例如，您可以建立快取規則，指定 CDN 一律對滿足以下條件的請求快取請求檔案，快取時長為 3 天：


* 請求 URL 中的目錄路徑為 `/img/loca-food/`。

* 檔案名稱以 `Chinese` 開頭。

* 檔案副檔名為 `.png`。


<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>



* <div data-tips="true" data-tips-type="tip">隨請求檔案一起被快取的還有來源伺ro器回應中的回應狀態碼和回應標頭。也就是說，CDN 快取的是完整的來源伺服器回應。在 CDN 回應使用者請求時，除了請求檔案，來源伺服器回應狀態碼和回應標頭也包含在 CDN 對使用者請求的回應中。</div>


* <div data-tips="true" data-tips-type="tip">快取檔案時，CDN 將來源伺服器回應中 <code>Date</code> 標頭的值記錄為該檔案的快取時間點。</div>


* <div data-tips="true" data-tips-type="tip">當 CDN 收到一個使用者請求，如果請求的檔案在 CDN 的快取中並且 <a href="https://docs.byteplus.com/en/docs/18/36289#cdn-%E5%A6%82%E4%BD%95%E5%88%A4%E6%96%B7%E5%BF%AB%E5%8F%96%E6%AA%94%E6%A1%88%E6%98%AF%E5%90%A6%E9%81%8E%E6%9C%9F">CDN 判斷快取的檔案未過期</a>，該請求被認為是快取命中。</div>



<span id="快取行為"></span>
## 快取行為

在快取規則中，各策略設定對快取行為的影響如下表所示：


|**快取策略** |**策略設定** |**快取行為** |
|---|---|---|
|遵循規則 |強制快取（開） |一律快取檔案，並遵循規則中的快取時長。 |
||強制快取（關） |* 如果來源伺服器回應標頭包含 Cache\-Control: no\-store/private/no\-cache，則不快取檔案。<br><br>* 其餘情況下，遵循規則中的快取時長快取檔案。 |
|遵循來源伺服器 |補充快取（開） |* 遵循來源伺服器回應標頭中的 Cache\-Control 或 Expires。<br><br>* 如果無 Cache\-Control 和 Expires，則遵循規則中的快取時長快取檔案。 |
||補充快取（關） |* 遵循來源伺服器回應標頭中的 Cache\-Control 或 Expires。<br><br>* 如果無 Cache\-Control 和 Expires，則不快取檔案。 |
|不快取 |N/A |一律不快取檔案。 |


<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">如果來源伺服器回應標頭同時包含 <code>Cache-Control: max-age</code> 和 <code>Cache-Control: s-maxage</code> ，後者的優先順序高。</div>

## 建立快取規則


1. 開啟 **快取規則** 設定頁面。操作步驟參見 [網域名稱設定](https://docs.byteplus.com/en/docs/byteplus-cdn/domain-management_zh-tw)。

2. 點擊 **新增規則**。

   您最多可以新增 50 條規則。

3. 參照以下 [設定說明](https://docs.byteplus.com/en/docs/18/36289#%E8%A8%AD%E5%AE%9A%E8%AA%AA%E6%98%8E)。

4. 設定完成後，點擊 **儲存**。

### **設定說明**


|**設定** |**說明** |
|---|---|
|優先順序 |表示規則的優先順序。數字 1 的規則優先順序最高。您可以透過拖曳調整規則的優先順序。 |
|規則類型 |表示規則中的比對條件。該設定有以下選項：<br><br><br>* **檔案副檔名**：表示 URL 路徑末尾的副檔名。<br><br>* **URL 目錄**：表示 URL 路徑中的一個目錄。<br><br>* **URL 全路徑**：表示完整的 URL 路徑。<br><br>* **路徑正規表示式**：表示一個用於比对完整 URL 路徑的正規表示式。 |
|規則 |表示規則中的比對值。多個比對值之間以分號（;）分隔，總長度不能超過 1,024 個字元，不能包含以下字元：<br><br><br>* 雙斜線（//）、空格、貨幣符號（$）、問號（?）。<br><br><br>另外，<br><br><br>* 如果 **規則類型** 是 **檔案副檔名**，則每個比對值是一個檔案副檔名，不能以句點（.）開頭。例如：`png;txt`。<br><br>* 如果 **規則類型** 是 **URL 目錄**，則每個比對值是一個目錄路徑，必須以斜線（/）開頭和結尾。例如：`/chs/foods/;/us/birds/`。<br><br>* 如果 **規則類型** 是 **URL 全路徑**，則每個比對值是一個 URL 路徑，必須以斜線（/）開頭。比對值可以包含星號（\*）用來表示一個或多個任意字元。例如：`/chs/foods/local*sets;/us/birds/chickadee`。<br><br>* 如果 **規則類型** 是 **路徑正規表示式**，則每個比對值是一個正規表示式，用於比对 URL 路徑。例如：`^/a{1,2}.*g$`。 |
|忽略大小寫 |表示比對值是否區分大小寫。 該設定的預設設定是 **關閉**，表示比對值區分大小寫。例如：**規則類型** 是 **檔案副檔名**，規則內容是 `png;txt`，**忽略大小寫** 為 **關閉**。此時，該規則比對 URL 是 `HTTPS://www.EXAMPLE.com/image.png` 的請求，但是不比对 URL 是 `https://www.example.com/image.PNG` 的請求。 |
|Set\-Cookie 不快取 |表示是否快取包含 `Set-Cookie` 標頭的來源伺服器回應。預設情況下，該開關是關閉的，表示 CDN 會快取這類回應。<br><br>&nbsp;<br><br>由於 `Set-Cookie` 標頭通常包含身份憑證或個性化設定等使用者專屬資訊，快取這類回應可能會帶來使用者身份混淆的安全風險。如果來源伺服器回應包含 `Set-Cookie` 標頭，請務必充分評估快取這類回應的安全性。<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">如果 <strong>強制快取</strong> 啟用，您無法設定 <strong>Set\-Cookie 不快取</strong>。包含 <code>Set-Cookie</code> 標頭的來源伺服器回應會被 CDN 快取。</div><br> |
|快取策略 |表示 CDN 的快取行為。參見 [快取行為](https://docs.byteplus.com/en/docs/18/36289#%E5%BF%AB%E5%8F%96%E8%A1%8C%E7%82%BA)。 |
|策略設定 ||
|快取過期時間 |表示檔案的快取時長，最大快取時長是 3,650 天。<br><br>如果快取時間設為 `0`，則表示不快取檔案，其效果与設定 **快取策略** 為 **不快取** 相同。對於比對該規則的使用者請求，CDN 會透傳請求到來源伺服器。 |


<span id="add00773"></span>
## 規則生效邏輯

規則清單中的規則具有優先順序，優先順序最高的規則先生效。對於一個使用者請求，如果某條規則與該請求比對，只有該規則生效，剩餘規則不生效。您可以拖曳規則來調整規則的優先順序。

## **更多資訊**

<span id="848521a7"></span>
### 預設快取規則

在快取規則清單中，有一條系統建立的快取規則。該規則對所有請求生效，是預設快取規則。該規則的設定為 "遵循來源伺服器 + 補充快取（關）"。該規則的優先順序最低。您無法修改或者刪除該規則，您也無法調整该規則的優先順序。

如果一個使用者請求無法比對您建立的任何快取規則，該請求將比對這條系統建立的快取規則。

<span id="47c480c4"></span>
### CDN 如何判斷快取檔案是否過期

當 CDN 收到一個使用者請求時，如果請求的檔案已被 CDN 快取並且以下條件滿足，CDN 判定快取未過期並將快取檔案傳送给使用者：


* CDN 收到請求的時間 \> 快取檔案的快取時間點 + 比對該請求的快取規則中所指定的快取時長


<span id="ce6c680c"></span>
### 快取規則對 CDN 處理使用者請求的影響

當 CDN 收到一個使用者請求時，CDN 處理該請求的步驟如下：


1. 確定比對该使用者請求的快取規則。

2. 基於该快取規則的設定，確定是否需要尋找快取中的檔案。

   * 如果快取規則的設定為不快取檔案，CDN 直接向來源伺服器請求该檔案。當收到檔案後，CDN 將该檔案傳送给使用者。**流程結束。** 

   * 否則，CDN 尋找快取中的檔案。

3. 判斷快取中是否存在该檔案。

   * 如果该檔案存在並且未過期，CDN 將快取的檔案傳送给使用者。**流程結束。** 

   * 如果该檔案存在但已過期，CDN 進行 [來源伺服器校驗](https://docs.byteplus.com/en/docs/18/36289#%E4%BE%86%E6%BA%90%E4%BC%BA%E6%9C%8D%E5%99%A8%E6%A0%A1%E9%A9%97)，也就是向來源伺服器校驗该檔案是否有更新。來源伺服器校驗有以下結果：

      * 來源伺服器上该檔案沒有更新：在這種情況下，CDN 將快取的檔案傳送给使用者。**流程結束。** 

      * 來源伺服器上该檔案有更新：在這種情況下，來源伺服器的回應中已包含了最新的檔案。繼續步驟 4。

   * 如果该檔案不存在，CDN 向來源伺服器請求该檔案。繼續步驟 4。

4. 當收到檔案後，CDN 將该檔案傳送给使用者。

5. 基於该快取規則的設定，CDN 快取收到的檔案。


<span id="2702473f"></span>
### 檔案分片的快取過期時間

當 CDN 收到一個 Range 請求，如果請求的分片已被 CDN 快取，CDN 使用以下步驟判斷快取中的分片是否已過期：


1. 對於该分片所對應的檔案，在快取中尋找该檔案的所有分片。

2. 在這些分片中（包括完整檔案，如果存在），確定最早被快取的那個分片，並獲取该分片的快取時間點。

3. 使用以下公式計算請求分片的過期時間：

   * 過期時間 = 步驟 2 中的快取時間點 + 比對该 Range 請求的快取規則中所指定的快取時長。

4. 判斷快取中的分片是否已過期。

   * 如果 CDN 收到该 Range 請求的時間晚於步驟 3 中的過期時間，則 CDN 判定快取中的分片已過期。

   * 否則，CDN 判定快取中的分片未過期。


**示例**

對於來源伺服器上的一個檔案，CDN 在某一天的不同時間點收到了以下請求：


* 09:00：CDN 收到了该檔案的分片 A 的請求。分片 A 的快取時間點是 09:01。

* 10:00：CDN 收到了分片 B 的請求。分片 B 的快取時間點是 10:01。

* 11:00：CDN 收到了完整檔案的請求。完整檔案的快取時間點是 11:01。

* 13:02：CDN 又收到了分片 B 的請求。


對於最後收到的請求，假設比對该請求的快取規則中所指定的快取時長是 4 小時。由於快取過期時間是 13:01，CDN 判定快取中分片 B 已過期。

<span id="26907f71"></span>
### CDN 不快取來源伺服器回應的情況

在以下任意情況下，CDN **不會**快取來源伺服器回應。並且，您無法使用快取規則改變 CDN 的行為。


* 來源伺服器回應中 `Content-Length` 標頭的值為 `0`。

* 使用者請求所使用的方法既不是 GET，也不是 HEAD。

* 來源伺服器回應狀態碼不是 2xx，並且您未對该狀態碼設定 [狀態碼快取](https://docs.byteplus.com/zh-CN/docs/byteplus-cdn/negative-cache_zh-tw)。

* 使用者請求使用 HEAD 方法，并且來源伺服器回應中包含 `Transfer-Encoding:chunked` 標頭。


在以下情況下，CDN 預設不快取來源伺服器回應。然而，您可以建立快取規則改變 CDN 的快取行為。


* 來源伺服器回應包含 `Expires` 標頭，並且该標頭值所表示的時間早於 CDN 收到使用者請求的時間。


<span id="0453fd47"></span>
### **強制快取更新**

假設 CDN 快取中的某个檔案還未過期，但是來源伺服器上该檔案已經被更新了。您需要使用者獲取该檔案的最新版本。

在這種情況下，您可以在 CDN 中對该檔案進行 [清除](https://docs.byteplus.com/zh-CN/docs/byteplus-cdn/purge-cache_zh-tw) 操作。清除操作強制使 CDN 將该檔案標記为已過期。之後，如果收到该檔案的使用者請求，CDN 會进行 [來源伺服器校驗](https://docs.byteplus.com/en/docs/18/36289#%E4%BE%86%E6%BA%90%E4%BC%BA%E6%9C%8D%E5%99%A8%E6%A0%A1%E9%A9%97)。獲取到更新檔案後，CDN 將更新的檔案傳送给使用者並快取该更新檔案。

<span id="eb911957"></span>
### **來源伺服器校驗**

當一個快取檔案過期後，如果 CDN 收到了该檔案的請求，CDN 向來源伺服器請求该檔案。但是如果之前隨该檔案快取的來源伺服器回應標頭中存在 `ETag` 或者 `Last-Modified`，CDN 會在來源伺服器請求中包含相應標頭。這些標頭用於与來源伺服器確認该檔案是否有更新。來源伺服器校驗的邏輯如下：


* 如果 `ETag` 存在，來源伺服器請求中會包含 `If-None-Match` 標頭。该標頭的值就是 `ETag` 的值。

* 如果 `ETag` 不存在但是 `Last-Modified` 存在，來源伺服器請求中會包含 `If-Modified-Since` 標頭。该標頭的值就是 `Last-Modified` 的值。


當收到包含 `If-None-Match` 或 `If-Modified-Since` 標頭的請求時，來源伺服器會基於该標頭檢查该檔案是否已更新。


* 如果该檔案已更新，來源伺f服器回應中會包含請求檔案，回應狀態碼是 200。

* 如果该檔案沒有更新，來源伺服器回應中不會包含請求檔案，回應狀態碼是 304。


基於來源伺服器回應中的狀態碼，CDN 執行以下某个操作：


* 如果狀態碼是 304，CDN 將快取的檔案傳送给使用者。同時，CDN 獲取來源伺服器回應中的 `Date` 標頭，然後將快取檔案的快取時間更新为该標頭值。

* 如果狀態碼是 200，CDN 將更新的檔案傳送给使用者並快取更新的檔案。
