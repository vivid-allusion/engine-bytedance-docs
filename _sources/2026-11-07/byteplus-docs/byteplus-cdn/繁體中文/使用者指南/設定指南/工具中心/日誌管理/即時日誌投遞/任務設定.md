本文檔介紹如何在 BytePlus CDN 中建立日誌投遞任務。您最多可以建立 20 個任務。

任務建立精靈包含兩個步驟：


1. 設定投遞資訊：設定投遞相關的設定。

2. 指定網域名稱：指定投遞哪些網域名稱的即時日誌。


<span>![图片](https://sf-bpcms.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/20260331074615-754427039674.png) </span>

<span id="步驟一：設定投遞資訊"></span>
## 步驟一：設定投遞資訊

在該步驟中，您可以指定將實時日誌投遞到支援的日誌分析服務或指定的 HTTP 伺服器。

<span id="byteplus-日誌服務（tls）"></span>
### BytePlus 日誌服務（TLS）

<span id="前提條件"></span>
#### 前提條件

如果您第一次將即時日誌投遞到 TLS，在您點擊 **投遞對象** 下的 **BytePlus 日誌服務（TLS）**  時，頁面會提示您開通 TLS 服務，然後授權 CDN 存取 TLS。請根據主控台頁面的提示進行操作。

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>



* <div data-tips="true" data-tips-type="tip">當您授權 CDN 存取 TLS 時，您的 BytePlus 主帳戶下會被新增 <code>ServiceRoleForCDN</code> 角色。</div>


* <div data-tips="true" data-tips-type="tip">要使 IAM 使用者有權限建立日誌投遞任務，IAM 使用者需要被授予 <code>CDNLogsFullAccess</code> 系統預設策略。</div>



如果前提條件滿足，在您點擊 **投遞對象** 下的 **BytePlus 日誌服務（TLS）**  時，你需要完成以下設定，使 CDN 將即時日誌投遞到您指定的日誌主題中。參見下方的設定說明。

<span id="驗證流程與權杖演算法"></span>
#### 驗證流程與權杖演算法

**驗證流程**


1. 在發送日誌投遞請求前，CDN 基於驗證 Key 和權杖演算法計算權杖。額外參與權杖計算的欄位有指定的時間標記（timestamp）、請求 URL 中的路徑（uri）、CDN 隨機產生的整數（rand）。rand 的範圍是 0 \- 2147483647。

2. 向 HTTP 伺服器發送 POST 請求。

   * 請求 URL 中包含 `auth_key` 查詢參數，參數值的格式為 `timestamp-rand-token`。

   * 請求 URL 的格式為 `http://[http_server_address]:[port]/[uri]?auth_key=timestamp-rand-token`

      請求 URL 範例：`http://https://www.example.com:8080/cdn-logs?auth_key=1744870608-14567-6459280fed54315c2960f9ae2e91807d`

   * 請求正文中包含多條日誌，日誌之間使用 `\n` 分隔。

3. 收到請求後，HTTP 伺服器基於驗證 Key、伺服器地址中的路徑、時間標記和隨機數計算權杖。參見下方的權杖範例和範例程式碼。

4. HTTP 伺服器判斷這兩個權杖是否相同。如果權杖相同，則表示驗證通過。


**權杖演算法**


* MD5(uri\-timestamp\-rand\-key)


**權杖範例**

假設：


* 伺服器地址為 `https://www.example.com:8080/cdn-logs`。

* 驗證 Key 為 `1a2c!=A?1`。

* 請求的發送時間（timestamp）為 `1744870608`。

* CDN 隨機產生的整數（rand）為 `14567`。


則權杖的計算公式為 `MD5(/cdn-logs-1744870608-14567-1a2c!=A?1)`，計算出的權杖為 `6459280fed54315c2960f9ae2e91807d`。

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">在該範例中，如果伺服器地址中不包含路徑，則權杖計算公式為 <code>MD5(-1744870608-14567-1a2c!=A?1)</code>。</div>

在將實時日誌投遞到 Google Cloud BigQuery 前，您需要在 Google Cloud Platform (GCP) 中完成以下準備工作：


1. 建立好 BigQuery 的資源層級：**專案** \> **資料集** \> **表**。

|備註資訊 |表示該投遞配置的備註。<br><br>&nbsp;<br><br>備註的輸入要求如下：<br><br><br>1. 長度為 3 \- 64 個字元，可以包含中文、字母、數字、底線（_）和連字號（\-）。中文佔 3 個字元。<br><br>2. 不能以連字號（\-）或底線（_）開頭或結尾。 |


<span id="步驟二：指定網域名稱"></span>
## 步驟二：指定網域名稱

在該步驟中，您指定投遞哪些網域名稱的即時日誌。


* 如果您要投遞所有網域名稱的即時日誌，請設定 **關聯方式** 為 **按帳號關聯**。對於您後續在 CDN 中新增的網域名稱，這些網域名稱的即時日誌也會被投遞。

* 如果您要投遞指定網域名稱的即時日誌，請設定 **關聯方式** 為 **按網域名稱關聯**，然後選擇這些網域名稱。您最多可以選擇 200 個網域名稱。


<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">如果已存在按帳戶關聯的投遞任務，則無法再建立按網域名稱關聯的投遞任務。反之亦然。</div>

<span id="iam-使用者權限說明"></span>
### IAM 使用者權限說明

在步驟二中，IAM 使用者只能新增其有權限操作的網域名稱。另外，假設一個 IAM 使用者被授予的相關策略存在專案限制，也就是說該 IAM 使用者有權限存取的是屬於指定 BytePlus 專案的網域名稱。在這個情況下，該 IAM 使用者無法指定 **按賬號關聯**。

<span id="查看日誌投遞任務"></span>
## 查看日誌投遞任務

在您建立投遞任務後，您的任務就出現在任務清單中了。


* 如果某個任務設定需要調整，您可以在 **操作** 列上，點擊 **編輯**。

* 要查看投遞任務的設定，您可以在相應任務的 **投遞資訊** 列上，點擊 **展開查看**。

* 對於投遞到 TLS 的日誌，您可以點擊 **操作** 列上的 **檢索**，然後在 **檢索與分析** 頁面對日誌進行檢索和分析，參見 [日誌檢索範例](https://docs.byteplus.com/en/docs/byteplus-cdn/log-query-examples_zh-tw)。


<span id="刪除日誌投遞任務"></span>
## 刪除日誌投遞任務

如果您不再需要某個即時日誌任務，您可以先停用該任務，然後再刪除。

<div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div>


<div data-tips="true" data-tips-type="warning">對於投遞目標是 TLS 的任務，任務刪除後，相應的日誌主題也會被刪除。</div>
