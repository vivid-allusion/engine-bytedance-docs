## 邊緣函數執行時期與 Node.js 或 Deno 等執行時期有何異同？

邊緣函數執行時期是部署於全球邊緣節點上的輕量級函數即服務（FaaS）環境。其設計初衷與傳統的中心雲 FaaS 不同，專注於處理大規模、高彈性、低延遲的業務場景。

邊緣函數執行時期與 Node.js 或 Deno 等執行時期的差異如下：


* **架構與資源管理**：邊緣函數執行時期基於 V8 隔離環境構建，實現了輕量級的多租戶隔離。該架構對每個租戶的計算和記憶體資源進行精密控制，包括記憶體使用、CPU 執行時間及函數回應時間等。更多資訊，請參見[使用限制](https://docs.byteplus.com/en/docs/byteplus-cdn/functions-usage-limits-zh-tw)。

* **安全性**：為保障執行時期環境的安全，邊緣函數採取了多層安全策略，有效防範惡意程式碼攻擊。這些策略包括 V8 隔離機制、CPU 時間限制以及防禦性的 API 設計。例如，邊緣函數執行時期的時鐘精度被調整至 10 毫秒左右，以防範攻擊者利用 [Date](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date) 物件返回的精確時間進行時序側信道攻擊（Timing Side\-Channel Attack）。

* **執行上下文**：邊緣函數執行時期強制實施嚴格的上下文隔離。API 呼叫被限制在各自的上下文中，且由 API 建立的物件的生命週期也受到精確管理。詳細資訊，请参见[工作原理](https://docs.byteplus.com/en/docs/byteplus-cdn/how-functions-work-zh-tw)。

* **API 相容性**：邊緣函數執行時期相容部分 [WinterTC](https://wintertc.org/) 的標準 API，並提供了一些邊緣函數專屬 API。邊緣函數執行時期 API 的底層由 C++ 實現，旨在降低資源消耗，提升執行效率。同時，出於安全和效能考量，邊緣函數執行時期不支援 Node.js 或 Deno 中的部分 API，如 `net`、`process`、`fs` 等。
