本文件介紹函數和邊緣 KV 的工作原理。

<span id="函數的工作原理"></span>
## 函數的工作原理

<span id="函數如何被事件驅動"></span>
### 函數如何被事件驅動

您在邊緣函數中建立的函數是事件驅動型函數。為了讓函數能在您指定的條件下執行，您需要為函數建立觸發器。觸發器包括網域名稱觸發器和 Cron 觸發器。觸發器在滿足一定的條件時會觸發對應的事件。事件被觸發時，您在函數程式碼中為該事件註冊的事件監聽器所指定的回呼函數會被呼叫。

在邊緣函數中，您呼叫 `addEventListener()` 方法註冊一個事件監聽器。

<span id="網域名稱觸發器"></span>
#### 網域名稱觸發器

為了建立網域名稱觸發器，您需要為一個函數關聯您在 BytePlus CDN 中新增的網域名稱並為該網域名稱設定轉發規則。如果存取該網域名稱的 HTTP 或 HTTPS 請求符合轉發規則，那麼網域名稱觸發器會觸發 fetch 事件。

網域名稱觸發器僅支援 HTTP 或 HTTPS 請求。

邊緣函數與 BytePlus CDN 共享邊緣伺服器。使用者向您 BytePlus CDN 中新增的網域名稱發起請求時，先透過 DNS 解析取得距離最近的邊緣伺服器的 IP 位址，再向該 IP 位址發送 HTTP 請求。當 BytePlus CDN 收到使用者的請求時，會根據網域名稱的轉發規則，判斷該請求是否由該網域名稱關聯的函數處理。


* 如果使用者請求不符合轉發規則，BytePlus CDN 會處理該使用者請求。

* 如果使用者請求符合轉發規則，BytePlus CDN 會將該使用者請求轉發給邊緣函數。同時，網域名稱觸發器會觸發與網域名稱關聯的函數的程式碼中的 fetch 事件。為 fetch 事件註冊的回呼函數會被呼叫。邊緣函數會根據函數的程式碼邏輯處理該使用者請求、把該使用者請求轉發到 BytePlus CDN 或其他公有雲服務。

<span id="cron-觸發器"></span>
#### Cron 觸發器

您可以建立 Cron 觸發器並為其設定定期任務。Cron 觸發器會在預定時間觸發 cron 事件。為 cron 事件註冊的回呼函數會被呼叫。cron 事件可以在一個邊緣伺服器上被觸發，也可以在所有邊緣伺服器上被觸發。

<span id="函數在什麼環境下運行"></span>
### 函數在什麼環境下運行

函數的運行環境是邊緣函數在 BytePlus 的全球邊緣伺服器上的執行時期。每個函數都可以在 V8 隔離環境下安全運行。執行時期支援的程式語言是 JavaScript（ES6）。開發者透過呼叫執行時期 API 與邊緣函數的執行時期進行互動。執行時期 API 包含部分 [WinterTC](https://wintertc.org/) 的標準 API 和一些邊緣函數獨有的 API。

如果一個函數首次執行或隔一段時間後再次執行，執行時期需要先為該函數分配資源，然後再執行該函數。這個過程被稱為「冷啟動」。邊緣函數與傳統的基於容器的雲函數相比，冷啟動時間縮短到數毫秒。

函數執行完成後，資源會保留一段時間。在資源被保留的時間段內，再次運行的函數可以直接使用這些資源。這個過程被稱為「熱啟動」。

<span id="函數運行的邊界和生命週期"></span>
### 函數運行的邊界和生命週期

為了高效解決資源隔離和垃圾回收問題，執行時期規定了函數運行的邊界和生命週期。

函數的程式碼每次被事件驅動執行時，執行時期都會為程式碼中的所有物件隱式關聯一個或多個上下文。上下文是一個獨立的函數運行環境，用於區分函數運行的邊界。所關聯的上下文不同的物件不能互相存取。執行時期的上下文包括**全域初始化上下文**和**請求上下文**。


* 全域初始化上下文：函數的初始化運行環境。在全域初始化上下文下可以呼叫 `addEventListener()` 、`atob()`、`btoa()` 和不屬於執行時期 API 的標準 ES6 API。全域初始化上下文僅在函數冷啟動時被建立且僅運行一次。

* 請求上下文：事件被觸發後，該事件註冊的回呼函數的運行環境。多個回呼函數可以同時運行。全域變數對多個並發的回呼函數可見。不同回呼函數的請求上下文不同。在請求上下文中，可以呼叫全部執行時期 API 。


例如，在下面的程式碼中，在回呼函數第一次執行時期， 第一次運行的請求上下文的關聯的 Response 物件被賦值給與全域初始化上下文關聯的全域變數 `respObject`。第二次執行時期，與第二次運行的請求上下文關聯的回呼函數嘗試存取與第一次運行的請求上下文關聯的物件，就會引發 JavaScript 運行異常。

```javascript
addEventListener('fetch', (event) => {
     event.respondWith(handle(event));
 });
 
 let respObject = null;
 async function handle(event) {
     const request = event.request; 
     if (respObject) {
        console.log(respObject.url); // 這個地方將會觸發 JavaScript 異常。

     } else {
         respObject = new Response("This will never work");
     }
     return "Hello World";
 }
```


所有的 JavaScript 內建物件是可以跨上下文使用的，包括 String、Number、Object、Promise 等物件。例如下面的程式碼就不會發生運行異常。

```javascript
addEventListener('fetch', (event) => {
    event.respondWith(handle(event));
});

let respObject = null;
async function handle(event) {
    const request = event.request; 
    if (respObject) {
       // 沒問題，因為 respObject 是原生的 JavaScript 物件了。
       console.log(respObject.url); 
    } else {
        respObject = JSON.stringify(event.request);
    }
    return "Hello World";
}
```


函數在執行時期中有固定的運行生命週期。例如，對於 fetch 事件，函數的運行生命週期從網域名稱觸發器觸發 fetch 事件開始，到 `respondWith()` 方法註冊的 promise 被 resolve 或 reject 後結束。運行生命週期結束後，未運行完畢的其他非同步操作會被取消。從網域名稱觸發器觸發事件開始，執行時期會為函數建立一個請求上下文。該請求上下文與為事件註冊的回呼函數隱式關聯。`respondWith()` 方法註冊的 promise 被 resolve 或 reject 後，執行時期將會銷毀該請求上下文。

<span id="邊緣-kv-的工作原理"></span>
## 邊緣 KV 的工作原理

邊緣 KV 服務是在 BytePlus 的全球邊緣伺服器上的分散式鍵值儲存服務。一個鍵值對透過邊緣函數控制台、OpenAPI、CLI 或執行時期 API 被寫入邊緣 KV 後，會自動被同步到所有邊緣伺服器。函數透過執行時期 API 可以快速讀取位於同一邊緣伺服器的鍵值對。一個鍵值對可以被一個或多個函數讀取。一個鍵值對的值被更新後，更新後的值會自動生效並被同步到所有邊緣伺服器。邊緣 KV 在所有邊緣伺服器中的資料具有最終一致性，最遲在 60 秒內在全部邊緣伺服器完成同步。

<span>![图片](https://sf16-resources.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/upload_4cf51da061440dbb53ea953eab91085b.jpeg) </span>

邊緣 KV 的資料包括儲存空間和鍵值對。一個 BytePlus 帳號下可以有一個或多個儲存空間。每個儲存空間下可以有一個或多個鍵值對。在一個儲存空間內，每個鍵值對的鍵都是唯一的。
