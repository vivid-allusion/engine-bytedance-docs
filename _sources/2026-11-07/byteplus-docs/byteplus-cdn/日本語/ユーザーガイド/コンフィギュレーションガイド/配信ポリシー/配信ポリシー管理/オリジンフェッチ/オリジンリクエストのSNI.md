<span id="sniとは"></span>
## SNIとは

SNIは Server Name Indication の略称です。SNIはTLSプロトコルの拡張機能です。同一サーバー上に複数のサイトがデプロイされているシナリオにおいて、SNIは以下の問題を解決します：


* クライアントがHTTPSプロトコルを使用してサーバーとの接続を確立する際、サーバー側がクライアントにどのサイトの証明書を送信すべきか判断できない問題。


クライアントが安全でないHTTPプロトコルを使用してサーバーと通信する場合、データ転送時にサーバーはクライアントリクエストのHostヘッダーを通じて、クライアントがアクセスしようとしているサイトを判断します。しかし、クライアントがHTTPSプロトコルを使用してサーバーに接続する場合、データ転送が開始される前にTLSハンドシェイクのプロセスがあります。このプロセス中、クライアントはまだHostヘッダーをサーバーに送信していません。そのため、サーバーはHostフィールド情報を取得してクライアントに送信すべきサイト証明書を判断することができません。この時、クライアントはSNIヘッダーを使用して、サーバーに目的のサイトを通知することができます。これにより、サーバーはTLSハンドシェイク段階で適切な証明書をクライアントに送信することができます。

<span id="オリジンリクエストのsni"></span>
## オリジンリクエストのSNI

本文で議論するSNIは、BytePlus CDNの「オリジンリクエストのSNI」設定です。「オリジンリクエストのSNI」は、CDNがHTTPSプロトコルを使用してオリジンサーバーにコンテンツをリクエストする際にアクセスする必要があるオリジンドメイン名を指定します。ドメイン名でHTTPSを有効にしている場合、システムにはデフォルトの「オリジンリクエストのSNI」設定があります。デフォルトの「オリジンリクエストのSNI」設定は以下の通りです：


* 「オリジンサーバーのHost」を指定していない場合、「オリジンリクエストのSNI」はドメイン名と同じになります。

* 「オリジンサーバーのHost」を指定している場合、「オリジンリクエストのSNI」は「オリジンサーバーのHost」と同じになります。


ただし、一部のシナリオでは、「オリジンリクエストのSNI」と「オリジンサーバーのHost」が異なる場合があります。そのようなシナリオがある場合、CDNコンソールで「オリジンリクエストのSNI」を設定できます。

<span id="操作手順"></span>
## 操作手順


1.  **オリジンリクエストのSNI**設定ペイジを開きます。操作手順については[ドメイン名設定](https://docs.byteplus.com/en/docs/byteplus-cdn/domain-management_jp)をご参照ください。

2.  **オリジンリクエストのSNI**の下で、**状態**を**有効**に設定します。

3. **SNIドメイン名**を目的のサイトのドメイン名に設定します。長さは1024文字を超えないようにしてください。

4. 設定が完了したら、**保存**をクリックします。
