このドキュメントでは、BytePlus CDN のキャッシュルールについて説明します。

<span id="キャッシュルールの概要"></span>
## キャッシュルールの概要

キャッシュルールは、CDN がオリジンサーバーから取得したファイルをどのようにキャッシュするかを決定します。デフォルトでは、CDN はオリジンサーバーのレスポンスヘッダーの指示に従って受信したファイルをキャッシュします。[デフォルトのキャッシュルール](https://docs.byteplus.com/en/docs/18/31975#%E3%83%87%E3%83%95%E3%82%A9%E3%83%AB%E3%83%88%E3%81%AE%E3%82%AD%E3%83%A3%E3%83%83%E3%82%B7%E3%83%A5%E3%83%AB%E3%83%BC%E3%83%AB) を参照してください。オリジンサーバーのレスポンスヘッダーは、CDN が受信したファイルをキャッシュする必要があるかどうか、およびキャッシュ期間を示します。

特定のファイルリクエストに対する CDN のキャッシュ動作を変更する必要がある場合は、CDN でキャッシュルールを作成できます。たとえば、次の条件を満たすリクエストに対して、リクエストされたファイルを常に3日間キャッシュするように CDN に指示するキャッシュルールを作成できます。


* リクエスト URL のディレクトリパスが `/img/loca-food/` である。

* ファイル名が `Chinese` で始まる。

* ファイルの拡張子が `.png` である。


<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>



* <div data-tips="true" data-tips-type="tip">リクエストされたファイルと一緒に、オリジンサーバーのレスポンスのステータスコードとレスポンスヘッダーもキャッシュされます。つまり、CDN は完全なオリジンサーバーのレスポンスをキャッシュします。CDN がユーザーリクエストに応答するとき、リクエストされたファイルに加えて、オリジンサーバーのレスポンスステータスコードとレスポンスヘッダーも CDN のユーザーリクエストへのレスポンスに含まれます。</div>


* <div data-tips="true" data-tips-type="tip">ファイルをキャッシュするとき、CDN はオリジンサーバーのレスポンスの <code>Date</code> ヘッダーの値をファイルのキャッシュタイムスタンプとして記録します。</div>


* <div data-tips="true" data-tips-type="tip">CDN がユーザーリクエストを受信したとき、リクエストされたファイルが CDN のキャッシュにあり、<a href="https://docs.byteplus.com/en/docs/18/31975#47c480c4">CDN　がキャッシュファイルの有効期限を判断する方法</a>、リクエストはキャッシュヒットと見なされます。</div>



<span id="キャッシュ動作"></span>
## キャッシュ動作

キャッシュルールでは、各ポリシ設定がキャッシュ動作に与える影響を次の表に示します。


| **キャッシュポリシー**  | **ポリシー設定** | **キャッシュ動作** |
|---|---|---|
|ルールに従う |常にキャッシュ（オン） |常にファイルをキャッシュし、ルールで指定されたキャッシュ期間に従います。 |
||常にキャッシュ（オフ） |* オリジンサーバーのレスポンスヘッダーに Cache\-Control:no\-store/private/no\-cache が含まれる場合、ファイルはキャッシュされません。<br><br>* それ以外の場合は、ルールで指定されたキャッシュ期間に従ってファイルをキャッシュします。 |
|オリジンに従う |カスタムTTLを使用（オン） |* オリジンサーバーのレスポンスヘッダーの Cache\-Control または Expires に従います。<br><br>* Cache\-Control と Expires がない場合は、ルールで指定されたキャッシュ期間に従ってファイルをキャッシュします。 |
||カスタムTTLを使用（オフ） |* オリジンサーバーのレスポンスヘッダーの Cache\-Control または Expires に従います。<br><br>* Cache\-Control と Expires がない場合、ファイルはキャッシュされません。 |
|キャッシュしない |N/A |常にファイルをキャッシュしません。 |


<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">オリジンサーバーのレスポンスヘッダーに <code>Cache-Control: max-age</code> と <code>Cache-Control: s-maxage</code> の両方が含まれている場合、後者が優先されます。</div>


<span id="キャッシュルールの作成"></span>
## キャッシュルールの作成


1.  **キャッシュルール**  設定ページを開きます。手順については、[ドメイン名設定](https://docs.byteplus.com/en/docs/byteplus-cdn/domain-management_jp) を参照してください。

2.  **ルールを追加** をクリックします。

   最大50個のルールを追加できます。

3. 次の [キャッシュルール](https://docs.byteplus.com/en/docs/18/31975#%E8%A8%AD%E5%AE%9A%E8%AA%AC%E6%98%8E) を参照してください。

4. 設定が完了したら、**保存** をクリックします。

<span id="add00773"></span>
## ルール適用ロジック

ルールリスト内のルールには優先度があり、最も優先度の高いルールが最初に適用されます。ユーザーリクエストに対して、あるルールがリクエストに一致する場合、そのルールのみが適用され、残りのルールは適用されません。ルールをドラッグして優先度を調整できます。

<span id="8990e788"></span>
## **詳細情報**

<span id="848521a7"></span>
### デフォルトのキャッシュルール

キャッシュルールリストには、システムによって作成されたキャッシュルールがあります。このルールはすべてのリクエストに適用され、デフォルトのキャッシュルールです。このルールの設定は「オリジンに従う + 補足キャッシュ（オフ）」です。このルールの優先度は最も低いです。このルールを変更または削除したり、優先度を調整したりすることはできません。

ユーザーリクエストが作成したどのキャッシュルールにも一致しない場合、リクエストはこのシステム作成のキャッシュルールに一致します。

<span id="47c480c4"></span>
### CDN がキャッシュファイルの有効期限を判断する方法

CDN がユーザーリクエストを受信したとき、リクエストされたファイルが CDN によってキャッシュされており、次の条件が満たされている場合、CDN はキャッシュが有効期限内であると判断し、キャッシュされたファイルをユーザーに送信します。


* CDN がリクエストを受信した時刻 \> キャッシュファイルのキャッシュタイムスタンプ + リクエストに一致するキャッシュルールで指定されたキャッシュ期間


<span id="ce6c680c"></span>
### キャッシュルールが CDN のユーザーリクエスト処理に与える影響

CDN がユーザーリクエストを受信すると、CDN は次の手順でリクエストを処理します。


1. ユーザーリクエストに一致するキャッシュルールを決定します。

2. キャッシュルールの設定に基づいて、キャッシュ内のファイルを検索する必要があるかどうかを判断します。

   * キャッシュルールの設定でファイルがキャッシュされない場合、CDN はオリジンサーバーに直接ファイルをリクエストします。ファイルを受信すると、CDN はファイルをユーザーに送信します。 **プロセスは終了します。** 

   * それ以外の場合、CDN はキャッシュ内のファイルを検索します。

3. ファイルがキャッシュに存在するかどうかを判断します。

   * ファイルが存在し、有効期限が切れていない場合、CDN はキャッシュされたファイルをユーザーに送信します。 **プロセスは終了します。** 

   * ファイルは存在するが有効期限が切れている場合、CDN は[オリジンサーバーへの再検証](https://docs.byteplus.com/en/docs/18/31975#%E3%82%AA%E3%83%AA%E3%82%B8%E3%83%B3%E3%82%B5%E3%83%BC%E3%83%90%E3%83%BC%E3%81%B8%E3%81%AE%E5%86%8D%E6%A4%9C%E8%A8%BC)を実行します。つまり、ファイルが更新されているかどうかをオリジンサーバーに確認します。オリジンサーバーへの再検証には次の結果があります。

      * オリジンサーバー上のファイルは更新されていません。この場合、CDN はキャッシュされたファイルをユーザーに送信します。 **プロセスは終了します。** 

      * オリジンサーバー上のファイルは更新されています。この場合、オリジンサーバーのレスポンスにはすでに最新のファイルが含まれています。手順4に進みます。

   * ファイルが存在しない場合、CDN はオリジンサーバーにファイルをリクエストします。手順4に進みます。

4. ファイルを受信すると、CDN はファイルをユーザーに送信します。

5. キャッシュルールの設定に基づいて、CDN は受信したファイルをキャッシュします。


<span id="2702473f"></span>
### ファイルチャンクのキャッシュ有効期限

CDN が Range リクエストを受信したとき、リクエストされたチャンクが CDN によってキャッシュされている場合、CDN は次の手順を使用してキャッシュされたチャンクが期限切れかどうかを判断します。


1. チャンクに対応するファイルについて、キャッシュ内のそのファイルのすべてのチャンクを検索します。

2. これらのチャンク（完全なファイルが存在する場合はそれを含む）の中から、最も早くキャッシュされたチャンクを特定し、そのキャッシュタイムスタンプを取得します。

3. 次の式を使用して、リクエストされたチャンクの有効期限を計算します。

   * 有効期限 = 手順2のキャッシュタイムスタンプ + Range リクエストに一致するキャッシュルールで指定されたキャッシュ期間。

4. キャッシュされたチャンクが期限切れかどうかを判断します。

   * CDN が Range リクエストを受信した時刻が手順3の有効期限より後の場合、CDN はキャッシュされたチャンクが期限切れであると判断します。

   * それ以外の場合、CDN はキャッシュされたチャンクが期限切れでないと判断します。


**例**

オリジンサーバー上のファイルについて、CDN はある日の異なる時刻に次のリクエストを受信しました。


* 09:00：CDN はファイルのチャンク A のリクエストを受信しました。チャンク A のキャッシュタイムスタンプは 09:01 です。

* 10:00：CDN はチャンク B のリクエストを受信しました。チャンク B のキャッシュタイムスタンプは 10:01 です。

* 11:00：CDN は完全なファイルのリクエストを受信しました。完全なファイルのキャッシュタイムスタンプは 11:01 です。

* 13:02：CDN は再びチャンク B のリクエストを受信しました。


最後に受信したリクエストについて、リクエストに一致するキャッシュルールで指定されたキャッシュ期間が4時間であると仮定します。キャッシュの有効期限は 13:01 であるため、CDN はキャッシュされたチャンク B が期限切れであると判断します。

<span id="26907f71"></span>
### CDN がオリジンサーバーのレスポンスをキャッシュしない場合

次のいずれかの状況では、CDN はオリジンサーバーのレスポンスを **キャッシュしません** 。また、キャッシュルールを使用して CDN の動作を変更することはできません。


* オリジンサーバーのレスポンスの `Content-Length` ヘッダーの値が `0` である。

* ユーザーリクエストで使用されるメソッドが GET でも HEAD でもない。

* オリジンサーバーのレスポンスステータスコードが 2xx ではなく、そのステータスコードに対して[ネガティブキャッシュ](https://docs.byteplus.com/en/docs/byteplus-cdn/negative-cache-jp)を設定していない。

* ユーザーリクエストが HEAD メソッドを使用し、オリジンサーバーのレスポンスに `Transfer-Encoding:chunked` ヘッダーが含まれている。


次の状況では、CDN はデフォルトでオリジンサーバーのレスポンスをキャッシュしません。ただし、キャッシュルールを作成して CDN のキャッシュ動作を変更できます。


* オリジンサーバーのレスポンスに `Expires` ヘッダーが含まれており、そのヘッダーが示す時刻が CDN がユーザーリクエストを受信した時刻より前である。


<span id="0453fd47"></span>
### **強制キャッシュ更新**

CDN キャッシュ内のファイルがまだ有効期限内であるが、オリジンサーバー上のファイルが更新されたとします。ユーザーにファイルの最新バージョンを取得させる必要があります。

この場合、CDN でそのファイルに対して[キャッシュパージ](https://docs.byteplus.com/en/docs/byteplus-cdn/purge-cache-jp)操作を実行できます。更新操作により、CDN は強制的にそのファイルを期限切れとしてマークします。その後、そのファイルのユーザーリクエストを受信した場合、CDN は[オリジンサーバーへの再検証](https://docs.byteplus.com/en/docs/18/31975#%E5%9B%9E%E6%BA%90%E6%A0%A1%E9%AA%8C)を実行します。更新されたファイルを取得した後、CDN は更新されたファイルをユーザーに送信し、更新されたファイルをキャッシュします。

<span id="eb911957"></span>
###  **オリジンサーバーへの再検証**

キャッシュされたファイルが期限切れになった後、CDN がそのファイルのリクエストを受信した場合、CDN はオリジンサーバーにそのファイルをリクエストします。ただし、以前にそのファイルと一緒にキャッシュされたオリジンサーバーのレスポンスヘッダーに `ETag` または `Last-Modified` が存在する場合、CDN はオリジンサーバーへのリクエストに対応するヘッダーを含めます。これらのヘッダーは、ファイルが更新されたかどうかをオリジンサーバーで確認するために使用されます。オリジンサーバーへの再検証のロジックは次のとおりです。


* `ETag` が存在する場合、オリジンサーバーへのリクエストには `If-None-Match` ヘッダーが含まれます。このヘッダーの値は `ETag` の値です。

* `ETag` が存在しないが `Last-Modified` が存在する場合、オリジンサーバーへのリクエストには `If-Modified-Since` ヘッダーが含まれます。このヘッダーの値は `Last-Modified` の値です。


`If-None-Match` または `If-Modified-Since` ヘッダーを含むリクエストを受信すると、オリジンサーバーはそのヘッダーに基づいてファイルが更新されたかどうかを確認します。


* ファイルが更新されている場合、オリジンサーバーのレスポンスにはリクエストされたファイルが含まれ、レスポンスステータスコードは 200 です。

* ファイルが更新されていない場合、オリジンサーバーのレスポンスにはリクエストされたファイルが含まれず、レスポンスステータスコードは 304 です。


オリジンサーバーのレスポンスのステータスコードに基づいて、CDN は次のいずれかのアクションを実行します。


* ステータスコードが 304 の場合、CDN はキャッシュされたファイルをユーザーに送信します。同時に、CDN はオリジンサーバーのレスポンスから `Date` ヘッダーを取得し、キャッシュされたファイルのキャッシュ時間をそのヘッダーの値に更新します。

* ステータスコードが 200 の場合、CDN は更新されたファイルをユーザーに送信し、更新されたファイルをキャッシュします。
