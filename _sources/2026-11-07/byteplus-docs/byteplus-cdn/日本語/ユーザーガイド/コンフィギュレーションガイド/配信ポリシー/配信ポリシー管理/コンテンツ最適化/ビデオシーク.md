BytePlus CDNは「ビデオシーク」機能を提供しており、特定のシナリオでプレーヤーから送信されるビデオセグメントリクエストを処理できます。[前提条件](https://docs.byteplus.com/en/docs/18/31985#%E5%89%8D%E6%8F%90%E6%9D%A1%E4%BB%B6)を参照してください。

<span id="前提条件"></span>
## 前提条件


* プレーヤーが再生するビデオファイルの形式がMP4であること。

* プレーヤーがリクエストURLで `start` と `end` クエリパラメータを使用して、リクエストするビデオセグメントを指定すること。例えば、以下のリクエストURLは、プレーヤーが15秒から120秒までのビデオセグメントをリクエストしていることを示します。

   * `http://www.example.com/4K_demo.mp4?start=15.000&end=120.000`


<span id="操作手順"></span>
## 操作手順

ドメイン名に対してこの設定を有効にするには、未公開の配信ポリシーで設定を行い、そのポリシーを公開してドメインに関連つける必要があります。ドメインが既にポリシーに関連付けされている場合は、[ポリシーのコピー](https://docs.byteplus.com/docs/byteplus-cdn/what-is-policy)を使用して未公開のポリシーを作成できます。


1.  **ビデオシーク** 設定ペイジを開きます。操作手順については[ドメイン名設定](https://docs.byteplus.com/en/docs/byteplus-cdn/domain-management_jp)をご参照ください。

2.  **ビデオシーク** の下で、**状態**を**有効**に設定します。

3. 設定が完了したら、**保存**をクリックします。

<span id="start-endパラメータの説明とビデオファイルのmetadata要件"></span>
## start/endパラメータの説明とビデオファイルのMetadata要件


| **ビデオ形式** |**Metadata** |**start/endパラメータ**  | **リクエストURLの例** |
|---|---|---|---|
|MP4 |オリジンサーバー上で、MP4ビデオファイルはMetadataを含む必要があり、Metadataはファイルの先頭に配置されている必要があります。 |ビデオの開始時間と終了時間を表し、単位は秒で、ミリ秒まで精確です。 |`http://www.example.com/video.mp4?start=5.013&end=12.123` |



* `start`と`end`パラメータについて、CDNはパラメータ名の大文字と小文字を区別します。例えば、CDNが`http://www.example.com/sample.mp4?Start=15`というリクエストURLを受け取った場合、`Start`パラメータの大文字小文字が正しくないため、CDNは指定されたビデオセグメントではなく、完全な`sample.mp4`を返します。

* `start`または`end`で指定された位置のビデオフレームがキーフレームでない場合、CDNはビデオの早い時点から`start`または`end`に最も近いキーフレームを実際の開始位置と終了位置として取得します。

## 詳細情報

<span id="ビデオシークの概要"></span>
### ビデオシークの概要

ビデオシークは現代のビデオプレーヤーで一般的にサポートされている機能です。ビデオ再生中、ユーザーはプレーヤーのプログレスバーをドラッグして再生時間を変更できます。ユーザーがプログレスバーを特定の時間点にドラッグすると、プレーヤーはサーバーにその時間点から始まるビデオセグメントをリクエストし、完全なビデオをリクエストしません。これにより、ユーザーがビデオを視聴する際、完全なビデオファイルのダウンロードを待つ必要がなく、プレーヤーがビデオセグメントを取得した後、対応する時間点から視聴を開始できるため、ユーザーエクスペリエンスが向上します。

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>



* <div data-tips="true" data-tips-type="tip">ユーザーがプレーヤーで初めてビデオを開く際、プレーヤーはサーバーにビデオの先頭から始まるビデオセグメントをリクエストします。</div>


* <div data-tips="true" data-tips-type="tip">ビデオ再生中、プレーヤーは現在のビデオセグメントの再生が終了する前に、サーバーに次のビデオセグメントをリクエストします。</div>



<span id="cdnがプレーヤーのビデオセグメントリクエストを処理する方法"></span>
### CDNがプレーヤーのビデオセグメントリクエストを処理する方法

ご利用のシナリオが[前提条件](https://docs.byteplus.com/en/docs/18/31985#%E5%89%8D%E6%8F%90%E6%9D%A1%E4%BB%B6)を満たし、かつ「ビデオシーク機能」が有効になっている場合、CDN はリクエストに含まれる start および end パラメータに基づき、キャッシュされた完全な動画ファイルから指定されたセグメントを切り出してプレイヤーに返します。なお、リクエスト自体が Range リクエストである場合、CDN は Range ヘッダーを無視します。

CDNがプレーヤーからのビデオセグメントリクエストを受信した時、CDNがまだ完全なビデオファイルをキャッシュしていない、またはキャッシュされたビデオファイルが期限切れの場合、CDNはまずオリジンサーバーに完全なビデオファイルをリクエストします。そのため、そのビデオセグメントリクエストを送信したプレーヤーは、CDNからの応答を受け取るまでに長い時間待つ必要があります。この問題を回避するには、人気のあるビデオに対して、CDNが提供する[プリフェッチ](https://docs.byteplus.com/en/docs/byteplus-cdn/file-prefetch-jp)機能を使用して、これらのビデオファイルを事前にCDNノードにキャッシュすることをお勧めします。

<span id="キーフレームとは"></span>
### キーフレームとは

ビデオ内の任意のスムーズな場面転換は、2つのキーフレームによって定義されます。これら2つのキーフレームは、それぞれその場面転換の開始状態と終了状態を記録しています。MP4形式のビデオファイルの場合、そのメタデータにどのビデオフレームがキーフレームであるかが指定されています。

<span id="その他の情報"></span>
### その他の情報


* CDNがビデオファイルをキャッシュする際、ファイルのキャッシュキーには`start`パラメータも`end`パラメータも含まれません。

* CDNがオリジンサーバーに完全なビデオファイルをリクエストする際、オリジンリクエストには`start`パラメータも`end`パラメータも含まれません。
