このドキュメントでは、BytePlusCDNの「共有キャッシュ」機能について説明します。この機能を使用するには、[チケットを送信](https://console.byteplus.com/workorder/create)してください。

<span id="「共有キャッシュ」とは"></span>
## 「共有キャッシュ」とは

「共有キャッシュ」を使用すると、複数のドメイン名で同じCDNキャッシュを共有できます。CDN では、1 つ以上の共有キャッシュ設定を作成できます。共有キャッシュ設定では、「共有ドメイン名」と「キャッシュドメイン名」を指定する必要があります。「共有ドメイン名」は、「キャッシュドメイン名」のCDNキャッシュを共有します。

<span id="ユースケース"></span>
## ユースケース

「共有キャッシュ」は、次のシナリオに適用できます。


* 複数のドメイン名配下のファイルが完全に同じである場合。CDNがオリジンサーバーにファイルをリクエストする回数を減らすために、これらのドメイン名に「共有キャッシュ」を設定できます。

* サイトに、さまざまなユーザー配信チャネル向けの複数のドメイン名がある場合。これらのドメイン名で配信されるコンテンツは同じです。


共有キャッシュ設定を追加、変更、または削除すると、「共有ドメイン名」へのリクエストのキャッシュヒット率が低下する可能性があります。具体的な理由については、「[共有キャッシュ」の仕組み](https://docs.byteplus.com/en/docs/18/53083#%E5%85%B1%E6%9C%89%E3%82%AD%E3%83%A3%E3%83%83%E3%82%B7%E3%83%A5-%E3%81%AE%E4%BB%95%E7%B5%84%E3%81%BF) を参照してください。慎重に操作してください。

<span id="「共有キャッシュ」の仕組み"></span>
## 「共有キャッシュ」の仕組み

共有キャッシュ設定を作成した後、「共有ドメイン名」のリクエストを受信した場合、CDN は次のプロセスに従ってリクエストを処理します。


1. 「共有ドメイン名」のキャッシュルールに基づいて、リクエストされたファイルをキャッシュする必要があるかどうか、およびキャッシュTTLを決定します。ファイルをキャッシュする必要がない場合、CDNは「共有ドメイン名」のオリジンサーバーにファイルをリクエストし、そのファイルを使用してこのリクエストに応答します。プロセスは終了します。

2. ファイルをキャッシュする必要がある場合、CDNはリクエストされたファイルの URLのドメイン名を「キャッシュドメイン名」に置き換え、キャッシュでリクエストされたファイルを検索します。キャッシュでファイルが見つからない場合は、手順 4 に進みます。

3. キャッシュでファイルが見つかった場合、CDNは手順 1 で取得したキャッシュTTLを使用して、キャッシュされたファイルが期限切れかどうかを判断します。ファイルが期限切れでない場合、CDNはそのファイルを使用してこのリクエストに応答します。プロセスは終了します。

4. ファイルが期限切れであるか、CDNがキャッシュでファイルを見つけられなかった場合、CDNは「共有ドメイン名」のオリジンサーバーにファイルをリクエストします。

5. オリジンサーバーからファイルを取得した後、CDNはそのファイルを「キャッシュドメイン名」のファイルとしてキャッシュします。プロセスは終了します。


「共有キャッシュ」設定はエッジノードのキャッシュに影響を与えるため、作成、削除、変更は慎重に行ってください。操作の前に、必ず[注意事項](https://docs.byteplus.com/en/docs/18/53083#%E6%B3%A8%E6%84%8F%E4%BA%8B%E9%A0%85)をお読みください。

<span id="利用制限"></span>
## 利用制限


* あるドメイン名が他のドメイン名の「キャッシュドメイン名」として設定されている場合、どの共有キャッシュ設定でもそのドメイン名を「共有ドメイン名」として設定することはできません。

* 「共有ドメイン名」と「キャッシュドメイン名」は、同じプライマリーアカウントに属している必要があります。

* 「キャッシュドメイン名」はワイルドカードドメイン名であってはなりません。


<span id="操作手順"></span>
## 操作手順


1. [BytePlusCDN管理コンソール](https://console.byteplus.com/cdn)にログインします。

2. 左側のナビゲーションバーで、**詳細設定** \> **共有キャッシュ**  をクリックします。

3. **共有キャッシュ**  ページで、**共有キャッシュを設定** をクリックします。

4. **共有キャッシュを設定** ページで、キャッシュドメイン名を1つ指定し、1つまたは1つ以上の「共有ドメイン名」を指定して、**提出** をクリックします。


<span>![图片](https://sf16-resources.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/upload_9b79fd69b3d7258ad5b1dc521839f64c.png) </span>

指定された「共有ドメイン名」は、「キャッシュドメイン名」のCDNキャッシュを共有します。**提出** をクリックすると、作成した共有キャッシュ設定がリストに表示されます。

<span id="注意事項"></span>
## 注意事項


* 共有キャッシュ設定を作成および変更する前に、「共有ドメイン名」と「キャッシュドメイン名」に同じオリジンサーバー設定とキャッシュキー設定を使用することをお勧めします。共有キャッシュ設定が有効になると、キャッシュヒット率が向上し、不正なキャッシュファイルが表示されるのを防ぐことができます。

   * 「共有ドメイン名」へのリクエストの場合、CDN がキャッシュでファイルを検索するときは、「共有ドメイン名」のファイルではなく、「キャッシュドメイン名」のファイルを検索します。短期的には、「共有ドメイン名」へのリクエストのキャッシュヒット率が低下する可能性があります。

   * 「共有キャッシュ」設定を作成すると、「共有ドメイン名」は自身のキャッシュを使用しなくなり、代わりに「キャッシュドメイン名」のキャッシュを使用します。「共有キャッシュ」設定を削除すると、「共有ドメイン名」は引き続き自身のキャッシュを使用します。

   * 共有キャッシュ設定のドメイン名には、同じオリジンサーバー設定を使用することをお勧めします。同じでない場合、次の状況が発生する可能性があります。

      * 異なるオリジンサーバーに、パスとファイル名は同じですが、更新時刻またはコンテンツが異なるファイルが存在する場合があります。[「共有キャッシュ」の仕組み](https://docs.byteplus.com/en/docs/18/53083#%E5%85%B1%E6%9C%89%E3%82%AD%E3%83%A3%E3%83%83%E3%82%B7%E3%83%A5-%E3%81%AE%E4%BB%95%E7%B5%84%E3%81%BF) に基づいて、実際にキャッシュされるファイルは任意のオリジンサーバーからのものである可能性があり、ユーザーが正しくないファイルを取得する状況が発生します。

      * キャッシュヒット率を向上させるために、「共有ドメイン名」のキャッシュキー設定を「キャッシュドメイン名」と同じにすることをお勧めします。
