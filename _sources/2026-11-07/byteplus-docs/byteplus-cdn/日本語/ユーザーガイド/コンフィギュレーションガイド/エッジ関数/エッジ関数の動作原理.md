このドキュメントでは、関数とエッジKVの動作について紹介しています。

<span id="関数の動作原理"></span>
## 関数の動作原理

<span id="関数がイベント駆動される仕組み"></span>
### 関数がイベント駆動される仕組み

エッジ関数で作成する関数はイベント駆動型です。関数を指定した条件で実行させるには、関数用のトリガーを作成する必要があります。トリガーには、ドメイントリガーとCronトリガーがあります。トリガーは特定の条件が満たされると対応するイベントを発生させます。イベントが発生すると、関数コードでそのイベントに登録したイベントリスナーで指定されたコールバック関数が呼び出されます。

エッジ関数では、`addEventListener()`メソッドを呼び出してイベントリスナーを作成します。

<span id="ドメイントリガー"></span>
#### ドメイントリガー

ドメイントリガーを作成するには、関数をBytePlus CDNのドメイン名に関連付け、そのドメイン名に関数転送ルールを設定する必要があります。そのドメイン名へのHTTP/HTTPSリクエストが関数転送ルールに一致すると、ドメイントリガーがfetchイベントをトリガーします。

ドメイントリガーはHTTP/HTTPSリクエストのみをサポートします。

<span>![图片](https://sf16-resources.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/upload_c74060bcfc1687cb39b6f2bdc9e51862.jpeg) </span>

エッジ関数はBytePlus CDNとエッジノードを共有します。ユーザーがBytePlus CDNのドメイン名にアクセスする際、まずDNS解決を通じて最も近いエッジノードのIPアドレスを取得し、そのIPアドレスにHTTPリクエストを送信します。BytePlus CDNがユーザーのリクエストを受信すると、ドメイン名の関数転送ルールに基づいて、そのリクエストがドメイン名に関連付けられた関数によって処理されるかどうかを判断します。


* ユーザーからのリクエストが関数転送ルールに一致しない場合、BytePlus CDNがそのユーザーからのリクエストを処理します。

* ユーザーからのリクエストが関数転送ルールに一致した場合、BytePlus CDNはそのユーザーからのリクエストをエッジ関数に転送します。同時に、ドメイントリガーがドメイン名に関連付けられた関数のコード内のfetchイベントをトリガーします。fetchイベントに登録されたコールバック関数が呼び出されます。エッジ関数は、関数のコードロジックに基づいてユーザーからのリクエストを処理し、そのユーザーからのリクエストをBytePlus CDNまたは他のパブリッククラウドサービスに転送します。


<span id="cronトリガー"></span>
#### Cronトリガー

Cronトリガーを作成し、定期的なタスクを設定できます。Cronトリガーは、予定された時間に関数コード内のcronイベントをトリガーします。cronイベントに登録されたコールバック関数が呼び出されます。cronイベントは1つのエッジノードでトリガーすることも、すべてのエッジノードでトリガーすることもできます。

<span id="関数が実行される環境"></span>
### 関数が実行される環境

関数の実行環境は、BytePlusのグローバルエッジノード上のエッジ関数のランタイムです。各関数はV8分離環境で安全に実行できます。ランタイムがサポートするプログラミング言語はJavaScript（ES6）です。開発者は関数のコードでランタイムAPIを呼び出すことで、エッジ関数のランタイムと対話します。ランタイムAPIには、[WinterTC](https://wintertc.org/)の一部の標準APIと、エッジ関数固有のいくつかのAPIが含まれています。

関数が初めて実行される場合や、実行される前に一定期間実行されていない場合、ランタイムはまずその関数にリソースを割り当ててから実行します。このプロセスは「コールドスタート」と呼ばれます。従来のコンテナベースのFaaSサービスと比較して、エッジ関数はコールドスタート時間を一桁ミリ秒レベルにまで短縮しました。関数の実行が完了すると、リソースは一定期間保持されます。リソースが保持されている間に再度実行される関数は、これらのリソースを直接使用できます。このプロセスは「ホットスタート」と呼ばれます。

<span id="関数実行の境界とライフサイクル"></span>
### 関数実行の境界とライフサイクル

リソース分離とガベージコレクションの問題を効率的に解決するために、ランタイムは関数実行の境界とライフサイクルを定義しています。

関数のコードがイベントによって実行されるたびに、ランタイムはコード内のすべてのオブジェクトに1つ以上のコンテキストを暗黙的に関連付けます。コンテキストは独立した関数実行環境で、関数実行の境界を区別するために使用されます。関連付けられたコンテキストが異なるオブジェクトは互いにアクセスできません。ランタイムのコンテキストには、 **グローバル初期化コンテキスト** と **リクエストコンテキスト** が含まれます。


* グローバル初期化コンテキスト：関数の初期化実行環境です。グローバル初期化コンテキストでは、`addEventListener()`、`atob()`、`btoa()`や非ランタイムAPIの標準ES6 APIを呼び出すことができます。グローバル初期化コンテキストは関数のコールドスタート時にのみ作成され、一度だけ実行されます。

* リクエストコンテキスト：イベントがトリガーされた後、そのイベントに登録されたコールバック関数の実行環境です。複数のコールバック関数を同時に実行できます。グローバル変数は複数の並行するコールバック関数から見えます。異なるコールバック関数のリクエストコンテキストは異なります。リクエストコンテキストでは、すべてのランタイムAPIを呼び出すことができます。


例えば、以下のコードでは、コールバック関数が初めて実行されるとき、最初に実行されるリクエストコンテキストに関連付けられたResponseオブジェクトがグローバル初期化コンテキストに関連付けられたグローバル変数`respObject`に割り当てられます。2回目の実行時に、2回目の実行のリクエストコンテキストに関連付けられたコールバック関数が最初の実行のリクエストコンテキストに関連付けられたオブジェクトにアクセスしようとすると、JavaScriptの実行例外が発生します。

```javascript
addEventListener('fetch', (event) => {
    event.respondWith(handle(event));
});

let respObject = null;
async function handle(event) {
    const request = event.request; 
    if (respObject) {
       console.log(respObject.url); // JavaScriptの実行例外が発生します
    } else {
        respObject = new Response("This will never work");
    }
    return "Hello World";
}
```


すべてのJavaScript組み込みオブジェクトは、コンテキスト間で使用することができます。これにはString、Number、Object、Promiseなどのオブジェクトが含まれます。例えば、以下のコードは実行時に例外を発生させません。

```javascript
addEventListener('fetch', (event) => {
    event.respondWith(handle(event));
});

let respObject = null;
async function handle(event) {
    const request = event.request; 
    if (respObject) {
       // JavaScriptの実行例外が発生しません。respObjectはJavaScriptの組み込みオブジェクトです。
       console.log(respObject.url); 
    } else {
        respObject = JSON.stringify(event.request);
    }
    return "Hello World";
}
```


関数はランタイム内で固定の実行ライフサイクルを持ちます。例えば、fetchイベントの場合、関数の実行ライフサイクルはドメイントリガーがfetchイベントをトリガーした時点から始まり、`respondWith()`メソッドに登録されたpromiseがresolveまたはrejectされた後に終了します。実行ライフサイクルが終了すると、完了していない他の非同期操作はキャンセルされます。ドメイントリガーがイベントをトリガーすると、ランタイムは関数用のリクエストコンテキストを作成します。このリクエストコンテキストは、イベントに登録されたコールバック関数と暗黙的に関連付けられます。`respondWith()`メソッドに登録されたpromiseがresolveまたはrejectされた後、ランタイムはそのリクエストコンテキストを破棄します。

<span id="エッジkvの動作原理"></span>
## エッジKVの動作原理

エッジKVサービスは、BytePlusのグローバルエッジノード上の分散キーバリューストレージサービスです。エッジ関数コンソール、OpenAPI、CLI、またはランタイムAPIを通じてキーバリューペアがエッジKVに書き込まれると、それは自動的にすべてのエッジノードに同期されます。関数はランタイムAPIを通じて、同じエッジノード上のキーバリューペアを迅速に読み取ることができます。1つのキーバリューペアは1つまたは複数の関数によって読み取ることができます。キーバリューペアの値が更新されると、更新された値は自動的に有効になり、すべてのエッジノードに同期されます。エッジKVはすべてのエッジノードでデータの最終的な一貫性を持ち、最大60秒以内にすべてのエッジノードで同期が完了します。

<span>![图片](https://sf16-resources.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/upload_7fbb8fc691cb33d81cf126d6b232cbcd.jpeg) </span>

エッジKVのデータには名前空間とキーバリューペアが含まれます。1つのBytePlusアカウントには、1つまたは複数の名前空間を持つことができます。各名前空間には、1つまたは複数のキーバリューペアを含めることができます。1つの名前空間内では、各キーバリューペアのキーは一意です。
