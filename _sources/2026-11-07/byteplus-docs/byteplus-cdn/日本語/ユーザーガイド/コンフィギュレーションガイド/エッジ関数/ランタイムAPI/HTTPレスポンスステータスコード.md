ドメイントリガーによって実行されたファンクションの場合、ファンクションはHTTPレスポンスステータスコードを通じて実行が成功したかどうかを示します。ファンクションの実行が失敗した場合、エッジ関数は異なるステータスコードに対して異なる再試行戦略を持っています。


|ステータスコード |意味 |説明 |再試行戦略 |
|---|---|---|---|
|200 |成功 |ファンクションが正常に実行されました。 |再試行戦略なし |
|599 |関数コードエラー |これは、プロミスの拒否やキャッチされない例外が原因である可能性があります。ランタイムはすべてのプロミス例外をリッスンします。プロミスが拒否されたり、例外がキャッチされず、それがレスポンス送信プロセス中に発生した場合、ランタイムはレスポンスを切り捨て、リクエストコンテキストをキャンセルします。 |現在のエッジノード内でべき等なリクエストを1回再試行 |
|598 |レート制限 |関数コードのコンテキストが多すぎる、またはリソース（メモリ、CPU実行時間など）が著しく不足しています。 |エッジノード間でべき等なリクエストを1回再試行。また、[チケットを提出](https://console.byteplus.com/workorder/create)してリソースやレート制限ポリシーの調整を要求することもできます。 |
|597 |禁止 |セキュリティ上の理由で禁止されており、通常は数分間続き、その期間後に自動的に復元されます。 |エッジノード間でべき等なリクエストを1回再試行 |
|596 |グローバルレート制限 |エッジ関数をホストしているエッジノードがリソース制限に達し、サーキットブレーキングとレート制限を開始します。 |エッジノード間でべき等なリクエストを1回再試行 |
|594 |認識されないユーザー |エッジ関数以外のユーザーからのトラフィックがランタイムに入ります。 |適用可能な戦略なし |
|593 |サービス検出インフラストラクチャエラー |プラットフォームサービスの例外。 |エッジノード間でべき等なリクエストを1回再試行 |
