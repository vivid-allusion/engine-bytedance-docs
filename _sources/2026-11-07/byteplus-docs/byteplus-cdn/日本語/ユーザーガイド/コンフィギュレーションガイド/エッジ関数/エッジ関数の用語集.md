本ページでは、エッジ関数の用語集を列挙しています。

<span id="エッジノード"></span>
## エッジノード

エッジノードは、ネットワークのエッジでデータを処理し、コンピューティングサービスを提供するサーバーのクラスターを指します。エッジノードはデータソースとエンドユーザーの近くに配置され、広く分散されています。BytePlus CDNとエッジ関数はエッジノードを共有します。

<span id="関数"></span>
## 関数

エッジ関数の関数はイベント駆動型です。関数には、関数設定と関数コードが含まれます。

<span id="トリガー"></span>
## トリガー

トリガーは関数の設定に属します。トリガーは、特定の条件が満たされたときにイベントをトリガーします。エッジ関数は、ドメイントリガーとCronトリガーをサポートします。


* ドメイントリガー: ユーザーがHTTPまたはHTTPSリクエストを介して関数に関連付けられたドメイン名にアクセスし、そのユーザーからのリクエストがドメイン名の関数転送ルールに一致する場合、ドメイン名トリガーはfetchイベントを発生させます。コード内でfetchイベントをリッスンし、処理する必要があります。

* Cronトリガー: 定義された時間に従って、cronイベントを定期的にトリガーします。コード内でcronイベントをリッスンして処理する必要があります。


<span id="環境変数"></span>
## 環境変数

環境変数を使用すると、コードを更新せずに関数の動作を調整できます。環境変数は、APIキーなどの機密情報や、外部サービスへのURLなどの環境固有の設定情報を保存するためによく使用されます。環境変数は関数設定に属します。したがって、環境変数を変更するたびに、新しい環境変数を有効にするために関数を再発行する必要があります。

<span id="バージョン"></span>
## バージョン

関数を公開するたびに、エッジ関数は関数のバージョンを自動的に生成します。このリリースには、トリガーを除く関数コードと関数設定のスナップショットが含まれています。バージョンを通じて関数コードと関数設定を管理できます。

<span id="カナリアリリーズ"></span>
## カナリアリリーズ

カナリアリリーズとは、関数の新しいバージョンをすべてのエッジノードに公開する前に、一部のエッジノードに公開することを意味します。エッジノードのこの部分を使用して、関数の機能とパフォーマンスを検証し、期待どおりであれば、すべてのエッジノードにリリースできます。

<span id="フルリリース"></span>
## フルリリース

フルリリースとは、関数をすべてのエッジノードに一度にリリースすることを意味します。

<span id="ランタイム"></span>
## ランタイム

エッジ関数のランタイムは、エッジノードで関数を実行するための環境です。

<span id="ランタイムapi"></span>
## ランタイムAPI

ランタイムAPIは、開発者がエッジ関数のランタイムを操作するためのAPIのセットです。

<span id="エッジkv"></span>
## エッジKV

Edge KVは、キーと値のペアデータ用の分散ストレージサービスを提供します。

<span id="名前空間"></span>
## 名前空間

エッジKVでは、名前空間は、キーと値のペアを分類および管理するために使用される論理パーティションです。さまざまなアプリまたはモジュールのキーと値のペア用に個別のストレージ スペースを作成できます。

<span id="キーと値のペア"></span>
## キーと値のペア

キーと値のペアは、エッジKVデータの基本単位です。キーと値のペアのキーは、名前空間内で一意です。
