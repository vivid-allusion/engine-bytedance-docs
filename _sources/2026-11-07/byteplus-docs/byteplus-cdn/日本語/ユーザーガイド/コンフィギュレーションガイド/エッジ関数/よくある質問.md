## エッジ関数ランタイムと Node.js や Deno などのランタイムとの違いは何ですか？

エッジ関数ランタイムは、グローバルなエッジノードにデプロイされる軽量の Function\-as\-a\-Service（FaaS）環境です。従来のクラウド FaaS とは異なり、大規模で弾力性が高く、低遅延のシナリオ向けに設計されています。

エッジ関数ランタイムと Node.js や Deno などのランタイムの主な違いは次のとおりです。


*  **アーキテクチャとリソース管理**：エッジ関数ランタイムは V8 Isolate 上に構築され、軽量のマルチテナント分離を実装しています。このアーキテクチャは、メモリ使用量、CPU 実行時間、関数応答時間など、各テナントのコンピューティングリソースとメモリリソースを正確に制御します。詳細については、[エッジ関数の使用制限](https://docs.byteplus.com/en/docs/byteplus-cdn/usage-limits-jp) を参照してください。

*  **セキュリティ** ：ランタイム環境のセキュリティを確保するため、エッジ関数は多層的なセキュリティポリシーを採用し、悪意のあるコード攻撃を効果的に防止します。これらのポリシーには、V8 分离メカニズム、CPU 時間制限、および防御的な API 設計が含まれます。たとえば、ランタイムのクロック精度は意図的に約 10 ミリ秒に調整されており、攻撃者が [Date](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date) オブジェクトから返される正確な時刻を使用してタイミングサイドチャネル攻撃を仕掛けるのを防ぎます。

* **実行コンテキスト** ：エッジ関数ランタイムは、厳格なコンテキスト分離を強制します。API 呼び出しはそれぞれのコンテキストに制限され、API によって作成されたオブジェクトのライフサイクルも正確に管理されます。詳細については、[エッジ関数の動作原理](https://docs.byteplus.com/en/docs/byteplus-cdn/function-how-it-works-jp) を参照してください。

* **API 互換性**：エッジ関数ランタイムは、一部の [WinterTC](https://wintertc.org/) 標準 API と互換性があり、エッジコンピューティングシナリオ専用の一連の API を提供します。これらの API の基盤となる C++ 実装は、リソース消費を最適化し、実行効率を向上させるように設計されています。同時に、セキュリティとパフォーマンス上の理由から、ランタイムは `net`、`process`、`fs` など、Node.js または Deno の一部の API をサポートしていません。
