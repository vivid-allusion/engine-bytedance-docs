このドキュメントでは、ログ検索の例を紹介します。これらの例は、ログの検索方法を理解するのに役立ちます。ドキュメントの目次を参照して、対応する例に移動できます。

ログを検索する際には、検索構文を理解する必要があります。検索ステートメントは、クエリステートメントと分析ステートメントの2つの部分で構成され、フォーマットは `<クエリステートメント>|<分析ステートメント>` です。分析ステートメントはオプションです。このドキュメントでは、検索構文について詳しく説明するのではなく、一般的な検索構文を例で示します。ログ検索の構文や、検索ステートメントで使用できる関数の詳細については、[ログ分析の概要](https://docs.byteplus.com/en/docs/tls/Analysis-overview) を参照してください。

検索結果をグラフで表示するように設定した場合、グラフをダッシュボードに追加して、グラフを簡単に表示できます。[ダッシュボードにグラフを追加する](https://docs.byteplus.com/en/docs/tls/Adding_charts_to_a_dashboard) を参照してください。

サンプルで使用されているログフィールドの説明については、[ログフィールドの説明](https://docs.byteplus.com/en/docs/byteplus-cdn/log-streaming-overview1_jp#%E3%83%AD%E3%82%B0%E3%83%95%E3%82%A3%E3%83%BC%E3%83%AB%E3%83%89) を参照してください。

<span id="インデックス設定の更新"></span>
### インデックス設定の更新

ログトピックのインデックス設定を次のように更新する必要があります。


* `ds_http_ua` のインデックスを有効にします。このフィールドは User\-Agent ヘッダーの値を記録します。

* `ds_http_status` のフィールドタイプを `double` に設定します。

   インデックス設定を更新すると、ログトピックに新しく配信されたログは更新後のインデックス設定を使用します。


インデックス設定を変更するには、次の手順に従います。


1.  **リアルタイムログ**  タブで、対応するタスクを見つけます。このタスクによって配信されるログのインデックスを設定します。

2. **操作** 列で、**検索** をクリックします。

3. **Query and analysis** ページで、**Index configuration** をクリックします。

4. ds_http_status のフィールドタイプを double に設定し、ds\-http_ua を有効に設定します。

   <span>![图片](https://sf16-resources.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/upload_cfcbec879f928461754bc5148d5b347e.png) </span>

5. **OK** をクリックして変更を保存します。


ログサービスにおけるインデックスの詳細については、[インデックスの設定](https://docs.byteplus.com/en/docs/tls/Configure-indexes-2) を参照してください。

## 指定した条件を満たすログのクエリ

<span id="指定したステータスコードのユーザーリクエストを取得する"></span>
### 指定したステータスコードのユーザーリクエストを取得する

要件：


* CDN の応答ステータスコードが 404 のユーザーリクエストを取得します。


検索構文：

```sql
ds_http_status:404
```


<span id="応答が遅いユーザーリクエストを取得する"></span>
### 応答が遅いユーザーリクエストを取得する

要件：


* 応答時間が 1 秒を超えるユーザーリクエストを検索します。


検索構文：

```sql
ds_req_time:>=1
```

### 指定した URL へのユーザーリクエストを取得する

要件：


* 指定した URL へのユーザーリクエストを取得します。


検索構文：

```sql
ds_http_uri: "/smoke.jpg"
```

## CDN のリクエストエラーを監視する

<span id="top-ドメインを統計する"></span>
### TOP ドメインを統計する

要件：


* リクエストエラー数が最も多い 10 個のドメインを取得します。


検索構文：

```sql
ds_http_status:>=400 | select domain,count(*) AS PV group by domain order by PV  DESC limit 10 
```

<span id="cdn-の応答サイズを統計する"></span>
### CDN の応答サイズを統計する

要件：


* 5 分を時間粒度として、各時間帯の以下のデータを統計します。

   * リクエストエラーに対応する CDN 応答サイズの平均値。

      5 分は 300000 ミリ秒です。


検索構文：

```sql
ds_http_status:>=400 |select __time__ - __time__ % 300000 as time,AVG(ds_http_resp_size) as SIZE group by time 
```


検索結果の表示：時系列グラフ

<span id="リクエストエラー数の割合を統計する"></span>
### リクエストエラー数の割合を統計する

要件：


* 5 分を時間粒度として、各時間帯のリクエストエラー数の割合を統計します。


5 分は 300000 ミリ秒です。

検索構文：

```sql
* | select __time__ - __time__ % 300000 as time , sum(case when ds_http_status BETWEEN 400 AND 599  then 1 else 0 end) / count(*) as percent group by time
```


検索結果の表示：時系列グラフ

<span id="リクエストエラーコードの数を取得する"></span>
### リクエストエラーコードの数を取得する

要件：


* エラーコードに基づいてリクエストエラーの数を統計します。


検索構文：

```sql
ds_http_status:>=400 | select ds_http_status,count(*) As errors group by ds_http_status
```


検索結果の表示：円グラフ

## CDN サービス指標を監視する

<span id="応答合計バイト数ランキングと平均応答時間を統計する"></span>
### 応答合計バイト数ランキングと平均応答時間を統計する

要件：


* URL に基づいて CDN 応答の合計バイト数と平均応答時間を統計し、応答の合計バイト数に基づいて結果を降順に並べ替えます。


応答時間の単位は秒です。

検索構文：

```sql
* | select domain,ds_http_uri,ds_http_resp_content_type,sum(ds_http_resp_size) AS total_size,avg(ds_http_resp_size)  AS resource_size,avg(ds_req_time) as avg_resp_time, count(*) as PV group by domain,ds_http_uri,ds_http_resp_content_type  order by total_size DESC
```


検索結果の表示：テーブル

<span id="応答が遅いリクエスト数の割合を統計する"></span>
### 応答が遅いリクエスト数の割合を統計する

要件：


* クライアント IP に基づいて以下のデータを統計します。データは降順に並べ替えられます。

   * 応答時間が 10 秒を超えるリクエスト数の割合。


検索構文：

```sql
* | select client_ip, pv/c as rate from (select client_ip, sum(case when ds_req_time > 10 then 1 else 0 end) as pv, count(*) * 1.0000 as c group by client_ip ) order by rate DESC
```


検索結果の表示：テーブル

<span id="cdn-がユーザーにデータを転送する速度を統計する"></span>
### CDN がユーザーにデータを転送する速度を統計する

速度の単位は Mbps です。

要件：


* 5 分の時間粒度に基づいて、各時間帯のデータ転送速度を統計します。


データ転送速度の単位は Mbps です。5 分は 300000 ミリ秒です。

検索構文：

```sql
* |select __time__ - __time__ % 300000 as time,avg(ds_http_resp_size)*8/1000/1000/avg(ds_req_time) as download_speed group by time
```


検索結果の表示：時系列グラフ

<span id="cdn-の応答時間を統計する"></span>
### CDN の応答時間を統計する

要件：


* 5 分の時間粒度に基づいて、各時間帯の平均応答時間を統計します。


応答時間の単位は秒です。5 分は 300000 ミリ秒です。

検索構文は次のとおりです。

```sql
* |select __time__ - __time__ % 300000 as time,AVG(ds_req_time) as req_time group by time
```


検索結果の表示：時系列グラフ

<span id="ヒット率を統計する"></span>
### ヒット率を統計する

要件：


* 5 分の時間粒度に基づいて、各時間帯のキャッシュヒット率とトラフィックヒット率を統計します。


5 分は 300000 ミリ秒です。

検索構文：

```sql
* | select __time__ - __time__ % 300000 as Time , sum(case when ds_http_bd_status_hit='hit'  then 1 else 0 end) / count(*) as count_percent , sum(case when ds_http_bd_status_hit='hit'  then ds_http_resp_size else 0.0 end) / sum(ds_http_resp_size) as size_percent group by Time
```


検索結果の表示：時系列グラフ
