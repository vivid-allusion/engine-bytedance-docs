<span id="cdn請求書の確認方法"></span>
## **CDN請求書の確認方法**

[BytePlus費用センター](https://console.byteplus.com/financial/overview)でCDN請求書を確認できます。

<span id="cdnの無料トライアルまたはテスト方法"></span>
## CDNの無料トライアルまたはテスト方法

CDNを開通した後、1TBのトラフィックリソースパックと1,000万リクエストのリソースパックを無料で受け取ることができます。有効期間は受け取り日から1年間です。これらのリソースパックを使用してCDNを試用またはテストできます。[CDNコンソールのリソース管理ページ](https://console.byteplus.com/financial/resource-package)でリソースパックの残量を確認できます。

<span id="cdnの課金方式の変更方法"></span>
## **CDNの課金方式の変更方法**

CDNを開通する際、デフォルトの課金方式はトラフィック従量課金で、1時間ごとに請求され、後払いです。他の課金方式を使用する必要がある場合は、[サポートチケットを提出](https://console.byteplus.com/workorder/create)してください。

<span id="cdn中間層のノードが生成するトラフィックは課金されますか"></span>
## **CDN中間層のノードが生成するトラフィックは課金されますか** 

CDNはエッジノードがユーザーからのリクエストに応答する際に生成されるトラフィックのみを課金します。中間層ノードが生成するトラフィックは課金されません。

<span id="cdn請求書に表示されるトラフィックとログに記録されるトラフィックが一致しない理由"></span>
## **CDN請求書に表示されるトラフィックとログに記録されるトラフィックが一致しない理由**

ユーザーからのリクエストに対して、CDNログに記録されるトラフィックはリクエストされたファイル自体のサイズですが、請求書に表示されるトラフィックはキャッシュノードがリクエストに応答して生成したトラフィックです。この応答トラフィックは、管理コンソールの[トラフィック](https://console.byteplus.com/cdn/cdn-volc/statistical-analysis/band-width)ページに表示されるトラフィックと同じであり、業界標準に従って統計されています。以下の2つの部分で構成されています：


* リクエストされたファイル自体のトラフィック。このトラフィックはCDNログに記録されるトラフィックと同じです。

* TCP/IPパケットヘッダーおよびTCP再送によって生成されるトラフィック。このトラフィックは応答トラフィックの約10%を占めます。


**TCP/IPパケットヘッダー** 

HTTPリクエストはTCP/IPプロトコルに基づいています。送信される各TCPパケットのサイズは46〜1,500バイトで、TCPプロトコルを表す20バイトのヘッダーとIPプロトコルを表す20バイトのヘッダーが含まれます。

各送信TCPパケットはイーサネットフレーム内で送信されます。現在のイーサネットフレーム形式はEthernet II形式を採用しています。形式は：プリアンブル(8バイト) | 宛先MAC(6バイト) | 送信元MAC(6バイト) | タイプ(2バイト) | データ(46〜1500バイト) | FCS(4バイト)です。したがって、各イーサネットフレームのヘッダーは追加で26バイト増加し、イーサネットフレームの最大サイズは1,526バイトです。

したがって、イーサネットフレーム内で、各種ヘッダーの合計サイズは20 + 20 + 26 = 66バイトです。これらのヘッダーはオペレーティングシステムのカーネル層のプロトコルスタックによって追加されるため、CDNログはこの66バイトを統計できません。TCP再送、TCP 3ウェイハンドシェイク、TCP 4ウェイハンドシェイクプロセス中のヘッダーを統計に含めない場合、これらのヘッダーが生成するトラフィックはCDNログが統計するトラフィックの約4.52%です。計算式は：[66\*(ログトラフィック/1460)]/ログトラフィック = 66/1460 = 4.52%です。

**TCP再送**

TCPパケットの送信過程で、ネットワークの揺らぎなどの理由により3%〜10%のTCPパケットが失われる可能性があります。サーバーは失われたパケットを再送します。再送もオペレーティングシステムのカーネル層のプロトコルスタックによって行われるため、CDNログは再送されたTCPパケットを統計できません。一般的に、再送されたTCPパケットが生成するトラフィックはCDNログが統計するトラフィックの約3%〜7%です。

<span id="cdn帯域幅使用量の単位1gbpsは何mbpsに相当しますか？"></span>
## CDN帯域幅使用量の単位1Gbpsは何Mbpsに相当しますか？

帯域幅使用量の進数は1,000です。つまり：1Gbps = 1000 Mbps、1Mbps = 1000 Kbps、1Kbps = 1000 bpsです。

<span id="cdnトラフィック使用量の単位1gbは何mbに相当しますか"></span>
## **CDNトラフィック使用量の単位1GBは何MBに相当しますか** 

トラフィック使用量の進数は1,000です。つまり：1GB = 1000 MB、1MB = 1000 KB、1KB = 1000 Bです。

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">GBとGiBは異なる単位です。MBとMiB、KBとKiBも同様です。</div>


<div data-tips="true" data-tips-type="tip">GiB、MiB、KiBは進数1,024を使用します。</div>


<span id="cdnサービスの解約方法"></span>
## **CDNサービスの解約方法**

CDNサービスを開通した後、コンソールまたは特定のAPIを使用してCDNサービスを解約することはできません。CDNサービスを解約する必要がある場合は、[サポートチケットを提出](https://console.byteplus.com/workorder/create)してください。

<span id="cdnが4xxステータスコードを応答する際に料金が発生するか"></span>
## CDNが4xxステータスコードを応答する際に料金が発生するか

簡単な回答：「はい」。

CDNでは、悪意のあるリクエストがあなたのドメイン名にアクセスするのを防ぐために、アクセス制御ルールを設定することができます。例えば、CDNはリファラーのブラックリスト/ホワイトリスト、URLの認証、オリジンのブラックリスト/ホワイトリスト、UAのブラックリスト/ホワイトリスト、リモート認証、地域アクセス制御などのアクセス制御機能を提供しています。

ユーザーからのリクエストを受信した際、そのリクエストが設定されたアクセス制御ルールに合致する場合、CDNはこれらのリクエストを拒否し、4xxステータスコードを応答します。応答にファイルは含まれていませんが、応答ヘッダーが含まれており、応答本文にも特定のメッセージが含まれています。これらの応答はCDNがユーザーに送信したデータとみなされます。

したがって、ステータスコードが4xxのCDN応答によって生成されたトラフィックと帯域幅の使用量は課金対象となります。同時に、拒否されたリクエストもCDNが受信したリクエスト数としてカウントされ、課金されます。これらの費用はあなたの請求書に含まれることになります。

注意すべき点は、あなたのドメイン名が大量の悪意のあるリクエストを受信した場合、これらの拒否されたリクエストでも「リクエスト数」という課金項目で高額な請求が発生する可能性があることです。

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">ステータスコードが2xxと4xx以外のユーザーからのリクエストも、トラフィックと帯域幅の使用量を生成し、リクエスト数としてカウントされて課金されます。</div>
