## 边缘函数运行时与 Node.js 或 Deno 等运行时有何异同？

边缘函数运行时是部署于全球边缘节点上的轻量级函数即服务（FaaS）环境。其设计初衷与传统的中心云 FaaS 不同，专注于处理大规模、高弹性、低延迟的业务场景。

边缘函数运行时与 Node.js 或 Deno 等运行时的差异如下：


* **架构与资源管理**：边缘函数运行时基于 V8 隔离环境构建，实现了轻量级的多租户隔离。该架构对每个租户的计算和内存资源进行精密控制，包括内存使用、CPU 执行时间及函数响应时间等。更多信息，请参见[使用限制](https://docs.byteplus.com/en/docs/byteplus-cdn/functions-usage-limits)。

* **安全性**：为保障运行时环境的安全，边缘函数采取了多层安全策略，有效防范恶意代码攻击。这些策略包括 V8 隔离机制、CPU 时间限制以及防御性的 API 设计。例如，边缘函数运行时的时钟精度被调整至 10 毫秒左右，以防范攻击者利用 [Date](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date) 对象返回的精确时间进行时序侧信道攻击（Timing Side\-Channel Attack）。

* **执行上下文**：边缘函数运行时强制实施严格的上下文隔离。API 调用被限制在各自的上下文中，且由 API 创建的对象的生命周期也受到精确管理。详细信息，请参见[工作原理](https://docs.byteplus.com/en/docs/byteplus-cdn/how-functions-work)。

* **API 兼容性**：边缘函数运行时兼容部分 [WinterTC](https://wintertc.org/) 的标准 API，并提供了一些边缘函数专属 API。边缘函数运行时 API 的底层由 C++ 实现，旨在降低资源消耗，提升执行效率。同时，出于安全和性能考虑，边缘函数运行时不支持 Node.js 或 Deno 中的部分 API，如 `net`、`process`、`fs` 等。
