本文档介绍如何在 BytePlus CDN 中启用智能压缩。

开启智能压缩后，您可以创建规则，指定哪些类型的文件需要压缩以及所使用的压缩算法。在 CDN 收到请求时，如果请求匹配了某条规则，CDN 会根据规则的配置对请求的文件进行压缩，然后返回压缩后的文件。该功能可以减小文件的大小，提高文件传输速度，降低流量消耗。

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">如果请求匹配了某条智能压缩规则，CDN 除了返回压缩文件，还会缓存压缩后的文件。也就是说，对于同一个文件，CDN 会分别缓存原始副本和压缩副本。</div>


<span id="支持的压缩算法"></span>
## 支持的压缩算法

智能压缩支持 Gzip 和 Brotli 压缩算法。


* Gzip 是 Internet 上普遍使用的数据压缩格式，Gzip 对一般纯文本文件可压缩到原大小的 40％。

* Brotli 是 Google 在 2015年9月推出的一种压缩算法，在压缩率和压缩性能上比 Gzip 有了很大的提升。目前绝大部分浏览器都支持 Brotli。


<span id="相关的请求头和响应头"></span>
## 相关的请求头和响应头

如果客户端可以处理压缩的数据，用户请求需要包含 `Accept-Encoding` 头部并指明客户端支持的压缩算法以及权重。权重是可选的。例如 `Accept-Encoding: gzip;q=0.8, br;q=0.6` 表示客户端同时支持 Gzip 和 Brotli，但是 Gzip 优先。如果请求中不包含该头部，表示客户端不能处理压缩数据。

CDN 的响应中包含 `Content-Encoding` 头部，指示了响应的文件所使用的压缩算法。

<span id="支持的文件类型"></span>
## 支持的文件类型

当前，智能压缩仅支持对 `Content-Type` 响应头是以下类型的文件进行压缩。如果您需要压缩的文件类型不在以下列表中，请 [提交工单](https://console.byteplus.com/workorder/create)。


* text/html

* text/xml

* text/plain

* text/css

* application/javascript

* application/x\-javascript

* application/rss+xml

* text/javascript

* image/tiff

* image/svg+xml

* application/json

* application/xml


<span id="注意事项"></span>
## 注意事项


* CDN 仅对 GET 请求的文件进行压缩。

* 如果源站开启了压缩功能，且源站响应中 `Content-Encoding` 头部的值不为空且不为 `identity`，表明源站已经对该文件进行了压缩。在这种情况下，CDN 不再对该文件进行压缩。

* 如果您在智能压缩配置中同时勾选了 Brotli 压缩和 Gzip 压缩，且用户请求中的 `Accept-Encoding` 头部的值包含 `br` 和 `gzip` 时，，有以下两种情况：

   * 如果 `Accept-Encoding` 不包含算法的权重，CDN 使用 Brotli 算法对请求文件进行压缩。

   * 如果 `Accept-Encoding` 包含算法的权重，CDN 使用权重高的算法对请求文件进行压缩。

* 如果请求为 Range 请求并且匹配了某条智能压缩规则，则，

   * 如果 CDN 节点存在请求文件的压缩副本，CDN 会从压缩副本中提取请求的分片，并返回**压缩后**的分片。

   * 如果 CDN 节点不存在请求文件的压缩副本，CDN 会返回**未压缩**的分片。

* 若源站文件配置了 MD5 校验机制，请勿开启智能压缩功能。

* 所有浏览器都支持 Gzip。老版本浏览器可能不兼容 Brotli。您可以[查看 Brotli 的浏览器兼容情况](https://caniuse.com/?search=Brotli)。

* 如果源站响应中 Vary 头部没有遵循 [RFC 标准](https://datatracker.ietf.org/doc/html/rfc7231#section-7.1.4)，则可能会导致压缩功能不生效。


<span id="操作步骤"></span>
## 操作步骤


1. 打开 **智能压缩** 配置页面。操作步骤参见 [域名配置](https://docs.byteplus.com/en/docs/byteplus-cdn/domain-management_zh-cn)。

2. 设置 **状态** 为 **开启**。

3. 点击 **添加规则**。您最多可以添加 50 条规则。

4. 参照下方 [配置说明](https://docs.byteplus.com/en/docs/18/6955#%E9%85%8D%E7%BD%AE%E8%AF%B4%E6%98%8E) 对规则进行设置。

5. 配置完成后，点击 **保存**。

<span id="配置说明"></span>
## 配置说明


|**配置** |**说明** |
|---|---|
|规则类型 |表示规则中的过滤类型。该配置有以下选项：<br><br><br>* **文件后缀**：表示路径末尾的扩展名。<br><br>* **URL 目录**：表示路径中的一个目录。<br><br>* **URL 全路径**：表示请求 URL 中的路径。<br><br>* **内容类型**：表示请求中的 `Content-Type` 请求头。<br><br><br>规则列表中只能有一条规则类型是 **内容类型** 的规则。这条规则的优先级是最低的，您也无法调整其优先级。 |
|规则 |表示规则中的过滤值，过滤值大小写不敏感。多个过滤值之间使用分号（;）分隔，总长度不能超过 1,024 个字符，不能包含以下字符：<br><br><br>* 连续斜杠（//）、空格、美元符号（$）、问号（?）、Delete（ASCII code 127）。<br><br><br>另外，<br><br><br>* 如果 **规则类型** 是 **文件后缀**，过滤值是一个或者多个文件后缀。文件后缀无需以句点（.）开头。例如：`png;txt`。<br><br>* 如果 **规则类型** 是 **URL 目录**，过滤值是一个或者多个目录路径。目录路径必须以斜杠（/）开头和结尾。例如：`/chs/foods/;/us/birds/`。<br><br>* 如果 **规则类型** 是 **URL 全路径**，过滤值是一个或者多个文件路径。文件路径必须以斜杠（/）开头，可以包含星号（\*）用来表示一个或者多个字符。例如：`/chs/foods/local*sets;/us/birds/chickadee`。<br><br>* 如果 **规则类型** 是 **内容类型**，控制台提供以下选项：<br><br>   * **默认**：表示规则应用于以下所有文件类型：text/html、text/xml、text/plain、text/css、application/javascript、application/x\-javascript、application/rss+xml、text/javascript、image/tiff、image/svg+xml、application/json、application/xml、text/plain; charset=utf\-8。<br><br>   * **定制**：表示规则应用于您指定的文件类型。您可以从列表中勾选一个或者多个文件类型。您也可以输入不在文件列表中的文件类型。 |
|文件大小（最小） |表示一个文件大小。如果请求文件的大小小于该值，则 CDN 不会压缩该文件。该配置的取值范围 0 \- 2,147,483,647，单位是 KB，使用的进制是 1,024。如果该配置值是 `0`，表示无论文件大小，CDN 始终对文件进行压缩。 |
|压缩算法 |表示该规则对指定类型的符合过滤条件的请求文件所使用的压缩算法。该配置有以下取值：<br><br><br>* Gzip<br><br>* Brotli<br><br><br>CDN 在使用 Brotli 算法压缩请求文件时，使用的压缩级别是 6。<br><br>&nbsp;<br><br>Brotli 提供了 12 个压缩级别，从 0 到 11，其中 0 提供最快的压缩速度，但压缩比最低，11 提供最高的压缩比，但需要更多的计算资源和压缩时间。 |


<span id="规则生效逻辑"></span>
## 规则生效逻辑

当收到用户请求时，CDN 基于规则在列表中出现的顺序，依次处理规则。在处理规则时，CDN 尝试将规则与请求匹配。如果任意一条规则匹配了请求，CDN 对请求文件应用压缩配置，并停止处理其余规则。您可以拖动规则调整规则在列表中的出现顺序。
