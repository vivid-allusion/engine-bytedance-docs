本文档介绍如何在 BytePlus CDN 中配置源站预建连。

<span id="功能说明"></span>
## 功能说明

默认情况下，CDN 节点在回源时不会与源站保持 TCP 长连接。每次需要回源获取内容时，CDN 节点都会建立新的 TCP 连接；对于 HTTPS 回源请求，还需要完成 TLS 握手。

开启源站预建连后，CDN 节点会在首次回源时与源站建立 TCP 长连接。后续回源请求优先复用该连接，无需重复执行 TCP 建连；对于 HTTPS 回源请求，也可避免重复进行 TLS 握手，从而降低回源建连耗时。

<span id="连接保持时间"></span>
## 连接保持时间

连接保持时间默认为 `3600` 秒。控制台暂不支持自定义；如需调整，请 [提交工单](https://console.byteplus.com/workorder/create?step=2&SubProductID=P00000735)。

在连接保持时间内，如果连接可用，CDN 节点会优先复用该连接处理后续回源请求。每次复用连接处理回源请求后，连接保持时间会重新开始计算。连接超时、被源站关闭或发生异常时，CDN 节点会在后续回源请求到达时重新建立连接。

<span id="适用场景"></span>
## 适用场景

源站预建连适用于以下场景：


* 回源请求较频繁，希望减少 TCP 或 TLS 重复建连耗时。尤其适用于回源请求以批次方式间歇发起，且相邻批次的间隔在连接保持时间内的场景。例如，从对象存储回源拉取文件时，首批请求建立的连接可由后续批次复用。

* 源站距离 CDN 节点较远，TCP 或 TLS 建连时延较高。

* 动态内容、接口请求等无法完全由 CDN 缓存响应，且对回源时延敏感。


对于回源请求较少的域名，连接复用带来的收益可能有限。

<span id="注意事项"></span>
## 注意事项


* 开启源站预建连后，当多个 CDN 节点分别向源站回源时，各节点建立的 TCP 长连接会在连接保持时间内保留，源站同时保持的连接数可能增加。请确认源站具备足够的连接处理能力。

* 建议将源站的空闲连接超时时间设置为不低于 `3600` 秒。否则，源站可能提前关闭空闲连接，CDN 后续回源请求需要重新建立连接。

* 本功能用于优化 CDN 到源站之间的连接建立过程，不影响客户端与 CDN 节点之间的连接配置。


<span id="操作步骤"></span>
## 操作步骤


1. 打开 **源站预建连** 配置页面。操作步骤参见 [域名配置](https://docs.byteplus.com/en/docs/byteplus-cdn/domain-management_zh-cn)。

2. 设置 **状态** 为 **开启**。

3. 点击 **保存**。


配置生效后，CDN 节点会在首次回源时建立与源站的 TCP 长连接；在连接可用且处于连接保持时间内时，后续回源请求会优先复用该连接。
