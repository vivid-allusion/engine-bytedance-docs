<span id="缓存刷新概述"></span>
## 缓存刷新概述

在 BytePlus CDN 中，每个被缓存的文件都有一个缓存过期时间。如果一个文件在缓存中未过期，但是源站上该文件已被更新，CDN 还是会将缓存的文件发送给用户。此时，如果您需要用户能获取源站上更新后的该文件，您可以使用 CDN 提供的"缓存刷新"功能。

<span id="工作原理"></span>
## 工作原理

您使用"缓存刷新"为特定文件或者目录提交刷新任务。


* 对于文件刷新，CDN 会从缓存中删除指定的文件。之后，当收到这些文件的请求时，CDN 会向源站请求文件。

* 对于目录刷新，CDN 会将指定目录下已缓存的文件标记为已过期。当收到这些文件的请求时，CDN 会向源站发送文件校验请求。关于文件校验的流程描述，参见 [回源校验](https://docs.byteplus.com/en/docs/byteplus-cdn/docs_cn-caching-rules-cn#%E5%9B%9E%E6%BA%90%E6%A0%A1%E9%AA%8C)。


<span id="适用场景"></span>
## 适用场景

"缓存刷新"适用于以下场景：


* 您站点上有关键文件被更新了，您需要用户获取最新的文件。

* 源站上的特定文件由于某些原因需要被删除。然而，这些文件可能已被 CDN 缓存了。您不希望用户访问这些文件。


<span id="注意事项"></span>
## 注意事项


* "缓存刷新" 可以确保用户获取最新版本的文件。但是当一个文件被刷新后，该文件的第一次访问是无法获得加速的。如果您需要该文件的第一次访问能被加速，在刷新任务成功执行后，您可以使用 [文件预热](https://docs.byteplus.com/en/docs/byteplus-cdn/docs_cn-prefetch-cn) 功能。

* 在您提交刷新任务后，其生效时间大约是 5 分钟。

* 在您对大量文件提交刷新任务后，这些文件的请求会触发回源请求。因此您的源站可能会在短期内承受流量压力，特别是在文件体积较大的时候。


<span id="刷新配额"></span>
## 刷新配额

您主账号下每天可刷新的文件和目录有以下限额：


* 如果您刷新的是文件，您每天最多可以刷新 10,000 个文件。每个刷新任务中最多可以包含 100 个 URL。

* 如果您刷新的是目录，您每天最多可以刷新 50 个目录。

* 您不能直接对泛域名下的文件和目录执行刷新操作，而是要对每个子域名进行这些操作。


<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">刷新配额是主账号和子账号共用的。</div>


<span id="操作步骤"></span>
## 操作步骤


1. 登录 [BytePlus CDN 管理控制台](https://console.byteplus.com/cdn)。

2. 在左侧导航栏，点击 **工具中心** \> **刷新预热**。

3. 在 **刷新预热** 页面，点击 **缓存刷新** 标签页。

4. 参照以下配置说明。

5. 配置完成后，点击 **提交**。

<span id="配置说明"></span>
## 配置说明


|**配置** |**说明** |
|---|---|
|任务类型 |表示任务的类型。该配置有以下取值：<br><br><br>* **URL 刷新**：表示刷新的对象是一个或者多个文件。<br><br>* **目录刷新**：表示刷新的对象是一个或者多个目录。<br><br><br>您账号下每天可刷新的文件和目录的数量是有限额的。参见 [刷新配额](https://docs.byteplus.com/docs/byteplus-cdn/docs_cn-purge-cn#%E5%88%B7%E6%96%B0%E9%85%8D%E9%A2%9D)。 |
|前缀刷新 |表示是否开启前缀刷新。该配置仅当 **任务类型** 是 **目录刷新** 时才会出现，默认是关闭。 |
|URLs |表示需要刷新的 URL。该配置有以下取值：<br><br><br>* **手动输入**：表示手动输入那些需要刷新的 URL。<br><br>* **上传文件**：表示上传一个 .txt 文本文件。需要刷新的 URL 包含在该文本文件中。<br><br><br>URL 必须满足以下条件：<br><br><br>* 如果 **任务类型** 是 **URL 刷新**，您可以指定最多 100 个文件的 URL。文件 URL 必须满足以下条件：<br><br>   * 文件 URL 必须 以 `https://` 或者 `http://` 开头。<br><br>   * 多个文件 URL 以换行分隔。<br><br>* 如果 **任务类型** 是 **目录刷新** 时，有以下说明：<br><br>   * 如果 **前缀刷新** 未开启，您可以指定最多 100 个目录的 URL。目录 URL 必须满足以下条件：<br><br>      * 目录 URL 必须 以 `https://` 或者 `http://` 开头，并且以 `/` 结尾。<br><br>      * 多个目录 URL 以换行分隔。<br><br>   * 如果 **前缀刷新** 已开启，您可以指定最多 100 个用于匹配目录 URL 的前缀。例如 `http://example.com/im` 可用于匹配 `http://example.com/image/` 和 `http://example.com/imece`。 |
|根据HTTP请求头刷新 |用于指定待刷新文件在缓存键中必须包含的请求头。只有当缓存文件的缓存键中完全包含了此处指定的请求头时，该文件才会被匹配并刷新。<br><br>&nbsp;<br><br>&nbsp;<br><br>请求头有以下要求：<br><br><br>* 您最多可以指定 10 个请求头。<br><br>* 请求头不能为 User\-Agent ，也不能以 `x-bdcdn-` 或 `Volc-Cdn` 开头。<br><br>* 请求头和请求头的值均不能超过 1,024 个字符。<br><br><br>此配置的常见使用场景如下：<br><br><br>* 您使用规则引擎配置了参与缓存键构造的请求头列表。在执行刷新操作时，您希望只刷新缓存键中包含指定请求头的文件。 |
