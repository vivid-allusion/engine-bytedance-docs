<span id="文件预热概述"></span>
## 文件预热概述

在 BytePlus CDN 中，如果一个文件未被缓存，则该文件的首次请求无法命中缓存。如果您希望首次请求也能命中缓存，可以使用 "文件预热" 功能。

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">"文件预热" 不会产生费用。</div>


<span id="适用场景"></span>
## 适用场景

"文件预热" 适用于以下场景：


* 预期有高访问流量的文件，例如某个软件的安装包。当您在站点上发布该安装包后，您可以对该安装包提交一个预热任务。这样，该安装包的下载就能立刻被加速。

* 大型活动的宣传页面。在活动开始前，您可以为该活动的那些宣传页面提交一个预热任务。当活动开始时，用户就能快速打开这些页面。


<span id="注意事项"></span>
## 注意事项


* 在您提交预热任务后，回源节点会向您的源站请求预热任务中指定的文件。如果预热任务中包含的文件较多，您的站点可能会在短期内承受流量压力，特别是某些文件体积较大的时候。为此，CDN 提供了 "并发限制" 配置。该配置指定了 CDN 在处理一个刷新任务时，回源节点单次向源站请求的文件的最大数量。参见 [配置说明](https://docs.byteplus.com/en/docs/18/6993#%E9%85%8D%E7%BD%AE%E8%AF%B4%E6%98%8E)。

* 根据被预热的文件的实际大小，预热任务的完成时间会有差异。

* 在对一个文件提交预热任务时，如果该文件已被 CDN 缓存并且缓存文件未过期，CDN 不会对该文件进行预热。对此，我们有以下建议：

   * 无论该文件是否被缓存，在提交预热任务前，先对该文件提交 [缓存刷新](https://docs.byteplus.com/en/docs/byteplus-cdn/docs_cn-purge-cn) 任务。对于该建议，如果文件未被缓存，刷新操作依然会消耗一次刷新额度。

   * [判断该文件是否被缓存](https://docs.byteplus.com/en/docs/18/6993#%E5%A6%82%E4%BD%95%E5%88%A4%E6%96%AD%E8%AF%B7%E6%B1%82%E6%98%AF%E5%90%A6%E5%91%BD%E4%B8%AD-cdn-%E7%9A%84%E7%BC%93%E5%AD%98)。如果该文件已被缓存，才提交 [缓存刷新](https://docs.byteplus.com/en/docs/byteplus-cdn/docs_cn-purge-cn) 任务。


<span id="预热配额"></span>
## 预热配额

主账号下每天可预热最多 1,000 个文件。

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">预热配额是主账号和子账号共用的。</div>


<span id="操作步骤"></span>
## 操作步骤


1. 登录 [BytePlus CDN 管理控制台](https://console.byteplus.com/cdn)。

2. 在左侧导航栏，点击 **工具中心** \> **刷新预热**。

3. 在 **刷新预热** 页面，点击 **文件预热新** 标签页。

4. 参照以下 [配置说明](https://docs.byteplus.com/en/docs/18/6993#%E9%85%8D%E7%BD%AE%E8%AF%B4%E6%98%8E)。

5. 配置完成后，点击 **提交**。


<span id="配置说明"></span>
### 配置说明


|**配置** |**说明** |
|---|---|
|URLs |表示需要预热的文件的 URL。该配置有以下取值：<br><br><br>* **手动输入**：表示手动输入那些需要预热的文件的 URL。您一次最多可以提交 100 个 URL。<br><br>* **上传文件**：表示上传一个 .txt 文本文件。需要预热的文件的 URL 包含在该文本文件中。<br><br><br>文件 URL 必须满足以下条件：<br><br><br>* 文件 URL 必须 以 `https://` 或者 `http://` 开头。<br><br>* 多个文件 URL 以换行分隔。<br><br><br>您账号下每天可预热的 URL 数量是有限额的。参见 [预热配额](https://docs.byteplus.com/en/docs/18/6993#%E9%A2%84%E7%83%AD%E9%85%8D%E9%A2%9D)。 |
|并发限制 |表示对于一个文件预热任务，CDN 向源站同时发起的请求的最大数量。该配置的默认值是 10。您可以设置的范围是 1\-1,000。<br><br>&nbsp;<br><br>您可以根据源站的请求处理能力，设置合理的请求并发数。 |

<span id="如何判断请求是否命中-cdn-的缓存"></span>
## 如何判断请求是否命中 CDN 的缓存

在 CDN 对用户请求的响应中，`X-Response-Cache` 头部表示请求是否命中了缓存。


* `edge_hit`：表示命中缓存。

* `miss`：表示未命中缓存。


您也可以通过 [CDN 响应头设置](https://docs.byteplus.com/en/docs/byteplus-cdn/docs_cn-cdn-response-headers-cn) 来获取 `cdn_cache_status` 变量的值。该变量表示请求是否命中了缓存。
