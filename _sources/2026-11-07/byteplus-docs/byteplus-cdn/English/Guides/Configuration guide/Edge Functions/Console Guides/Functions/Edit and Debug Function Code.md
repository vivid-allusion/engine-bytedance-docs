This document describes how to edit and debug function code.

<span id="limitations"></span>
## Limitations

The debugging environment for Edge Functions currently does not support running the [Edge KV Runtime API](https://docs.byteplus.com/docs/byteplus-cdn/docs-EdgeKV-RuntimeAPI). The Edge KV Runtime API can only run in the production environment.

<span id="steps"></span>
## Steps

Follow these steps to edit and debug function code.


1. Open the [Functions](https://console.byteplus.com/cdn/edge-function/list) page.

2. Find the function whose code you want to edit and debug, and click on the function name.

3. Select the **Code** tab, click **Modify and deploy**.

   <span>![图片](https://sf16-resources.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/upload_869cdf45d45bf711437ade4681dc70b9.jpeg) </span>

4. Use the code editor to edit the code.

   <span>![图片](https://sf16-resources.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/upload_cab1cf52c0a881a2f7db7ac12d510501.jpeg) </span>

5. In the HTTP tab, configure the debugger settings per the following list. Click **Send**. You can view the function execution results in the right area of the page. View the function's logs, execution information, and performance in the bottom area of the page.

   * Select the HTTP request method.

   * Enter a URL to simulate a user request. By default, the function uses a URL similar to `http://a5624*****33b010b` to simulate user requests, where `a5624*****33b010b` is the function's ID. This URL can be used to trigger fetch events. However, this URL can only be used for internal testing in the Debugger and cannot be accessed from the internet. In addition, for user requests simulated in the Debugger, the property values in `FetchEvent.info` are all `undefined`. Therefore, a Debugger error does not necessarily mean that your code is wrong. You need to test the code that the Debugger does not support in a canary environment.

   * (Optional) Add Header and Body.

      * Header: Customize HTTP request headers.

      * Body: Customize HTTP request body.

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">You need to send requests to debug the function when the HTTP tab shows a green dot. If you haven't performed any operations for a long time, the debugger will disconnect from the server. At this time, the HTTP tab will show a red dot, and you won't be able to debug. After refreshing the page, the debugger will automatically reconnect, and the HTTP tab will show a green dot.   </div>
   

6. Check the **Console**, **Insight**, and **Profiler** tabs to monitor the function execution.



<Tabs>
<Tab zoneid="Ejhqsx4BPJ" title="Console">
<TabTitle>Console</TabTitle>

The content of the response body is not automatically recorded in the logs. You need to use `console.log()` /`console.info()`/`console.error()`/`console.trace()` statements in the function code to customize the log information you want to view.


</Tab>
<Tab zoneid="haKbDIW0nN" title="Insight">
<TabTitle>Insight</TabTitle>

Check **Enable insight** under the **Insight** tab. After sending a request, you can view the code execution information generated by the function's most recent request.

<img src="https://sf16-resources.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/upload_42669eb6afa6634dcf1ff79fe0517f89.jpeg" width="800px" /></div>



</Tab>
<Tab zoneid="bKafP9DWXH" title="Profiler">
<TabTitle>Profiler</TabTitle>

Under the **Profiler** tab, you can analyze the function's response performance using a flame graph.

<div style="text-align: center">
<img src="https://sf16-resources.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/upload_4c829d8fbc994d3801b722e44ef7326f.jpeg" width="800px" /></div>



&nbsp;

1. Click the ● icon to start recording.

2. Click **Send** to trigger the code.

3. Click **Stop recording**, and a flame graph of the CPU Profiler will be generated.


</Tab>
</Tabs>



7. After debugging, click **Save**.
