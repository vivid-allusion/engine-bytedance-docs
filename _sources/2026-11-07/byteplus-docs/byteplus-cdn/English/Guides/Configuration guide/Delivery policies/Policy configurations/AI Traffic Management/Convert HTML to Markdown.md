This document describes how to enable Markdown Format Conversion (HTML to Markdown) in BytePlus CDN. After the feature is enabled, edge nodes can convert HTML responses into Markdown, making the content easier for AI agents, crawlers, and other automated clients to consume.

<span id="3a499196"></span>
## Feature overview

HTML to Markdown is an AI traffic management feature in CDN that converts HTML responses into Markdown for AI clients. After it is enabled, CDN edge nodes automatically convert HTML content returned by the origin into Markdown when a request for an HTML resource includes the `Accept: text/markdown` request header.

The conversion is completed at edge nodes. You do not need to modify the origin. AI agents and crawlers can directly obtain Markdown versions of HTML pages. This provides the following benefits:


* **Reduce token usage:**  Raw HTML contains a large amount of markup, scripts, styles, and other information unrelated to the page content. After conversion to Markdown, the response is more compact, which can reduce the number of tokens used during AI processing.

* **Make content easier for AI agents and crawlers to parse and process:**  Structured Markdown is easier for large language models to parse and understand, helping AI search systems extract and use website content more effectively.

* **Reduce origin\-side development work:**  You do not need to deploy HTML conversion logic at the origin. Processing is completed at CDN edge nodes.


<span id="6ccd4d4d"></span>
## Conversion details


|Item |Description |
|---|---|
|**Trigger** |CDN decides whether to convert the response based on the request header. CDN performs conversion only when the request header includes `Accept: text/markdown`. |
|**Origin response content type** |The origin response `Content-Type` must be `text/html`. |
|**Conversion result** |Markdown content. |
|**Response header** |After conversion is complete, CDN returns `content-type: text/markdown; charset=utf-8` in the response header. |
|**Conversion logic** |The current version does not extract the main content or remove non\-content elements from the HTML returned by the origin. CDN converts the HTML returned by the origin as is, so the conversion result depends entirely on the HTML returned by the origin. |
|**Cache behavior** |CDN does not cache converted Markdown responses. |

## Limits

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">We do not recommend enabling this feature for CSR/SPA pages when Markdown responses are expected to contain the rendered page content.</div>


<div data-tips="true" data-tips-type="tip">For client\-side rendered pages, such as single\-page applications built with React or Vue, the HTML returned by the origin is only a page shell and does not include the page content. The actual content is dynamically generated on the client after the browser executes JavaScript. If this feature is enabled for such pages and a request includes <code>Accept: text/markdown</code>, conversion is still triggered, but the following issues may occur:</div>



* <div data-tips="true" data-tips-type="tip">The converted Markdown content may be almost empty because the origin HTML does not contain the page content.</div>


* <div data-tips="true" data-tips-type="tip">If a browser or debugging tool sends <code>Accept: text/markdown</code>, the returned Markdown response is displayed as Markdown instead of being rendered as the original HTML page.</div>



<div data-tips="true" data-tips-type="tip">Therefore, this feature is more suitable for pages where the page content is already present in the HTML returned by the origin, such as server\-side rendered (SSR) pages, pages generated through static site generation (SSG), and fully rendered HTML pages generated by server\-side templating technologies such as PHP and JSP.</div>


Other notes:


* The current version does not support custom conversion rules or content summary generation.

* The requested file must use the `.html` or `.htm` extension. Files with other extensions do not trigger HTML to Markdown.

* Conversion is triggered only when the request header explicitly includes `Accept: text/markdown`. Regular browser requests that do not include `Accept: text/markdown` are not affected and still receive the original HTML.

## Steps


1. Open the **Convert HTML to Markdown** configuration page. For the steps, see [Domain Management](https://docs.byteplus.com/en/docs/byteplus-cdn/domain-management_en).

2. Set **Status** to Enabled.

## Verify the configuration

After the configuration takes effect, you can send a request for an HTML resource with the `Accept: text/markdown` request header to verify whether the returned content is in Markdown format. Example command:

```Bash
curl -i -H "Accept: text/markdown" "https://<YOUR-DOMAIN>/example.html"
```


If the feature takes effect as expected, the `content-type` response header is `text/markdown; charset=utf-8`, and the response body is the converted Markdown content. For comparison, accessing the same URL without this request header should return the original HTML.
