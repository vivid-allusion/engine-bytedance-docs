<span id="how-to-view-cdn-bills"></span>
## **How to View CDN Bills**

You can view your CDN bills at the [BytePlus Cost Center](https://console.byteplus.com/financial/overview).

<span id="how-to-try-or-test-cdn-for-free"></span>
## How to Try or Test CDN for Free

After activating CDN, you can claim two free resource packages: a 1 TB traffic package and a package for 10,000,000 requests. The validity period is 1 year from the date of claim. You can use these two resource packages to try or test the CDN. You can check the remaining balance of your resource packages on the [CDN console's resource management page](https://console.byteplus.com/financial/resource-package).

<span id="how-to-change-the-billing-method-for-cdn"></span>
## **How to Change the Billing Method for CDN**

The default billing method when you activate CDN is traffic\-based billing, which is charged hourly and postpaid. If you need to use another billing method, please [submit a ticket](https://console.byteplus.com/workorder/create).

<span id="will-there-be-charges-for-the-traffic-generated-by-cdn-intermediary-nodes"></span>
## **Will There Be Charges for the Traffic Generated by CDN Intermediary Nodes?** 

CDN only charges for the traffic generated when edge nodes respond to user requests. Traffic generated by intermediary layer nodes is not charged.

<span id="why-is-the-traffic-shown-in-the-cdn-bill-inconsistent-with-the-traffic-recorded-in-the-logs"></span>
## Why is the traffic shown in the CDN bill inconsistent with the traffic recorded in the logs?

You can view BytePlus CDN usage and traffic data in several places, including your bill, Usage Query, monitoring pages, APIs, and logs. Each data source is designed for a different use case, so it may cover a different scope of data or use a different calculation method. As a result, when you compare traffic, bandwidth, or request counts for the same domain and time range, the values may not be identical.


|Data source |What to use it for |Related documentation |
|---|---|---|
|Billing usage data |Reconciling bills and exporting billing usage data. |[Usage Query](https://docs.byteplus.com/en/docs/byteplus-cdn/docs-usage-query), [Billing documentation](https://docs.byteplus.com/en/docs/byteplus-cdn/docs-pricing), and [How to view CDN bills](https://docs.byteplus.com/en/docs/byteplus-cdn/docs-billing#how-to-view-cdn-bills) |
|Real\-time monitoring data |Monitoring trends in traffic, bandwidth, request counts, and status codes. This data is refreshed more frequently than billing usage data or offline logs. |[Edge Monitoring](https://docs.byteplus.com/en/docs/byteplus-cdn/bWlzDn), [Origin Monitoring](https://docs.byteplus.com/en/docs/byteplus-cdn/xdlhZY), [Insights](https://docs.byteplus.com/en/docs/byteplus-cdn/6a4Gqa), and [DescribeEdgeData](https://docs.byteplus.com/en/docs/byteplus-cdn/DescribeEdgeData_En) |
|Offline log data |Request\-level analysis, such as aggregating requests by URL, status code, or client IP address. |[Log Download](https://docs.byteplus.com/en/docs/byteplus-cdn/docs-logs) and [Log Batch Delivery](https://docs.byteplus.com/en/docs/byteplus-cdn/log-batch-delivery_en-us) |


If you need to reconcile your bill, use the data in your bill, Usage Query, or Usage Export as the primary reference. Billing usage data is optimized for accuracy, so BytePlus CDN generates it through an offline processing pipeline. This improves accuracy, but the data may not be as fresh as monitoring data.

When you compare billing usage data with CDN request log data, the main difference is where the data is measured. CDN logs record application\-layer request data. Billing usage data measures traffic generated at the transport layer when cache nodes respond to user requests. For each user request, the traffic in billing usage data usually includes:


* Traffic generated by transmitting the requested file itself. This is the same traffic that CDN logs record.

* Traffic generated by TCP/IP headers and TCP retransmissions. This usually makes the traffic in billing usage data about 10% higher than the traffic recorded in logs.


TCP/IP headers are added by the OS kernel's network stack during transmission, so CDN logs cannot capture this data at the application layer. If you exclude headers generated during TCP retransmissions, the TCP three\-way handshake, and TCP connection teardown, header traffic accounts for about 4.52% of the traffic recorded in logs. In addition, packet loss caused by network instability or jitter can trigger TCP retransmissions, which usually add another 3% to 7% of the traffic recorded in logs. As a result, the traffic in billing usage data is usually about 10% higher than the traffic recorded in logs.

When you compare real\-time monitoring data with CDN request log data, you may still see minor differences. For example, this can happen when you use the `DescribeEdgeData` API to query request counts or traffic and compare the result with statistics calculated from request logs obtained through Log Download or Log Batch Delivery. Although both data sources collect data at Layer 7, or the application layer, real\-time monitoring data is optimized for freshness and visibility into trends, while CDN request log data is better suited for request\-level analysis. Because the two sources use different collection pipelines, measurement scopes, and calculation methods, you may see minor differences when comparing them over the same time range.

If the discrepancy is larger than expected or affects bill reconciliation, [submit a ticket](https://console.byteplus.com/workorder/create). Include the domain name, time range, API request parameters, log package name, and your calculation method so that we can help investigate.

<span id="how-many-mbps-are-in-1-gbps"></span>
## How many Mbps are in 1 Gbps?

The base for bandwidth is 1,000. That is: 1 Gbps = 1000 Mbps, 1 Mbps = 1000 Kbps, 1 Kbps = 1000 bps.

<span id="how-many-mb-are-in-1-gb"></span>
## How many MB are in 1 GB?

Traffic is measured using a base of 1,000. That is: 1 GB = 1000 MB, 1 MB = 1000 KB, 1 KB = 1000 B.

<span id="will-cdn-incur-charges-when-responding-with-4xx-status-codes"></span>
## Will CDN incur charges when responding with 4xx status codes?

Short answer: "Yes".

CDN allows you to configure access control rules to block malicious requests from accessing your domain. For example, CDN provides access control features such as Referer allowlists and blocklists, URL authentication, origin allowlists and blocklists, and User\-Agent (UA) allowlists and blocklists, remote authentication, and regional access control.

When a user request is received, if the request matches your configured access control rules, CDN rejects these requests and responds with 4xx status codes. Although there are no files in the response, the response includes response headers and the response body contains specific messages. CDN considers these responses as billable data transmission.

Therefore, the traffic and bandwidth usage generated by CDN responses with 4xx status codes will be billed. Additionally, the rejected requests will be counted in the number of requests received by CDN and will be billed accordingly. This portion of the charges will be included in your bill.

It is important to note that if your domain receives a large number of malicious requests, these rejected requests can still lead to significant charges if you are billed per request.

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">Requests that result in status codes other than 2xx or 4xx also generate billable traffic and bandwidth. These requests are also counted and billed accordingly.</div>
