This topic explains basic FileNAS concepts to help you get started with the product.


|**Concepts** |**Description** |
|---|---|
|Network File System (NFS) |NFS is the primary network file sharing protocol in Linux or Unix environments. It enables remote file systems to be mounted and accessed similarly to local storage. |
|File system |File systems deliver storage services via the standard NFS protocol, enabling remote file access across networks. After creating a mount target via the console, you can access the file systems on NFS clients using standard POSIX interfaces. |
|Portable Operating System Interface (POSIX) |POSIX is the collective name for a series of interrelated standards defined by the Institute of Electrical and Electronics Engineers (IEEE) for running software on various UNIX operating systems. Programs written for a POSIX\-compliant operating system can be compiled and executed on any other POSIX operating system. |
|Extreme FileNAS |A FileNAS specification that provides file storage services for applications requiring small capacity, low latency, and high performance. |
|Region |The physical location of the data center. You can configure each region according to your needs. |
|Availability zone |Availability zones refer to independent physical areas in the same region where power and network are interconnected. |
|Virtual private cloud (VPC) |A VPC is a virtual private network, and VPCs are isolated from each other. |
|Mount target |A mount target is the connection point for file systems in a network environment. To access and store data, you need to mount file systems on the computing node first. Mounting is the operation of connecting a compute node to a FileNAS file system. |
|Permission group |Permission groups enable you to manage file system permissions via various mount targets. This includes authorizing IP addresses and granting read and write access. |
