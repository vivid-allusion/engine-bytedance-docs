BytePlus VOD offers a video encryption solution that leverages proprietary encryption algorithms to safeguard the security of the entire transmission chain. In contrast to standard HLS encryption, BytePlus' private encryption provides enhanced security and reduced usage complexities. This article provides an overview of the benefits, architecture, compatibility, and operational procedures of BytePlus' private encryption solution.

<span id="937eb1ae"></span>
## Solution architecture

The private encryption solution consists of two main components: **Transcoding & encryption**, **Decryption & playback**.

**Transcoding & encryption:** 


1. The user uploads a video to the BytePlus VOD service.

2. The BytePlus VOD service stores the source file.

3. The user triggers a transcoding task to encrypt the video file.

4. The BytePlus VOD transcoding service retrieves a key from the key management service and uses it to encrypt the video file.

5. After transcoding is complete, the encrypted video file is stored.


**Decryption & playback:** 


1. **Business authorization**: When a mobile app or web page needs to access a video, it first makes a request to the user's own API or backend page. The user can implement their own access control mechanisms here, such as requiring user login for playback. It is recommended to use the HTTPS protocol. If playback is authorized, the business backend signs a playback token using a sub\-account's Access Key/Secret Key and returns it to the app/web client.

2. **Acquiring playback address**: The client\-side passes the video ID and the playback token to the BytePlus VOD Player SDK. The SDK is responsible for:

   * Fetching the corresponding multi\-format, multi\-bitrate playback addresses from the BytePlus VOD service.

   * Obtaining the corresponding decryption key. This key is then encrypted again to enhance security.

3. **Decrypt & playback**:

   * The Player SDK fetches the encrypted video file using the playback address.

   * It then decrypts the video using the key and begins playback.


<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">Key concepts:</div>



* <div data-tips="true" data-tips-type="tip"><strong>DEK (Data Encryption Key):</strong> A key used to encrypt audio and video data.</div>


* <div data-tips="true" data-tips-type="tip"><strong>KEK (Key Encryption Key):</strong> A key used to encrypt the Data Encryption Key. A public\-private key pair is generated by the client\-side Player SDK.</div>


   * <div data-tips="true" data-tips-type="tip">The <strong>public key</strong> is further encrypted (this encrypted version is the <strong>DrmKEK</strong>) and then sent to the server. The server uses it to encrypt the DEK.</div>


   * <div data-tips="true" data-tips-type="tip">The <strong>private key</strong> is kept securely on the client, is not sent to the server, and is used to decrypt the DEK.</div>

## Benefits

The private encryption solution offers the following benefits:


* Each video file is assigned a unique key, effectively preventing security risks that may arise from key leakage. Additionally, the keys undergo an additional encryption process to enhance security.

* BytePlus provides Player SDKs for platforms like Android, iOS, and Web, enabling automatic decryption and playback of encrypted content. Moreover, it supports device\-level `UnionInfo` verification, reducing the risk of unauthorized playback on compromised devices.

* The solution supports secure downloads, encrypting the downloaded videos. This ensures that even without an internet connection, videos remain protected against unauthorized use.

### Decryption & playback

Videos encrypted by BytePlus' private encryption can only be decrypted and played using the BytePlus Player SDKs.

<span id="74a9fb4f"></span>
#### Native

<span id="db10e323"></span>
##### Overall process

The overall decryption and playback process for Vid mode on native clients is as follows:

<span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/06bedd1d00d84123956aba3babaec613~tplv-goo7wpa0wc-image.image) </span>


1. **Client\-side key generation**: The process begins on the client device. The BytePlus Player SDK generates a unique device identifier (`UnionInfo`) and a public key (`DrmKek`). This pair of credentials serves as the foundation for the secure playback session.

2. **Token authorization**: The client sends the newly generated `UnionInfo` and `DrmKek` to your application server. Your server, acting as a trusted authority, uses the BytePlus VOD Server SDK to generate a short\-lived, signed playback token. This token essentially grants the specific device permission to play the video.

3. **Requesting playback info**: The Player SDK then sends a request to the BytePlus VOD service, presenting the Video ID (Vid) and the temporary token it received from your server.

4. **Secure key delivery**: The BytePlus VOD service validates the token. Upon successful validation, it uses the public key (`DrmKek`) provided by the client to encrypt the actual video decryption key. This critical step ensures that only the original device holding the corresponding private key can decrypt the video key. The VOD service then returns the encrypted video key and the video's streaming address (PlayUrl) to the client.

5. **Fetching video content**: The Player SDK requests the encrypted video content from the CDN using the provided `PlayUrl`.

6. **Decryption and playback**: Internally, the Player SDK uses its private key to decrypt the video key it received from the VOD service. With the actual key now available, the SDK can decrypt the video stream from the CDN in real\-time as it plays.


<span id="a6a45b43"></span>
##### Implementation steps

This section provides a step\-by\-step guide for developers to implement the playback of private encrypted videos.


1. **Generate** **`UnionInfo`** ** and ** **`DrmKek`**

   Call the Player SDK's `getEngineUniqueId` and `getEngineUniqueKek` methods to generate the `UnionInfo` (unique device identifier) and `DrmKek` (the public key used for encryption).

   * **Android Player SDK:** 

      ```Java
      String unionInfo = TTVideoEngine.getEngineUniqueId(context);
      String kek = TTVideoEngine.getEngineUniqueKek(context);
      ```
      

   * **iOS Player SDK:** 

      ```objectivec
      NSString *kek = [TTVideoEngine getEngineUniqueKek];
      NSString* unionInfo = [TTVideoEngine getEngineUniqueId];
      ```
      

2. **Request a temporary playback token**

   Send a request to your application server, carrying the `UnionInfo` and `DrmKek` generated in the previous step, to obtain a temporary playback token. Your application server uses the BytePlus VOD server SDK to locally sign the token and then sends it back to the client.

   When generating the token on the server, you must set the following parameters:

   * `FileType`: Set to `private_evideo`.

   * `UnionInfo`: Set to the `UnionInfo` generated by the Player SDK.

   * `DrmKEK`: Set to the `DrmKek` generated by the Player SDK.

      For specific code examples, please refer to the following documents:

   * [Java SDK - Generating temporary playback token](https://docs.byteplus.com/en/docs/byteplus-vod/docs-java-sdk#generating-temporary-playback-token)

   * [Python SDK - Generating temporary playback token](https://docs.byteplus.com/en/docs/byteplus-vod/docs-python-sdk#generating-temporary-playback-token)

   * [PHP SDK - Generating temporary playback token](https://docs.byteplus.com/en/docs/byteplus-vod/docs-php-sdk#generating-temporary-playback-token)

   * [Go SDK - Generating temporary playback token](https://docs.byteplus.com/en/docs/byteplus-vod/docs-go-sdk#generating-temporary-playback-token)

   * [Node.js SDK - Generating temporary playback token](https://docs.byteplus.com/en/docs/byteplus-vod/docs-nodejs-sdk#generating-temporary-playback-token)

3. **Set the playback source**

   The Player SDK only supports playing private encrypted videos using Vid mode. Refer to the documentation below to pass the `Vid` and the temporary playback token to set the playback source:

   * Android: [Set playback source](https://docs.byteplus.com/en/docs/byteplus-vod/docs-getting-started-with-the-android-player-sdk#step-6-set-the-playback-source)

   * iOS: [Set playback source](https://docs.byteplus.com/en/docs/byteplus-vod/docs-getting-started-with-the-ios-player-sdk#step-8-set-the-playback-source)


Once these steps are completed, the Player SDK will automatically handle the subsequent processes of fetching playback information, requesting video content, and performing decryption for playback.

## Setting an expiration timestamp

This section explains how to set an expiration timestamp for private encryption.

<span id="7529b4d6"></span>
### Step 1: Generating a temporary playback token

Issue a temporary playback token using the BytePlus Server SDKs. The table below lists the required parameters for playing a private encrypted video. For a comprehensive list of all configurable parameters, refer to [GetPlayInfo](https://docs.byteplus.com/docs/byteplus-vod/reference-getplayinfo).


|Parameter |Data Type |Sample Value |Description |
|---|---|---|---|
|Vid |String |`v029c1g10003civ2i5mqib*******` |The video ID. After you upload audio and video files to the BytePlus VOD service, you can use the following methods to get the `Vid`:<br><br><br>* Get the `Vid` through the [GetMediaList](https://docs.byteplus.com/en/docs/byteplus-vod/reference-getmedialist) API.<br><br>* If you have set a callback event for media upload completion, the `Vid` will be returned in [FileUploadComplete](https://docs.byteplus.com/en/docs/byteplus-vod/docs-fileuploadcomplete). |
|FileType |String |`video` |The file type. Supported values:<br><br><br>* `evideo`: Encrypted video stream.<br><br>* `eaudio`: Encrypted audio stream.<br><br>* `video`: (Default) Unencrypted video stream.<br><br>* `audio`: Unencrypted audio stream. |
|UnionInfo |String |`87878***` |A unique identifier extracted from the client (browser or device), used for playing private encrypted video and audio. |
|DrmExpireTimestamp |String |`1695037103` |The private encryption expiration timestamp in seconds. Once set, the issued `PlayAuthToken` will include an expiration timestamp for private encryption. |


Below is an example code snippet using the Java SDK. For examples in other languages, please refer to the documentation below.


* [Java SDK - Generating temporary playback token](https://docs.byteplus.com/en/docs/byteplus-vod/docs-java-sdk#generating-temporary-playback-token)

* [Python SDK - Generating temporary playback token](https://docs.byteplus.com/en/docs/byteplus-vod/docs-python-sdk#generating-temporary-playback-token)

* [PHP SDK - Generating temporary playback token](https://docs.byteplus.com/en/docs/byteplus-vod/docs-php-sdk#generating-temporary-playback-token)

* [Go SDK - Generating temporary playback token](https://docs.byteplus.com/en/docs/byteplus-vod/docs-go-sdk#generating-temporary-playback-token)

* [Node.js SDK - Generating temporary playback token](https://docs.byteplus.com/en/docs/byteplus-vod/docs-nodejs-sdk#generating-temporary-playback-token)


```Java
package com.byteplus.example.vod.play;

import com.byteplus.service.vod.IVodService;
import com.byteplus.service.vod.impl.VodServiceImpl;
import com.byteplus.service.vod.model.request.VodGetPlayInfoRequest;

public class VodGetPlayAuthTokenDemo {

    public static void main(String[] args) throws Exception {
        IVodService vodService = VodServiceImpl.getInstance();

        String vid = "v11080g50000cg4pmekmabdhks5c******";

        // call the method below if you do not set ak and sk in ~/.byteplus/config
        vodService.setAccessKey("your AK");
        vodService.setSecretKey("your SK");

        try {
            VodGetPlayInfoRequest.Builder reqBuilder = VodGetPlayInfoRequest.newBuilder();
            reqBuilder.setVid(vid);
            reqBuilder.setFileType('evideo');
            reqBuilder.setDrmExpireTimestamp("1834342505");
            reqBuilder.setUnionInfo("Y29tLmJ5dGVkYW5jZS5ieXRldm9kZGVtb18xNzM0MzQyMTk1ODM2X***********************************");

            String resp = vodService.getPlayAuthToken(reqBuilder.build(), 36000L);
            System.out.println(resp);
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```
