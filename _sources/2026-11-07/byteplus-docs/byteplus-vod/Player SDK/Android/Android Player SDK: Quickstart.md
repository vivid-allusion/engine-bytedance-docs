To quickly add video playback to your Android application, this guide provides step\-by\-step instructions for integrating the Android Player SDK. You will learn the complete process, from initializing the SDK and setting up a view to playing videos from various sources and properly releasing resources.

<span id="25576f3e"></span>
## Prerequisites

Ensure that you have integrated the Player SDK into your Android project.

<span id="d7ffd8a7"></span>
## Procedure

<span id="8592ffc2"></span>
### Step 1: Enable logging for debugging

Before initializing the Player SDK, it is recommended to enable logging to facilitate debugging and troubleshooting. Disable full Logcat output in production to minimize performance overhead. Remote log retrieval works independently of these debugging APIs. For configuration and upgrade guidance in SDK `1.52.100.5` and later, see [Getting SDK logs](https://docs.byteplus.com/docs/byteplus-vod/docs-getting-sdk-logs-android). The following examples demonstrate how to enable logs:


<Tabs>
<Tab zoneid="cJQ6pTMY8Y" title="For version 1.41.200.2 and later">
<TabTitle>For version 1.41.200.2 and later</TabTitle>

```Java
// () Enable logging for all SDK modules
VodSDK.openAllVodLog();
```



</Tab>
<Tab zoneid="OcvjsEZE3Q" title="For versions before 1.41.200.2">
<TabTitle>For versions before 1.41.200.2</TabTitle>

```Java
// Enable logging for individual SDK modules
// Enable logging for the ttsdk module
TTVideoLog.turnOn(TTVideoLog.LOG_DEBUG, 1);
// Enable logging for the CacheModule module
CmLog.turnLogLevel(CmLog.LogLevel.D, true);
// Enable logging for the engine module
TTVideoEngineLog.turnOn(TTVideoEngineLog.LOG_DEBUG, 1);
// Enable logging for the data loading module
AVMDLLog.turnOn(AVMDLLog.LOG_DEBUG, 1);
// Enable logging for the license module
LicenseManager.turnOnLogcat(true);
```



</Tab>
</Tabs>


After enabling logs, follow these steps to output specific log levels to Logcat:


1.  **(Optional) Set the log level**: By default, the SDK outputs four levels of logs: `LOG_INFO`, `LOG_WARN`, `LOG_ERROR`, and `LOG_KILL`. During development and debugging, it is recommended to additionally enable the `LOG_DEBUG` level to obtain more detailed information.

   ```Java
   TTVideoEngineLog.setLogNotifyLevel(TTVideoEngineLog.LOG_DEBUG, 1);
   ```
   

2.  **(Required) Set the log output listener**: Use the `setListener` method to specify the output destination for the logs. The following example prints logs generated by the Engine to the Android Logcat.

   ```Java
   // Output Engine logs to Logcat
   TTVideoEngineLog.setListener(new TTVideoEngineLogListener() {
       @Override
       public void consoleLog(String log) {
           Log.d("TTVideoEngineLog", log); // Use Log.d to print to Logcat
       }
   });
   ```
   


<span id="3334c95d"></span>
### Step 2: Initialize the SDK

Initialize the SDK in `Application#onCreate`. See the following sample code:

```Java
File videoCacheDir = new File(context.getCacheDir(), "video_cache");
if (!videoCacheDir.exists()) videoCacheDir.mkdirs();
VodConfig.Builder vodBuilder = new VodConfig.Builder(context)
        .setCacheDirPath(videoCacheDir.getAbsolutePath())
        .setMaxCacheSize(300 * 1024 * 1024);
        
Env.start(new Config.Builder()
        .setApplicationContext(context)
        .setAppID("Your app ID")
        .setAppName("Your app name")
        .setAppVersion(BuildConfig.VERSION_NAME)
        .setAppChannel("channel name")
        .setLicenseUri("assets:///license/vod.lic")
        .setVodConfig(vodBuilder.build())
        .setBizType(BIZ_TYPE_VOD)
        .build());
```


When initializing the SDK, set the following parameters:


|**Name** |**Type** |**Required** |**Default value** |**Description** |
|---|---|---|---|---|
|AppID |String |Yes |None |The app ID. You can get the app ID from the [app management](https://console.byteplus.com/vodpaas/sdk/) page in the BytePlus VOD console. |
|AppName |String |Yes |None |The app name. You can get the app name from the [app management](https://console.byteplus.com/vodpaas/sdk/) page in the BytePlus VOD console. |
|AppVersion |String |Yes |None |The version number of the app. You can set this parameter as `BuildConfig.VERSION_NAME`. A valid version number should contain two or more delimiters, such as `"1.3.2"`. |
|AppChannel |String |Yes |None |The name of the channel where your app is distributed, such as `Google Play`. |
|LicenseUri |String |Yes |None |The path to your license file. Place the file in the `app/assets` folder and set this parameter to its path, for example, `assets/license/vod.lic`.<br><br>For more information on the license, see [License Guide](https://docs.byteplus.com/docs/byteplus-vod/docs-license-guide-android). |
|CacheDirPath |String |No |`/data/user/0/<package_name>/cache/video_cache` |The path for caching videos. |
|MaxCacheSize |Int |No |300 \* 1024 \* 1024 (300 MB) |The maximum size (bytes) of the folder for caching videos. |

### Step 3: Customize the device ID

After initializing the SDK, you can customize the device ID to view the playback data of a single device in the BytePlus VOD console. For more information, refer to [Endpoint tracker](https://docs.byteplus.com/en/docs/byteplus-vod/docs-end-point-tracker). Sample code:

```Java
// Initialize custom ID
private void initVodSDK(Context context, String userUniqueId) {
    // 1. Initialize the SDK
    Env.start(new Config.Builder()
        // ...
        .build());
    // 2. Get AppLog instance and set userUniqueId
    IAppLogInstance applog = AppLogWrapper.getAppLogInstance();
    if (applog != null && !TextUtils.isEmpty(userUniqueId)) {
        applog.setUserUniqueID(userUniqueId); 
    }
}

// Call this when your user logs out
private void onUserLogout() {
    IAppLogInstance applog = AppLogWrapper.getAppLogInstance();
    if (applog != null) {
        applog.setUserUniqueID(null);
    }
}

// Call this when your user logs in
private void onUserLogin(String userUniqueId) {
    IAppLogInstance applog = AppLogWrapper.getAppLogInstance();
    if (applog != null) {
        applog.setUserUniqueID(userUniqueId);
    }
}
```

### Step 4: Create a player instance

Create a player instance with the `TTVideoEngine` class, as follows:

<div data-tips="true" data-tips-type="warning" data-tips-is-title="true">Warning</div>


<div data-tips="true" data-tips-type="warning">For better playback performance, it is recommended to create a new engine instance every time you play a video, rather than reusing the same engine instance.</div>


```Java
// When creating the instance, pass in the app context
TTVideoEngine ttVideoEngine = new TTVideoEngine(context, TTVideoEngine.PLAYER_TYPE_OWN);
```

### Step 5: Set up a view for displaying the video

To display the video, bind the player with either a texture or surface view.


<Tabs>
<Tab zoneid="SisQPS6qjA" title="Bind the player with a texture view">
<TabTitle>Bind the player with a texture view</TabTitle>

Follow these steps to bind the player with a texture view:


1. Declare a texture view in XML, as follows:

   ```XML
   <TextureView
       android:id="@+id/textureView"
       android:layout_width="match_parent"
       android:layout_height="match_parent"
       android:background="@null" />
   ```
   

   If the Android API level that your app targets is 24 or higher, when declaring the texture view, you must either not set the background or set it to null. Otherwise, the app will crash.

2. Get the `SurfaceTexture` instance of the texture view that you declare and pass it to `TTVideoEngine`. The `SurfaceTexture` can then be used to render the video from `TTVideoEngine`. See the following sample code:

   ```Java
   TextureView textureView = findViewById(R.id.textureView);
   // Set the listener for the TextureView's SurfaceTexture
   textureView.setSurfaceTextureListener(new TextureView.SurfaceTextureListener() {
       @Override
       // Called when the TextureView's SurfaceTexture is ready for use
       public void onSurfaceTextureAvailable(SurfaceTexture surfaceTexture, int width, int height) {
           // Pass the TextureView's SurfaceTexture to the player
           ttVideoEngine.setSurface(new Surface(surfaceTexture));
       }
       @Override
       public void onSurfaceTextureSizeChanged(SurfaceTexture surfaceTexture, int width, int height) { 
       }
       @Override
       public boolean onSurfaceTextureDestroyed(SurfaceTexture surfaceTexture) {
           return true;
       }
       @Override
       public void onSurfaceTextureUpdated(SurfaceTexture surfaceTexture) {
       }
   });
   ```
   


</Tab>
<Tab zoneid="Nn0TGSuFHx" title="Bind the player with a surface view">
<TabTitle>Bind the player with a surface view</TabTitle>

Follow these steps to bind the player with a surface view:


1. Declare a surface view in XML, as follows:

   ```XML
   <SurfaceView
       android:id="@+id/surfaceView"
       android:layout_width="match_parent"
       android:layout_height="match_parent" />
   ```
   

2. The `SurfaceView` provides a dedicated drawing surface. You can get the underlying surface via the `SurfaceHolder` interface, which can be retrieved by calling `getHolder()`. Pass the `SurfaceHolder` interface to `TTVideoEngine`. The player then uses the `SurfaceView` to display the video from `TTVideoEngine`. See the following sample code:

   ```Java
   SurfaceView surfaceView = findViewById(R.id.surfaceView);
   // Pass the SurfaceHolder to TTVideoEngine
   ttVideoEngine.setSurfaceHolder(surfaceView.getHolder());
   ```
   

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">Note   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">The <code>ttVideoEngine.setSurface</code> and <code>ttVideoEngine.setSurfaceHolder</code> methods must be called before <code>ttVideoEngine.play</code>.   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">Starting from the Android API level 24, SurfaceView supports synchronizing the rendering position in the window with other views in the view tree. If your app targets the Android API level 24 or lower, you may encounter disordered view hierarchies and out\-of\-sync animations. For details, see <a href="https://developer.android.com/reference/android/view/SurfaceView.html">SurfaceView</a> in the Android developer reference.   </div>
   


</Tab>
</Tabs>


<div data-tips="true" data-tips-type="warning" data-tips-is-title="true">Warning</div>



* <div data-tips="true" data-tips-type="warning">You must first call the <code>setSurface</code> or <code>setSurfaceHolder</code> method of <code>TTVideoEngine</code>, and then call the <code>play</code> method.</div>


* <div data-tips="true" data-tips-type="warning">The parent layout of <code>TextureView</code> or <code>SurfaceView</code> must be a <code>FrameLayout</code>.</div>

### Step 6: Set the playback source

The SDK supports playing both local and online videos. This section introduces how to play videos from different sources.

<span id="4056ca96"></span>
#### Play a video with the video ID

If you've uploaded your videos to the BytePlus VOD service, you can simply set the player's `vid` parameter to the vid generated by the service, and the `playAuthToken` parameter to the temporary playback token. The vid and temporary token are provided by the application server, so the client doesn't need to worry about them. For further information, see [Playing videos with temporary playback tokens](https://docs.byteplus.com/docs/byteplus-vod/docs-playing-videos-with-temporary-playback-tokens).

Sample code:

```Java
// Enable caching the video model
ttVideoEngine.setIntOption(PLAYER_OPTION_USE_VIDEOMODEL_CACHE, 1);

// Get the video ID from your app server
final String vid = "your video ID";
// Get the playback token from your app server
final String playAuthToken = "your playback token";

final String encodeType = TTVideoEngine.CODEC_TYPE_H264;
// final String encodeType = TTVideoEngine.CODEC_TYPE_h265;

// 1. Assemble the playback source
StrategySource vidSource = new VidPlayAuthTokenSource.Builder()
        .setVid(vid)
        .setPlayAuthToken(playAuthToken)
        // Set the codec type. The default value is TTVideoEngine.CODEC_TYPE_H264
        .setEncodeType(encodeType)
        // Set the resolution when the video playback initiates. The default resolution is 360P
        // Here we set the resolution to 480p
        .setResolution(Resolution.High)
        .build();
// 2. Set the playback source
ttVideoEngine.setStrategySource(vidSource);
// 3. Play the video
ttVideoEngine.play()
```


When assembling the video source, set the following parameters:


|**Parameter** |**Type** |**Required** |**Default Value** |**Description** |
|---|---|---|---|---|
|Vid |String |Required |None |The video ID. |
|PlayAuthToken |String |Required |None |The playback token. |
|EncodeType |String |Not required |CODEC_TYPE_H264 |The codec type:<br><br><br>* `CODEC_TYPE_H264`: (Default) H.264<br><br>* `CODEC_TYPE_H265`: H.265 |
|Resolution |Resolution |Not required |Standard |The initial video resolution. See [Resolutions](https://docs.byteplus.com/docs/byteplus-vod/docs-implementing-basic-features-android#b30c3e47). |


<span id="23e78654"></span>
#### Play a video with the HTTP URL

To play videos in DirectUrl mode, set the `url` parameter to the video's URL. This address can be from a third\-party VOD service or one generated by the BytePlus VOD service. When assembling the playback source, the following parameters are also required:


* `vid`: This is the unique identifier of the video. The `vid` can be the unique identifier in your video management system or a custom ID generated at the app level. This ID is used for features like log reporting, preloading, and prerendering in the SDK.

* `cacheKey`: It is recommended to use the MD5 of the URL as the cache key. The cache key should also be unique. It should not contain any special characters and can be used as a file name.


Sample code:

```Java
// The unique identifier of the video
final String vid = "video id";
// The URL of the video
final String url = "http://www.example.com/h264.mp4";
final String cacheKey = TTVideoEngine.computeMD5(url);

// 1. Assemble the playback source
StrategySource directUrlSource = new DirectUrlSource.Builder()
        .setVid(vid)
        .addItem(new DirectUrlSource.UrlItem.Builder()
                .setUrl(url)
                .setCacheKey(cacheKey)
                .build())
        .build();
       
// 2. Set the video source
ttVideoEngine.setStrategySource(directUrlSource);
// 3. Play the video
ttVideoEngine.play()
```


<span id="53a5c9b2"></span>
#### Play a local video

If you play a local video, set the `videoFile` parameter to the local file path. See the following sample code:

```Java
// Replace "/sdcard/Download/video.MP4" with the video address
File videoFile = new File("/sdcard/Download/video.MP4");
ttVideoEngine.setLocalURL(videoFile.getAbsolutePath());
ttVideoEngine.play()
```

### Step 7: Release the player instance

When the video ends or the user leaves the playback page, stop playback and release the player instance by calling `releaseAsync`. This call releases the hardware decoder, memory, and network resources to save device power. See the following sample code:

```Java
ttVideoEngine.releaseAsync();
```
