This document guides you on using the Web Player SDK to play HLS format videos, including regular HLS videos and HLS standard encrypted videos.

<span id="aca6c6a3"></span>
## Prerequisites


* **Configure Cross\-Origin Resource Sharing (CORS) for your domain**: When playing HLS videos, you must configure the correct[ CORS ](https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS)related HTTP response headers for the playback domain. This allows the web page to retrieve M3U8 and TS files. For specific steps, please refer to [Configure HTTP Response Headers](https://docs.byteplus.com/en/docs/byteplus-vod/docs-http-response-headers). The required headers are as follows:

   
   |**Response Header** |**Value** |
   |---|---|
   |Access\-Control\-Allow\-Origin |* or the origin of your web application |
   |Access\-Control\-Allow\-Methods |* or include GET, HEAD, OPTIONS |
   |Access\-Control\-Expose\-Headers |* or include Range |
   

* **Use HTTPS Protocol**: You must use playback links with the HTTPS protocol for successful playback on an HTTPS page. The playback domain must have a valid SSL certificate. In Vid mode, set `Ssl` as 1 when the `playAuthToken` is generated on the server. Take the [Go SDK example for generating playAuthToken](https://docs.byteplus.com/en/docs/byteplus-vod/docs-go-sdk#generating-temporary-playback-token) as an example:


```Go
query := &request.VodGetPlayInfoRequest{
                   Vid:             vid,
                   Format:          "hls",
                   FileType:        "video",
                   Ssl:             "1",          
   }
```


<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">If you lack an SSL certificate during early testing, add <code>reqParams: { Ssl: 0 }</code> to the <code>getVideoByToken</code> configuration within the player's instantiation <code>options</code> parameter.</div>

## Playing regular HLS videos

You can play regular, unencrypted HLS videos using **DirectUrl mode** or **Vid mode**.

<span id="bc9c020a"></span>
### DirectUrl mode

Pass the HLS video's M3U8 file address directly and set `streamType` to `hls`.

```JavaScript
const playerSdk = new VePlayer({
  id: 'player-container',
  width: 600,
  height: 360,
  streamType: 'hls',
  url: 'https://your-domain/your-video.m3u8',
  codec: 'h264',
  vodLogOpts: {
    vtype: 'HLS',
    tag: 'Regular video',
    line_app_id: 123456, // (Required) App ID, number,. You can obtain from the VOD Console > SDK Management > Applications.
    line_user_id: 123456, // (Required) User ID, string or number. It corresponds to the Device ID in the Endpoint Tracker feature.
  }
});
```


<span id="f1b55e13"></span>
### Vid mode

You can play videos using a Vid and `playAuthToken`. When generating the `playAuthToken` on your server, you must specify the `Format`, `FileType`, and `Codec` (for example, `Format: 'hls'`). This ensures the video for that Vid has been transcoded to the appropriate format and codec. Otherwise, the server will deliver a video with a different format and protocol based on its strategy. For H.265 encoded HLS video, set `Format` as `hls` and `Codec` as `H265`. See [Request Parameters for GetPlayInfo](https://docs.byteplus.com/en/docs/byteplus-vod/reference-getplayinfo#request-parameters) for supported values and defaults. Take the Go server\-side Token generation as an example:

```Go
query := &request.VodGetPlayInfoRequest{
                Vid:             vid,
                Format:          "hls",
                Codec:            "H265",
                FileType:        "video",
                Ssl:             "1", // It is recommended to enable on HTTPS pages.         
}
```


Client\-side player initialization:

```JavaScript
const playerSdk = new VePlayer({
  id: 'player-container',
  width: 600,
  height: 360,
  getVideoByToken: {
    playAuthToken: 'your_play_auth_token'
  },
  vodLogOpts: {
    vtype: 'HLS',
    tag: 'Regular video', 
    line_app_id: 123456, // (Required) App ID, number.
    line_user_id: 123456, // (Required) User ID, string or number.
  }
});
```

## Playing HLS standard encrypted videos

HLS standard encryption (AES\-128) is a common content protection scheme. The core requirement is that the player must obtain the correct decryption key.

<span id="e90f73d6"></span>
### Scenario 1: Videos generated by VOD

The Player SDK integrates with VOD's media processing service for convenient and secure playback. Before you begin, complete the following steps:


1. **Set up the decryption service**: Deploy a service to return the correct decryption key upon the player's request.

2. **Perform encrypted transcoding**: Create a media processing template in the VOD Console, enable **HLS standard encryption**, enter your decryption service address, and transcode the video.


For detailed steps, please refer to the [HLS standard encryption](https://docs.byteplus.com/en/docs/byteplus-vod/docs-standard-encryption). After the preparations, you can play the encrypted video via **Vid mode (recommended)**  or **DirectUrl mode**.

<span id="7ad991a2"></span>
#### Vid mode

This method uses Vid and `playAuthToken` for playback. It offers a more secure process and supports **custom authorization parameters**.


* **Server\-side PlayAuthToken generation**: Your application server needs to call the `GetPlayInfo` to generate `playAuthToken`. When you call it, set the `FileType` parameter to `standard_evideo` (encrypted video) or `standard_eaudio` (encrypted audio).

   ```Go
   // Go SDK example
   query := &request.VodGetPlayInfoRequest{
                   Vid:             vid,
                   Format:          "hls",
                   Codec:            "H265",
                   FileType:  "standard_evideo", // Key parameter: Specifies the encrypted file type                
                   Ssl:             "1", // It is recommended to enable on HTTPS pages.     
   }
   ```
   

* **Client\-side Player initialization**: In the `getVideoByToken` configuration, you need to pass the `playAuthToken`. If you have configured [HLS encryption rewrite](https://docs.byteplus.com/en/docs/byteplus-vod/docs-standard-encryption#step-3-configuring-hls-encryption-rewrite-recommended), use the `urlQueryParams` parameter to add custom authorization parameters to the M3U8 file request URL.

   ```JavaScript
   const playerSdk = new VePlayer({
     id: 'player-container',
     width: 600,
     height: 360,
     getVideoByToken: {
       urlQueryParams: {
         hlsSign: 'your_app_auth_token'
       },
       playAuthToken: 'your_play_auth_token_for_encrypted_video',
     },
     // ... Other configurations
   });
   ```
   


The Player SDK automatically handles the subsequent steps of obtaining playback information, requesting the key, and decrypting the stream for playback.

<span id="cc4faf66"></span>
#### DirectUrl mode

You need to manually obtain the complete playback address on the server and pass it to the client for playback.


* **Server\-side playback address retrieval**: Your application server calls [GetPlayInfo](https://docs.byteplus.com/en/docs/byteplus-vod/reference-getplayinfo) to retrieve the M3U8 playback address for the encrypted video. The `FileType` parameter must be set to `standard_evideo` or `standard_eaudio`.

* **Client\-side player initialization**: The player's configuration is the same as [DirectUrl mode](https://docs.byteplus.com/docs/byteplus-vod/playing_hls_standard_encrypted_videos_web_new#bc9c020a). You can simply pass the retrieved encrypted video URL.


<span id="3bc31565"></span>
### Scenario 2: Videos from third\-party sources

The Web Player SDK can play third\-party HLS standard encrypted videos, provided the videos meet the HLS specification. You must use **DirectUrl mode** and pass the third\-party's M3U8 playback address directly to the player. The player's configuration remains identical to playing a regular HLS video. It directly requests the key URI specified in the M3U8 file's `#EXT-X-KEY` tag. You need to ensure the key URL is publicly accessible and correctly configure CORS policies for it.

<span id="05c095b1"></span>
## Playback strategy description


* On PC, VePlayer defaults to using the [MSE](https://developer.mozilla.org/zh-CN/docs/Web/API/MediaSource) plugin for HLS video playback. It provides more flexible playback strategies such as seamless resolution switching and advanced buffer control.

* On H5 devices, VePlayer defaults to the native Video element. This approach prioritizes device performance and browser compatibility.
