The AI MediaKit Video Smoothness Enhancement tool is designed to resolve common motion discontinuity issues in videos, especially AI\-generated videos. Based on the video frames and motion information, the tool automatically identifies and repairs two core types of issues: abrupt changes in motion rhythm (periodic stutter) and multiple consecutive frames with identical images (duplicate frames). Using optical flow, motion vectors, and other algorithms, the tool intelligently generates intermediate frames to compensate for missing motion or removes redundant duplicate frames. This significantly improves video smoothness and restores continuous, natural motion without changing the video resolution.

The tool is particularly suitable for repairing videos generated by Seedance models that exhibit occasional stutter. It is also widely applicable to low\-frame\-rate or transcoded videos, screen recordings, gameplay footage, live\-stream replays, and other scenarios in which stutter or duplicate frames commonly occur.

<span id="use-cases"></span>
## Use cases

Video Smoothness Enhancement is suitable for any video with discontinuous motion. Typical use cases include:


* **Repair AI\-generated videos**: Seedance and other video generation models may occasionally produce abrupt changes in motion rhythm or duplicate frames, causing the video to pause briefly or display the same image across multiple consecutive frames. After obtaining the generated video, you can use this tool to automatically compensate for missing motion and remove redundant duplicate frames, thereby restoring natural and smooth motion.

* **Optimize low\-frame\-rate or transcoded videos**: For low\-frame\-rate source videos or videos that may have lost frames after multiple transcoding operations, intelligent frame insertion restores continuous motion.

* **Repair screen recordings, gameplay footage, and live\-stream replays**: The tool automatically detects and repairs periodic stutter caused by instability during capture or encoding in screen recordings, gameplay footage, or live\-stream replays.


<span id="quickstart-detect-and-repair-video-stutter"></span>
## Quickstart: Detect and repair video stutter

This section uses the default stutter detection and repair of a video as an example to demonstrate the complete Video Smoothness Enhancement workflow.

<span id="prerequisites"></span>
### Prerequisites


* **Obtain access credentials**: Before you begin, go to the [API key](https://console.byteplus.com/vodpaas/region:vodpaas+ap-southeast-1/ai-mediakit/settings?tab=apiKey) page in the AI MediaKit console to create and obtain a **MediaKit API Key**.

* **Prepare a video file**: Prepare the video file for processing, upload it to a publicly accessible server, and obtain an HTTP or HTTPS URL that the API can access.


<span id="procedure"></span>
### Procedure

Video Smoothness Enhancement runs as an asynchronous task. The standard workflow is as follows:


1. After you successfully call `POST /api/v1/tools/enhance-video-smoothness` to submit a task, you receive a task ID.

2. Poll `GET /api/v1/tasks/{task_id}` until the task status `status` changes to `completed`. Alternatively, use [Event notification](https://docs.byteplus.com/docs/byteplus-vod/ai-mediakit-event-notification) to automatically receive task status updates.

3. After the task is complete, parse the `result` field in the response. The download URL of the repaired video is returned in `video_url`. If the video does not require repair or no repair option is enabled, `video_url` is not returned.


<span id="step-1-submit-a-video-smoothness-enhancement-task"></span>
#### Step 1: Submit a Video Smoothness Enhancement task

Call the [Create a video smoothness enhancement task](https://docs.byteplus.com/docs/byteplus-vod/ai-mediakit-create-a-video-smoothness-enhancement-task). You can directly use the following cURL command.

```Bash
curl -X POST 'https://mediakit.ap-southeast-1.bytepluses.com/api/v1/tools/enhance-video-smoothness' \
-H 'Authorization: Bearer {Your_API_Key}' \
-H 'Content-Type: application/json' \
-d '{
  "video_url": "https://example.com/your_video.mp4"
}'
```


<div data-tips="true" data-tips-type="default" data-tips-is-title="true">INFO</div>



* <div data-tips="true" data-tips-type="default">Replace <code>{Your_API_Key}</code> with your valid API key.</div>


* <div data-tips="true" data-tips-type="default">Replace <code>video_url</code> with the URL of your video.</div>


* <div data-tips="true" data-tips-type="default">By default, the tool enables both periodic stutter detection and duplicate frame detection, automatically repairs the detected issues, and directly returns the repaired video. To disable repair or use advanced features, provide the <code>periodic_stutter_detect</code> or <code>duplicate_frame_detect</code> configuration object. For details, see <a href="https://docs.byteplus.com/docs/byteplus-vod/ai-mediakit-video-smoothness-enhancement#advanced-usage">Advanced usage</a>.</div>



After the request succeeds, you receive the following response containing a `task_id`. Save this ID for subsequent queries.

```JSON
{
  "success": true,
  "task_id": "amk-tool-enhance-video-smoothness-123456789",
  "request_id": "20240523100000ABCDEFG12345"
}
```


<span id="step-2-get-the-repair-result"></span>
#### Step 2: Get the repair result

A stutter repair task requires processing time, depending on the video file size and duration. Poll the [Get task details](https://docs.byteplus.com/docs/byteplus-vod/ai-mediakit-get-task-details) API until the task status `status` changes to `completed`.

```Bash
curl -X GET 'https://mediakit.ap-southeast-1.bytepluses.com/api/v1/tasks/{task_id}' \
-H 'Authorization: Bearer {Your_API_Key}'
```

<span id="advanced-usage"></span>
## Advanced usage

The default request covers most scenarios. If you require more precise control, refer to the following advanced options.

<span id="repair-workflow-and-processing-order"></span>
### Repair workflow and processing order

If you enable multiple repair features at the same time, understanding the internal processing workflow helps you better anticipate the result.

<span id="processing-workflow"></span>
#### Processing workflow

The tool performs the following steps sequentially:


1. **Periodic stutter processing**: The tool first detects periodic stutter. If `periodic_stutter_repair` is `true`, it performs repair by intelligently inserting frames.

2. **Duplicate frame processing**: The tool then detects duplicate frames. If `duplicate_frame_repair` is `true`, it performs repair by removing duplicate frames.


<span id="dependencies-between-processing-steps"></span>
#### Dependencies between processing steps

The input to Step 2 depends on the result of Step 1:


* If periodic stutter repair in Step 1 is successfully performed, duplicate frame detection in Step 2 processes the repaired intermediate result.

* If periodic stutter repair in Step 1 is automatically skipped because the repair result is considered ineffective, duplicate frame detection in Step 2 processes the source video.


<span id="quality-evaluation-and-manual-intervention"></span>
#### Quality evaluation and manual intervention


* **Automatic skip mechanism**: The two repair stages, periodic stutter repair and duplicate frame repair, independently evaluate their repair results. If the algorithm determines that a repair cannot provide an effective improvement or may have a negative effect, the tool automatically skips the repair operation for that stage. This mechanism helps ensure the quality of the output. Even if a repair is skipped, the task result still returns the relevant detection details, such as `inserted_frames_detail`.

* **Highest priority for manually specified frame insertion**: Frame insertion positions specified through `insert_frame_indices` are not affected by the quality evaluation mechanism. As long as `periodic_stutter_repair` is `true`, the frames you specify are always inserted. The following example inserts one frame between frames 80 and 81 and another frame between frames 120 and 121.


```JSON
{
  "video_url": "https://example.com/your_video.mp4",
  "periodic_stutter_detect": {
    "periodic_stutter_repair": true,
    "insert_frame_indices": [80, 120]
  }
}
```


<span id="detect-without-repairing"></span>
### Detect without repairing

If you only want to evaluate periodic stutter and duplicate frames in a video without generating a repaired video, set the corresponding repair options to `false`. The task then returns only detection summaries, such as `inserted_frames_detail` and `duplicate_frames_detail`, and does not return `video_url`. The billing mode also changes. For details, see [Billing](https://docs.byteplus.com/docs/byteplus-vod/ai-mediakit-video-smoothness-enhancement#billing).

```JSON
{
  "video_url": "https://example.com/your_video.mp4",
  "periodic_stutter_detect": {
    "periodic_stutter_repair": false
  },
  "duplicate_frame_detect": {
    "duplicate_frame_repair": false
  }
}
```


<span id="keep-the-source-frame-rate"></span>
### Keep the source frame rate

By default, the frame rate of the repaired video may be higher than that of the source video because frames are inserted. This setting provides the best repair quality. If your business requires a consistent frame rate, such as keeping the total frame count the same as that of the source video, set `align_source_fps` to `true`. After you enable this option, the tool removes a number of low\-variation frames equal to the number of inserted frames, keeping the total frame count and video duration unchanged.

<span id="billing"></span>
### Billing

Video Smoothness Enhancement is billed per minute. The final price depends on whether the task actually performs a repair operation.


* Detection only: 0.03 USD/minute

* Detection and repair: 0.30 USD/minute


The task result determines the billing mode:


* If the task outputs a repaired video, meaning the result contains `video_url`, the task is billed as detection and repair. This includes tasks that complete any repair operation, including manually specified frame insertion.

* If the task does not output a video, meaning the result does not contain `video_url`, the task is billed as detection only. Even if you enable a repair option, the task is still billed at the lower detection\-only rate if the algorithm determines that the video does not require repair or skips repair after evaluating the result.


For more information about billing mode determination and billing examples, see [Video smoothness enhancement pricing](https://docs.byteplus.com/docs/byteplus-vod/ai-mediakit-pricing#ee096855).
