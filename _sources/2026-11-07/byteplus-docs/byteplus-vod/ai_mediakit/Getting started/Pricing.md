## General billing rules

Before reviewing the detailed pricing, please familiarize yourself with these global calculation rules:

* **Resolution determination by short side**: The resolution tier of an output video is determined by the pixel count of its **short side**. For example, a video with a resolution of 1920x800 has a short side of 800 pixels. Since 800 is greater than 720 (the short side of 720p) but less than or equal to 1080 (the short side of 1080p), it falls into the **1080p** billing tier.

* **Millisecond precision**: While prices are quoted per minute, usage is calculated with millisecond precision. The total accumulated milliseconds are converted to minutes for the final bill. For example, a task with an output duration of 90 seconds will be billed as 1.5 minutes.

### Highlight clipping

#### Billing rules

|Item |Description |
|---|---|
|Billable duration |The task result's `result.duration`, in seconds. |
|Unit price |$0.25 per minute |
|Billing formula |Highlight clipping fee = `result.duration` (seconds) ÷ 60 × $0.25 per minute |

#### Billing scenarios

The billable duration includes up to three components, depending on the task settings:

1. **Highlight analysis duration**: The duration of the input footage actually analyzed for highlights.

2. **Intro/outro detection duration**: If detection is enabled, `20 × N` seconds, where N is the total number of input videos.

3. **Generated highlight duration**: The combined duration of the highlight sections in all rendered videos. Appended source footage is excluded.

The following four scenarios show how these components apply.

**Scenario 1: Generate highlight videos (default)**

Analyze the input footage and generate highlights without detecting intros and outros or appending source videos. Use the default settings: `skip_video_output=false`, `append_source_video=false`, and `analyze_intro_outro_info=false`.

Billable duration = Highlight analysis duration + Generated highlight duration

**Scenario 2: Generate highlights and append source videos**

Set `append_source_video=true` to add the source videos after the highlights, for example, to promote a short drama series. Keep video output enabled and intro/outro detection disabled. Appended footage is excluded from billing, so only the analysis and generated highlights are charged.

Billable duration = Highlight analysis duration + Generated highlight duration

**Scenario 3: Generate highlights with intro/outro detection**

Set `analyze_intro_outro_info=true` to detect intros and outros for removal from the highlights or appended episodes. Keep video output enabled. You can set `append_source_video` to either `true` or `false`; appending source videos does not change the billable duration.

Billable duration = Highlight analysis duration + Intro/outro detection duration (`20 × N` seconds) + Generated highlight duration

**Scenario 4: Return highlight data without generating a video**

Set `skip_video_output=true` to retrieve highlight timestamps and, if detection is enabled, intro/outro intervals for rendering in your own system. No video is generated, so the generated highlight duration is zero and `append_source_video` has no effect.

Billable duration = Highlight analysis duration + Intro/outro detection duration (if enabled)

Intro/outro detection applies only to `preset=short_drama`. Appending source videos also requires `preset=short_drama` and `skip_video_output=false`.

#### Measurement details

* Highlight analysis duration (`result.input_duration`): `analysis_video_count` limits highlight analysis to the first N input videos. For a single video, `time_range` limits analysis to the specified time window. Only footage within the effective analysis scope is counted.

* Intro/outro detection duration: Each input video contributes a fixed 20 seconds, giving a total of `20 × N` seconds for all videos in `video_urls`. This applies even when a video is shorter than 20 seconds or no intro or outro is detected. The detection charge is independent of the highlight analysis scope.

* Generated highlight duration: Add the actual highlight duration across all rendered outputs, which can vary with `target_duration` and `allow_replay`. When a task generates multiple videos, highlight analysis and intro/outro detection are each billed once; only the generated highlight durations are added across outputs. Because `outputs[].duration` includes any appended source footage, it cannot be used directly as the billable duration.

#### Billing example

You analyze a 10\-minute video in full and generate two highlight videos, with actual durations of 1 and 2 minutes. Intro/outro detection and source video appending are disabled.

* Billable duration: 10 + 1 + 2 = 13 minutes.

* Fee: 13 minutes × $0.25 per minute = $3.25.

#### Rules for determining the processing mode

The system automatically determines the billing mode from the task's final execution result, specifically whether a repaired video was actually generated.

* **Conditions for detection and repair**: The task is billed in detection\-and\-repair mode as long as it successfully performs any repair operation and outputs a repaired video. In other words, this mode applies when the final task result contains an output video in `video_url`. This includes the following cases:

   * The algorithm detects periodic stutter and successfully repairs it.

   * The algorithm detects duplicate frames and successfully repairs them.

   * You manually specify frame insertion positions through `insert_frame_indices`.

* **Conditions for detection only**: The task is billed in detection\-only mode if it does not perform any actual repair operation. In other words, this mode applies when the final task result does not contain an output video in `video_url`. This includes the following cases:

   * You explicitly set all repair options to `false` in the request.

   * You enable a repair option, but the algorithm determines after detection that the video does not require repair.

   * The algorithm detects an issue but automatically skips the repair because its quality evaluation determines that the repair may have a negative effect.

#### Billing examples

* Example 1: Default request with repair

   * Scenario: You submit a Video Smoothness Enhancement task to process a 10\-minute video without specifying any repair configuration. The repair options default to `true`, and the task successfully performs a repair and returns `video_url`. Therefore, the task is billed in detection\-and\-repair mode.

   * Calculation: 10 minutes × 10 × $0.03 per minute

   * Total cost: $3.00

* Example 2: Detection only

   * Scenario: You submit a Video Smoothness Enhancement task to process a 10\-minute video and explicitly set both `periodic_stutter_repair` and `duplicate_frame_repair` to `false`.

## Overdue payment policy

Please ensure your account has a sufficient balance to avoid service interruptions. AI MediaKit follows the standard BytePlus overdue payment policy.

### Suspension and resource reclamation schedule

If your account has an overdue payment, your service will be restricted according to the following timeline:

|Stage |Trigger Time |Action Taken |
|---|---|---|
|Service Suspension |**3 days (72 hours)**  after payment is overdue |New task submissions will be blocked. You will not be able to create new API keys. Existing API calls will fail. |
|Resource Reclamation |**15 days (360 hours)**  after service suspension |Your service instance will be destroyed. All related configurations will be permanently deleted and cannot be recovered. |

### Service restoration

* **Restoring from suspension**: To restore your service, simply settle all outstanding payments to bring your account balance to a non\-negative value. All service functionalities will be automatically restored upon successful payment.

* **Restoring after reclamation**: Once your resources have been reclaimed, your original service instance is permanently deleted. To use the service again, you will need to reactivate AI MediaKit in the BytePlus console.
