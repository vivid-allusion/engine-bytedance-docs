You can enable the auto\-renewal function or manually renew the instances before the subscription instances expire, so the business will not be affected by the expiration of the instances.

<span id=".5rOo5oSP5LqL6aG5"></span>
## Precautions


* Only the subscription instances can be renewed, while the pay\-as\-you\-go instances do not need to be renewed, and you only need to ensure that your account has a sufficient balance available.

* After a subscription instance expires, it will be retained for a period of time but not deleted immediately, and you will need to renew it before it is forcibly deleted. For more information on instances in arrears or expiring, refer to [Arrears and expiration](https://docs.byteplus.com/en/docs/redis/arrear-and-expiration).


<span id=".57ut6LS55pa55byP"></span>
## Renewal method

Cache for Redis supports the following two renewal methods:


* **Automatic renewal**: You can enable auto\-renewal when creating a new annual or monthly subscription instance, or you can enable auto\-renewal at any time during the use of the instance to avoid business disruptions caused by instance expiration due to forgetting to manually renew. Once it is enabled, the system will automatically renew the instance before expiration each time, so please make sure that your account has a sufficient balance.

* **Manual renewal**: You can manually renew an instance at any time before it is forcibly deleted.


For specific instance renewal methods, refer to [Automatic or manual renewal](https://docs.byteplus.com/en/docs/redis/automatic-manual-renewal).
