Cache for Redis has been integrated with Database Workshop (DBW), providing multiple features including instance management, data management, O&M management, and enterprise security management.

## Feature introduction

The various features provided by Database Workshop (DBW) for Redis are shown in the table below.

|**Functional modules** |**Feature** |**Feature introduction** |
|---|---|---|
|Instances |Instance list management |In the Instances list, view Redis instance status, primary node availability zones, and instance specifications. You can filter instances by project or region and search for target instances by instance ID or name. You must have created Redis instances in the Running state before use. For more details, see [Instance list management](https://docs.byteplus.com/en/docs/DBW/instance-list-management-for-redis?lang=en). |
||Enable security control |Integrate Redis instances into DBW for unified management. Configure security controls and approval workflows for database operations, ensuring that all related operations adhere to established rules for permission requests and approvals. Once enabled, password\-free login is supported on the data interaction platform. Configuring security controls requires a DBW administrator role. For more details, refer to [Enabling security control](https://docs.byteplus.com/en/docs/DBW/enabling-security-management-for-redis?lang=en). |
|Data management |Logging on to the data interaction platform (Cache for Redis) |Connect to Redis instances via the data console to perform command execution and data management. Supports password\-free login when conditions are met, and authorizes DBW to add service IPs to the instance allowlist; re\-logging in after logout will default to restoring the previous page. For more details, see [Log in to Cache for Redis Workbench](https://docs.byteplus.com/en/docs/DBW/logging-on-to-the-data-interaction-platform-for-cache-for-redis?lang=en). |
||Executing commands |Execute statement commands on the Redis data console, manage operation windows with multiple tabs, and use hotkeys to execute specified statements. Query results display a maximum of 3,000 rows, and a maximum of 10 tabs can be opened. Some commands are not supported, and it is not recommended to execute tasks sensitive to response latency in this window. For more information, see [Command operations](https://docs.byteplus.com/en/docs/DBW/executing-commands-for-redis?lang=en). |
||Key value management |Switch the target DB in the data interaction platform's visual area. Create, edit, and delete key\-value pairs to manage their full lifecycle. Supports searching for keys. Prioritize exact searches as fuzzy searches use the SCAN command and may time out or impact the instance when there are many keys. For more details, refer to [Key value management](https://docs.byteplus.com/en/docs/DBW/key-value-management-for-redis?lang=en). |
||Creating an operation permission ticket |The DBW user role applies for Redis instance operational permissions through a permission application ticket, filling in information such as authorized instances, application reasons, and permission validity period, then proceeding according to the approval process configured by instance security control. The maximum validity period for permissions is 1 year. For more details, refer to [Creating an operation permission ticket](https://docs.byteplus.com/en/docs/DBW/creating-an-operation-permission-ticket-for-redis?lang=en). |
||Managing permission application tickets |In the work order list, filter and view the basic information, application content, and current status of permission applications. Approvers can approve or reject authorization requests. DBW administrators can view all tickets, while normal users can only view tickets they created or are assigned as approvers. For more details, see [Managing permission application tickets](https://docs.byteplus.com/en/docs/DBW/managing-permission-application-tickets-for-redis?lang=en). |
|Operation and maintenance management |Performance monitoring management |Provide performance monitoring metrics for Redis instances, switch to the target instance on the observation and diagnosis page to view performance trends and operational status, and identify potential risks. Before use, you must grant DBW permission to access other Cloud Service resources. For more details, see [Performance monitoring management](https://docs.byteplus.com/en/docs/DBW/Redis_Performance_monitoring_management?lang=en). |
||(Beta) Database audit management |Records database data write operations, allowing you to view information such as execution level, execution time, and execution type, for tracking database activities, identifying issues, and checking for non\-compliant operations. This feature is currently in the invitation\-only beta phase. You must submit a ticket to apply for its use, and billing has already commenced. For more details, refer to [(Beta) Database audit management](https://docs.byteplus.com/en/docs/DBW/database-audit-management?lang=en).<br><br>> **tip**<br><br><br>> You can access the **Database audit** page via the Redis console: Log in to the Redis console \> Select an instance \> Instance details \> Database workbench \> Database audit.<br> |
||Bandwidth auto\-scaling management |Dynamically adjust network specifications based on Redis instance read/write bandwidth utilization to handle traffic spikes during scenarios like e\-commerce promotions and game launches, and optimize resource costs when traffic decreases. Automatic scaling and auto\-contraction rules for read and write bandwidth are independent of each other. Each instance can create a maximum of 4 rules, subject to a cooldown period. For more details, see [Bandwidth auto-scaling management](https://docs.byteplus.com/en/docs/DBW/automatic-bandwidth-scaling-management-for-redis?lang=en).<br><br>> **tip**<br><br><br>> Access the **Bandwidth auto\-scaling management** page via the Redis console: Log in to the Redis console \> Select an instance \> Instance Details \> Database Workbench \> Bandwidth Auto\-Scaling.<br> |
||Database inspection management |Regularly and automatically perform health checks and risk assessments on Redis instances, and generate inspection reports. Rating involves indicators such as CPU, memory, and connection usage rates; automatic inspection is performed once daily and by default evaluates data from the previous day. Inspection records and reports are retained for the last 30 days, and support downloading reports. For more details, see [Database inspection management](https://docs.byteplus.com/en/docs/DBW/Redis_database_inspectioin_management?lang=en).<br><br>> **tip**<br><br><br>> You can access the **Database inspection** page via the Redis console: Log in to the Redis console \> Select instance \> Instance details \> Database Workbench \> Database Inspection.<br> |
|Corporate security management |Granting operation permissions for system roles |Grant operational permissions for Redis instances to individual users, multiple users, or user groups in User Management. Authorized instances can be selected directly or based on their associated projects, facilitating unified management of instance access scope for different users. The target instance must have security control enabled. For more details, refer to [Granting operation permissions for system roles](https://docs.byteplus.com/en/docs/DBW/granting_operation_permissions_for_system_roles_for_redis?lang=en). |
||Security rule set management |Refine database instance access and operation control using security rule sets, implement the principle of least privilege, and manage custom rule sets. The system provides a default rule set, redis default, which cannot be deleted. Custom rule sets cannot be recovered after deletion. Management operations require the DBW Administrator role. For more details, refer to [Security rule set management](https://docs.byteplus.com/en/docs/DBW/security-rule-set-management-for-redis?lang=en). |
||Security rule management |View and enable or disable rules as needed in the security rule set to control permission checks in specific scenarios. The default rule listed in the documentation is "All users need permission checks" in the SQL window, which is enabled by default. Currently, only security rules in the default security rule set can be enabled or disabled, and system rules cannot be deleted. For more details, refer to [Security rule management](https://docs.byteplus.com/en/docs/DBW/security_rule_management_redis?lang=en). |
