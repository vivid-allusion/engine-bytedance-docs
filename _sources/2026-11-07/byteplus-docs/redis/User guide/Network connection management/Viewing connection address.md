Cache for Redis supports various connection address types. You can select the appropriate connection address based on your business needs to access and manage Redis instances. This topic describes how to view the connection address of Redis on the console.

## Connection address type

Cache for Redis groups and displays connection addresses by access method, including **private network access (proxy private network access, direct private network access)**  and **public network access (proxy public network access)** . Specific descriptions and precautions for different connection address types are detailed in the following table.

|Connection address type |Private network access ||Public network access |
|---|---|---|---|
||Proxy private network address |Direct connection proxy access |Proxy public network access |
|Description |* Accessing the Redis instance through a private network address maximizes security and performance.<br><br>* To connect instances through private networks, refer to [Connecting to instance via private address](https://docs.byteplus.com/en/docs/redis/connect-instance-via-private-address). |* Cache for Redis adopts the proxy\-server architecture by default. You can directly access the data shards at the instance backend through a direct address (similar to a native architecture that directly connects to the Redis server). When a client first uses a direct connection address to access instance, the direct connection address will be resolved to the fixed Virtual IP (VIP) address allocated by Redis to all shards, and then routed to each data shard via the Redis cluster protocol.<br><br>* For more information on how to request direct connection address and access Redis instances via direct connection address, refer to [Applying for direct connection address](https://docs.byteplus.com/en/docs/redis/apply-direct-connection-address) and [Connecting to instance via direct connection address](https://docs.byteplus.com/en/docs/redis/connect-instance-through-direct-connection-address). |* You can enable public network access for your Redis instance, allowing devices outside the VPC to access it.<br><br>* For more information on how to enable internet access and access Redis instances via public network address, refer to [Applying for public address](https://docs.byteplus.com/en/docs/redis/apply-public-address) and [Connecting to instance via public address](https://docs.byteplus.com/en/docs/redis/connect-instance-via-public-address). |
|Precautions |* A private network address is generated by default when Redis instance is created.<br><br>* Deletion of the Redis private network address is not supported. |* Only Redis instances with sharing cluster enabled support direct connection addresses. For more details about sharding cluster enabled, refer to [Product architecture](https://docs.byteplus.com/en/docs/redis/product-component-architecture).<br><br>* Access through direct addresses to save time in processing requests through proxies. In theory, this can shorten the response time of the server to the client, but automatic load balancing, automatic read/write splitting, and other advanced features are lost. We recommend that you exercise due caution when selecting the address type according to your actual needs.<br><br>* Your client must support the Redis cluster protocol, otherwise it cannot connect to Redis instances via the direct address. |* Compared with private network access, internet access has a higher latency and involves certain security risks. We recommend that you only use it in testing environments, while private network access is recommended for production environments.<br><br>* When devices outside the VPC no longer need to access Redis instances, promptly disable public network access. For instructions on how to disable internet access, refer to [Releasing public network address](https://docs.byteplus.com/en/docs/redis/release-public-address). |
|Support for modifying address domain name? |Yes. For specific procedures, refer to [Modifying connection address](https://docs.byteplus.com/en/docs/redis/modify-address). |||
|Support for modifying address port number? |Yes. For specific procedures, refer to [Modifying port number](https://docs.byteplus.com/en/docs/redis/modify-port). |||

## Procedure

1. Log in to the [Redis console](https://console.byteplus.com/db/redis).

2. In the top menu bar, select the project and region to which the instance belongs.

3. On the **Instances** page, click the target instance name.

4. On the instance details page, click on the **Connectivity** tab.

5. On the **Connectivity** tab, you can view detailed information for each group, including the **proxy private network address/proxy private IP/proxy private port**, **direct connection private network address/direct connection private IP/direct connection private port**, and **proxy public network address/public port**.

   > **tip**

   * > For more information on various addresses, refer to [Connection address type](https://docs.byteplus.com/en/docs/redis/view-address#.6L-e5o6l5Zyw5Z2A57G75Z6L).

   * > Only the private network access connection address can be viewed on the Redis console. For how to view the IP address corresponding to direct connection address or public network address, refer to [How to view the IP address corresponding to the Redis connection address](https://docs.byteplus.com/en/docs/redis/network-connection#.5aaC5L2V5p-l55yLLXJlZGlzLei_nuaOpeWcsOWdgOWvueW6lOeahC1pcC3lnLDlnYA=).

   * > Only Redis instances with sharing cluster enabled support direct connection addresses. You must require a direct address before you can view the information about the direct address. For specific procedures, refer to [Applying for direct connection address](https://docs.byteplus.com/en/docs/redis/apply-direct-connection-address).

   * > Cache for Redis disables public network access by default. To view public network address information, you must manually enable public network access first. For specific procedures, refer to [Applying for public address](https://docs.byteplus.com/en/docs/redis/apply-public-address).
