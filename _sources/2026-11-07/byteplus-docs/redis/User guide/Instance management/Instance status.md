This topic summarizes all possible instance status and their details for Cache for Redis.

|Instance status |Status code |Triggering operation |Description or impact |
|---|---|---|---|
|Allowlist maintaining |AllowListMaintaining |Modify the association between instances and allowlists, including:<br><br><br>* Associate instances and allowlists.<br><br>* Disassociate instances from allowlists. |When associating and disassociating instance to allowlist, the status of the instance will become **AllowList maintaining**. For specific procedures, refer to [Associating instances and allowlists](https://docs.byteplus.com/en/docs/redis/associate-allowlist) and [Disassociating instances from allowlists](https://docs.byteplus.com/en/docs/redis/disassociate-allowlist). |
|Availability zone migrating |AZChanging |Modify availability zone of instance. |This status will appear during the change process when modifying available zone for instance. |
|Shutting down |Closing |The following operations will cause the instance to release:<br><br><br>* The account associated with a pay\-as\-you\-go instance is in arrears.<br><br>* A subscription instance has expired. |This is an intermediate status during instance releasing. When a subscription instance expires or the account of a pay\-as\-you\-go instance is in arrears, the instance enters the **Closing** status, and you should wait for the system to perform relevant processing. After the system handles the event, the instance enters the **Closed** status. |
|Creating |Creating |Create instance. |The instance is being created, and the next status will be **Running**, during which database services are not yet provided. |
|Creation failed |CreateFailed |Failed to create instance. |Instance creation failed due to system exceptions or other reasons. The instance cannot provide services in this status. |
|Deleting |Deleting |Delete Pay\-as\-you\-go instance. |Delete all resources and data of the instance, and the action cannot be undone. For more details, refer to [Deleting instance](https://docs.byteplus.com/en/docs/redis/delete-instance). |
|Maintaining |Maintaining |When the system conducts unscheduled maintenance on the database, it will enter **Maintaining** status. |To ensure the stability of Cache for Redis, the system conducts unscheduled maintenance on the database. During the maintenance period, you cannot perform any modification operations on the target instance, such as modifying specifications or restarting instance.<br><br>> **tip**<br><br><br>> Notifications will be sent via SMS, email, and in\-app messages before maintenance operations. Check your phone or email promptly for relevant information.<br> |
|Network maintaining |NetworkMaintaining |Modify the instance's network connection settings, including:<br><br><br>* Modifying VPC or subnet.<br><br>* Apply for or release public address.<br><br>* Apply for or release direct connection addresses.<br><br>* Modify port.<br><br>* Modify connection address.<br><br>* Enable or disable public network resolution.<br><br>* Upgrade domain name suffix. |When modifying VPC or subnet, applying for or releasing direct addresses or public addresses, modifying addresses or ports, enabling or disabling public network resolution, upgrading domain name suffix, the instance status will change to **Network maintaining**. For more information about network connections, refer to [Managing network connections](https://docs.byteplus.com/en/docs/redis/network-connection-management). |
|Parameter modifying |ParameterModifying |* Modify instance parameter configuration.<br><br>* Create account, delete account, or update account role, description, password.<br><br>* Setting query result cache. |After modifying instance's parameter configuration, performing account management related actions, or setting query result cache, the instance status is displayed as **Parameter modifying**. |
|Node role switching |PrimaryChanging |The following actions will trigger primary\-secondary node switchover:<br><br><br>* System\-triggered failover.<br><br>* Executing failover manually. |When a fault is detected in an instance, the system automatically triggers a primary\-secondary node switch, or when you manually execute a primary\-secondary node switch based on service requirements. This status appears during the failover process. For more details, refer to [Failover](https://docs.byteplus.com/en/docs/redis/failover). |
|Rroxy restarting |ProxyRestarting |Restart proxy node. |Restarting proxy node impacts existing connections. Please operate during off\-peak hours and ensure that the business has a reconnection mechanism. For more details, refer to [Restarting proxy node](https://docs.byteplus.com/en/docs/redis/restart-proxy-node). |
|Closed |Released |The following operations will cause the instance to release:<br><br><br>* The account associated with a pay\-as\-you\-go instance is in arrears.<br><br>* A subscription instance has expired. |When a subscription instance expires or the account of a pay\-as\-you\-go instance has arrears, the instance enters the **Closed** status. The instance cannot provide services in this status.<br><br>> **tip**<br><br><br><br>* > Billing is suspended for instances whose status is **Closed**.<br><br><br>* > You can enable automatic renewal or manually renew the instance before it expires. For specific procedures, refer to [Automatic and manual renewal](https://docs.byteplus.com/en/docs/redis/automatic-manual-renewal).<br><br><br>* > You can recharge your account in the [Billing center](https://console.byteplus.com/finance/account-overview/) before it goes into arrears.<br> |
|Restarting |Restarting |Restart instance. |Temporary disconnections lasting a few seconds may occur during instance restart. We recommend that you perform restarts during off\-peak hours and ensure that applications have an automatic reconnection mechanism. For more details, refer to [Restarting instance](https://docs.byteplus.com/en/docs/redis/restart-instance). |
|Restoring |Restoring |Restore instance backup data to the source instance. |When restoring data to the source instance, the status of the source instance will change to **Restoring**. For more details, refer to [Data recovery](https://docs.byteplus.com/en/docs/redis/recovery). |
|Running |Running |The instance is successfully created. |Database services are operating normally. |
|Configuration modifying |Scaling |Modify instance specifications, including:<br><br><br>* Modify instance specifications.<br><br>* Modify bandwidth. |This status appears when instance configurations or bandwidth are being modified.<br><br>> **tip**<br><br><br>> If you choose to execute configuration changes (such as node specifications, number of shards, number of nodes, enabling sharding cluster, or switching to primary\-seconday instance) during a maintenance period, the instance status immediately changes to **Configuration modifying**. This status persists until the task is complete, but the actual execution time of the operation remains within the maintenance period. For more details, refer to [Setting maintenance period](https://docs.byteplus.com/en/docs/redis/set-maintenance-period).<br> |
|Task failed |TaskFailed |Failed to perform operations such as changing configurations, upgrading versions, or modifying parameters. |When the execution of specification modifications and version upgrades or parameter modifications fails, the instance status changes to **Task failed**. The instance can usually provide services normally in this status. |
|Upgrading minor version |Upgrading |Upgrade the minor database version of the instance. |This status appears when upgrading the minor database version of the instance.<br><br>> **tip**<br><br><br>> If you choose to perform the operation within the maintenance period, the instance status will immediately change to **Upgrading minor version**, and this status will persist until the task is complete, but the actual execution time of the operation task will still be within the maintenance period. For more details, refer to [Setting maintenance period](https://docs.byteplus.com/en/docs/redis/set-maintenance-period).<br> |
|Waiting for payment |WaitingPaid |The order for creating instance has been submitted, but payment has not been completed or payment has failed. |If you have submitted an order to create an instance but have not completed the payment or the payment has failed, the instance will enter the **Waiting for payment** status.<br><br>> **tip**<br><br><br><br>* > The successfully created instance order waiting for payment will be retained for 24 hours. It is recommended to complete the payment in a timely manner, otherwise the order will be automatically cancelled and you will need to recreate the instance order.<br><br><br>* > You can choose any of the following methods to complete the payment:<br><br><br>   * > On the instance list page of the [Redis console](https://console.byteplus.com/db/redis), find the target instance in the **Waiting for payment** status. In the **Actions** column on the right side of the instance, click **Go to pay** to jump to the **Submit payment information** page of the instance, and you need to complete the payment according to the prompts on the page.<br><br><br>   * > Go to [Billing center \> Order](https://console.byteplus.com/finance/order/) page, find the corresponding **Waiting for payment** order and complete the payment according to the prompts on the page.<br> |
|Blue\-green deployment in progress<br><br> |BlueGreenDeployment |Upgrading major versions using blue\-green deployment. |When upgrading major instance version using blue\-green deployment feature, there are 3 main processes: creating green instance, testing and verification, and blue\-green switch. During the aforementioned process, both blue and green instances will enter the **Blue\-green deployment in progress** status. For more details, refer to [Upgrading major version using blue-green deployment](https://docs.byteplus.com/en/docs/redis/upgrade_major_version_using_blue_green_deployment).<br><br>> **tip**<br><br><br>> To use the major version upgrade feature, [submit a ticket](https://console.byteplus.com/workorder/create/) to technical support to apply for usage.<br> |
