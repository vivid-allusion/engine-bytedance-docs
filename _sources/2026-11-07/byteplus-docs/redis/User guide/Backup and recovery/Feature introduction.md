Cache for Redis provides data backup and recovery functions for quick recovery after data update or delete, ensuring reliable data security.

<span id=".5L2_55So6ZmQ5Yi2"></span>
## Limits

Only Redis instances of **primary\-secondary** type support backup recovery functions, and Redis instances of **single\-node** type **not** support data backup recovery related functions. For details about the feature differences between the two instance types, refer to [Feature differences](https://docs.byteplus.com/en/docs/redis/feature-faq#.5Li75aSH5a6e5L6L5ZKM5Y2V6IqC54K557G75Z6L5a6e5L6L5pSv5oyB55qE5Yqf6IO954m55oCn5pyJ5L2V5beu5Yir77yf).

## Billing instructions

<span id=".5pWw5o2u5aSH5Lu96K6h6LS5"></span>
### Billing for data backup

All backups generated by Cache for Redis are stored in the BytePlus [TOS](https://docs.byteplus.com/en/docs/tos/docs-what-is-tos) service, do not occupy the storage space of the Redis instance, and are not charged currently. We will inform you, on our website or via a product notification, before a service charge is officially introduced.

For more information about Redis instance billing items, refer to [Billing items and prices](https://docs.byteplus.com/en/docs/redis/billing-item-price).

<span id=".5pWw5o2u5oGi5aSN6K6h6LS5"></span>
### Billing for data recovery

Currently, the data recovery feature is free to use, but when restoring to a new instance by backup set or by point in time, there is a payment for the new instance. For instance billing details, refer to [Billing overview](https://docs.byteplus.com/en/docs/redis/billing-overview).

## Data backup

Cache for Redis supports both automatic and manual backup methods. See the table below for details of different backup methods. Cache for Redis provides basic backup and cross\-region backup capabilities.

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>



* <div data-tips="true" data-tips-type="tip">All Redis backups have a fixed retention time of 7 days and cannot be modified.</div>


* <div data-tips="true" data-tips-type="tip">You can view backups of instances on the Redis console. For specific procedures, refer to <a href="https://docs.byteplus.com/en/docs/redis/view-backup">Viewing backups</a>.</div>


* <div data-tips="true" data-tips-type="tip">When creating a backup, the Cache for Redis will preferentially pull data from the secondary node of the instance for backup. If there is no available secondary node for instance, it will pull data from the primary node for backup. During the backup period, it may cause a short\-term increase in instance access latency. It is recommended to perform backup\-related operations during off\-peak business hours.</div>



<span id=".5Z-656GA5aSH5Lu9"></span>
### Basic backup

The basic backup function is enabled by default in all Redis instances. Basic backup refers to backups stored in the same region as the instance, and its disaster recovery capability is limited. In the event of a region\-level failure, there is no guarantee that the backup will be available.

Basic backup supports both automatic and manual backup methods. The following table illustrates the differences between the two backup methods.


|Backup method |Description |
|---|---|
|[Automatic backup](https://docs.byteplus.com/en/docs/redis/automatic-backup) |Cache for Redis uses RDB snapshot storage by default to achieve persistence. It saves the memory data at a certain point in time to files on the hard disk.<br><br>After the Redis instance is successfully created, if you do not modify the automatic backup policy, the system will select any hour (such as 02:00~02:59) from 00:00 to 06:59 every day for backup by default, and the backup will be kept for 7 days by default. You can also set backup policies based on business needs, and the instance will automatically backup Redis data according to the backup policies you set. |
|[Manual backup](https://docs.byteplus.com/en/docs/redis/manual-backup) |When you need to temporarily backup Redis data, you can trigger the generation of backup files through the manual backup function. |

## Data Recovery

Cache for Redis supports a variety of data recovery scenarios, as detailed in the following table.


|Data recovery scenario |Description |
|---|---|
|[Restore by backup set](https://docs.byteplus.com/en/docs/redis/recovery-from-backup-set) |Cache for Redis supports restoring data to the original instance according to the specified backup set, or creating a new instance according to the specified backup set. The data in the new instance is consistent with the data in the specified backup set, which can be used for scenarios such as data recovery, rapid deployment business or data verification. |
|[Recovery by point in time](https://docs.byteplus.com/en/docs/redis/recovery-by-time-point) |After enabling the [Data flashback](https://docs.byteplus.com/en/docs/redis/set-data-flashback) function, you can restore the Redis instance to a specified point in time, or restore the backup file at a specified point in time to a new instance, so as to avoid data loss caused by misoperations. |
|[Restoring deleted instance](https://docs.byteplus.com/en/docs/redis/restore-deleted-instance) |Before primary\-secondary Redis instance deleted, the latest backup will be created by default and retained in the backup list for a period of time. When instance is deleted due to misoperation, account arrears, or expiration of the instance, you can restore the deleted instance to a new instance through backup. |
| | |
