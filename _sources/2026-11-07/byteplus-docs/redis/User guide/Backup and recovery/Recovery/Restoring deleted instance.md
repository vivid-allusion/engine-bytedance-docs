Before the primary\-secondary instance of Cache for Redis is deleted, a new backup is created by default and retained in the backup list for a period of time. When an instance is deleted due to incorrect actions, account overdue, or instance due, you can restore the deleted instance to a new instance through backup.

## Prerequisite

* The instance type is the **Primary\-secondary** instance. Single\-node instances do not support backup and restore functionality. For details about the feature differences between the two instance types, refer to [Feature differences](https://docs.byteplus.com/en/docs/redis/feature-faq#.5Li75aSH5a6e5L6L5ZKM5Y2V6IqC54K557G75Z6L5a6e5L6L5pSv5oyB55qE5Yqf6IO954m55oCn5pyJ5L2V5beu5Yir77yf).

* The backup for the deleted instance was successfully created and the backup status is **Available**. For more information about backup status, refer to [Backup status](https://docs.byteplus.com/en/docs/redis/view-backup).

## Precautions

* After a backup created for a deleted instance is successful, the backup retention period is fixed to 7 days and cannot be modified.

* Backups will be automatically deleted after expiration and cannot be recovered. It is recommended to download the backup locally in time before the end of the backup retention period, or perform data recovery through backup.

* During data recovery (either to a new instance or to an original instance), do not perform any read or write operations on the instance. Otherwise, the recovery may fail or the recovered data may not meet expectations.

## Billing instructions

There is no charge for the recovery of deleted instances itself, but when you restore deleted instance data to a new instance through backup, you need to pay for the new instance. For instance billing details, refer to [Billing overview](https://docs.byteplus.com/en/docs/redis/billing-overview).

## Procedure

1. Log in to the [Redis console](https://console.byteplus.com/db/redis).

2. In the top menu bar, select the project and region to which the instance belongs.

3. In the left navigation bar, select **NoSQL Database \> Redis \> Backups**.

4. Under the **Basic backups** tab of the **Backups** page, find the available backups for the deleted instance and click **Restore** in the right **Actions** column.

   > **tip**

   > You can quickly filter out the available backups of deleted instances in the backup list using the following filter criteria:

   * > **Backup status** is **Available**.

   * > **Instance status** is **Deleted**.

   > For more information about backup filter conditions or fields, refer to [Viewing backups](https://docs.byteplus.com/en/docs/redis/view-backup).

5. On the **Data recovery** page, configure the following parameters.

   1. In the **Restore settings** area, follow these steps to select the appropriate backup set.

      2. In the **Select backup set** control panel that pops up on the right, select the backup set you want to restore.

         > **tip**

         > In the backup set list, backups of the current instance with a backup status of **Available** under the **Basic backups** tab are displayed by default.

      3. In the lower right corner of control panel, click **OK**.
