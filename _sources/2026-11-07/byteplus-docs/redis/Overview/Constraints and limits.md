## Data type limits


|Data type |Limit |
|---|---|
|String |A single String type value cannot exceed 512 MiB. |
|List |List and number of its elements do not exceed `2^32-1`. The value of a single element cannot exceed 512 MiB.<br><br>The recommended number of elements in the List is less than 8192. The max length of the value cannot exceed 1 MiB. |
|Set |Set and number of its elements do not exceed `2^32-1`. The value of a single element cannot exceed 512 MiB.<br><br>The recommended number of elements in the Set is less than 8192. The max length of the value cannot exceed 1 MiB. |
|ZSet |ZSet and number of its elements do not exceed `2^32-1`. The value of a single element cannot exceed 512 MiB.<br><br>The recommended number of elements in the ZSet is less than 8192. The max length of the value cannot exceed 1 MiB. |
|Hash |Hash and number of its elements do not exceed `2^32-1`. The value of a single element cannot exceed 512 MiB.<br><br>The recommended number of elements in the Hash is less than 8192. The max length of the value cannot exceed 1 MiB. |

## Feature limits


|Feature |Limit |
|---|---|
|Redis command support and limit |For more information, refer to [Supported commands](https://docs.byteplus.com/en/docs/redis/supported-command) and [Command limits](https://docs.byteplus.com/en/docs/redis/command-limit). |
|Default disable command |Cache for Redis instances disable the `flushall`, `flushdb`, and `keys` commands by default.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">To use the above commands, remove the corresponding commands from the default value of the parameter <code>disabled-commands</code>. For specific procedures, refer to <a href="https://docs.byteplus.com/en/docs/redis/set-parameter">Setting instance parameters</a>.</div><br> |
|Deletion policy for stale data |Cache for Redis supports the following policies:<br><br><br>* **Auto delete**: The system backend periodically detects and automatically deletes expired keys.<br><br>* **Manual delete**: If an expired key is not deleted by the system backend, you can manually delete it. |
|Reclaim mechanism for idle connections |The server does not actively reclaim Redis idle connections. The user must manage it. |
|Data persistence policy |AOF persistence policy is enabled for primary\-secondary instances by default.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><br>* <div data-tips="true" data-tips-type="tip">Single\-node instances do not have data persistence capabilities and do not support any data persistence policies. For more information on the functional characteristics of primary\-secondary and single\-node instances, refer to <a href="https://docs.byteplus.com/en/docs/redis/feature-faq#.5Li75aSH5a6e5L6L5ZKM5Y2V6IqC54K557G75Z6L5a6e5L6L5pSv5oyB55qE5Yqf6IO954m55oCn5pyJ5L2V5beu5Yir77yf">Feature differences</a>.</div><br><br><br>* <div data-tips="true" data-tips-type="tip">Each Redis instance supports saving AOF files of the same size as the instance memory. For example, if the instance memory is 1 GiB, up to 1 GiB of AOF files can be saved in the instance and any portion exceeding 1 GiB will be deleted.</div><br> |
|Monitoring and alerts |Cache for Redis has no services for capacity alerts. If you need to use the alert service, please configure it in Cloud Monitor. For configuration methods, refer to [Creating alarm strategy](https://docs.byteplus.com/en/docs/cloudmonitor/Creating-an-alarm-strategy). |
|Number of available DBs |Each Redis instance can use up to 256 databases. |
|Number of shard(s) |Each Redis instance with sharding cluster enabled has up to 256 shards. |
|Total instance nodes |Total instance nodes: total nodes per instance = number of shards × nodes per shard. The current instance has a maximum of 256 shards. Each shard can be configured with up to 6 nodes, allowing a single instance to have a maximum of 1536 total nodes. If your instance requires more nodes, [submit a ticket](https://console.byteplus.com/workorder/create/) to contact technical support to modify the relevant parameters. |
|IP allowlist |* Each BytePlus account can create up to 1,000 allowlists per region.<br><br>* Each BytePlus account can allow up to one default allowlist per region. A newly created default allowlist will automatically override the existing default allowlist. That is, the existing default allowlist will automatically become a non\-default allowlist.<br><br>* Each allowlist can be associated with up to 200 instances at a time, and there is no limit to the total number of instances that can be associated.<br><br>* Each allowlist can be associated with up to 300 IP addresses or IP address segments in CIDR format.<br><br>* Each allowlist can be associated with up to 10 ECS security groups.<br><br>* Each instance can be associated with a maximum of 100 allowlists. A maximum of 100 allowlists can be associated at a time.<br><br>* Each instance can be associated with up to 1,000 IP addresses or IP address segments in CIDR format.<br><br>* If no allowlist is associated with an instance, its access is denied to all addresses. |
|Connections |For each instance of Cache for Redis or each shard in the instance, 10,000 concurrent connections can be created every time. Requests for new connections are rejected over this limit. If you need to use more connections, you can modify the maximum number of connections. For specific procedures, refer to [Modifying maximum number of connections](https://docs.byteplus.com/en/docs/redis/modify-max-conn-number). |
|Concurrent connections |For each instance of Cache for Redis or each shard in the instance, 10,000 concurrent connections can be created every time. Requests for new connections are rejected over this limit. |
|Bandwidth |Redis instances of different specifications support different upstream and downstream bandwidths. For more information, refer to [Instance specifications](https://docs.byteplus.com/en/docs/redis/product-specification).<br><br>High network input and output bandwidth utilization of the instance can cause request response latency and may even lead to errors such as IO timeouts. For more information on bandwidth utilization monitoring, refer to [Monitoring metrics](https://docs.byteplus.com/en/docs/redis/monitoring-metric). |
|Number of customized parameter templates |Each root account of BytePlus can create up to 20 customized parameter templates in each region by default. For more information, refer to [Creating parameter template](https://docs.byteplus.com/en/docs/redis/create-parameter-template). |
|Number of instances of parameter templates that can be applied in batches at a time |Each parameter template can be applied to up to 20 instances at one time. |
|Number of disableable commands |Each instance can disable up to 16 commands. You can set the disabled commands for an instance with the `disabled-commands` parameter, and multiple disabled commands are separated by a comma (,). For details, refer to [Setting instance parameters](https://docs.byteplus.com/en/docs/redis/set-parameter). |
|Number of accounts available |Each Redis instance can have up to 100 accounts by default. If you need to create more accounts, please [submit a ticket](https://console.byteplus.com/workorder/create/) to contact technical support to modify relevant parameters. |
|Number of usable roles |Each Redis instance can have up to 100 roles by default. If you need to create more roles, please [submit a ticket](https://console.byteplus.com/workorder/create/) to contact technical support to modify relevant parameters. |
|Number of key parameters in a Lua script |For instances with proxy minor version less than 1.511.0, the maximum limit for the number of key parameters in a Lua script is 100 by default. When the number of keys exceeds the limit, an error message `command arguments invalid` will appear. If needed, [submit a ticket](https://console.byteplus.com/workorder/create/) to contact technical support to upgrade the instance proxy to the latest version and cancel this limit. |
