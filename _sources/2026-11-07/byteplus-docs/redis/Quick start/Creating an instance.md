Creating instance is the first step of using Cache for Redis. This topic shows you how to create Redis instances.

## Prerequisites

* A BytePlus account has been registered and completed verification. For the detailed method, refer to [Sign up and verify BytePlus account](https://docs.byteplus.com/en/docs/byteplus-platform/docs-signing-up-your-account).

* As per the regulations in the Chinese mainland, you must have completed real name registration before you can activate and use cloud services in regions in the Chinese mainland through BytePlus. For more details, refer to [Real name registration](https://docs.byteplus.com/en/docs/byteplus-platform/docs-real-name-registration).

* Cross\-service access has been authorized to allow Redis to access other services (such as VPC and EIP). For specific procedures, refer to [Cross-service access authorization](https://docs.byteplus.com/en/docs/redis/cross-service-access-authorization).

## Procedure

1. Log in to the [Redis console](https://console.byteplus.com/db/redis).

2. In the top menu bar, select the project and region to which the instance belongs.

3. On the **Instances** page, click **Create instance**.

4. On the **Create instance** page, set the following parameters.

   |Parameters ||Description |
   |---|---|---|
   |Service type ||Currently fixed to **Redis community edition**, no selection required. |
   |Basic information |Instance name |Enter the instance name. Optional. If left blank, the instance ID will be used as the instance name by default. The name must meet the following requirements:<br><br><br>* It cannot start with a number or hyphen (\-).<br><br>* It can only contain Chinese characters, letters, digits, underscores (_), and hyphens (\-).<br><br>* The length should be 1 to 128 characters.<br><br><br>> **tip**<br><br><br>> After setting the instance name, if you choose to batch create instances, the system will automatically add `_<instance_number>` after the name you set to differentiate the instances. For example, `redistest_000` and `redistest_001`.<br> |
   ||Database version |Select the Redis database version. You can choose **Redis 7.0**, **Redis 6.0**, or **Redis 5.0**. |
   |Specification configuration |Instance type |Select the Redis instance type. Valid values:<br><br><br>* **Primary\-secondary**: Each shard of a primary\-secondary instance contains at least two nodes, one of which is the primary node (also known as the read/write node), and the other is the secondary node (also known as the read\-only secondary node). There is a replication relationship between the primary and secondary nodes.<br><br>* **Single node**: Each shard of a single\-node instance contains only one node (primary node), without replication relationships between the nodes. Single\-node instances do not have data persistence and high availability features.<br><br><br>> **tip**<br><br><br>> Single\-node instances do not support persistence or backup, and cannot guarantee data availability or service continuity. We recommend that you use them only in testing, learning, and other scenarios, and not in production environments. For more details about single\-node instance types, refer to [Product architecture](https://docs.byteplus.com/en/docs/redis/product-component-architecture).<br> |
   ||Sharding cluster |Choose to **Enable** or **Disable** sharding clusters.<br><br>For more details about sharding cluster enabled, refer to [Product architecture](https://docs.byteplus.com/en/docs/redis/product-component-architecture). |
   ||Connection mode |Select the connection mode for the instance, with the following options:<br><br><br>* **Proxy connection mode**: Higher throughput, supports advanced features like automatic read/write splitting and routing.<br><br>* **Direct connection mode**: Lower cost, lower latency, requires manual read/write deployment.<br><br><br>> **tip**<br><br><br>> Direct connection mode is only available when the database version is Redis 7.0 and shard cluster is not enabled. The direct connection feature without shard cluster enabled is currently an allowlist feature. To use it, [submit a ticket](https://console.byteplus.com/workorder/create/) to apply.<br> |
   ||Number of shard(s) |Select the number of shards for instance with sharding cluster enabled. Specify an integer between 2 and 256.<br><br>> **tip**<br><br><br>> This configuration is supported only when the **Sharding cluster** status is **Enable**.<br> |
   ||Extension module |Check the extension modules that need to be enabled. For more information about extension modules, refer to [Extension module](https://docs.byteplus.com/en/docs/redis/extended-data-structure).<br><br>> **tip**<br><br><br><br>* > Only instances with **Database version** **Redis 7.0** support enabling extension modules.<br><br><br>* > To use extension modules,[submit a support ticket](https://console.byteplus.com/workorder/create/) and contact technical support to apply.<br><br><br>* > Enabled extension modules do not support disabling.<br><br><br>* > You can also enable the extension module after creating the instance. For specific procedures, refer to [Enabling extension module](https://docs.byteplus.com/en/docs/redis/enable_extended_module).<br><br><br>* > After selecting the Valkey\-Search module, if you need to create a JSON\-formatted index, you must also select the Valkey\-JSON module.<br> |
   ||Node type |Select an appropriate node type for instances with the Valkey\-Search module enabled. Using the Valkey\-Search module consumes a large amount of CPU, so it is recommended to choose a node type with more cores.<br><br>> **tip**<br><br><br><br>* > This configuration is supported only when the Valkey\-Search module is enabled.<br><br><br>* > The node type is currently free of charge. We will inform you, on our website or via a product notification, before a service charge is officially introduced.<br> |
   ||Node(s) per shard |Choose the number of nodes in each shard, where:<br><br><br>* This configuration is supported only for the Redis instances whose **Instance type** is **Primary\-secondary**. A single node instance contains 1 node fixed in each shard and there is no need to set this parameter.<br><br>* Each shard of a primary\-secondary instance contains by default 2 nodes (1 primary node and 1 secondary node), and up to 6 nodes (1 primary node and 5 secondary nodes).<br><br><br>> **tip**<br><br><br>> For nodes with a memory capacity of 256 MiB, you can create up to four nodes per account in each region by default. To adjust the purchase quota of 256 MiB nodes (maximum is 10), refer to [Account quota](https://docs.byteplus.com/en/docs/redis/quota-and-limit#.6LSm5Y-36YWN6aKd).<br> |
   ||Node specification |Cache for Redis supports various node specifications with different performance parameters such as memory and bandwidth. You can choose the specification that suits your business needs. For more details, refer to [Instance specifications](https://docs.byteplus.com/en/docs/redis/product-specification). |
   ||Specifications preview |Review and confirm the performance details of the selected specification, including total memory capacity, number of shards, number of nodes per shard, bandwidth estimation and total connections. |
   |Availability zone and network configuration |Deployment plan |Complete the following actions based on the desired availability zone deployment scenario:<br><br><br>* Set up single availability zone deployment<br><br>   1. Select the Deployment plan as **Single availability zone deployment**.<br><br>   2. Select the required availability zone from the **Availability zone** drop\-down list.<br><br>* Set up multiple availability zone deployment<br><br>   1. Select the deployment plan as **Multiple availability zone deployment**.<br><br>   2. From the **Availability zone** drop\-down list, set the required availability zones for the primary node and each secondary node respectively.<br><br>   > **tip**<br>   <br><br>   * > If you select multiple identical availability zones, indicating that both the primary and secondary nodes are in the same availability zone, then during the instance creation, the system will automatically switch the deployment scheme to the **Single availability zone deployment** plan.<br>   <br><br>   * > Multiple availability zone deployment can improve availability, and at the same time, there may be a network delay of 2ms to 3ms.<br>   <br><br><br>For more details, refer to [Multi-availability-zone disaster recovery solution](https://docs.byteplus.com/en/docs/redis/multi-az-solution). |
   ||Virtual private cloud |Select the VPC where the instance is located from the drop\-down list.<br><br>We recommend that you connect Redis instances to ECS instances in the same VPC. Otherwise, they cannot achieve optimal communication performance. For more details, refer to [What is VPC](https://docs.byteplus.com/en/docs/vpc/What-is-VPC).<br><br>> **tip**<br><br><br><br>* > If you have not created any VPCs yet, please click **Create VPC** on the right side of the drop\-down list first. For detailed steps, refer to [Creating VPC](https://docs.byteplus.com/en/docs/vpc/Creating-a-VPC).<br><br><br>* > After the instance is successfully created, you can modify the VPC and subnet to which the instance belongs. For specific procedures, refer to [Modifying VPC or subnet](https://docs.byteplus.com/en/docs/redis/modify-vpc-or-subnet).<br><br><br>* > When you log on to the console with IAM user, you only see VPC information under the project that the IAM user belongs to. If you can't see the target VPC, confirm that IAM user is used and that IAM user has permissions on the target project resources. For more details, refer to [Using Redis with IAM user](https://docs.byteplus.com/en/docs/redis/using_redis_with_subusers).<br> |
   ||Subnet |Select an available subnet in the current VPC from the drop\-down list.<br><br>A subnet is an IP address block within a VPC. All cloud resources in the VPC must be deployed within a subnet. The subnet allocates private IP addresses to cloud resources.<br><br>> **tip**<br><br><br><br>* > If you have not created any subnet, click **Create subnet** on the right of the drop\-down list to create a subnet. For specific procedures, refer to [Creating subnet](https://docs.byteplus.com/en/docs/vpc/Creating-a-subnet).<br><br><br>* > Subnets possess availability zone properties. The drop\-down list only shows subnets that belong to the same availability zone as the instance in the current VPC.<br><br><br>* > You can specify a project when you create a VPC, but you cannot specify a project when you create a subnet, which is by default under the same project as the VPC to which it belongs. The project changes of the VPC and the subnet are independent, that is, modifying the project to which the VPC belongs will not modify the project of the subnet under the current VPC at the same time. For more details, refer to [Managing projects](https://docs.byteplus.com/en/docs/vpc/Managing-projects).<br><br><br>* > If you change the project to which the VPC belongs, you also need to change the project of the subnets under the VPC to ensure the consistency of the projects to which they belong. Otherwise, when IAM user with non\-global privileges creates a cloud resource (such as Cache for Redis), it will not be able to select a subnet or anomalies will be reported. For specific procedures for modifying projects, refer to [Editing project](https://docs.byteplus.com/en/docs/byteplus-platform/docs-editing-a-project).<br> |
   ||Port |You can customize the port number for private addresses. The default port is 6379. Value range: 1024 to 65535.<br><br>After creating the instance successfully, you can modify the port number of the private address. For specific procedures, refer to [Modifying port](https://docs.byteplus.com/en/docs/redis/modify-port). |
   |Account configuration |Set password |Set the `default` account password for instance. You can select **Set up now** or **Set up later** to set the account password for instance. Among which:<br><br><br>* If you select **Set up now**, you need to enter the instance password and confirm it. The password must meet the following conditions:<br><br>   * The length is 8~64 characters.<br><br>   * It contains at least two of the following: uppercase letters, lowercase letters, digits, and special characters.<br><br>   * It supports the following special characters:<br><br>      ```Plain Text```<br>```      ()`~!@#$%^&*-+=_\|{}[];<>,.?```<br>```      ```<br>      <br><br>* If you select **Set up later**, you can set the password for the root account after the instance is created. For more details, refer to [Resetting password](https://docs.byteplus.com/en/docs/redis/reset-password). You can also set a new account and password based on business requirements. For specific procedures, refer to [Creating and managing account](https://docs.byteplus.com/en/docs/redis/manage-account). |
   ||Password\-free access |Select whether to turn on the **Password\-free access** switch for the new instance.<br><br>After enabling password\-free access, when connecting to an instance through a private address or a direct connection address, there is no need to enter a password.<br><br>> **tip**<br><br><br>> After the instance is created successfully, you can also turn off the **Password\-free access** switch at any time. After turning it off, the client connections that originally used the password\-free access function will be disconnected. It is recommended that you first connect to the Redis instance using account password verification on the client before turning off the password\-free access function. For specific procedures, refer to [Password\-free access](https://docs.byteplus.com/en/docs/redis/pwd-free-access).<br> |
   |Advanced configuration |Allowlist |If a default allowlist already exists when a new instance is created, the default allowlist is automatically selected for the new instance.<br><br>If the default allowlist does not exist when you create a new instance, or you need to add the new instance to another allowlist, refer to the following steps to complete the operation:<br><br><br>1. Click on the allowlists input box.<br><br>2. In the control panel pop\-up, complete the following steps based on the selected association method.<br><br>   * If you select **New allowlist**, that is, create a new allowlist and automatically associate it to the current instance, you need to:<br><br>      1. Select the project to be added to the allowlist from the **Affiliated project** drop\-down list. By default, the **default** project will be added.<br><br>      2. Enter a new allowlist name, description (optional), and IP address. You can also choose to set the newly created allowlist as the default allowlist.<br><br>      3. Click **OK**.<br><br>   * If you select **Existing allowlist**, that is, associate an existing allowlist to the current instance, you need to:<br><br>      1. In the **Existing allowlist** list, select the allowlists to be associated.<br><br>         > **tip**<br>         <br><br>         > You can quickly filter out the target allowlist through the dropdown list of **Affiliated project** and the search box of **Allowlist name** above the allowlist list.<br>         <br><br>      2. Click **OK**.<br><br><br>> **tip**<br><br><br><br>* > For more information on configuring the name, description, and IP address when creating an allowlist, refer to [Creating allowlist](https://docs.byteplus.com/en/docs/redis/create-allowlist).<br><br><br>* > If you use the Redis cloud service through IAM user, you can only see the allowlist information under the projects that have been authorized for the current IAM user. For more details, refer to [Using Redis with IAM user](https://docs.byteplus.com/en/docs/redis/using_redis_with_subusers).<br> |
   ||Project |Set the project to which the instance belongs according to your business needs. Depending on the project you have selected in the top menu bar of the [Redis console](https://console.byteplus.com/db/redis), perform the corresponding actions:<br><br><br>* If you select **All resources**, the **default** (**Default project**) project will be added by default to the new instance. You can also select other items according to your business needs.<br><br>* If you select a specific project (e.g., one you created yourself) instead of **All resources**, then the new instance will join the project by default. You can also select other items according to your business needs.<br><br><br>> **tip**<br><br><br><br>* > After the instance is successfully created, you can also change the project to which the instance belongs. For example, move the instance from the current project to the target project, or move cloud resources that are not part of the project to the target project. For specific procedures, refer to [Editing project](https://docs.byteplus.com/en/docs/byteplus-platform/docs-editing-a-project).<br><br><br>* > A project is a virtual concept that includes a set of resources, users, and roles. A project allows for a unified view and management of a set of resources, and controls the permissions of users and roles within the project for those resources. For more details, refer to [Resource management](https://docs.byteplus.com/en/docs/byteplus-platform/docs-managing-projects).<br> |
   ||Tag |Click **Add tag** and enter the tag key and tag value to add a tag to the instance. For the tag key and tag value setting rules, refer to [Tag setting rules](https://docs.byteplus.com/en/docs/redis/associate-tag#.5qCH562-6K6-572u6KeE5YiZ).<br><br>A tag consists of a key\-value object that identifies cloud resources. It can help you classify cloud resources with the same characteristics (such as use, owner, or environment) for easy filtering and aggregation, so that you can easily manage cloud resources. For more details, refer to [Tag management](https://docs.byteplus.com/en/docs/redis/tag-management). |
   ||Deletion protection |You can choose to enable or disable **Deletion protection**.<br><br>Once deletion protection is enabled, the instance cannot be deleted. This is done to prevent accidental deletion. For more details, refer to [Instance deletion protection](https://docs.byteplus.com/en/docs/redis/deletion-protection). |
   ||Parameter configuration |Select a parameter template for the new instance from the drop\-down list.<br><br>A default system parameter template is created for each Cache for Redis **primary\-secondary** and **single\-node** instance of each database version respectively. The template contains all the parameters and default parameter values supported by that version. You can select and apply the corresponding parameter template from the drop\-down list according to the selected database version and instance type.<br><br>> **tip**<br><br><br><br>* > The drop\-down list will only display the parameter templates with the same database version as the current instance under the current account and region. For example, if you select the database version as Redis 6.0 when creating an instance, then the drop\-down list will only display the parameter template information of all database versions of Redis 6.0 under the current account and region. For more details, refer to [Parameter template management](https://docs.byteplus.com/en/docs/redis/parameter-template-overview).<br><br><br>* > If you haven't created any customized templates yet, you can click **View parameter templates** on the right side of the drop\-down list to enter the parameter template list page for creation. For specific procedures, refer to [Creating parameter template](https://docs.byteplus.com/en/docs/redis/create-parameter-template).<br> |
   |Billing information |Billing method |You can choose between **Pay\-as\-you\-go** or **Subscription**.<br><br>If you select the billing method as **Subscription**, you need to confirm **Purchase period**, and you can also select **Automatic renewal**, and the system will automatically renew before the instance expires. |

5. After selecting the number of instances to purchase at the lower\-left corner of the page, click **Confirm order** at the lower\-right corner.

   > **tip**

   > You need to purchase at least one instance at a time, and can purchase up to 20 instances.

6. Complete the subsequent steps according to the billing method you have selected.

   |Billing method |Procedure |
   |---|---|
   |Pay\-as\-you\-go |On the **Confirm order** page, confirm the order details, read and check the service terms, and then click **Buy now**. |
   |Subscription |1. On the **Confirm order** page, confirm the order details, read and check the service terms, and then click **Submit order**.<br><br>2. On the **Confirm order information** page, confirm the order details again and then click **Next step**.<br><br>3. On the **Submit payment information** page, confirm the payment details and select the payment method, and then click **Go to pay**.<br><br>   > **tip**<br>   <br><br>   * > If you have submitted an order to create an instance but have not completed the payment or the payment has failed, the instance will enter the **Waiting for payment** status. For more details, refer to [Instance status](https://docs.byteplus.com/en/docs/redis/instance-status).<br>   <br><br>   * > The successfully created instance order waiting for payment will be retained for 24 hours. It is recommended to complete the payment in a timely manner, otherwise the order will be automatically cancelled and you will need to recreate the instance order.<br>   <br><br>   * > You can choose any of the following methods to complete the payment:<br>   <br><br>      * > On the instance list page of the [Redis console](https://console.byteplus.com/db/redis), find the target instance in the **Waiting for payment** status. In the **Actions** column on the right side of the instance, click **Go to pay** to jump to the **Submit payment information** page of the instance, and you need to complete the payment according to the prompts on the page.<br>   <br><br>      * > Go to [Billing center \> Order](https://console.byteplus.com/finance/order/) page, find the corresponding **Waiting for payment** order and complete the payment according to the prompts on the page.<br>    |

   > Description

   * > It takes about several minutes to create an instance, and you can see the newly created instance in the instance list.

   * > You can go to **Tasks** to view the corresponding task of the newly created instance (the **Task name/ID** is `CreateDBInstance`), and understand the stage and progress details of the current task. For the specific procedures, refer to [Task management](https://docs.byteplus.com/en/docs/redis/task-management).
