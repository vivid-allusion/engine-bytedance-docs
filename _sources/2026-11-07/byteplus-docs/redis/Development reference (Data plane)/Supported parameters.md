Cache for Redis supports customizing the values of certain parameters. This topic introduces relevant information about the customizable parameters in Redis instances.

## Supported parameters table

> **tip**

> To ensure the stable operation of the instance, part of the parameters are active in Cache for Redis. The customizable parameters are listed in the table below. The parameters not in the table are non\-customizable currently.

|Parameters |Description |
|---|---|
|active\-defrag\-cycle\-max |Set the maximum CPU usage percentage when triggering memory defragmentation.<br><br>Unit: %. Value range: [1,40]. Default value: 25. |
|active\-defrag\-cycle\-min |Sets the minimum CPU usage threshold for triggering memory defragmentation.<br><br>Unit: %. Value range: [1,20]. Default value: 1. |
|active\-defrag\-ignore\-bytes |Sets the minimum fragmentation space occupancy that triggers memory defragmentation.<br><br>Unit: MB. Value range: [100,1024]. Default value: 100. |
|active\-defrag\-max\-scan\-fields |Set the maximum number of `set/hash/zset/list` domains for processing in Hash table scan.<br><br>Value range: [500,50000]. Default value: 1000. |
|active\-defrag\-threshold\-lower |Set the minimum usage ratio of fragmented space when triggering memory defragmentation.<br><br>Unit: %. Valid range: [5,50]. Default value: 10. |
|active\-defrag\-threshold\-upper |Set the maximum usage ratio of fragmented space when triggering memory defragmentation. Perform defragmentation thoroughly when the memory fragmentation exceeds this percentage.<br><br>Unit: %. Valid range: [50,150]. Default value: 100. |
|activedefrag |Enable or disable automatic memory defragmentation. Valid values:<br><br><br>* `yes`: Enable.<br><br>* `no` (Default): Disable. |
|client\-output\-buffer\-pubsub\-hard\-limit |Hard limit for output buffer of publish\-subscribe client.<br><br>When client output buffer memory usage reaches or exceeds this limit, the client connection will be terminated.<br><br>Unit: MB. Value range: [1,64]. Default value: 32. |
|client\-output\-buffer\-pubsub\-soft\-limit |Soft limit for output buffer of publish\-subscribe client.<br><br>When output buffer memory usage continuously exceeds the soft limit value for the duration specified by the `client-output-buffer-pubsub-soft-seconds` parameter, the client will be disconnected.<br><br>Unit: MB. Value range: [1,64]. Default value: 8. |
|client\-output\-buffer\-pubsub\-soft\-seconds |The duration during which the output buffer size continuously exceeds the value of `client-output-buffer-pubsub-soft-limit` before disconnecting a publish\-subscribe client.<br><br>Unit: seconds. Value range: [1,900]. Default value: 60. |
|disabled\-commands |Set disabled commands.<br><br>By default, the `flushall`, `flushdb`, and `keys` commands are disabled.<br><br>You can also disable certain commands that have long execution times, high complexity, or pose significant business risks based on your requirements. Different types of Redis instances support different commands. For more details about the commands supported by Cache for Redis, refer to [Supported commands](https://docs.byteplus.com/en/docs/redis/supported-command).<br><br>> **tip**<br><br><br>> You can enter any command in the `disabled-commands` parameter value, but note the following:<br><br><br><br>* > A single instance can support disabling up to 16 commands at most. Multiple commands are separated by English commas (,). For details on the quantity limit of disabled commands, refer to [Limit on features](https://docs.byteplus.com/en/docs/redis/quota-and-limit#.5Yqf6IO954m55oCn6ZmQ5Yi2).<br><br><br>* > The `AUTH` command is not supported to be disabled.<br><br><br>* > Commands are case\-insensitive, but spaces are not allowed in parameter values.<br><br><br>* > If a main command is entered, all its subcommands will be disabled.<br><br><br>   > For example, if you enter the `OBJECT` main command in the `disabled-commands` parameter, all subcommands under OBJECT (including `OBJECT ENCODING`, `OBJECT FREQ`, `OBJECT HELP`, `OBJECT IDLETIME`, and `OBJECT REFCOUNT`) will be disabled.<br>   <br><br>* > Any sub\-command cannot be disabled individually.<br><br><br>   > For example, regardless of the form in which you input the subcommand `OBJECT ENCODING` (including but not limited to `OBJECTENCODING`, `object\|encoding`, `object-encoding`, and so on) into the `disabled-commands` parameter value, this subcommand will not be disabled.<br>   <br><br>   > To disable this subcommand, you must enter its corresponding main command `OBJECT` in the `disabled-commands` parameter value.<br>   <br><br>* > When executing commands not supported by Cache for Redis (for example, `RESET`), you typically receive an error message as `unknown command`. However, if you add unsupported parameters to the `disabled-commands` parameter value, executing such commands will result in an error message as `no permission to execute the command`.<br> |
|hash\-max\-ziplist\-entries |Use ziplist encoding when a hash object meets all the following conditions:<br><br><br>* The numbers of bytes in the key and value strings of all key\-value objects saved in the Hash object are less than the value of `hash-max-ziplist-value`.<br><br>* The number of key\-value pairs stored in the hash object is less than the value of `hash-max-ziplist-entries`.<br><br><br>Value range: [1,10000]. Default value: 512. |
|hash\-max\-ziplist\-value |Use ziplist encoding when the Hash object meets the following two conditions simultaneously:<br><br><br>* The numbers of bytes in the key and value strings of all key\-value objects saved in the Hash object are less than the value of `hash-max-ziplist-value`.<br><br>* The number of key\-value pairs stored in the hash object is less than the value of `hash-max-ziplist-entries`.<br><br><br>Value range: [1,10000]. Default value: 64. |
|hz |Set the number of executions per second for Redis backend tasks, such as clearing expired keys.<br><br>Value range: [1,500]. Default value: 10.<br><br>> **tip**<br><br><br>> Higher value indicates that more CPU resources are consumed, excessive expired keys are cleared more frequently, and timeouts are more accurately processed by Redis. Recommended value should not exceed 100.<br> |
|lazyfree\-lazy\-eviction |Whether to enable lazyfree\-based eviction. Valid values:<br><br><br>* `yes` (Default): Enable.<br><br>* `no`: Disable. |
|lazyfree\-lazy\-expire |Whether to enable lazyfree\-based expired key deletion. Valid values:<br><br><br>* `yes` (Default): Enable.<br><br>* `no`: Disable. |
|lazyfree\-lazy\-server\-del |Whether to enable lazyfree\-based DEL command (that is, whether to enable asynchronous data deletion). Valid values:<br><br><br>* `yes` (Default): Enable.<br><br>* `no`: Disable. |
|lazyfree\-lazy\-user\-del |Whether to enable asynchronous memory release for user\-initiated delete operations. Valid values:<br><br><br>* `yes` (Default): Enable.<br><br>* `no`: Disable.<br><br><br>> **tip**<br><br><br>> This parameter is only available in Redis 7.0 and Redis 6.0 instances.<br> |
|list\-compress\-depth |The number of uncompressed nodes at both ends of the list. Valid values:<br><br><br>* `0` (Default): Neither end of the list is compressed.<br><br>* `1~65535`: Indicates 1~65535 nodes at each end of the list remain uncompressed, while middle nodes are compressed. |
|list\-max\-ziplist\-size |The strategy for setting ziplist length in each quicklist node, with valid range: [\-5,100000], where:<br><br><br>* Positive values indicate limiting ziplist length on each quicklist node by the number of data items. For example, when this parameter is set to 5, each quicklist node's ziplist can contain up to 5 data items.<br><br>* A negative value indicates limiting the ziplist length on each quicklist node by occupied bytes, where:<br><br>   * `-5`: The ziplist size on each quicklist node cannot exceed 64 KB.<br><br>   * `-4`: The ziplist size on each quicklist node cannot exceed 32 KB.<br><br>   * `-3`: The ziplist size on each quicklist node cannot exceed 16 KB.<br><br>   * `-2` (Default): The ziplist size on each quicklist node cannot exceed 8 KB.<br><br>   * `-1`: The ziplist size on each quicklist node cannot exceed 4 KB.<br><br><br>> **tip**<br><br><br>> Redis 7.0 replaces the `list-max-ziplist-size` parameter with `list-max-listpack-size`. When using Cache for Redis 7.0 instances, you only need to set the `list-max-ziplist-size` parameter, which is fully compatible with the `list-max-listpack-size` parameter (including value ranges and implementation effects). For more information about `list-max-listpack-size`, refer to [Configuration file](https://redis.io/docs/latest/operate/oss_and_stack/management/config-file/).<br> |
|lua\-time\-limit |The maximum time that a Lua script can block execution. When Lua execution exceeds this parameter limit, Redis will start accepting other commands but won't execute them, instead returning error message as `Busy`.<br><br>Unit: milliseconds. Value range: [0,5000] (0 means unlimited execution time). Default value: 5000. |
|maxmemory\-policy |Set the strategy for deleting content when Redis cache is full. Valid values:<br><br><br>* `volatile-lru` (Default): Select the least recently used keys from the keys that have been set to expire for eviction.<br><br>* `volatile-lfu`: Select the least frequently used keys from the keys that have been set to expire for eviction.<br><br>* `volatile-random`: Select some keys randomly from the keys that have been set to expire for eviction.<br><br>* `volatile-ttl`: Select the key with the shortest Time To Live (TTL) from the keys that have been set to expire for eviction.<br><br>* `allkeys-lru`: Preferentially evict the least recently used keys.<br><br>* `allkeys-lfu`: Preferentially evict the least recently used keys.<br><br>* `allkeys-random`: Select some keys randomly to evict.<br><br>* `noeviction`: Do not delete any keys, but respond with errors during write operations. |
|proxy\-slowlog\-slower\-than |The execution time threshold for requests to be recorded as slow logs on Proxy nodes. Requests with execution times exceeding this threshold will be recorded in the Proxy node's slow logs.<br><br>Unit: microseconds. Value range: [50000,2000000]. Default value: 500000. |
|read_request_distribution_strategy |Set the read/write splitting policy for the Redis instance shard. Valid values:<br><br><br>* `read_primary_node_only` (Default): Read requests are only sent to the primary node.<br><br>* `read_secondary_nodes_only`: Read requests are randomly distributed across all secondary nodes.<br><br>* `read_primary_node_and_secondary_nodes`: Read requests are randomly distributed across the primary node and all secondary nodes.<br><br><br>> **warning**<br><br><br><br>* > After modifying the `read_request_distribution_strategy` parameter, clients may briefly encounter request failure\-related error reports. It is recommended to perform parameter modification operations during off\-peak business hours and ensure that the client is configured with the correct retry mechanism.<br><br><br>* > Redis **single node instance** doesn't support read/write splitting and cannot set this parameter. For more details about single\-node instance types, refer to [Product architecture](https://docs.byteplus.com/en/docs/redis/product-component-architecture).<br> |
|repl\-backlog\-size |Set the capacity of replication backlog. Backlog is a buffer used to store primary\-secondary synchronization data. When a secondary node wants to reconnect, it usually does not want all data to be resynchronized, but only to transfer the data that was lost when the secondary node was disconnected. The larger this value, the longer a secondary node can remain disconnected.<br><br>Unit: MB. Value range: [64,256]. Default value: 128. |
|set\-max\-intset\-entries |When all elements in the set are integers and the length does not exceed the value of `set-max-intset-entries` (default value: 512), Redis will use Intset as the internal encoding. When exceeding 512, it will use set as the internal encoding.<br><br>Value range: [1,10000]. Default value: 512. |
|slowlog\-log\-slower\-than |The execution time threshold for requests to be recorded as slow logs on Server nodes. Requests exceeding this threshold will be logged as slow queries.<br><br>Unit: microseconds. Value range: [10000,10000000]. Default value: 20000. |
|slowlog\-max\-len |The maximum number of slow logs that can be saved. Slow log is a FIFO queue. When the queue size exceeds `slowlog-max-len`, the earliest logs are deleted and the latest logs are added to the slow log.<br><br>Value range: [1,1000]. Default value: 128. |
|proxy\-client\-idle\-timeout |Disconnect the client when its idle time reaches the specified value.<br><br>Unit: seconds. Value range: [0,4000000]. Default value: 0. |
|zset\-max\-ziplist\-entries |When elements in a sorted set meet both of the following conditions, ziplist encoding is used, which can effectively reduce memory usage.<br><br><br>* The number of elements in the sorted set is less than the `zset-max-ziplist-entries` configuration.<br><br>* The value of each element is less than `zset-max-ziplist-value`.<br><br><br>Value range: [1,10000]. Default value: 128. |
|zset\-max\-ziplist\-value |When a sorted set's elements meet both following conditions, ziplist encoding is used, which can effectively reduce memory usage.<br><br><br>* The number of elements in the sorted set is less than the `zset-max-ziplist-entries` configuration.<br><br>* The length of each element is less than `zset-max-ziplist-value`.<br><br><br>Value range: [1,10000]. Default value: 64. |
|notify\-keyspace\-events |Configure keyspace or key event notifications. The parameter value can be any combination of the following characters:<br><br><br>* `K`: Key space, publishing events with the prefix `__keyspace@<db>__`.<br><br>* `E`: Key event, publishing events with the prefix `__keyevent@<db>__`.<br><br>* `g`: General commands unrelated to type, such as DEL, EXPIRE, RENAME.<br><br>* `$`: String commands.<br><br>* `l`: List commands.<br><br>* `s`: Set commands.<br><br>* `h`: Hash commands.<br><br>* `z`: Sorted set commands.<br><br>* `x`: Expiration events, notifications are sent when expired keys are deleted.<br><br>* `e`: Eviction events, notifications are sent when keys are evicted due to `maxmemory` policy.<br><br>* `A`: Alias of parameter combination `g$lshzxe`.<br><br><br>For example, if you need to subscribe to notifications for expired events, first set the `notify-keyspace-events` parameter value to `Ex`. After configuration, execute the `PSUBSCRIBE __keyevent@0__*` command on the client to subscribe to key event notifications for DB0.<br><br>> **tip**<br><br><br><br>* > Different instance architecture types have varying support for this parameter, where:<br><br><br>   * > Redis instances with sharding cluster disabled supports setting this parameter. You can directly set it according to business needs.<br><br><br>   * > For Redis instances with sharding cluster enabled, instances created on or after May 9, 2024 support setting this parameter directly. While for instance created before May 9, 2024, you need to [submit a ticket](https://console.byteplus.com/workorder/create/) to contact technical support to upgrade the instance version if this parameter is required to set.<br><br><br>* > An empty string indicates turning off event notifications, and the default value is an empty string. After enabling event notifications, a certain amount of CPU capacity is used. For more details, refer to [Redis keyspace notifications](https://redis.io/docs/manual/keyspace-notifications/).<br><br><br>* > When customizing parameter values, the following specifications must be met simultaneously. Otherwise no events will be generated:<br><br><br>   * > Specify at least one of `K` or `E`.<br><br><br>   * > Specify at least one of `A`, `g`, `$`, `l`, `s`, `h`, `z`, `x`, or `e`.<br> |
|read_local_node_only |Enable or disable close\-by access for instance with multiple availability zones. Valid values:<br><br><br>* `yes` (Default): Enable.<br><br>* `No`: Disable.<br><br><br>> **warning**<br><br><br><br>* > After modifying the `read_local_node_only`, clients may briefly encounter request failure\-related error reports. It is recommended to perform parameter modification operations during off\-peak business hours and ensure that the client is configured with the correct retry mechanism.<br><br><br>* > Only instances deployed with multiple availability zones support setting this parameter. Single\-node instances have only one node and do not support deployment in multiple availability zones. Therefore, Redis **single\-node instances** do not support setting this parameter. For details about multi\-availability zone deployment solution, refer to [Deploying in multiple availability zones](https://docs.byteplus.com/en/docs/redis/deploy-multi-az).<br><br><br>* > If read/write splitting is disabled for instance (that is, the value of `read_request_distribution_strategy` is `read_primary_node_only`), close\-by access is invalid even if it is enabled. For more details about close\-by access, refer to [Setting read local node only](https://docs.byteplus.com/en/docs/redis/read-local-node-only).<br> |
|appendonly\-switch |Enable or disable AOF persistence for instance. Valid values:<br><br><br>* `on` (Default): Enable.<br><br>* `off`: Disable.<br><br><br>> **tip**<br><br><br><br>* > For instances created before July 10, 2024 that need to use this parameter, [submit a ticket](https://console.byteplus.com/workorder/create/) to contact technical support for instance version upgrade.<br><br><br>* > Only **primary\-secondary instances** support this parameter. Single node instances do not support persistence capability and cannot set this parameter. For more details about instance types, refer to [Product architecture](https://docs.byteplus.com/en/docs/redis/product-component-architecture).<br><br><br>* > There are constraints between AOF persistence and [read/write splitting](https://docs.byteplus.com/en/docs/redis/set-read-write-splitting) features:<br><br><br>   * > When parameter `read_request_distribution_strategy` is set to `read_secondary_nodes_only` or `read_primary_node_and_secondary_nodes`, parameter `appendonly-switch` cannot be set to `off`.<br><br><br>   * > When parameter `appendonly-switch` is set to `off`, parameter `read_request_distribution_strategy` cannot be set to `read_secondary_nodes_only` or `read_primary_node_and_secondary_nodes`.<br><br><br>* > There are constraints between AOF persistence and [Data flashback](https://docs.byteplus.com/en/docs/redis/set-data-flashback) features:<br><br><br>   * > When the `appendonly-switch` parameter is set to `off`, the data flashback feature cannot be enabled.<br><br><br>   * > When the data flashback feature is enabled, the `appendonly-switch` parameter cannot be adjusted to `off`.<br> |
|TransactionSplit |When using **proxy mode** (i.e., using public/private network addresses) to connect to an instance and execute transaction commands, whether to support splitting the keys operated by transaction commands across different slots. Valid values:<br><br><br>* `false` (Default): Splitting is not supported, that is, all the keys must be in the same slot.<br><br>* `true`: Support splitting, that is, the keys can be in different slots.<br><br><br>> **tip**<br><br><br><br>* > This parameter can only be set for instance with sharding clusters enabled. Instances without sharding clusters only support one slot and cannot be split. For more details about instance architecture, refer to [Product architecture](https://docs.byteplus.com/en/docs/redis/product-component-architecture).<br><br><br>* > This parameter only takes effect on Redis instance with sharding cluster enabled whose proxy version is equal to or less than `proxy_version_1.506.0`. Redis instance with sharding cluster enabled whose proxy version is greater than `proxy_version_1.506.0`, keys operated by transaction commands can be in different slots by default regardless of this parameter's value. For more details about transaction command limits for Redis instances with sharding clusters enabled in proxy mode, refer to [Transaction command limits](https://docs.byteplus.com/en/docs/redis/command-limit#.5LqL5Yqh5ZG95Luk6ZmQ5Yi2).<br><br><br>* > You can build keys with the same slot through hash tag. For how to use hash tags, refer to [Keys hash tags](https://redis.io/docs/reference/cluster-spec/#hash-tags).<br> |
|sentinel\-passwordless\-auth<br><br> |After enabling the Sentinel mode, whether to allow passwordless execution of Sentinel\-related commands. Valid values:<br><br><br>* `yes`: Allowed.<br><br>* `no` (Default): Not allowed.<br><br><br>> **tip**<br><br><br><br>* > After setting it to `yes`, you can execute the following commands **without password** on any connection:<br><br><br>   * > Execute Sentinel\-related commands, including SENTINEL SENTINELS and SENTINEL GET\-MASTER\-ADDR\-BY\-NAME subcommands. For more details about sentinel\-related commands, refer to [Sentinel](https://docs.byteplus.com/en/docs/redis/Sentinel).<br><br><br>   * > Execute the PING command.<br><br><br>   * > Execute the HELLO command without the auth parameter.<br><br><br>   * > Use the SENTINELcommand to listen to the `+switch-master` channel.<br><br><br>* > For instance with proxy minor version equal to or greater than `1.507.1`, the new parameter value takes effect immediately after modifying `sentinel-passwordless-auth` to `yes.` For instance with versions less than `1.507.1`, the new parameter value takes effect only after [submit a ticket](https://console.byteplus.com/workorder/create/) to contact technical support for version upgrade. You can view the instance's database version and minor version information under the **Summary** tab. For specific procedures, refer to [Viewing instance information](https://docs.byteplus.com/en/docs/redis/view-instance).<br><br><br>* > For details about the procedure of password\-free command execution in Sentinel mode, refer to [Configuring password\-free command execution in Sentinel mode](https://docs.byteplus.com/en/docs/redis/password-free_execution_in_sentinel_mode).<br> |
|extra\-passwordless\-auth\-command |Sets the additional command list allowed for **password\-free execution** in Sentinel mode. Commands must be entered in lowercase letters, with multiple commands separated by English commas (,).<br><br>> **tip**<br><br><br><br>* > Only when the `sentinel-passwordless-auth` parameter is set to `yes` and the parameter value takes effect, the commands added in the `extra-passwordless-auth-command` parameter are allowed for password\-free execution.<br><br><br>* > After configuration, you can **execute commands without password** on any connection for added commands. Proceed with caution. For details about the procedure of password\-free command execution in Sentinel mode, refer to [Configuring password\-free command execution in Sentinel mode](https://docs.byteplus.com/en/docs/redis/password-free_execution_in_sentinel_mode?type=preview).<br> |
