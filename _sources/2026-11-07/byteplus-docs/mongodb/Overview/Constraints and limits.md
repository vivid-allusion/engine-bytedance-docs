This topic summarizes account quotas, features, and quantitative constraints and limits for Document Database for MongoDB.

## Account quota

The BytePlus platform sets default quotas for each service in every root account. The service\-related quota limits for Document Database for MongoDB are listed in the table below.


|Quota item |Description |
|---|---|
|Number of instances |Each root account of BytePlus can purchase a maximum of 30 instances by default in each region.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">If you need to adjust the quota to purchase more instances, please go to the <strong>Quota center</strong> to submit a <a href="https://console.byteplus.com/quota/productList/coParameterList?ProviderCode=MongoDB_ToB">Quota application</a>.</div><br> |

|Modifying configuration |* When modifying storage space (including decreasing and increasing), the modified storage space capacity must be greater than or equal to 1.2 times the used space to ensure the instance operates normally.<br><br>* For replica set instances, changing the number of read\-only nodes is mutually exclusive with other configuration change operations of the instance. ## Quantity limits


|Configuration item |Quantity limits |
|---|---|
|Recommended number of connections |The recommended number of connections supported varies depending on the MongoDB instance node specification. For details on the recommended number of connections for each specification node, refer to [Product specifications](https://docs.byteplus.com/en/docs/mongodb/product-specification).<br><br>When the number of connections reaches the upper limit, the system will reject new connections. If you need to use more connections, you can modify the maximum number of concurrent connections per node of the instance through the `net.maxIncomingConnections` parameter. For more information about this parameter, refer to [Supported parameter](https://docs.byteplus.com/en/docs/mongodb/supported-parameter). You can also obtain a larger number of connections by upgrading the node specifications. |
|Number of connection addresses |The number of supported addresses varies depending on the MongoDB instance type or connection type. Among them:<br><br><br>* Replica set instance<br><br>   It provides one private IP address by default and allows requesting one public IP address.<br><br>* Sharding cluster instance<br><br>   * Mongos: By default, one private IP address is provided for all Mongos nodes, and a separate public IP address can also be requested for each Mongos node.<br><br>   * Shard: Supports requesting one private IP address and one public IP address for each Shard.<br><br>   * ConfigServer: Only supports requesting one private IP address and one public IP address for ConfigServer nodes.<br><br><br>For more details about connection addresses, refer to [Connection address type](https://docs.byteplus.com/en/docs/mongodb/addresses-introduction). |
|Number of read\-only nodes |Up to 5 read\-only nodes are supported by each replica set instance or each shard in each sharding cluster instance. For more details on read\-only node limits, refer to [MongoDB read-only nodes](https://docs.byteplus.com/en/docs/mongodb/managing_read_only_nodes#.5L2_55So6ZmQ5Yi2). |
|IP allowlist |* Each root account of BytePlus can create up to 500 IP allowlists per region.<br><br>* Each BytePlus account can allow up to one default allowlist per region. A newly created default allowlist will automatically override the existing default allowlist. That is, the existing default allowlist will automatically become a non\-default allowlist.<br><br>* Each allowlist can contain up to 1000 IP addresses or IP address segments in CIDR format.<br><br>* Each allowlist can be associated with up to 500 instances.<br><br>* Each allowlist can be associated with up to 200 instances in batches at a time.<br><br>* Each instance can be associated with up to 100 allowlists, but the total number of IP addresses or IP address segments in CIDR format within all allowlists associated with an instance cannot exceed 1000.<br><br>* Each instance can be associated with a maximum of 100 allowlists in batches each time.<br><br>* If no allowlist is associated with an instance, its access is denied to all addresses. |
|Number of tags |The total number of tags is unlimited, but each MongoDB instance can associate up to 50 tags. |
|Number of batch\-recoverable databases, tables, or instances |* A maximum of 50 instances can be selected for batch rollback at one time.<br><br>* A single instance can select a maximum of 1,000 tables for rollback at a time. |
