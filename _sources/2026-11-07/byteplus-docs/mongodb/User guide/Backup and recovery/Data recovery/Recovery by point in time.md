Document Database for MongoDB supports restoring instances to a specified point in time through backup files. You can restore instance data to a new instance or the source instance according to service requirements.

<span id=".5YmN5o-Q5p2h5Lu2"></span>
## Prerequisite

The original instance must be in **Running** or **Restoring** status. For more details, refer to [Instance status](https://docs.byteplus.com/en/docs/mongodb/instance-status).

<span id=".5L2_55So6ZmQ5Yi2"></span>
## Limits


* The current point\-in\-time restore feature only supports restoring instance data to a new instance, not to the original instance.

* The backup retention period will affect the available time range for point\-in\-time restoration. For example, if you set the retention period to 10 days, the available time range for restoring instance to a specific point in time will be any point within the past 10 days. For information on how to set the backup retention period, refer to [Automatic Backup](https://docs.byteplus.com/en/docs/mongodb/automatic-backup).

* Document Database for MongoDB does not support restoring time series collections. Therefore, if there is time series data in the original instance, data inconsistency may occur after restoring to a new instance.


<span id=".5pON5L2c5q2l6aqk"></span>
## Procedure


1. Log in to the [MongoDB console](https://console.byteplus.com/db/mongodb).

2. In the upper\-left corner of the top menu bar, select the project and region for instance.

3. Select either **Replica set instances** or **Sharding instances** in the left navigation bar depending on the instance type.

4. On the target instance type list page, click the target instance name.

5. On the instance details page, click the **Backups** tab.

6. Under the **Full backup** sub\-tab, click **Restore by point in time** above the backup file list.

7. In the pop\-up dialog box, select the time point for restoration, and click **OK**.
