Call the `DescribeLiveRecordData` API to query the recording usage, including the maximum number of concurrent recordings, of specified live streaming domains within the specified time range.

<span id="requirements"></span>
## Requirements


* Billing: For recording pricing, please refer to [Recording Billing](https://docs.byteplus.com/en/docs/byteplus-media-live/docs-transcoding_2).

* Limitations: Supports querying recording usage data generated by deleted domains.

* Rate limit: 30 queries per second per account.

* Data latency: 7 hours.


<span id="http-request"></span>
## HTTP request


* Method: POST

* Endpoint: https://open.byteplusapi.com/?Action=DescribeLiveRecordData&Version=2023\-01\-01


<span id="request-parameters"></span>

<span id="body-parameters"></span>
### Body parameters


|Parameter |Data Type |Required |Sample Value |Description |
|---|---|---|---|---|
|DomainList |Array of String |No |`["push.example.com"]` |List of domains. By default, it is empty, indicating that bandwidth usage data for all domains under your BytePlus MediaLive will be queried. You can call the [ListDomainDetail](https://docs.byteplus.com/en/docs/byteplus-media-live/docs-listdomaindetail-2023) API or go to the [Domains](https://console.byteplus.com/live/main/domain/list) page in the BytePlus MediaLive console to obtain the domains to be queried. |
|StartTime |String |Yes |`2021-04-13T00:00:00Z` |The start time of your query's range in RFC 3339 format with second precision. |
|EndTime |String |Yes |`2021-04-14T00:00:00Z` |The end time of your query's range in RFC 3339 format with second precision. |
|Aggregation |Integer |No |`300` |The granularity of data aggregation, measured in seconds, with the following supported options:<br><br><br>* `300` (default): 5 minutes. When aggregated in 5\-minute intervals, the maximum time span for a single query is 31 days, and for historical queries, the maximum time range is 366 days.<br><br>* `3600`: 1 hour. When aggregated in 1\-hour intervals, the maximum time span for a single query is 93 days, and for historical queries, the maximum time range is 366 days.<br><br>* `86400`: 1 day. When aggregated in 1\-day intervals, the maximum time span for a single query is 93 days, and for historical queries, the maximum time range is 366 days. |
|DetailField |Array of String |No |`["Domain"]` |The dimension for data segmentation is empty by default, indicating no data segmentation. Currently, only the `Domain` dimension is supported for data segmentation.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Data segmentation by the <code>Domain</code> dimension will occur only if the <code>DetailField</code> parameter is set to <code>Domain</code> and the <code>DomainList</code> parameter contains multiple values.</div><br> |
|App |String |No |`live` |The AppName field in the live stream URL. It can include uppercase letters (A\-Z), lowercase letters (a\-z), numbers (0\-9), underscores (_), hyphens (\-), and periods (.), with a length ranging from 1 to 30 characters.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">When querying stream granularity data, both the <code>App</code> and <code>Stream</code> parameters are required.</div><br> |
|Stream |String |No |`example_stream` |The StreamName field in the live stream URL. It can include uppercase and lowercase letters (A\-Z, a\-z), numbers (0\-9), underscores (_), hyphens (\-), and periods (.), with a length ranging from 1 to 100 characters.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">When querying stream granularity data, both the <code>App</code> and <code>Stream</code> parameters must be provided.</div><br> |


<span id="response-parameters"></span>
## Response parameters

For unique API\-specific response parameters, see the table below. For more details, refer to the [Request response](https://docs.byteplus.com/en/docs/byteplus-platform/reference-request-response) section.


|Parameter |Data Type |Sample Value |Description |
|---|---|---|---|
|DomainList |Array of String |`["push.example.com"]` |List of domain names. |
|StartTime |String |`2021-04-13T00:00:00Z` |The start time of your query's range in RFC 3339 format with second precision. |
|EndTime |String |`2021-04-14T00:00:00Z` |The end time of your query's range in RFC 3339 format with second precision. |
|Aggregation |Integer |`300` |Data granularity, measured in seconds. |
|DetailField |Array of String |`["Domain"]` |The data breakdown dimension is currently limited to `Domain`, representing domain names. |
|RecordPeak |Integer |`2` |The maximum number of concurrent recording streams allowed under the current query conditions. |
|RecordDataList |Array of [RecordDataList](https://docs.byteplus.com/en/docs/24/25093#recorddatalist) |`-` |Data at all time granularity levels. |
|RecordDetailDataList |Array of [RecordDetailDataList](https://docs.byteplus.com/en/docs/24/25093#recorddetaildatalist) |`-` |Data that has been categorized based on specific dimensions. |
|App |String |`live` |The AppName field of stream when querying stream granularity data. |
|Stream |String |`example_stream` |The StreamName field of stream when querying stream granularity data. |


<span id="recorddatalist"></span>
### RecordDataList


|Parameter |Data Type |Sample Value |Description |
|---|---|---|---|
|TimeStamp |String |`2022-04-13T00:00:00Z` |The start time of each time granularity when data is aggregated by time granularity, formatted in RFC3339 UTC time with second precision. |
|Value |Integer |`1` |The maximum number of concurrent recording streams within the current data aggregation time granularity. |


<span id="recorddetaildatalist"></span>
### RecordDetailDataList


|Parameter |Data Type |Sample Value |Description |
|---|---|---|---|
|Domain |String |`push.example.com` |Domain name information when data is split by the domain dimension. |
|RecordPeak |Integer |`2` |The maximum number of concurrent recording streams for the current dimension after data is split by dimensions. |
|RecordDataList |Array of [RecordDataList](https://docs.byteplus.com/en/docs/24/25093#recorddatalist) |`-` |All data at every granularity level under the current dimension after data is split by dimensions. |
