分段域名適用於透過 `HLS`、`DASH`、`LL-HLS` 和 `LL-DASH` 等協定進行直播播放。

> **說明**

> 如果您在控制台中找不到此功能，請聯絡[技術支援](https://console.byteplus.com/workorder/create?step=2&SubProductID=P00000980)啟用。

## 如何選擇用於拉流的域名

您可以依業務需求，選擇新增分段域名或串流域名。

![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/eb67beb3049c488e8e834218551b38e7~tplv-goo7wpa0wc-topic.webp)

* 如果您需要 `HLS`、`DASH`、`LL-HLS` 和 `LL-DASH` 等協定的拉流位址來觀看直播，請選擇分段域名。

* 如果您需要 `RTM`、`FLV` 和 `RTMP` 等協定的拉流位址來觀看直播，請選擇串流域名。

* 如果需要兩種類型的協定，請分別新增分段域名和串流域名。

> **說明**

* > 如果您已透過串流域名使用 `HLS`、`DASH`、`LL-HLS` 和 `LL-DASH` 等協定的拉流位址，可以繼續使用現有位址。不過，若要新增這些協定的拉流位址，請使用分段域名。

* > 若要使用 HLS\-ABR 或 DASH\-ABR，請使用分段域名。若要使用 RTM\-ABR，請使用串流域名。

## 分段域名與串流域名的功能差異

分段域名與串流域名支援的功能不同。即使支援相同功能，具體設定方法也可能不同。詳情請參閱對應文件。

|功能 |說明 |分段域名 |串流域名 |
|---|---|---|---|
|憑證 |新增 SSL 憑證以啟用 HTTPS 加密。 |支援 |支援 |
|HTTP/2 協定 |使用 HTTPS 拉流位址時，拉流請求會透過 HTTP/2 傳送。 |支援 |支援 |
|QUIC 協定 |使用 HTTPS 拉流位址時，拉流請求會透過 QUIC 傳送。 |支援 |不支援 |
|強制重新導向 |強制 HTTP 拉流請求重新導向至 HTTPS，或強制 HTTPS 拉流請求重新導向至 HTTP。 |支援 |不支援 |
|OCSP 裝訂 |直接為 HTTPS 拉流請求傳回憑證狀態資訊。 |支援 |不支援 |
|HSTS |指示瀏覽器優先對後續拉流請求使用 HTTPS。 |支援 |不支援 |
|TLS 版本範圍 |指定建立 HTTPS 連線時可使用的 TLS 版本範圍。 |支援 |支援 |
|IPv6 |使用 IPv6 位址傳送拉流請求。 |支援 |不支援 |
|停用 HTTP 方法 |停用使用特定 HTTP 方法的拉流請求。 |支援 |不支援 |
|WebSocket |在瀏覽器與伺服器之間建立 WebSocket 連線，以支援雙向通訊。 |支援 |不支援 |
|Proxy protocol |在代理轉送情境中傳輸觀看者真實 IP 位址等資訊。 |支援 |不支援 |
|URL 驗證 |設定 URL 簽署規則，以允許或拒絕拉流請求。 |支援 |支援 |
|地理限制 |根據觀看者公網 IP 位址的地理位置，允許或拒絕拉流請求。 |支援 |支援 |
|IP 限制 |根據 IP 白名單或黑名單，允許或拒絕拉流請求。 |支援 |支援 |
|UA 限制 |根據 UA 白名單或黑名單，允許或拒絕拉流請求。 |支援 |支援 |
|Referer |根據 Referer 白名單或黑名單，允許或拒絕拉流請求。 |支援 |支援 |
|Origin 限制 |根據 Origin 白名單或黑名單，允許或拒絕拉流請求。 |支援 |不支援 |
|遠端驗證 |將拉流請求轉送至您的驗證伺服器進行驗證。 |支援 |支援 |
|HTTP 回應標頭 |自訂傳回的 HTTP 回應標頭。 |支援 |支援 |
|自訂錯誤頁面 |自訂發生存取錯誤時傳回的錯誤頁面。 |支援 |不支援 |
|URL 正規化 |依規則正規化拉流請求 URL。 |支援 |不支援 |
|速率限制 |限制拉流請求的頻率。 |不支援 |支援 |
|協定限制 |依協定停用拉流請求。 |不支援 |支援 |
|快取規則 |設定節點快取規則。 |支援 |不支援 |
|快取鍵 |設定查詢參數是否納入快取鍵。 |支援 |不支援 |
|狀態碼快取規則 |設定錯誤狀態碼快取規則。 |支援 |不支援 |
|瀏覽器快取規則 |設定瀏覽器快取規則。 |支援 |不支援 |
|源站清單 |設定主要和備用源站伺服器。 |支援 |不支援 |
|回源協定 |設定對源站發出請求時使用的協定。 |支援 |不支援 |
|IPv6 源站 |設定對以域名設定的源站發出請求時，優先使用 IPv4 或 IPv6 位址。 |支援 |不支援 |
|回源主機 |設定對源站發出請求時的 Host 標頭值。 |支援 |不支援 |
|回源逾時 |設定與源站建立連線，以及等待源站內容的逾時時間。 |支援 |不支援 |
|HTTP 請求標頭 |設定對源站發出請求時的 HTTP 請求標頭。 |支援 |支援 |
|回源 Range 請求 |當源站伺服器支援 Range 時，從源站分段擷取內容。 |支援 |不支援 |
|跟隨源站重新導向 |設定源站伺服器傳回 301 或 302 狀態碼時是否跟隨重新導向。 |支援 |不支援 |
|回源參數 |設定對源站發出請求時包含的參數。 |支援 |不支援 |
|源站 SNI |設定對源站發出 HTTPS 請求時使用的 SNI 域名。 |支援 |不支援 |
|回源位址重寫 |依規則重寫對源站發出請求的請求路徑。 |不支援 |支援 |
|GOP 快取 |設定圖片群組 (GOP) 快取時長，以平衡延遲與網路波動韌性。 |不支援 |支援 |
|頻寬限制 |設定拉流的頻寬限制。 |不支援 |支援 |
|HLS/LL\-HLS |設定 HLS 和 LL\-HLS 串流的分段和低延遲設定。 |支援 |不支援 |
|DASH/LL\-DASH |設定 DASH 和 LL\-DASH 串流的分段和低延遲設定。 |支援 |不支援 |
|位址產生器 |為對應協定產生拉流位址。 |僅支援產生 HLS、DASH、LL\-HLS 和 LL\-DASH 拉流位址。 |僅支援產生 RTMP、FLV 和 RTM 拉流位址。 |

> **說明**

> 分段域名與串流域名使用不同的源站設定方法。預設情況下，兩者都可直接用於直播播放。

> 若要使用自訂源站設定：

* > 對於分段域名，源站設定是以域名為基礎。

* > 對於串流域名，源站設定是在串流層級執行，包括依特定串流（`AppName` + `StreamName`）和依串流協定（`AppName` + 串流協定）。同時支援隨選和排程模式。
