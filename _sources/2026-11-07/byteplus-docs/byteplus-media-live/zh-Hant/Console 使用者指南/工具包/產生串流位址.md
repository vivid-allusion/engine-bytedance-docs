請在 MediaLive 控制台中使用位址產生器工具，為您的直播串流產生推流與拉流位址。

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">如需瞭解更多關於位址組成規則及產生方式的資訊，請參閱<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-generating-live-stream-addresses-zh-TW">產生直播串流地址</a>。</div>


<span id="Prerequisites"></span>
## 先決條件


* 您已新增推流與拉流的網域名稱，並完成 CNAME 設定。如需更多資訊，請參閱 [新增網域名稱](https://docs.byteplus.com/docs/byteplus-media-live/docs-domain-zh-TW) 和 [新增 CNAME 記錄](https://docs.byteplus.com/docs/byteplus-media-live/docs-adding-a-cname-record-zh-TW)。

* 如需下列功能，請啟用 HTTPS：

   * 使用 BytePlus MediaLive 控制台提供的線上推流工具。

   * 使用 BytePlus MediaLive 控制台提供的線上播放工具。

   * 使用 HTTPS 推流或拉流位址。

   * 在瀏覽器環境中推送或播放 RTM 串流。

   如需更多資訊，請參閱 [HTTPS 設定](https://docs.byteplus.com/docs/byteplus-media-live/docs-https-zh-TW)。

* 若要對推流或拉流位址進行 URL 驗證，您必須啟用 URL 驗證功能。如需更多資訊，請參閱 [設定 URL 驗證](https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-TW)。

* 若要產生轉碼串流的拉流位址，您必須完成轉碼設定。如需更多資訊，請參閱 [管理轉碼配置](https://docs.byteplus.com/docs/byteplus-media-live/docs-configuring-screenshot-capturing-zh-TW)。

* 若要產生特定協議 ABR 串流的拉流位址，您必須完成 ABR 設定並選擇相應的協議類型。如需更多資訊，請參閱 [管理自適應位元率設定](https://docs.byteplus.com/docs/byteplus-media-live/standbystream-zh-TW)。

* 若要產生加密串流的拉流位址，您必須完成加密設定。如需更多資訊，請參閱 [管理加密設定](https://docs.byteplus.com/docs/byteplus-media-live/docs-manage-subtitle-configuration-zh-TW)。


<span id="Procedure"></span>
## 操作流程


1. 登入 [BytePlus MediaLive 控制台](https://console.byteplus.com/live)。

2. 在左側導覽窗格中，選擇 **工具箱** \> **位址產生器**。

3. 選擇 **位址類型** 與 **網域名稱**，並輸入自訂的 `AppName`、`StreamName` 與有效期限。

   <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/305f90015f364f2e8ce96f4f455612de~tplv-goo7wpa0wc-image.image) </span>

   
   |參數 |說明 |
   |---|---|
   |位址類型 |選擇要產生的位址類型。<br><br><br>* **推流位址**：使用此位址將串流從主機推送至 MediaLive。<br><br>* **拉流位址**：使用此位址將串流從 MediaLive 拉取給觀眾。 |
   |網域名稱 |根據位址類型選擇推流或拉流所用的網域名稱。 |
   |AppName |產生位址的`AppName`，可包含字母（A\-Z, a\-z）、數字（0\-9）、底線（_）、連字號（\-）及句點（.），長度為 1 至 30 個字元。預設值為`live`。<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">拉取指定串流時，推流與拉流位址的<code>AppName</code>必須相同。</div><br> |
   |StreamName |產生位址的`StreamName`，可包含字母（A\-Z, a\-z）、數字（0\-9）、底線（_）及連字號（\-），長度為 1 至 100 個字元。<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">拉取指定串流時，推流與拉流位址的<code>StreamName</code>必須相同。</div><br> |
   |到期時間 |選擇位址的到期時間。<br><br>到期後，該位址將無法再用於發起新的推流或拉流請求。到期前已發起的請求不受影響。<br><br><div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div><br><br><br><div data-tips="true" data-tips-type="warning">僅當所選網域已啟用 URL 驗證時，才能設定到期時間。如需啟用 URL 驗證，請參閱<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-TW">設定 URL 驗證</a>。</div><br> |
   

4. 點擊 **產生推流位址** 或 **產生拉流位址**，即可在 **結果**區取得推流或拉流位址。

   * **推流位址**： 支援產生含驗證資訊的推流位址。位址產生器支援以下推流協議：RTMP、TS over SRT、RTMP over SRT 及 RTM。

      <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="2">tip      </div>
      

      * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="2">若使用 OBS（Open Broadcaster Software）通過 RTMP 推流，可從產生結果中獲取<strong>OBS 推流位址</strong>和<strong>OBS 串流金鑰</strong>，並分別填入 OBS 的<strong>Server</strong>和<strong>Stream Key</strong>欄位。      </div>
      

      * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="2">如需包含驗證資訊，必須先為推流網域名稱啟用 URL 驗證。如需更多資訊，請參閱<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-TW">設定 URL 驗證</a>。      </div>
      

      <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/c168f4ac83b440cd85c8caffef3d8286~tplv-goo7wpa0wc-image.image) </span>

* **拉流位址**：支援產生含驗證資訊的原始串流、轉碼串流及 ABR 串流拉流位址。位址產生器支援以下拉流協議：RTMP、FLV、HLS（M3U8）、RTM 及 DASH。

   <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/4ba7e572d98e4d6f83fb4492893052aa~tplv-goo7wpa0wc-image.image) </span>

   * 在 **拉流 URL** 標籤頁中，您可以找到兩種 RTM 拉流位址。

      * **RTM Web SDK 播放位址**：使用此位址可搭配 BytePlus MediaLive Player SDK for Web 播放。此位址會觸發自動轉碼，流程如下：

         * 系統會自動偵測串流是否包含 B\-frame。

            * 若包含 B\-frame：系統會轉碼移除 B\-frame，並收取標準轉碼費用。

            * 若不包含 B\-frame：原始串流的影片會直接複製，不收取影片轉碼費用。

         * 系統會自動偵測音訊編碼格式是否為 AAC 或 Opus。

            * 若音訊編碼為 AAC：音訊會轉換為 Opus。若未涉及影片轉碼，則僅收取音訊轉碼費用。如需更多資訊，請參閱 [僅音訊轉碼](/docs/byteplus\-media\-live/docs\-transcoding\-zh\-TW#Audio transcoding)。

            * 若音訊編碼為 Opus：原始串流的音訊會直接複製，不收取音訊轉碼費用。

      * **RTM 位址**：使用此位址可搭配客戶端 SDK（BytePlus MediaLive Player SDK for iOS、Android、React Native、Flutter）及其他播放器播放。

   * 在 **轉碼串流** 標籤頁中，您可以選擇轉碼後綴以取得不同的轉碼串流位址。您也可以找到兩種 RTM 拉流位址。

      * **RTM Web SDK 播放地址**：使用此地址可搭配 BytePlus MediaLive Player SDK for Web 進行播放。此 RTM 拉流地址保留原始轉碼配置，並新增以下處理：

         * 系統會自動檢測該流是否包含 B 幀。

            * 若存在 B 幀：系統會對該流進行轉碼以移除 B 幀，其餘設置遵循原始轉碼配置，並按原始轉碼配置收取轉碼費用。

            * 若不存在 B 幀：系統會依原始轉碼配置對該流進行轉碼，並按原始轉碼配置收取轉碼費用。

         * 系統會自動檢測音訊編碼格式是否為 AAC 或 Opus。

            * 若音訊編碼格式為 AAC：音訊將轉換為 Opus，其餘設置遵循原始轉碼配置，並按原始轉碼配置收取轉碼費用。

            * 若音訊編碼格式為 Opus：音訊將直接複製，不進行音訊轉碼，其餘設置遵循原始轉碼配置，並按原始轉碼配置收取轉碼費用。

      * **RTM 地址**：使用此地址可搭配用戶端 SDK（BytePlus MediaLive Player SDK for iOS、Android、React Native 及 Flutter）及其他播放器進行播放。

   * 在 **自適應碼率** 標籤頁中，若於 ABR 配置中啟用 RTM\-ABR，請選擇啟動畫質等級（後綴）以獲取對應的 RTM\-ABR 地址。您也可以找到兩種類型的 RTM\-ABR 拉流地址。

      * **RTM Web SDK 播放地址**：使用此地址可搭配 BytePlus MediaLive Player SDK for Web 進行播放。此 RTM\-ABR 拉流地址保留原始 ABR 配置，並新增以下處理：

         * 系統會自動檢測副流是否包含 B 幀。

            * 若存在 B 幀：系統會對副流進行轉碼以移除 B 幀，其餘設置遵循原始 ABR 配置，並按原始 ABR 配置收取轉碼費用。

            * 若不存在 B 幀：系統會依原始 ABR 配置對副流進行轉碼，並按原始 ABR 配置收取轉碼費用。

         * 系統會自動檢測音訊編碼格式是否為 AAC 或 Opus。

            * 若音訊編碼格式為 AAC：音訊將轉換為 Opus，其餘設置遵循原始 ABR 配置，並按原始 ABR 配置收取轉碼費用。

            * 若音訊編碼格式為 Opus：音訊將直接複製，不進行音訊轉碼，其餘設置遵循原始 ABR 配置，並按原始 ABR 配置收取轉碼費用。

      * **RTM 地址**：使用此地址可搭配 BytePlus MediaLive Player SDK for iOS 及 Android，以及其他播放器進行播放。

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">如需包含驗證資訊，必須先為拉流網域名稱啟用 URL 驗證。如需更多資訊，請參閱<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-TW">設定 URL 驗證</a>。   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">若無法獲取<strong>RTM Web SDK 播放位址</strong>，請聯絡<a href="https://console.byteplus.com/workorder/create?step=2&SubProductID=P00000980">技術支援</a>。   </div>
   

5. 您也可以：

   * 點擊線上推流圖示，在控制台的 **Web 推流** 頁面開始推流。

   * 點擊線上播放圖示，在控制台的 **Web 拉流** 頁面開始播放。

   * 點擊複製圖示以複製地址。

   * 點擊二維碼圖示以查看二維碼。

   * 點擊頁面右上角的**歷史記錄**，以查看先前產生的位址記錄。

## 接下來該怎麼做


* 使用 MediaLive 控制台提供的[Web 推流](https://console.byteplus.com/live/main/WebPushStream)和[Web 拉流](https://console.byteplus.com/live/main/webPullStream/play)工具，嘗試通過 HTTPS 進行推流和拉流。

* 使用基於 Web Player SDK 1.x 並與 BytePlus VOD 合作開發的 VePlayer [Web player V1](https://demo.byteplus.com/common/veplayer/basic/example?tab=function-display)，體驗各種網頁播放功能。

* 使用基於 Web Player SDK 2.x 並為 MediaLive 開發的 VePlayer [Web player V2](https://demo.byteplus.com/common/veplayer/v2/basic/example?tab=function-display)，體驗各種網頁播放功能。
