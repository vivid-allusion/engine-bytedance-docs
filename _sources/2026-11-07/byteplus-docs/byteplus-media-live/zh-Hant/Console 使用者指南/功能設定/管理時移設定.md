時移功能可讓觀看者像觀看隨選影片一樣控制直播串流進度。無論直播串流進行中或已結束，觀看者都可以暫停並順暢恢復播放、重播任何已串流的內容，或在設定的時間範圍內隨時從頭開始觀看，確保不錯過任何重要內容。本主題將引導您完成從設定到播放的完整步驟。

## 核心價值

* **提升觀看體驗**：觀看者不再受限於「即時」。他們可以隨時暫停並重播關鍵時刻，例如體育賽事中的進球，或線上課程中的重點講解。這大幅提升觀看彈性和滿意度。

* **增加內容消費**：中途加入的觀看者可以從頭開始觀看，以體驗完整內容。這可有效增加線上時長和互動度。

* **即時內容複用**：直播串流結束後，時移內容可用於隨選播放，實現「直播轉回放」體驗。

## 運作方式

時移可簡單理解為一邊串流一邊同時錄製。啟用時移功能後，伺服器會執行以下操作：

1. 即時錄製和索引：伺服器會根據 HLS 通訊協定，將直播串流即時分割為影片片段（TS 檔案）。同時，系統會維護一個 M3U8 播放清單檔案，其中包含所有這些 TS 檔案的完整播放順序。

2. 回應播放請求：當觀看者暫停、倒轉或從頭開始播放時，播放器會使用 `timeshift` 或 `start`/`end` 參數，向伺服器請求特定時間點的影片內容。

3. 產生自訂播放清單：收到請求後，伺服器會根據 M3U8 檔案，為觀看者動態產生一個臨時的自訂播放清單。此播放清單只包含觀看者想觀看的時間範圍內的 TS 檔案。

4. 隨選播放：取得自訂播放清單後，播放器會依序載入並播放 TS 檔案，形成時移效果。

## 注意事項

* **費用：**

   * 使用時移會產生儲存費用和錄製費用。如需儲存費用，請參閱[時移](https://docs.byteplus.com/docs/byteplus-media-live/docs-time-shifting)；如需錄製費用，請參閱[錄製](https://docs.byteplus.com/docs/byteplus-media-live/docs-transcoding_2)。

   * 選擇**轉碼串流**或 **HLS\-ABR** 作為**錄製串流類型**會產生轉碼費用。如需詳細資訊，請參閱[轉碼](https://docs.byteplus.com/docs/byteplus-media-live/docs-transcoding)。

* **生效時間**：新增、更新或刪除時移設定後，您必須等待 3\-5 分鐘，然後重新推流，新的設定才會生效。

## 前提條件

* 您已將用於推流的域名和用於拉流的域名新增至所需的域名空間。如需詳細資訊，請參閱[新增域名](https://docs.byteplus.com/docs/byteplus-media-live/docs-domain)。

* 若要使用現有錄製設定中的設定新增設定，請確保您已新增使用 **HLS** 作為錄製格式，並將錄製檔案儲存在 TOS bucket 中的錄製設定。如需詳細資訊，請參閱[將錄製檔案儲存在 TOS bucket 中](https://docs.byteplus.com/docs/byteplus-media-live/docs-configuring-recordings#fbac8c5c)。

* 若要從轉碼串流產生時移內容，請在所需的域名空間下新增轉碼設定，並將**觸發轉碼**設定為**推流**。確保要新增的轉碼設定和時移設定使用相同的 `AppName` 和域名空間。如需詳細資訊，請參閱[管理轉碼設定](https://docs.byteplus.com/managing-transcoding-configuration-1789729303738)。

* 若要從主播放清單的自適應位元率（ABR）子串流產生時移內容，請在所需的域名空間下新增 ABR 設定，並將 **HLS\-ABR** 作為通訊協定類型。確保要新增的 ABR 設定和時移設定使用相同的 `AppName` 和域名空間。如需詳細資訊，請參閱[管理自適應位元率設定](https://docs.byteplus.com/managing-adaptive-bitrate-configuration-1789729318801)。

## 步驟 1：新增時移設定

您可以透過兩種方式新增時移設定。您的選擇取決於是否已使用錄製功能，以及要將時移內容儲存在何處。

* [從頭新增設定](https://docs.byteplus.com/docs/byteplus-media-live/docs-configuring-time-shifting#8cd67d7c)：使用 MediaLive 預設儲存空間存放時移內容。時移內容會儲存在由 BytePlus 管理的公用 TOS bucket 中。您不需要提供或管理自己的儲存 bucket。

   在以下情況選擇此方式：

   * 您**未**使用錄製功能。

   * 您想要**快速且簡單的設定**，不需要為時移管理自己的 TOS bucket。

   * 您的主要目標只是啟用時移功能，且不需要直接存取時移內容檔案。

* [從現有錄製設定新增](https://docs.byteplus.com/docs/byteplus-media-live/docs-configuring-time-shifting#c0228dfa)：允許您透過重用現有錄製設定中的設定來新增時移設定。該錄製設定需使用 **HLS** 作為錄製格式，並將檔案儲存在您自己的 TOS bucket 中。

   在以下情況選擇此方式：

   * 您**已經**使用錄製功能，並使用自己的 TOS bucket。

   * 您的錄製設定使用 **HLS** 作為錄製格式。

   * 您需要**直接存取**時移內容檔案，以便進一步處理。

## 步驟 2：產生時移內容的播放位址

新增時移設定後，請產生時移內容的播放位址，並在您的播放器中使用該位址。

若要啟用時移播放，請先設定播放器使用直播串流的拉流位址。當觀看者倒轉、從頭開始，或選擇過去的時間點觀看時，產生時移播放位址，並將該位址傳遞給播放器，以拉取並播放請求的內容，如下所示。

> **說明**

> 如果您使用 Player SDK for Web 拉取並播放請求的內容，請參閱[直播時移](https://docs.byteplus.com/docs/byteplus-media-live/docs-live-time-shifting)。

* **相對時移**：在直播串流進行期間使用此模式。此時觀看者需要重播目前直播位置之前一段時間的內容。

   當觀看者拖曳進度列以重播先前內容時，播放器會計算目標位置與目前直播位置之間的時間差，單位為秒。播放器接著會將此值用於 `timeshift` 參數，以產生新的播放位址並播放請求的內容。

   僅在啟用 URL 鑑權時，才將 `&{AuthInfo}` 附加到播放位址。如需詳細資訊，請參閱[設定 URL 鑑權](https://docs.byteplus.com/configuring-url-authentication-1789729269482)。

   對於原始串流和轉碼串流，時移播放位址使用以下格式：

   ```Plain
   http(s)://{DomainName}/{AppName}/{StreamName}{Suffix}.m3u8?timeshift={time}&{AuthInfo}
   ```

   對於原始串流，請將 `Suffix` 留空。對於轉碼串流，`Suffix` 是您轉碼設定中的轉碼尾碼，例如 `_hd`。

   對於 HLS\-ABR 時移內容，請使用 HLS\-ABR 位址格式：

   ```Plain
   http(s)://{DomainName}/{AppName}/{StreamName}/abr.m3u8?timeshift={time}&{AuthInfo}
   ```

   **範例**：

   觀看者拖曳進度列以重播 5 分鐘前的內容。

   * 原始串流播放位址：`http://pull.example.com/live/test.m3u8`

   * 播放器產生的原始串流時移播放位址：`http://pull.example.com/live/test.m3u8?timeshift=300`

   * 播放器產生的轉碼串流時移播放位址：`http://pull.example.com/live/test_hd.m3u8?timeshift=300`

   * 播放器產生的 HLS\-ABR 時移播放位址：`http://pull.example.com/live/test/abr.m3u8?timeshift=300`

   玩家使用時移播放位址拉取內容後，觀看者會立即跳轉到 5 分鐘前的內容，並從該點繼續觀看。

* **絕對時移**：當您希望觀看者在直播串流期間或直播串流結束後，觀看特定時間範圍的內容時，請使用此模式。為此，請將 `mode`、`start` 和 `end` 參數新增至播放位址。`start` 和 `end` 值支援精確到秒的 RFC3339 UTC 時間、以秒為單位的 Unix 時間戳記，或 `YYYYMMDDHHMMSS` 格式。`YYYYMMDDHHMMSS` 格式的值會被解譯為 UTC+0。例如，`20260325153000` 表示 2026 年 3 月 25 日 UTC+0 的 15:30:00。

   常見範例是觀看者較晚加入進行中的直播串流並想從頭開始觀看，或觀看者想在直播串流結束後重播特定時段，例如 19:00 到 19:30。

   * `mode`：此參數決定播放器如何播放請求的時間範圍，以及播放到達 `end` 時間後會發生什麼。預設值為 `1`。

      * 當值為 `1` 時：內容會像隨選影片一樣播放。這適用於直播串流結束後的完整回放或精彩片段播放。伺服器會傳回包含 `#EXT-X-ENDLIST` 標籤的播放清單（M3U8 檔案），播放器在到達 `end` 時間時會自動停止播放影片。觀看者可以像觀看隨選影片一樣自由拖曳進度列。

      * 當值為 `3` 時：內容會像直播串流一樣播放。這適用於觀看者需要在進行中的直播串流中從較早時間點開始，然後繼續觀看直播串流的情境。伺服器會傳回不含 `#EXT-X-ENDLIST` 標籤的播放清單（M3U8 檔案），因此播放器會將該串流視為仍在直播。播放到達 `end` 時間後，如果直播串流仍在進行，播放器會繼續播放後續直播內容。

      > **警告**

      > 當 `mode` 設定為 `3` 時，`start` 值不得早於直播串流實際開始時間前 2 小時。例如，如果直播串流於 2026 年 3 月 25 日 15:00 開始，最早有效的 `start` 值為 2026 年 3 月 25 日 13:00。更早的值會傳回 `404` 錯誤。

   * `start`：播放開始時間。

   * `end`：播放結束時間。

      僅在啟用 URL 鑑權時，才將 `&{AuthInfo}` 附加到播放位址。如需詳細資訊，請參閱[設定 URL 鑑權](https://docs.byteplus.com/configuring-url-authentication-1789729269482)。

      對於原始串流和轉碼串流，時移播放位址使用以下格式：

   ```Plain
   http(s)://{DomainName}/{AppName}/{StreamName}{Suffix}.m3u8?mode={mode}&start={UTC/Unix/Human}&end={UTC/Unix/Human}&{AuthInfo}
   ```

   對於原始串流，請將 `Suffix` 留空。對於轉碼串流，`Suffix` 是您轉碼設定中的轉碼尾碼，例如 `_hd`。

   對於 HLS\-ABR 時移內容，請使用 HLS\-ABR 位址格式：

   ```Plain
   http(s)://{DomainName}/{AppName}/{StreamName}/abr.m3u8?mode={mode}&start={UTC/Unix/Human}&end={UTC/Unix/Human}&{AuthInfo}
   ```

   **範例**：

   假設某直播串流在 2026 年 3 月 25 日 UTC+0 的 15:00 到 17:00 進行。若要在直播串流結束後提供完整回放，請使用以下其中一個播放位址：

   * 原始串流：`http://pull.example.com/live/test.m3u8?mode=1&start=20260325150000&end=20260325170000`

   * 帶有 `_hd` 尾碼的轉碼串流：`http://pull.example.com/live/test_hd.m3u8?mode=1&start=20260325150000&end=20260325170000`

   * HLS\-ABR：`http://pull.example.com/live/test/abr.m3u8?mode=1&start=20260325150000&end=20260325170000`
