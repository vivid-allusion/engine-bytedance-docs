自適應碼率（ABR）是一項以觀眾為中心的影片傳遞技術。無論網路狀況如何波動，都能提供順暢且高品質的播放體驗。您可以預先設定多個子串流，並使用不同的編碼格式、解析度與位元率。播放器會根據觀眾的即時網路狀況，自動選擇最佳串流，以平衡順暢播放與影片品質。本主題將引導您在 MediaLive 主控台中管理 ABR 設定。

## 為什麼使用 ABR？

ABR 有助於解決主要串流挑戰，並透過智慧且個人化的直播體驗，大幅提升觀眾滿意度。

* **在不同畫質等級間自動切換，以平衡順暢播放與影片品質**

   透過建立多個畫質等級（例如 UHD、HD 和 SD），您可以讓播放器監控每位觀眾的即時網路狀況，並在這些等級間無縫切換：

   * **當觀眾的網路狀況不佳時**：播放器會自動切換到較低位元率的串流。這會犧牲部分影片品質，但可確保播放順暢且無緩衝。

   * **當觀眾的網路恢復時**：播放器會自動切回較高位元率的串流，以提供最佳影片品質。

      這種動態調整可提供最佳且不中斷的觀看體驗，讓您的串流能因應波動的網路速度。

* **降低頻寬成本並提升相容性**

   * **降低頻寬成本：**  您可以在傳遞前，將來源串流從標準 H.264 編解碼器轉換為效率更高的 H.265 編解碼器。H.265 提供更高的壓縮率，可大幅降低頻寬用量與成本。

   * **提升播放器相容性：**  如果您使用 H.265 串流，而部分較舊的瀏覽器和裝置不支援 H.265，您可以同時提供 H.264 版本。這可確保所有觀眾都能觀看您的串流，不會遇到相容性問題。

## ABR 如何運作？

對於 HLS\-ABR 和 DASH\-ABR，播放器會請求 ABR 位址並接收主播放清單。主播放清單會作為所有可用子串流（例如 1080p 和 720p）的導覽。接著，播放器會持續監控觀眾的網路狀況，並在這些子串流間自動切換。對於 RTM\-ABR，您會使用一個 RTM\-ABR 拉流位址。所選的尾碼會決定啟動時的畫質等級，而 MediaLive 會根據觀眾的網路狀況，在不同畫質等級間自動切換。在任一情況下，當網路狀況不佳時，都會使用較低位元率的串流以減少緩衝；當網路改善時，則會恢復較高位元率的串流，確保最佳且不中斷的觀看體驗。

## 先決條件

您已在相同的網域名稱空間下，新增用於推流和拉流的網域名稱。如需詳細資訊，請參閱[新增網域名稱](https://docs.byteplus.com/docs/byteplus-media-live/docs-domain)。

## 注意事項

* **費用**：子串流是透過將來源串流轉碼為不同解析度和位元率而建立，此程序會產生轉碼費用。如需詳細資訊，請參閱[轉碼](https://docs.byteplus.com/docs/byteplus-media-live/docs-transcoding)。

* **生效時間**：新增、更新或刪除 ABR 設定後，您必須等待 3 到 5 分鐘，然後重新開始推流，新的設定才會生效。

* **通訊協定**：ABR 適用於 HLS、DASH 和 RTM 通訊協定。

## 新增 ABR 設定

1. 登入 [BytePlus MediaLive 主控台](https://console.byteplus.com/live)。

2. 在左側導覽窗格中，選取 **Feature configuration**，然後按一下右側的 **Adaptive bitrate** 索引標籤。

3. 從 **Domain name space** 下拉式清單中選取所需的網域名稱空間，然後按一下 **Add configuration**。

4. 在 **Basic information** 索引標籤上，設定下列項目。這些設定會套用至所有子串流。

   ![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/177407d5283e4816839c416df6b6519e~tplv-goo7wpa0wc-topic.webp)

   |參數 |說明 |
   |---|---|
   |AppName |指定此設定將套用的 `AppName`。此名稱必須與推流位址中的 `AppName` 完全相符。例如，如果推流位址為 `rtmp://push.example.com/live/test?authinfo`，則 `AppName` 為 `live`。<br><br>`AppName` 可包含字母 (a\-z, A\-Z)、數字 (0\-9)、底線 (`_`) 和連字號 (`-`)，且長度必須為 1\-30 個字元。<br><br>> **说明**<br><br><br>> 每個 `AppName` 只能有一個 ABR 設定。<br> |
   |Type |選取轉碼模式。此選項可讓您在轉碼成本、影片品質與頻寬用量之間取得平衡。<br><br><br>* **標準模式：**  採用標準壓縮的更經濟選項。此選項可提供良好品質，適合以降低轉碼成本為主要優先事項的情境。<br><br>* **低位元率 HD：**  使用比 **標準模式** 更有效率的壓縮，以節省頻寬或提升影片品質。<br><br>   * **節省頻寬：**  在較低位元率下維持相同影片品質，大幅降低頻寬用量與傳遞成本。<br><br>   * **提升影片品質：**  在相同位元率下提供更清晰且更細緻的影像，帶來更好的觀看體驗。<br><br>      此模式適合您想在較低位元率下達到相同影片品質，或在相同位元率下取得更佳影片品質的直播情境。請注意，此模式會產生比 **標準模式** 更高的轉碼費用。 |
   |Video codec |選擇子串流的影片編解碼器。**H.265** 提供較佳壓縮（節省頻寬），而 **H.264** 則在各類裝置上提供更廣泛的相容性。 |
   |Trigger transcoding |根據您對成本和觀看體驗的優先順序，選擇何時開始轉碼。<br><br><br>* **推流（預設）** ：您開始推送來源串流時，轉碼立即開始。由於子串流會立即準備就緒，這可確保每位觀眾都沒有啟動延遲。不過，只要來源串流處於直播狀態，轉碼就會持續執行，因此此選項會產生較高成本。建議用於即時可用性至關重要的高優先順序活動。<br><br>* **拉流**：只有在第一位觀眾開始播放子串流時，轉碼才會開始。這是最具成本效益的選項，但第一位觀眾可能會遇到短暫的啟動延遲。建議用於以成本最佳化為優先的大多數使用案例。 |
   |Protocol Type |選擇一種或多種 ABR 通訊協定類型。通訊協定類型會決定觀眾的播放器如何接收並在不同畫質等級間切換。<br><br><br>* **HLS\-ABR** (`.m3u8`)：選擇此項以觸及**最廣泛的受眾**。此通訊協定是 iPhone 和 iPad 等 Apple 裝置以及 Safari 瀏覽器原生播放的必要項目。此外，HLS\-ABR 在 Android、桌面瀏覽器和智慧電視上都具備出色相容性，因此是高度可靠的選擇。如果您需要支援 Apple 生態系統，建議選擇 HLS\-ABR。<br><br>* **DASH\-ABR** (`.mpd`)：當大多數觀眾使用 **Android 裝置和非 Safari 桌面瀏覽器**（例如 Chrome 和 Firefox），或您的工作流程涉及特定**數位版權管理 (DRM)**  解決方案時，請選擇此項。請注意，DASH 在 iOS Safari 上不受原生支援，需要特定播放器程式庫才能在該瀏覽器上運作。<br><br>* **RTM\-ABR** (`.sdp`)：選擇此項用於體育轉播等對延遲敏感的情境。RTM\-ABR 可提供**約 2\-3 秒的低延遲**，同時透過自動調整畫質等級以符合**不穩定的網路狀況**，維持順暢的觀看體驗。這會在弱網路環境中切換到較低畫質等級，避免緩衝和卡頓，且不會增加延遲。如果您的目標是在確保播放穩定性的同時達到最低可能延遲，建議選擇 RTM\-ABR。 |
   |Copy user request parameters to substream URL |如果您使用[遠端鑑權](https://docs.byteplus.com/en/docs/byteplus-media-live/remote-authentication)，可以啟用此設定。啟用後，系統會自動將所有 URL 參數（例如鑑權 Token）從主播放清單請求複製到所有子串流 URL。<br><br>播放器會發出多個請求，包括主播放清單請求和子串流請求。若未啟用此設定，主播放清單請求中的 URL 參數不會自動傳遞至子串流請求。因此，鑑權伺服器可能會封鎖子串流請求，導致播放失敗。啟用此設定可確保所有請求都帶有所需的 URL 參數，進而順暢播放。<br><br>> **警告**<br><br><br>> 如果您使用時移功能，則無法啟用此設定。<br> |

   |---|---|
   |Quality level |選取畫質等級。您可以使用各等級的預設設定以節省時間，這些設定會定義解析度、位元率和影格率。音訊設定預設為 AAC。您可以直接使用這些預設設定，或在選取後自訂設定。<br><br><br>* **4K (2160p)：**  15,000 kbps，60 fps<br><br>* **2K (1440p)：**  10,000 kbps，30 fps<br><br>* **UHD (1080p)：**  3200 kbps，30 fps<br><br>* **HD (720p)：**  2048 kbps，30 fps<br><br>* **SD (540p)：**  1638 kbps，30 fps<br><br>* **LD (360p)：**  1024 kbps，30 fps<br><br><br>> **说明**<br><br><br>> 若要啟用 4K 或 2K 選項，請透過[建立工單](https://console.byteplus.com/workorder/create?step=2&SubProductID=P00000980)聯絡 BytePlus 支援團隊。<br> |
   |Substream suffix |此子串流的唯一尾碼，例如 `uhd`。尾碼可包含字母 (A\-Z, a\-z)、數字 (0\-9) 和連字號 (\-)，且長度必須為 1\-10 個字元。<br><br>> **说明**<br><br><br><br>* > 對於相同的 `AppName`，請確保此尾碼不會與個別轉碼設定中使用的任何尾碼衝突。<br><br><br>* > 如果您選取 **DASH\-ABR** 作為 **Protocol Type**，系統會自動使用 `abr` 尾碼作為主播放清單 URL（例如 `.../streamname_abr/index.mpd`）。為避免命名衝突，在相同 `AppName` 下，您**不能**將 `abr` 用作個別轉碼設定的尾碼。<br> |
   |Resolution |子串流的解析度，單位為像素。值的範圍可介於 150 到 4096。<br><br>> **说明**<br><br><br>> 設定高於來源串流的解析度不會提升影片品質，且可能導致不必要的處理成本。<br> |
   |Bitrate |設定子串流的位元率，單位為 kbps。較高的位元率會產生較清晰的影像，但需要更多頻寬。值的範圍可介於 0 到 30,000 kbps。將值設為 0 可讓位元率與來源串流相同。當來源位元率已符合您的品質需求時，這很有用。<br><br>> **说明**<br><br><br>> 設定高於來源串流的位元率不會增加視覺細節，只會提高頻寬成本。<br> |
   |Frame rate |設定子串流的影格率，單位為 fps。較高的影格率會產生更順暢的動作，但需要更多處理能力和頻寬。值的範圍可介於 0 到 60 fps。將值設為 0 可讓影格率與來源串流相同。當來源影格率已符合您的品質需求時，這很有用。<br><br>> **说明**<br><br><br>> 設定高於來源串流的影格率只會產生重複影格。這類重複影格不會讓動作看起來更順暢，反而可能讓影片顯得不自然。<br> |
   |Audio settings |選擇如何處理子串流的音訊。您的選擇取決於您優先考量最大相容性、頻寬用量或成本節省。<br><br><br>* **AAC**：選取此項以取得最大相容性。AAC 是業界標準，幾乎可在任何裝置或瀏覽器上播放，包括較舊的裝置或瀏覽器。這是觸及最廣泛受眾的最可靠選擇。<br><br>* **Opus**：選取此項以使用進階壓縮，在節省頻寬成本的同時提供出色音訊品質。雖然很適合現代平台，但請注意，部分舊版裝置可能不支援 Opus。<br><br>* **複製來源串流**：選取此項可直接使用原始音訊，不進行任何變更。這會略過音訊轉碼程序，節省轉碼費用，是最具成本效益的選項。由於沒有重新編碼，原始音訊品質會完整保留。當來源音訊格式和品質已符合需求，且您想最大化成本節省時，建議使用此選項。 |
   |Transcoding stop waiting time |設定在最後一位觀眾**停止拉流**後，轉碼任務保持作用中的等待時間（秒）。此設定有助於您平衡觀看體驗與轉碼成本。<br><br>參數值：<br><br><br>* **0 到 300：**  定義特定等待時間。如果在此期間結束前沒有新觀眾加入，任務就會停止。<br><br>*  **\-1：**  將等待時間設為**無限**。只要來源串流處於直播狀態，任務就不會自動停止。<br><br><br>根據您的串流情境設定等待時間：<br><br><br>* **取得最佳體驗：**  如果您預期觀眾流動率高（例如直播體育賽事或熱門活動期間），請設定**較長的等待時間（例如 60\-180 秒）** 。這可確保大多數新觀眾能立即播放，但會增加閒置期間的成本。<br><br>* **控制成本：**  如果您的觀眾相對穩定，或節省成本是優先事項，請設定**較短的等待時間（例如 10\-30 秒）** 。這會在無人觀看時更快停止轉碼任務，降低您的費用。<br><br>* **用於關鍵 24/7 串流：**  只有在必要串流需要隨時立即啟動，且您接受持續轉碼成本時，才使用  **\-1** 的值。<br><br><br>> **说明**<br><br><br>> 只有當 **Trigger transcoding** 設為 **Stream pulling** 時，此設定才會生效。<br> |
   |Resolution not exceeding the original |* **啟用（預設）：**  防止將影片解析度升頻到高於來源串流的解析度。如果來源串流的解析度低於您的設定，例如 ABR 設定設為 `1080p`，但來源串流為 `720p`，則輸出解析度也會是 `720p`。這可避免潛在的品質下降與不必要成本。<br><br>* **停用：**  強制輸出符合設定的解析度，即使這表示要將較低解析度的來源升頻。只有在播放器或下游服務嚴格要求固定解析度時，才停用此項。 |
   |Bitrate not exceeding the original |* **啟用（預設）：**  防止輸出位元率超過來源串流。如果來源串流的位元率低於您的設定，例如 ABR 設定設為 3200 kbps，但來源串流為 2048 kbps，則輸出位元率也會是 2048 kbps。這可最佳化頻寬用量並降低成本，因為將位元率提高到超過來源串流沒有任何效益。<br><br>* **停用：**  強制輸出符合設定的位元率。只有在播放器或下游服務嚴格要求固定位元率時，才停用此項。 |
   |Frame rate not exceeding the original |* **啟用（預設）：**  防止輸出影格率超過來源串流。如果來源串流的影格率低於您的設定，例如 ABR 設定設為 30 fps，但來源串流為 25 fps，則輸出影格率也會是 25 fps。這可避免重複影格以確保播放順暢，並減少不必要的處理成本。<br><br>* **停用**：強制輸出符合設定的影格率。只有在播放器或下游服務嚴格要求固定影格率時，才停用此項。 |

6. 按一下 **Confirm** 以儲存設定。您隨時可以按一下 **Action** 欄中的 **Edit** 或 **Delete**，以編輯或刪除設定。

## 後續操作

1. 使用[位址產生器](https://console.byteplus.com/live/main/locationGenerate)產生 ABR 拉流位址。

   1. 完成下列設定，然後按一下 **Generates Pull stream address**。

      * **Address type**：選取 **Pull stream address**。

      * **Domain name**：選取新增 ABR 設定時所用網域名稱空間內的拉流網域名稱。

      * **AppName** 和 **StreamName**：輸入推流位址中的 `AppName` 和 `StreamName`。例如，如果推流位址為 `rtmp://push.example.com/live/test?authinfo`，則 `AppName` 為 `live`，`StreamName` 為 `test`。

   2. 在 **Adaptive bitrate** 索引標籤上取得 ABR 拉流位址。您可以複製位址，或按一下右側圖示產生 QR 碼。如需詳細資訊，請參閱[產生串流位址](https://docs.byteplus.com/docs/byteplus-media-live/docs-address-generator)。

      ![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/9d1af8b216d44940a91b4a576a318520~tplv-goo7wpa0wc-topic.webp)

   * **HLS\-ABR 位址**：`.m3u8` 位址。

   * **DASH\-ABR 位址**：`.mpd` 位址。

   * **RTM\-ABR 位址**：選取啟動畫質等級（尾碼）以取得對應的 RTM\-ABR 位址。

      * **RTM 位址**：使用此位址透過 iOS 和 Android 的 BytePlus MediaLive Player SDK 以及其他播放器進行播放。

      * **RTM Web SDK 播放位址**：使用此位址透過 BytePlus MediaLive Player SDK for Web 進行播放。此 RTM\-ABR 拉流位址會保留原始 ABR 設定，並加入下列處理：

         * 系統會自動偵測子串流是否包含 B\-frames。

            * 如果存在 B\-frames：子串流會被轉碼以移除 B\-frames，其他設定則遵循原始 ABR 設定，且轉碼費用會依原始 ABR 設定收取。

            * 如果不存在 B\-frames：子串流會依原始 ABR 設定轉碼，且轉碼費用會依原始 ABR 設定收取。

         * 系統會自動偵測音訊編解碼器是 AAC 還是 Opus。

            * 如果音訊編解碼器為 AAC：音訊會轉換為 Opus，其他設定則遵循原始 ABR 設定，且轉碼費用會依原始 ABR 設定收取。

            * 如果音訊編解碼器為 Opus：音訊會在不進行音訊轉碼的情況下複製，其他設定則遵循原始 ABR 設定，且轉碼費用會依原始 ABR 設定收取。

      > **注意**

      > 如果您無法取得 **RTM Web SDK 播放位址**，請聯絡[技術支援](https://console.byteplus.com/workorder/create?step=2&SubProductID=P00000980)。

2. 使用您的推流位址推送來源串流。請確保用於推流和拉流的網域名稱屬於相同的網域名稱空間，並且推流和拉流位址使用相同的 `AppName` 和 `StreamName`。如需詳細資訊，請參閱[產生串流位址](https://docs.byteplus.com/docs/byteplus-media-live/docs-address-generator)。

3. 使用下列任一方法進行播放。

   |方法 |情境 |說明 |
   |---|---|---|
   |Player SDK for Web |在網頁瀏覽器中播放串流。 |整合 Player SDK for Web，並在您的網站或 Web 應用程式上播放串流。如需詳細資訊，請參閱[播放 RTM-ABR 串流](https://docs.byteplus.com/docs/byteplus-media-live/docs-adaptive-bitrate-streaming-abr#c552533f)。 |
   |Client SDK |在原生行動應用程式中播放串流。 |整合用戶端 SDK，並在行動應用程式中播放串流。如需詳細資訊，請參閱：<br><br><br>* iOS：[RTM-ABR 串流](https://docs.byteplus.com/docs/byteplus-media-live/docs-implementing-advanced-features-3#affd8a26)<br><br>* Android：[RTM-ABR 串流](https://docs.byteplus.com/docs/byteplus-media-live/docs-implementing-advanced-features-2#ff47ac00) |

## 常見問題

### 為什麼我的新 ABR 設定沒有生效？

新增、更新或刪除 ABR 設定後，您必須等待 3 到 5 分鐘，然後重新開始推流，新的設定才會生效。

### 第一位觀看我串流的觀眾遇到延遲。如何修正？

此延遲是因為 **Trigger transcoding** 設定設為 **Stream pulling**，因此只有在第一位觀眾開始觀看時才會開始轉碼。若要消除此啟動延遲，請將觸發方式變更為 **Stream pushing**。這會在來源串流上線的當下開始轉碼程序，確保所有觀眾都能立即播放。請注意，只要來源串流處於直播狀態，即使無人觀看，此選項仍會產生成本。

### 控制轉碼成本的最佳方式有哪些？

若要最佳化費用，請考慮下列策略：

* **使用拉流觸發方式：**  將 **Trigger transcoding** 保持設為 **Stream pulling**，這樣只有在有人正在觀看時，您才需要為轉碼付費。

* **複製來源音訊：**  將 **Audio settings** 設為 **Copy source stream**。這可完全避免音訊轉碼費用，並保留原始音訊品質。

* **選擇標準轉碼模式：**  選取 **Standard mode** 作為 **Type**。這是更經濟的選項，適合以降低轉碼成本為主要優先事項的情境。

* **避免不必要的升頻：**  保持啟用 **not exceeding the original** 選項。這可避免浪費資源，因為轉碼到高於來源的解析度、位元率或影格率並不會提升影片品質。

### 自適應碼率與轉碼：我應該使用哪一個？

選擇最符合您的串流通訊協定與所需觀看體驗的設定。關鍵差異在於播放器是否能在不同畫質等級間自動切換。

* **ABR**：使用 ABR 設定可提供無縫且自動調整的觀看體驗。此功能提供多個畫質等級，播放器會根據觀眾的網路狀況在等級間自動切換，確保以最佳可能影片品質順暢播放。

* **轉碼**：在下列情境中使用轉碼設定：

   * **更廣泛的通訊協定支援**：當您需要使用 ABR 功能不支援的通訊協定進行串流時，例如 RTMP。

   * **手動畫質選擇**：當您想為每個畫質等級提供個別拉流位址，並在播放器中實作手動畫質選擇器，讓觀眾選擇偏好的解析度時。

### 轉碼可以改善模糊來源串流的品質嗎？

不可以，轉碼無法建立來源串流中不存在的細節。如果您的來源串流模糊或品質低，子串流也會顯得模糊，即使您將其設為較高解析度、位元率或影格率也一樣。

### 我的鑑權串流播放片刻後就停止。為什麼？

這通常發生在使用遠端鑑權時，因為主播放清單請求中的 URL 參數（例如鑑權 Token）未傳遞至子串流請求。若要修正此問題，請啟用 **Copy user request parameters to substream URL** 選項。這可確保每個子串流請求都包含所需的 URL 參數，進而不中斷播放。

### 我應該選擇哪種通訊協定：HLS\-ABR、DASH\-ABR 還是 RTM\-ABR？

最佳選擇取決於您的目標受眾、播放裝置與延遲需求：

* 選擇 **HLS\-ABR** 以取得最廣泛相容性。如果您需要支援 Apple 生態系統，或不確定該選哪個，建議選擇 HLS\-ABR。

* 如果觀眾主要使用 Android 和非 Safari 瀏覽器（例如 Chrome 和 Firefox），或您有特定 DRM 需求，請選擇 **DASH\-ABR**。

* 選擇 **RTM\-ABR** 用於體育轉播等**對延遲敏感的情境**。如果您的目標是在確保播放穩定性的同時達到最低可能延遲，建議選擇 RTM\-ABR。
