要開始直播，您需要有效的推流與拉流地址。本主題說明如何透過三種不同方法產生這些地址：手動建構以批量操作、主控台的地址產生工具以快速生成單一地址，以及 API 呼叫以無縫整合至您的應用程式。

<span id="259f72de"></span>
## 使用場景


* **手動建構**：適用於批量產生推流／拉流地址以供業務應用。依照提供的地址建構規則，您可在不呼叫 API 的情況下使用 MediaLive 服務。

* **使用地址產生工具**：適合生成單一串流地址。無需撰寫程式碼，可直接於頁面操作完成。

* **使用 API**：適用於將直播功能整合至您的應用程式，並自動產生直播地址。


<span id="2f0ce12a"></span>
## 背景

<span id="59687c11"></span>
### 地址資訊說明

直播地址通常由`Domain`、`AppName`、`StreamName`組成，若啟用URL authentication，則還包含驗證資訊。

<span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/760f0061f25f4875ba068a1910305167~tplv-goo7wpa0wc-image.image) </span>

下表說明直播地址的參數。


|參數 |說明 |
|---|---|
|Domain |您已新增的網域名稱。推流時請使用您的網域名稱以產生推流位址，拉流時請使用您的網域名稱以產生拉流位址。 |
|AppName |直播串流的 `AppName`。拉取指定串流時，推流與拉流位址的 `AppName` 必須一致。 |
|StreamName |直播串流的 `StreamName`。拉取指定串流時，推流與拉流位址的 `StreamName` 必須一致。<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">對於轉碼後的串流，串流名稱由原始<code>StreamName</code>和後綴組成。後綴為轉碼配置中的轉碼後綴。例如，<code>stream_hd</code>。</div><br> |
|AuthInfo |請參考 [設定 URL 驗證](https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-TW) 以瞭解 URL 驗證結構並組建驗證字串。 |

### 地址組成規則

地址格式與組成規則會依傳輸協議而異，如下所示：

<Tab zoneid="gM1Xus8IbZ" title="推流位址">
<TabTitle>推流位址</TabTitle>

<span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/643156abf4e14e9b914050c72af157ba~tplv-goo7wpa0wc-image.image) </span>


* RTMP 推流位址：`rtmp://{DomainNameforStreamPushing}/{AppName}/{StreamName}?{AuthInfo}`。例如，`rtmp:// push.example.com/live/test?expire=1782309627&sign=a6937f4926**** 7b05f3987b088d473c`。若您使用 OBS 進行推流，請將 `rtmp://{DomainNameforStreamPushing}/{AppName}/` 設為 **Server**，並將 `{StreamName}?{AuthInfo}` 設為 **Stream Key**。

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">若要產生 RTMPS 推流地址，請將產生的 RTMP 地址中的<code>rtmp://</code>替換為<code>rtmps://</code>。   </div>
   

* TS over SRT 推流位址：`srt://{DomainNameforStreamPushing}:9000?streamid=#!::h={DomainNameforStreamPushing},r={AppName}/{StreamName},m=publish,{AuthInfo}`。例如，`srt:// push.example.com:9000?streamid=#!::h=push.example.com,r=live/test,m=publish,expire=1782309627,sign=a6937f4926**** 7b05f3987b088d473c`。

* RTMP over SRT 推流位址：`rtmp://{DomainNameforStreamPushing}:1999/{AppName}/{StreamName}?{AuthInfo}`。例如，`rtmp:// push.example.com:1999/live/test?expire=1782309627&sign=a6937f4926**** 7b05f3987b088d473c`。

* RTM 推流位址：`http( s)://{DomainNameforStreamPushing}:9922/{AppName}/{StreamName}.sdp?{AuthInfo}`。例如，`https://push.example.com:9922/live/test.sdp?expire=1782309627&sign=a6937f4926**** 7b05f3987b088d473c`。


<div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div>



* <div data-tips="true" data-tips-type="warning">若要使用 HTTPS 推流地址或於瀏覽器環境中推送 RTM 串流，必須先為推流網域名稱啟用 HTTPS。如需更多資訊，請參見<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-https-zh-TW">HTTPS 設定</a>。</div>


* <div data-tips="true" data-tips-type="warning">若要包含驗證資訊，必須先為推流網域名稱啟用 URL 驗證功能。如需更多資訊，請參見<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-TW">設定 URL 驗證</a>。</div>

<span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/609da30481ca476f8076d58aebd5c545~tplv-goo7wpa0wc-image.image) </span>


* RTMP 拉流位址：`rtmp://{DomainNameforStreamPulling}/{AppName}/{StreamName}?{AuthInfo}`。例如，`rtmp:// pull.example.com/live/test?auth_key=1779891783-0-0-a808d5b3**** d47e28fdafb87a65ce9a`。

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">若要產生 RTMPS 拉流地址，請將產生的 RTMP 地址中的<code>rtmp://</code>替換為<code>rtmps://</code>。   </div>
   

* FLV 拉流位址：`http( s)://{DomainNameforStreamPulling}/{AppName}/{StreamName}.flv?{AuthInfo}`。例如，`https://pull.example.com/live/test.flv?auth_key=1779891783-0-0-e1f5a2a**** 4b5fe21cb3efdc89af901`。

* HLS 拉流位址：`http( s)://{DomainNameforStreamPulling}/{AppName}/{StreamName}. m3u8?{AuthInfo}`。例如，`https://pull.example.com/live/test.m3u8?auth_key=1779891783-0-0-cd9bdb2b6**** 5e9f6f27c180a13a652`。

* 用於客戶端 SDK（BytePlus MediaLive Player SDK for iOS、Android、React Native、Flutter）及其他播放器的 RTM 拉流位址：`http( s)://{DomainNameforStreamPulling}/{AppName}/{StreamName}.sdp?{AuthInfo}`。例如，`https://pull.example.com/live/test.sdp?auth_key=1779891783-0-0-873bca4ce**** e85f357be5434067b70`。

* 用於 BytePlus MediaLive Player SDK for Web 的 RTM 拉流位址：`http(s)://{DomainNameforStreamPulling}/{AppName}/{StreamName}_autortm.sdp?{AuthInfo}`。例如，`https://pull.example.com/live/test_autortm.sdp?auth_key=1779891783-0-0-cd9bdb2b6**** 5e9f6f27c180a13a652`。啟用拉流域名的 URL 驗證後，用於驗證計算的 `StreamName` 為 `{StreamName}_autortm`。例如，若地址為 `https://pull.example.com/live/test_autortm.sdp`， 用於驗證計算的 `StreamName` 為 `test_autortm`。此地址會觸發自動轉碼，具體如下：

   * 系統會自動檢測流中是否包含 B 幀。

      * 若存在 B 幀：系統會將流轉碼以移除 B 幀，並收取標準轉碼費用。

      * 若不存在 B 幀：會複製源流中的視頻，不收取視頻轉碼費用。

   * 系統會自動檢測音訊編碼格式是否為 AAC 或 Opus。

      * 若音訊編碼格式為 AAC：音訊會轉換為 Opus。若未涉及視頻轉碼，則僅收取音訊轉碼費用。如需更多資訊，請參見 [僅音訊轉碼](/docs/byteplus\-media\-live/docs\-transcoding\-zh\-TW#Audio transcoding)。

      * 若音訊編碼格式為 Opus：會複製源流中的音訊，不收取音訊轉碼費用。

* DASH 拉流地址：`http( s)://{DomainNameforStreamPulling}/{AppName}/{StreamName}/index.mpd?{AuthInfo}`。例如，`https://pull.example.com/live/test/index.mpd?auth_key=1779891783-0-0-873bca4ce**** e85f357be5434067b70`。


<div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div>



* <div data-tips="true" data-tips-type="warning">若要使用 HTTPS 拉流地址或於瀏覽器環境中播放 RTM 串流，必須先為拉流網域名稱啟用 HTTPS。如需更多資訊，請參見<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-https-zh-TW">HTTPS 設定</a>。</div>


* <div data-tips="true" data-tips-type="warning">若要包含驗證資訊，必須先為拉流網域名稱啟用 URL 驗證功能。如需更多資訊，請參見<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-TW">設定 URL 驗證</a>。</div>

## 先決條件


* 您已新增推流與拉流的網域名稱，並完成 CNAME 設定。更多資訊，請參閱[新增網域名稱](https://docs.byteplus.com/docs/byteplus-media-live/docs-domain-zh-TW)與[新增 CNAME 記錄](https://docs.byteplus.com/docs/byteplus-media-live/docs-adding-a-cname-record-zh-TW)。

* 若需要，請啟用 HTTPS：

   * 使用 BytePlus MediaLive 主控台提供的線上推流工具。

   * 使用 BytePlus MediaLive 主控台提供的線上播放工具。

   * 使用 HTTPS 推流或拉流地址。

   * 在瀏覽器環境中推送或播放 RTM 串流。

   更多資訊，請參閱[HTTPS 設定](https://docs.byteplus.com/docs/byteplus-media-live/docs-https-zh-TW)。

* 要對推流或拉流地址進行 URL 驗證，必須啟用 URL authentication。更多資訊，請參閱[設定 URL 驗證](https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-TW)。

```Java
package demo;

import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;

public class Demo1 {
    public static void main(String[] args) throws NoSuchAlgorithmException {
        System.out.println((GenAuthUrl("testDomain", "testApp", "testStream", "testKey", 1636963457)));
    }

    public static String GenAuthUrl(String domain, String app, String stream, String secretKey, int volcTime) throws NoSuchAlgorithmException {

        String src = String.format("/%s/%s%s%d", app, stream, secretKey, unixtime);
        MessageDigest md5 = MessageDigest.getInstance("MD5");
        byte[] md5Bytes = md5.digest(src.getBytes(StandardCharsets.UTF_8));
        String sign = "";
        for (int i = 0; i < md5Bytes.length; i++) {
            sign += Integer.toHexString(md5Bytes[i] | 0xFFFFFF00).substring(6);
        }

        return String.format("rtmp://%s/%s/%s?expire=%d&sign=%s", domain, app, stream, unixtime, sign);
    }
}
```
