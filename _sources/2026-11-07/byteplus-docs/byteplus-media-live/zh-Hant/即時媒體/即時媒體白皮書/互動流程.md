RTM 基於 WebRTC 技術，根據 WebRTC 標準建立點對點傳輸通常包含以下三個步驟：


1. 媒體協商：通信雙方透過會話描述協議（SDP）進行互動。此步驟旨在確認雙方所支援的媒體類型、編碼方式、解析度及其他參數，以確保後續媒體傳輸能順利進行。

2. 網路位址協商：在此步驟中，雙方協商網路位址以發現對方的實際 IP 位址。此步驟為建立媒體傳輸通道做準備，並確保資料能在雙方之間精確傳輸。

3. 媒體資料點對點傳輸：雙方現在可以進行媒體資料的點對點傳輸。在此步驟中，媒體資料會透過先前協商好的傳輸通道即時傳送，從而建立 RTM 會話。

## 訊號互動

在媒體資料傳輸之前，客戶端與伺服器需協商其傳輸與處理視聽媒體的能力（例如支援的格式、編解碼處理細節、品質保證方法等）。RTM 使用 SDP 來傳遞共享的媒體能力並確保相容性。

媒體協商會透過網路進行，此過程稱為訊號互動。訊號互動主要使用 SDP。在訊號互動過程中，可使用不同的網路傳輸協議，包括 TCP/UDP 及 HTTP/QUIC。

## 媒體傳輸

協商步驟完成後，即開始媒體資料的傳輸（包含直播推流／拉流的視聽資料）。視聽資料可透過 UDP 結合 QoS 方法（如擁塞控制、封包遺失偵測與恢復）進行傳輸與分發，以實現基於 WebRTC 的媒體串流。

訊號互動、媒體協商與媒體傳輸的完整流程即構成一次 RTM 會話。

推流（即直播主將音視頻資料傳送至伺服器）與拉流（即觀眾從伺服器請求音視頻資料）皆屬於單向傳輸，與視訊通話模式下視聽資料的全雙工雙向傳輸有所不同。
