This topic serves as the official changelog for the Player SDK for Web. Here, you can find a detailed record of all version updates, including new features, improvements, and bug fixes.

|Release date |Version |Description |
|---|---|---|
|October 19, 2026 |2.13.0 |Added SEI delay statistics to the playback information returned by [getRTMStats()](https://docs.byteplus.com/docs/byteplus-media-live/docs-1156178#veplayerlive-getrtmstats) and [getFLVStats()](https://docs.byteplus.com/docs/byteplus-media-live/docs-1156178#veplayerlive-getflvstats). The new `delay_s2s` and `delay_s2e` fields, defined by the [SEIDelayStats](https://docs.byteplus.com/docs/byteplus-media-live/docs-1155423#seidelaystats) type, report the server\-to\-server delay and server\-to\-end delay, respectively. |
|June 23, 2026 |2.12.1 |Optimizes playback log reporting for overseas regions. It is recommended that applications in regions outside the Chinese mainland upgrade to this version. |
|June 08, 2026 |2.12.0 |* Added support for integrating the Player SDK for Web on Tizen and webOS smart TV systems. When creating an SDK application, enter the application identifier in the **Wildcard domain** field. For more information, see [Integrating the Player SDK for Web](https://docs.byteplus.com/docs/byteplus-media-live/docs-integrating-the-player-sdk-for-web_1) and [Getting your SDK license](https://docs.byteplus.com/docs/byteplus-media-live/docs-sdk-management).<br><br>* Enabled strict app ID verification. When integrating the Player SDK for Web, both the app ID and license must be configured.<br><br>* Added the [isRTMSeiSupported](https://docs.byteplus.com/en/docs/byteplus-media-live/docs-1156178?lang=en#isrtmseisupported) method to check whether the current browser supports receiving SEI (Supplemental Enhancement Information) messages from RTM streams.<br><br>* Fixed a playback issue in Baidu browser on HarmonyOS. In this scenario, playback now falls back to M3U8 by default.<br><br>* Adjusted the RTM stream playback implementation to prevent the `video` element's `src` from being incorrectly intercepted by HeyTap browser. |
|January 20, 2026 |2.11.2 |Updated the automatic fallback mechanism for pulling RTM streams. Currently, the player automatically triggers a fallback only in the following cases:<br><br><br>* The browser or device environment does not support RTM protocol playback, or playback of RTM streams encoded with H.264.<br><br>* A decoding exception occurs during playback.<br><br><br>For RTM stream pulling failures caused by network exceptions, the player triggers automatic retries (3 by default) and does not fall back directly. You can customize the number of retries using the `retryCount` parameter. |
|January 07, 2026 |2.11.0 |* To further improve the features and services of the Player SDK for Web, BytePlus MediaLive enables license validation for the Player SDK for Web and updates the billing rules. For more information, see [Announcement on license validation for Player SDK for Web](https://docs.byteplus.com/docs/byteplus-media-live/announcement_on_license_validation_for_player_sdk_for_web).<br><br>* The default value of `retryCount` for [RTM](https://docs.byteplus.com/en/docs/byteplus-media-live/docs-1155423?lang=en#rtm), [FLV](https://docs.byteplus.com/en/docs/byteplus-media-live/docs-1155423?lang=en#flv), and [HLS](https://docs.byteplus.com/en/docs/byteplus-media-live/docs-1155423?lang=en#hls) streams is changed from `0` to `3`. |
|November 27, 2025 |2.10.3 |* Support importing individual plugins via npm to reduce package size. For more information, see [Step 1: Import dependencies](https://docs.byteplus.com/docs/byteplus-media-live/docs-integrating-the-player-sdk-for-web_1#ceef554f).<br><br>* Fixed an issue where preloading JS via a `link` tag caused an error. |
|November 12, 2025 |2.10.2 |* Optimized the log reporting logic for the first\-frame time of RTM and FLV streams, with support for reporting the time breakdown for each stage.<br><br>* Fixed an issue where log reporting would stop when downgrading to other protocols after an RTM stream pulling error.<br><br>* Fixed an issue where calling [retry](https://docs.byteplus.com/en/docs/byteplus-media-live/docs-1156178#retry) after an RTM stream disconnection caused repeated errors.<br><br>* Fixed an issue on some mobile phones where non\-muted playback was hijacked by the browser, causing audio without video. |
|October 21, 2025 |2.10.0 |* Configuration delivery is supported after you pass in the `appId` (application ID).<br><br>* Fixed an issue where the cover image could not be hidden in the following scenario: when the `poster` parameter is set, autoplay is disabled (`autoplay: false`), and an RTM stream is playing. |
|September 2, 2025 |2.9.2 |Fixed an issue in HarmonyOS where clicking to mute or unmute was not working during RTM streaming. |
|August 6, 2025 |2.9.1 |Fixed the issue where RTM playback failures triggered repeated error events. This issue affected only versions V2.8.2 to V2.9.0. |
|August 4, 2025 |2.9.0 |Replaced the hls plugin with the hlsjs plugin. |
|July 24, 2025 |2.8.2 |Handling non\-compliant FLV specifications to mitigate incorrect screen orientation display. |
|July 15, 2025 |2.8.1 |Optimized the RTM Jitterbuffer playback strategy to dynamically adjust buffer duration based on real\-time network conditions, balancing latency and playback smoothness. |
|July 8, 2025 |2.8.0 |* Added SEI data support in RTM for synchronized display of comments and markers.<br><br>* Enabled commercial DRM (FairPlay, Widevine, PlayReady) to protect video content.<br><br>* Improved RTM stutter logging to aid issue diagnosis in weak network environments.<br><br>* Implemented jitter buffer strategy for smoother RTM playback under poor network conditions. |
|June 12, 2025 |2.7.1 |1. Fixed the issue where `userId` was not correctly logged (only affects versions V2.6.1 to V2.7.0). This ensures that log information accurately records the user identifier, facilitating easier issue tracking and debugging.<br><br>2. Fixed the issue where switching clarity or lines was ineffective when `controls` was set to `false`. This ensures that the functionality to switch clarity or lines works correctly even when the controls are hidden.<br><br>3. Optimized the playback of RTM streams on certain OPPO mobile devices. This addresses the issue where an error was thrown when playing RTM streams on specific OPPO mobile devices, ensuring a smoother playback experience. |
|May 19, 2025 |2.7.0 |Added support for multi\-protocol fallback, allowing multiple protocol URLs and a fallback order to be specified. Fallback scenarios include:<br><br><br>* Selecting a supported protocol based on the defined fallback order.<br><br>* Automatically falling back in sequence after RTM playback fails.<br><br>* Supporting error\-code\-based fallback on failure.<br><br>* Supporting custom fallback strategies for different protocols.<br><br><br>For more information, see [Pulling RTM streams](https://docs.byteplus.com/docs/byteplus-media-live/RTM-Streaming-Integration) and [Pulling FLV streams](https://docs.byteplus.com/docs/byteplus-media-live/docs-flv-streaming-integration). |
|April 21, 2025 |\- |**Documentation Update:**  Added a guide for integrating ABR (Adaptive Bitrate) playback, enabling dynamic quality adjustment based on real\-time network conditions for improved viewing experience. |
|March 10, 2025 |2.6.1 |Added support for passing a `video` DOM element via the new `mediaElement` parameter. This enables multiple players to share the same video source. |
|October 23, 2024 |2.5.1 |* The methods isMseSupported, isMMSSupported, and isFLVSupported support passing encoding information of string type to determine the browser's support for encoding and decoding information.<br><br>* Added log upload configuration check. When AppID is not configured, an error will be reported in the console of the browser developer tool, and the default AppID will be used for log reporting. |
|September 06, 2024 |2.5.0 |* New feature:<br><br>   * [RTM](https://docs.byteplus.com/en/docs/byteplus-media-live/docs-1155423#rtm) configuration supports configuring the disconnection time after pausing playback and whether it is seamless to re\-pull the stream after disconnection.<br><br>   * Optimize the implementation logic of LL\-HLS.<br><br>   * Added a method to check whether the iOS browser supports FLV format streaming playback, and supports playing FLV in iOS 17.1 and above browsers. Refer to [isFLVSupported](https://docs.byteplus.com/en/docs/byteplus-media-live/docs-1156178#isflvsupported) and [isMMSSupported](https://docs.byteplus.com/en/docs/byteplus-media-live/docs-1156178#ismmssupported) method. |
|June 12, 2024 |2.4.0 |* New features:<br><br>   * The player adds the setting of networkEvaluateInterval (network evaluation time interval) when pulling the RTM stream.<br><br>   * Adds the [getRTMNetWorkInfo](https://docs.byteplus.com/en/docs/byteplus-media-live/docs-1156178#getrtmnetworkinfo) method, which supports obtaining the network evaluation information of the RTM pull stream.<br><br>   * Adds the [getRTMStats](https://docs.byteplus.com/en/docs/byteplus-media-live/docs-1156178#getrtmstats) method, which supports obtaining the playback information of the RTM pull stream.<br><br>   * Adds the [getFLVStats](https://docs.byteplus.com/en/docs/byteplus-media-live/docs-1156178#getflvstats) method, which supports obtaining the playback information of the FLV pull stream.<br><br>   * The FLV pull stream supports adaptive bitrate (ABR) pull stream.<br><br>   * Adds the playTime attribute of the player, which supports obtaining the current playback duration. |
|February 29,2024 |2.3.0 |Version 2.x has the following improvements compared to version 1.x:<br><br><br>* Improved integration processes and reduced package size.<br><br>* Enhanced player creation processes.<br><br>* Optimized player configurations, methods, properties, and event formats.<br><br><br>> **说明**<br><br><br>> Version 2.x introduces breaking changes and is not compatible with Video\-on\-Demand (VOD). If you want to play both live streams and VOD, use previous versions of the SDK instead. Refer to [Player SDK for Web: 1.x versions](https://docs.byteplus.com/docs/byteplus-media-live/docs-player-sdk-for-web-1-x-versions) for details.<br> |
|October 16,2023 |1.6.3 |* Improvement: Since v1.6.3, the SDK uses new addresses for importing JS and CSS files. You cannot import the JS and CSS files for previous versions with the new addresses. See [Integrating the Player SDK for Web](https://docs.byteplus.com/en/docs/byteplus-media-live/docs-integrating-the-player-sdk-for-web).<br><br>* Fixed issues:<br><br>   * Some log information could not be uploaded when the SDK plays an RTM stream.<br><br>   * The value of `userId` in error messages was inconsistent with the one passed through [liveLogger](https://docs.byteplus.com/docs/byteplus-media-live/docs-api-reference#liveLogger). |
|May 5,2023 |1.0.1 |This is the first release of the BytePlus MediaLive Player SDK for Web. |
