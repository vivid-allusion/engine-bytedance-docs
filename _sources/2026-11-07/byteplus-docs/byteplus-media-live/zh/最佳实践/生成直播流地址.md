要开始直播流，您需要有效的推流地址和拉流地址。本主题介绍了通过三种不同方法生成这些地址的操作说明：批量操作的手动构建、用于快速生成单个地址的控制台地址生成器工具，以及通过 API 调用实现应用程序无缝集成。

<span id="259f72de"></span>
## 使用场景


* **手动构建**：适用于为业务应用批量生成推流地址和拉流地址。按照提供的地址构建规则，您可以在无需调用 API 的情况下使用 MediaLive 服务。

* **使用地址生成器工具**：适合生成单流地址。无需编写代码，可直接在页面完成操作。

* **使用 API**：适用于将直播流功能集成到您的应用中，实现自动生成直播流地址。


<span id="2f0ce12a"></span>
## 背景

<span id="59687c11"></span>
### 地址信息接口行为

直播流地址通常由`域名`、`AppName` 和 `StreamName` 组成，若已开启URL 鉴权，还包含鉴权信息。

<span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/760f0061f25f4875ba068a1910305167~tplv-goo7wpa0wc-image.image) </span>

下表描述了直播流地址参数。


|参数 |接口行为 |
|---|---|
|域名 |你已添加的域名。使用你的域名进行推流以生成推流地址，使用你的域名进行拉流以生成拉流地址。 |
|AppName |直播流的`AppName`。拉取指定流时，推流地址和拉流地址的`AppName`必须一致。 |
|StreamName |直播流的`StreamName`。拉取指定流时，推流地址和拉流地址的`StreamName`必须一致。<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">对于转码流，流名称由原始<code>StreamName</code>和后缀组成。后缀为你转码配置中的转码后缀。例如，<code>stream_hd</code>。</div><br> |
|AuthInfo |参考[配置URL鉴权](https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-CN)了解URL鉴权结构并构造鉴权字符串。 |


<span id="f7580405"></span>
### 地址组成规则

地址格式和组成规则因传输协议而异，具体如下：


<Tabs>
<Tab zoneid="QBe2PGGV6A" title="推流地址">
<TabTitle>推流地址</TabTitle>

<span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/643156abf4e14e9b914050c72af157ba~tplv-goo7wpa0wc-image.image) </span>


* RTMP推流地址：`rtmp://{DomainNameforStreamPushing}/{AppName}/{StreamName}?{AuthInfo}`。例如，`rtmp:// push.example.com/live/test?expire=1782309627&sign=a6937f4926**** 7b05f3987b088d473c`。如果使用OBS进行推流，`rtmp://{DomainNameforStreamPushing}/{AppName}/`作为**服务器**，`{StreamName}?{AuthInfo}`作为**流密钥**。

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">要生成 RTMPS 推流地址，请将生成的 RTMP 地址中的<code>rtmp://</code>替换为<code>rtmps://</code>。   </div>
   

* TS over SRT推流地址：`srt://{DomainNameforStreamPushing}:9000?streamid=#!::h={DomainNameforStreamPushing},r={AppName}/{StreamName},m=publish,{AuthInfo}`。例如，`srt:// push.example.com:9000?streamid=#!::h=push.example.com,r=live/test,m=publish,expire=1782309627,sign=a6937f4926**** 7b05f3987b088d473c`。

* RTMP over SRT推流地址：`rtmp://{DomainNameforStreamPushing}:1999/{AppName}/{StreamName}?{AuthInfo}`。例如，`rtmp:// push.example.com:1999/live/test?expire=1782309627&sign=a6937f4926**** 7b05f3987b088d473c`。

* RTM推流地址：`http( s)://{DomainNameforStreamPushing}:9922/{AppName}/{StreamName}.sdp?{AuthInfo}`。例如，`https://push.example.com:9922/live/test.sdp?expire=1782309627&sign=a6937f4926**** 7b05f3987b088d473c`。


<div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div>



* <div data-tips="true" data-tips-type="warning">要使用 HTTPS 推流地址或在浏览器环境中推送 RTM 流，你必须先为推流域名开启 HTTPS。更多信息，请参见<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-https-zh-CN">HTTPS 配置</a>。</div>


* <div data-tips="true" data-tips-type="warning">要包含鉴权信息，你必须先为推流域名开启 URL 鉴权。更多信息，请参见<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-CN">配置URL鉴权</a>。</div>



</Tab>
<Tab zoneid="TpEFeoV7EM" title="拉流地址">
<TabTitle>拉流地址</TabTitle>

<span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/609da30481ca476f8076d58aebd5c545~tplv-goo7wpa0wc-image.image) </span>


* RTMP拉流地址：`rtmp://{DomainNameforStreamPulling}/{AppName}/{StreamName}?{AuthInfo}`。例如，`rtmp:// pull.example.com/live/test?auth_key=1779891783-0-0-a808d5b3**** d47e28fdafb87a65ce9a`。

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">要生成 RTMPS 拉流地址，请将生成的 RTMP 地址中的<code>rtmp://</code>替换为<code>rtmps://</code>。   </div>
   

* FLV拉流地址：`http( s)://{DomainNameforStreamPulling}/{AppName}/{StreamName}.flv?{AuthInfo}`。例如，`https://pull.example.com/live/test.flv?auth_key=1779891783-0-0-e1f5a2a**** 4b5fe21cb3efdc89af901`。

* HLS拉流地址：`http( s)://{DomainNameforStreamPulling}/{AppName}/{StreamName}. m3u8?{AuthInfo}`。例如，`https://pull.example.com/live/test.m3u8?auth_key=1779891783-0-0-cd9bdb2b6**** 5e9f6f27c180a13a652`。

* 客户端拉流 SDK（BytePlus MediaLive拉流 SDK for iOS、Android、React Native和Flutter）及其他播放器的RTM拉流地址：`http( s)://{DomainNameforStreamPulling}/{AppName}/{StreamName}.sdp?{AuthInfo}`。例如，`https://pull.example.com/live/test.sdp?auth_key=1779891783-0-0-873bca4ce**** e85f357be5434067b70`。

* BytePlus MediaLive Web拉流 SDK的RTM拉流地址：`http(s)://{DomainNameforStreamPulling}/{AppName}/{StreamName}_autortm.sdp?{AuthInfo}`。例如，`https://pull.example.com/live/test_autortm.sdp?auth_key=1779891783-0-0-cd9bdb2b6**** 5e9f6f27c180a13a652`。拉流域名已开启 URL 鉴权后，用于鉴权计算的 `StreamName` 为 `{StreamName}_autortm`。例如，若地址为 `https://pull.example.com/live/test_autortm.sdp`，用于鉴权计算的 `StreamName` 为 `test_autortm`。该地址会触发自动转码，具体如下：

   * 系统会自动检测流是否包含 B帧。

      * 若存在 B帧：流会被转码以移除 B帧，并收取标准转码费用。

      * 若不存在 B帧：源流中的视频会被复制，不收取视频转码费用。

   * 系统会自动检测音频编码格式是否为 AAC 或 Opus。

      * 若音频编码格式为 AAC：音频会被转换为 Opus。若不涉及视频转码，则收取音频转码费用。更多信息，请参见 [音频转码](/docs/byteplus\-media\-live/docs\-transcoding_2\-zh\-CN#Audio transcoding)。

      * 若音频编码格式为 Opus：源流中的音频会被复制，不收取音频转码费用。

* DASH 拉流地址：`http( s)://{DomainNameforStreamPulling}/{AppName}/{StreamName}/index.mpd?{AuthInfo}`。例如，`https://pull.example.com/live/test/index.mpd?auth_key=1779891783-0-0-873bca4ce**** e85f357be5434067b70`。


<div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div>



* <div data-tips="true" data-tips-type="warning">要使用 HTTPS 拉流地址或在浏览器环境中播放 RTM 流，你必须先为拉流域名开启 HTTPS。更多信息，请参见<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-https-zh-CN">HTTPS 配置</a>。</div>


* <div data-tips="true" data-tips-type="warning">要包含鉴权信息，你必须先为拉流域名开启 URL 鉴权。更多信息，请参见<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-CN">配置URL鉴权</a>。</div>

## 前提条件


* 您已添加推流和拉流的域名，并完成 CNAME 配置。更多信息，请参见[添加域名](https://docs.byteplus.com/docs/byteplus-media-live/docs-domain-zh-CN)和[添加 CNAME 记录](https://docs.byteplus.com/docs/byteplus-media-live/docs-adding-a-cname-record-zh-CN)。

* 如需启用 HTTPS，可：

   * 使用 BytePlus MediaLive 控制台提供的在线推流工具。

   * 使用 BytePlus MediaLive 控制台提供的在线回放工具。

   * 使用 HTTPS 推流地址或拉流地址。

   * 在浏览器环境中推送或播放 RTM 流。

   更多信息，请参见[HTTPS 配置](https://docs.byteplus.com/docs/byteplus-media-live/docs-https-zh-CN)。

* 要对推流地址或拉流地址进行 URL 鉴权，必须已开启 URL 鉴权。更多信息，请参见[配置URL鉴权](https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-CN)。

* 要生成转码流的拉流地址，必须完成转码配置。更多信息，请参见[管理转码配置](https://docs.byteplus.com/docs/byteplus-media-live/docs-configuring-screenshot-capturing-zh-CN)。

* 要生成特定协议 ABR 流的拉流地址，必须完成 ABR 配置并选择对应协议类型。更多信息，请参见[管理自适应码率配置](https://docs.byteplus.com/docs/byteplus-media-live/standbystream-zh-CN)。

* 要生成加密流的拉流地址，必须完成加密配置。更多信息，请参见[管理加密配置](https://docs.byteplus.com/docs/byteplus-media-live/docs-manage-subtitle-configuration-zh-CN)。

* 手动构建单个地址；

* 通过代码批量生成。示例请参见[地址生成代码示例](https://docs.byteplus.com/docs/byteplus-media-live/docs-generating-live-stream-addresses-zh-CN#c8dfbaa6)。

## 方法二：使用地址生成器


1. 登录[BytePlus MediaLive 控制台](https://console.byteplus.com/live)。

2. 在左侧导航栏选择**工具箱** \> **地址生成器**。

3. 选择**地址类型**和**域名**，并输入自定义`AppName`、`StreamName`和过期时间。

   <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/305f90015f364f2e8ce96f4f455612de~tplv-goo7wpa0wc-image.image) </span>

   
   |参数 |描述 |
   |---|---|
   |地址类型 |选择要生成的地址类型。<br><br><br>* **推流地址**：使用该地址将流从主播推送到 MediaLive。<br><br>* **拉流地址**：使用该地址将流从 MediaLive 拉取到观众端。 |
   |域名 |根据地址类型选择推流或拉流的域名。 |
   |AppName |生成地址的 `AppName`，可包含字母（A\-Z，a\-z）、数字（0\-9）、下划线（_）、连字符（\-）和点（.），长度为 1~30 个字符。默认值为 `live`。 |
   |StreamName |生成地址的 `StreamName`，可包含字母（A\-Z，a\-z）、数字（0\-9）、下划线（_）和连字符（\-），长度为 1~100 个字符。 |
   |过期时间 |选择地址的过期时间。<br><br>过期后，该地址将无法用于发起新的推流或拉流请求。在过期前已发起的请求不受影响。<br><br><div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div><br><br><br><div data-tips="true" data-tips-type="warning">仅当所选域名已开启 URL 鉴权时，才能配置过期时间。要开启 URL 鉴权，请参见<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-CN">配置URL鉴权</a>。</div><br> |
   

4. 点击**生成推流地址**或**生成拉流地址**，即可在**结果**区域获取推流地址或拉流地址。

   * **推流地址**：支持生成带鉴权信息的推流地址。地址生成器支持以下推流协议：RTMP、TS over SRT、RTMP over SRT 和 RTM。

      <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="2">tip      </div>
      

      * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="2">如果你使用 OBS（Open Broadcaster Software）通过 RTMP 推流，可以在生成结果中获取 <strong>OBS 推流地址</strong> 和 <strong>OBS Streaming Key</strong>，并分别填写到 OBS 的 <strong>Server</strong> 和 <strong>Stream Key</strong> 字段中。      </div>
      

      * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="2">要包含鉴权信息，你必须先为推流域名开启 URL 鉴权。更多信息，请参见<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-CN">配置URL鉴权</a>。      </div>
      

      <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/c168f4ac83b440cd85c8caffef3d8286~tplv-goo7wpa0wc-image.image) </span>

* **拉流地址**：支持为源流、转码流和 ABR 流生成带鉴权信息的拉流地址。地址生成器支持以下拉流协议：RTMP、FLV、HLS（M3U8）、RTM 和 DASH。

   <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/4ba7e572d98e4d6f83fb4492893052aa~tplv-goo7wpa0wc-image.image) </span>

   * 在**拉流 URL**标签页，可找到两种 RTM 拉流地址。

      * **RTM Web SDK 回放地址**：使用此地址可通过 BytePlus MediaLive 拉流 SDK for Web 进行回放。此地址会触发自动转码，具体如下：

         * 系统会自动检测流中是否包含 B帧。

            * 若存在 B帧：流会被转码以移除 B帧，并收取标准转码费用。

            * 若不存在 B帧：源流中的视频会被复制，不收取视频转码费用。

         * 系统会自动检测音频编码格式是否为 AAC 或 Opus。

            * 若音频编码格式为 AAC：音频会被转换为 Opus。若未涉及视频转码，则收取音频转码费用。更多信息，请参见 [音频转码](/docs/byteplus\-media\-live/docs\-transcoding_2\-zh\-CN#Audio transcoding)。

            * 若音频编码格式为 Opus：源流中的音频会被复制，不收取音频转码费用。

      * **RTM 地址**：使用此地址可通过客户端拉流 SDK（BytePlus MediaLive 拉流 SDK for iOS、Android、React Native 和 Flutter）及其他播放器进行回放。

   * 在 **转码流** 标签页中，可以选择转码后缀以获取不同的转码流地址。你还可以找到两种 RTM 拉流地址。

      * **RTM Web SDK 回放地址**：使用此地址可通过 BytePlus MediaLive 拉流 SDK for Web 进行回放。此 RTM 拉流地址保留原始转码配置，并增加如下处理：

         * 系统会自动检测流中是否包含 B帧。

            * 若存在 B帧：流会被转码以移除 B帧，其他设置遵循原始转码配置，并按原始转码配置收取转码费用。

            * 若不存在 B帧：流会按照原始转码配置进行转码，并按原始转码配置收取转码费用。

         * 系统会自动检测音频编码格式是否为 AAC 或 Opus。

            * 若音频编码格式为 AAC：音频会被转换为 Opus，其他设置遵循原始转码配置，并按原始转码配置收取转码费用。

            * 若音频编码格式为 Opus：音频会被复制，不进行音频转码，其他设置遵循原始转码配置，并按原始转码配置收取转码费用。

      * **RTM 地址**：使用此地址可通过客户端拉流 SDK（BytePlus MediaLive 拉流 SDK for iOS、Android、React Native 和 Flutter）及其他播放器进行回放。

   * 在 **自适应码率** 标签页中，若 ABR 配置已开启 RTM\-ABR，可选择启动质量等级（后缀）以获取对应的 RTM\-ABR 地址。你还可以找到两种 RTM\-ABR 拉流地址。

      * **RTM Web SDK 回放地址**：使用此地址可通过 BytePlus MediaLive 拉流 SDK for Web 进行回放。此 RTM\-ABR 拉流地址保留原始 ABR 配置，并增加如下处理：

         * 系统会自动检测子流中是否包含 B帧。

            * 若存在 B帧：子流会被转码以移除 B帧，其他设置遵循原始 ABR 配置，并按原始 ABR 配置收取转码费用。

            * 如果没有B帧：子流将按照原始ABR配置进行转码，并按照原始ABR配置收取转码费用。

         * 系统会自动检测音频编码格式是否为AAC或Opus。

            * 如果音频编码格式为AAC：音频将转换为Opus，其他设置遵循原始ABR配置，并按照原始ABR配置收取转码费用。

            * 如果音频编码格式为Opus：音频将直接复制，不进行音频转码，其他设置遵循原始ABR配置，并按照原始ABR配置收取转码费用。

      * **RTM地址**：使用此地址可通过BytePlus MediaLive拉流 SDK（iOS和Android）及其他播放器进行回放。

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">要包含鉴权信息，你必须先为拉流域名开启 URL 鉴权。更多信息，请参见<a href="https://docs.byteplus.com/docs/byteplus-media-live/docs-url-authentication-zh-CN">配置URL鉴权</a>。   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">如果你无法获取<strong>RTM Web SDK 回放地址</strong>，请联系<a href="https://console.byteplus.com/workorder/create?step=2&SubProductID=P00000980">技术支持</a>。   </div>
   

5. 你还可以：

   * 点击在线推流图标，在控制台的**Web推流**页面开始推流。

   * 点击在线回放图标，在控制台的**Web拉流**页面开始回放。

   * 点击复制图标复制地址。

   * 点击二维码图标查看二维码。

   * 点击页面右上角的**历史记录**，查看已生成的地址记录。

## 方法三：**通过API**

<TabTitle>Java</TabTitle>

```Java
package demo;

import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;

public class Demo1 {
    public static void main(String[] args) throws NoSuchAlgorithmException {
        System.out.println((GenAuthUrl("testDomain", "testApp", "testStream", "testKey", 1636963457)));
    }

    public static String GenAuthUrl(String domain, String app, String stream, String secretKey, int volcTime) throws NoSuchAlgorithmException {

        String src = String.format("/%s/%s%s%d", app, stream, secretKey, unixtime);
        MessageDigest md5 = MessageDigest.getInstance("MD5");
        byte[] md5Bytes = md5.digest(src.getBytes(StandardCharsets.UTF_8));
        String sign = "";
        for (int i = 0; i < md5Bytes.length; i++) {
            sign += Integer.toHexString(md5Bytes[i] | 0xFFFFFF00).substring(6);
        }

        return String.format("rtmp://%s/%s/%s?expire=%d&sign=%s", domain, app, stream, unixtime, sign);
    }
}
```
