RTM 基于 WebRTC 技术，按照 WebRTC 标准建立点对点传输通常包括以下三个步骤：


1. 媒体协商：通信双方通过会话描述协议（SDP）进行交互。此步骤旨在确认双方支持的媒体类型、编码方法、分辨率及其他参数，以确保后续媒体传输能够顺利进行。

2. 网络地址协商：在此步骤中，双方协商网络地址以发现对端的实际 IP 地址。该步骤为媒体传输通道的构建做准备，并确保数据能够在双方之间准确传输。

3. 媒体数据的点对点传输：双方此时可以进行媒体数据的点对点传输。在此步骤中，媒体数据通过之前协商好的传输通道实时传输，从而建立 RTM 会话。

## 信令交互

在媒体数据传输之前，客户端与服务器需要协商其传输和处理音视频媒体的能力（例如，支持的格式、编码格式处理细节、质量保障方法等）。RTM 使用 SDP 传递共享的媒体能力并确保兼容性。

媒体协商通过网络进行，称为信令交互。信令交互主要使用 SDP。在信令交互过程中，可以使用不同的传输协议，包括 TCP/UDP 和 HTTP/QUIC。

<span id="f5840039"></span>
## 媒体传输

协商步骤完成后，媒体数据（包括流推送/拉取音视频数据）的传输开始。音视频数据可通过 UDP 结合 QoS 方法（如拥塞控制、丢包检测与恢复）进行传输和分发，从而实现基于 WebRTC 的媒体流。

信令交互、媒体协商和媒体传输的完整流程构成一次 RTM 会话。

流推送（即主播将音视频数据发送至服务器）和流拉取（即观众从服务器请求音视频数据）均属于单向传输，这与视频通话模式下音视频数据的全双工双向传输不同。
