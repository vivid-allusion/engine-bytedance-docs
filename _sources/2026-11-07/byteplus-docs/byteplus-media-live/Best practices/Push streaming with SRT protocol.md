This document will introduce you to the functions and usage of live video SRT streaming.

<span id="5f710556"></span>
## Context

The Secure Reliable Transport protocol (referred to as SRT hereinafter) is an open\-source low\-latency video transmission protocol. It supports optimizing the streaming media performance on unpredictable networks such as the Internet and achieving secure and reliable high\-definition video transmission and distribution.

The SRT protocol is based on the UDT protocol (the UDT protocol is a transmission protocol based on UDP), and retains the core ideas and mechanisms of UDT. It has a good packet loss retransmission capability. SRT supports Automatic Repeat reQuest (ARQ) and Forward Error Correction (FEC), which can help recover data.

<span id="458950f1"></span>
## Restrictions


* MediaLive supports two methods to push streaming with SRT protocol: RTMP over SRT and TS over SRT.

   * The TS over SRT function uses UDP port 9000;

   * The RTMP over SRT function uses UDP port 1999.

* Support live streaming push with video encoding formats of H.264 or H.265, and support pure audio live streaming push with audio encoding format of AAC and single audio track.

* After using the SRT protocol for pushing streams, it supports pulling streams and playing in four formats: RTMP, FLV, and RTM. Currently, pulling streams using the SRT protocol is not supported.

* MediaLive by default supports pushing streams using the SRT protocol. The traffic generated by pushing streams using the SRT protocol uses **Standard pricing.**

## Procedure

<span id="30d88731"></span>
### Obtain SRT push stream address

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">It is recommended that you use an <a href="https://docs.byteplus.com/en/docs/byteplus-media-live/docs-address-generator">address generator</a> to quickly generate SRT streaming addresses.</div>


You can also obtain the push streaming address by splicing it yourself according to the SRT push stream address rules. The rules are as follows.


* TS over SRT

   ```Plain
   srt://push.example.com:9000?streamid=#!::h=push.example.com,r=AppName/StreamName,m=publish,volcTime=1648717***,volcSecret=xxx
   ```
   

   Format description is shown in the following table.

   
   |Parameter |Description |
   |---|---|
   |`streamid` |Needs to start with `#!::` and comply with the writing specification of YAML format files. |
   |`h` |The value is the push domain name. |
   |`r` |The value is `{AppName}/{StreamName}`. |
   |`m` |The value is `publish`, indicating pushing stream. |
   

* RTMP over SRT

   ```Plain
   rtmp://push.example.com:1999/AppName/StreamName?volcTime=1648717***&volcSecret=***
   ```

### Push Streaming with SRT protocol

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">This chapter's example uses the latest version of OBS streaming software for streaming tests. You can use any streaming software that supports the SRT protocol for live streaming.</div>



1. Open the OBS streaming software.

2. Click **Settings** in the **Controls** area.

3. On the left navigation bar of the settings page, select **Stream**, choose **Custom** for the service, fill in the SRT streaming address in the server field, and click **OK**.

4. Click **Start Streaming** in the **Controls** area.
