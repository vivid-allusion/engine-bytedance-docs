The recording feature automatically captures your live streams and saves them as video files to your BytePlus VOD (Video on Demand) space or TOS bucket. This allows you to store, manage, and reuse your live content after the live stream ends. This topic provides step\-by\-step instructions on how to add a recording configuration to store recorded files in a VOD space or TOS bucket through the console.

## Why use recording?

By recording your live streams, you unlock a wide range of possibilities for content reuse and monetization. The primary purposes include:

* **Creating on\-demand content**: Make your live content available for viewers who missed the live stream or wish to watch again. This significantly extends the reach and lifespan of your content.

* **Repurposing and monetizing content**: Edit recorded files into highlight reels, short clips for social media, or other promotional materials. You can also place full recordings behind a paywall as exclusive content.

* **Archiving for compliance and record\-keeping**: Maintain a permanent record of your live streams for compliance, legal, training, or historical purposes.

* **Assuring quality and moderating content**: Use recordings to review stream quality and handle any user\-generated content moderation issues that may arise.

## HLS recording modes

HLS recordings support segmented recording and full recording.

### Segmented recording

Segmented recording records the live stream in segments and stores the recorded content in real time. You must configure **Fixed time** and **Duration of a TS file**.

* If there is no stream interruption, the system generates a recording file each time the configured **Fixed time** is reached.

* If a stream interruption occurs:

   * The interruption lasts for 180 seconds or less: Recording continues after the stream resumes, and no new recording is generated at the interruption point.

   * The interruption lasts for more than 180 seconds: The current recording is finalized at the interruption point. After streaming resumes, a new recording is generated.

### Full recording

Full recording does not limit the recording duration and stores the complete recording after the live stream ends. You must configure **Waiting time** and **Duration of a TS file**.

* If there is no stream interruption, one complete recording is generated.

* If a stream interruption occurs:

   * The interruption lasts for no longer than the configured **Waiting time**: Recording continues after the stream resumes, and no new recording is generated at the interruption point.

   * The interruption lasts for longer than the configured **Waiting time**: The current recording is finalized at the interruption point. After streaming resumes, a new recording is generated.

## Notes

* **Fees**:

   * Using recording will incur recording fees and storage fees. See [Recording](https://docs.byteplus.com/docs/byteplus-media-live/docs-transcoding_2) for recording fees, [Media storage](https://docs.byteplus.com/en/docs/byteplus-vod/docs-pay-as-you-go-pricing#media-storage) for storage fees if you are storing recorded files in a VOD space, and [Storage fee](https://docs.byteplus.com/en/docs/tos/docs-storage-fee) for storage fees if you are storing recorded files in a TOS bucket.

   * Selecting **Transcoding stream** or **HLS\-ABR** as the **Recording stream type** will incur transcoding fees. For more information, see [Transcoding](https://docs.byteplus.com/docs/byteplus-media-live/docs-transcoding).

* **Activation time**: After adding, updating, or deleting a recording configuration, you must wait for 3\-5 minutes and then restart pushing your stream for the new configuration to take effect.

* **File availability**: Recorded files stored in a VOD space or TOS bucket may take some time to appear. If you cannot find a recorded file, refresh the page later.

* **Recorded content quality**: The quality of recorded files depends on the stream you record. **Original stream** records the source stream that you push. **Transcoding stream** and **HLS\-ABR** record the corresponding transcoded stream or adaptive bitrate (ABR) substream. If the recorded stream contains visual artifacts, the recorded file will also contain visual artifacts.

* **Managing recorded files**: BytePlus MediaLive stores files generated by recording and time\-shifting configurations, but does not modify or delete your existing files in VOD spaces or TOS buckets. Deleting a recording configuration does not delete recorded files that are already stored. You are responsible for managing these files.

* **Configuration uniqueness**: Only one recording configuration is supported for the same domain name space, `AppName`, and `StreamName`, regardless of whether recorded files are stored in a VOD space or a TOS bucket.

## Prerequisites

* You have added a domain name for stream pushing and a domain name for stream pulling to your desired domain name space. For more information, see [Adding a domain name](https://docs.byteplus.com/docs/byteplus-media-live/docs-domain).

* To store recorded files in a VOD space, activate the [VOD service](https://console.byteplus.com/vodpaas/totalOverview/) and create a VOD space. For more information, see [Creating a space](https://docs.byteplus.com/en/docs/byteplus-vod/docs-space-management).

* To store recorded files in a TOS bucket, activate the [TOS service](https://console.byteplus.com/tos/) and create a TOS bucket. For more information, see [Creating a bucket](https://docs.byteplus.com/en/docs/tos/docs-create-a-bucket).

* To record transcoded streams, add a transcoding configuration under your desired domain name space. Make sure the transcoding configuration and the recording configuration to be added use the same `AppName` and domain name space. For more information, see [Managing transcoding configuration](https://docs.byteplus.com/docs/byteplus-media-live/docs-configuring-transcoding).

* To record HLS\-ABR substreams in a TOS recording configuration, add an ABR configuration with `HLS-ABR` as the protocol type under your desired domain name space. Make sure the ABR configuration and the recording configuration to be added use the same `AppName` and domain name space. For more information, see [Managing adaptive bitrate configuration](https://docs.byteplus.com/docs/byteplus-media-live/docs-configuring-an-hls-abr-task).

## Adding a recording configuration

* [Storing recorded files in a VOD space](https://docs.byteplus.com/docs/byteplus-media-live/docs-configuring-recordings#7be622f0): Saves your recording in BytePlus VOD. Your recording immediately becomes a video asset in a manageable space, ready for playback and further processing. Select this when your primary goal is immediate playback and video management.

   * You need to provide on\-demand playback right after the live stream ends. Storing the recording in a VOD space makes it easier to manage, process, and play the content.

   * You want to use the BytePlus VOD features. This includes things like further transcoding and adding watermarks.

   * You need a ready\-to\-use, feature\-rich video solution.

* [Storing recorded files in a TOS bucket](https://docs.byteplus.com/docs/byteplus-media-live/docs-configuring-recordings#fbac8c5c): Saves your recording in your TOS bucket without applying video\-specific features by default. Select this when your primary goal is raw file storage, archiving, or custom processing.

   * You need a long\-term archive of the original recording for compliance, legal, or backup purposes.

   * You have your own custom video processing workflow. For example, you want to download the file and feed it into your own AI analysis engine or a third\-party editing pipeline.

## What to do next

1. Add a recording event callback configuration for live streams to be recorded.

   When a recorded file is stored in your VOD space or TOS bucket, BytePlus MediaLive sends a callback message to your configured callback URL. For more information about configuring the callback URL, see [Managing callback configuration](https://docs.byteplus.com/docs/byteplus-media-live/docs-configuring-a-callback-task).

2. Use the [Address generator](https://console.byteplus.com/live/main/locationGenerate) to generate the push stream address. For more information, see [Generating stream addresses](https://docs.byteplus.com/docs/byteplus-media-live/docs-address-generator).

   1. Complete the following configurations, and click **Generates Push stream address**.

      ![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/1d65baa0c7ce4779af0cd30a0c9da55b~tplv-goo7wpa0wc-topic.webp)

      * **Address type**: Select **Push stream address**.

      * **Domain name**: Select the domain name for stream pushing within the domain name space used when adding the recording configuration.

      * **AppName** and **StreamName**: Enter the `AppName` and `StreamName` used when adding the recording configuration.

   2. Get the push stream address on the right.

3. Use the generated push stream address to push the source stream. If you use the Broadcast SDK for Web, see [Integrating the Broadcast SDK for Web](https://docs.byteplus.com/docs/byteplus-media-live/docs-integrating-the-broadcast-sdk-for-web).

4. The live stream that matches your recording configuration will be automatically recorded. Then, you can find your recorded files in any of the following ways:

   * On the [Recordings](https://console.byteplus.com/live/main/record/vod) page, find the recorded file under the **VOD** or **TOS** tab and then go to the corresponding VOD space or TOS bucket. For more information, see [Managing recorded files](https://docs.byteplus.com/docs/byteplus-media-live/docs-managing-recordings).

      > **Note**

## FAQ

### My recording failed. Why?

Recording failures are often due to configuration mismatches. Please check the following common causes:

* Mismatched `AppName` or `StreamName`: Check whether the `AppName` or `StreamName` in your recording configuration matches the stream you are pushing. If more than one configuration matches the stream, the most specific configuration takes precedence. See the `AppName` and `StreamName` descriptions in the configuration table.

* Deleted configuration: You want to record transcoded streams or HLS\-ABR substreams, but the corresponding transcoding or ABR configuration was deleted.

### Why aren't changes to my recording configuration taking effect?

After adding, updating, or deleting a recording configuration, you must wait for 3\-5 minutes and then restart pushing your stream for the new configuration to take effect.

### My old recorded file was overwritten by a new one. How do I prevent this?

This happens when the **File name** in your VOD recording configuration or the **Storage path** in your TOS recording configuration does not generate a unique file path for each recorded file. To prevent overwrites, make sure the file path is unique. We recommend including at least one time\-based variable, such as `{StartTime}` or `{EndTime}`, in the last segment of the path.

### What do I actually get when I record in HLS format? Is it one file or many?

An HLS recording includes one M3U8 playlist file and multiple TS video files. For playback, you only need to use the M3U8 file.

### How do I record a long live stream but provide only one playback URL?

To record a long live stream and provide only one playback URL, configure your recording with:

* **Recording format**: HLS

* **File generation mode**: Full recording

With this configuration, a live stream that is not split by a long interruption typically results in a single playback URL.

However, this approach may not always result in a single playback URL for very long\-duration live streams. If the stream is interrupted for longer than the **Waiting time**, the current recording is finalized and a new recording is generated after the stream resumes.

To improve the likelihood of generating a single playback URL, keep the live stream stable and avoid long interruptions.
