## Overview

The Transit Router (TR) Flow Log feature periodically collects inbound and outbound traffic flowing through a TR, including intra\-region and cross\-region traffic. It aggregates this data into log records based on custom fields and delivers them to [Torch Log Service (TLS)](https://docs.byteplus.com/en/docs/tls/What_is_TLS). You can then search and analyze these traffic logs in TLS, which facilitates business analysis and fault diagnosis.

<span id="2M50apUZ"></span>
## Billing notes

When using the TR flow log feature, the following two types of fees will be incurred:


* **Log generation fees**: The fee is billed by the TR based on the volume of logs generated. Currently, it is free of charge.

* **TLS service fees**: The generated flow logs are stored in TLS. You are charged by TLS for the storage and any related actions (e.g., search, analysis) performed on these logs. For details, see [TLS Billing overview](https://docs.byteplus.com/en/docs/tls/billable_items).

## Terms


|Term |Description |
|---|---|
|Log record |The traffic information string generated by the TR based on custom flow log fields, including source/destination IP address, source/destination port, protocol, etc. For example: `${srcaddr}${dstaddr}${srcport}${dstport}${protocol}${bytes}${tr-id}${src-region-id}${dst-region-id}${tr-attachment-id}${packets}${start}${end}${packets-lost-no-route}${packets-lost-blackhole}${packets-lost-mtu-exceeded}${direction}`. |
|Collection cycle |The time window for collecting traffic information by the TR, and delivering TR flow logs to TLS for storage according to this interval. The default is 1 minute, and 10 minutes are supported as a setting. |
|Service default policy |[IAM](https://docs.byteplus.com/en/docs/byteplus-platform/docs-overview-3) service default policies. When using the flow log function of the TR, you must authorize the service default policy to grant the TR permission to operate TLS. |
|Log project |The project management unit of data in TLS, used for the isolation and control of log resources. |
|Log topic |Data collection and storage unit in the TLS. |

## Flow log fields

TR flow logs support custom log fields. The logs generated will contain the specific fields you configure. The default format for each log entry is as follows: `${srcaddr}${dstaddr}${srcport}${dstport}${protocol}${bytes}${tr-id}${src-region-id}${dst-region-id}${tr-src-resource-account-id}${tr-dst-resource-account-id}${tr-pair-attachment-id}${tr-attachment-id}${packets}${start}${end}${packets-lost-no-route}${packets-lost-blackhole}${direction}`.

|---|---|---|
|version |\-\- |Version of TR flow log. |

## Limits


* The TR flow log feature is unavailable in regions where the TLS is unsupported, as its operation requires integration with TLS. For regions where TLS is available, see [Select an endpoint](https://docs.byteplus.com/en/docs/tls/endpoint).

* Within the same TR instance, only one flow log can be configured per TR attachment.

* Exceeding quotas for log projects and log topics in TLS may cause inability to create TR flow logs. For quota details, see [Apply for resource quota](https://docs.byteplus.com/en/docs/tls/Apply_for_resource_quota).

* Once the TR flow log is created, you cannot modify its flow log fields. To adjust them, delete the existing TR flow log and create a new one.
