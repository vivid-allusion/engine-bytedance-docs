## Overview

Transit Router (TR) supports attaching cross\-account network instances such as Virtual Private Clouds (VPCs), VPN Connects, Direct Connect (DC) Gateways, and TRs to enable private interconnection between the TR and the network instance.


* **Cross\-account network instance attachment**: With the instance sharing feature, share a TR instance in my account with any other account or enterprise organization. This enables mutual access between TR instances within my account and another account's network instance (such as VPC, VPN, and DC Gateway) via the TR.

   * **Share with any account**: The Owner can share resources with any root user. If the Owner belongs to an enterprise organization, resources can also be shared with the entire enterprise organization, departments, or member accounts.

   * **Share within an enterprise organization**: The Owner must be an administrator of the enterprise organization, and can only share resources with this organization and its organizational units or member accounts.

* **Cross\-account peering attachment**: Includes cross\-account inter\-region attachments. You don't need to share your local TR instance. Create it directly using the peer Account ID and TR Instance ID; creation completes once the peer TR authorizes it.

## Billing notes


* The account that creates a cross\-account network instance attachment is the Shared User​, and bears the attachment fee and traffic processing fee generated by the attachment.

* **Cross\-account inter\-region attachment:**  Both accounts can add to the bandwidth package in my account. The bandwidth package fee is borne by the account that creates it (the shared user).

## Limits


* The Owner can share a single TR instance with up to 10 Shared Users by default. A single account can accept up to 10 shared TRs in a single region by default. If the default quota cannot meet your requirements, access [the Quota Center](https://console.byteplus.com/quota/productList/ParameterList?ProviderCode=TransitRouter) to adjust.

* The Owner cannot delete a TR instance that is currently being shared. The shared unit must be deleted first.

* Shared TR instances do not support cross\-account multicast.

   * The Owner can only select subnets under my account when configuring multicast.

   * The Shared User cannot configure multicast.

* When creating a cross\-account peering attachment, both TR instances must not be shared instances.
