**TransitRouterId ** <span data-label="purple">String</span> <span data-api-tag="require|pz2UEa">必选</span>`Example: tr-7qthudw0ll6jmc****`</a\>

The ID of the Transit Router (TR) instance. You can call the [DescribeTransitRouters](https://docs.byteplus.com/en/docs/transitrouter/DescribeTransitRouters) API to obtain the TR instance ID.



**Direction ** <span data-label="purple"> String  </span><span data-api-tag="require|PaXlsX">必选</span> `Example value: In`

The direction of the route policy. Values:


* In: Inbound. The direction that TR receives routes from a network instance only if they meet the route policy.

* Out: Outbound. The direction that TR synchronizes routes to a network instance only if they meet the route policy.



**TransitRouterRoutePolicyTableName ** <span data-label="purple"> String  </span>`Optional` `Example: tr-routepolicy-for-rtb1`

The name of the route policy.


* Must start with a letter, number, or Chinese character. May include letters, numbers, Chinese characters, and the following symbols: periods (.), underscores (_), and hyphens (\-).

* Must be 1 to 128 characters.

* If you do not provide this parameter or leave it unset, it defaults to the ID of the route policy.



**Description ** <span data-label="purple"> String </span>`Optional` `Example: A route policy for migrating services with AsPath appending`

The description of the route policy.


* Must start with a letter, number, or Chinese character. May include letters, numbers, Chinese characters, and the following symbols: commas (,), periods (.), underscores (_), spaces ( ), equal signs (=), hyphens (\-), Chinese commas ( ， ), and Chinese periods ( 。 ).

* Must be 0 to 255 characters.

* If you do not provide this parameter or leave it unset, it defaults to an empty string.



**ClientToken ** <span data-label="purple"> String </span>`Optional` `Example value: 123e4567-e89b-12d3-a456-42665544****`

* This parameter value is auto\-generated by the client. Ensure uniqueness across requests, preventing duplicate actions caused by multiple client retries during API timeouts or server internal errors.
