Before the first use of Message Queue for Kafka, cross\-service access authorization is required to allow Message Queue for Kafka to access other service resources under the current account, such as Virtual Private Cloud (VPC). This topic describes how to authorize cross\-service access.

<span id="注意事项"></span>
## Precautions


* Cross\-service access authorization is needed only before you initially create a Kafka instance. Once authorized, Kafka can access resources in other services until the deletion of service\-associated roles.

* Permissions on service\-associated roles are generated by the system and cannot be changed. To revoke authorization, delete the roles.

* We recommend that you use BytePlus account to complete cross\-service access authorization. Otherwise, when an IAM user creates the first Kafka instance, cross\-service authorization may fail due to a lack of permission to create service\-related roles. If cross\-service access authorization by IAM users is needed in your business scenario, grant the IAMFullAccess system policy to IAM users.


<span id="背景信息"></span>
## Background information

Message Queue for Kafka instances must be associated with resources like VPCs and subnets. When you create a Kafka instance, Message Queue for Kafka has to access to services such as VPC to retrieve lists of VPCs and subnets. Before you initially create a Kafka instance, authorization for the Message Queue for Kafka service is required to allow it to assume the ServiceRoleForKafka role. This role has a set of default permission policies, enabling Message Queue for Kafka to access other service resources under your account.

<span id="操作步骤"></span>
## Procedure


1. Log on to the [Message Queue for Kafka console](https://console.byteplus.com/kafka).

2. In the top menu bar, select the Region in which you want to create an instance.

3. On the upper\-left corner of the **Instances** page, click **Create Instance**.

4. On the **Cross\-service access request** page that appears, verify the associated role and trust relationship, and click **Authorization**.

   Following successful authorization, the created ServiceRoleForKafka service\-associated role appears in the IAM roles list.


<span id="后续操作"></span>
## What to do next

Upon completing authorization, you are returned to the **Instances** page, where you can click **Create Instance** to create your first Kafka instance.
