Message Queue for Kafka is a distributed, message\-oriented middleware service based on Apache Kafka. It features high throughput and high scalability. Message Queue for Kafka allows you to publish and subscribe to streaming data and store them in multiple replicas. It is used in a wide range of scenarios such as log compression and collection, streaming data processing, message decoupling, and traffic peak clipping.

Message Queue for Kafka offers out\-of\-the\-box services that require no code modification. This helps you focus more on business development and frees you from cumbersome deployment and operations and maintenance (O&M) work.

<span id="产品功能"></span>
## Features


* Efficient sending and receiving of messages: Message Queue for Kafka maintains a high throughput of messages that are sent to and received from Kafka clusters even if a large number of messages are accumulated. It allows you to reuse consumed messages or clear accumulated messages. This eliminates the need to be concerned about data O&M and helps easily recover your business from failures.

* Clustered deployment: Message Queue for Kafka supports clustered deployment and multi\-replica data storage. This ensures high availability of data and services.

* Monitoring and alarming: Message Queue for Kafka provides real\-time statistics of message production and consumption. It also monitors various data such as consumption delay and message accumulation and generates alarms in real time. This helps you detect issues at the earliest opportunity.


<span id="应用场景"></span>
## Use scenarios

<span id="流计算处理"></span>
### Stream computing

Faster data computing and analysis are required in the fields of financial and scientific computing due to large data volumes and real\-time computing needs. In a conventional data processing flow, data is collected first and then stored in a database for query and analysis. This approach no longer meets growing needs. Message Queue for Kafka can be used in conjunction with Apache Flink and other stream computing engines. They together compute and analyze real\-time data and quickly apply the analysis results to the next service node.

<span id="流量削峰"></span>
### Traffic peak clipping

As for e\-commerce systems or large\-scale websites, the processing capabilities vary among different systems. During a major event such as a flash sale or new product launch, burst traffic in an upstream system may pose a challenge to some downstream systems that have low processing capabilities. If no corresponding protection or caching mechanism is available, this may lead to an overload or even crash of these systems. As a result, loss of business data can occur. Message Queue for Kafka can temporarily cache surge requests from the upstream system when a traffic spike occurs. It also allows the downstream systems to process access requests according to their actual message consumption capabilities. This enables the downstream systems to run smoothly and stably within the safe usage level and prevents downstream subscription systems from crashing due to traffic spikes.

<span id="日志分析"></span>
### Log analysis

Message Queue for Kafka decouples the application system from the log analysis system and acts as a bridge between these systems. The application system asynchronously sends the logs generated by multiple application hosts to a Message Queue for Kafka cluster in batches. The log analysis system uses Hadoop or other systematic data storage and analysis systems to extract logs for statistical analysis at any time.

The low latency of Message Queue for Kafka ensures smooth log collection without interfering with business operations. Compared with Apache Kafka, Message Queue for Kafka achieves enhanced data persistence and lower end\-to\-end latency under the same performance conditions.
