VMP provides Alert Center, which offers various features and enables you to quickly configure alerts for monitoring objects. This topic describes the common glossary of Alert Center.

<span id="mzVlPX9g"></span>
## Alert rule

VMP allows you to configure alert rules at multiple levels. In this way, you can specify different urgency levels by using different durations and thresholds. The system executes alert PromQL calculations every 1 minute and then generates alerts based on the results at different time points and the configuration of different levels for alert rules. <div data-tips="true" data-tips-type="default">Alert event: PromQL statements configured in alert rules can generate many time series. If a time series reaches both the alert threshold and the alert duration during alert evaluation, it is referred to as an alert event.</div>


After alerts are generated, VMP determines whether to send alert notifications based on the alert aggregation policies bound to the corresponding alert rules. After VMP determines sending alert notifications, the corresponding alerts will not be sent if the alerts match alert silence policies. The alert notifications will be sent through different channels based on the configured alert notification policies.

<span id="UXJYAdXS"></span>
## Alert aggregation policy


1. **Aggregation dimension**: You can aggregate alerts only by alert rules. In this way, when an alert notification is sent, all alerts in the notification originate from the same alert rule.

2. **Aggregation interval**: After an alert rule generates the first alert, the system checks whether a new alert event or recovery event is generated based on the alert aggregation interval. If a new event is generated, an alert notification will be sent at the end of the interval.

3. **Notification interval**: If no change occurs in alerts within an alert rule, an alert notification will be sent again when the alarm notification interval is reached.

4. **Time when the first alert notification is sent**: Time when the first alert event is generated + Waiting time configured by VMP.



|**Alert Level** |**First notification waiting time** |
|---|---|
|P0 |30s |
|P1/P2 |60s |

## Alert notification template

If the default alert notification template provided by VMP does not meet your business requirements, the system allows you to create custom alert notification templates. For more details, refer to [Custom alert notification templates](https://docs.byteplus.com/en/docs/vmp/variable-structure-and-parameters?lang=zh).

## Annotation and Label

If the native alert content generated by alert rules does not meet your business requirements, the system allows you to configure additional annotations or labels in the alert rules.


* **Label**: Specify a group of additional labels to be added to alerts. If the added labels conflict with any label calculated by PromQL, the original label values will be overwritten in notifications. If the label value is left empty, the labels will not be displayed in notifications. The label value can be defined through plain text or a template.

* **Annotation**: Specify a group of information labels, which are typically used to store longer supplementary information, such as alert descriptions or runbook URLs. The annotation value can be specified through a template.


<span id="RLHPWA3Q"></span>
### Template

Labels and annotation values can be declared through the [Go template](https://pkg.go.dev/text/template), with the following two variables available:


* `$labels` **: ** the original label key\-value pairs calculated by PromQL in alert rules. You can retrieve the value of a specific label by using `{{$labels.<labelname> }}`.

* `$value` **:**  the current value calculated by PromQL in the alert rules.


In addition, VMP supports many ease\-of\-use [functions](https://prometheus.io/docs/prometheus/latest/configuration/template_reference/#functions) in templates like native Prometheus. However, [query-type](https://prometheus.io/docs/prometheus/latest/configuration/template_reference/#queries) functions are not supported.

### Example

Add the label `docKey: docValue` and the annotation `detail: {{ $labels.instance}} in {{$labels.cluster}} has been scraped` to an alert rule.
