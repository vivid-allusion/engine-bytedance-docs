An alert notification policy is used to specify alert contact groups that will receive alerts if alerts at different levels are triggered and restored. This topic describes how to configure an alert notification policy.

## Prerequisites

* Notification objects have been created based on the selected notification method, such as contacts, contact groups, callback addresses, and on\-call schedules. For more information, see [Notification objects](https://docs.byteplus.com/en/docs/Observability_Platform/Notification_objects) and [Creating on-call schedules](https://docs.byteplus.com/en/docs/Observability_Platform/Creating_on-call_schedules).

* A notification template has been created based on the selected notification method, such as notification templates for phone calls, email, Feishu bot, DingTalk, and a general callback address. For more details, see [Creating notification templates](https://docs.byteplus.com/en/docs/Observability_Platform/Creating_notification_templates).

## Limits

* A notification policy is a collection of notification methods. Supported notification methods vary by cloud service. For more details, see the descriptions of notification methods in [Alert Center overview](https://docs.byteplus.com/en/docs/Observability_Platform/Alert_Center_overview).

* You can create up to 1,000 notification policies.

* You can add up to 10 contacts, 10 contact groups, 10 on\-call schedules, and 10 webhook URLs for each notification policy.

* You can add up to 10 orchestration plans, 10 message queues, and 10 log services.

## Procedure

1. Log in to the [Cloud Monitor console](http://console.volcengine.com/observe/cloud-monitor/overview).

2. In the left navigation bar, click **Notification** \> **Notification policy**.

3. Select the **Notification Policy** tab, click **Create notification policy**, and configure the notification policy parameters as needed.

   |Parameter |Description |
   |---|---|
   |Policy name |Specify a name for the notification policy as a unique identifier. Duplicate names are not allowed. |
   |Effective time |The effective time of the notification policy, which can be configured as needed. |
   |Alert level configuration |The configuration methods of alert levels.<br><br><br>* **Hierarchical configuration**: Configure different notifications for alerts of different severity levels. ## What to do next

You can use the created notification policies for each product in alert tasks or alert policies. When an alert is triggered, notification messages are sent to the contacts in the display style specified by the notification policy. For configuration examples of alert tasks or alert rules, see [Creating Cloud Monitor alert rules](https://docs.byteplus.com/en/docs/Observability_Platform/Creating_Cloud_Monitor_alert_rules) and [Creating cloud service event rules](https://docs.byteplus.com/en/docs/Observability_Platform/Creating_cloud_service_event_rules).
