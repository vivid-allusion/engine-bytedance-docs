This topic describes how to create an agent runtime, covering configurations such as deployment method, access mode, permissions, and access control.

## Prerequisites

Before using AgentKit, first activate the **core basic services**. You can activate other services as needed based on your model call, deployment method, network access, monitoring, and security requirements.

|Category |Description |
|---|---|

If AgentKit is not activated, log in to the [AgentKit console](https://console.byteplus.com/AgentKit) and follow the system prompts to complete the operations.<br><br>   > The first time you log in to the AgentKit console, the platform will automatically select the dependent products required to use AgentKit basic features (such as veFaaS, API Gateway, Container Registry, and Code Pipeline). You can also select other products based on your needs. ## What to do next

### Test the agent

You can check whether an agent works as expected in the console or by executing the` curl` command. For details, refer to [Calling agents](https://docs.byteplus.com/en/docs/agentkit/Sample_calls_for_text_prompts).

### Observe the agent

Agent operation typically involves stages such as model calls, tool execution, memory retrieval, and knowledge base retrieval. Once observability is enabled, AgentKit and the VeADK SDK automatically collect traces (call chains) and metrics for each stage based on OpenTelemetry and deliver the data to the observability platform.

On the "**Observability**" page, you can view runtime monitoring (such as request volume, latency, and error rate), trace analysis (the complete call chain), session analysis, model monitoring (such as token consumption), and log analysis. Observability data is also a prerequisite for subsequent evaluation. For details, refer to [Observability](https://docs.byteplus.com/en/docs/agentkit/Observability-).

### Evaluate the agent

Evaluation measures the agent's performance across the three dimensions of effectiveness, performance, and cost in a structured manner, providing a basis for release decisions and iterations.

The evaluation mechanism typically consists of three parts: evaluation sets, evaluators, and experiments. Evaluation sets provide standardized inputs and reference answers. Evaluators score results based on predefined rules using either an LLM or code. Experiments are responsible for combined execution and aggregating result metrics, while also supporting comparative analysis across multiple experiments. For details, refer to [Evaluation](https://docs.byteplus.com/en/docs/agentkit/Evaluation).

## Related documents

After the agent runtime is created, you can integrate the following capabilities into the agent as needed:

* [Integrate a sandbox template](https://docs.byteplus.com/en/docs/agentkit/Integrating_tools_in_agent): Provides the agent with an isolated code execution environment for running code, operating browsers, and performing other tasks.

* [Integrate a session resource](https://docs.byteplus.com/en/docs/agentkit/Integrating_session_resources_in_agents): Provides the agent with short\-term memory capabilities. This feature supports session connection maintenance and context management.

* [Integrate a memory](https://docs.byteplus.com/en/docs/agentkit/Integrating_memories_in_agent): Provides the agent with long\-term memory capabilities. This enables cross\-session context retrieval, personalized interaction, and continuous learning.

* [Integrate a knowledge base](https://docs.byteplus.com/en/docs/agentkit/Integrating_knowledge_base_in_agent): Enables the agent to call a knowledge base via APIs, achieving low\-cost, maintainable, updatable, and traceable knowledge retrieval.

* [Integrate an MCP service](https://docs.byteplus.com/en/docs/agentkit/Integrating_MCP_service_in_agent): Enables the agent to call an MCP service without code changes, thereby enhancing interaction with large models and existing systems.

* [Integrate a skills space](https://docs.byteplus.com/en/docs/agentkit/Integrating_Skills_into_agent): Inject skills into a skills space and integrate them into an agent. This enables the agent to quickly extend specific capabilities and adapt to different business scenarios.

After the features are integrated, you need to correctly configure all dependencies in` requirements.txt`, package the agent, upload the agent to the Container Registry, [update the agent runtime image version](https://docs.byteplus.com/en/docs/agentkit/Updating_custom_images), and then republish the agent.

If you build the agent runtime by using AgentKit CLI, VeADK, existing agent migration, or TRAE, update the code, configurations, and dependencies in your local project, and then rebuild and release the runtime using the corresponding method. For details, refer to [Advanced quick start​: Developing and deploying agents](https://docs.byteplus.com/en/docs/agentkit/Developing_and_deploying_agents), [Advanced quick start​: Migrating existing agents](https://docs.byteplus.com/en/docs/agentkit/Migrating_existing_agents), and [Natural language-driven: Developing and deploying agents with TRAE](https://docs.byteplus.com/en/docs/agentkit/developing_and_deploying_agents_with_trae).
