OAuth connection credentials are used to initiate authorization with third\-party identity providers on behalf of users or agents and obtain access tokens with a validity period. After creation, agent code can reference the configuration by credential name. The platform handles credential storage, authorization interactions, and outbound injection, so you do not need to hardcode client secrets or access tokens in the code.

Create an OAuth connection credential for scenarios where OAuth2 authorization is required to access external services, such as obtaining short\-lived access tokens on behalf of users or agents.

## Recommended scenarios

* **Access third\-party services on behalf of end users**

   When an agent needs to access Feishu, GitHub, Coze, or other services that support OAuth2 on behalf of a user, it can obtain access tokens via the user delegation flow and call target APIs within the scope granted by the user.

* **Use a machine identity to call downstream services**

   When an agent needs to call a third\-party system as itself or as a service identity, and the target service supports machine\-to\-machine authorization, it can obtain a short\-lived token via the M2M flow. This is suitable for background calls without user interaction.

* **Centrally manage OAuth client configurations**

   When your business requires centralized maintenance of client IDs, client secrets, permission scopes, callback URLs, token validity periods, and other OAuth parameters, you can use OAuth connection credentials for unified management to avoid configurations being scattered across different agents or runtime environments.

* **Manage credentials by project and identity pool**

   When different businesses, teams or environments require independent management of OAuth connections, you can assign and isolate resources by project and agent identity pool, reducing the risk of credential misuse across businesses or environments.

## Prerequisites

* **Prepare OAuth client information (optional)**

   If you need to **manually create credentials**, first go to the developer platform of the target identity provider to create an OAuth application or client. After creation, obtain the client ID and client secret generated by the platform, and enter them in the identity provider configuration section of AgentKit.

   > **warning**

   > If you use **Dynamic Client Registration (DCR)** for integration, confirm in advance that the identity provider supports DCR, and prepare the corresponding discovery URL, registration endpoint URL, and required authentication information for automatic client registration.

   Creation methods and credential names may vary across providers. Refer to the table below:

   |**Provider type** |**Preparations** |**Related documents** |
   |---|---|---|
   |GitHub |Create an OAuth App, configure the Homepage URL and Authorization callback URL, and obtain the client ID and client secret. |[Creating an OAuth app](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app) |
   |Feishu |Create or open a Feishu application, and obtain the App ID and App Secret in "Basic Info \> Credentials & Basic Info". App ID corresponds to the client ID, and App Secret corresponds to the client secret. |[How to obtain the App ID and App Secret of an application](https://open.larkoffice.com/document/server-docs/im-v1/faq#534e3009) |
   |Coze |Create an OAuth application and obtain the Client ID and Client Secret.<br><br>> When creating the OAuth application, enter the callback URL actually used by AgentKit in the current OAuth flow. |[Create an OAuth application and obtain client credentials](https://docs.coze.cn/developer_guides_oauth_code#3fba3e8e) |
   |User pool |Create a user pool, then create a client within the user pool to obtain the corresponding client ID and client secret. |[Creating user pools](https://docs.byteplus.com/en/docs/agentkit/create-user-pool?lang=en) and [Creating clients](https://docs.byteplus.com/en/docs/agentkit/create-client-side?lang=en) |
   |Custom |Go to the developer platform of the target identity provider to create an OAuth client, and configure the callback URL, permission scope, and other OAuth parameters according to the official documentation. |Refer to the official documentation of the target identity provider. |

* **Prepare KMS key resources (optional)**

   If you choose to use a "custom primary key" for encryption when creating credentials, first create a usable key ring and primary key in KMS, and ensure that the current account has permission to use the primary key for encrypting and decrypting credentials. For details, see [Getting started with key management](https://docs.byteplus.com/en/docs/KeyManagementSystem/KeyManagementQuickStart?lang=en).

   > **tip**

   > If you do not need to manage keys yourself, you can use the system default key. The platform manages the encryption configuration to reduce extra preparation work.

* **Create the target agent (optional)**

   If you want to complete the association during credential creation, create the [target agent](https://docs.byteplus.com/en/docs/agentkit/Creating_agent_runtimes_in_console?lang=en) that will use this credential in advance. After the association, the target agent can reference this credential to make outbound calls at runtime.

   > **tip**

   > If you are not sure which agent needs to be associated, you can create the credential first and then [associate it with an agent](https://docs.byteplus.com/en/docs/agentkit/associating-and-disassociating-agents?lang=en) later.

## Procedure

### Step 1: Select a credential type

1. Log in to[ the AgentKit console](https://console.byteplus.com/agentkit).

2. In the left navigation pane, select "Identity and Permission  **\>**  Credential management".

3. Click "Create credential". On the "Select type" page, select "OAuth connection".

4. Click the "Next" button.

2. **Configure identity provider parameters**

   The identity provider parameters vary by creation method. Based on the creation method selected earlier, click the **Create manually** or **Dynamic Client Registration (DCR)**  tab, and complete the configuration according to the corresponding parameter descriptions.

   **Dynamic Client Registration (DCR)**

When the creation method is set to **Dynamic Client Registration (DCR)** , the system automatically registers an OAuth client and obtains information such as the client ID and client secret based on the public OAuth 2.0 or OpenID Connect (OIDC) configuration information from the identity provider.

   1. **Select configuration type**: Specify how the system obtains the OAuth/OIDC endpoint information from the identity provider. Both automatic discovery and manual configuration are supported.

      * **Automatic discovery**

         Enter the discovery URL provided by the identity provider. The system will obtain the registration endpoint, authorization endpoint, token endpoint, and other related configurations from the discovery document. Applicable to scenarios where the identity provider supports the standard OAuth/OIDC discovery mechanism.

      * **Manual configuration**

         Manually enter information such as the Issuer URL, registration endpoint, authorization endpoint, and token endpoint. Applicable to scenarios where the identity provider does not provide a standard discovery URL or where specific endpoints need to be used.

   2. Configure the corresponding parameters based on the selected configuration type.

      **Automatic discovery (recommended)**

In the "Automatic discovery URL" field, enter the OAuth/OIDC discovery document URL provided by the identity provider. The system will read this document and automatically obtain the relevant endpoint information. Example: `https://example.com/.well-known/openid-configuration`

      > **tip**

      > Make sure that this URL is accessible and returns a valid discovery document. For the specific URL, refer to the official developer documentation from the target identity provider.

      **Manual configuration**
