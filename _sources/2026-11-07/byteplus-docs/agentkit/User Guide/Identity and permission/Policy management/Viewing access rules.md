The access rule details display the rule's authorized principal, target resources, operation type, and underlying Cedar policy statement. This topic describes how to view details of an access rule to verify permission configurations, troubleshoot access issues, and conduct permission audits.

## Recommended scenarios

* **Verify access permissions of a user, department, or user group**

   When you need to verify the authorization configuration of a specific user, department, or user group, view the related access rules. Check whether the principal scope, target resources, action types, and additional conditions meet expectations.

* **Check the exposure scope of a resource**

   When you need to determine which users can access a specific agent or MCP tool, view the target resources and principal scope configured in the access rules. Confirm that the resource is exposed only to the intended users, departments, or user groups to avoid over\-authorization.

* **Troubleshoot access failures**

   When a user reports that they cannot enter an agent or cannot call an MCP tool, view the access rules to check whether an allow rule covers the user and the resource, whether any deny rule is hit, and whether the condition expressions in the rules match the actual request.

* **Perform a permission audit**

   During a permission audit or security review, view the underlying Cedar policy statements in the access rules to verify whether the rules follow the principle of least privilege and whether there are expired rules, over\-authorization, or access scopes that are no longer needed.

## Procedure

1. Log in to the [AgentKit console](https://console.byteplus.com/agentkit).

2. In the left navigation pane, select "Identity & Permission  **\>**  Policy management".

3. Click the name of the target permission policy space.

4. On the access rule list page, click the name of the target access rule to view the following information:

   |Tab |Description |
   |---|---|
   |Rule |Displays the core information of an access rule in natural language, suitable for quickly confirming the objects governed by the rule and when it takes effect. The information includes the target rule summary, authorized subject ID, and evaluation method.<br><br>> Rule summary: describes the business meaning of the rule in natural language, typically including the rule effect, access principal, action type, and target resource. For example, "Allow specified users to call the target agent" or "Deny a specific user group from calling the specified tool". |
   |Simulate evaluation |Through a simulated evaluation, you can quickly verify whether permission boundaries meet expectations and locate the root cause when an agent cannot be accessed or an MCP tool cannot be called. [Learn more](https://docs.byteplus.com/en/docs/agentkit/simulating-evaluation?lang=en) |
   |Advanced settings |Displays the underlying configuration of the rule in the policy service. This view is suitable for policy administrators, security auditors, or users familiar with Cedar who need to verify technical details, including:<br><br><br>* **Policy name**: The policy identifier in the system, which can be used for auditing, troubleshooting, and associating policy service records.<br><br>* **Policy statement**: A Cedar statement generated by the system or written by the user, which includes the rule effect, access principal, action type, target resource, and additional conditions.<br><br>* **Middle\-tier agent**: The chain of agents that are traversed before the target resource is called. When no middle\-tier agent exists, "None" is displayed.<br><br>* **Resource type**: The type of target on which the rule acts, such as an agent, an MCP service, or a specific tool. |
