This topic reviews the operations in AgentKit that may trigger charges during resource creation, deployment, configuration, calling, and data processing, helping you quickly identify which fees an operation may generate and when those fees start and stop accruing.

> **warning**

* > Each AgentKit billing item is charged independently based on actual usage. A single operation may incur compute, request, index, or public network traffic fees at the same time.

* > This topic does not list fixed prices. Refer to the console order page, product pricing page, and the latest announcements for actual prices.

* > Stopping requests does not necessarily stop all fees. If resources such as instances or indexes are still retained, related fees may continue to be incurred.

## Billing trigger logic

AgentKit uses a pay\-as\-you\-go (postpaid) billing model. The system aggregates actual usage of each billing item on an hourly basis and automatically deducts the amount from your available account balance. To view the billing items, billing units, and prices for AgentKit, see [Billing overview](https://docs.byteplus.com/en/docs/agentkit/Billing_items).

From an operational perspective, fees are typically triggered by the following actions:

* First, keeping instances running or retained — for example, when the runtime minimum instance count is greater than 0.

* Second, initiating calls, retrievals, or model inference — for example, calling services through the gateway or performing retrieval with a toolset.

* Third, uploading, indexing, vectorizing, or writing data — for example, vectorizing knowledge base documents.
