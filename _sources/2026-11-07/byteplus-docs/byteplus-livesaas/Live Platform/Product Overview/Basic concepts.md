This topic lists the basic concepts in BytePlus Live.


|**Term** |**Description** |
|---|---|
|SaaS (Software as a Service) solution |SaaS is a service model based on cloud computing. You can quickly set up your own live streaming platform by using the BytePlus Live service as needed, without the need to build, maintain, and update the software yourself, which significantly reduces the investment and operation costs of your enterprise. The BytePlus Live console is the SaaS solution provided by BytePlus Live. |
|aPaaS (Application Platform as a Service) solution |A cost\-effective, end\-to\-end integration solution offered by BytePlus Live for customers with development capabilities. The solution covers the host\-side, console, and viewer\-side, allowing customers to subscribe to services as needed and quickly establish their own branded live streaming service system. |
|Push stream |The process of transmitting live content to live streaming platforms via the Internet in real time. For example, transmit live content from live streaming tools like OBS to live rooms of BytePlus Live. |
|Push stream address |A string used to tell where to transmit live content. Generally, the string is automatically generated by a live streaming platform. You can copy the string to live streaming tools like OBS to synchronize the live content to the live streaming platform where the string is generated. |
|Pull stream |The process of getting live content from a live streaming platform and playing the content. For example, when viewers watch a live stream, their devices get live content from a live streaming platform and display the content on their screens. BytePlus Live gets live content from other platforms and plays the content also applies to this situation. |
|Pull stream address |A string used to tell where to get live content. Generally, the string is automatically generated by a live streaming platform. You can synchronize live content from other live streaming platforms to BytePlus Live by using such strings, allowing viewers to watch live content synchronized from multiple platforms on a single platform. |
|Live room |A virtual space where viewers can watch videos, interact with other viewers and the host, and participate in interactive activities like lucky draws. |
|Viewing page |The page designed for watching videos, engaging in interactions, and displaying specific content. |
|Viewing page address |The address used by viewers to watch live videos, previews, and playbacks. |
|Live stream |The live content transmitted to viewers' devices in real time via the Internet for real\-time viewing. |
|Playback |The live stream recording generated after a live stream ends, which can be released to the viewing page for viewers to watch. |
|Status of a live room |A live room has one of the following statuses:<br><br><br>* Live: Viewers can watch live videos.<br><br>* Preview: Viewers can watch a preview if the preview is uploaded, otherwise view the cover of the live room.<br><br>* Playback: Viewers can watch playbacks.<br><br>* Over: The live stream has ended but no playback is released to the viewing page. |
|Cover of a live room |The image displayed on the player when a live room is in the **Preview** status but no preview is uploaded or in the **Over** status. |
|OBS (Open Broadcaster Software) |A free and open\-source software for video recording and live streaming, compatible with Windows, macOS, and Linux operating systems. |
|Activity ID |The unique identifier of a live room. You can get the ID in the upper\-left corner of the live room on the BytePlus Live console. |
|Pull stream protocol |A protocol used to transmit live content from other platforms to a specific platform, such as BytePlus Live, via the Internet, enabling synchronous playing across different platforms. For example, BytePlus Live supports pulling streams using the RTMP, HLS, or FLV protocol. |
|Live streaming protocol |A protocol used to transmit live content, ensuring stable transmission and viewing quality. Different live streaming platforms and devices may use different live streaming protocols. For example, BytePlus Live's Viewer SDK for Android, Viewer SDK for iOS, and Web Viewer SDK (PC\-side) use the HTTP\-FLV protocol, while Web Viewer SDK (mobile\-side) uses the HLS protocol. |
|Vid |Video ID, the unique identifier of a video file. |
|BytePlus account |An account used to sign up BytePlus, with full administrator permissions and complete control over the resources and permissions of the entire account. |
|IAM user |An account created by the BytePlus account and used to manage resources. However, typically with limited permissions. |
|Role |A collection of feature permissions. For example, assigning the Operation role to an IAM user grants the user view permission to live rooms and pages on the BytePlus Live console. |
|Organization |A collection of IAM users. Departments or subsidiaries of an enterprise can be divided into different organizations, which isolates resources between organizations and allows for the independent management of resources created by users within each organization. |
|Bullet comments |Dynamic, real\-time comments that float across the screen during online videos or live streams. These comments provide an interactive and engaging way for viewers to express their thoughts, reactions, or questions as they watch the content. |
