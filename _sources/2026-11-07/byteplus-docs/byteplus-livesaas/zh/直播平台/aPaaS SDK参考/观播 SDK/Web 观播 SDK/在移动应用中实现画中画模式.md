为确保观众在离开主观看页时仍能持续关注在线流或点播内容，可以实现画中画（PiP）模式。本指南为移动应用开发者提供了如何通过在原生应用与网页内容之间建立通信桥梁，启用 Web 观播 SDK（v1.1.3及以上）画中画功能的操作说明。

<div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div>



* <div data-tips="true" data-tips-type="warning">该方案旨在建立 Web 与 Native 之间的通信机制，要求 Native 集成方具备一定的开发能力，以实现通信并调整 WebView 窗口的大小。</div>


* <div data-tips="true" data-tips-type="warning">在本文档中，<em>Native</em> 指的是移动应用。</div>

## 方案介绍

作为原生应用集成合作伙伴，你可以在应用中使用 WebView 打开直播间的 H5 页面，并根据需要调整 WebView 窗口的大小。此外，你可以使用`JSBridge`与 H5 页面（网页端）进行通信，并通过`postMessage`方法实现数据传输与交互。

<span id="131d1327"></span>
## 前提条件

在 Android 端，你需要自行实现`invokeNative`方法，以便网页端向原生端发送消息。

<span id="23d000da"></span>
## 详细流程

<span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/a6a2ccd6184a4fb4a3e63df4ab6e6bcf~tplv-goo7wpa0wc-image.image) </span>


1. 观众访问观看页后，原生应用会检测到网页组件的`INIT_FINISH`事件，表明`JSBridge`已加载完成。

2. 检测到网页组件的`CREATE_PLAYER`事件后，原生应用确认播放器已创建，并获取流是否为直播流以及直播间是否为竖屏模式的信息。

3. 当观众离开观看页时，原生应用需进入画中画模式，并向网页组件发送`ENTER_MINI_WINDOW`事件。

4. 检测到原生端的`ENTER_MINI_WINDOW`事件后，网页端会在画中画模式窗口内全屏显示播放器。

5. 原生端需在以下场景实现退出画中画模式，并向网页端发送`EXIT_MINI_WINDOW`事件。检测到原生端的`EXIT_MINI_WINDOW`事件后，网页端会退出播放器的全屏，并返回观看页。

   * 观众返回观看页，例如点击画中画窗口。

   * 若直播间状态发生变化或观众切换直播源，原生应用会检测到网页组件的`DESTROY_PLAYER`事件，表明播放器已被销毁。

6. （可选）若 WebView 出现回放问题，原生应用可：

   * 在 WebView 播放暂停时，向网页端发送`PLAY`事件。网页端检测到该事件后，可播放直播流或点播内容。

   * 在 WebView 播放过程中，向网页端发送`STOP_PLAY`事件。网页端检测到该事件后，可暂停直播流或点播内容。


有关相关事件的更多信息，请参见[事件](https://docs.byteplus.com/docs/byteplus-livesaas/docs-ui-customizations-zh-CN#b73988d7)。

## 附录

<span id="57969dbc"></span>
### 信令定义

原生端与网页端需遵循以下信令定义，以实现双向通信。

```TypeScript
// Message types used in communication.
export interface IMessage {
  eventKey: number; // Message type.
  info?: any; // (Optional) Additional information.
}

// Defines messages sent from the web component to the native app.
export enum Web2NativeMessageEvent {
  /** JsBridge loading is complete.*/
  INIT_FINISH = 10001,
  /** The player is created.*/
  CREATE_PLAYER = 11000,
  /** The player is destroyed.*/
  DESTROY_PLAYER,
}

// Defines the message sent by Native to the Web.
export enum Native2WebMessageEvent {
  /** Enter PiP mode.*/
  ENTER_MINI_WINDOW = 21000,
  /** Exit PiP mode.*/
  EXIT_MINI_WINDOW,
}

// Defines the event triggered when the player is created.
export interface IMsgCreatePlayer {
  isPortrait: boolean; // Whether the live room is in portrait mode.
  isLive: boolean; // Whether the live room is in Live status.
}
```


<span id="72ece41d"></span>
### `JsBridge`交互流程

`JSBridge`作为原生应用与网页组件之间的桥梁，实现双向通信。

BytePlus Live 会将全局变量`window.ByteLiveJsBridge`注入到`window`中，包含以下 API：


* `nativeCallBack`：原生端调用`window.ByteLiveJsBridge.nativeCallBack`向网页端发送消息。

* `invokeNative`：网页端调用该 API 向原生端发送消息。


<span id="b73988d7"></span>
### 事件

<span id="36dec7d6"></span>
#### 网页组件到原生应用的事件

```TypeScript
// The event triggered when the player is created.
window.ByteLiveJsBridge.invokeNative({
  eventKey:11000,
  info: {
     isPortrait: true, // The live room is in portrait mode.
     isLive: true, // The live room is in the Live status.
  }
)
```



|**事件** |**键值** |**接口行为** |
|---|---|---|
|INIT_FINISH |10001 |JsBridge 加载完成时触发的事件。 |
|CREATE_PLAYER |11000 |播放器创建时触发的事件。<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">该事件触发后，可以通过 <code>info</code> 参数获取直播间是否处于 Live 状态以及是否为竖屏模式。</div><br> |
|DESTROY_PLAYER |11001 |播放器销毁时触发的事件。 |


<span id="6d361e2e"></span>
#### 原生端发送到网页端的事件

```TypeScript
// The event to enter PiP mode.
window.ByteLiveJsBridge.nativeCallBack({
  eventKey: 21000   
})
```



|**事件** |**键值** |**接口行为** |
|---|---|---|
|ENTER_MINI_WINDOW |21000 |进入 PiP 模式的事件。 |
|EXIT_MINI_WINDOW |21001 |退出 PiP 模式的事件。 |
|STOP_PLAY |21002 |暂停播放的事件。 |
|START_PLAY |21003 |恢复播放并退出 PiP 模式的事件。 |
|PLAY |21004 |播放直播流或点播内容的事件。 |
