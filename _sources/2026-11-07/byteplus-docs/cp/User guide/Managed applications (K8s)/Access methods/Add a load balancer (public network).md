Add a public load balancer to the application to enable other applications to access the current application via the public network. This article explains how to add a public network load balancer.

<span id=".5YmN5o-Q5p2h5Lu2"></span>
## Prerequisites


* A managed application has been created and deployed, and the application must be deployed on a Vital Kubernetes Engine cluster. For specific operations, refer to [Create and deploy managed applications (JAR / WAR)](https://docs.byteplus.com/en/docs/cp/Create_and_deploy_managed_apps_JAR_WAR).

* BytePlus load balancing has been activated.

   * If you use an existing CLB instance, please create it in advance. For specific operations, refer to [create a load balancing instance](https://docs.byteplus.com/en/docs/clb/CLB-instances-01).

   * If you select automatic creation of CLB instances, please ensure that your account balance is sufficient; otherwise, creation may fail.


<span id=".5L2_55So6ZmQ5Yi2"></span>
## Limit


* CLB instances automatically created by CP will have modification protection turned on. Do not manually modify the instance content directly through the load balancing console.

* CLB instances automatically created by CP are deleted at the same time as the service.

* If you use an existing CLB instance, it is not supported to select instances automatically created by other Products, in order to avoid configuration conflicts between services.


<div data-tips="true" data-tips-type="danger" data-tips-is-title="true">danger</div>


<div data-tips="true" data-tips-type="danger">Do not manually modify listeners and backend server groups maintained by CP (with names containing the <code>k8s_</code> prefix) through the load balancer console, as configuration changes made in the load balancer console may be rolled back, potentially causing issues with application ingress.</div>


<span id=".5pON5L2c5q2l6aqk"></span>
## Procedure


1. Log in to the application management page.

   1. Log in [Code Pipeline console](https://console.byteplus.com/cp).

   2. Select **workspace** from the left navigation bar.

   3. Click the name of the target workspace to enter that workspace.

   4. In the left navigation bar, select **Application Delivery \> Application Management**.

2. On the application management page, select the target hosted application, click the application card, then go to the basic information tab.

3. Switch to the application orchestration tab. In the Access Method settings section, select **Load Balancer (Public Network) \> Add Load Balancer (Public Network)** .

4. In the Add Load Balancer (Public) dialog box, set load balancer parameters.

   
   |Configuration Item |Descriptions |
   |---|---|
   |CLB load balancer |Configure the service's load balancer, supporting **automatic creation** or **use of an existing one**. It is recommended to select automatic creation except in special cases.<br><br><br>* Automatic creation: CP automatically creates a brand new CLB instance for you. Instances will use the following default configuration, which cannot be modified.<br><br>   * Name: Automatically generated by the system, in the format `K8s-xxx`.<br><br>   * Instance specification: Medium I.<br><br>   * Subnet: Randomly use one subnet under your account as the default subnet.<br><br>   * Instance protection: Turn on instance modification protection.<br><br>   * IP version: IPv4.<br><br>   * Route type: BGP.<br><br>   * Billing method: Pay\-as\-you\-go. The maximum bandwidth is 200 Mbps. For detailed billing standards, refer to [product billing](https://docs.byteplus.com/en/docs/clb/Billing-01).<br><br><br><div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div><br><br><br><br>* <div data-tips="true" data-tips-type="warning">Do not manually modify CLB instances that were automatically created in the load balancing console.</div><br><br><br>* <div data-tips="true" data-tips-type="warning">Automatically created CLB instances are deleted synchronously when the service is deleted. Do not use automatically created CLBs for other purposes to avoid residual resources or accidental deletion.</div><br><br><br>* <div data-tips="true" data-tips-type="warning">Automatically created CLB instances support multiple availability zones. If the load balancer in the current Region supports cross\-availability zone disaster recovery, primary and standby availability zone load balancer instances will be created by default. When the primary availability zone fails, traffic is switched to the standby availability zone to ensure uninterrupted business operations.</div><br><br><br>* Use existing: Supports using CLB instances that are not automatically created by the system. The billing type is not limited.<br><br><br><div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div><br><br><br><br>* <div data-tips="true" data-tips-type="warning">Selecting CP or other products to automatically create CLB instances is not supported.</div><br><br><br>* <div data-tips="true" data-tips-type="warning">When using an existing CLB instance, do not overwrite its existing listener rules.</div><br><br><br>* <div data-tips="true" data-tips-type="warning">CP will configure new listeners and backend server groups under your CLB instance. Do not modify the related configuration in the load balancing console without authorization.</div><br> |
   |Scheduling algorithm |Rules to follow when forwarding requests with the specified listener.<br><br><br>* Weighted Round Robin: traffic is forwarded based on weight values. The higher the weight of the backend server, the more frequently (probabilistically) it is selected as the forwarding destination.<br><br>* Weighted Least Connection: traffic is forwarded first to the backend with the smallest real\-time ratio of connections to weight.<br><br>* Source Hashing: traffic is always forwarded to a single backend server if the hash of the source IP remains unchanged. |
   |Port mapping |Configure port mapping rules. Supports the configuration of multiple port mappings.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><br>* <div data-tips="true" data-tips-type="tip">Multiple port mappings are commonly used in scenarios where an application defines several ports to distinguish between different features. For example, one port is used for service access, and another port is used for debugging.</div><br><br><br>* <div data-tips="true" data-tips-type="tip">When adding multiple port mappings, service ports must not be duplicated.</div><br><br><br>* Service port: Defines the frontend port for public network load balancing. The application can be accessed through this port, and the port number can be set within the range of 1 to 65535.<br><br>* Protocol: Select a communication protocol.    |External traffic policy |The policy in Service for forwarding external traffic currently supports only **Cluster**.<br><br><br>* Cluster: Traffic can be load\-balanced across all application instances. |
   

5. Click **confirm** to begin creating the public load balancer.


<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">The main specification metrics of CLB include <strong>maximum number of connections</strong>, <strong>new connections per second</strong>, and <strong>queries per second</strong>. If your application traffic exceeds the CLB specification limits, you can add multiple CLBs to distribute the traffic load.</div>


<span id=".57uT5p6c6aqM6K-B"></span>
## Result validation


1. View the port mapping for the public network load balancer in the table: `<Load balancer IP>:<Port number>`.

2. Using a machine with public network access permission, enter `<load balancer IP>:<port number>` in the browser address bar. For example, `101.xx.xx.xx:80`. You can successfully access the application homepage.

## Related Operations

|Feature |Descriptions |

Please modify with caution.</div><br> |
|Delete a service |Select the target load balancing Service. In the **Actions** column, click **delete** to remove the current Service.<br><br><div data-tips="true" data-tips-type="danger" data-tips-is-title="true">danger</div><br><br><br><div data-tips="true" data-tips-type="danger">After deleting the service, the public CLB instances automatically created by CP will be physically deleted. Other applications will not be able to access your application through the public CLB port. Please exercise caution when performing actions!</div><br> |
