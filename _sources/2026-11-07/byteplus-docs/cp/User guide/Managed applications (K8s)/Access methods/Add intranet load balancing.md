Add internal load balancing for the application to enable other applications within the same VPC to access the current application. This article introduces how to add intranet load balancing.

<span id=".5YmN5o-Q5p2h5Lu2"></span>
## Prerequisites


* A managed application has been created and deployed, and the application must be deployed in a Vital Kubernetes Engine (VKE) cluster. For specific operations, refer to [Create and deploy managed applications (JAR /WAR)](https://docs.byteplus.com/en/docs/cp/Create_and_deploy_managed_apps_JAR_WAR).

* The BytePlus Load Balancer has been activated.

   * If you use an existing CLB instance, please create it in advance. For specific operations, refer to [create a load balancing instance](https://docs.byteplus.com/en/docs/clb/CLB-instances-01).

   * If you choose to automatically create a CLB instance, please ensure that your account balance is sufficient; otherwise, creation may fail.


<span id=".5L2_55So6ZmQ5Yi2"></span>
## Limit


* Modification protection will be turned on for CLB instances automatically created by CP. Do not directly manually modify the instance content through the load balancing console.

* CLB instances automatically created by CP are deleted synchronously when the service is deleted.

* When using an existing CLB instance, you cannot select instances automatically created by other Product, in order to avoid configuration conflicts between services.


<div data-tips="true" data-tips-type="danger" data-tips-is-title="true">danger</div>


<div data-tips="true" data-tips-type="danger">Do not manually modify listeners and backend server groups maintained by CP (with names containing the <code>k8s_</code> prefix) via the load balancing console, as this may result in rollback of configuration changes made in the load balancing console and cause failures related to application ingress.</div>


<span id=".5pON5L2c5q2l6aqk"></span>
## Procedure


1. Log in to the application management page.

   1. Log in to [Code Pipeline console](https://console.byteplus.com/cp).

   2. In the left navigation bar, select **workspace**.

   3. Click the name of the target workspace to enter the current workspace.

   4. In the left navigation bar, select **Application Delivery \> Application Management**.

2. On the application management page, select the target hosted application, click the application card, and go to the basic information tab for the current application.

3. Switch to the application orchestration tab. In the access method settings section, select **Load Balancer (Intranet) \> Add Load Balancer (Intranet)** .

4. In the Add Load Balancer (Intranet) dialog box, set load balancer parameters.

   
   |Configuration Item |Descriptions |
   |---|---|

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">The key specifications of CLB include <strong>maximum number of connections</strong>, <strong>number of connections created per second</strong>, and <strong>number of queries per second</strong>. <span id=".57uT5p6c6aqM6K-B"></span>
## Result validation


1. View the port mapping for the load balancer (internal network) in the table: `<Load balancer IP>:<Port number>`.

2. Using a machine with internal network access permission, enter `<load balancer IP>:<port number>` in the browser address bar. For example, `192.xx.xx.xx:80`. You will be able to successfully access the application homepage.


<span id=".55u45YWz5pON5L2c"></span>
## Related Operations

For an already created load balancing (internal network) type Service, modifying the scheduling algorithm, port mapping, and other information is supported, as well as deleting the Service.


|Feature |Descriptions |
|---|---|
|Modify the Service |Select the target load balancing Service, click **edit** in the **Actions** column, and modify the relevant information.<br><br><div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div><br><br><br><div data-tips="true" data-tips-type="warning">Modifying the scheduling algorithm here will override the configuration in the CLB console. Please modify with caution.</div><br> |
|Delete a service |Select the target load balancing Service, click **Actions** in the column, then click **delete** to delete the current Service.<br><br><div data-tips="true" data-tips-type="danger" data-tips-is-title="true">danger</div><br><br><br><div data-tips="true" data-tips-type="danger">After you delete the service, the internal CLB instance automatically created by CP will be physically deleted. Applications within the same VPC will not be able to access your application through the internal CLB port. Please exercise caution when performing actions!</div><br> |
