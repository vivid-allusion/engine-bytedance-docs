Built\-in **SonarQube scanning** task in CP supports connecting to your SonarQube platform for rapid code analysis. This article describes the usage instructions for this built\-in task.

<span id=".5YmN5o-Q5p2h5Lu2"></span>
## Prerequisites


* The SonarQube service has been deployed; for details, refer to the [official documentation](https://docs.sonarqube.org/latest/setup/sonarqube-on-kubernetes/).

* The SonarQube token has been obtained; for specific operations, refer to [Obtaining the SonarQube token](https://docs.byteplus.com/en/docs/cp/Obtain_a_SonarQube_token).


<span id=".5L2_55So6ZmQ5Yi2"></span>
## Usage limits

When deploying the SonarQube service, note the following considerations:


* The SonarQube service must be able to communicate with the network of the build resource pool you use.

   * If you use a public resource pool, ensure that the SonarQube service is accessible via the public network.

   * If you use a private resource pool, ensure that the SonarQube service and your private resource pool are in the same VPC.

* The version of the SonarQube service must not be lower than LTS 8.9.

* In the `values.yaml` file, the value of the `postgresql.volumePermissions.enabled` parameter must be set to true; other parameter configurations can be modified as needed.


<span id=".5re75Yqg5Lu75Yqh"></span>
## Add task

When creating or editing a pipeline, go to the **Process Orchestration** tab, click **Add Job**, and the **Add Job** drawer will pop up. Select the task template **Test \> SonarQube scanning**.

<span id=".5Y-C5pWw6K-05piO"></span>
## Parameter description

The following describes the parameters for this built\-in task.


* **Task name**

   The default is SonarQube scanning; custom task names are supported.

* **Upstream task**

   Displays the name of the upstream sequential task for the current task. If there is no upstream task, `-` is displayed.

* **Source code download policy**

   Select the source code download policy based on whether the current task requires the source code.

   * **Download code**: The current task needs to download the source code.

   * **Do not download code**: The current task does not require the source code.

* **Step**

   The current task includes a default built\-in step (SonarQube code scanning). You can add other sequential steps to the current task as needed. The following describes the parameters for this default built\-in step.

   
   |Parameter |Description |
   |---|---|
   |Step name |The default is SonarQube code scanning, and custom step names are supported. |
   |Server address |Enter the access address of your SonarQube service; both HTTP and HTTPS protocols are supported. The address can be an IP address with port, or a domain name. |
   |User Token |Enter the token prepared in the prerequisites. |
   |Quality gate |Supports using the quality gate value as the condition for determining whether the SonarQube code scanning task passes. You can use the number of defects and vulnerabilities as evaluation indicators.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">To modify the quality gate value, directly modify this parameter in the CP console. The quality gate displayed on the SonarQube server (named <code>cp_[project_name]_qg</code>) is the quality gate value generated by CP. Modifying the quality gate on the SonarQube server will not take effect.</div><br> |
   |Skip on fail |Optional configuration.<br><br><br>* Turn on: If the current step fails, it is skipped directly; the remaining steps of the current task can continue to execute, and the pipeline can continue to run.<br><br>* Turn off: After the current step fails, the remaining steps of the current task will not execute, and the pipeline will fail. |
   

* **Task output**

   Displays all artifacts output by the current task, including artifacts from all steps within the task. When there are no artifacts, show as `-`. Artifacts can be used as input for subsequent tasks.

   For the current default predefined steps, the output will include the number of bugs, vulnerabilities, code smells, coverage, and the scan report.

* **Advanced settings**

   * **LimitRange**: Supports setting the maximum CPU and memory.

   * **Disk capacity limit**: Supports setting the maximum disk capacity, up to 100 GiB.

   * **Timeout time**: Sets the timeout time for the entire task. The task will automatically fail after timing out. A task can include multiple serial steps, and the total execution time of all steps must be less than the task's timeout time.

   * [Webhook notification](https://docs.byteplus.com/en/docs/cp/Webhook_notification): Supports sending task\-level messages via Webhook and Feishu bot, helping you stay informed about task status in a timely manner.

   * **Automatic fail retry**: After enabling, enter the maximum number of retries supported. When task execution fails, it will retry up to the specified number of times according to the configured maximum number of retries.

## Logs and artifacts

The following describes the details displayed in the pipeline after the predefined task completes.

On the current pipeline's execution details page, click the title of the SonarQube scan card to view the execution log, artifacts, and task configuration information.


* Execution log: Shows the real\-time execution log of the SonarQube scan task.

* Task configuration: Shows the configuration parameters for this task. For details, refer to the parameter description above.

* Artifacts: After successful execution, the SonarQube scan task will output the following artifacts.

   * Number of bugs: Shows the number of bugs in the code.

   * Number of vulnerabilities: Shows the number of security\-related vulnerabilities in the code.

   * Code smells: Shows the number of maintainability\-related issues in the code. Code smells indicate poor maintainability.

   * Coverage: The percentage of code covered by test cases.

   * Scan report: Click to go to the SonarQube server to view the detailed report.
