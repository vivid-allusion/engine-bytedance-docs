The CP built\-in **compilation and build** task supports compilation and build for Java Maven, Java Gradle, Python, Go, and NodeJS languages. This document uses **NodeJS compilation and build** as an example to introduce usage instructions for this built\-in task.

<span id=".54m55oCn5LuL57uN"></span>
## Feature introduction

NodeJS compilation and build supports proxy acceleration. When enabled, it can effectively improve the compilation speed for cross\-border public resource pools, such as Github, Gitlab, and similar domain names.

<span id=".5YmN5o-Q5p2h5Lu2"></span>
## Prerequisites

The code source has been created. For specific operations, see [Create code source](https://docs.byteplus.com/en/docs/cp/Integrate_code_source).

<span id=".5re75Yqg5Lu75Yqh"></span>
## Add task

When creating or editing a pipeline, go to the **Process Orchestration** tab, click **Add Job**, and the **Add Job** drawer will pop up. Select **Build \> NodeJS compilation and build** in the task template.

<span id=".5Y-C5pWw6K-05piO"></span>
## Parameter description

The following section introduces the parameters for this built\-in task.


* **Job name**

   The default is NodeJS compilation and build; custom task names are supported.

* **Upstream task**

   Displays the name of the upstream serial task for the current task. If there is no upstream task, `-` is displayed.

* **Code source download policy**

   Select the code source download policy according to whether the current task needs to use the code source.

   * **Download code**: The current task needs to download the code source.

   * **Do not download code**: The current task does not need to use the code source.

* **Step**

   The current task includes a default predefined step (NodeJS compilation and build). Supports adding other serial steps to the current task as needed. The following describes the parameters of this default built\-in step.

   
   |Parameter |Description |
   |---|---|
   |Step name |The default is NodeJS compilation and build; custom step names are supported. |
   |Version |Select the tool version used for NodeJS compilation and build. Refer to the Console for supported versions of different languages. |
   |Compilation command |Enter the compilation command. The command box contains the default compilation command. Please adjust it according to your requirements. |
   |Turn on proxy acceleration |After enabling this option, the public resource pool supports compilation acceleration for domain names such as Github, Gitlab, and more. |
   |Skip on failure |Optional configuration.<br><br><br>* Turn on: If the current step fails during execution, it will be skipped directly, and the remaining steps of the current task can continue to execute. The pipeline can also continue to run.<br><br>* Turn off: After the current step fails, the remaining steps of the current task will not be executed, and the pipeline execution will fail. |
   

* **Task output**

   Displays all artifacts generated by the current task, including artifacts from all steps within the task. If there are no artifacts, displays as `-`. Artifacts can be used as input for subsequent tasks.

   There is no artifact output for the current default built\-in step.

* **Advanced settings**

   * **LimitRange**: Supports setting upper limits for CPU and memory.

   * **Disk capacity limit**: Supports setting an upper limit for disk capacity, up to 100 GiB.

   * **Timeout**: Sets the timeout for the entire task. If the task times out, it will automatically fail. A task can include multiple serial steps, and the total execution time of all steps must be less than the task's timeout.

   * [Webhook notification](https://docs.byteplus.com/en/docs/cp/Webhook_notification): Supports pushing task\-level messages via both Webhook and Feishu bot, helping you stay informed about task status in a timely manner.

   * **Automatic retry on failure**: When enabled, enter the maximum number of retries supported. If task execution fails, it will retry up to the specified number of times according to the configured maximum number of retries.

## Log description

The following describes the detailed information displayed in the pipeline after this built\-in task is completed.

On the execution details page of the current pipeline, click the title of the NodeJS compile and build card to view the execution log and task configuration information.


* Execution log: Displays the execution log of this task in real time.

* Task configuration: Displays the configuration parameters of this task. For details, refer to the parameter description above.
