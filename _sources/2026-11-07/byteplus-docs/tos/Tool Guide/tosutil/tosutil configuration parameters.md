tosutil offers many configuration parameters that you can view in the `vim ~/.tosutilconfig` file. This article provides a detailed description of the configuration file.

<div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div>


<div data-tips="true" data-tips-type="warning">The configuration file also contains some less frequently used parameters not listed above (such as <code>skipCheckEmptyFolderForDownload</code>, <code>memoryEconomicalScanForUpload</code>, <code>faultTolerantMode</code>). These parameters typically do not require modification and can remain at their default values. For detailed information on their usage, please contact the BytePlus TOS team.</div>



|**Parameter** |**Description** |**Recommended value** |
|---|---|---|
|endpoint |Service address for connecting to TOS. |N/A |
|region |Region name for connecting to TOS. |N/A |
|ak |Access Key ID for permanent or temporary access keys. To protect key security and prevent leaks, tosutil automatically encrypts your information. |N/A |
|sk |Secret Access Key in permanent or temporary access credentials. To ensure key security and prevent leaks, tosutil automatically encrypts your information. |N/A |
|token |The Security Token in temporary access keys, used together with temporary Access Key and Secret Key. |N/A |
|connectTimeout |Connection timeout in seconds, default is 30. |[5, 60] |
|socketTimeout |Timeout for reading and writing data, in seconds, default is 120. |[5, 120] |
|maxConnections |Configure the maximum allowed open connections, default is 1000. |N/A |
|maxRetryCount |Maximum retry count for requests, default is 10.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Retry with backoff selectively when the TOS server responds with HTTP status codes 408, 429, 5XX, or when a timeout error occurs during the TOS service request.</div><br> |[0, 10] |
|useListType2 |Whether to use the ListObjectsType2 interface for batch operations and object listing. Supported values:<br><br><br>* `true`: Use listobjectstype2.<br><br>* `false` (default): Use listobjects. |N/A |
|defaultSse |The default server\-side encryption algorithm used when uploading or copying objects. Supported values:<br><br><br>* `aes256`<br><br>* `kms` |N/A |
|defaultSseKeyId |Default KMS key used when uploading or copying objects with server\-side encryption algorithm set to kms. |N/A |
|defaultBigfileThreshold |Threshold to enable chunked tasks. If the file to upload, download, or copy exceeds this threshold, it will be processed in chunks. Unit: bytes, default is 100 MB.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Supports configuration with size units, for example, setting 1 MB represents 1,048,576 bytes.</div><br> |[50MB, max) |
|defaultPartSize |The segment size for each slice task, in bytes, defaults to `auto`.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><br>* <div data-tips="true" data-tips-type="tip">Supports capacity unit configuration, for example, setting 1 MB represents 1,048,576 bytes.</div><br><br><br>* <div data-tips="true" data-tips-type="tip">If set to auto, tosutil automatically adjusts each slice task's size based on the source file size.</div><br> |Default value |
|defaultParallels |Maximum concurrency for each shard task; default is 1. |Based on the client machine environment, it is recommended not to exceed 50. |
|defaultJobs |Maximum concurrency for batch tasks; default is 3.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Batch tasks include uploading folders, downloading folders, copying folders, batch deleting objects, etc.</div><br> |Based on the client machine environment, it is recommended not to exceed 1000. |
|defaultJobsCacheCount |The cache size of the batch task queue, indicating the maximum number of tasks that can be cached. The default is 1,000,000.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">The more tasks cached, the greater the memory usage. It is recommended to keep the default value. Adjust this parameter based on actual usage if necessary.</div><br> |Default value |
|rateLimitThreshold |Flow control threshold for upload/download commands, unit: bytes. The default is 0, meaning no flow limit. The minimum value is 1 KB.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Supports configuration with capacity units. For example, setting 1 MB equals 1,048,576 bytes.</div><br> |\> 100 KB |
|utilLogPath |The full path of the tosutil log file must be a filename. By default, it is the tosutil.log file located in the .tosutil_log subfolder of the user directory (HOME directory on macOS or Linux; C:\\Users\<username\> on Windows).<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><br>* <div data-tips="true" data-tips-type="tip">If this parameter is empty, no log will be generated.</div><br><br><br>* <div data-tips="true" data-tips-type="tip">The path must point to a file, not a folder.</div><br><br><br>* <div data-tips="true" data-tips-type="tip">After enabling tosutil logging, normal and error logs generated during command execution will be saved in the tosutil log file for troubleshooting and analysis.</div><br><br><br>* <div data-tips="true" data-tips-type="tip">Ensure the user running the command has read and write permissions for this path.</div><br> |Default value |
|utilMaxLogSize |tosutil log file size; unit: bytes; default is 30 MB.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Supports capacity unit configuration. For example, setting 1 MB represents 1,048,576 bytes.</div><br> |[10MB, 100MB] |
|utilLogBackups |Maximum number of tosutil log files to keep, default is 10. |[3, 30] |
|utilLogLevel |Log level of tosutil. Supported values: DEBUG, INFO, WARN, ERROR. Default is INFO. |N/A |
|sdkLogPath |Full path of the TOS SDK log file. It must be a filename. By default, it is tossdk.log under the .tosutil_log subfolder in the user directory (HOME directory on macOS or Linux; C:\\Users\<username\> on Windows).<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">If this parameter is empty, no logs will be generated; the path must be a file, not a folder.</div><br> |Default value |
|sdkMaxLogSize |TOS SDK log file size, in bytes, default is 30MB.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Supports capacity units in configuration, for example, setting 1MB equals 1,048,576 bytes.</div><br> |[10MB, 100MB] |
|sdkLogBackups |Maximum number of files to retain for TOS SDK logs; default is 10. |[3, 30] |
|sdkLogLevel |SDK log level supports: DEBUG, INFO, WARN, and ERROR. The default is WARN. |N/A |
|recordMaxLogSize |Size of the batch task result file for success/failure/warning, in bytes. Default is 30 MB.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Supports configuration with capacity units, for example, configuring 1 MB represents 1,048,576 bytes.</div><br> |[10MB, 100MB] |
|recordBackups |The maximum number of success or failure result list files that batch tasks can retain is 2048 by default. |Default value |
|humanReadableFormat |Whether to convert the byte count in the listing object results and results list into a readable format. The value descriptions are as follows:<br><br><br>* `true` (default): Indicates conversion is applied.<br><br>* `false`: Indicates no conversion is applied. |N/A |
|showProgressBar |Whether to display the progress bar in the console, explained as follows:<br><br><br>* `true` (default): Displays the progress bar in the console.<br><br>* `false`: Does not display the progress bar in the console. |N/A |
|showStartTime |Whether to display the start time on the console. The values are explained as follows:<br><br><br>* `true` (default): Displays the start time on the console.<br><br>* `false`: Does not display the start time on the console. |N/A |
|helpLanguage |The language of the help documentation. Supported values are as follows:<br><br><br>* `Chinese` (default)<br><br>* `English` |N/A |
|defaultOutputDir |The default folder for batch task result list files is the user directory, explained as follows:<br><br><br>* macOS or Linux: The `HOME` directory.<br><br>* Windows: The subfolder `.tosutil_output` under `C:\\Users\\<username>`.<br><br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Batch tasks support the \-o parameter to override the folder address each run.</div><br> |N/A |
|defaultCheckpointDir |The default folder for resumable file transfers is the user's directory unless specified otherwise, detailed as follows:<br><br><br>* macOS or Linux: The `HOME` directory.<br><br>* Windows: The subfolder `.tosutil_checkpoint` under `C:\\Users\\<username>`.<br><br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Upload, download, or copy tasks support the <code>-cpd</code> parameter to override this folder path with each run.</div><br> |N/A |
|defaultTempFileDir |Folder to save temporary files when downloading large files. Default is empty, meaning temporary files are saved in the same directory as the large file being downloaded. |N/A |
|readBufferIoSize |The cache size for uploaded data. Unit: bytes; default is 8192.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><br>* <div data-tips="true" data-tips-type="tip">Adjust this value based on use cases. Set smaller for uploading many small files; set larger for large files.</div><br><br><br>* <div data-tips="true" data-tips-type="tip">Support configuration with capacity units, for example, configuring 1 MB to represent 1,048,576 bytes.</div><br> |[4096, 65536] |
|writeBufferIoSize |The cache size for downloaded data in bytes, default is 65536.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><br>* <div data-tips="true" data-tips-type="tip">Set this value according to actual scenarios. If the file to download is large, increase this value.</div><br><br><br>* <div data-tips="true" data-tips-type="tip">Capacity units are supported; for example, setting 1 MB represents 1,048,576 bytes.</div><br> |N/A |
|checkSourceChange |When uploading, downloading, or copying, whether to check for changes in source files or objects after the operation completes. The values mean:<br><br><br>* `true`: Enables checking for changes in source files or objects.<br><br>* `false` (default): Disables checking for changes in source files or objects. |N/A |
|fsyncForDownload |Whether to force synchronization of memory (pagecache) data to disk during downloads. The options are explained below:<br><br><br>* `true`: Indicates forced synchronization.<br><br>* `false` (default): Indicates no forced synchronization.<br><br><br><div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div><br><br><br><div data-tips="true" data-tips-type="warning">This parameter can be enabled in scenarios requiring extremely high data reliability; enabling it significantly impacts download performance, so use cautiously.</div><br> |N/A |
|forceOverwriteForDownload |When downloading objects on Linux or macOS, whether to force overwrite local executables (even if running). The values mean:<br><br><br>* `true` (default): Force overwrite.<br><br>* `false`: Indicates no forced overwrite. |N/A |
|forceReadFileChecksumForDownload |When running the `cp` command to download an object, whether to read the local target file again after download to calculate CRC64 and compare it with the source object for data consistency check. The values are explained as follows:<br><br><br>* `true`: Indicates that the local target file needs to be read.<br><br>* `false` (default): Do not read the local target file. |N/A |
|forceReadFileChecksumForUpload |When executing the `cp` command to upload an object, during data consistency verification, whether to reread the local source file after upload to calculate CRC64 and compare it with the destination object; the options are:<br><br><br>* `true`: Indicates the local source file is read.<br><br>* `false` (default): Indicates the local source file is not read. |N/A |
|defaultVerifyChecksum |When executing the `cp` or `fcp` command, whether to enable the data consistency check mechanism by default. The options are as follows:<br><br><br>* `true` (default): Enable the data consistency check mechanism.<br><br>* `false`: Do not enable the data consistency check mechanism. |Default value |
|panicForSymbolicLinkCircle |Handling method after detecting a symlink loop during upload; the values are described as follows:<br><br><br>* `true`: Triggers a panic exception.<br><br>* `false` (default): Only logs the error. |N/A |
|fastFailThreshold |Threshold for fast failure upon encountering 4XX errors in batch tasks. Once the number of 4XX errors exceeds this threshold, the fast failure process starts, interrupting all unexecuted or scanning tasks. The default value is 5. |N/A |
|useTempFileForDownloadSmallFile |When downloading small files locally, whether to use write temporary file mode: true means writing to a temporary file first and then renaming it to the final file; false means writing directly to the final file. The default is true. |N/A |
|skipWriteSucceedRecord |Skip generating the batch task success result list file. When set to true, no success result list file is generated during the batch task execution. Default is true. |N/A |
|scanLocalFolderByChunk |When executing `cp` to upload folders or `fcp` to copy local folders, chunk mode reads files in the local folder. For folders with many files, set to true. Default is false. |N/A |
|abortHttpStatusForResumableTasks |HTTP status codes that quickly abort multipart upload, download, or copy tasks. When any subtask’s HTTP status code falls within this range, the entire multipart upload, download, or copy task will be immediately aborted.<br><br>The default values are: 401, 403, 404, 405, 409. |N/A |
|additionalRetryHttpStatus |Additional HTTP status codes that support retries when the server response is non\-2xx.<br><br>The default value is 408. |N/A |
|additionalRetryEc |When the server response status is not 2xx, additional EC codes that support retries take priority over additionalRetryHttpStatus.<br><br>Default value: 0002\-00000018 |N/A |
|enablePprof |Whether to enable the pprof service when running the command. Valid values:<br><br><br>* `true` (default): Enables the pprof service on port 18888.<br><br>* `false`: Disables the pprof service. | |
|allowNoDelimiterForHns |When using HNS buckets, specify whether to allow listing without a delimiter, with the following options:<br><br><br>* `true`: Allow listing without a delimiter.<br><br>* `false` (default): Delimiter must be included for listing. |N/A |
|printMemUsageForMount |Whether to log memory allocation metrics when using the mount command. Values are as follows:<br><br><br>* `true`: Log memory allocation metrics.<br><br>* `false` (default): Do not log memory allocation metrics. |N/A |
|noTruncateForCreateNewFile |When creating a new file, whether to use the `Truncate` parameter to specify the file size. The meanings of the values are as follows:<br><br><br>* `true`: When creating a new file, do not use the `Truncate` parameter to specify the file size.<br><br>* `false` (default): When creating a new file, use the `Truncate` parameter to specify the file size. |N/A |
