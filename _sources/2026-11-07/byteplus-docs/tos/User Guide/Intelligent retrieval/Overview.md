Companies are storing increasing amounts of unstructured content—such as documents, images, and audio\-video files—in TOS as data volume continues to grow. Traditional keyword\- or structured field\-based search methods struggle to capture the semantic meaning of content. Consequently, these methods cannot provide users with highly relevant, comprehensive results. Additionally, unstructured data lacks inherent indexing structures, which severely limits search capabilities.

TOS contains a large amount of unstructured data that has remained largely untapped. Previously, in order to build data retrieval capabilities on TOS buckets, you had to develop a complete processing pipeline from scratch, including object attribute parsing, embedding model inference, vector data storage, and query and retrieval services. This process required coordinating multiple components, managing resources, and ensuring high availability. As a result, it presented high technical barriers, significant costs, and heavy maintenance burdens.

<span id="mhv86dbX"></span>
## Introduction

TOS's intelligent retrieval feature has built\-in capabilities for extracting scalar attributes and performing multimodal vectorization. With a simple configuration, it can automatically build scalar and vector indexes for objects, offering excellent out\-of\-the\-box scalar, vector, and hybrid retrieval capabilities.

This feature offers the following core capabilities:


* **Scalar retrieval**: Allows for flexible querying and aggregation using object metadata properties, such as size, creation time, and Content\-Type, for filtered searches and statistical analyses.

* **Vector retrieval**: Leverages multimodal embedding to efficiently retrieve content based on semantic similarity.

* **Hybrid retrieval**: Combines semantic search with scalar metadata filtering to allow for more precise control over search results.

## Benefits

While traditional data retrieval methods have significant limitations, intelligent retrieval offers the following advantages:


* **Improved search quality**: By vectorizing content with deep learning models, intelligent retrieval identifies semantic similarity and achieves high\-relevance recall across languages and expressions. This method significantly outperforms keyword matching.

* **Lower data processing costs**: TOS automatically handles content parsing, embedding inference, and index construction. This eliminates the need to build models, manage GPUs, or maintain vector databases, greatly reducing development and maintenance costs.

* **Reduced architecture complexity**: Retrieval capabilities are provided as a serverless service with automatic scaling and support for second\-level index updates. You can access enterprise\-grade, high\-availability, high\-performance retrieval services without developing any additional components.

* **Foundation for AI applications**: As AI applications place greater demands on understanding multimodal content, intelligent retrieval provides the necessary infrastructure for developing capabilities such as intelligent content management, content discovery, and knowledge base construction.

## Use cases


* **Statistical aggregation**

   The scalar retrieval capability provides flexible and powerful aggregation functions on objects within TOS buckets for scenarios that require complex and cost\-effective statistical aggregation, such as compliance auditing or content categorization.

* **Unstructured data retrieval**

   Intelligent retrieval enables a semantic\-level search of unstructured data, such as documents, contracts, reports, and emails. This feature is particularly useful for industries like legal, finance, and enterprise records management.

* **Semantic search and content discovery**

   Intelligent retrieval uses vision models to interpret images, audio, and video content. This enables use cases such as recommending similar content, retrieving images, and monitoring copyrighted content on platforms.

* **Multimodal retrieval**

   Intelligent retrieval supports key e\-commerce scenarios, including product image search, content recommendation, and discovery of similar items. The high\-quality vectors generated by these processes can be fed directly into recommendation systems to enhance them.

### Configuring datasets

Through the TOS console, you can use the intelligent retrieval feature to create a dataset and associate it with one or more buckets.


1. **Create a dataset**: A dataset is a product entity that enables intelligent retrieval. Each dataset corresponds to one retrieval template and can be associated with one or more buckets.

2. **Manage retrieval templates**: A retrieval template determines a dataset's retrieval capabilities. Different templates support different retrieval functions. For instance, a basic information retrieval template offers scalar retrieval, whereas an image retrieval template facilitates semantic image searches.

3. **Bind TOS buckets**: Once a database is associated with TOS buckets, intelligent retrieval automatically extracts and builds the required indexes from the objects in those buckets to deliver the corresponding retrieval capabilities.


<span id="vdoCRMSP"></span>
### Building indexes

Intelligent retrieval offers fully automated index building. Based on the dataset template, different operators process all or incremental objects in the associated TOS buckets. This process usually involves the following steps:


1. **Data ingestion/Change monitoring**: Listens for object creation, update, and deletion events.

2. **Operator execution**: Executes operations such as object metadata extraction, vector embedding generation, and image tagging.

3. **Index writing**: Writes the extracted index information into a high\-performance retrieval database.


<span id="vyRcFqCA"></span>
### Retrieving data

During retrieval, the system first performs the necessary preprocessing steps according to the dataset template. Then, it queries the high\-performance retrieval database. The general workflow includes the following steps:


1. **Query parsing**: Identifies the query type (e.g., scalar, vector, or hybrid retrieval).

2. **Embedding/vector retrieval (if applicable)** : If vector or hybrid retrieval is required, the query content is vectorized, and a K\-nearest neighbor (KNN) vector search is performed in the retrieval database

3. **Scoring and ranking**: Ranks candidate results based on metadata filtering and business rules.

4. **Result return**: Returns the final, ranked list of results.
