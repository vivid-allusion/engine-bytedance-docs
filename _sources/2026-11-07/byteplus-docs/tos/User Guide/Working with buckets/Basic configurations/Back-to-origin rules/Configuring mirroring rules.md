When you set up a mirror\-based back\-to\-origin (mirroring) rule and request an object that does not exist in the bucket, TOS fetches the object or its metadata from the origin server and sends it back to you. This topic explains how to configure mirroring rules.

<span id="d6eb0e4e"></span>
## Background information

A mirroring action can be triggered by one of the following two operations:


* Triggering via GetObject: When the requested object does not exist in the bucket, TOS fetches the object from the specified origin server and returns it to the requester. Simultaneously, TOS writes the object to the bucket.

   <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_719828337c81eb7984b2ee4ea0a56377.png) </span>

* Triggering via HeadObject: When the metadata of the requested object does not exist in the bucket, TOS retrieves the object's metadata from the configured origin server and returns it to the requester.

   <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_07d3ba2c7abd4b4e63f9b6e0c2778f4e.png) </span>

## Notes


|**Scenario** |**Category** |**Considerations** |
|---|---|---|
|General |Handling failed back\-to\-origin requests |When a mirroring action is triggered and the requested object is not found on the origin server, the origin server will return an HTTP status code to TOS. Specifically:<br><br><br>* If the origin server returns status code 200, 206, or 404 to TOS, TOS will return the same status code to the user.<br><br>* If the origin server returns a status code other than 200, 206, or 404 to TOS, TOS will return 424 to the user uniformly. |
||Data processing |The mirroring feature does not work with the data processing feature. |
||Permissions |By default, the owner of an account has full permissions. IAM users have no permissions by default. If an IAM user needs to perform any of the following operations, the account owner must grant the user the appropriate permissions using an [IAM](https://docs.byteplus.com/en/docs/tos/docs-overview_6) or [Bucket policy](https://docs.byteplus.com/en/docs/tos/docs-overview_5).<br><br><br>* Configure mirroring rules: `tos:PutBucketMirror`<br><br>* View mirroring rule configurations: `tos:GetBucketMirror`<br><br>* Delete mirroring rules: `tos:DeleteBucketMirror` |
|Triggering via GetObject |Object size |* The requested object can be up to 5 GiB in size. To request an object larger than 5 GiB, use GetRange.<br><br>* If an anonymous user triggers a mirroring request and the bucket has server\-side encryption enabled, but the user lacks KMS key permissions, the object cannot be written to the bucket. The mirroring action will fail, and additional traffic fees may be incurred. |
||Back\-to\-origin condition |A mirroring action is only triggered when the GetObject request results in an HTTP status code of 404. |
|Triggering via HeadObject |Restrictions |You cannot retrieve objects that are symlinks via HeadObject requests. |
||Back\-to\-origin condition |A mirroring action is only triggered when the option **Whether to support HeadObject** is enabled for the mirroring rule and the HeadObject request results in an HTTP status code of 404. |

## Steps


1. Log in to the [TOS console](https://console.byteplus.com/tos).

2. In the left navigation pane, click **Buckets**. In the **Buckets** list, click the bucket you want to manage.

3. In the left navigation pane, select **Basic configurations \> Back\-to\-Origin rules**. On the **Back\-to\-Origin rules** page, click **Create rule**.

4. On the **Create Back\-to\-Origin Rule** page, configure the following parameters:

   
   |**Parameter** |**Description** |
   |---|---|
   |Back\-to\-Origin method |Select **Mirroring**. |
   |Back\-to\-Origin condition |Configure the desired trigger conditions. A mirroring action will only be triggered when all configured conditions are met simultaneously. The fields are described as follows:<br><br><br>* **HTTP Status Code**: Selected by default and only supports **HTTP status code** **404**.<br><br>* **Filename prefix**: Select this option and enter the desired prefix.<br><br>* **Filename suffix**: Select this option and enter the desired suffix.<br><br><br>For example, if you set the filename prefix to `test` and the filename suffix to `object.png`, and then you attempt to access an object in the bucket that matches the pattern `test***object.png`, the object does not exist in the bucket and an HTTP 404 status code is returned. In this case, TOS provides the back\-to\-origin address configured in the rule, allowing you to access the object.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><br>* <div data-tips="true" data-tips-type="tip">After checking the box(es) for Filename prefix or/and Filename suffix, you must enter the corresponding information for the condition to take effect. If you leave the field(s) blank, the condition will not be matched.</div><br><br><br>* <div data-tips="true" data-tips-type="tip">To match all suffixes under a specific prefix, enable only the Filename prefix condition. Alternatively, enable the Filename suffix condition without entering a value.</div><br> |
   |Specify the domain |Specify which domain names are allowed to access the origin server. Accessing the origin server via any other domain name will not trigger mirroring actions.<br><br><div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div><br><br><br><br>* <div data-tips="true" data-tips-type="warning">You can specify a maximum of 20 domain names.</div><br><br><br>* <div data-tips="true" data-tips-type="warning">The domain names must be accessible to the bucket. We recommended using the custom domain associated with the bucket.</div><br> |
   |Back\-to\-Origin type |Set the origin server type for back\-to\-origin. The fields are described as follows:<br><br><br>* Select ** back to source private bucket** if the origin server is a private bucket from TOS or another cloud provider.<br><br>* Do not select **back to source private bucket** if the origin server is a public bucket from TOS or another cloud provider. |
   |Back\-to\-Origin address |Configure the address to which TOS will redirect once the back\-to\-origin conditions are met. Three configuration methods are supported, as explained below:<br><br><br>* **Add prefix and suffix**: When a mirroring action is triggered, redirect to the requested object with the prefix and/or suffix added to its name. The fields are described as follows:<br><br>   1. Origin server type (Required): Select **Primary Server** or **Secondary Server**. You can configure multiple primary and secondary servers.<br><br>      * If you configure multiple primary and secondary servers, TOS prioritizes requests to the primary servers and only requests the backup ones if all the primary ones fail to connect.<br><br>      * When requesting primary servers, TOS randomly selects one to initiate the request if multiple primary servers exist.<br><br>      * The same process applies to secondary servers.<br><br>   2. Protocol (Required): The options are **http** and **https**. The default is **http**.<br><br>   3. Domain name (Required): It must be in domain format. IP addresses are not supported.<br><br>   4. Prefix (Optional): If configured, this prefix is added to the object name for the request sent to the origin server. The object name returned to the client is unaffected by this prefix and remains unchanged.<br><br>   5. Suffix (Optional): If configured, this suffix is added to the object name for the request sent to the origin server. The object name returned to the client is unaffected by this suffix and remains unchanged.<br><br>      <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_3f1130e8e2478f7d7f6b6c7726025322.png) </span><br><br>      For example, if a client requests the object aaa.txt and the prefix is set to bbb, the requested object from the origin server will be bbbaaa.txt. However, the object returned to the client will still be aaa.txt.<br><br>* **Back\-to\-Origin address**: When a mirroring action is triggered, redirect to the back\-to\-origin address. The fields are described as follows:<br><br>   * Origin server type (Required): Select **Primary Server** or **Secondary Server**. You can configure multiple primary and secondary servers.<br><br>      * If you configure multiple primary and secondary servers, TOS prioritizes requests to the primary servers and only requests the backup ones if all the primary ones fail to connect.<br><br>      * When requesting primary servers, TOS randomly selects one to initiate the request if multiple primary servers exist.<br><br>      * The same process applies to secondary servers.<br><br>   * Protocol (Required): The options are **http** and **https**. The default is **http**.<br><br>   * Domain name (Required): It must be in domain format. IP addresses are not supported.<br><br>      For example, if a client requests the object aaa.txt and the back\-to\-origin address is set to http://example.com, and the object does not exist on the origin server, the request will be redirected to http://example.com to retrieve the object from that address.<br><br>* **Replace filename prefix**: When a mirroring action is triggered, redirect to the object with the filename prefix replaced. The fields are described as follows:<br><br>   * Origin server type (Required): Select **Primary Server** or **Secondary Server**. You can configure multiple primary and secondary servers.<br><br>      * If you configure multiple primary and secondary servers, TOS prioritizes requests to the primary servers and only requests the backup ones if all the primary ones fail to connect.<br><br>      * When requesting primary servers, TOS randomly selects one to initiate the request if multiple primary servers exist.<br><br>      * The same process applies to secondary servers.<br><br>   * Protocol (Required): The options are **http** and **https**. The default is **http**.<br><br>   * Domain name (Required): It must be in domain format. IP addresses are not supported.<br><br>   * Prefix (Optional): To replace a prefix, first specify the **Filename prefix** in the **Back\-to\-Origin condition** section. Then, the new prefix will replace the specified filename prefix.<br><br>      * Replacing a prefix is typically considered truncation. However, if you do not specify a prefix before replacing it, filling in this field is the same as adding a prefix.<br><br>      * The object name returned to the client is unaffected by this prefix and remains unchanged.<br><br>         For example, if a client requests the object aaa.txt, and the **Filename prefix** in the **Back\-to\-Origin condition** section is set to aa and the **Prefix** is set to bb, the requested object from the origin server will be bba.txt. However, the client will still receive aaa.txt.<br><br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">If you selected "back to source private bucket" as the Back\-to\-Origin type, you must enter the service provider information for your source bucket in the Back\-to\-Origin address section. The fields are described as follows:</div><br><br><br><br>* <div data-tips="true" data-tips-type="tip">If the service provider is BytePlus, click <strong>Click to Authorize</strong> to grant TOS access to your private bucket. Then, select the source bucket, which must be a bucket under the current account.</div><br><br><br>* <div data-tips="true" data-tips-type="tip">When the service provider is Baidu Cloud or Other S3 storage protocols, fill in the AccessKey (AK), SecretKey (SK), Source Region, Source bucket, and Back\-to\-Origin address to access the service provider.</div><br> |
   |Whether to support HeadObject |Select whether to trigger mirroring actions via HeadObject requests. When this occurs, TOS will not fetch the object from the origin server, but rather, retrieve the object metadata and return it to the requester.<br><br>By default, only GetObject requests can trigger mirroring actions. Enabling this option allows both GetObject and HeadObject requests to trigger mirroring actions. This option is disabled by default. |
   |Whether to carry request parameter |Select whether to forward the query string from the request to the origin server. This option is enabled by default.<br><br><div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div><br><br><br><div data-tips="true" data-tips-type="warning">Enabling this option will only transmit <a href="https://docs.aws.amazon.com/zh_cn/AmazonS3/latest/API/API_GetObject.html#API_GetObject_RequestParameters">parameters defined by AWS Signature Version 4</a> if your origin server is a private bucket. Note that this feature does not support forwarding all query string parameters from the request.</div><br> |
   |Disable Range Download Request Pull File |When this option is disabled and a range download request triggers a mirroring action, the requested object is fetched from the origin server, returned to the requester, and written to the bucket.<br><br>This option is disabled by default. For more information on range downloads, see [Range download (Java SDK)](https://docs.byteplus.com/docs/tos/Scope-download-java-sdk). |
   |Whether to redirect based on the origin server |Select whether to redirect the request based on the 3XX status code of the origin server. A request can only be redirected once. This option is disabled by default. |
   |HTTP Header Delivery Rules (client side to source) |Select the rule for passing response headers when TOS accesses the specified origin server. The options are as follows:<br><br><br>* **Transparently Transmit All HTTP Headers** (Default): When selected, all parameters are passed through, except the following headers: Host, Content\-Length, Date, and Authorization.<br><br>* **Transparently Transmit Specified HTTP Headers**: Define the specific headers that are allowed to be passed through. You can add a maximum of 10 headers.<br><br>* **Transparently Transmit No HTTP Headers**: When selected, all parameters are blocked from being passed through.<br><br>* **Not Transparently Transmit Specified HTTP Headers**: Define the specific headers prohibited from being passed through. You can add a maximum of 10 headers. |
   |Add specified HTTP headers (client side to source) |Specify the key and value for the HTTP header. This key and value will then be added to the header and passed through to the origin server.<br><br><div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div><br><br><br><br>* <div data-tips="true" data-tips-type="warning">You can specify a maximum of 10 HTTP headers.</div><br><br><br>* <div data-tips="true" data-tips-type="warning">Headers of the types Content\-Length, Date, Range, and Authorization are not supported.</div><br> |
   |Support custom metadata |* When fetching an object from a specified origin server, you can save the response headers (SourceHeader) from the origin as custom metadata for the object. TOS automatically prefixes the metadata key with `x-tos-meta-` and appends the suffix you set (MetaDataSuffix), forming the final metadata key.<br><br>* Click **Add metadata** and configure the following:<br><br>   * Enter the origin response header (SourceHeader) in the left input box.<br><br>   * Enter the metadata key suffix (MetaDataSuffix) in the right input box.<br><br>   You can add or remove multiple mapping groups. Each rule supports up to ten mappings.<br><br>* For example, if SourceHeader is `content-language` and MetaDataSuffix is `language`, the final metadata key is `x-tos-meta-language`. |
   

5. Click **Submit**.

   After creating a mirroring rule, you can view it in the rules list.

## Related operations


* Edit a back\-to\-origin rule: Click **Edit** in the **Actions** column of the rule you want to modify.

* Delete a back\-to\-origin rule: Click **Delete** in the **Actions** column of the rule you want to remove, and confirm the deletion by clicking **Delete** in the box that appears.

* Move a back\-to\-origin rule up/down: In the **Actions** column of the rule you want to move, click  **...**   **\> Up** or  **...**   **\> Down**.
