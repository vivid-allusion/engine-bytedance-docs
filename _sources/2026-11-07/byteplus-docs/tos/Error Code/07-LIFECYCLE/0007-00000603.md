# Problem description

For the same lifecycle rule or multiple rules with overlapping prefixes, both `Expiration` and `Transition` have configurations for `Date` and `Days` simultaneously.

<span id="51d11e16"></span>
# Root cause

For the same lifecycle rule or multiple rules with overlapping prefixes, both `Expiration` and `Transition` have configurations for `Date` and `Days` simultaneously.

<span id="104cff06"></span>
# Example

The following rule configures deletion after 30 days and transition to infrequent access after 10 days, but `Expiration` uses `Days` while `Transition` uses `Date`, which is not compliant.

```JSON
{
    "Rules": [{
      "ID": "id",
      "Prefix": "prefix",
      "Status": "Enabled",
      "Expiration": { "Days": 10 },
      "Transitions": [
        {
          "StorageClass": "IA",
          "Date": "2024-02-27T00:00:00.000Z"
        }
      ]
    }]
}
```


<span id="0f010e7b"></span>
# Solution

When configuring both `Expiration` and `Transition` in a lifecycle rule, either both must use `Days` or both must use `Date`.
