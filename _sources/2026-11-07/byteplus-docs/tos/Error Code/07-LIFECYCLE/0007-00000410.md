# Problem description

Multiple `Transitions` rules in the configured lifecycle policy conflict in timing.

<span id="4fe7465e"></span>
# Root cause

Multiple `Transitions` rules in the configured lifecycle policy conflict in timing. TOS requires the days for transitioning to different storage classes to follow this order:

Standard\-IA < Intelligent\-Tiering < Archive Instant Retrieval < Archive < Deep Archive < Ultra Deep Archive.

<span id="104cff06"></span>
# Example

The following configuration transitions to Standard\-IA after 30 days and to Intelligent\-Tiering after 3 days, which does not meet the requirements.

```JSON
{
    "Rules": [{
      "ID": "id",
      "Prefix": "prefix",
      "Status": "Enabled",
      "Transitions": [
        {
          "StorageClass": "IA",
          "Days": "30"
        },
        {
          "StorageClass": "INTELLIGENT_TIERING",
          "Days": "3"
        }
      ]
    }]
}
```


<span id="1d69dd3f"></span>
# Solution

Set lifecycle rules according to the settling time requirements between storage types (low\-frequency < intelligent tiering < archive instant retrieval < archive < cold archive < deep cold archive). For example, set the transition to intelligent tiering storage after 60 days.

```JSON
{
    "Rules": [{
      "ID": "id",
      "Prefix": "prefix",
      "Status": "Enabled",
      "Transitions": [
        {
          "StorageClass": "IA",
          "Days": "30"
        },
        {
          "StorageClass": "INTELLIGENT_TIERING",
          "Days": "60"
        }
      ]
    }]
}
```
