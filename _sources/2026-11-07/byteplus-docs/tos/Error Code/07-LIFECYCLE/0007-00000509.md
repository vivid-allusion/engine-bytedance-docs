# Problem description

There is a time conflict among multiple `NoncurrentVersionTransitions` rules in the configured lifecycle policies.

<span id="51d11e16"></span>
# Root cause

There is a time conflict among multiple `NoncurrentVersionTransitions` rules in the configured lifecycle policies. TOS requires the days for transitioning to different storage types to follow this order:

Infrequent access < intelligent tiering < archive instant retrieval < archive < cold archive < deep cold archive.

<span id="104cff06"></span>
# Example

The following configuration transitions to infrequent access storage after 30 days and to intelligent tiering storage after 3 days, which does not meet the requirements.

```JSON
{
    "Rules": [{
      "ID": "id",
      "Prefix": "prefix",
      "Status": "Enabled",
      "NoncurrentVersionTransitions": [
        {
          "StorageClass": "IA",
          "NoncurrentDays": "30"
        },
        {
          "StorageClass": "INTELLIGENT_TIERING",
          "NoncurrentDays": "3"
        }
      ]
    }]
}
```


<span id="2db96d63"></span>
# Solution

Set lifecycle rules according to settlement time requirements between storage types (low\-frequency < intelligent tiering < archive instant recovery < archive < cold archive < deep cold archive). For example, set to transition to intelligent tiering storage after 60 days.

```JSON
{
    "Rules": [{
      "ID": "id",
      "Prefix": "prefix",
      "Status": "Enabled",
      "NoncurrentVersionTransitions": [
        {
          "StorageClass": "IA",
          "NoncurrentDays": "30"
        },
        {
          "StorageClass": "INTELLIGENT_TIERING",
          "NoncurrentDays": "60"
        }
      ]
    }]
}
```
