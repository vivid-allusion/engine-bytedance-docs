# Problem description

Within the same lifecycle rule or between multiple rules with overlapping prefixes, there is a timing conflict between `Expiration` and `Transitions` configurations (for example, deletion set at 20 days and transition to archive set at 30 days).

<span id="51d11e16"></span>
# Root cause

Within the same lifecycle rule or between multiple rules with overlapping prefixes, there is a timing conflict between `Expiration` and `Transitions` configurations (for example, deletion set at 20 days and transition to Archive set at 30 days).

TOS requires that the days for transitions to different storage types follow this order:

Infrequent Access < Intelligent Tiering < Flashback Archive < Archive < Cold Archive < Deep Cold Archive < Deletion after expiration

<span id="104cff06"></span>
# Example

The following rule sets deletion at 10 days and transition to infrequent access at 30 days, which does not meet the requirement.

```JSON
{
    "Rules": [{
      "ID": "id",
      "Prefix": "prefix",
      "Status": "Enabled",
      "Expiration": { "Days": 10 },
      "Transitions": [
        {
          "StorageClass": "IA",
          "Days": 30
        }
      ]
    }]
}
```


<span id="9c931fb1"></span>
# Solution

When configuring both `Expiration` and `Transitions`, the number of days before switching to different storage types must follow this order:

Infrequent Access < Intelligent Tiering < Flashback Archive < Archive < Cold Archive < Deep Cold Archive < Deletion after expiration
