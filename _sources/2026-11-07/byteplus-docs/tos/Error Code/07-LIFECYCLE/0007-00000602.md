# Problem description

Within the same lifecycle rule, or multiple rules with overlapping prefixes, there is a time conflict between `NoncurrentVersionExpiration` and `NoncurrentVersionTransition` settings (for example, set to delete after 20 days and transition to archive after 30 days).

<span id="8816b076"></span>
# Root cause

Within the same lifecycle rule, or multiple rules with overlapping prefixes, there is a time conflict between `NoncurrentVersionExpiration` and `NoncurrentVersionTransition` settings (for example, set to delete after 20 days and transition to Archive after 30 days).

TOS requires that the days to transition between storage types must follow this order:

Infrequent Access < Intelligent Tiering < Flashback Archive < Archive < Cold Archive < Deep Cold Archive < Deletion after expiration

<span id="104cff06"></span>
# Example

The following rule configures historical version objects to delete after 10 days and transition to infrequent access after 30 days, which does not meet the requirements.

```JSON
{
    "Rules": [{
      "ID": "id",
      "Prefix": "prefix",
      "Status": "Enabled",
      "NoncurrentVersionExpiration": { "NoncurrentDays": 10 },
      "NoncurrentVersionTransition": [
        {
          "StorageClass": "IA",
          "NoncurrentDays": 30
        }
      ]
    }]
}
```


<span id="c400478b"></span>
# Solution

When configuring `NoncurrentVersionExpiration` and `NoncurrentVersionTransition` simultaneously, the number of days for transitioning to different storage types must follow this order:

Infrequent Access < Intelligent Tiering < Flashback Archive < Archive < Cold Archive < Deep Cold Archive < Deletion after expiration
