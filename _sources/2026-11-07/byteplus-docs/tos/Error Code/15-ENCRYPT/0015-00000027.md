## Problem description

The request fails when calling download or access object\-related interfaces (such as via API, SDK, or tosutil tool).

<span id="e3cd0283"></span>
## What it means

The target object uses KMS for server\-side encryption protection. When initiating a download or read request, the current credentials (IAM user or role) lack decryption permission for the KMS key (missing `kms:Decrypt Action`), causing the server to deny the data access request.

<span id="09ef757f"></span>
## Example

You initiate the following request:

```HTTP
GET /abc HTTP/1.1
Host: bucketname.tos-cn-beijing.volces.com
Date: GMT Date
Authorization: authorization xxx
```


Because object abc is encrypted with KMS and you don’t have decryption permission for that KMS key, the request fails with an error.

<span id="db35e26a"></span>
## Solution

When accessing KMS\-encrypted objects, add the corresponding KMS decryption permission to the IAM identity initiating the current request. Follow the steps below to resolve this issue:


1. Identify the request identity: Check the tool configuration or business code that caused the error and confirm the IAM user or role linked to the AccessKey used to initiate the request.

2. Configure IAM policy: log in to the Access Management (IAM) console and add or modify the permission policy for this identity, ensuring that the Action list includes `kms:Decrypt` permission.

   <div data-tips="true" data-tips-type="default" data-wrapper-indent="1">Following the principle of least privilege, replace the wildcard <code>*</code> in the Resource field with the specific TRN path of the KMS key that actually encrypts the object. After the permission policy configuration takes effect, resend the download or access request.   </div>
