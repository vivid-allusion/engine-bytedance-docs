# **Problem description**

The signature format is invalid.

<span id="ba9bae35"></span>
# Root cause

The signature format is incorrect.

<span id="85b94601"></span>
# Example

You initiated a request carrying the signature information in the Authorization header, but after splitting the Signature info by equal signs (=), the resulting array does not have a length of 2, the first element is not Signature, or the second element is empty.

```Go
PUT /objectName HTTP/1.1
Host: <Bucket name>.<TOS endpoint>
Date: GMT Date
x-tos-content-sha256: abc***
x-tos-date: 2022***
Authorization: TOS4-HMAC-SHA256 Credential=testAK/20220322/cn-beijing/tos/request,SignedHeaders=host;x-tos-content-sha256;x-tos-date,Signature=d40b6642843=67096f25d
```


The Signature info in the signature above is `Signature=d40b6642843=67096f25d`, which splits into an array of length 3 using equal signs (=).

<span id="e4e3712c"></span>
# Solution

Calculate the signature correctly. For detailed operations, refer to the [Signature mechanism](https://docs.byteplus.com/en/docs/tos/reference-signature-mechanism_1).
