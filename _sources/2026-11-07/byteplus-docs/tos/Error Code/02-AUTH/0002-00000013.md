# Problem description

Invalid signature format.

<span id="fd761bb8"></span>
# Root cause

The signature format is incorrect.

<span id="85b94601"></span>
# Example

You initiated a request carrying signature information in the Authorization header and URL parameter X\-Tos\-SignedHeaders, but the array elements obtained by splitting the SignedHeaders information by semicolon (;) include headers that do not exist.

```Go
PUT /objectName HTTP/1.1
Host: <Bucket name>.<TOS endpoint>
Date: GMT Date
x-tos-content-sha256: abc***
x-tos-date: 2022***
Authorization: TOS4-HMAC-SHA256 Credential=testAK/20220322/cn-beijing/tos/request,SignedHeaders=host;x-tos-content-sha256;x-tos-date;x-tos-acl,Signature=d40b66cf0054d1642843670d10fa095e1609c7896f25df217770b0abe717693b
```


In the above signature, the SignedHeaders information is `SignedHeaders=host;x-tos-content-sha256;x-tos-date;x-tos-acl`; among the elements split by semicolon (;), `x-tos-acl` does not appear in the request headers.

<span id="e4e3712c"></span>
# Solution

Use the correct method to calculate the signature. For detailed operations, refer to the [Signature mechanism](https://docs.byteplus.com/en/docs/tos/reference-signature-mechanism_1).
