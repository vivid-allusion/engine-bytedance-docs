# Problem description

The target file the symbolic link points to is also a symbolic link.

<span id="3616764e"></span>
# Root cause

The user accesses a symbolic link, but the target file the symbolic link points to is still a symbolic link.

<span id="cf2ef955"></span>
# Example

You request to download a symbolic link, but the target file it points to is still a symbolic link, causing the request to fail.

```Go
GET /link-to-link HTTP/1.1
Host: <Bucket name>.<TOS endpoint>
Date: Mon, 18 Mar 2019 08:25:17 GMT
Authorization: SignatureValue
```


<span id="cf2ef955"></span>
# Solution

Make sure the target file the symbolic link points to is not a symbolic link. Use the GetSymlink API to check the target file and its bucket, and use the x\-tos\-object\-type in the HeadObject API response to determine whether the target file is a symbolic link.
