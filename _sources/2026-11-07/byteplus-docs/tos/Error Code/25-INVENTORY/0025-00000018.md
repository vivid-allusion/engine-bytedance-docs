# Problem description

The content field in the bucket inventory rule is invalid.

<span id="70e05290"></span>
# Root cause

The bucket inventory rule only supports outputting several fixed field types; the server cannot recognize the field you set.

<span id="1d3e5f0b"></span>
# Example

When setting the bucket inventory rule, you passed a field not supported by the bucket inventory in the inventory content information (`OptionalFields`), specifically `SSEType`.

```HTML
PUT /?inventory&id=report1 HTTP/1.1
Host: <Bucket name>.<TOS endpoint>
Date: Mon, 31 Oct 2016 12:00:00 GMT
Authorization: authorization string
Content-Length: length
{
  "InventoryConfiguration": {
    "Id": "id",
    "IsEnabled": "true",
    "Filter": {
      "Prefix": "prefix"
    },
    "Destination": {
      "TOSBucketDestination": {
        "Format": "CSV",
        "AccountId": "2000000000000000", 
        "Role": "TosArchiveTOSInventory",
        "Bucket": "destination-bucket",
        "Prefix": "prefix1"
      }
    },
    "Schedule": { "Frequency": "Daily" },
    "IncludedObjectVersions": "All",
    "OptionalFields": {
      "Field": [
        "Size",
        "LastModifiedDate",
        "ETag",
        "StorageClass",
        "IsMultipartUploaded",
        "EncryptionStatus",
        "CRC64",
        "ReplicationStatus",
        "SSEType"
      ]
    }
  }
}
```


<span id="4021cb4f"></span>
# Solution

The fields passed in the inventory content information (`OptionalFields`) must be supported by the bucket inventory. For all supported field information, please refer to [PutBucketInventory](https://docs.byteplus.com/en/docs/tos/PutBucketInventory).
