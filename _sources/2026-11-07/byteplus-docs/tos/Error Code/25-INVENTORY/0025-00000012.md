# Problem description

The permission check for the role failed when creating the bucket inventory rule.

<span id="70e05290"></span>
# Root cause

When creating the bucket inventory rule, the provided `AccountId` or `Role` is in the wrong format, or the `AccountId` and `Role` do not have operation permissions on the target bucket.

<span id="1d3e5f0b"></span>
# Example

You entered an invalid `Role` when creating the bucket inventory rule.

```HTML
 PUT /?inventory&id=report1 HTTP/1.1
 Host: <Bucket name>.<TOS endpoint>
 Date: Mon, 31 Oct 2016 12:00:00 GMT
 Authorization: authorization string
 Content-Length: length
{
  "InventoryConfiguration": {
    "Id": "id",
    "IsEnabled": "true",
    "Filter": {
      "Prefix": "prefix"
    },
    "Destination": {
      "TOSBucketDestination": {
        "Format": "CSV",
        "AccountId": "2000000000000000", 
        "Role": "InValidRole",
        "Bucket": "destination-bucket",
        "Prefix": "prefix1"
      }
    },
    "Schedule": { "Frequency": "Daily" },
    "IncludedObjectVersions": "All",
    "OptionalFields": {
      "Field": [
        "Size",
        "LastModifiedDate",
        "ETag",
        "StorageClass",
        "IsMultipartUploaded",
        "EncryptionStatus",
        "CRC64",
        "ReplicationStatus"
      ]
    }
  }
}
```


<span id="4021cb4f"></span>
# Solution

Ensure that the `AccountId` and `Role` have the correct execution permissions on the target bucket. The `Role` can be set to the TOS default role TosArchiveTOSInventory. For details, see [PutBucketInventory](https://docs.byteplus.com/en/docs/tos/PutBucketInventory).
