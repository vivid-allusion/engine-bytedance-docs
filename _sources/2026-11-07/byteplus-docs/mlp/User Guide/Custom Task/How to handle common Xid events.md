Xid messages are error reports that the NVIDIA driver prints to the operating system's kernel log or event log. The Xid message indicates that a general GPU error has occurred, usually due to incorrect driver programming or corrupted commands sent to the GPU. Problems with GPU hardware, NVIDIA software, or user applications can generate Xid messages.

<span id="常见的-xid-事件"></span>
# Common Xid Events

When using the GPU in the Machine Learning Platform, users can view the number of Xids over a period of time through the monitoring panel of the task/service details page. The meaning of different Xid events is different. The following standard is "whether the user can solve it by himself", and the common Xid errors are divided into two categories for introduction. The complete Xid description is detailed in the [official NVIDIA documentation ](https://docs.nvidia.com/deploy/xid-errors/index.html).

<span id="尝试自行解决"></span>
## Try to solve it yourself

When encountering the following Xid errors, it is recommended to follow these steps to try to resolve them:


1. Try resubmitting the payload and observe if the Xid error disappears.

2. If the error persists, try to self\-check the code or analyze the log to see if the Xid error is due to user code.

3. If you confirm that the code is correct, contact the Machine Learning Platform customer service staff to deal with it.



|Xid |Note |
|---|---|
|13 |Graphics Engine Exception.<br><br>Usually the array is out of bounds, the instruction is wrong, and the small probability is a hardware problem. |
|31 |GPU memory page fault.<br><br>Usually it is an illegal address access by the application, and it is very unlikely that it is a driver or hardware problem. |
|43 |GPU stopped processing.<br><br>It is usually a user application error rather than a hardware problem. |
|45 |Preemptive cleanup, due to previous errors\-\-Most likely to see when running multiple cuda applications and hitting a DBE.<br><br>Usually the user exits manually or other failures (hardware, resource limitations, etc.) cause the GPU application to exit. Xid 45 is just a result and usually requires log analysis. |
|68 |NVDEC0 Exception.<br><br>It is usually a hardware or driver issue. |


<span id="联系平台处理"></span>
## Contact the platform to deal with it.

When encountering the following Xid errors, it is recommended to contact the Machine Learning Platform customer service staff directly:


|Xid |Note |
|---|---|
|32 |Invalid or corrupted push buffer stream.<br><br>Events are reported by the DMA controller on the PCIE bus that manages communication between the NVIDIA driver and the GPU, usually due to a PCI quality issue rather than a user program. |
|38 |Driver firmware error.<br><br>It is usually a driver firmware error rather than a hardware issue. |
|48 |Double Bit ECC Error（DBE）.<br><br>When an uncorrectable error occurs on the GPU, an Xid48 event is reported. The error is also reported to the user's application. It is usually necessary to reset the GPU or restart the node to clear this error. |
|61 |Internal micro\-controller breakpoint/warning.<br><br>The internal GPU engine has stopped working, and customer business has been affected. |
|62 |Internal micro\-controller halt.<br><br>Similar to the triggering scenario of Xid61. |
|63 |ECC page retirement or row remapping recording event.<br><br>When an application encounters a GPU memory hardware error, NVIDIA's self\-correction mechanism will retire or remap the erroneous memory area. The retirement and remapped information needs to be recorded to the infoROM for permanent effect.<br><br>Volt architecture: Log ECC page retirement event to infoROM successfully.<br><br>Ampere architecture: record row remapping event to infoROM successfully |
|64 |ECC page retirement or row remapper recording failure.<br><br>It is similar to the triggering scenario of Xid63, except that Xid63 means that the retirement and remapped information are successfully recorded in the infoROM, and Xid64 means that the recording operation fails. |
|74 |NVLINK Error.<br><br>Xid generated by NVLink hardware error. Receiving this event indicates that the GPU has suffered a serious hardware failure and needs to be offline for repair. |
|79 |GPU has fallen off the bus.<br><br>The GPU hardware detected a card drop and could not be detected from the bus. Receiving this event indicates that the GPU has suffered a serious hardware failure and needs to be offline for repair. |
|92 |High single\-bit ECC error rate.<br><br>Hardware or driver failure. |
|94 |Contained ECC error.<br><br>When an application encounters an uncorrectable video memory ECC error on the GPU, NVIDIA's error suppression mechanism attempts to suppress the error to the application stepping on the hardware failure, without causing the error to affect all applications on the GPU.<br><br>When the suppression mechanism successfully suppresses an error, an Xid 94 event is generated, affecting only applications that have encountered an uncorrectable ECC error. |
|95 |Uncontained ECC error.<br><br>Similar to the triggering scenario of Xid94. Only Xid94 represents suppression success, while Xid95 represents suppression failure, indicating that all applications running on that GPU have been affected. |
