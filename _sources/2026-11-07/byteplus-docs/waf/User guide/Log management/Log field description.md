When conducting log retrieval analysis, the involved log fields are divided into required fields and optional fields. Required fields are those that are collected by default in WAF logs, while optional fields are configurable for collection in WAF logs. Below are field descriptions and samples.

<span id="7f08e97e"></span>
## Required fields

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">Among the required log fields, <code>Host</code>, <code>XForwardedFor</code>, <code>Referer</code>, and <code>UserAgent</code> are common header fields. When you integrate website protection, WAF will by default collect these common header log fields.</div>



* <div data-tips="true" data-tips-type="tip">If you <strong>disable</strong><code>recording full headers</code>, the logs will only record these common header fields.</div>


* <div data-tips="true" data-tips-type="tip">If you <strong>enable</strong><code>recording full headers</code>, WAF will record both common header fields and custom header fields. Except for <code>Cookie</code>, other custom header fields are uniformly recorded in <code>Headers</code>.</div>




|**Field** |**Description** |Sample value |
|---|---|---|
|Host |The Host field of the client request header indicates the accessed domain name. |`www.test.com` |
|MatchedHost |Matching WAF access domain name. Identify the domain name of the hit WAF configuration. |For example, when configuring a wildcard domain `*.test.com`, the accessed domain is `a.test.com`, and this field records `*.test.com` |
|ClientIP |Client IP. |`1.XX.XX.1` |
|ClientPort |The port initiated by the client for access. |`80` |
|Path |The requested relative path, which refers to the part after the domain name and before the question mark (?) in the requested URL, excluding the query string. |`/news/search.php` |
|Method |The request method of the client request. |`GET` |
|TraceID |The unique identifier generated by WAF for the client request. |`7837b11715********************` |
|Scheme |The request protocol, including HTTP and HTTPS. |`HTTP` |
|XForwardedFor |The X\-Forwarded\-For (XFF) field in the client request header is used to identify the original IP address of the client connecting to the web server through HTTP proxy or load balancing. |`1.XX.XX.1` |
|ContentType |The content type being requested. |`application/x-www-form-urlencoded` |
|Referer |The Referer field in the client request header indicates the source URL information of the request. If the request has no source URL information, this field will be empty. |`http://example.com` |
|UserAgent |The User\-Agent field of the client request header contains information such as the client browser identifier and operating system identifier of the request source. |`Dalvik/2.1.0 (Linux; U; Android 7.0; EDI-AL10 Build/HUAWEIEDISON-AL10)` |
|QueryArgs |The query string in the client request, specifically referring to the part after the question mark (?) in the requested URL. |`title=tm_content%3Darticle&pid=123` |
|Status |The HTTP status code returned by WAF in response to the client request, including:<br><br><br>* 200: Request successful<br><br>* 4XX: Request failed |`200` |
|AttackType |Attack types include:<br><br><br>* blocklist: black<br><br>* geo_black: geographical location block<br><br>* httpflood: CC attack<br><br>* web_vulnerability: Web vulnerability attack<br><br>* bot: bot rules<br><br>* bot_frequency: bot frequency limit<br><br>* bot repeat: bot statistical protection<br><br>* bot dytoken: dynamic token<br><br>* bot sequence: behavior map<br><br>* route abnormal: Unregistered API exceptions<br><br>* param abnormal: Invalid API parameters<br><br>* api discarded: Discarded APIs<br><br>* api sensitive: Sensitive information<br><br>* sensitive info: sensitive information leakage |`black` |
|Plugin |Protection policy type.<br><br><br>* acl: access control<br><br>* dlp: prevent sensitive information leakage<br><br>* api_policy: API protection<br><br>* bot_policy: Bot management<br><br>* cc_policy: cc protection<br><br>* web_policy: vulnerability protection |`acl` |
|HitInfo |Secondary rule type after hitting the protection strategy type. |`ua_bot_web_scraper` |
|PolicyID |Protection rule ID. |`F000000000001` |
|EventLevel |Event level, including:<br><br><br>* 0: Low risk<br><br>* 1: Medium risk<br><br>* 2: High risk |`1` |
|ActionType |Disposal actions include:<br><br><br>* Pass: Allow<br><br>* Permit: Exception<br><br>* Observe: Observe<br><br>* Block: Intercept<br><br>* HumanVerify: Human verification<br><br>* HumanVerifyBlock: Human\-machine verification \- Intercept<br><br>* JS: JS Challenge<br><br>* JSBlock: JS Challenge \- Intercept<br><br>* Pow: Proof of Work<br><br>* PowBlock: Proof of Work \- Intercept<br><br>* Drop: Discard<br><br>* AnswerOpt: Answer Optimization |`Pass` |
|MatchedInfo |The field values that hit the rule match, such as sensitive information (ID card number or mobile phone number, etc.), regular expressions of vulnerability rules. |`[{"VarName":"RequestHeaders","Key":"X-Forwarded-For","Val":"sVyiy8bP' OR 252=(SELECT 252 FROM PG_SLEEP(15))--"}]` |
|UpStreamAddres |IP address of origin server and port. Format as `IP:Port`. Separate multiple records with a half\-width comma (,). |`192.168.0.0:55556` |
|UpStreamResponseTime |The time the origin server responds to the WAF back\-origin request. |`0.002` |
|UpStreamStatus |HTTP status codes that the origin server responds to WAF requests, including the custom status codes you have set. |`200` |
|Time |Client request initiation time. Represented according to the [ISO 8601](https://help.aliyun.com/zh/ecs/developer-reference/iso-8601-time-format#EcsApiTimeFormatISO8601) standard, using UTC time, in the format `yyyy-MM-ddTHH:mm:ss+08:00`. |`2024-09-25T14:49:50+08:00` |
|ServerProtocol |The protocol and version number of the source server's response to the WAF backsource request. |`HTTP/1.1` |
|APIID |API asset ID. |`I957277495165` |
|APIName |API asset name. |`apitest` |
|APIStatus |API status, including:<br><br><br>* pending: pending discovery<br><br>* discovering: Discovering<br><br>* discovered: Discovered<br><br>* managed: managed<br><br>* Dismissed: Dismissed<br><br>* Discarded: Discarded |`managed` |
|RequestBodyType |Request body type, such as: application/x\-www\-form\-urlencoded, application/json, etc. |`application/json` |
|ResponseBodyType |Response Body type, such as: application/json, application/xml, etc. |`application/json` |
|SensitiveTags |Sensitive information tag. |`test` |
|HitField |Strings that hit the rules, for example: `COOKIE:uid`, `CLIENTIP`. |`CLIENTIP` |
|Verification Status |Execution actions (including JS challenges, proof of work, human verification) verification results.<br><br><br>* Trigger: Trigger verification<br><br>* Timeout: Trigger after timeout<br><br>* Ok: Verification successful<br><br>* Pass: Verification released<br><br>* Failed: Verification failed<br><br>* Block: Intercept after failure<br><br>* skip: observe after failure |`pass` |

## Optional fields


|Field |Note |Sample value |
|---|---|---|
|Cookie |The Cookie field in the client request header, indicating the Cookie information of the originating client. |`k1=v1; k2=v2` |
|RequestBody |Request payload, currently supports up to 4 KB. |`2 KB` |
|RuleName |Name corresponding to the hit rule.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">This field is currently only effective for access control blocklist rules; under other rule conditions, this field value is empty.</div><br> |`rule1` |
|RuleDescription |The Description corresponding to the matching rule.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">This field currently only applies to access control blocklist rules; under other rule conditions, the value of this field is empty.</div><br> |`Used to restrict access for corresponding IPs.` |
|Headers |User\-defined header fields other than Cookie. Does not include common header fields recorded by WAF by default: `Host`, `XForwardedFor`, `Referer`, and `UserAgent`. |`Content-Length` |
