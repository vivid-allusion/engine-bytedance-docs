Bot management helps you monitor or restrict traffic from common automation tools, such as search engines, speed testing tools, content aggregators, scanning tools, etc., supporting the use of managed Bot management rules or custom Bot management rules. You can also configure frequency limits and statistical protection rules to prevent malicious access behaviors that meet statistical characteristics. In addition, the WAF can intelligently generate behavior maps based on already discovered and confirmed API requests, helping you analyze and manage risk APIs.

## Enable dynamic tokens

Dynamic tokens serve as a measure to enhance security, ensuring that only verified users can access protected applications or information. After enabling dynamic tokens, the client needs to provide a temporary code generated by the dynamic token when requesting access to complete authentication. If a request does not carry a dynamic token, it will be handled as "observe" or "intercept" according to the set action.

## Select managed bot classification rules

Managed bot classification means executing actions and rule switches according to the system's default Bot types to control traffic from different Bots.


1. Log in to [Web Application Firewall Console](https://console.byteplus.com/waf/dashboard).

2. In the top menu bar, select the region of your instance.

3. In the left navigation, select **Protection Policy \> Bot Management**.

4. Enable the classification rules for hosting bots for the domains that require protection.

   1. Select the domain that needs to add a policy.

   2. (Optional) Confirm that the protection mode of the current domain is "Protection enabled". Otherwise, click **Change protection mode** to modify it.

   3. Turn on the policy switch.

5. Set the bot hosting configuration in the hosted bot list.

   * Set the execution actions.

      * Observe: Allow the traffic to pass through, but record the behavior in the attack log.

      * Intercept: Intercept the request traffic and report the request behavior to the attack log. If a custom interception response page is configured, WAF will return the configured interception response page information to the client side.

      * JS Challenge: Verify the client\-side JavaScript execution capability through the JS\-SDK. If the verification is passed, it will be released within the specified time.

      * Man\-machine verification: Man\-machine verification is carried out through the verification code. If the verification is passed, it will be released to prevent false sealing.

      * Proof of Work: The client is required to calculate and submit results through the JS\-SDK. If the verification is passed, it will be released within the specified time.

         <div data-tips="true" data-tips-type="warning" data-tips-is-title="true" data-wrapper-indent="3">warning         </div>
         

         <div data-tips="true" data-tips-type="warning" data-wrapper-indent="3">Man\-machine verification, JS challenge, and proof\-of\-work action configuration only support web applications built on HTML and JavaScript. They are not applicable to native apps, mini\-program platforms, and server\-to\-server API communication. Please ensure that your web application is within the scope of use.         </div>
         

      * Release: Directly release the request traffic that meets the conditions.

   * Enable or disable a single rule switch.

      * Enable: The corresponding actions will be taken for this type of Bot traffic.

      * Disable: This type of Bot traffic will be released.

## Enable behavior mapping

The Bot behavior map refers to the WAF's intelligent tracking and analysis of discovered and confirmed API access behaviors and corresponding traffic based on domain name dimensions, providing a visual queue graph. You can set the default handling action for the queue, which means executing observation, interception, JS challenge, or CAPTCHA verification actions for API request behaviors in the queue.

<span id="49db89f7"></span>
### Steps are as follows:


1. Log in to [Web Application Firewall Console](https://console.byteplus.com/waf/dashboard).

2. Select the instance region in the top menu bar.

3. In the left navigation, select **Protection Policy \> Bot Management**.

4. Enable the behavior map policy for the domain to be protected.

   1. Select the domain to which the policy needs to be added.

   2. (Optional) Confirm that the protection mode of the current domain is "Protection enabled". Otherwise, click **Change protection mode** to modify it.

   3. Turn on the policy switch.

&nbsp;

5. Set actions for the behavior map policy.

   * Observe: Allow the traffic to pass through, but record the behavior in the attack log.

   * Intercept: Intercept the request traffic and report the request behavior to the attack log. If a custom interception response page is configured, WAF will return the configured interception response page information to the client side.

   * Man\-machine verification: Man\-machine verification is carried out through the verification code. If the verification is passed, it will be released to prevent false sealing.

   * JS challenge: Verify the client's JavaScript execution capability through the JS\-SDK. If the verification is passed, it will be released.


<span id="243e028f"></span>
### Behavior map user guide


* 1: Clicking on the name of the action queue in the list on the left side of the behavior map allows you to view the ID of that action queue, the number of hits, the number of abnormal behaviors, API request path information, and more. Supports setting disposal actions and time limits based on the behavior queue. For example, when the user activity sequence meets the queue shown in the diagram, set a CAPTCHA action that is effective for 60 seconds, with a limit duration of 120 seconds. This means that access is allowed within 60 seconds after passing verification, and detection continues after 60 seconds; if not passed, access will only be allowed after 120 seconds.

* 2: When you click the name of the action queue in the left list of the behavior map, the queue diagram corresponding to it will be displayed on the right side, including the accessed domain names and corresponding API nodes.

* 3: Clicking on the nodes in the queue diagram allows you to view the API request path and the queue associated with that node.
