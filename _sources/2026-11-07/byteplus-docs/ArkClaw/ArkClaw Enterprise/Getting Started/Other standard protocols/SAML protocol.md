ArkClaw Enterprise supports integration with your enterprise's existing identity provider (IdP) via SAML, enabling employees to use single sign\-on (SSO). This topic uses **Microsoft Active Directory Federation Services (AD FS)**  as an example to guide administrators through the entire process: ‌activating‌ an ArkClaw space, uploading IdP metadata, configuring user attribute mapping, adding a relying party trust and claim rules in AD FS, and providing the callback address. After the process is complete, administrators can provide employees with the employee login link for accessing ArkClaw.

<div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div>



* <div data-tips="true" data-tips-type="default">Using other standard protocols enables you to activate ArkClaw Enterprise quickly. Relevant information will be used in the configuration procedure after ArkClaw Enterprise activation.</div>


* <div data-tips="true" data-tips-type="default">ArkClaw supports independent ArkClaw spaces for different projects.<strong> This is an allowlist\-restricted feature available only after after being enabled.</strong> For details, see <a href="https://docs.byteplus.com/en/docs/ArkClaw/Quick_start_guide?TagIDs=2,522,512,502&lang=en#rH30UfdE">Activating multiple spaces</a>.</div>

* You already have an available AD FS environment and administrative privileges for the environment.

* You have obtained the IdP attribute name from the enterprise IT administrator.

* You have downloaded the IdP metadata file FederationMetadata.xml by accessing the AD FS IdP metadata endpoint `https://{AD FS domain name}/{path to FederationMetadata.xml}`.

## Terminology


|Term |Description |
|---|---|
|SAML |A common enterprise Single Sign\-On (SSO) protocol. You can think of it as the standard way for the enterprise identity system to securely convey to ArkClaw information about "who the currently logged\-in user is." |
|IdP |The identity provider (IdP). It is the system responsible for login authentication. For example, AD FS used in this topic. |
|SP (Service Provider) |Service provider, i.e., the system that receives the login result and provides services. In this topic, ArkClaw is the SP. |
|Metadata |Used to describe SAML connection information, typically including login URLs, certificates, and protocol capabilities. Importing the metadata reduces manual configuration effort. |
|SP Metadata |A metadata file generated by ArkClaw as the service provider. After importing this file, the IdP can automatically obtain the necessary connection information for ArkClaw. |
|Unique identifier policy |The field used to uniquely identify an employee. We recommend choosing a stable field that does not change frequently, such as email address or phone number. ‌Misconfiguration of this field may prevent employees from matching their existing accounts for logging in to ArkClaw. |
|IdP attribute name |The name of the user information field that the enterprise identity system (such as AD FS) sends to ArkClaw after user login. ArkClaw uses this IdP attribute name to locate the corresponding value (such as email address or name) and match it with the system fields. |
|Assertion |After a user logs in successfully, the IdP generates and signs identity credentials containing information such as "who the user is" and "when they logged in". When ArkClaw receives this information, it will verify the credentials to confirm the login identity is trustworthy. |
|Response Signature Verification |Signature verification of identity information returned by the IdP. This verification ensures the content remains untampered‌. |
|Assertion encryption |Encrypt the identity credentials returned by the IdP to prevent login credentials from being read in transit. |
|Claim / Claim Rule |Claims are attribute data (such as email, name, and employee ID) carried for each user by enterprise identity systems, for example, AD FS. Claim Rules‌ determine which attributes are sent to ArkClaw. |

## Step 4: Configure SAML protocol information


1. In the left navigation pane of the [ArkClaw Enterprise console](https://console.byteplus.com/arkclaw/enterprise), select "Organizations" \> "Users".

2. On the Users page, click "Configure now".

3. On the “Change employee authentication method” page, fill in the configuration information.

   
   |Configuration item |Description |
   |---|---|
   |Select protocol |Select "SAML" in the dropdown list. |
   |SAML metadata |Paste the content of the FederationMetadata.xml file downloaded from AD FS. |
   |User attribute mapping |Enter the user attribute mapping information.<br><br><br>* System fields:<br><br>   * id_attribute: The unique identifier of the user. ArkClaw uses this field to distinguish between different users. **Required**. Typically mapped to the email address or employee ID in the enterprise identity system.<br><br>   * name: The user's full name, which is displayed on the page after login.<br><br>   * email: The user's email address, which is used for receiving notifications.<br><br>   * phone_number: The user's phone number.<br><br>* IdP attribute name: The name of the user information field that the enterprise identity system (such as AD FS) sends to ArkClaw after user login. ArkClaw uses this name to locate the corresponding value (such as email address or name) and match it with the system fields on the left.<br><br><br><div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div><br><br><br><br>* <div data-tips="true" data-tips-type="default">The IdP attribute names need to be obtained from the enterprise IT administrator.</div><br><br><br>* <div data-tips="true" data-tips-type="default">For example, if the enterprise uses "http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress" to pass the email address, enter this name in the IdP attribute name field corresponding to the "email" row. ArkClaw will then recognize it as the user's email address.</div><br> |
   |Security configuration |Both **Response signature verification** and **Assertion encryption** are enabled by default. They effectively ensure the security of the login process and do not require manual adjustment. |
   |Unique identifier policy |Select based on the primary identity information used by your enterprise. When importing employee information or switching authentication methods later, the system will automatically merge accounts that share the same phone number or email address.<br><br><div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div><br><br><br><br>* <div data-tips="true" data-tips-type="default">The unique identifier policy is used to determine whether the same employee has been imported multiple times: When the employee list is imported again, the system will merge records for the same employee into a single entry based on the unique identifier you select. This field <strong>only determines the basis for merging and does not determine the login method</strong>.</div><br><br><br>* <div data-tips="true" data-tips-type="default">Policy options:</div><br><br><br>   * <div data-tips="true" data-tips-type="default"><strong>Email:</strong> Applicable to scenarios where employee email addresses are standardized and uniformly managed across the enterprise.</div><br><br><br>   * <div data-tips="true" data-tips-type="default"><strong>Mobile number:</strong> Applicable to scenarios involving external contractors or temporary accounts.</div><br><br><br>* <div data-tips="true" data-tips-type="default"><strong>After the unique identifier policy is applied, we recommend against changing it later</strong>: If you change it, existing employee records may not match newly imported employee records, resulting in duplicate accounts.</div><br> |
   

4. After configuration is complete, click the "Save" button to finish the operation.

5. On the "Users" page, click the "Login configuration" tab. In the "Basic configuration information" section, click "Download" to download the SP metadata file.

## Step 5: Configure callback information


1. Log in to the AD FS management console.

2. Add a relying party trust in AD FS.

   1. In the left pane of the AD FS console, select "Relying Party Trusts", then click "Add Relying Party Trust..." on the right.

      <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_9d1d09cbc9dca61b05c47f797c710620.png) </span>

   2. By default, "Claims aware" is selected. Click "Start".

      <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_cef31976a90e4cbef31c62c8c130017e.png) </span>

   3. Select "Import data about the relying party from a file", and locate the SP metadata file downloaded from ArkClaw.

      <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_c2c2afe8bf4c2f190a122afede8ddd74.png) </span>

   4. Set Display name and Access Control Policy as needed, and click "Next" to complete the addition.

      <div data-tips="true" data-tips-type="default" data-tips-is-title="true" data-wrapper-indent="2">tip      </div>
      

      * <div data-tips="true" data-tips-type="default" data-wrapper-indent="2"><strong>Display Name</strong>: Give this trust record an easily identifiable name (for example, "ArkClaw") so that you can quickly find it later in the AD FS console.      </div>
      

      * <div data-tips="true" data-tips-type="default" data-wrapper-indent="2"><strong>Access Control Policy</strong>: Determines which users can log in to ArkClaw via AD FS. If there are no special requirements, you can keep the default setting (Allow all users).      </div>
      

3. Configure the user information returned by the AD FS SAML client. That is, add new rules to select the target user information to be passed to ArkClaw.

   <div data-tips="true" data-tips-type="warning" data-tips-is-title="true" data-wrapper-indent="1">warning   </div>
   

   <div data-tips="true" data-tips-type="warning" data-wrapper-indent="1">Ensure that the user information passed to ArkClaw includes the <strong>unique user identifier attribute</strong>.   </div>
   

   1. Click the target trust record, then click "Edit Claim Issuance Policy...".

      <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_db0eeedb5c8b54d91aa9f7c712c5fd6e.png) </span>

   2. Click the "Add Rule" button to add a rule.

      <div data-tips="true" data-tips-type="default" data-tips-is-title="true" data-wrapper-indent="2">tip      </div>
      

      <div data-tips="true" data-tips-type="default" data-wrapper-indent="2">For detailed rule configuration, see <a href="https://learn.microsoft.com/en-us/windows-server/identity/ad-fs/operations/create-a-rule-to-send-ldap-attributes-as-claims">Understanding how user information is passed</a> and <a href="https://learn.microsoft.com/en-us/windows-server/identity/ad-fs/technical-reference/the-role-of-claims">How to configure AD FS to send User information fields to applications</a>.      </div>
      

      <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_e0253d218d8184e9f5f119f0938bfa50.png) </span>
