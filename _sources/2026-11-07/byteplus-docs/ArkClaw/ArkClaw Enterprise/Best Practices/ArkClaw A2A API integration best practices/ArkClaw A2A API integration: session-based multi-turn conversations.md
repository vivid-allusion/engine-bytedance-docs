When calling ArkClaw through an A2A client, each request creates an independent session by default, and the agent has no awareness of previous conversations. To enable coherent multi\-turn conversations and allow the agent to retain context from previous conversations, you can use `contextId` to associate the session context.

This topic describes how to use `contextId` to associate multiple requests with the same session, enabling multi\-turn context inference and follow\-up questions.

<span id="u3F4FcK8"></span>
## Background

After Webhook is enabled for the target ArkClaw instance, a dedicated public endpoint is generated. External A2A clients can use this endpoint to actively call the ArkClaw instance and handle various interaction scenarios, including single\-turn Q&A, long\-text streaming output, and asynchronous task processing.

### Step 2: Associate multiple requests to the same session through contextId

Requests carrying the same `contextId` belong to the same session. The agent can read the full conversation history within a session to perform context understanding, follow\-up questioning, and multi\-turn logical reasoning. The A2A API supports two multi\-turn session calling modes, synchronous and asynchronous. You can select the appropriate access mode based on your business scenario.


* **Synchronous access to the A2A API**

   After a request is sent, the connection remains blocked until the agent completes processing and returns the result. This access mode is suitable for short Q&A interactions, lightweight computations, and tasks with short overall processing time.

* **Asynchronous access to the A2A API**

   After a request is submitted, a task receipt is returned immediately. The task continues to run in the background, and the result can be retrieved later through polling. This access mode is suitable for long\-text generation, complex tool calls, and tasks with long execution times.


<div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="default">contextId lifecycle:</div>


<div data-tips="true" data-tips-type="default">
|<strong>Stage</strong> |<strong>Description</strong> |
|---|---|
|Generate |On the first request (without a <code>contextId</code>), the contextId is generated by the server. |
|Extract |The caller extracts the <code>contextId</code> value from the first response. |
|Reuse |For subsequent requests, the <code>contextId</code> value is written into <code>params.message.contextId</code> to maintain the same session. |
|End |Once the <code>contextId</code> is no longer included (by removing the <code>contextId</code> field from <code>message</code> in the request body), a new independent session starts. |
</div>
