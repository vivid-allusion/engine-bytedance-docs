The platform provides a dedicated monitoring dashboard for each ArkClaw instance, enabling real\-time, efficient oversight of key metrics, such as resource consumption and operational performance. This topic describes how to view the monitoring dashboard for an ArkClaw instance.

<span id="mZeKSeRK"></span>
## Prerequisites


* The administrator has completed basic settings (such as enterprise system permissions and callback configuration) and has activated ArkClaw Enterprise. For details, see [ArkClaw management for administrators](https://docs.byteplus.com/en/docs/ArkClaw/Administrator_opens_ArkClaw).

* Enterprise employees have applied for and created ArkClaw instances and initiated conversations with them for task processing. For details, see the [ArkClaw guide for employees](https://docs.byteplus.com/en/docs/ArkClaw/Employee_use_of_ArkClaw_new_version).


<span id="mcdSJk3X"></span>
## Limits

The token metrics for usage analysis are for reference only. For cost analysis, we recommend using the token metrics in model billing for cost calculation and comparison.

<span id="0F6EIwL7"></span>
## Procedure


1. Log in to the [ArkClaw Enterprise console](https://console.byteplus.com/arkclaw/enterprise).

2. In the left navigation pane, click **Claws** to access the ArkClaw instance management list.

3. Find the target ArkClaw instance and click **More \> Monitor** in the Actions column. Then, you'll be redirected to the **Monitor** tab of the details page for the ArkClaw instance.

4. Select a time range as needed to view the monitoring data for the specified period on the dashboard.


<span id="v1Mggpxp"></span>
### Token consumption


|Metric |Description |
|---|---|
|Input token |The number of tokens provided to the ArkClaw instance within the specified time range. This metric measures the volume of input text and is a core input item for model calculation and billing. |
|Output token |The number of tokens output by the ArkClaw instance within the specified time range. It measures the length of content generated by the model, and is a core output item for model calculation and billing. |
|Cached token |The number of tokens read from the cache by the ArkClaw instance within the specified time range. It measures cache reuse efficiency and reflects resource savings from cache hits. |
|Cache hit ratio |The cache hit ratio for input tokens of the ArkClaw instance within the specified time range. It is used to evaluate the effectiveness of the cache strategy. The calculation formula is as follows: Cache hit ratio = Cached tokens / (Input tokens + Cache tokens). |
|Input token trend |Visualizes and displays the real\-time consumption trend of tokens input to the ArkClaw instance within the specified time range. This helps evaluate changes in input load due to business growth by allowing you to observe fluctuations in input traffic, peak distribution, and changes in request complexity. |
|Output token trend |Visualizes and displays in real time the consumption trend of tokens output by the ArkClaw instance over time within the specified time range. It reflects changes in the overall volume of autoregressive inference and answer generation. This information helps you observe pressure on inference computing power or identify exceptions such as infinite loops and abnormally long outputs. |
|Cached tokens |Visualizes and displays in real time the trend of tokens read from the cache by the ArkClaw instance over time within the specified time range. It allows you to intuitively observe whether the cache remains effective and the level of reuse. You can use this information to optimize resource scheduling and develop an optimal high\-reuse path. |

### Resource monitoring


|Metric |Description |
|---|---|
|Claw process startup duration |The process lifetime of the current ArkClaw within the specified time range. It is used to measure instance startup efficiency and resource loading speed. |
|Gateway starts |The number of times the gateway of the current ArkClaw instance is started within the specified time range. It is used to collect statistics on instance restart frequency and lifecycle transitions, evaluate system stability, identify unexpected restart failures, and verify the effectiveness of self\-healing policies. |
|CPU usage |The CPU usage trend of the current ArkClaw within the specified time range. It is used to monitor instance compute load saturation, prevent computing power overload, guide scaling and scheduling, and ensure request processing throughput. |
|Memory usage |The memory usage trend of the current ArkClaw within the specified time range. It is used to monitor instance memory consumption and leakage risks, optimize memory structure, prevent OOM crashes, and ensure stable storage of chat context. |
|Disk IOPS |The disk IOPS read/write trend of the current ArkClaw within the specified time range. It is used to monitor disk read/write request processing capacity, identify storage I/O bottlenecks, and ensure the smoothness and stability of log and data read/write operations. |
|Disk IO bandwidth |The disk I/O read/write bandwidth trend of the current ArkClaw within the specified time range. It is used to monitor disk data transfer throughput, avoid I/O congestion, and improve data retrieval efficiency. |

### Skill & Tool invocations


|Metric |Description |
|---|---|
|Skill access count |The total number of times ArkClaw reads the `skill.md` file and loads it into the context within the specified time range. It reflects the activity level and business dependency on skill assets and can be used to assess context load and skill library utilization. |
|Average tool execution latency |The average latency taken for the ArkClaw instance to execute tools within the specified time range. It measures the overall response efficiency of the tool invocation process and reflects the end\-to\-end performance‌ from tool request initiation to result return. |
|Tool execution P90 latency |The P90 latency of tool executions by the ArkClaw instance within the specified time range. This metric indicates that 90% of all tool invocation requests are completed within this duration. It serves as a key metric for evaluating the stability of tool services. |
|Tool executions |The total number of tool executions by the ArkClaw instance within the specified time range. |
|Tool execution errors |The number of failed tool executions by the ArkClaw instance within the specified time range. It reflects the scale of anomalies occurring during tool invocations. |
|Tool execution error rate |The error rate of tool executions by the ArkClaw instance within the specified time range. The calculation formula is as follows: Tool execution error rate = Number of failed tool executions / Total number of tool executions. It is used to measure the reliability and stability of tool invocations. |
|Tool execution latency |The trend of changes in the tool execution latency for the ArkClaw instance over the specified time range. It visually demonstrates latency fluctuations and evolution patterns and helps pinpoint performance degradation issues, validate optimization results, warn of high\-latency risks, and ‌maintain a consistent tool invocation experience‌. |
|Skill access distribution |The distribution of the top 50 most accessed skills by ArkClaw within the specified time range. This metric intuitively shows the access popularity and usage proportion of each skill. It helps identify core high\-frequency skills and underused skills and provides data support for skill library governance, resource allocation optimization, and cost control. |
|Tool execution distribution |The distribution of the top 50 most executed tools by the ArkClaw instance within the specified time range. This metric intuitively presents the invocation popularity and business dependency of each tool and thereby helps identify core high\-frequency tools. It supports decision\-making for ensuring tool service stability, prioritizing resource allocation, and optimizing business processes. |
|Tool execution error distribution |The distribution of the top 50 tools with the most execution errors for the ArkClaw instance within the specified time range. This metric enables rapid identification of tools and interfaces with frequent execution errors, pinpoints failure\-prone components, and guides targeted tool optimization, interface remediation, and business process adjustments to enhance overall service stability. |

### Messages


|Metric |Description |
|---|---|
|Messages |The total number of messages processed by the ArkClaw instance within the specified time range. |
|Message processing success rate |The message processing success rate of the ArkClaw instance within the specified time range. It measures the service availability and stability of the ArkClaw instance. This information, together with metrics such as average message queue length and average message processing duration, enables rapid troubleshooting and root cause identification. The message processing success rate is the percentage of successful message processing tasks to the total message processing tasks. |
|Average message processing duration |The average time that ArkClaw spends processing messages within the specified time range. It quantifies the average processing duration of messages from receipt to full completion, directly reflecting end\-to\-end waiting time and user experience. In addition, as a service availability indicator, it can be used to assess whether the agreed response time requirements (such as P95 and P99 latencies) are met. |
|Average message queuing time |The average queuing time of messages in the ArkClaw instance within the specified time range. It quantifies the waiting time of messages in queues and reflects the level of alignment between the processing capacity and traffic load. |

### Agents


|Metric |Description |
|---|---|
|Agents |The total number of agents that engaged in data interactions with the ArkClaw instance within the specified time range. |
|Agent invocations |The total number of agent invocations by the ArkClaw instance within the specified time range. |
|Agent invocation P90 latency |The P90 latency of agent invocations by the ArkClaw instance within the specified time range. This metric indicates that 90% of agent invocation requests complete within this duration. It can be used to evaluate agent service quality and user experience. |
|LLM invocation success rate |The LLM invocation success rate of the current ArkClaw instance within the specified time range. This metric measures service reliability and LLM invocation stability and reflects the overall end\-to\-end health from request initiation to the return of a valid model response. It serves as a key metric for evaluating the availability of core agent capabilities. |
|Agent invocation latency |The trend of changes in the average agent invocation latency and ‌P90 latency over time for the ArkClaw instance within the specified time range. It visually demonstrates long\-term fluctuation patterns of agent invocation performance. This metric helps identify performance degradation, evaluate optimization effectiveness, implement early warnings of high\-latency risks, and ensure a consistent agent invocation experience. |
|LLM invocation success rate trend |The trend of the changes in LLM invocation success rates for the ArkClaw instance over the specified time range. This visually demonstrates fluctuations in LLM invocation success rates. It helps identify service failures, impacts of version changes, or network anomalies. It enables early warning of service disruption risks to ensure business continuity. |

|2 |Refresh frequency |Data refresh frequency. Available refresh methods include manual refresh or auto\-refresh at the specified intervals. |
