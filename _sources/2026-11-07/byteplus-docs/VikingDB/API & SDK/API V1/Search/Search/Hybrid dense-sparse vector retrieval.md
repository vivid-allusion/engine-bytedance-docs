# Overview

To perform a dense\-sparse mixed nearest neighbor retrieval, which combines semantic and keyword matching for improved search accuracy, you can use the /index/search API. This document details the required request parameters, response formats, and provides a complete request example to guide your implementation.

Dense\-sparse mixed nearest neighbor retrieval is a retrieval method that combines dense vectors and sparse vectors. It leverages the semantic matching capability of dense vectors and the keyword matching capability of sparse vectors to improve the accuracy and coverage of search results.

<span id="dense-vector"></span>
### **Dense Vector**


* **definition**:


Dense vectors are high\-dimensional vectors generated by models such as Skylark\-embedding that typically extract semantic features from text, images, or other data using deep learning models. Each dimension of the vector has a non\-zero value.


* **feature**:

   * Capturing implicit relationships through semantic understanding is suitable for semantic similarity calculation.

   * Disadvantages: Inability to find specific keywords or phrases, and a strong dependence on the quality of the embedding model. For example, if the search query is "Latest electronic product reviews", if a document contains the text "Here are detailed introductions and relevant user reviews of various latest electronic products on the shelves", it might not be accurately matched due to a semantic understanding bias.

   * For example: [1.2, 2.4, 3.7, 4.8]

* **application scenario**:

   * **semantic search**Find documents that are semantically similar to the query, even if they don't contain the exact same keywords.**recommender system**Generate dense vectors based on user interests, matching relevant content.


<span id="sparse-vector"></span>
### **Sparse Vector**


* **definition**:

* A sparse vector is a high\-dimensional vector in which most of the dimensions are zero, typically generated by bag\-of\-words models based on explicit keyword representations.**feature**:

   * More interpretable, capturing the explicit presence or absence of keywords.

   * Disadvantages: Difficulty in capturing richer, more nuanced semantics and similarities. For example, if the search query is "beautiful red apples", and a document contains the text "bright red apples are very beautiful", it may be missed because the keywords are not matched exactly.

* **application scenario**:

   * **Accurate keyword matching**: Suitable for retrieving documents that explicitly contain specific keywords.

   * **Legal documents, patent documents, and other fields: It is necessary to precisely locate keywords and determine their frequency.**

|---|---|---|

|**request header** |Content\-Type: application/json |Request message type |
| |Authorization: HMAC\-SHA256 \*\*\* |Authentication |


<span id="request-parameters"></span>
# **Request parameters**

For a **Vector Nearest Neighbor Search, you can specify the dense and sparse vectors for retrieval in the order_by_vector parameter and adjust the dense vector weight using the dense_weight sub\-parameter.** 


|**parameter** |**sub\-parameter** |**type** |**Is it required?**  |**default value** |**parameter description** |
|---|---|---|---|---|---|
|Search |order_by_vector |Map |Yes |*  |Performs a search based on vector distance. This parameter contains the following sub\-parameters:<br><br><br>* Vectors: Dense vectors for retrieval, up to 10.<br><br>* sparse_vectors: Sparse vectors for retrieval, up to 10. |
| |dense_weight |Float |No |0.5 |The weight of the dense vector in a mixed search. A value of 1 indicates a pure dense search.<br><br>Valid only if the index is a mixed index (hnsw_hybrid). Range [0.2, 1] |


Dense and sparse mixed nearest neighbor retrieval requires both dense and sparse vectors.

A dense vector is provided as a list of floats. A sparse vector is provided as a JSON object, where each key is a keyword and its corresponding value is the weight.

You can provide multiple dense and sparse vectors in a list, but the number of vectors of each type must be the same. A dense vector and a sparse vector at the same list index together form a single query.

<span id="complete-example"></span>
# Complete example

<span id="request-message"></span>
## Request message

```Shell
curl -i -X POST \
  -H 'Content-Type: application/json' \
  -H 'Authorization: HMAC-SHA256 ***' \
  https://api-vikingdb.mlp.ap-mya.byteplus.com/api/index/search \
  -d '{
    "collection_name": "test_name",
    "index_name": "index_test",
    "search": {
        "order_by_vector": {
            "vectors": [      // the query dense vectors 
                [0.1, 0.2, 0.3......0.9], 
                [0.01, 0.02, 0.03......0.09],
            ],  
            "sparse_vectors": [     // the query sparse vectors 
                {"what": 0.34, "is": 0.03, "B": 0.11, "M":0.32, "25": 0.03}, 
                {"one": 0.08, "of": 0.14, "information": 0.19, "retrieval": 0.63, "algorithms":0.97}            ]     
        }, 
        "limit": 2,
        "dense_weight": 0.5,     // the weight of the dense vectors 
    }
}
}'
```
