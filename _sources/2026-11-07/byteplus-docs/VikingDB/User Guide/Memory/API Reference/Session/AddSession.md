## API Overview

Adds a batch of messages (typically multi\-turn conversations) to a specified memory collection. The system will process and store these messages according to the memory collection's configuration (event types, profile types, extraction settings) to form structured memory events and potentially update associated profiles.

<span id="503c6f79"></span>
### **Notes**


* **Session Overwrite**

   * When calling the add_session API, using the same session_id will overwrite the existing user profile and events under that session.

   * It is recommended to generate session_id dynamically using a UUID to ensure each session is independent

   * Reuse the same session_id only if you explicitly intend to overwrite the profile and events.

* **Message Attribution**

   * The profiles and events are correctly attributed to the user and assistant **only if** both user and assistant messages are included in messages.

   * The API does not rely solely on the metadata IDs for attribution.

   * If only user messages are provided, events will not be linked to the assistant specified in metadata.

* **Memory Isolation Mechanism:** 

   * **Events:**  Events generated from messages associated with different assistants or groups are tagged with corresponding identifiers. These identifiers can be used as filter parameters during retrieval.

   * **Profiles:**  Profile isolation operates on two levels:

      * **Group:**  Profiles generated under different groups are completely isolated. (Note: 'Group' does not represent a group chat; it is recommended for use only when profile isolation is necessary.)

      * **Assistant:**  If a profile is configured for isolation by assistant, then within the same group, profiles generated from messages involving different assistants and users are also completely isolated. If the original message does not specify an `assistant` parameter, a profile not linked to any assistant (i.e., `assistant_id=""`) will be created.

## Sample Code

<span id="cURL Request"></span>
### Python Request

```python
import json
import requests
from volcengine.base.Request import Request
from volcengine.Credentials import Credentials
from volcengine.auth.SignerV4 import SignerV4

AK = "your AK" 
SK = "your SK" 
Domain = "api-knowledgebase.mlp.cn-hongkong.bytepluses.com"

def prepare_request(method, path, ak, sk, data=None):
  r = Request()
  r.set_shema("http")
  r.set_method(method)
  r.set_host(Domain)
  r.set_path(path)

  if data is not None:
    r.set_body(json.dumps(data))
  credentials = Credentials(ak, sk, 'air', 'cn-north-1')
  SignerV4.sign(r, credentials)
  return r

def internal_request(method, api, payload, params=None):

  req = prepare_request(
                        method = method,
                        path = api,
                        ak = AK,
                        sk = SK,
                        data = payload)

  r = requests.request(method=req.method,
          url="{}://{}{}".format(req.schema, req.host, req.path),
          headers=req.headers,
          data=req.body,
          params=params,
      )
  return r

import datetime
messages = [
    {"role": "user", "content": "I really love watching matches, and there's another one tomorrow!"},  
    {"role": "user", "content": "Xiao A has been training for this match against Xiao B for half a year."},  
    {"role": "assistant", "content": "So inspiring! That means the win is pretty much guaranteed, right?"},  
    {"role": "user", "content": "I think so too, since Xiao B hardly prepared at all."},  
    {"role": "assistant", "content": "Haha, let’s look forward to Xiao A’s performance together!"}  
]

path = "/api/memory/session/add"
playload = {
    "collection_name": "my_first_memory_collection",
    "session_id": "message0",
    "messages": messages,
    "metadata": {
        "default_user_id": "user1",
        "default_assistant_id": "assistant1",
        "time": int((datetime.datetime.now() - datetime.timedelta(days=1)).timestamp() * 1000) 
    } 
}
rsp = internal_request('POST', path, playload)
print(rsp.json())
```
