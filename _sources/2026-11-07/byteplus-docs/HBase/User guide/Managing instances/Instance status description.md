This document summarizes all possible status details of an HBase instance.


|Instance state |Parameter value |Actions that trigger this state |Description or impact |
|---|---|---|---|
|Creating |Creating |Create an instance. |The instance is being created and is not available to provide database services. |
|Failed to create |CreateFailed |The instance creation failed. |Failed to create the instance due to a system exception or other issues. The instance cannot provide services. Try creating the instance again, or [submit a ticket](https://console.byteplus.com/workorder/create/) to contact technical support. |
|Running |Running |The instance has been successfully created. |Database services can be provided normally. |
|Changing configuration |Scaling |Changing instance configuration. |The **Changing configuration** status appears after you confirm a configuration change. |
|Deleting |Deleting |Delete pay\-as\-you\-go instances or unsubscribe from subscription instances. |Deleting or unsubscribing from an instance clears all its resources and data. This action is irreversible. To learn how to delete or unsubscribe from an instance, see [Deleting or unsubscribing an instance](https://docs.byteplus.com/en/docs/HBase/Deleting_or_unsubscribing_an_instance).<br><br><div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div><br><br><br><div data-tips="true" data-tips-type="warning">After deleting or unsubscribing an instance, all data will be completely deleted and cannot be restored. Please operate with caution.</div><br> |
|Restarting |Restarting |Restart instance. |During the instance restart process, there will be a short\-term disconnection within seconds. Please perform this operation during off\-peak hours and ensure that the application has an automatic reconnection mechanism. For more details, see [Restarting instances](https://docs.byteplus.com/en/docs/HBase/Restarting_instances). |
|Upgrading |Upgrading |Upgrade the minor version of the instance. |During an upgrade, a single RegionServer node may be unwritable for a few seconds, but read requests are not affected. |
|Shutting down |Closing |The account for the pay\-as\-you\-go instance is overdue, or the subscription instance has expired. |An intermediate state during the instance shutdown process. When the account of a pay\-as\-you\-go instance has an overdue payment or its subscription expires, the instance first enters the **Shutting down** state for system processing. After the system finishes processing, the instance status changes to **Closed**. |
|Closed |Released |The account for the pay\-as\-you\-go instance is overdue, or the subscription instance has expired. |If the account to which a pay\-as\-you\-go instance belongs is in arrears or the subscription instance expires, the instance will enter the **Closed** state. The instance cannot provide services.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">We recommend topping up your account in the <a href="https://console.byteplus.com/finance/account-overview/">Expense center</a> before any payment is overdue, or <a href="https://docs.byteplus.com/en/docs/HBase/Renewal_management">renewing</a> your subscription instance before it expires.</div><br> |
|Network maintaining |NetworkMaintaining |Modify the instance's network connection settings, including:<br><br><br>* Upgrade the subnet.<br><br>* Enabling or disabling high\-availability Thrift connection address.<br><br>* Enable or disable public network access. |When you upgrade the subnet, enable or disable the high\-availability Thrift connection address, or enable or disable public network access, the instance enters the **Network maintaining** state. For more information about the HBase connection address, see [Viewing connection address](https://docs.byteplus.com/en/docs/HBase/Viewing_connection_address). |
|Allowlist maintaining |AllowListMaintaining |Modify the association between an instance and an allowlist, including:<br><br><br>* Associate an instance with an allowlist.<br><br>* Disassociate an instance from an allowlist. |When associating or disassociating an instance and an allowlist, the instance enters the **Allowlist maintaining** state. For details, see [Associating allowlist and instance](https://docs.byteplus.com/en/docs/HBase/Associating_allowlist_and_instance) and [Disassociating instance and allowlist](https://docs.byteplus.com/en/docs/HBase/Disassociating_instance_and_allowlist). |
|Task failed |TaskFailed |Failure to perform operations such as configuration changes, version upgrades, parameter modifications, and network changes. |The instance enters the **Task failed** state if an operation, such as a configuration change, version upgrade, parameter modification, or network change, fails. In this state, the instance can typically provide services as usual. |
