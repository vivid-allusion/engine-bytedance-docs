This article describes how to perform symbol table management and SourceMap management.

<span id="ca61e174"></span>
## symbol table management

The symbol table is used to parse the contents of crash stack traces and convert the minidump format into more readable text.

<span id="47c37795"></span>
### iOS symbol table management


1. Log in to [the Application Performance Management Plus console](https://console.byteplus.com/observe/apmplus-client).

2. Click **App Monitoring** under the target application.

3. In the upper left corner of the console, select **File Management \> Symbol Table Management**.

4. On the **symbol table management** page, select the iOS operating system, then click + or drag a file to upload the symbol table file.

   * The symbol table file is a dSYM file.

   * Because a dSYM file is actually a folder, you must compress the dSYM file before uploading, and the compressed file size must not exceed 1GB.

   * When uploading multiple files, directly compress all symbol tables together before uploading. Do not add unnecessary folder levels during compression.

      When compressing, the zip utility on Mac needs to execute the following command to remove the default generated `DS_Store__MACOSX` files.

      ```PowerShell
      zip -r test.app.dSYM.zip test.app.dSYM -x "*.DS_Store" -x "__MACOSX"
      ```
      

      <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="2">tip      </div>
      

      <div data-tips="true" data-tips-type="tip" data-wrapper-indent="2">Please replace <code>test.app.dSYM.zip</code> and <code>test.app.dSYM</code> with your symbol table name.      </div>
      

5. After a successful upload, verify in the symbol table list under the **Uploaded** tab whether the upload was successful.

   The symbol table list displays information about uploaded symbol table files. The specific details are shown in the following table.

   
   |**Parameters** |**DescriptionS** |
   |---|---|
   |UUID |Binary UUID package. Execute `dwarfdump -uuid` in the command line. You can view the UUID. |
   |Package name |The application's Bundle ID. |
   |Size |The size of the uploaded symbol table file. |
   |Version Number |App version number. |
   |Uploader |The operator who uploads the symbol table file. |
   |Upload time |Upload time of the symbol table file. |
   |Actions |Click **download** to view the symbol table file. |

### Android symbol table management


1. Log in [Application Performance Management Plus console](https://console.byteplus.com/observe/apmplus-client).

2. Click **App Monitoring** under the target application.

3. In the upper left corner of the console, select **File management \> symbol table management**.

4. On the **symbol table management** page, select Android, select **crash type**, and then click **upload symbol table**.

   API Key and API Token, used for automatically uploading symbol table. For details, refer to [(Optional) Step 3: Upload symbol table](https://docs.byteplus.com/en/docs/apmplus/Integrate_the_Android_SDK_into_the_application#49dce7df).

   <div data-tips="true" data-tips-type="warning" data-tips-is-title="true" data-wrapper-indent="1">warning   </div>
   

   <div data-tips="true" data-tips-type="warning" data-wrapper-indent="1">When the crash type is <strong>Native crash</strong>, please upload the Debug SO file.   </div>
   

   <div data-tips="true" data-tips-type="warning" data-wrapper-indent="1">On the Android platform, a Debug SO file refers to an SO file that contains debugging information, including symbol information that allows users to restore the stack trace. To facilitate locating the Debug SO file corresponding to a crash and restoring the stack trace, it is recommended to back up the Debug SO file before each build or app version release.   </div>
   

   * <div data-tips="true" data-tips-type="warning" data-wrapper-indent="1">Build a project with CMake:   </div>
   

      * <div data-tips="true" data-tips-type="warning" data-wrapper-indent="1">By default, the Debug SO file generated by a Debug build will be located at: <project folder\>//build/intermediates/cmake/debug/obj/local<architecture\>/   </div>
   

   * <div data-tips="true" data-tips-type="warning" data-wrapper-indent="1">NDK build project:   </div>
   

      * <div data-tips="true" data-tips-type="warning" data-wrapper-indent="1">By default, the Debug SO file generated by a Debug build will be located at: <project folder\>//build/intermediates/ndk/debug/obj/local<architecture\>/   </div>
   

      * <div data-tips="true" data-tips-type="warning" data-wrapper-indent="1">The Debug SO files generated by the Release build will be located at: <project folder\>//build/intermediates/ndk/release/obj/local<architecture\>/   </div>
   

   * <div data-tips="true" data-tips-type="warning" data-wrapper-indent="1">The symbol table of the NDK compilation project may also be located at:   </div>
   

      * <div data-tips="true" data-tips-type="warning" data-wrapper-indent="1">Debug build <project folder\>//build/intermediates/<strong>ndkBuild/</strong>/debug/obj/local<architecture\>/   </div>
   

      * <div data-tips="true" data-tips-type="warning" data-wrapper-indent="1">Release build <project folder\>//build/intermediates/<strong>ndkBuild/</strong>/release/obj/local<architecture\>/   </div>
   

5. In the upload symbol table dialog, click + or drag the symbol table file, and configure the version number.

   Parameter description:

   
   |**Parameter** |**DescriptionS** |
   |---|---|
   |Symbol table file |Upload the mapping file generated after packaging. |
   |Version Number |Enter the application version number that corresponds to the symbol table (version_code). |
   

6. After the upload is successful, check the **Uploaded** tab in the symbol table list to verify the upload.

   The symbol table list displays information about uploaded symbol table files. The specific details are shown in the table below.

   
   |**Parameters** |**DescriptionS** |
   |---|---|
   |Shared object library name |The symbol table name. When the crash type is Native crash, the information in this column will be displayed. |
   |Version Number |The application version number. |
   |UUID |A binary UUID package. |
   |Size |Size of uploaded symbol table file |
   |Uploader |The operator who uploaded this symbol table file. |
   |Upload time |Symbol table file upload time. |
   |Actions |* Click **download** to view the symbol table file.<br><br>* Click **Update**: After selecting the symbol table file from your computer, re\-upload the symbol table file. |

### Harmony symbol table management


1. Log in to [the Application Performance Management Plus console](https://console.byteplus.com/observe/apmplus-client).

2. Click **App Monitoring** under the target application.

3. In the upper left corner of the console, select **File Management \> Symbol Table Management**.

4. On the **symbol table management** page, select the Harmony operating system, select the **crash type**, and then click **upload symbol table**.

   API Key and API Token, used to automatically upload the symbol table. For details, refer to [(Optional) Step 3: Upload symbol table](https://docs.byteplus.com/en/docs/apmplus/Integrate_the_Android_SDK_into_the_application#49dce7df).

5. In the **Upload Symbol Table** dialog box, click + or drag the symbol table file, and configure the version number.

   Parameter descriptions:

   
   |**Parameter** |**DescriptionS** |
   |---|---|
   |Symbol table file |Upload the mapping file generated after packaging. |
   |Version Number |Enter the application version code (version_code) that corresponds to the symbol table. |
   

6. After a successful upload, verify it in the **Uploaded** tab of the symbol table list.

   The symbol table list displays information about uploaded symbol table files. The specific information is shown in the table below.

   
   |**Parameters** |**DescriptionS** |
   |---|---|
   |.so library name |Symbol table name. When the crash type is Native crash, this column's information will be displayed. |
   |Version Number |Application version number. |
   |UUID |The binary UUID package. |
   |Size |The size of the uploaded symbol table file. |
   |Uploader |The operator who uploaded this symbol table file. |
   |Upload time |Upload time of the symbol table file. |
   |Actions |* Click **download**: view the symbol table file.<br><br>* Click **Update**: After selecting the symbol table file locally, re\-upload the symbol table file. |

## SourceMap management

A SourceMap is a file that stores mapping information between the positions in source code and compiled code. It allows you to restore compressed, obfuscated, or merged output code to its original, unpackaged form, helping you accurately locate the line and column where issues occur in the production environment.


1. Log in to the [Application Performance Management Plus console](https://console.byteplus.com/observe/apmplus-client).

2. Click **App Monitoring** under the target application.

3. In the upper left corner of the console, select **File management \> Sourcemap management**.

4. On the **Sourcemap management** page, click **Upload Sourcemap**.

5. On the **Upload Sourcemap File** page, complete the following configuration, and then click **Confirm**.

   Parameter description:

   
   |Parameter |DescriptionS |
   |---|---|
   |File names to be parsed |A custom filename, used to identify this Sourcemap file. |
   |Upload Sourcemap |Click **Add file**.<br><br><br>* Only one file can be uploaded.<br><br>* Only files in the .js.map format are supported. |
