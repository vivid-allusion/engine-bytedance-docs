Some jailbroken devices may use malicious techniques to frequently generate crashes or other abnormal data, resulting in a large number of logs being reported. To prevent such devices from unexpectedly consuming your event quota, you can use the following methods to block logs generated by these devices.

<span id="dRZjo8Z3"></span>
## Prerequisites


* Only iOS is supported.

* You need to upgrade the SDK version to 5.1.7 or later.


<span id="Csd8kWEm"></span>
## Operation Procedure

<span id="7TLGHV1T"></span>
### Crash analysis

After adding the following configuration, all crash logs generated by jailbroken devices will be blocked.


1. Switch to the **Whether to ignore jailbroken device** parameter.

2. Click **Create configuration** or edit the fallback configuration.

3. Switch the value of the parameter to **Yes**.

4. Save the changes, and wait for the client to retrieve the latest configuration. After that, crash logs generated by jailbroken devices will no longer be reported.


<span id="ExaB09ca"></span>
### Other logs

Setting the sampling rate of jailbroken devices to 0 can block other logs generated by these devices. In [Event Usage](https://docs.byteplus.com/en/docs/apmplus/Event_usage_app), view the sampling rates for each type of event, and then adjust the sampling rate for any events you want to block. The following example shows how to block MetricKit data.


1. Select **MetricKit stability sampling rate**, then create a configuration.

2. Sampling rate is set to**0**At the same time, add the filter condition: `Jailbroken user = Yes`.

3. Drag the newly created configuration to the top to make it the highest priority, and save the changes. Once the client fetches the latest configuration, MetricKit logs generated by jailbroken devices will no longer be reported.
