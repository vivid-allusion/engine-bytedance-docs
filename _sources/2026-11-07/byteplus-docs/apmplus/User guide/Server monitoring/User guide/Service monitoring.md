Service monitoring integrates information related to services, including Trace, Metrics, log, infrastructure monitoring, and more. It provides convenient monitoring capabilities such as service list, global service topology, service overview, and instance analysis.

<span id=".5YmN5o-Q5p2h5Lu2"></span>
## Prerequisites

The service metrics and distributed tracing features require the application to integrate Trace capability. For details, see [Application Integration](https://docs.byteplus.com/en/docs/apmplus/Java_application_integration).

<span id=".5YWo5bGA5pyN5Yqh5ouT5omR"></span>
## Global service topology

The global topology helps you quickly organize the overall service architecture and upstream and downstream call relationships. You can also view the success rate of calls between services in real time and quickly identify problematic services.

Service topology page description:


* The service topology displays a tree diagram by default. You can switch to a star diagram as needed.

   * Tree diagram: Shows hierarchical relationships, allowing you to more clearly view the call sequence and trace between services.

   * Star diagram: Shows group relationships, providing a more intuitive understanding of how many service traces exist.

* Services are represented by points

   * Point size: Associated with the number of times the service is called. The more calls, the larger the point.

   * Point color: Associated with the service success rate. According to the threshold configured by the user in the configuration, the colors are displayed as follows:

      * Green: Satisfactory

      * Yellow: Average

      * Red: Poor

* Call relationships are represented by lines

   * Red (poor): Used to mark calls with a failure rate higher than 50%

* Click a node in the topology map to open the **Service Metric Details** panel on the right, which displays core metrics for the node, such as QPS, error rate, and latency, and provides the following quick navigation links:

   * Service node: [Service Details](https://docs.byteplus.com/en/docs/apmplus/Service_monitoring?lang=en#.5pyN5Yqh5oC76KeI), [Trace Analysis](https://docs.byteplus.com/en/docs/apmplus/Trace_analysis?lang=en), [Log Analysis](https://docs.byteplus.com/en/docs/apmplus/Service_monitoring?lang=en#.5pel5b-X5YiG5p6Q)

   * Middleware node: [Middleware Details](https://docs.byteplus.com/en/docs/apmplus/Middleware_monitoring?lang=en)


<span id=".5pyN5Yqh5YiX6KGo"></span>
## Service list


* Services integrated with monitoring are automatically added to the service list after they start. You can also manually create service information before the service starts.

* The list displays information such as service name, type, status, error rate, QPS, latency, CPU utilization, memory usage rate, and most recent view time. All metrics support sorting.

* Keyword search by service name is supported.

* Supports subscribing to, configuring, and deleting services. By configuring services, you can modify sampling configuration and interface configuration. For a detailed configuration description, see: [Parameter management](https://docs.byteplus.com/en/docs/apmplus/parameter_management).


<div data-tips="true" data-tips-type="warning" data-tips-is-title="true">warning</div>



* <div data-tips="true" data-tips-type="warning">The priority of custom service configuration is higher than the Parameter configuration at the workspace level in Parameter management. For example, when both Parameter management and the service configure sampling rules, the actual sampling rules follow the custom service configuration.</div>


* <div data-tips="true" data-tips-type="warning">Service\-level sampling configuration is only effective for the root span generated by the current service.</div>

### Service overview

The service overview allows you to quickly obtain the most critical monitoring metrics for the current service, helping you confirm whether there are issues such as excessive calls, a high error rate, or high latency. Includes the following metrics:

<div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="default">Large language model\-related metrics are only displayed in the service overview of AI applications.</div>



* Call overview: request count, error count, response time, large language model call count, total token consumption, average latency of large language model calls. Click the jump button in the upper left corner of the chart to navigate to the Trace Analysis page related to the current service. The time range is consistent with the current dashboard.

* Large language model metrics: large language model call QPS, large language model call count, token count, large language model call latency, TTFT, TPOT.

* Request metrics: request QPS, request count, status code distribution, status code request count. Click the data link in the chart to navigate to the Trace Analysis page related to the current service. The time range is consistent with the current dashboard.

* Latency metrics: average latency, latency PCT50, latency PCT90, latency PCT99. Click the data link in the chart to navigate to the Trace Analysis page related to the current service. The time range is consistent with the current dashboard.

* Error metrics: error count, error rate, errors per second. Click the data link in the chart to navigate to the Trace Analysis page related to the current service. The time range is consistent with the current dashboard.

* Log metrics: error log count, error log count per second. Click the jump button in the upper left corner of the chart to navigate to the Trace Analysis page related to the current service. The time range matches the current dashboard range.

* Container metrics: Service CPU Usage Ratio, CPU Usage, Service Memory Usage Ratio, memory usage.

* Interface ranking: Top 5 interface requests, Top 5 interface error count, Top 5 interface latency.

### Instance analysis

<div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="default">If the process startup time is not collected, <code>-</code> will be displayed.</div>



* Click the host name to view the detailed host monitoring dashboard, which provides multiple monitoring metrics for CPU, memory, disk, and load, for example: CPU utilization, CPU monitoring, average load over the past 15 minutes, available memory, memory usage, disk space usage ratio, IO latency, and process memory usage distribution.

* Click **view details** in the Actions column of the target instance to view the basic information and monitoring metrics of the instance. Includes Overview, container metrics, process metrics, RED method, runtime monitoring, connection pool monitoring, and thread pool monitoring.

   * **Overview**: Includes data overview, instance overview, and Container list. The data overview displays metrics such as request count, error count, and average time. Click **container monitoring** in the Actions column of the Container list to enter the **container metrics** page and view the metric data of the container to which the instance belongs.

   * **Container metrics**: Includes data overview, Container list, and container dashboard. The container dashboard displays metrics such as the container's CPU utilization, the container's memory usage rate, the container's write IO throughput, the container's write IO QPS, and the container's FD thread count.

   * **Process metrics**: Displays metrics for CPU, memory, file count, and context switches.

   * **RED method**: Displays metrics such as request count, response latency, request QPS, status code distribution, error count, error rate, average latency, latency PCT90, top 5 interface requests, top 5 interface latency, and more.

   * **Runtime monitoring**: Displays JVM monitoring metrics, Go Runtime monitoring metrics, Python Runtime monitoring\-related metrics, e.g.: GC count, GC duration, memory usage rate, heap memory usage details, heap memory submit details, buffer usage details, cgo call count, HeapAlloc, and more.

   * **Connection pool monitoring**: Displays metrics such as maximum connection count, active connection count, idle connection count, minimum idle connection count, maximum idle connection count, blocked connection count, and more.

   * **Thread pool monitoring**: Displays metrics such as maximum thread count, core thread count, active thread count, thread pool size, thread pool task count, rejected task count, and more.

### Interface monitoring

Through interface monitoring, you can view the complete list of service interfaces, and sort by QPS, overall error rate, or latency PCT90 within the selected time period. You can also view trend charts for key metrics of the selected interface.


* Call metrics: QPS, request count

* Error metrics: error rate, error count, and errors per second

* Latency metrics: mean response latency and quantile


Click an interface in the interface list to quickly drill down to the interface call details search page. You can sort and filter by latency to quickly locate slow queries, and filter by status code to quickly locate error queries.

Click TraceID to view Trace details and highlight the selected Span information.

<span id=".5LiK5LiL5ri46LCD55So"></span>
### Upstream and downstream calls

Through upstream and downstream monitoring, you can view the complete list of all upstream and downstream services and interfaces, view the average QPS, overall error rate, and latency PCT90 within the selected time period, and view trend charts for key metrics of the selected call.


* Call metrics: QPS, request count

* Error metrics: error rate, error count, and errors per second

* Latency metrics: mean response latency and quantile


Click the called interface and called service to quickly drill down to the interface call details search page.

#### Python runtime metrics

For Python application services, the following metrics are provided: CPU time, CPU utilization, memory usage, GC object count, thread count, and context switch count.

Description of Python runtime metrics:


|**Metric name** |**Metric** |**Description** |**Unit** |
|---|---|---|---|
|CPU time |process_runtime_cpython_cpu_time |CPU time consumed by the application, counted separately for user mode and kernel mode. |s |
|CPU utilization |process_runtime_cpython_cpu_utilization |Application CPU utilization, which may exceed 100% |% |
|Memory usage |process_runtime_cpython_memory |Application memory usage, categorized into RSS (Resident Set Size) and VMS (Virtual Memory Size). |Byte |
|GC object count |process_runtime_cpython_gc_count |Number of objects added to each generation by the garbage counter since the last garbage collection, counted for generations 0, 1, and 2 **.**  |\- |
|Number of threads |process_runtime_cpython_thread_count |Number of application threads. |\- |
|Number of context switches |process_runtime_cpython_context_switches |The number of context switches, counted separately as Involuntary and Voluntary. |\- |

### Error analysis

Through error analysis, you can intuitively see the various types of interface errors present in the system and their distribution across different dimensions. You can also view the various exceptions in the system. The data is integrated with trace data, making it easier to view the context of errors and exceptions, analyze, and resolve interface errors and exceptions in the system.

### SQL analytics

SQL analytics displays all SQL queries generated by the service. You can view SQL request trends, the SQLPattern list after removing parameters, as well as the events, failure rate, and average response time for each pattern.

Click SQLPattern to view all desensitized original SQL queries matching the pattern.
