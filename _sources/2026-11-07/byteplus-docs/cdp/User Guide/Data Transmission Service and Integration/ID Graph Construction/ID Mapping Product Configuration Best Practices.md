# 1. Common Scenarios

**The most basic IDMapping configuration in three sentences:** 


1. Highest priority for Business IDs (Business UID/Vehicle Vin/Merchant ShopID)

2. Non\-highest priority IDs cannot exist in isolation (configure reference relationships, reference higher priority IDs)

3. Keep default settings silent (do not change default configurations easily)



|Configuration Explanation |Scenario Map |
|---|---|
|Customer data channels consist of three parts:<br><br><br>* Business ID: User ID<br><br>* Device Information: Device ID<br><br>* WeChat Mini Program: APPID+OpenID<br><br>* Enterprise WeChat: UnionID<br><br><br>Priority Configuration: User ID \> Device ID \> APPID+OpenID \> UnionID<br><br>Reference Relationship Configuration: All non\-high\-priority IDs refer to high\-priority IDs<br><br><br>* Device ID refers to User ID: In a multi\-device scenario, the device associated with a user can be determined based on the latest login time<br><br>* WeChat Mini Program refers to Device ID: WeChat Mini Programs can obtain device information during program development to establish a reference relationship with the device ID<br><br>* Enterprise WeChat refers to Device ID: Enterprise WeChat needs external contact authorization to obtain user device information. After acquiring user device information, a reference relationship can be established (Note: User association in Enterprise WeChat requires user authorization to obtain real user device information) |<span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/7b60b48a47454ba7ad692b718644246b~tplv-goo7wpa0wc-image.image) </span><br><br>When integrating Enterprise WeChat's UnionID (Enterprise WeChat's user ID) with the user of the private domain, the fusion and integration method is optional:<br><br><br>1. # 2. Reuse Customer OneID Configuration


|Scene |Configuration Instructions |Attention |
|---|---|---|
|OneID generated by VeCDP corresponds one\-to\-one with the customer's existing OneID |1. The customer's existing OneID has the highest priority<br><br>2. All non\-customer OneID types refer to the customer's existing OneID |Attention: This scene is compared to the one above:<br><br><br>1. The OneID in the CDP system is independently generated and numerically does not equal the customer's OneID<br><br>2. If the phone number 1 does not reference the highest priority OneID, it will independently generate a OneID |
|The OneID generated by VeCDP = the customer's existing OneID<br><br>(Absolute reuse logic) |1. The customer's existing OneID must be of **<ins>numerical type</ins>**; other types are not supported<br><br>2. Turn on the backend switch for "Reuse Existing OneID"<br><br>3. The customer's existing OneID has the highest priority<br><br>4. All non\-customer OneID ID types reference the customer's existing OneID |Attention:<br><br><br>1. It is required that the customer's OneID must be the most complete. If it contains real\-time input through visual modeling<br><br>2.
