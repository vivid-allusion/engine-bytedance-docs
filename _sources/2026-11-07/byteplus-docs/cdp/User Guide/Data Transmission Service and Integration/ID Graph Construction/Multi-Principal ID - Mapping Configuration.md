# 1. Function Overview

VeCDP supports **multiple subject ID graph construction**, which means supporting the construction of multiple subjects other than "people," such as cars, merchants, etc., by configuring the mapping relationships between multiple subjects to achieve the management and analysis of multi\-subject scenarios.

<span id="09e570fc"></span>
# 2. Usage Restrictions

Only group administrators (i.e., admin accounts) can configure the ID graph.

<span id="501768bc"></span>
# 3. Application Scenarios


* **Automotive Scenario:** 

   * **Marketing Promotion Scenario:**  For example, if a car company wants to promote a specific type or color of car, they can pull target users in the relationship between multiple subjects [people <\-\> cars = follow relationship] to send marketing promotions, achieving a scenario where marketing information is immediately pushed when users click to follow or algorithmically predict interest.

   * **Vehicle Owner Service Scenario:**  For example, focusing on "vehicles" as subjects, using data generated by vehicle use to locate target vehicles needing service, finding the "vehicle owners" associated with this group of target vehicles, and conducting message reach for bettering the vehicle owner service experience.

* **High Consumption Scenario:**  In high consumption scenarios, multi\-subject capabilities can achieve more precise matching of people and goods, people and stores, goods and stores, etc.

# 4. Noun Definition


|Noun |Explanation and explanation |
|---|---|
|One ID |Also known as BaseID or baseline ID, it is the unique identity ID of the subject. |
|Subject |Also known as entity/object, often refers to people/vehicles/places that can be operated, grown, or analyzed for insights. |
|ID |Represents a sequence of numbers for a subject, such as a phone number. |
|ID type |Defines the data information of the subject's identity, often referring to specific identifiers that follow the subject, such as user ID, device ID, which can be understood as identity ID. |
|ID identification Code |ID's unique identifier, defined in English with underscores. |
|ID data type |Base data type, default can be selected as string type. |
|Channel identification mark |Used to mark official types that can be recognized downstream, such as phone number/IDFA. |
|Dataset |In the ID Graph Construction module, it specifically refers to the dataset of offline full ID, currently only Hive data set is available. |
|Full update |Read the latest partition data update data P_date (date partition) = the latest day every day. |
|Incremental update |Read historical data updates from all partitions every day where P_date (date partition) <= the latest date. |
|Multi\-subject conversion relationships |By configuring the relationship data and conversion strategies between multiple subjects, build conversion relationships commonly used in recommendation, matchmaking, and data exchange scenarios, such as finding potential customer information corresponding to a car through the car's label data. |

## 5.2 Configure Subject Mapping Relationships

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">Explanation</div>


<div data-tips="true" data-tips-type="tip">Purpose: By configuring the relationship data and conversion strategies between multiple subjects, build conversion relationships commonly used in recommendation, matchmaking, and asset reuse scenarios, such as finding potential customers corresponding to a car through the car's label data.</div>


<div data-tips="true" data-tips-type="tip">Result: Generate conversion relationship data dimensional tables from subject A to subject B</div>


The operating steps are as follows:


1. Click **Data Management\-ID Graph Construction** to enter **Subject Transformation Relationship Configuration** page, and click the **Configuration** button at the top right corner.

2. Click **to create a new subject transformation relationship**, and fill in the corresponding information:

* Relationship Name: Used to represent the naming of the transformation relationship, such as the relationship of person to vehicle purchase.

* Relationship Name: Used for naming transformation relationships, such as person\-to\-vehicle purchase relationship.

* Relationship dataset: The data source for building transformation relationships is currently only supported for datasets of the Hive type.

* Date partition field: Date partition field in the relational dataset.

* Date partition format: The content format corresponding to the partition field.

* Update method: The logic of obtaining dataset data, as below.

   * Full: Read the latest partition data for data update every day P_date (date partition) = the latest day.

   * Incremental: Read all historical partitions for data update every day P_date (date partition) <= the latest day.

* Subject of transformation: Establishing the transformation relationship between two subjects based on the dataset, sequentially selecting the subject, subject ID, and ID corresponding dataset field.

* Transformation method: When transforming between subjects, whether it is necessary to obtain all transformed subject data based on data, supporting one\-to\-many, one\-to\-one, and disallow transformation. If "disallow transformation" is selected, then the transformation relationship is not available in the corresponding transformation direction. For example, setting "disallow transformation" for person\-\>car prohibits transforming from a person's ID to a car.

* Transformation strategy: When subjects mutually reference each other, if "one\-to\-one (obtain a unique transformation subject based on the strategy)" is set but there is actually a one\-to\-many relationship, the most suitable transformation subject needs to be chosen based on the strategy. If not configured, one will be randomly selected.
