# New dataset

You need to create a temporary **intermediate table** (view) and **into the group table in the dataset page,**  A/B experiment platform in the calculation of data warehouse indicators, by entering the table and the business data table stored in the customer's data warehouse at the same time, associated query in the indicator calculation.

<span id="0cb0635d"></span>
## Create group table

The group entry table is used to record the user's group entry.


1. Enter basic information.

   <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/cc52e88c2b874b16b7be0274290039d2~tplv-goo7wpa0wc-image.image) </span>

2. Generate the incoming table using SQL.

   Select a defined data connection as the target database for the query, and enter the SQL command generated by the query into the group table in the code editing box for executing SQL.

   The format requirements of the incoming table are: the fields that the incoming table must contain are: **event_date** (support YYYYMMDD/YYYY\-MM\-DD format), **user_id**, **ab_version**.

   For example, there is an incoming table in the data warehouse, named "ab", with the following table fields:

   
   |cust_no (customer number) |Dt (entry date) |ab_version (incoming version) |Time (incoming timestamp) |
   |---|---|---|---|
   |user_1 |20200223 |12455 |161111111111 |
   

   The feed table SQL in the corresponding DataTester is defined as:

   ```SQL
   select
     cust_no as user_id,
     dt as event_date,
     ab_version
   from
     ab
   ```
   

3. Click Run to verify the correctness of the SQL and save it into the group table.

## Create virtual intermediate table

The middle table is the business table where metrics need to be calculated.


1. Enter basic information.

   <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/ebb28919ab3447a695dcf7ef15c87ff8~tplv-goo7wpa0wc-image.image) </span>

   * Association table: Select a group table that needs to be associated, and subsequent indicator analysis will be done with the selected group table.

   * Data ready time: As the SLA constraint of the sum data warehouse, the data of the previous day can be ready after the date set daily, and the task will try to query whether the data of the previous day is available after this time point. If there is data that the data of the previous day is ready, the indicator can start to run the task of offline calculation.

2. SQL generates virtual intermediate tables.

   The fields that the intermediate table must contain are: **event_date** (support YYYYMMDD/YYYY\-MM\-DD format), **user_id**, and the remaining fields can be selected as indicators or dimensions. event_date will report the start and end dates of the calculation analysis as follow\-up indicators; user_id will serve as the join_key associated with the input table.

   For example, there is an order table in the warehouse:

   
   |order_no (order number) |Amount (order amount) |cust_no (customer number) |Dt (order date) |product_type (Product Type) |
   |---|---|---|---|---|
   |order_222 |100 |user_1 |20200223 |Electronic products |
   

   I want to use the amount field as the order amount calculation indicator, and I want to use the product_type field as the product type for dimensional filtering.

   Definition of the corresponding intermediate table:

   ```SQL
   select
     cust_no as user_id,
     amount,
     product_type,
     dt as event_date
   from
     order
   ```
   

   Because event_date, user_id required, so you need to rename the cust_no to user_id, dt renamed to event_date, the remaining fields are the amount, product_type that you want to use as an indicator calculation or dimensional analysis.

3. Configuration field.

   <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/8123e12ead6e425fb4fb3662cdfddd98~tplv-goo7wpa0wc-image.image) </span>

   * In addition to the required fields user_id and event_date, other fields need to specify the field type

   * If you need to analyze as an indicator, please select int/float for type, and indicator for dimension/indicator column

   * If you need to filter as a dimension, the type is optional, and the dimension/metric column is selected

      Click **Save** to complete the intermediate table creation.
