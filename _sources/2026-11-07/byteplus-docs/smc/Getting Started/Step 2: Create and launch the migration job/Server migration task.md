After the migration source information is imported, the SMC console will automatically generate a migration source record. You can create and start a server migration task for the migration source in the console, migrate the source server data to a new instance of the platform or save it as a whole image (that is, a custom image containing system volume and data volume data).

This topic describes the steps for creating migration tasks, viewing migration task details, and other related operations.

<span id=".5YmN5o-Q5p2h5Lu2"></span>
## Prerequisites


* The migration source has been imported. For details, see [Importing migration source](https://docs.byteplus.com/en/docs/smc/Step-1-Import-Migration-Sources).

* Make sure that the source server complies with the [server migration](https://docs.byteplus.com/en/docs/smc/Preparations#.5pyN5Yqh5Zmo6L-B56e7) requirements.

* Make sure that the [snapshot](https://docs.byteplus.com/en/docs/ecs/Overview-of-snapshots) feature is enabled.


<span id=".5rOo5oSP5LqL6aG5"></span>
## Usage notes


|Operation |Description |
|---|---|
|Batch creation of migration tasks |* Migration source:<br><br>   * The number of migration sources selected at one time must not exceed 20.<br><br>   * Only migration sources with the status **Online** and not associated with active migration tasks can be selected.<br><br>* Migration task:<br><br>   * The specified "Task name" will be used as a prefix. SMC will automatically generate sequentially numbered task names based on the number of tasks created in a batch (for example: test\-1, test\-2), making it easier for you to quickly locate tasks.<br><br>   * Only "Create new instance" or "Migrate to image" can be selected as the destination type. |
|Data backup |SMC will automatically create a custom image (naming format: `IMAGE_FROM_SMC_$MigrationTaskID$`) and a snapshot (naming rule: `create from $TargetResourceID$`) for the target instance to back up data, making it convenient for you to recover data in case of migration failure. Rules are as follows:<br><br><br>* When the destination type is "Existing server" or "Create new instance", and the instance is of the "Subscription" billing method, a system volume image and snapshot will be created. After the migration is successful, the image and snapshot will be automatically deleted by the resource cleanup feature.<br><br>* When the destination type is "Migrate to image", a whole image and snapshot consistency group will be created. After the migration is successful, the image and snapshot will not be automatically deleted by the resource cleanup feature. You can manually [clear task resources](https://docs.byteplus.com/en/docs/smc/Clean-up-task-resources). |
|Initialization of the relay/target instance |Before the migration starts, SMC will initialize the relay instance (when the source server is migrated to an image) or the target instance (when the source server is migrated to an existing/new instance).<br><br><br>* The operating system of the relay or target instance is changed first. After the full migration is complete, the operating system of the relay or target instance is reverted to the operating system of the source server.<br><br>   * When the source server operating system is Windows, change the operating system of the relay or target instance to Windows Server 2019.<br><br>   * When the source server operating system is Linux, if the source server contains the xfs file system, the operating system of the relay or target instance is changed to veLinux 1.0. Otherwise, the operating system of the relay or target instance is changed to CentOS 7.9.<br><br>* When the target instance is set to "Existing instance", a temporary security group will be mounted to the target instance. This security group will open the following ports for data transfer and will be automatically unmounted after the migration is complete.<br><br>   * Migrate to Linux instances: ports 22 and 5201.<br><br>   * Migrate to Windows instances: ports 5986, 8080, and 5201. |
|Migration tool |Do not close the migration Agent before the migration process completes. Otherwise, the migration source will disconnect from the SMC console, and the migration task will fail to finish. |

## Procedure

After you import the migration source information via the migration Agent, the ECS console will display the corresponding migration source information. You can create a migration task to migrate it to the platform.


<Tabs>
<Tab zoneid="QDBh3W5YKW" title="Full migration">
<TabTitle>Full migration</TabTitle>

A full migration task refers to a one\-time task that fully migrates all data of the source server specified by you to BytePlus. This type of migration task will only perform a single migration operation, and the incremental data on the source server will not be migrated to BytePlus.

<span id="Cxzh93WA"></span>
### Step 1: Assess the usage of temporary resources

There is a limit on the number of cloud resources that can be created per account in a single region. Before starting the migration, you can evaluate the remaining quota of cloud resources available for creation in your BytePlus account. Make sure that the sum of existing resources in the account and the corresponding temporary resources to be created by SMC does not exceed the quota limit. This prevents migration failures caused by SMC inability to create temporary resources. For details, see [Evaluating the quantity of cloud resources used by migration tasks](https://docs.byteplus.com/en/docs/smc/Evaluate-the-number-of-cloud-resources-used-by-Migration-Jobs).

<span id="GRvyF1MC"></span>
### Step 2: Stop the workload that generates incremental data on the source server (optional)

If your business requires data consistency, we recommend that you stop the workload that continuously generates data on the source server before performing full migration. This helps ensure data consistency between the source and target servers. For operation details, refer to [Stopping source server processes generating incremental data](https://docs.byteplus.com/en/docs/smc/Stop-generating-incremental-data-in-the-source-server).

<span id="BoO4XUnV"></span>
### Step 3: Create a full migration task


1. Log in to the [ECS console](https://console.byteplus.com/ecs/instance).

2. In the left directory tree under any region, select "Server Migration Center \> Migration Source".

3.  **(Optional)**  If you have already enabled the snapshot service, skip this step. Otherwise, hover the mouse over the "Create migration task" button. In the pop\-up window, check the box next to "Click to activate, indicating that you are aware and agree Service\-Specific Terms for BytePlus Elastic Compute Service", and then click the "Confirm" button.

4. After the snapshot service is enabled, click the "Create migration task" button in the "Actions" column of the target migration source.

### Step 4: Stop the workload that generates incremental data on the source server (optional)

If your business requires data consistency, we recommend that you stop the workload that continuously generates data on the source server before performing the final incremental migration. For operation details, refer to [Stopping source server processes generating incremental data](https://docs.byteplus.com/en/docs/smc/Stop-generating-incremental-data-in-the-source-server).
