## General FAQ

<span id=".5LuA5LmI5piv5aKe6YeP5ZCM5q2l77yf"></span>
### What is incremental synchronization?

Incremental synchronization refers to the process of periodically migrating only the data that is new, modified, or deleted on the source server to the destination, after the full data synchronization of a source server is complete.


* After you enable the "Auto incremental synchronization" feature for a migration task, the new data generated since the last synchronization is synchronized by SMC automatically to the cloud according to the configured synchronization schedule. For operation details, see [Server migration tasks](https://docs.byteplus.com/en/docs/smc/Server-Migration-Task).

* During service cutover, you need to manually start the last incremental synchronization to synchronize the last incremental data from the source server to the cloud. For operation details, see [Performing the last incremental synchronization](https://docs.byteplus.com/en/docs/smc/Managing-Migration-Jobs#BAr0uiwS).


<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">Before performing the last incremental synchronization, please stop the business processes that continuously produce incremental data on the source server. This prevents newly generated data from failing to be synchronized to the target instance during the migration process, and ensures data integrity and consistency. For operation details, refer to <a href="https://docs.byteplus.com/en/docs/smc/Stop-generating-incremental-data-in-the-source-server">Stopping source server processes generating incremental data</a>.</div>


<span id=".U01D5piv5ZCm5pSv5oyB6L-B56e75rqQ5pyN5Yqh5Zmo5Lit55qE5pWw5o2u5bqT44CB5aSn5pWw5o2u5Y-K572R56uZ562J5pyN5Yqh77yf"></span>
### Does SMC support migrating services like databases, big data platforms, and websites from the source server?

Yes. SMC performs whole\-server migration. Therefore, any service installed on the source server's disks, such as databases, big data platforms, and websites, is supported for migration.

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">When migrating services such as databases, big data, and websites, you must stop the relevant services before the last migration to ensure data consistency. This prevents issues such as prolonged startup times, data inconsistencies, or service failures on the target instance. It is recommended to stop the relevant services at the following stages:</div>



* <div data-tips="true" data-tips-type="tip">For incremental migration, stop the services on the source server before the last incremental synchronization (the source server cannot be shut down).</div>


* <div data-tips="true" data-tips-type="tip">If you choose not to perform incremental migration, stop the services on the source server before the initial migration (the source server cannot be shut down).</div>

### How to obtain AK/SK?

**Access key (Access Key)**  is a security credential for requesting BytePlus APIs. It consists of `an Access Key ID` (AK) and `a Secret Access Key` (SK). For operation details, see [About access keys](https://docs.byteplus.com/en/docs/byteplus-platform/docs-managing-keys).

### What should I do if rsync is not installed or the installed version is too low on the source server?


* Option 1: Migrate data via the "File replication" method:

   Make sure that the rsync tool 3.1.0 or later is installed. If it is not installed or the version is too low, go to the[ rsync official website](https://rsync.samba.org/) to download and install it.

* Option 2: Migrate via the "Block replication" method:

   When creating a migration task, you can select the "Block replication" method for migration.

### Why did my imported migration source go offline unexpectedly?

Migration relies on network connectivity, the migration tool Agent, and other components. You can troubleshoot based on the following possible causes:


* **Possible cause 1**: The migration tool Agent has stopped.

   Solution: Log in to the source server and restart the migration tool Agent.

* **Possible cause 2**: Network fluctuations or disconnections may prevent SMC from receiving migration source information reported by the migration tool Agent, causing it to appear offline.

   Solution: Check the migration source network configuration, restart the migration tool Agent, and import the migration source again.

* **Possible cause 3**: If an **Online** migration source is not used to create a migration task within 2 hours, the Agent automatically stops reporting, and the source appears offline.

   Solution: Re\-import the migration source and perform migration within 2 hours.


<span id=".5Li65LuA5LmI5Zyo5rqQ5pyN5Yqh5Zmo5Lit5ZCv5Yqo5LqG6L-B56e7QWdlbnTvvIzkvYbmmK_lnKjngavlsbHlvJXmk47mjqfliLblj7DnnIvkuI3liLDov4Hnp7vmupDkv6Hmga_vvJ8="></span>
### Why is the migration source not displayed in the BytePlus console even with the migration Agent on the source server enabled?

This may be due to the source server configuration not meeting migration requirements. To diagnose, check the smc.log file in the directory where the Agent is installed on the source server. Look for the latest `ERROR` message to identify the specific cause. Common errors include:


* `checkOSSupport err`

   The operating system on the source server is not supported for migration. For a list of supported OS, see [Configuring migration sources](https://docs.byteplus.com/en/docs/smc/Preparations#.6YWN572u6L-B56e75rqQ).

* `checkUserConfig err`

   The user_config.json file of the Agent is incorrectly configured.

* `checkCharacterSet err`

   The required character set is missing on the source server. Execute the following command on the source server to install the `UTF-8` character set.

   ```Plain Text
   localedef -i en_US -f UTF-8 en_US.UTF-8
   ```
   

* `checkVirtioInstall err`

   The Virtio driver is missing on the source server. Install the Virtio driver on the source server by following the guide: [Installing Virtio1.1 driver](https://docs.byteplus.com/en/docs/ecs/Creating-Linux-images#.5a6J6KOFVmlydGlvMS4x6amx5Yqo).

* `checkRsyncInstall err`

   Rsync is not installed, or the version is lower than 3.1 on the source server. Download and install it from the [official rsync website](https://rsync.samba.org/).

* `cannot execute binary file`

   The source server architecture is not x86_64. Ensure your server architecture meets the migration requirements. For details, see [Configuring migration sources](https://docs.byteplus.com/en/docs/smc/Preparations#.6YWN572u6L-B56e75rqQ).

## Migration task

<span id=".5Li65LuA5LmI6YCa6L-H6L-B56e75rqQ5Yib5bu66L-B56e75Lu75Yqh5pe277yM4oCc6L-B56e757G75Z6L4oCd5rKh5pyJ4oCc5pON5L2c57O757uf6L-B56e74oCd6YCJ6aG577yf"></span>
### Why is the "Operating System Migration" option missing under "Migration type" when I create a migration task using my migration source?

Please confirm that your migration source is a BytePlus ECS instance running the CentOS 7.x operating system. If your source does not meet this criterion, the "Operating System Migration" option will not appear on the migration task creation page.

<span id=".6L-B56e75Yiw56ys5LiJ5Luj5a6e5L6L5oiW6Ieq5a6a5LmJ6ZWc5YOP5pe277yM6Ieq5Yqo5a6J6KOFVmlydGlvMS4x6amx5Yqo5aSx6LSl5oCO5LmI5Yqe77yf"></span>
### What should I do if the automatic Virtio 1.1 driver installation fails during migration to a 3rd\-generation instance or a custom image?

You can install the Virtio1.1 driver by following these steps:


1. (Optional) Create a custom image based on the target instance. For details, see [Creating custom image based on instance](https://docs.byteplus.com/en/docs/ecs/Creating-custom-images-from-a-Linux-instance).

   > This step is required only when the migration target is a 3rd\-generation instance.   
   

2. Use the custom image created in step 1 or the custom image generated by migration to create a 2nd\-generation instance. For instructions, see [Purchasing instances via custom images](https://docs.byteplus.com/en/docs/ecs/Buying-ECS-instances-with-custom-images).

3. Install the Virtio1.1 driver in the newly created instance. For details, see [Installing Virtio1.1 driver](https://docs.byteplus.com/en/docs/ecs/Creating-Linux-images#.5a6J6KOFVmlydGlvMS4x6amx5Yqo).

4. Create a custom image based on the instance where the driver is installed. For details, see [Creating custom image based on instance](https://docs.byteplus.com/en/docs/ecs/Creating-custom-images-from-a-Linux-instance).

5. Use the custom image created in step 4 to create the required 3rd\-generation instance. For instructions, see [Purchasing instances via custom images](https://docs.byteplus.com/en/docs/ecs/Buying-ECS-instances-with-custom-images).


<span id=".6L-B56e75oiQ5Yqf5ZCO77yM5Zyo5a6e5L6L5Lit6YCa6L-HZ3Jvd3BhcnTlkb3ku6TmianlrrnliIbljLrlpLHotKXvvIzlpoLkvZXop6PlhrPvvJ8="></span>
### How do I resolve partition expansion failure when I execute the `growpart` command in the instance after a successful migration?


* **Issue example:** 

   <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_76a337b5103481c5910f5a9ad4252eb5.png) </span>

* **Solution:** 

   1. Execute the following command in the instance to reload the partition table information for all devices in the system:

      ```Plain Text
      partprobe
      ```
      

   2. Then, execute the `growpart` command again to expand the partition. For details, see [Expanding partitions and file systems](https://docs.byteplus.com/en/docs/ecs/Extend-volume-linux#step-3-extend-partitions-and-file-systems).


<span id=".5Li65LuA5LmIQ2VudE9TIDYueOi_geenu-WIsOWunuS-i-WSjOmVnOWDj-WQju-8jOayoeacieiiq-WuieijheaJuemHj-S9nOS4muWSjOS6keebkeaOp-aPkuS7tu-8nw=="></span>
### Why aren't cloud assistant and Cloud Monitor plugins installed after migrating a CentOS 6.x system to an instance or image?

Features of cloud assistant and Cloud Monitor plugins are not supported on CentOS 6.x. Therefore, BytePlus does not perform installation.

<span id="FIVrZEZi"></span>
### Why did the operating system activation fail for a migrated Windows server that did not have BYOL enabled?

Due to factors such as network stability, the activation operation may take a long time. It is recommended to wait patiently. If activation is not successful after an extended period, you can [submit a ticket](https://console.byteplus.com/workorder/create) to obtain technical support.
