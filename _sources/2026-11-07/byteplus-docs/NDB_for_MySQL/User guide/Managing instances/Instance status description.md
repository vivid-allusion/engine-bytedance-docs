This article mainly describes the state that an instance will appear in during use, and the operations supported by the instance when in that state.


|Instance state |Status code |Actions that trigger this state |Supported operations in this state |Description or impact |
|---|---|---|---|---|
|Running |Running |Instance created successfully. |All operations are supported, see [Feature overview](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Features_overview). |Database services can be provided normally. |
|Creating |Creating |* Creating an instance.<br><br>* Recovering to the new instance from a backup set or recovering to the source instance from a backup set.<br><br>* Recovering a backup of a deleted instance to a new instance. |No operation on the instance is supported. |When a new instance is created or full backup data is restored to a new instance, the instance is in the process of creation, and the instance state is **running** after creation. |
|Deleting |Deleting |* Delete the pay\-as\-you\-go instance.<br><br>* Unsubscribe from yearly/monthly subscription. ||Deleting is an intermediate state, when the instance is deleted or unsubscribed, the instance will first become a ** Deletin**g state and then enter a **Recycling** state. |
|Recycling |Reclaiming |* Delete the pay\-as\-you\-go instance.<br><br>* Unsubscribe from yearly/monthly subscription. ||After an instance is deleted or unsubscribed, it enters the ‌**Recycling‌**  state. During this period, the system will automatically create and retain a final backup file in the **backups of deleted instances** list. You can restore an instance from a preserved backup file, or completely destroy a backup of a deleted instance. For activity details, see [Backups of deleted instances](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Backups_of_deleted_instances). |
|Error |Error |The instance encountered an exception and was unable to connect or provide database services. ||Please [submit a ticket](https://console.byteplus.com/workorder/create) to contact technical support. |
|Waiting for payment |WaitingPaid |Create a yearly/monthly subscription instance. |No operation on the instance is supported. Only support click Actions column **To pay**, pay fees. |When creating a yearly/monthly subscription instance, no payment is made after submitting the order. At this time, the instance is in a waiting state for payment.<br><br><br>* If you need the instance, click **Go to pay** in the **Actions** column, and when the payment is complete, the instance will enter the **Creating** state.<br><br>* If the instance is no longer needed, no action is required, and the instance is automatically deleted after 24 hours. |
|||Batch instance creation. |No operation on the instance is supported. |Batch creation of instances, there may be **Waiting for payment** state, waiting for the system to complete processing, will automatically change to the **Creating** state. |
|Configuration modifying |Scaling |* Changing instance configuration.<br><br>* Change the storage billing type of the yearly/monthly subscription instance.<br><br>* Create/change analysis nodes. |The following operations are supported:<br><br><br>* [Instance deletion protection](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Instance_deletion_protection)<br><br>* [Viewing instance details](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Viewing_instance_details)<br><br>* [Viewing connection endpoints](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Viewing_connection_endpoints)<br><br>* [Viewing monitoring information](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Viewing_monitoring_information)<br><br>* [Viewing parameter modification history](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Viewing_parameter_modification_history)<br><br>* Viewing instance parameter configuration<br><br>* Viewing backup policy<br><br>* Viewing backup list<br><br>* Viewing the allowlist of instance associations<br><br>* Viewing instance parameter configuration |When changing the instance\-related configuration, the instance is in this state. During the configuration change, the database connection may be disconnected temporarily. Therefore, it is recommended to perform configuration changes during off\-peak hours and ensure that the application has an automatic reconnection mechanism. |
|Restarting |Restarting |* Restarting instances.<br><br>* Modify the parameters that need to be restarted. ||Instance restart will cause connection interruptions. Schedule businesses accordingly before restarting. We recommend you restart instances during off\-peak hours and ensure that applications have an automatic reconnection mechanism. For more information, see [Modifying parameters](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Modifying_parameters) and [Restarting instances](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Restarting_instances). |
|Upgrading version |Upgrading |Upgrade the instance kernel version. ||During the upgrade of the instance kernel version, the database may experience one or two connection failures. Please ensure that your application has an automatic reconnection mechanism. |
|Primary node switching |PrimaryChanging |* If the primary node fails, the system will automatically trigger the switch to the primary node.<br><br>* Manually switch the primary node. ||When switching the primary node generally takes 30s to 60s, and 1 to 2 brief disconnections may occur. Ensure your application implements automatic reconnection to minimize business impact. For more details, see [Switching to primary node](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Switch_to_primary_node). |
|Billing is recovering. |Resuming |* Renewal for yearly/monthly subscription instance.<br><br>* Recharge the account to which the volume\-based billing instance is owed. ||Billing Recovery is an intermediate state. After an instance enters the **overdue** or **arrears** state, if you recharge your pay\-as\-you\-go account or renew your subscription instance, the instance will first enter the **Billing recovery** state. After the system completes processing, the instance status will change to **Running**, indicating that the instance is ready to provide normal database services. |
|Due |Expired |The yearly/monthly subscription instance expires. ||After the yearly/monthly subscription instance expires, the instance enters the **Due** state. The instance is currently unavailable and cannot be served. For more details, see [Expiration](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Arrears_and_expiration).<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Please enable automatic or manual renewal for the instance before or after the instance expires. For methods of a renewal instance, see <a href="https://docs.byteplus.com/en/docs/NDB_for_MySQL/Renewal_management">Renewal management</a>.</div><br> |
|Overdue |Owing |The account to which the Pay\-as\-you\-go instance belongs is in arrears. ||After the billing instance belongs to the account arrears, the instance will enter the **Overdue** state. The instance is currently unavailable and cannot be served. For more details, see [Arrears](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Arrears_and_expiration).<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Please go to the <a href="https://console.byteplus.com/finance/account-overview/">Expense center</a> to recharge the account immediately after the account is in arrears.</div><br> |
|Recovering |Restoring |Recovering database and table by time point or Recovering database and table from a backup set |Support all the above **query operations**, and the following operations:<br><br><br>* [Managing databases](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Managing_databases)<br><br>* [Managing accounts](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Account_and_access_authorization)<br><br>* [Monitoring and alerts](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Monitoring_and_alerts)<br><br>* [Managing connections](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Managing_connections)<br><br>* [Backup data](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Backup_data)<br><br>* [Instance deletion protection](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Instance_deletion_protection)<br><br>* [Configuring maintenance window](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Configuring_maintenance_window) |After executing the database and table recovery operation, the instance will enter the **Recovering** state, and operations such as specification changes, restarts, and deletions of the instance are not allowed at this time. For more details, see [Data recovery](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Data_recovery). |
|Allowlist maintaining |AllowListMaintaining |* Associating allowlist and instance.<br><br>* Disassociating instance and allowlist. ||When you associate or disassociate instances and allowlist, the instance will enter an **Allowlist maintaining** state. For specific steps, see [Associating allowlist and instance](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Associating_allowlist_and_instance) and [Disassociating instance and allowlist](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Disassociating_instance_and_allowlist). |
|Access address modifying |AddressModifying |Modifying address prefix and port ||When modifying the prefix and port of the connection address, the instance will enter the state of **Access address modifying**. After the modification is completed, the old connection address will become invalid. Please modify the connection configuration of the application synchronously, otherwise it may affect the business, so proceed with caution. For more details, see [Modifying address prefix and port](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Modifying_address_prefix_and_port). |
|Failed to create |CreateFailed |Creating an instance. |[Deleting an instance](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Deleting_or_unsubscribing_an_instance). |The instance creation failed due to system reasons, and only the delete instance operation is supported at this time. |
