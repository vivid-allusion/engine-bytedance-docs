NDB for MySQL provides multiple data recovery methods for various data misoperation scenarios, depending on the scenario and the database engine version. This article lists common misoperation scenarios. You can select the corresponding data recovery method based on your actual situation.


|**Scenario** |**Database version** |**Restore method** |
|---|---|---|
|Accidentally deleted table |MySQL 5.7<br><br> |Databases and tables recovery is not yet supported. You need to restore the entire instance data to a temporary instance by [Recovering to the new instance from a backup set](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_to_the_new_instance_from_a_backup_set) or [Recovering to the new instance by time point](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_to_the_new_instance_by_time_point), and then read the table data from the temporary instance and write it to the original instance. |
||MySQL 8.0 |Restore an accidentally deleted table using databases and tables recovery, which provides two methods: restore to a point in time or restore from a backup set:<br><br><br>* If the desired restore time point matches a User backup set (snapshot), you can directly choose [Recovering database and table from a backup set](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_database_and_table_by_backup_set).<br><br>* If the desired restore time is a point in time other than that of a user backup set (snapshot), you can select [Recovering database and table by time point](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_database_and_table_by_time_point). |
|Accidental database deletion |MySQL 5.7 |Databases and tables recovery is not yet supported. You need to restore the entire instance data to a temporary instance by [Recovering to the new instance from a backup set](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_to_the_new_instance_from_a_backup_set) or [Recovering to the new instance by time point](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_to_the_new_instance_by_time_point), and then read the table data from the temporary instance and write it to the original instance. |
||MySQL 8.0 |Use the databases and tables recovery method to restore an accidentally deleted database. This includes two methods: restoring to a point in time or restoring from a backup set:<br><br><br>* If the desired restore time point matches a User backup set (snapshot), you can directly choose [Recovering database and table from a backup set](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_database_and_table_by_backup_set).<br><br>* If the desired restore time is a point in time other than that of a user backup set (snapshot), you can select [Recovering database and table by time point](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_database_and_table_by_time_point). |
|Accidental instance deletion |MySQL 5.7 |When an instance is deleted, a snapshot is automatically created with a retention period of 7 days. If you discover an accidental deletion within 7 days, you can restore the instance using [Recovering a backup of a deleted instance to a new instance](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_a_backup_of_a_deleted_instance_to_a_new_instance). |
||MySQL 8.0 ||
|Accidental operations on table data, such as overwriting an entire table or accidentally deleting/modifying columns, rows, or data |MySQL 5.7 |Databases and tables recovery is not yet supported. You need to restore the entire instance data to a temporary instance by [Recovering to the new instance from a backup set](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_to_the_new_instance_from_a_backup_set) or [Recovering to the new instance by time point](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_to_the_new_instance_by_time_point), and then read the table data from the temporary instance and write it to the original instance. |
||MySQL 8.0 |* If the affected databases or tables can be identified and the total number of tables does not exceed 100, use the databases and tables recovery method to restore them. This includes two methods: restoring to a point in time and restoring from a backup set:<br><br>   * If the desired restore time point matches a User backup set (snapshot), you can directly choose [Recovering database and table from a backup set](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_database_and_table_by_backup_set).<br><br>   * If the desired restore time is a point in time other than that of a user backup set (snapshot), you can select [Recovering database and table by time point](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_database_and_table_by_time_point).<br><br>* If you are unable to identify the affected scope or if more than 100 databases and tables are affected, use [Recovering to the new instance from a backup set](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_to_the_new_instance_from_a_backup_set) or [Recovering to the new instance by time point](https://docs.byteplus.com/en/docs/NDB_for_MySQL/Recovering_to_the_new_instance_by_time_point) to restore the entire instance data to a temporary instance. Then, read the table data from the temporary instance and write it to the original instance. |
