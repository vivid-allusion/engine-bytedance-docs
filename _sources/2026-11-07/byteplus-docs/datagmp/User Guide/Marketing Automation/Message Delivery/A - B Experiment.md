### **1. Product Overview**

Message Delivery experiments are divided into two types: traffic splitting experiments and race experiments.


| |Experiment Type Description |
|---|---|
|**Split traffic** |When operators cannot determine which content is better for outreach, they can use the GMP split traffic feature. When a Message Delivery Task activates a split traffic experiment, the system divides all users pending outreach into multiple groups according to the set proportion, and each group is targeted with content preset by the system.<br><br><span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/2d31a7b4f2324723b88aa622750f491e~tplv-goo7wpa0wc-image.image) </span> |
|**Horse racing** |Horse racing and split traffic capabilities are similar, but the difference is that split traffic reaches out based on proportions set by the operator, whereas horse racing targets a small part of the traffic initially, then reaches the remaining traffic based on the most optimal experimental group.<br><br>**Horse racing phase**: Set a certain percentage of experimental traffic, like 10%, and deploy multiple copies for horse racing within this traffic; thus, various horse racing copies will equally share this 10% of experimental traffic during the designated experimental period.<br><br>**Total remaining traffic**: After the experiment, the system or person identifies the winning group in horse racing, and then it's possible to target the remaining 90% of the traffic according to the winning group.<br><br><span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/7099d67eefb14e9c90ecdfcb069bd3f7~tplv-goo7wpa0wc-image.image) </span> |

|**Frequently Asked Questions** |**Will the distribution ratio assigned in the experiment strictly follow the proportion set by the task?** <br><br>No, there will be some gap discrepancies.<br><br>The logic of the experiment is: you can simply understand it as dividing the total traffic into 1000 buckets, and 50% means selecting 500 of those buckets. The user falls into the corresponding experimental group based on which bucket the hash value modulo result is in. Based on this implementation plan, it can be understood that the users assigned to each group are random, and there will be some differences compared to the volume of users configured by the task.<br><br>What is Hash: Hash is turning any length of input into a fixed length output using a Hash algorithm.<br><br>What is Modulo: Modulo operation is to find the remainder of the division of two numbers.<br><br>If each experimental group reaches a larger audience, then the number of people assigned to each group will tend to approach the number set by the task configuration. Conversely, if only a few dozen people are assigned to each group, there might be a significant difference in the number of people entering each group. |


**2.2 Racing**

Racing is divided into two scenarios, one is "manual decision," and the other is "automatic decision based on conversion rate," and the difference is whether all actions are completed by the operator or the system automatically decides based on the indicators.

**2.2.1 Racing with Manual Decision**


| |Introduction |
|---|---|
|**Experimental Configuration Introduction** |For the manual decision\-making horse racing experiment, you need to set: the experimental groups to be tested, and the traffic during the horse racing period.<br><br><span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/01caade148424d83acffb3db76363a37~tplv-goo7wpa0wc-image.image) </span> |
|**Experimental Operational Logic** |**Horse Racing Period**<br><br>After reaching the "reach time", the traffic settings configured for the "horse racing period" will be applied, and a corresponding proportion of users will be reached. Example:<br><br>Scheduled \- One\-Time: For the segment that is about to be reached, select 30% of the users to send to.<br><br>Scheduled \- Repeated: For each subtask of every horse racing period, select 30% of the users to send to.<br><br>Event\-Triggered: Completion of Event A, Event\-Triggered: Event A Completed & Event B Incomplete: For users who meet the event conditions, select 30% of the users to send to.<br><br><span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/c76c6aa32a1d4877a94ab99c52e3ff42~tplv-goo7wpa0wc-image.image) </span><br><br>After reaching out, you can observe on the "Data Analysis" page which group has the best data performance.<br><br><span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/6291dd7fb1c442a2a775adfb6f68ff0c~tplv-goo7wpa0wc-image.image) </span><br><br>**Optimal group selection for horse racing**<br><br>Select the group you want to fully deploy. After selection, different types of tasks will be handled as follows:<br><br>Scheduled \- One\-Time: Use this group to reach the remaining 70% of users immediately.<br><br>Scheduled \- Repeated: Use this group for every subtask that runs subsequently.<br><br>Event\-Triggered: Completion of Event A, Event\-Triggered: Event A Completed & Event B Incomplete: Use this group for subsequent users who meet the event criteria.<br><br><span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/9ef95bde32fd4490a53dbe21e86bde6a~tplv-goo7wpa0wc-image.image) </span> |
