Creating an instance is the first step to use RDS for MySQL. This topic describes how to create a MySQL instance.

## Background

RDS for MySQL provides two methods for creating instances: custom creation and fast creation.

When creating an instance, RDS for MySQL supports customizing the instance's basic information, specifications, network configuration, account configuration, and advanced configuration. To meet the needs of different business scenarios, RDS for MySQL provides two methods for creating instances: custom creation and fast creation. Different creation methods offer different levels of customization. With the fast creation method, you can only configure the node specification, compatible version, time zone, lower case table names, billing method, purchase duration, automatic renewal, and quantity. Other configurations are set automatically based on predefined rules to accelerate instance creation. The configuration rules for the fast creation method are as follows:

* Instance name: The instance ID is automatically used as the instance name.

* Instance type: The double node type is automatically used.

* Specification type: The general purpose type is automatically used.

* Storage type: Local SSD is automatically used.

* Storage space: Automatically set to 40 GiB.

* Automatic storage expansion: Disabled.

* Virtual private cloud and Subnet: The default virtual private cloud and subnet are used. If a default virtual private cloud or subnet does not exist, a new one is created.

* Maintenance window: Set to a random value.

* Tag: No tags are associated.

* Deletion protection: enabled automatically.

* High\-privilege account settings: Set up later is automatically selected.

* Affiliated project: the default project is automatically selected.

* Parameter templates: the default parameter template for the compatible version is automatically selected.

* Allowlists: the default allowlist for the current region is automatically selected. If no default allowlist is configured in the current region, no allowlist is associated with the instance.

## Prerequisites

* A BytePlus account has been registered and completed verification. For the detailed method, refer to [Sign Up and Verify BytePlus account](https://docs.byteplus.com/en/docs/byteplus-platform/docs-signing-up-your-account).

* As per the regulations in the Chinese mainland, you must have completed real name registration before you can activate and use cloud services on regions in the Chinese mainland through BytePlus. For more details, refer to [Real name registration](https://docs.byteplus.com/en/docs/byteplus-platform/docs-real-name-registration).

* VPC service access authorization has been completed. For the authorization method, refer to [Cross-service access authorization](https://docs.byteplus.com/en/docs/RDS_for_MySQL/cross-service_access_authorization).

## Procedure

1. Log on to the [RDS for MySQL console](https://console.byteplus.com/db/rds-mysql).

2. (optional)In the top menu bar, select the project and region for the instance.

   > **tip**

   * > If the project for the instance is not selected beforehand, you can choose it during instance creation.

   * > If you selected a project before creating an instance, you can also change the project during instance creation.

3. In the left navigation bar, choose **MySQL** \> **Instances**.

4. On the **Instances** page, click **Create instance**.

5. On the **Create instance** page, select a creation method and complete the corresponding configuration.

* [Creating alert policies](https://docs.byteplus.com/en/docs/RDS_for_MySQL/creating_alert_policies) for an instance

   To monitor the instance State and ensure stable operation, create alert policies for important metrics. This ensures you are notified promptly to intervene when metrics are too high or abnormal, preventing the instance from malfunctioning. For details on the monitoring items for RDS for MySQL, refer to [Monitoring metrics](https://docs.byteplus.com/en/docs/RDS_for_MySQL/monitoring_metrics).

   > **tip**

   > RDS for MySQL uses a primary\-secondary high\-availability architecture, where the secondary node synchronizes data from the primary node through Binlog. During synchronization, the secondary node's disk usage is higher than the primary node's. In extreme cases, the primary node's disk usage may approach 100%, while the secondary node's disk usage has already reached 100%. At this point, the connection between the primary and secondary nodes is interrupted, which significantly impacts the instance's high availability. Therefore, you should closely monitor the storage space usage of both the primary and secondary nodes and create alert policies for their disk usage rates.

* Viewing or switching an instance's connection pool mode

   A database connection pool is responsible for allocating, managing, and releasing database connections. RDS for MySQL provides direct connection pools and transaction\-level connection pools. For more information about connection pool modes, refer to [About connection pool mode](https://docs.byteplus.com/en/docs/RDS_for_MySQL/about_connection_pool_mode).

   Transaction\-level connection pools are suitable for services with primarily short\-lived connections, while direct connection pools are for services with primarily long\-lived connections. Selecting the corresponding connection pool mode according to the specific business scenario can improve the performance of the database and improve the utilization of database resources. When the database proxy is enabled, the instance uses the transaction\-level connection pool by default. When the database proxy is disabled, the instance uses the direct connection pool by default. To switch the connection pool mode, refer to [Switching connection pool mode](https://docs.byteplus.com/en/docs/RDS_for_MySQL/switching_connection_pool_mode).
