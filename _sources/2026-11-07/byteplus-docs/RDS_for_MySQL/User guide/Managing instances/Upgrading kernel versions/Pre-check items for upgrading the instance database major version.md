This topic describes the pre\-check items for upgrading the instance database major version.


|**Check items** |Description |Scope |**Problem, impact, and solution** |
|---|---|---|---|
|defaultCollationForUTF8MB4Check |Check default collation rule: after the upgrade, the parameter default_collation_for_utf8mb4 is modified to utf8mb4_general_ci by default. Evaluate its execution security in MySQL 8.0. |Warning |* Problem: After the upgrade, the default_collation_for_utf8mb4 parameter is set to utf8mb4_general_ci<br><br>* Impact: The sort order of results returned after SQL execution may differ from the order before the upgrade. |
|fullTextIndexCheck |Check if the FTS_0 prefix exists in the global index. |Error |Problem: there are indexes prefixed with FTS_0 in the current instance.<br><br>Impact: The internal dependency prefix causes the upgrade task to become abnormal.<br><br>Solution: For query operations involving fts_0 or FTS_0, delete or modify the global index.<br><br>`SELECT * FROM information_schema.tables WHERE table_name LIKE 'fts_0%';` |
|expiredEventCheck |Check the event and trigger states of the current instance. |Error |* Problem: the current instance contains uncleared expired events (EVENTS).<br><br>* Impact: if event_scheduler is enabled on the target instance, expired events are automatically cleared, leading to inconsistency between the primary and secondary instances.<br><br>* Solution: check related events `select * from information_schema.events where EXECUTE_AT <= NOW() AND ON_COMPLETION='NOT PRESERVE' AND EVENT_TYPE ='ONE TIME';`<br><br>   Remove invalid events. For example, DROP EVENT IF EXISTS NAME; |
|initConnectCheck |Check the init_connect parameter: detects whether connection initialization SQL statements are configured and evaluates their execution security in MySQL 8.0. |Error/Warning |* Warning<br><br>   * Problem: After the upgrade, the default collation changes to utf8mb4_0900_ai_ci, and the parameter 'set @@collation_connection = IF(@@collation_connection = 'utf8mb4_0900_ai_ci', 'utf8mb4_general_ci', @@collation_connection)' is automatically added.<br><br>   * Impact: The sort order of SQL execution results may be different from that before the upgrade.<br><br>* Error<br><br>   * Problem: After the upgrade, the default collation changes to utf8mb4_0900_ai_ci, and the parameter 'set @@collation_connection = IF(@@collation_connection = 'utf8mb4_0900_ai_ci', 'utf8mb4_general_ci', @@collation_connection)' is automatically added.<br><br>   * Impact: The sort order of SQL execution results may be different from that before the upgrade.<br><br>   * Solution: Delete the 'set names utf8mb4' configuration in parameters. |
|instanceDBEngineCheck |Check for business tables with non\-InnoDB engines: identifies business tables that use non\-InnoDB engines, such as MyISAM and MEMORY, which require an engine conversion or compatibility assessment. |Error |* Problem: The instance database contains service tables with non\-InnoDB engines, which restricts the upgrade.<br><br>* Impact: The following tables do not meet the %s condition.<br><br>* Solution:<br><br>   * Query the current tables and databases first.<br><br>   ```sql```<br>```   SELECT table_name, table_schema FROM information_schema.TABLES WHERE NOT (ENGINE = 'innodb')  AND table_schema NOT IN ('mysql', 'information_schema', 'performance_schema', 'byte_rds_meta');```<br>```   ```<br>   <br><br>   * Modify the storage engine first.<br><br>      ```sql```<br>```      ALTER TABLE your_database.your_table ENGINE = InnoDB;```<br>```      ```<br>       |
|instanceHealthCheck |Check instance health: obtain the instance's running status to confirm if it meets upgrade requirements. |Error |* Problem: The basic information check failed.<br><br>* Impact: The upgrade is not supported.<br><br>* Solution:<br><br>   * The instance load is too high and requires expansion.<br><br>   * The instance node connectivity may be abnormal. Retry later.<br><br>   * Check if global read\-only is enabled for the instance. If enabled, disable it and retry. |
|instanceSlaveStateCheck |Check standby node status: Checks if the standby node in primary\-secondary replication is synchronized properly to prevent data inconsistency caused by the upgrade. |Error |* The standby node state is abnormal.<br><br>* The standby node delay is not within the threshold. |
|instanceStatusCheck |Check instance status: verify the running status of the MySQL instance (for example, whether the service starts normally and the connection is stable). |Error |* Problem: The instance status is not eligible for the upgrade. |
|InstanceSyncDelayCheck |Check the instance latency. |Warning |Problem: The master\-slave synchronized latency does not meet the requirements.<br><br>Impact: The upgrade cycle is extended. |
|instanceTDEOrSSLCheck |Check instance TDE and SSL usage. |Error |Problem: The instance has TDE/SSL enabled. Upgrades are not supported. |
|mysqlShellCheck |Check the MySQL Shell tool: Verify the installation and compatibility of the MySQL 8.0 command\-line tool (MySQL Shell) to ensure that the upgrade operation can be performed. |Error |* Problem: The MySQL shell tool execution is abnormal.<br><br>* Impact: The upgrade cannot continue due to a dependency tool abnormality, [submit a ticket](https://console.byteplus.com/workorder/create) to contact technical support for assistance. |
|removedSysVars |Check for system parameter changes: Verify if parameters are deprecated (e.g., query_cache_size). |Warning |* Problem: parameters deprecated in MySQL 8.0 are used.<br><br>* Impact: the relevant parameters will be ignored after the upgrade. |
|sequenceEngineCheck |Check the use of self\-developed functions: Identifies if the self\-developed SEQUENCE capability of MySQL 5.7 is used (this capability is incompatible after the upgrade). |Error |* Problem: Current instance uses the self\-developed SEQUENCE feature of MySQL 5.7.<br><br>* Impact: After the upgrade, the SEQUENCE feature will be incompatible, which may cause service abnormalities. |
|statementOutlineChecker |Upgrade Statement Outline to the MySQL 8.0\-compatible SQL fingerprint format. |Warning |* Problem: SQL query fingerprints are different in MySQL 5.7 and MySQL 8.0. An upgrade to a MySQL 8.0\-compatible version is required.<br><br>* Impact: Before the Outline upgrade, user query plans on MySQL 8.0 may be inconsistent with those on MySQL 5.7, and the Outline feature will be affected during the upgrade. |
|sysVarsNewDefaults |Check system parameters with new default values: detect whether variables whose default values have changed in MySQL 8.0 are explicitly overridden (for example, the default value of innodb_flush_neighbors is changed from 1 to 0). |Notice |* Problem: the following system parameters not defined in your configuration file will have new default values. If you rely on their current values, review and define them before executing the upgrade.<br><br>* Impact: Related parameters will be changed after the upgrade. |
|databaseNumberCheck |Limit the number of databases on local disk instances: the total number of databases in a single instance exceeds the threshold, which may cause metadata management performance problems. |Error |Problem: the number of databases on the local disk instance exceeds the limit, restricting the upgrade.<br><br><br>* For instances with 4 CPU cores or fewer, the database limit is 1,000.<br><br>* For instances with more than 4 and up to 8 CPU cores, the database limit is 10,000.<br><br>* For other CPU core specifications, the database limit is 100,000. |
|tableDiscardCheck |Check for discarded tables: Detect tables discarded through ALTER TABLE ... Tables discarded by the DISCARD TABLESPACE operation must be repaired or have their data files re\-imported. |Error |* Problem: The upgrade is restricted because the instance contains discarded tables (i.e., tables where the ALTER TABLE discard TABLESPACE operation was performed).<br><br>* Impact: The following tables do not meet the %s condition<br><br>* Solution:<br><br>   * Query operation<br><br>      ```sql```<br>```      SELECT * FROM INFORMATION_SCHEMA.INNODB_SYS_TABLESPACES WHERE FS_BLOCK_SIZE=0 AND FILE_SIZE=0 AND name NOT LIKE '%#sql%';```<br>```      ```<br>      <br><br>   * The current table does not support upgrading. |
|tableNumberCheck |Limit on the number of tables for local disk instances: To prevent metadata management performance problems, the total number of tables for a single instance exceeds the threshold. |Error |Problem: The quantity of databases and tables for the local disk instance exceeds the limit, restricting the upgrade.<br><br><br>* For 4 CPU cores or fewer, the quantity of databases and tables is limited to 1,000.<br><br>* When there are more than 4 and up to 8 CPU cores, the quantity of databases and tables is limited to 10,000.<br><br>* For other CPU core specifications, the quantity of databases and tables is limited to 100,000. |
|tableSpatialIndexType |Check for BTREE indexes on Spatial fields: detects the incorrect use of BTREE indexes on geospatial type fields (such as GEOMETRY), which need to be changed to SPATIAL indexes. |Error |* Impact: the following tables used %s BTREE indexes.<br><br>* Solution:<br><br>   * Execute an SQL query on the current table and database.<br><br>      ```sql```<br>```      SELECT```<br>```          s.TABLE_SCHEMA,```<br>```          s.TABLE_NAME,```<br>```          s.INDEX_NAME,```<br>```          s.COLUMN_NAME```<br>```      FROM```<br>```          INFORMATION_SCHEMA.STATISTICS s```<br>```      JOIN```<br>```          INFORMATION_SCHEMA.COLUMNS c```<br>```      ON```<br>```          s.TABLE_SCHEMA = c.TABLE_SCHEMA```<br>```          AND s.TABLE_NAME = c.TABLE_NAME```<br>```          AND s.COLUMN_NAME = c.COLUMN_NAME```<br>```      WHERE```<br>```          c.DATA_TYPE IN ('GEOMETRY', 'POINT', 'LINESTRING', 'POLYGON', 'MULTIPOINT', 'MULTILINESTRING', 'MULTIPOLYGON', 'GEOMETRYCOLLECTION')```<br>```          AND s.INDEX_TYPE = 'BTREE';```<br>```      ```<br>      <br><br>   * Modify the type of an index.<br><br>      1. Delete the corresponding index.<br><br>         ```sql```<br>```         DROP INDEX index_name ON table_name;-- Create a unique index ALTER TABLE table_name```<br>```         ```<br>         <br><br>      2. Add a new index.<br><br>         ```sql```<br>```         ADD UNIQUE INDEX index_name (column1, column2, ...);```<br>```         ```<br>          |
|oldTemporal |Check for deprecated time types: detects the use of time types deprecated in MySQL 8.0 (e.g., old formats of TIME and DATETIME), which may cause compatibility issues. |Error |* Problem: Detected the use of old temporal types, such as obsolete formats for TIME or DATETIME.<br><br>* Impact: A direct upgrade may cause data truncation or query errors.<br><br>* Solution: Rebuild the table using ALTER TABLE <table_name\> FORCE.<br><br>   Example: `ALTER TABLE orders FORCE;` |
|routineSyntax |Check syntax compatibility for stored procedure objects: verify that the syntax of stored procedures, functions, or triggers complies with the new specifications in MySQL 8.0 (for example, DEFINER syntax or changes in variable scope). |Error |* Problem: The stored procedure references a MySQL 8.0 reserved keyword (such as RANK).<br><br>* Impact: The stored procedure fails to execute after the upgrade.<br><br>* Solution: Enclose the keyword in backticks or rename the object.<br><br>   Example: `SELECT `\\rank` FROM scores;` |
|reservedKeywords |Check if database object names conflict with reserved keywords: Identifies if table names, column names, etc., use new reserved keywords in MySQL 8.0 (such as CUME_DIST, JSON_TABLE). They must be renamed to avoid syntax errors. |Error |* Problem: Object name conflicts with a MySQL 8.0 reserved word (such as GROUPS).<br><br>* Impact: Syntax parsing error.<br><br>* Solution: Rename the object or use backticks in the query.<br><br>   Example: `RENAME TABLE groups TO user_groups;` |
|utf8mb3 |Check the use of the utf8mb3 character set: detects if the 3\-byte utf8mb3 character set is still in use. It is recommended to replace it with utf8mb4 to support full Unicode characters (such as emojis). |Warning |* Problem: The instance uses the utf8mb3 character set.<br><br>* Impact: Unable to store 4\-byte Unicode characters.<br><br>* Solution: Convert to utf8mb4: `ALTER TABLE t CONVERT TO CHARSET utf8mb4;` |
|mysqlSchema |Check for table name conflicts in MySQL System libraries: Ensures that the names of Database objects created by users do not conflict with new System tables in MySQL 8.0 (such as innodb_index_stats). |Error |* Problem: A user table has the same name as a MySQL 8.0 system table, such as innodb_index_stats.<br><br>* Impact: Metadata conflict during upgrade.<br><br>* Solution: Rename the user table: `RENAME TABLE innodb_index_stats TO my_stats;` |
|nonNativePartitioning |Check for partitioned tables that use non\-native partitioning engines: Detects whether partitioned tables rely on non\-InnoDB engines (such as MyISAM), as MySQL 8.0 only supports InnoDB as the default engine for partitioned tables. |Error |* Problem: Partitioned tables use a non\-InnoDB engine (such as MyISAM).<br><br>* Impact: The table is inaccessible after the upgrade.<br><br>* Solution: Convert the engine: `ALTER TABLE t ENGINE=InnoDB;` |
|foreignKeyLength |Check if foreign key constraint names exceed 64 characters: Foreign key names are limited to 64 characters in MySQL 8.0. Longer names must be modified to prevent metadata errors. |Error |* Problem: The foreign key name exceeds 64 characters.<br><br>* Impact: Metadata corruption.<br><br>* Solution: Rename the foreign key: `ALTER TABLE t DROP FOREIGN KEY fk_long_name, ADD FOREIGN KEY (col) REFERENCES t2(col) CONSTRAINT fk_short;` |
|maxdbSqlModeFlags |Check for the deprecated MAXDB SQL_MODE mode: Checks whether the MAXDB compatibility mode is enabled. This mode was removed in 8.0, so you need to adjust the relevant SQL logic. |Warning |* Problem: The MAXDB mode is enabled.<br><br>* Impact: Abnormal conversion between DATETIME and TIMESTAMP types.<br><br>* Solution: Remove the MAXDB mode: `SET GLOBAL sql_mode=(SELECT REPLACE(@@sql_mode,'MAXDB',''));` |
|obsoleteSqlModeFlags |Check for deprecated SQL_MODE modes: identify the use of SQL modes deleted in MySQL 8.0 (such as NO_FIELD_OPTIONS) and update the configuration to avoid unexpected behavior. |Warning |* Problem: Using deprecated sql_mode options (such as NO_FIELD_OPTIONS).<br><br>* Impact: Abnormal SQL behavior after the upgrade.<br><br>* Solution: Clean up the sql_mode configuration. |
|enumSetElementLength |Check if the length of ENUM/SET column elements exceeds the limit: ensure that the element values for ENUM or SET types do not exceed 255 characters. Otherwise, data truncation or creation failure will occur. |Error |* Problem: ENUM/SET elements are too long.<br><br>* Impact: Data truncation occurs during insertion.<br><br>* Solution: Shorten the element or change it to VARCHAR: `ALTER TABLE t MODIFY c VARCHAR(500);` |
|partitionedTablesInSharedTablespaces |Check partitioned tables in shared tablespace: detects if partitioned tables are stored in a shared tablespace (such as ibdata1), as MySQL 8.0 requires partitioned tables to use individual tablespaces. |Error |* Problem: the partitioned table uses a shared tablespace.<br><br>* Impact: upgrade failure.<br><br>* Solution: migrate to an independent tablespace: `ALTER TABLE t REORGANIZE PARTITION p1 INTO (PARTITION p1 VALUES LESS THAN (100) TABLESPACE=innodb_file_per_table);` |
|circularDirectory |Check for circular directory references in tablespace paths: Verifies whether tablespace file paths contain circular symbols (such as .. or .), which can cause file access errors. |Error |* Problem: The tablespace path contains circular references (such as `/../`).<br><br>* Impact: This path is prohibited in MySQL 8.0.17 and later versions.<br><br>* Solution: Modify the path to an absolute path. |
|removedFunctions |Check for removed functions: identifies the use of functions deleted in MySQL 8.0 (e.g., ENCRYPT() or IS_OLD_PASSWORD()), which need to be replaced with equivalent new functions. |Error |* Problem: Using a removed function (such as ENCRYPT()).<br><br>* Impact: SQL execution failed.<br><br>* Solution: Replace with an equivalent function (such as AES_ENCRYPT()). |
|groupbyAscSyntax |Check the ASC/DESC syntax in GROUP BY clauses: Detects reliance on the implicit sorting behavior of GROUP BY col ASC/DESC, which must be changed to an explicit ORDER BY. |Error |* Problem: Using GROUP BY col ASC/DESC.<br><br>* Impact: Syntax error.<br><br>* Solution: Use ORDER BY: `SELECT col FROM t GROUP BY col ORDER BY col ASC;` |
|sysVars |Check for system variable deprecation, deletion, or default value changes: verifies if configured system variables (such as innodb_file_format) are deprecated or deleted in 8.0, or if their default values have changed. |Error |* Problem: using deprecated variables (for example, innodb_file_format).<br><br>* Impact: configuration failure. Solution: remove or replace the variable. |
|zeroDates |Check for zero date and time values: detects illegal date and time values, such as 0000\-00\-00, which must be fixed or disabled with the NO_ZERO_DATE mode. |Warning |* Problem: zero\-value dates exist (e.g., 0000\-00\-00).<br><br>* Impact: insertion fails after the upgrade.<br><br>* Solution: update the data: `UPDATE t SET date_col='1970-01-01' WHERE date_col='0000-00-00';` |
|schemaInconsistency |Check for metadata inconsistencies caused by deleted or corrupted files: verify that the table definition file (.frm) is consistent with the storage engine data to prevent metadata errors during the upgrade. |Error |* Problem: The table files (.frm/.ibd) are corrupted or lost.<br><br>* Impact: The table is inaccessible.<br><br>* Solution: Restore from a backup or rebuild the table. |
|engineMixup |Check for tables with engine ownership conflicts: detects if the InnoDB engine incorrectly manages tables from other engines (such as MyISAM). The engine definition needs to be fixed. |Error |* Problem: The InnoDB engine is inconsistent with the metadata declaration.<br><br>* Impact: Table access error.<br><br>* Solution: Rebuild the table structure: `CREATE TABLE t_new LIKE t; INSERT t_new SELECT * FROM t; RENAME TABLE t TO t_old, t_new TO t;` |
|checkTableCommand |Check for problems reported by the CHECK TABLE command: Ensure all tables pass the CHECK TABLE validation and do not report any corruption or index errors. |Warning |* Problem: CHECK TABLE reports an error.<br><br>* Impact: Risk of data corruption.<br><br>* Solution: Repair table: `REPAIR TABLE t;` |
|changedFunctionsInGeneratedColumns |Check function indexes for semantic changes: Detect if a function index relies on behavior from a previous version, such as expression length limits, and re\-evaluate its validity. |Warning |* Problem: semantic change in function indexes (e.g., behavioral change of SUBSTRING()).<br><br>* Impact: abnormal query results.<br><br>* Solution: rebuild the index: `ALTER TABLE t DROP INDEX idx, ADD INDEX idx ((SUBSTRING(col,1,10)));` |
|columnsWhichCannotHaveDefaults |Check for columns that do not allow default values: identifies column definitions, such as BLOB and TEXT, that do not support default values and require table structure adjustments. |Error |* Problem: A default value is set for a BLOB/TEXT column.<br><br>* Impact: Table creation fails.<br><br>* Solution: Remove the default value: `ALTER TABLE t ALTER COLUMN c DROP DEFAULT;` |
|invalid57Names |Check for invalid table or database names: detects names that contain special characters (such as / or .), which must be renamed to meet the 8.0 naming conventions. |Error |* Problem: The object name contains special characters (such as #).<br><br>* Impact: The upgrade failed.<br><br>* Solution: Rename: `ALTER DATABASE \#mysql50#` UPGRADE DATA DIRECTORY NAME;`` |
|orphanedObjects |Check for orphaned stored procedures or events: Identify invalid stored procedures or events caused by the deletion of dependent objects, which need to be cleaned up or redefined. |Error |* Problem: The database that the stored procedure depends on has been deleted.<br><br>* Impact: The upgrade failed.<br><br>* Solution: Delete the orphaned object: `DROP PROCEDURE orphaned_proc;` |
|dollarSignName |Check for single dollar signs in object names: detects if the dollar sign ($) is used in an object name, such as $event, which needs to be changed to another naming format. |Warning |* Problem: the object name starts with $ but is not enclosed.<br><br>* Impact: syntax warning.<br><br>* Solution: rename it to the $name$ format. |
|indexTooLarge |Check for oversized invalid indexes: Verify whether the index length exceeds 3072 bytes (InnoDB limit). You must shorten the index or use a prefix index. |Error |* Problem: Index exceeds 3072 bytes (redundant row format).<br><br>* Impact: The table is inaccessible.<br><br>* Solution: Enable dynamic row format: `ALTER TABLE t ROW_FORMAT=DYNAMIC;` |
|emptyDotTableSyntax |Checks for deprecated table prefix syntax in routines: detects whether stored procedures use the `.<table>` format to reference tables (for example, db.table), which needs to be changed to the standard format. |Error |* Problem: the stored procedure uses the `.<table>` syntax.<br><br>* Impact: syntax error.<br><br>* Solution: Use the fully qualified name: db.table. |
|invalidEngineForeignKey |Check for cross\-engine foreign keys: Identify foreign keys that link tables with different storage engines (e.g., an InnoDB table referencing a MyISAM table), and unify the engines. |Error |* Problem: cross\-engine foreign keys (for example, InnoDB referencing MyISAM).<br><br>* Impact: invalid foreign keys.<br><br>* Solution: unify engines: `ALTER TABLE t ENGINE=InnoDB;` |
|authMethodUsage |Check for deprecated or invalid user authentication methods: detects whether old password hashes (such as mysql_old_password) are used, which need to be upgraded to caching_sha2_password. |Warning |* Problem: Old password hashes are being used.<br><br>* Impact: Client connection failed.<br><br>* Solution: Migrate user: `ALTER USER 'user' IDENTIFIED WITH caching_sha2_password BY 'password';` |
|pluginUsage |Check for deprecated or removed plugins: identifies if deprecated plugins, such as partition or innodb_plugin, are loaded. They need to be disabled or replaced. |Warning |* Problem: Loading a removed plugin, such as partition.<br><br>* Impact: The plugin is unavailable.<br><br>* Solution: Uninstall the plugin: `UNINSTALL PLUGIN partition;` |
|deprecatedDefaultAuth |Check the default authentication method in system variables: verify if default_authentication_plugin is set to an invalid value (such as mysql_native_password). |Warning |* Problem: The default_authentication_plugin is set to an old value.<br><br>* Impact: New user authentication fails.<br><br>* Solution: Update the variable: `SET GLOBAL default_authentication_plugin='caching_sha2_password';` |
|deprecatedRouterAuthMethod |Check the authentication method for the internal MySQL Router account: Ensure that the internal account used by the router does not rely on a legacy authentication agreement. |Warning |* Problem: the Router internal account uses an old authentication method.<br><br>* Impact: the Router fails to start.<br><br>* Solution: upgrade the Router to the latest version. |
|deprecatedTemporalDelimiter |Check for deprecated time separators in table partitions: detects partition definitions that use a colon (e.g., 1990:01), which must be changed to the standard date format. |Error |* Problem: The partition uses a colon to separate the time (e.g., 1990:01).<br><br>* Impact: Partitions are not accessible.<br><br>* Solution: Use the standard format: `PARTITION p VALUES LESS THAN ('1990-01')` |
|invalidUTF8MB3Character<br><br> |Check for invalid utf8mb3 characters: Detects invalid utf8mb3 characters in the database.<br><br> |Error |* Problem: Unsupported characters exist.<br><br>* Impact: The upgrade failed.<br><br>* Solution: Check the `information_schema` system database for illegal characters in the metadata and delete them if they exist. |
