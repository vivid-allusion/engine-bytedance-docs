This topic describes the pre\-check items for a blue\-green switch.


|**Check items** |**Description** |**Scope** |**Problem, impact, and solution** |
|---|---|---|---|
|check_endpoint |Compare the endpoint status of the blue and green instances before and after the switch. |Warning/Failed |* Warning<br><br>   * **Problem**:<br><br>      * The IPv4 and IPv6 protocol stack configurations of blue instance endpoints and green instance endpoints are inconsistent.<br><br>      * A public network exists in the default endpoint of the blue or green instance.<br><br>      * The VPCID configurations of the blue and green instances are inconsistent.<br><br>* Failed<br><br>   * **Problem**: The endpoints of the blue and green instances switch between proxy endpoints and direct endpoints. |
|check_allow_list |Compare the allowlist configurations of the blue and green instances. |Warning |* **Problem**: The allowlists of the blue and green instances are inconsistent.<br><br>* **Impact**: After the blue\-green switch, users may be unable to access the database connection.<br><br>* **Solution**: Modify the allowlists of the green instance to match those of the blue instance. |
|check_resource |Compare the basic resource information of the primary nodes in the blue and green instances. |Warning |* **Problem**: The specifications and instance types of the blue and green instances are different. For example:<br><br>   * The storage space of the green instance is less than the storage space of the blue instance.<br><br>   * The specification types of the green and blue instances are inconsistent.<br><br>   * The storage types of the green and blue instances are inconsistent.<br><br>* **Impact**: The configuration of the green instance is relatively low. After a blue\-green switch, the green instance may be unable to handle the service traffic, resulting in problems such as performance bottlenecks and full disks.<br><br>* **Solution**: Upgrade the specifications of the green instance to match those of the blue instance. |
|check_param |Compare the runtime values of key parameters for the blue and green instances. |Warning |* **Problem**: The parameter configurations for sql_mode, collation_server, default_time_zone, or init_connect are inconsistent between the blue and green instances.<br><br>* **Impact**:<br><br>   * Inconsistent sql_mode configuration: causes issues such as GROUP BY query syntax errors and string data truncation.<br><br>   * Inconsistent collation_server configuration: causes incorrect sorting of Chinese and English characters, garbled Chinese search or query results, and abnormal case matching.<br><br>   * Inconsistent default_time_zone configuration: causes abnormal storage for time field data in data tables.<br><br>   * Inconsistent init_connect configuration: causes new database connections to lack preset session configurations and leads to abnormal initialization of character sets and session variables, resulting in garbled query results and permission errors.<br><br>* **Solution**: Modify the parameter configuration to ensure consistent parameter values between the blue and green instances. |
|check_status |Check the state of the blue and green instances. |Failed |* **Problem**:<br><br>   * The blue instance is not in the Running state.<br><br>   * The blue or green instance has External Replication enabled.<br><br>* **Solution**:<br><br>   * The blue instance state must be Running.<br><br>   * Close the External Replication feature for the blue instance or the green instance. |
|check_node_info |Compare the number of nodes in the blue and green instances. |Prompt |* **Problem**: The blue and green instances have an inconsistent number of nodes.<br><br>* **Impact**: A difference in the number of read\-only nodes and secondary nodes between the blue instance and green instance results in different read/write separation traffic and high\-availability disaster recovery capabilities.<br><br>* **Solution**: Modify the number of nodes to ensure the blue instance and the green instance have the same number of nodes. |
|check_proxy |Compare the database proxy specifications of the blue and green instances. |Failed/Warning |* Failed<br><br>   * **Problem**: The database proxy configurations for the blue and green instances are inconsistent. The database proxy is enabled on one instance but disabled on the other.<br><br>   * **Solution**: Enable or disable the database proxy on the green instance to match the status of the blue instance.<br><br>* Warning<br><br>   * **Problem**: The number of database proxy cores is inconsistent between the blue and green instances.<br><br>   * **Impact**: After a blue\-green switch, the database proxy may experience high loads, increased access latency, and reduced availability.<br><br>   * **Solution**: Modify the number of proxy cores to be consistent between the blue and green instances. |
|check_mysql_version |Compare the major and minor kernel versions of the blue and green instances. |Prompt |* **Problem**: The major database kernel version and kernel version are inconsistent between the blue and green instances.<br><br>* **Impact**:<br><br>   * Inconsistent major database kernel versions: Different major versions have different authentication plugins, SQL syntax, built\-in functions, and data field types. If the major database kernel version of the blue instance is lower than that of the green instance, a blue\-green switch may cause database connection failures and invalid fields in data tables.<br><br>   * Inconsistent kernel versions: Some underlying parameters may differ between kernel versions, which can cause compatibility issues after a blue\-green switch. |
|check_instance_type |Compare the instance types of the blue and green instances. |Prompt |**Problem**: The instance types of the blue and green instances are inconsistent. |
|check_ssl_tde |Check the TDE/SSL status of the blue and green instances. |Warning |* **Problem**: Switching is not supported because the blue instance has enabled TDE or SSL encryption.<br><br>* **Solution**: Disable TDE or SSL encryption for the blue instance. |
|check_support_switch |Check whether the blue and green instances support switching. |Failed |* **Problem**:<br><br>   * The green instance was once set with global read\-only mode disabled, during which data write operations were performed.<br><br>   * The DTS synchronization link for the blue\-green switch was not created.<br><br>* **Impact**: The blue\-green switch failed.<br><br>* **Solution**:<br><br>   * Rebuild green instance.<br><br>   * Create a DTS synchronization link between the blue and green instances. |
|check_monitor |The monitoring configuration may be inconsistent after the blue and green instances are switched. |Prompt |* **Problem**: The monitoring configuration for the blue and green instances is inconsistent.<br><br>* **Impact**: Monitoring configurations are not automatically switched following a blue\-green switch, which may delay timely monitoring and alert notifications for core metrics.<br><br>* **Solution**: After a blue\-green switch, manually configure the new instance using the original monitoring configuration as a reference. |
|check_backup |Switching the blue and green instances does not migrate instance backups. |Prompt |* **Problem 1**: After a blue\-green switch, the backup policy is not automatically migrated.<br><br>* **Impact 1**: After blue\-green switching, the backup policies configured for instances will not be synchronized, resulting in untimely data backups on the instances. If the instance fails at this point, no backup datasets will be available, making it difficult to quickly restore complete business data.<br><br>* **Solution 1**: Before a blue\-green switch, modify the backup policy to ensure that the backup policies of the blue and green instances are consistent.<br><br>* **Problem 2**: The backup data of the blue and green instances are independent and cannot be migrated.<br><br>* **Impact 2**: Backup files in the instance are not migrated after a blue\-green switch. |
|check_domaig |During the blue\-green switch, the IP address is not switched. Only the domain of the specified endpoint is switched. |Prompt |* **Problem**: Blue\-green switch does not support IP switching. It only supports switching the domain of a specified endpoint.<br><br>* **Impact**: After a blue\-green switch, the IP address of the endpoint changes. The connection information for accessing the database using an IP address is not migrated, which can lead to unexpected write and read/write actions.<br><br>* **Solution**: Access the database by using a domain name. |
|check_blue_instance |Check the health state of the blue instance. |Failed |* **Problem**:<br><br>   * The synchronization link between the primary and secondary nodes failed.<br><br>   * The usage rate of CPU, memory, and storage is greater than 80%.<br><br>   * DNS resolution does not meet the switch requirements.<br><br>* **Impact**: the green instance does not meet the switch conditions, which may cause abnormal access after the switch.<br><br>* **Solution**:<br><br>   * Check the synchronization link for any abnormalities.<br><br>   * Expand the instance to reduce the CPU, memory, and storage usage rate. |
|check_green_instance |Check the health state of the green instance. |Failed |* **Problem**:<br><br>   * The synchronization link between the primary and secondary nodes failed.<br><br>   * The usage rate of CPU, memory, and storage is greater than 80%.<br><br>   * DNS resolution does not meet the switch requirements.<br><br>* **Solution**:<br><br>   * Check the synchronization link for any abnormalities<br><br>   * Expand the instance to reduce the CPU, memory, and storage usage rate. |
|check_dts_delay |Check the synchronized latency of the blue and green instances. |Warning |* **Problem**: The synchronization latency of DTS between the blue and green instances exceeds 30 seconds.<br><br>* **Impact**: After a blue\-green switch, data inconsistency may arise and generate dirty data. If an instance fails, rollback operations may cause data loss, as incremental data written during the synchronization latency window cannot be retrieved. Furthermore, persistent rising latency leads to accumulated binlog transactions, degrading overall instance performance. |
|check_dts_sync_lag |Check the number of unsynchronized transactions for the blue and green instances. |Warning |* **Problem**: The volume of unsynchronized transactions between the blue and green instances exceeds the switch threshold.<br><br>* **Impact**: After a blue\-green switch, data may become inconsistent between the blue and green instances. A large backlog of transactions can also increase the CPU, IO, and memory load.<br><br>* **Solution**: Check whether there are abnormalities in the synchronization link. If the synchronization link works properly, you can scale up the instance to improve CPU, I/O and memory performance. You may also split large transactions to prevent massive data generation at once. Perform blue\-green instance switching during off\-peak business hours. |
|check_dts_incr_data_validation |Check the incremental data consistency of the blue and green instances. |Failed/Warning |* Failed<br><br>   * **Problem**: The incremental data of the blue and green instances is inconsistent.<br><br>   * **Impact**: Blue\-green switching is prohibited, as data consistency cannot be guaranteed after switching.<br><br>   * **Solution**: Rebuild the green instance and check for data differences by using DTS.<br><br>* Warning<br><br>   * **Problem**: Data validation is not configured for the DTS synchronization link.<br><br>   * **Impact**: It cannot be verified whether incremental data remains consistent before and after the blue\-green switch.<br><br>   * **Solution**: Enable incremental data validation. |
