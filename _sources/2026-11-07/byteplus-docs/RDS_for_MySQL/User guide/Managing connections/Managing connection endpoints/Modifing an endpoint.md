RDS for MySQL supports modifying the connection information, endpoint information, associated nodes, and Read/Write separation settings of a connection endpoint. This topic describes how to edit connection endpoints.

## Prerequisites

An instance has been created, and its state is **Running**. For more details, refer to [Creating an instance](https://docs.byteplus.com/en/docs/RDS_for_MySQL/creating_an_instance_1).

## Precautions

The endpoint type, read/write mode, automatically add new nodes feature, and read request scheduling policy for connection endpoints of multiple node instances cannot be adjusted. The automatically add new nodes feature is enabled by default for default and read\-only endpoints, and disabled by default for write endpoints. The read request scheduling policy uses round\-robin scheduling by default.

## Procedure

1. Log on to the [RDS for MySQL console](https://console.byteplus.com/db/rds-mysql).

2. In the top menu bar, select the project and region for the instance.

> **tip**

> If the project of the instance has not been set, the project should be selected as **All resources**.

3. On the left navigation bar, click **Instances** to go to the **Instances** page.

4. Click the name of the target instance on the **Instance list** page to go to the **Instance information** page.

5. On the **Summary** page, click the **Connectivity** tab to enter the **Connectivity** page.

6. On the **Connectivity** page, in the **Endpoints** list, click **Edit** in the **Actions** column for the target connection endpoint to open the **Modify endpoint** page.

   On the **Modify endpoint** page, you can configure the following features:

   |Configuration item |Applicable endpoint type |Description |
   |---|---|---|
   |Endpoint type |\- |If the database proxy feature is enabled for the instance, you can convert the endpoint type between a proxy endpoint and a direct endpoint.<br><br><br>* After a direct endpoint is converted to a proxy connection endpoint, the endpoint will have the advanced functions provided by the proxy. During the conversion process, there will be a connection interruption of seconds. It is recommended to add a reconnection mechanism to the application in advance to reduce the impact on the business.<br><br>* After a proxy endpoint is converted to a direct connection endpoint, the additional functions provided by the proxy will be lost, and the proxy\-related configuration will not be retained. During the conversion process, there will be a connection interruption of seconds. It is recommended to add a reconnection mechanism to the application in advance to reduce the impact on the business.<br><br><br>> **tip**<br><br><br>> The endpoint type for multiple node instances cannot be modified.<br> |
   |Read/Write mode |Proxy endpoint and direct endpoint |Select the Read/Write mode of the connection endpoint. You can select **Read/Write** or **Read\-only**.<br><br>> **tip**<br><br><br>> The read/write mode of connection endpoints for multiple node instances cannot be modified.<br> |
   |Connection pool |Proxy endpoint |Select the connection pool mode for the connection endpoint. You can select **Transaction\-level connection pool** or **Direct connection mode**. For more information about the connection pool mode, refer to [About connection pool modes](https://docs.byteplus.com/en/docs/RDS_for_MySQL/about_connection_pool_mode). |
   |Wait_timeout |Proxy endpoint |Select whether to enable the Wait_timeout feature.<br><br><br>* When enabled, connections through the proxy will be automatically disconnected if they have been idle for longer than the period specified in `wait_timeout`, reducing resource usage.<br><br>* When disabled, connections through the proxy will not be automatically disconnected even if they have been idle for longer than the period specified in `wait_timeout`, which may consume more system resources.<br><br>* The Wait_timeout feature relies on the MySQL session tracker mechanism. This feature will not work if the [session_track_state_change](https://dev.mysql.com/doc/refman/8.4/en/server-system-variables.html#sysvar_session_track_state_change) parameter is set to `OFF` and the [session_track_system_variables](https://dev.mysql.com/doc/refman/8.4/en/server-system-variables.html#sysvar_session_track_system_variables) parameter is left empty.<br><br>* If the Database proxy feature for the instance is disabled after the Wait_timeout feature is enabled, the Wait_timeout feature will not take effect and will not be displayed on the Modify endpoint page. When the Database proxy feature for the instance is re\-enabled, the Wait_timeout feature is automatically restored. |
   |Endpoint name |Proxy endpoint and direct endpoint |Set the name of the connection endpoint. The rules for the endpoint name are as follows:<br><br><br>* Cannot be empty.<br><br>* It cannot start with a digit or hyphen (\-).<br><br>* The name length is limited to 1–64 characters.<br><br>* It can contain only Chinese characters, letters, digits, underscores (_), and hyphens (\-). |
   |Modify the connection address prefix |Proxy endpoint and direct endpoint |Modify the connection address prefix. For more details, refer to [Modifying address prefix and port](https://docs.byteplus.com/en/docs/RDS_for_MySQL/modifying_address_prefix_and_port). |
   |Modify port |Proxy endpoint and direct endpoint |Modify the port. For more details, refer to [Modifying address prefix and port](https://docs.byteplus.com/en/docs/RDS_for_MySQL/modifying_address_prefix_and_port). |
   |Enabling or disabling public network resolution |Proxy endpoint and direct endpoint |Enable or disable public network resolution. For more details, refer to [Enabling or disabling public network resolution](https://docs.byteplus.com/en/docs/RDS_for_MySQL/enabling_or_disabling_public_network_resolution). |
   |Enable or disable public network access |Proxy endpoint and direct endpoint |Enable or disable public network access For more details, refer to [Enabling or disabling public network access](https://docs.byteplus.com/en/docs/RDS_for_MySQL/enabling_internet_access). |
   |Associate node |Proxy endpoint and direct endpoint |Associate nodes with the connection endpoint. The rules for associating nodes with connection endpoints vary for different instance types:<br><br><br>* **Single\-node instances**: associated with the primary node of the instance by default.<br><br>* **Double node instance**<br><br>   * A proxy endpoint in read/write mode can be associated with only the primary node or with the primary node and up to 10 read\-only nodes; in Read\-only mode, it can only be associated with 1 to 10 read\-only nodes.<br><br>   * A direct endpoint in Read/Write mode can only be associated with the primary node; in Read\-only mode, it can only be associated with 1 read\-only node.<br><br>* **Multiple node instances**<br><br>   * The default endpoint is associated with all nodes of the instance, the write endpoint is only associated with the primary node of the instance, and adjusting the associated nodes is not supported for either the default endpoint or the write endpoint.<br><br>   * The read\-only endpoint is associated with all secondary nodes by default, and it can be associated with a minimum of one and a maximum of all secondary nodes.<br><br>   * A direct endpoint only supports Read/Write mode and in read\-write mode they can only be associated with the primary node.<br><br>   > **tip**<br>   <br><br>   * > When adjusting the nodes associated with the read\-only endpoint of a multiple node instance, disable the **Associate all secondary nodes** function.<br>   <br><br>   * > After a secondary node is switched to the primary node, it is automatically disassociated from the connection endpoint.<br>   <br><br><br>> **tip**<br><br><br><br>* > When adding a read\-only node (for a double node instance) or a secondary node (for a multiple node instance) to a connection endpoint, new requests will be automatically distributed to the new node immediately. When removing a read\-only node from a connection endpoint, if the node is in a normal state, MySQL uses hot switching technology. The association will not be removed until all queries on the node are executed. During this process, the connection is not interrupted and normal business access is not affected.<br><br><br>* > Once a secondary node associated with the read\-only endpoint of a multiple node instance is switched to the primary node, the number of secondary nodes associated with the read\-only endpoint is reduced by one. If you need to maintain the original number of secondary nodes in the read\-only endpoint, you need to manually add a new secondary node. It is recommended to configure enough secondary nodes for the endpoint to handle business traffic.<br><br><br>* > To ensure high availability in read\-only mode, it is recommended to associate the read\-only endpoint with at least two secondary nodes (for multiple node instances) or two read\-only nodes (for double node instances).<br> |
   |Associate all secondary nodes |Proxy endpoint |Set whether to associate the connection endpoint with all secondary nodes.<br><br>> **tip**<br><br><br><br>* > Only read\-only endpoints of multiple node instances support this configuration.<br><br><br>* > To disable this function, the instance must have at least two secondary nodes.<br> |
   |Automatically add new nodes |Proxy endpoint |Select whether to automatically add new nodes. When enabled, the connection endpoint automatically associates with newly added nodes.<br><br>> **tip**<br><br><br><br>* > The "Automatically add new nodes" feature for the connection endpoint of a multiple\-node instance cannot be closed.<br><br><br>* > After a secondary node is switched to the primary node, it is automatically disassociated from the connection endpoint.<br> |
   |Connection persistence |Proxy endpoint |Select whether to enable connection persistence for the endpoint. For more information about the connection persistence feature, refer to [Enable or disable connection persistence](https://docs.byteplus.com/en/docs/RDS_for_MySQL/configuring_connection_persistence). |
   |Read/Write separation |Proxy endpoint |Select whether to enable the Read/Write separation feature. Once enabled, you can configure read requests to be forwarded to read\-only nodes to reduce the read load on the primary node.<br><br>> **tip**<br><br><br>> Only connection endpoints in Read/Write mode support the Read/Write separation feature.<br> |
   |Consistency level<br><br> |Proxy endpoint |Select one of the following levels based on your business scenario:<br><br><br>* Eventual consistency (Default value).<br><br>* Session consistency.<br><br>* Global consistency.<br><br><br>> **tip**<br><br><br><br>* > Only connection endpoints with an **Endpoint type** of **Proxy endpoint** and a **Read/Write mode** of **Read/Write** support setting the consistency level.<br><br><br>* > For the application scenarios of Eventual consistency, Session consistency, and Global consistency, refer to [Consistency introduction](https://docs.byteplus.com/en/docs/RDS_for_MySQL/set-consistency-level?lang=en#9yKTOGwS).<br> |
   |Consistent read timeout |Proxy endpoint |Sets the maximum time for the proxy to wait for read\-only nodes to catch up to the target data position. The default value is 10 ms. The value range is 0~60,000, and the unit is ms (milliseconds). When this parameter is set to 0, no waiting is required.<br><br>> **tip**<br><br><br>> This parameter can only be configured when the **consistency level** is set to **Session consistency** or **Global consistency**.<br> |
   |Timeout policy |Proxy endpoint |Set the method used by the proxy to handle read requests when the read\-only node fails to catch up with the target position within the timeout period. Values are as follows:<br><br><br>* **Switch to primary node** (Default value): Forwards read requests to the primary node. This approach may increase the load on the primary node.<br><br>* **Return error**: Returns an error message. It is recommended that your application has a retry mechanism.<br><br><br>> **tip**<br><br><br>> This parameter can only be configured when the **consistency level** is set to **Session consistency** or **Global consistency**.<br> |
   |Multi\-Statements mode |Proxy endpoint |Select Multi\-Statements mode. You can select **Strict mode** or **Loose mode**.<br><br><br>* Strict mode<br><br>   In this mode, Multi\-Statements will be sent to the primary node, and subsequent requests for read/write separation of the current connection will fail. All requests will be routed to the primary node. Disconnecting the current connection and reconnecting is needed to restore read/write separation. The connection endpoints in this mode does not parse Multi\-Statements, has good performance, and is suitable for short connection and connectionless multiplexing scenarios.<br><br>* Loose mode<br><br>   In this mode, Multi\-Statements are sent to the primary node, and subsequent requests for the current connection can still be read/write separation. The connection endpoints in this mode does not parse Multi\-Statements, and has good performance. It is suitable for scenarios where Multi\-Statements only contain DML SQL and do not contain operations such as setting session variables, creating temporary tables, creating stored procedures, and executing uncommitted transactions.<br><br><br>> **tip**<br><br><br>> The Multi\-Statements mode for the endpoint can only be adjusted when read/write separation is enabled.<br> |
   |Overload protection |Proxy endpoint |Select whether to enable overload protection. When enabled, a protection mechanism for the primary node is activated if all its read\-only nodes become abnormal, preventing it from being overwhelmed by traffic spikes.<br><br>> **tip**<br><br><br><br>* > When enabled, the overload protection time must be set. The overload restriction on the primary node is lifted after the configured protection time expires. The value range for the overload protection time is 60 to 7200s.<br><br><br>* > If the connection endpoint of your instance does not have the overload protection feature, upgrade the kernel version of the instance. To upgrade the kernel version of the instance, refer to [Manually upgrading instance kernel version](https://docs.byteplus.com/en/docs/RDS_for_MySQL/upgrading_instance_kernel_minor_version).<br><br><br>* > The overload protection feature is effective only when the Read/Write separation feature is enabled for the connection endpoint, and the associated nodes include both the primary node and read\-only nodes (for a double node instance) or secondary nodes (for a multiple node instance).<br><br><br>* > Only proxy endpoints support the overload protection feature.<br> |
   |Read request scheduling policy |Proxy endpoint |Select the read request scheduling policy for the connection endpoint. The options are **Round robin scheduling** or **Connection schedule**.<br><br><br>* Round robin scheduling<br><br>   Recommended option. When this scheduling policy is selected, the system dispatches new connections to associated nodes via round\-robin scheduling, based on a weight configuration that is automatically calculated based on the instance specification.<br><br>* Connection schedule<br><br>   The system automatically distributes new connections to nodes with lighter loads based on the node's active request volume and response time.<br><br><br>> **tip**<br><br><br>> Multiple node instances only support the round robin scheduling policy.<br> |
   |Weight allocation policy |Proxy endpoint |The weight allocation policy when the read request scheduling policy is set to **Round robin scheduling**. You can select **Automatic assignment** or **Custom assignment**.<br><br><br>* Automatic assignment<br><br>   When this assignment policy is selected, the system automatically assigns a weight to each associated node based on its specification.<br><br>* Custom assignment<br><br>   With custom assignment, the page displays the associated nodes, and you can set a weight for each node in the list. The default weight is automatically calculated based on the node specification. Weight ranges from 0 to 10000 and must be an integral multiple of 100.<br><br><br>> **tip**<br><br><br><br>* > Set the weight according to the proportion of node specifications to prevent uneven node pressure from wasting resources.<br><br><br>* > Multiple node instances only support automatic assignment for the Weight allocation policy.<br> |
   |Primary node routing |Proxy endpoint |Select whether to enable primary node routing for the connection endpoint. When enabled, the primary node is evaluated along with read\-only nodes and accepts separable read\-only requests. When disabled, separable read requests are not routed to the primary node.<br><br>> **tip**<br><br><br><br>* > This configuration is supported only when the read request scheduling policy is set to **Connection schedule** and is only valid for connection endpoints in Read/Write mode.<br><br><br>* > Multiple node instances only support round robin scheduling for the read request scheduling policy, so this configuration is not supported.<br> |
   |Read\-only latency threshold |Proxy endpoint |Set the read\-only latency threshold for the connection endpoint. Read\-only nodes with a latency exceeding this threshold will not be assigned read requests. The range of values is 1 to 3600, in seconds, with a step size of 1.<br><br>> **tip**<br><br><br>> Only Read/Write endpoints support this setting.<br> |
   |Transaction splitting |Proxy endpoint |Select whether to enable transaction splitting for the connection endpoint. |
   |Forwarding rules<br><br> |Proxy endpoint |Set SQL forwarding rules for the endpoint. For more information about setting SQL forwarding rules, refer to [Configure SQL forwarding rules](https://docs.byteplus.com/en/docs/RDS_for_MySQL/Configuring_SQL_forwarding_rules). |

7. Complete the above settings and click **OK**.
