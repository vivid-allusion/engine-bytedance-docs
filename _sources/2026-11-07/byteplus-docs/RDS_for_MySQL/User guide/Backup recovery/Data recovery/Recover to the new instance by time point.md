This topic describes how to recover data to a new instance by time point.

## Prerequisites

An instance has been created and its state is **Running** or **Suspended**. For details, see [Creating an instance](https://docs.byteplus.com/en/docs/RDS_for_MySQL/creating_an_instance_1).

## Precautions

* The engine type, allowlist settings, backup settings, parameter settings, lower case table names setting, and time zone settings of the restored instance are consistent with those of the original instance.

* The data information in the restored instance is consistent with the information at the backup point in time.

* Point\-in\-Time Recovery supports second\-level precision for restore time points. During point\-in\-time recovery, the system restores data generated prior to the specified restore time by one second.

   Example: Three records (Data A, Data B, Data C) are inserted at timestamps 2026\-06\-26 15:12:02.999999, 2026\-06\-26 15:12:03.000000 and 2026\-06\-26 15:12:03.000001 respectively. If you set the restore time point to 2026\-06\-26 15:12:03, only Data A will be restored, while Data B and Data C will not be restored.

* The restored instance contains the account information at the point in time the backup was used.

* If you want to create a pay\-as\-you\-go instance, make sure your account balance is greater than or equal to 100 USD.

* If you want to create a yearly or monthly subscription instance, make sure your account balance is sufficient to pay the order amount.

* After you perform operations such as modifying the configuration, upgrading the version, or restoring to the original instance, RDS for MySQL may reset the Binlog number and restart from 000001. If you have configured Binlog monitoring, check the Binlog after these operations to prevent service impact from monitoring failures.

* The instance is restored to a point in time through a **Backup set + Binlog logs**. If there is a long interval between the full backup set and the target recovery point‑in‑time, a large number of Binlog logs need to be replayed, resulting in increased recovery duration. Recovery duration cannot be estimated. The actual time is directly proportional to the real‑world data volume.

## Procedure

1. Log on to the [RDS for MySQL console](https://console.byteplus.com/db/rds-mysql).

2. In the top menu bar, select the project and Region for the instance, then click **Instances** in the left\-side navigation bar.

   > **tip**

   > If the project to which the instance belongs is not set, this operation should select the project as **All resources**.

3. On the **Instances** page, click the target instance name.

4. At the top of the page, click the **Backups** tab, and on the **Basic backup list** tab, click **Data recovery**.

5. In the pop\-up **Restore To** dialog box, select the **New instance** card and click **OK**.

6. Configure the following parameters by following the guide on the Restore to New Instance page.

7. Click **Confirm order**.

8. Complete the subsequent steps based on the billing type selected.

   * If **Pay\-as\-you\-go** is selected: on the **Confirm order** page, confirm the order details, read and check **Database Products and Services Terms** and **Unsubscription rules**, and click **Buy now** to restore the backup to a new instance.

   * If **Subscription** is selected:

      1. On the **Confirm order** page, confirm the order details, read and check the **Database Products and Services Terms** and **Unsubscription rules**, and click **Submit the order**.

      2. On the **Confirm order information** page, reconfirm the order information, and click **Next step**.

      3. On the **Submit payment information** page, confirm the payment details and select the payment method, click **Go to payment**, and complete the payment according to the prompts to restore to a new instance.

   > **tip**

   * > If you are using a root account, point your mouse to ![](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_a8e8b2ede59e969d5e0f5f63054bb5f5.png)to the right of the Configuration fee at the bottom of the page to view the fee details for purchasing the instance with the current configuration, including the original price, discount, and discounted price. If you are using a IAM account and do not have the policy that allows the QueryDiscountPrice action, you can only view the original price. For more information about policies, refer to [About policies](https://docs.byteplus.com/en/docs/byteplus-platform/docs-managing-policies).

   * > Return to the instance list page, refresh the current list, the original instance state becomes **Recovering**, and the new instance state becomes **Creating**. Wait for the backup and recovery to complete and then use it normally.
