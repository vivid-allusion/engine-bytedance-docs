# Learning Path Overview

iDA is a **data\-native** agent product that unifies intelligent data query, in\-depth research, insight reporting, document writing, multi\-modal material generation and other capabilities into one entrance, helping enterprises complete the complete link from data query to report delivery in natural language. It is not limited to data analytics scenarios, but also covers general scenarios such as office collaboration, content creation, and knowledge Q&A.

In practical use, the iDA learning path will face three types of roles, and problems of their concern, learning paths, and learning depths are all different. This article breaks down the learning path by role, so that you can focus only on the content that is relevant to you.


|Role |Typical cohorts |Main concern |Learning depth |
|---|---|---|---|
|**Agent user** |Business staff, data analysts, business analysts, operations, products, content creators |Make good use of ready\-made agents to quickly obtain answers and products. |Beginner\-oriented |
|**Agent builder** |Data BP, data engineer, data product manager, scenario owner |Accessing data, importing knowledge, and tuning agents. |Beginner + Advanced |
|**Agent manager** |Data platform administrator, IT/Security leader |Deployment, account, authority, audit, operation and maintenance. |Master |


<span id="23a4b8a9"></span>
# User trial preparation

Before entering the learning path, confirm that you have the account and permission to use iDA. It is recommended to prepare through the following aspects:

**Trial or purchase**

If you have not purchased but need a trial, you can contact the business staff to apply for experience permission; if the enterprise has purchased SaaS or private deployment version, the administrator will create an account for the user and open the corresponding permissions.

**Project and user authorization**

Users need access to the correct region and projects, and are granted access to target agents, datasets, knowledge resources, and export & sharing capabilities. The project manager should complete the user or user group authorization in advance.

**Data and business context**

Data to be analyzed, indicator criteria, business rules, analysis templates and historical reports should be prepared before use. The effectiveness of iDA's in\-depth research and report generation relies on data quality and clarity of business knowledge.

# Common process

The complete use link of iDA can be compressed into 5 steps: building projects, connecting data, configuring agents, measuring effects, and opening up for use. The depth of participation for different roles is different, but it is recommended to understand the entire link, otherwise it is easy to misjudge "incorrect answer" as a model problem, and ignore unconfigured data, knowledge, authority or configuration.


|Step |Process |Action |Learning focus |
|---|---|---|---|
|1 |Create project |Create projects by business scenario and set user or user group permissions. |Core focus on mastery for managers; users only need to know which project they belong to. |
|2 |Access data |After entering the project, in the "Data Preparation" module of the upper navigation, data access, processing and management are completed through functions such as "Data Connection", "Dataset", and "Visual Modeling". |Core focus on mastery for builders; the analytical agent effect mainly depends on the quality of this step. |
|3 |Configure Agent |On the'Agent 'type selection, click 'Create Agent'. Select the appropriate agent type, and then configure the basic information, data and knowledge, content, audit, skills, and other modules. |Core focus on mastery for builders; the user needs to know what scenarios different agents are suitable for. |
|4 |Test & Tune |Test responses, graphs, reports, citations, and tool calls with typical questions in the agent dialogue interface. |Core focus on mastery for both builders and managers; permissions, ambiguities, and boundary issues must be covered before publishing. |
|5 |Open access |Confirm whether Lark robot integration is required. |Managers should focus on access methods, security policies, and operational feedback; users should focus on how to access and use them. |

## Agent user learning path


* Role definition: Users are generally business operations, data analysts, business analysts, product managers, sales, marketing staff, or content creators. The learning goal is not to configure an agent, but to make good use of existing agents and quickly obtain answers, charts, reports, PowerPoint, web pages, images, or video products.

* Object & Vision: Users should master how to choose the right agent and skills, how to ask high\-quality questions in natural language, how to view the analysis process and judge the credibility of the results, and how to use the results of iDA for reporting, collaboration, and decision\-making by copying, exporting, and sharing.

## Agent builder learning path


* Role definition: Agent builders usually come from the data team, business analysis team, data product team or business middle platform, and are the builders of data assets, knowledge assets and agent capabilities behind iDA. They are responsible for enabling iDA to understand enterprise data, metrics, business rules, and high\-frequency analysis methods.

* Object & Vision: Builders should master data access, dataset configuration, knowledge accumulation, Prompt configuration, skill management, and effect tuning methods, and be able to build stable and usable general\-purpose scenario agents according to business scenarios, and continuously improve the quality of Q&A and reporting.

## Agent manager learning path


* Role definition: An agent manager generally comes from the big data team, IT team, platform operations team, or enterprise digital management team, and is the project, authority, resources, operations, and integration leader for iDA. They need to understand not only how users use iDA, but also the configuration logic on the construction and governance sides.

* Object & Vision: Managers should be able to establish a clear system of projects and permissions, manage the scope of agent release and use, track usage and problem feedback, and promote the integration of iDA with existing enterprise systems such as Lark, H5, OpenAPI, and HiAgent.
