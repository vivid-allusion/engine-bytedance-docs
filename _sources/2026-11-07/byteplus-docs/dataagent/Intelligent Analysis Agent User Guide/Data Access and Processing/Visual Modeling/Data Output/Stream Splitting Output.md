# 1. Overview

In the visual modeling module of Smart Data Insights, the output operator category supports real\-time stream splitting output operators. Users can use the stream splitting operator to directly process a single real\-time stream into multiple output streams. During the splitting process, rule configurations are applied, and real\-time streams that meet the conditions are directed into the corresponding substream for output. The stream splitting operator can be directly connected to data cleansing or output operators, or it can be used independently. When running independently, it outputs to a built\-in topic for system consumption. A single real\-time stream can be split into multiple streams based on event behavior or application App ID. Only one Flink task is activated during the process, making this operator highly efficient in utilizing computing resources.

# 2. Features

<span id="_2-1-添加分流输出算子"></span>
## 2.1 Add stream splitting output operator

In a visual modeling task, click the add operator button to see "Stream splitting output" in the output operator category, then click to select it. Notes:

(1) Input restrictions: Read nodes and data cleansing nodes.

(2) Output restrictions: This is a final operator and cannot connect to downstream operators.

<span id="_2-2-配置分流输出算子"></span>
## 2.2 Configure stream splitting output operator

With the stream splitting operator, a single real\-time stream can be directly processed into multiple output streams. Rule configurations are applied during splitting, and real\-time streams that meet the conditions are directed into the corresponding substream for output. The output is provided as a dataset, and you can set the dataset lifecycle as needed to avoid duplicate data storage.

After selecting and adding the stream splitting output operator, you can configure each split stream individually, as well as add or delete split stream configurations. Caution regarding the limit on the number of stream splits: Currently, up to 10 stream splits are supported. Specific configuration is as follows:

(1) Create a new output dataset. You can also proceed to edit dimension metrics.

(2) Configure filtering criteria: Build AND/OR relationships using field conditions to output data that meets the criteria. Click "AND" or "OR" in the logic tree to switch between AND/OR relationships.

(3) You can click "Add Split" to continue creating and configuring.

(4) Click the Delete button in the upper right corner to delete.

**Notes**

(1) Split configuration restrictions: After adding, it must not be left empty. If it is empty, you will be prompted with "There are empty configuration items" when saving.

(2) Output dataset:

a. Naming rules: Only English letters, numbers, and underscores are allowed. Spaces and other special characters are not permitted. The maximum length is 50 characters, and names must be unique.

b. Add switch configuration (or reuse offline switch): Supports editing kafka topic/CK database name and table name. After enabling, you can customize the database name, table name, and topic name.

c. When the switch is off, it is recommended to add a prefix to topics generated by splits to facilitate identification.
