# 1. Overview

In the visual modeling module of Intelligent Data Insight, the output operator category supports real\-time stream splitting output operators. Users can use the stream splitting operator to directly process a single real\-time stream into multiple output streams. The splitting process uses rule configuration, and real\-time streams that meet the conditions are directed into the corresponding substream for output. The stream splitting operator can be directly connected to data cleansing or output operators, or it can be used independently. When running independently, it outputs to a built\-in topic for system consumption. A single real\-time stream can be split into multiple streams based on event behavior or appid. Only one Flink task is enabled during the process, making it an efficient operator for utilizing computing resources.

# 2. Function overview

<span id="_2-1-添加分流输出算子"></span>
## 2.1 Add stream splitting output operator

In a visual modeling task, click the add button for operators to see "Stream splitting output" in the output operator category, then click to select it. Notes:

(1) Input restrictions: read nodes and data cleansing nodes.

(2) Output restrictions: as the final operator, downstream operators cannot be connected.

<span id="_2-2-配置分流输出算子"></span>
## 2.2 Configure stream splitting output operator

The stream splitting operator can directly process a single real\-time stream into multiple output streams. The splitting process uses rule configuration, and real\-time streams that meet the conditions are directed into the corresponding substream for output. The output is provided as a dataset, and the dataset lifecycle can be set as needed to avoid duplicate data storage.

After selecting and adding the stream splitting output operator, you can configure each stream split in detail, as well as add or delete stream split configurations. Caution regarding the stream split limit: currently, up to 10 stream splits are supported. Specific configuration is as follows:

(1) Create a new output dataset; you can also edit dimension metrics.

(2) Configure filter criteria: Build AND/OR relationships using field conditions to output data that meets the criteria. Click "AND" or "OR" in the logic tree to switch between AND/OR relationships.

(3) You can click Add branch to continue creating and configuring.

(4) Click the Delete button in the upper right corner to delete.

**Caution**

(1) Branch configuration restrictions: After adding, it must not be left empty. If it is empty, a prompt will appear when saving: "There are empty configuration items."

(2) Output dataset:

a. Naming rules: Only English letters, numbers, and underscores are allowed. Spaces and other special characters are not permitted. The maximum length is 50 characters, and names must be unique.

b. Add switch configuration (or reuse offline switch): Supports editing kafka topic/CK database name and table name. After enabling, you can customize the database name, table name, and topic name.

c. When the switch is off: It is recommended to add a prefix to topics generated by branching for identification.
