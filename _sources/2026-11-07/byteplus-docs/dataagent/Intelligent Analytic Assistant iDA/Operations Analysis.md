Operational analysis is used to see the usage of an agent over a period of time, helping you quickly understand three things: how many people are using it, whether the answers are normal, and where the single processing is slow. This article details how to use operational analytics capabilities to monitor and troubleshoot agent issues. You can view two types of content here:

|Type |Description |Interface diagram |
|---|---|---|
|**Data Analytics** |Focusing on the number of users, number of sessions, number of requests, time, error rate, and model calls. |![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/880cc2186a95450c96607e4b595e763d~tplv-goo7wpa0wc-image.image) |
|**Traces and Sessions** |View input, output, time, and each step in a single request or full session. |![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/e7ac38ba25fa47e8bc83a4ad3f17d944~tplv-goo7wpa0wc-image.image)<br><br>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/9f4e4f5a49b345baaf7d014cd2e762de~tplv-goo7wpa0wc-image.image) |

# Precautions

* The operation analysis module only supports North China.

* The user has operational analytics access permission for the corresponding project. The main account can be viewed by default; the sub\-account needs to be authorized access to the corresponding project by the main account;

* The top right corner of the page shows the current project. Before reviewing the data, ensure that the project name is correct and avoid mixing data from different projects.

* The operation analysis page is mainly used to view data and troubleshoot problems, not used to directly adding models. When you need to add a new model, you should enter the model integration page in the iDA management background, as detailed in [Model Intergration](https://docs.byteplus.com/docs/dataagent/model-intergration).

# Operation instructions

## Select View Range

1. After logging in to the Volcano console, enter iDA, click Operations Analysis at the top of the agent list page, and enter the Operations Analysis interface.

![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/3fda7d9119584238a36ff9030ee864e9~tplv-goo7wpa0wc-image.image)

2. You can first check the project name in the upper left corner of the page to confirm that you are currently viewing the target project;

3. Select the agent that needs statistics at the top right: view all agents when not specified, or select a single agent;

4. Select the start and end dates; if you want to view at a fixed date granularity, adjust the date dimension options;

5. After adjusting the conditions, the page will display the data according to the selected range; if the data does not change immediately, you can click the refresh button to reload.

![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/7e7fbbf261134303bc771ed83c75d283~tplv-goo7wpa0wc-image.image)

## Filter for abnormal or time\-consuming records

1. Select **Trace & Session \> Trace List** in the Operations Analysis left navigation.

2. Select the view based on the problem to be investigated:

   * **Default view**: View normal records.

   * **Abnormal**: Priority is given to viewing records with failed processing or errors.

   * **Long latency**: Prioritize viewing records with longer processing times.

3. To further narrow the scope, you can set the date, enter the session ID, message ID, or user ID, or use the Span type (e.g. filter out all model calls related to Spans) and advanced filter (e.g. filter out all abnormal records by'error = true ') for precise lookup.

4. View the input, output, start time, and duration of each record in the list; if the duration is abnormal or the output does not meet expectations, click on the record to enter the details.

![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/60a254b7b2bc4d5680fd1599a7ea3bee~tplv-goo7wpa0wc-image.image)

## View single session and processes

After entering the details, you can check the information from three areas:

|Regional content |Description |Schematic diagram |
|---|---|---|
|**Session flow on the left** |To view each round of user input and agent return results, click "View More" to expand the full content. |![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/d9c8bc77d7f0454ab4cfbdc767780726~tplv-goo7wpa0wc-image.image) |
|**Processing link in the middle** |View the attachments, models, skills, context, and other nodes that a response passes through in turn. Each node displays the processing status and time consumption. ||
|**Basic information on the right** |View session rounds, duration, start time, update time, and more. ||

In the right area, you can view node input, output, metadata, and details through Input, Output, Metadata, and Details, respectively. When troubleshooting long time consumption, we should focus on comparing the time\-consuming of each node; when troubleshooting results are abnormal, we should also check the user input, node output, and final answer.

# Frequently asked questions and view methods

|Frequently asked questions |It is recommended to check the location: |Focus on content |
|---|---|---|
|How many users are using it recently? |Data Analytics \> Scenario Dashboards \> Overview or Business tab |Total users, average DAU, new users, and total sessions |
|Why does the answering process slow down? |Performance, latency views, and session link details |P99 latency, node time, and model processing time |
|Why the wrong result? |Abnormal, Trace details, and Components tab |Error rate, tool error code, node status, and output content |
|Which model is used the most? |Component tab \> Large Model Metrics |Ranking of model calls, number of calls, error rate and call duration |
