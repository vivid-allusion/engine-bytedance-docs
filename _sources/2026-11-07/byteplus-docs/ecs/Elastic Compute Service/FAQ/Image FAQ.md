### Why does the system encounter issues after I execute the yum update or yum remove command in a CentOS image?


* **yum update command**

   * Cause:

      The `yum update` command is used to update the software packages installed on the system to the latest available version. Executing this command without restrictions may cause the instance to encounter issues such as dependency conflicts, system incompatibility, or performance degradation. For example, it may result in modification of the default software repository or uninstallation of the Virtio1.1 driver.

   * Recommended solution:

      * Use the `yum update package_name` command to explicitly specify the software package name. This way, only the software that you specify is updated.

      * Use the `yum update --security` command to install only security\-related updates. This helps reduce the risk posed by feature changes.

      * Use the `yum update --exclude` command to exclude packages that you do not want to update, such as the kernel or critical libraries.

* **yum remove command**

   * Cause:

      The `yum remove` command is used to remove the specified software packages and their exclusive dependencies. For example, when you remove postfix, the virtio\-dkms module is uninstalled. This is because postfix depends on the module. As a result, the instance fails to start as expected due to the missing Virtio driver.

   * Recommended solution:

      Use the `yum remove --assumeno package_name` command to simulate the removal of the target software package and check which dependent packages will also be removed. If Virtio driver\-related modules are removed, we recommend that you manually install the Virtio driver\-related modules after the target software is removed.

### Why am I required to install the Virtio 1.1 driver?

Virtio is a standard interface that provides efficient device I/O between virtual machines and the host in the virtualization environment. According to the requirements of the BytePlus proprietary Data Processing Unit (DPU) architecture, the operating system kernel must support the Virtio1.1 protocol. When you use ECS instances based on the architecture (such as [General-purpose g3i](https://docs.byteplus.com/en/docs/ecs/General-purpose#.5qaC6L-w), [Compute-optimized c3i](https://docs.byteplus.com/en/docs/ecs/Computing-optimized#.6K6h566X5Z6LYzNp), and [Memory-optimized r3i](https://docs.byteplus.com/en/docs/ecs/Memory-optimized#uvEC2ygI)), make sure that the operating system kernel supports this protocol. Otherwise, you need to [install the Virtio1.1 driver](https://docs.byteplus.com/en/docs/ecs/Creating-Linux-images#.5a6J6KOFVmlydGlvMS4x6amx5Yqo).

<span id=".5Li65LuA5LmI6KaB5a6J6KOFYmxrLW5vbmXlt6XlhbfvvJ8="></span>
### Why do I have to install the blk\-none tool?

When you run your business that involves a large number of I/O merge operations and deep I/O request queues on ECS instances in General\-purpose (g3a/g3i), Compute\-optimized (c3a/c3i), or Memory\-optimized (r3a/r3i) types, if the kernel version of your operating system is old, I/O hang issues may occasionally occur.

The blk\-none tool provided by BytePlus sets the disk scheduling algorithm of the disk mounted on your instance to `none` or `noop` to prevent such issues. [Learn more](https://docs.byteplus.com/en/docs/ecs/blk-none).

### Why is the project to which the snapshot consistency group of the target image is associated not updated after I copy a whole image?


* **Issue description**

   When I replicate a whole image across regions and configure a project for the target image, the target image belongs to the configured project after the replication is complete. However, the project associated with the snapshot consistency group of the target image remains the same as that of the source snapshot consistency group. For example:

   The source whole image (Image_A) and the associated snapshot consistency group (SnapGroup_A) both belong to the same project `Project_a`. During cross\-region image replication, set the project of the target image to `Project_b`. After replication is complete, the target whole image (Image_B) belongs to `Project_b`, and the associated snapshot consistency group (SnapGroup_B) belongs to `Project_a`.

* **Solutions**

   You can use the [project resource management](https://docs.byteplus.com/en/docs/resourcemanagement/Project_Overview) feature to change the project of the snapshot consistency group associated with the target image to the configured project of the target image.

You cannot delete a shared custom image. You need to cancel all sharing relationships for the image before you delete the image. For more information, see [Unsharing images](https://docs.byteplus.com/en/docs/ecs/Sharing-or-canceling-sharing-image#.5Y-W5raI5YWx5Lqr6ZWc5YOP).

### What are the risks when I share a custom image with another account?

Data leakage and software leakage risks exist. Before you share an image, make sure that the image does not contain security\-related sensitive and important data and software.

<span id=".5oCO5LmI5p-l55yL5L2_55So5oiR55qE5YWx5Lqr6ZWc5YOP55qE6LSm5oi35pyJ5ZOq5Lqb77yf"></span>
### How can I view the accounts that use my shared image?

You can view information of the accounts with which your image is shared on the "Shared object" tab of the details page of the shared custom image.

<span id=".5L2_55So5YWx5Lqr6ZWc5YOP5Yib5bu65a6e5L6L5pyJ6aOO6Zmp5ZCX77yf"></span>
### What are the risks when I create instances by using a shared image?

The image owner can view the sharing relationships of the image, including your account ID, and can also delete the image.

When you use an image shared by another account, the BytePlus platform cannot ensure the security and integrity of the image. Make sure that you use images shared by trusted accounts.

<span id=".5L2_55So5YWx5Lqr6ZWc5YOP5Yib5bu65a6e5L6L5pyJ5Zyw5Z-f6ZmQ5Yi25ZCX77yf"></span>
### Are there limits on the regions in which I can create instances based on a shared image?

Yes. The region of the shared image and source image must be the same. You can use the shared image to create or reinstall ECS instances only in the region.

<span id=".5YW25LuW55So5oi35YWx5Lqr55qE6ZWc5YOP5piv5ZCm6IO95Yig6Zmk77yf"></span>
### Can I delete an image shared by another account?

No. Only the owner of the shared image can delete the shared image.

<span id=".5YyX5Lqs5Zyw5Z-f5pyN5Yqh5ZmoQeWItuS9nOeahOmVnOWDj-iDveWFseS6q-e7meS4iua1t-WcsOWfn-eahOacjeWKoeWZqELlkJfvvJ8="></span>
### Can the image created for ECS instance A in the Beijing region be shared with ECS instance B in the Shanghai region?

If the two instances belong to the same account, you can replicate the image from the Beijing region to the Shanghai region. For more information, see [Copying custom images](https://docs.byteplus.com/en/docs/ecs/Copying_custom_images).

If the two instances belong to different accounts, you can replicate the image from the Beijing region to the Shanghai region and then share the image with the account of ECS instance B. The image is displayed in the shared image list of the account of ECS instance B. For more information, see [Copying custom images](https://docs.byteplus.com/en/docs/ecs/Copying_custom_images) and [Sharing or unsharing images](https://docs.byteplus.com/en/docs/ecs/Sharing-or-canceling-sharing-image).

### What is the impact if I remove Account A from the list of accounts with which a custom image (Image M) is shared?

Account A cannot query Image M in the ECS console or by using OpenAPI, and can no longer use Image M to create ECS images or change system volumes.

### What are the advantages of veLinux compared to other operating systems?


* Service: The BytePlus platform provides an enterprise\-level Linux operating system for servers, offering long\-term service with updates at least once every four months, 24/7 dedicated customer service, and official support available through tickets and other channels.

* Security: The BytePlus platform provides rapid kernel issue resolution, data security, and General\-purpose vulnerability fixes for security assurance.

* Stability: veLinux is stably running on more than one million ECS instances deployed for ByteDance internal applications for a long period of time. The downtime rate of veLinux is 50% lower than that of open\-source Linux.

* Performance: BytePlus platform deeply integrates and optimizes the infrastructure, continuously enhancing the runtime performance of the system. Commonly used E2E application performance surpasses community Linux by more than 20%.

* Ecology: veLinux is compatible with the CentOS 7 and Debian 10 ecosystem. Most software that can run on CentOS 7 and Debian 10 can run on veLinux without or with minimal modification.

* Feature: The veLinux kernel is customized based on the LTS 5.4 version from the kernel community, with effective bug fixes and feature enhancements applied to modules including memory management, networking, I/O, and file systems.

### How does veLinux ensure data security?

veLinux ensures data security by using the following methods:


* In collaboration with the BytePlus security team, veLinux uses standard vulnerability scanning and security testing tools to perform security scans.

* veLinux assesses CVEs and patches in a timely manner and issues user security alerts and patch updates accordingly.

* veLinux regularly updates the system to fix high\-risk and critical CVEs, and updates and releases public images.
