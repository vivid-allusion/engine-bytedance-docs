This topic summarizes the types, statuses, names of, and recommended actions for currently supported events.

<span id=".6LWE5rqQ5LqL5Lu2"></span>
## Events of cloud resources

Events triggered by faults, operations, or status changes during the operation of cloud resources

<span id=".6K6h5YiS5YaF6L-Q57u05LqL5Lu2"></span>
### Scheduled operations events


|Event type |Event name  |Event |Event description and impact |Recommended action on the tenant side |
|---|---|---|---|---|
|SystemMaintenance.Redeploy |Redeployment for instances of system maintenance |* SystemMaintenance.Redeploy:Inquiring<br><br>* SystemMaintenance.Redeploy:Executing<br><br>* SystemMaintenance.Redeploy:Succeeded<br><br>* SystemMaintenance.Redeploy:Failed<br><br>* SystemMaintenance.Redeploy:Rejected<br><br>* SystemMaintenance.Redeploy:Canceled |BytePlus detected that the host machine or dedicated host of the ECS instance is in a suboptimal state, such as CPU overheating, power failure, or fan malfunction. This may cause downtime risks. |For instances without mounted local volumes<br><br><br>* **Manual authorization**<br><br>   You need to select the maintenance time slot and give permission for the redeployment of the instance onto a new host. <br><br>* **Automatic authorization**<br><br>   You need to [create a scheduled maintenance window](https://docs.byteplus.com/en/docs/ecs/Creating_scheduled_maintenance_windows) in advance to authorize BytePlus to redeploy the instance on a new host.<br><br><br><div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div><br><br><br><br>* <div data-tips="true" data-tips-type="default">If BytePlus has not obtained your permission for O&M operations, the event will be automatically canceled when there are changes to the host machine (such as type changes, power\-on, and restart). This is an automatic O&M process.</div><br><br><br>* <div data-tips="true" data-tips-type="default">The automatic cancellation (automatic O&M) is triggered only for instances of General\-purpose, Compute\-optimized, Memory\-optimized, and High Frequency families. For details, refer to the <a href="https://docs.byteplus.com/en/docs/ecs/Introduction-to-instance-types">instance type list</a>.</div><br> |

### Unexpected operation and maintenance events


|Event type |Event name  |Event |Event description and impact |Recommended action on the tenant side |
|---|---|---|---|---|
|SystemFailure.Redeploy |The instance is redeployed due to system failures |* SystemFailure.Redeploy:Failed<br><br>* SystemFailure.Redeploy:Succeeded<br><br>* SystemFailure.Redeploy:Inquiring<br><br>* SystemFailure.Redeploy:Executing<br><br>* SystemFailure.Redeploy:Canceled |It is detected that the ECS instance shut down due to failures in the host machine and dedicated host. The instance needs to be redeployed to a new host to restore normal operations. Otherwise, the instance and its services stop running. |* If the triggered event is "SystemFailure.Redeploy:Executing", no actions are required, because the instance will be automatically deployed on another host by default. You can also manually adjust the automatic maintenance mode. For detailed actions, refer to the [Querying and responding to the "Redeployment due to instances of system failure" event](https://docs.byteplus.com/en/docs/ecs/Responding-to-the-SystemMaintenance_Redeploy-event).<br><br>* If the "SystemFailure.Redeploy:Inquiring" event is triggered, [give permission to the redeployment of the instance](https://docs.byteplus.com/en/docs/ecs/Responding-to-the-SystemMaintenance_Redeploy-event). |
|SystemFailure.Reboot |System failure instance restart<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Only instances of Big Data, Local SSD, and HPC\-optimized instance type families can trigger this event. For details, refer to the <a href="https://docs.byteplus.com/en/docs/ecs/Introduction-to-instance-types">instance type list</a>.</div><br> |* SystemFailure.Reboot:Executing<br><br>* SystemFailure.Reboot:Succeeded<br><br>* SystemFailure.Reboot:Failed |A system failure on the host machine of the ECS instance is detected. The instance will be restarted to restore the running status. |If the restart fails, your permission is required to redeploy the instance. |
|SystemFailure.Stop |The instance is stopped due to system failures |* SystemFailure.Stop:Executing<br><br>* SystemFailure.Stop:Succeeded<br><br>* SystemFailure.Stop:Failed |It is detected that the ECS instance shuts down due to failures in the host machine. |No action is required. |
|FileSystemReadOnly.Change |File system became read\-only |* FileSystemReadOnly.Change:Executing<br><br>* FileSystemReadOnly.Change:Succeeded |The file system of the mounted disk of the ECS instance becomes read\-only. At this time, the disk can only be read but not written. Reasons can be disk hardware failure or system file corruption. |No action is required. |
|InstanceFailure |An operating system error instance exception |InstanceFailure:Succeeded |A kernel panic has been detected in the operating system of an ECS instance during its runtime. |We recommend that you check whether the instance exceptions exist. If no instance exception exists, no action is required on your part. If any instance exception exists, you need to [restart the instance](https://docs.byteplus.com/en/docs/ecs/Restarting-instances) manually to restore the instance normal operation.<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">For more rapid troubleshooting of kernel crashes in the instance, we recommend that you enable the Kdump service for the operating system:</div><br><br><br><br>* <div data-tips="true" data-tips-type="tip"><a href="https://docs.byteplus.com/en/docs/ecs/Enabling_Kdump_service_in_Linux_operating_system">Enabling Kdump service in Linux operating system</a></div><br><br><br>* <div data-tips="true" data-tips-type="tip"><a href="https://docs.byteplus.com/en/docs/ecs/Enable_kernel-mode_dump_in_the_Windows_operating_system">Enabling kernel\-mode dump in the Windows operating system</a></div><br> |
|GpuRiskDetected |GPU risk detected<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Only GPU Accelerated and HPC\-optimized instance type families can trigger this event. For details, refer to the <a href="https://docs.byteplus.com/en/docs/gpu/Instances">instance type list</a>.</div><br> |GpuRiskDetected.Succeeded |An exception has been detected in your running GPU instance, or an exception is predicted. You need to restart the instance to restore the normal instance operations.<br><br><div data-tips="true" data-tips-type="default" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="default">If the instance is not restarted, it may lead to downtime or performance exceptions, which could impact your business continuity.</div><br><br><br> |You need to restart the instance manually. |
|DiskErrorDetected |Hard disk exception<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Only instances of Big Data, Local SSD, EBM mounted with local volumes, and Heterogeneous Compute\-optimized (GPU and HPC) instance type families can trigger this event. For details, refer to the <a href="https://docs.byteplus.com/en/docs/ecs/Introduction-to-instance-types">instance type list</a>.</div><br> |* DiskErrorDetected:Inquiring<br><br>* DiskErrorDetected:Succeded<br><br>* DiskErrorDetected:Canceled |Exceptions are detected in the hard disk of the Local SSD instances and cause exceptions for read and write operations. You need to give permission to the redeployment of the instance to a new host or replacement of the hard disk. Otherwise, the instances stop running. |You need to give permission for the redeployment of the instance or replacement of the volume with exceptions. For details, refer to the [Local volume event O&M](https://docs.byteplus.com/en/docs/ecs/Local-volume-event-auto-maintenance). |
|DiskError.Redeploy |Instance redeployment due to hard disk failure<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">After you grant permission on instance redeployment, this event is generated.</div><br> |* DiskError.Redeploy:Executing<br><br>* DiskError.Redeploy:Succeeded<br><br>* DiskError.Redeploy:Canceled |Due to hardware or software failures in the hard disk of Local SSD instances, Byteplus is deploying the instances with exceptions onto new hosts to restore the normal operation of the instances. |No action is required. |
|DiskError.ReplaceDisk |Hard disk replaced due to exception<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">After you grant permission on the replacement of the faulty hard disk, this event is generated.</div><br> |* DiskError.ReplaceDisk:Executing<br><br>* DiskError.ReplaceDisk:Succeeded<br><br>* DiskError.ReplaceDisk:Failed<br><br>* DiskError.ReplaceDisk:Canceled<br><br>* DiskError.ReplaceDisk:Pending |Due to hardware or software failures in the hard disk of Local SSD instances, BytePlus is replacing the faulty hard disk with a new one for instance normal operations. |No action is required. |
|InstanceOOM |Instance memory OOM |InstanceOOM:Succeeded |The OOM is detected in ECS instance memory. |No action is required. |
|InstanceFileSystemFailure.StopAndRepair |Downtime repair due to file system exception<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">Currently, only Windows instances can trigger this event.</div><br> |* InstanceFileSystemFailure.StopAndRepair:Inquiring<br><br>* InstanceFileSystemFailure.StopAndRepair:Canceled<br><br>* InstanceFileSystemFailure.StopAndRepair:Execting<br><br>* InstanceFileSystemFailure.StopAndRepair:Failed<br><br>* InstanceFileSystemFailure.StopAndRepair:Succeed<br><br>* InstanceFileSystemFailure.StopAndRepair:Rejected |It is detected that file system exceptions occur due to the damaged system volume of the instance. This may cause startup issues or connection failures. |You need to select a maintenance time slot and give permission to Byteplus for shutdown repair operations. For details, refer to [Authorized shutdown repair](https://docs.byteplus.com/en/docs/ecs/File-system-exception-shutdown-repair-operation-and-maintenance-description).<br><br><div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div><br><br><br><div data-tips="true" data-tips-type="tip">After the instance enters the repair status, the instance status is <strong>MAINTENING</strong>, and you can not start the instance, replace the system volume, initialize the system volume, or change the specification.</div><br> |
|InstanceDiskStalled |Seriously impaired disk performance for instance |* InstanceDiskStalled.Executing<br><br>* InstanceDiskStalled.Succeeded |On the mounted volume of the ECS instance, IO congestion occurs. This may severely impact volume performance and thereby effect normal read/write operations. |We recommend that you isolate read and write operations to the volume at the application level or temporarily remove the instance from the load balancer list. |

### Fee warning events


|Event type |Event name  |Event |Event description and impact |Recommended action on the tenant side |
|---|---|---|---|---|
|AccountUnbalanced.Stop |Instance stopped due to account arrears |* AccountUnbalanced.Stop:Executing<br><br>* AccountUnbalanced.Stop:Succeeded |The pay\-as\-you\-go instance will stop in 1 hour because the associated account is in arrears. |We recommend you to recharge your account in time for renewal. |
|AccountUnbalanced.Delete |Instance released due to account arrears |* AccountUnbalanced.Delete:Executing<br><br>* AccountUnbalanced.Delete:Succeeded |The pay\-as\-you\-go instance will be released in 3 hours because the associated account is in arrears. |We recommend you to recharge your account in time for renewal. |
