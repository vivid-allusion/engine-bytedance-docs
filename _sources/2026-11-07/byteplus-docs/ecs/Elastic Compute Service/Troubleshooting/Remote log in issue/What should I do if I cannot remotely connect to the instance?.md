If you are unable to log in to or connect to your instance, troubleshoot the issue by checking the items in the following table one by one.

<span id=".5o6S5p-l5oCd6Lev"></span>
## Troubleshooting approach


|Troubleshooting item ||Description |Solution |
|---|---|---|---|
|Resource status |Check whether the resource status is normal. |You can only log in to instances in the **Running** status. |Check whether the instance status is **Running**. For more information, see [Viewing instance information](https://docs.byteplus.com/en/docs/ecs/Instance-overview-1).<br><br>If the instance status is **Stopped**, [start the instance](https://docs.byteplus.com/en/docs/ecs/Starting-instances) and log in to it. |
|Login password |Check login credentials. |When you log in to an instance, make sure that the login credentials (username, password/key) you enter are the same as those specified during instance creation. |* Username: The default username of the Linux instance is root. [Why am I unable to log in to an instance by using the root account?](https://docs.byteplus.com/en/docs/ecs/Logon-and-connection-FAQs#.5Li65LuA5LmI5peg5rOV5L2_55Socm9vdOeUqOaIt-eZu-W9leWunuS-i--8nw==)<br><br>* Password: If you log in by using a password, make sure that the password is correct. If you forget your password, you can [reset the login password](https://docs.byteplus.com/en/docs/ecs/Resetting-passwords) for your instance.<br><br>* Key pair: Upload the key pair associated with the instance. You can [view the key pairs that have already been associated with an instance](https://docs.byteplus.com/en/docs/ecs/Viewing-key-pairs-bound-to-instances) on the instance details page or the key pair list page. |
|Login port |Check whether the security group configuration is correct. |To log in to a Linux instance, you need to open the default TCP port 22. |In the ECS console, click the name of the instance you cannot log in to to go to the instance details page, select the "Security Group" tab, and make sure that port 22 is added to the inbound rules of a security group associated with the instance.<br><br>If the port is not added, [modify the security group access rules](https://docs.byteplus.com/en/docs/ecs/Modifying-security-group-rules). |
||Check whether the configuration of the firewall is correct. |Check whether the internal firewall (iptables, firewalld) of the ECS instance is blocking SSH (port 22). |If the instance has the firewall enabled and has configured rules to block external access, remote login to the instance may fail.<br><br>[How do I configure the firewall for a Windows ECS instance?](https://docs.byteplus.com/en/docs/ecs/Security-FAQs#.5aaC5L2V6YWN572uIFdpbmRvd3Mg5LqR5pyN5Yqh5Zmo6Ziy54Gr5aKZ77yf)<br><br>[How do I configure the firewall for a Ubuntu ECS instance?](https://docs.byteplus.com/en/docs/ecs/Security-FAQs) |
|Resource overload |Check whether Internet bandwidth exceeds the upper limit. |If the Internet bandwidth upper limit is exceeded, you may fail to log in to the instance. |Check whether Internet bandwidth exceeds the upper limit. For more information, see [Checking Internet bandwidth upper limit of instance](https://docs.byteplus.com/en/docs/ecs/Instance-overview-1#.5p-l55yL56S65L6L) and [Checking Internet bandwidth usage](https://docs.byteplus.com/en/docs/ecs/Monitoring-FAQs#.5aaC5L2V5p-l55yL5a6e5L6L55qE5bim5a6955So6YeP77yf).<br><br>For information about how to increase bandwidth, see [Modifying the maximum bandwidth](https://docs.byteplus.com/en/docs/eip/Modifying-the-maximum-bandwidth). |
||Check whether CPU or memory load is too high. |High CPU or memory usage on an instance may prevent users from logging in to it. |If you have already [created an alert task](https://docs.byteplus.com/en/docs/ecs/Collecting-alerts-triggered-by-ECS-metrics) by using the Cloud Monitor service, the system will automatically send you an alert when CPU or memory usage is too high.<br><br>You can upgrade vCPU and memory by [changing the instance type](https://docs.byteplus.com/en/docs/ecs/Overview-2). |
|Network configuration |Check whether an EIP is associated with the instance. |To use third\-party remote login tools such as PuTTY or XShell to log in to an instance, an EIP must be associated with the instance. |For information about how to view the EIPs associated with an instance, see [Viewing instance information](https://docs.byteplus.com/en/docs/ecs/Instance-overview-1).<br><br>If no EIP is associated with the instance, associate one with the instance. For more information, see [Associating EIPs](https://docs.byteplus.com/en/docs/ecs/associating-an-EIP). |
||Check whether the local network works as expected. |Determine whether the login failure is caused by a local network failure. |Try logging in to the instance from a local host in another network environment, or switch to a mobile hotspot to test access.<br><br>For local network operator issues, we recommend that you contact the network operator. |
|Remote connection tools |Check whether SSH is enabled on Linux. |Check whether SSH is disabled inside the Linux instance. |To connect to Linux via Remote Desktop using the ECS Terminal or third\-party tools, [enable SSH](https://docs.byteplus.com/en/docs/ecs/Enable-SSH-on-Linux-instance). |
||Check whether RDP is enabled in Windows. |Check whether RDP is disabled inside the Windows instance. |When you use the ECS Terminal or third\-party tools to connect to Windows via Remote Desktop, you need to [enable Remote Desktop Protocol (RDP)](https://docs.byteplus.com/en/docs/ecs/Method_for_enable_Remote_Desktop_Connection_RDP_service_for_Windows_system_instances). |
|Internal operating system issues |Check whether the login failure is caused by internal reasons of the instance operating system. |Determine whether the login failure is caused by file system corruption or similar reasons. |* Password injection failed: The most common reason for password retrieval failure is a Cloud\-init password injection failure. Submit a ticket to resolve this issue.<br><br>* After a forced shutdown due to file system corruption: There is a small chance that the file system corruption may persist or reoccur, causing the ECS instance to fail to start again. Try using the `fsck` command to repair the file system. |
|Submit a ticket |Check whether there are any error messages for remote login. |To address error messages during remote connection, check the SSH configuration based on the prompt. |Refer to the [troubleshooting documentation](https://docs.byteplus.com/en/docs/ecs/Remote-log-in-issue) to check for relevant solutions. If none of the content matches your error message, go to the console, click "Support \> Create ticket" in the top menu bar, and fill in the ticket information to obtain technical support. |


If you still cannot log in to the ECS instance after the preceding troubleshooting, submit a ticket to obtain technical support.
