<span id="self-adaptation"></span>
### Self\-adaptation

The self\-adaptation layout follows the following rules:


* The specific layout will be selected according to the number of people, following the above diagram. When the number of people does not reach the maximum number applicable to the layout, the vacant window will display the background color.

* Users who only send audio will still occupy the window on the overall layout, and the window will display the background color.

* If the aspect ratio of the actual video stream does not match the aspect ratio of the window, the video is automatically cropped to fit the size of the window.

<span id="vertical-layout"></span>
### Vertical layout

The vertical layout follows the following rules:


* For the main window:

   * If there is no specified user or the specified user has not entered the channel, the main window displays the background color.

   * If the aspect ratio of the actual video stream does not match the aspect ratio of the window, the window will be scaled to ensure the integrity of the video.

* For small windows:

   * The small windows are arranged according to the order of joining. If a user quits the channel, the following users will occupy the window of the previous users and replace them in turn.

   * If the aspect ratio of the actual video stream does not match the aspect ratio of the window, the video is cropped to fit the size of the window.

   * When the number of people does not reach the maximum number applicable to the layout, the vacant window will display the background color.

   * Users who only send audio will still occupy the window on the overall layout, and the window will display the background color.

<span id="location-x-and-location-y"></span>
#### Location X and Location Y

The actual coordinates of the upper left corner of the corresponding area of the video stream are obtained by multiplying the picture size and normalized scale and rounding. Suppose, `Canvas. Width = 1920, Region. LocationX = 0.33`, then the abscissa of the upper left corner of the canvas is `634`(1920\*0.33=633.6 rounded).

<span id="location-x-and-location-y"></span>
#### WidthProportion and HeightProportion

The pixel values of the width and height of the area corresponding to the video stream are multiplied by the picture size and the normalized proportion, rounded, and converted upwards to an even number. Suppose, `Canvas. Width = 1920, Region. WidthProportion = 0.21`, then the lateral width of the canvas is `404px`(1920\*0.21=403.2, rounded up and converted up to an even number).

<span id="widthproportion-and-heightproportion"></span>
#### AlternateImage:


1. If the video stream corresponding to the `Region. StreamIndex`is not published, or suspended, the image corresponding to `AlternateImage`will fill the canvas space corresponding to the `Region`. When the video stream is captured and published, `AlternateImage`does not cause any impact.

2. The formats that can be uploaded include: JPG, JPEG, PNG.

3. When the size of the picture and the canvas do not match, the picture will be rendered in the canvas according to the settings of RenderMode.

Add frame: The frame rate of the video is usually fixed when audio & video is recorded or transcoded. However, due to network fluctuations or other reasons, the actual frame rate may not reach the preset frame rate. At this time, it is necessary to add frames to keep the video smooth. Adding the last frame means that the supplementary video frame is the same as the last frame before the interruption, and the picture seen at this time may be temporarily still. Completing black frames means that the supplementary video frames are all black.

Redundant segment The server segments by the fixed `Duration`, so there may be cases where sensitive words are truncated or unrecognized. In such cases, you can add a redundant segment which is the end of the previous segment, and the duration of the segment will be `RedundantDuration`+ `Duration`.

For example, when `Duration`= `20` and `RedundantDuration`= `3`, the duration of final output files are: [0\-20], [17\-40], [37\-60].

<span id="redudant"></span>
#### Note1

`Align`is the switch to enable alignment, whose default value is `False`. You can use this function to align the starttime and endtime of each user's segmented file.

When `Align = False`, this function is turned off. In the duration of a segment, if the user publishes audio streams, a segment will be generated. If the user does not publish streams in a part of the time during the duration, the duration of a file will be less than the duration set. The start time of all files may not be the same.

When `Align = True`, this function is turned on. In the duration of a segment, if the user publishes audio streams, a segment will be generated. The duration of a file is equal to the set value, and the start time of all files is the same. If the user does not publish streams in a part of the time during the duration, and the duration of a file remains the same, silent part will be included in the file. However, if the user does not publish audio during the whole duration, no file will be generated.

<span id="note11"></span>
#### Note2

 &nbsp;

'Mixed' is a switch to enable mixing\-stream segment, whose default value is `False`.


* When `Mixed = False`, only the audio streams specified in `TargetStreams` will be segmented separately.

* When `Mixed = True`, the audio streams specified in `TargetStreams` will be segmented separately, and the specified audio streams will also be mixed to generate a file, and the username of the mixing\-stream file is `mixed`. After the task is created, callbacks for the mixed\-stream segment will continue to be triggered regardless of whether someone is publishing audio.
