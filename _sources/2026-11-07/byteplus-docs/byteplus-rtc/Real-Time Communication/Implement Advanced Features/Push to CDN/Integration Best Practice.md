You can refer to the following best practices to get the best results from Push to CDN.

<span id="sei-type"></span>
### **SEI Type**

SEI (Supplemental Enhancement Information) that clients receive from the live stream is categorized into two types: RTC passthrough SEI and server\-side merged SEI:


* RTC passthrough SEI:

   * Definition: This is the SEI data sent by the client via the sendSEIMessage API. The server subscribes to the user's stream, extracts the SEI from the video frame, and then passes it through without modification. The data structure is defined by the user.

   * Trigger conditions: After the transcoding bot on the server\-side receives the user's video stream, it immediately encodes the information into the next video frame (normal video frame/key frame).

* Server\-side merged SEI:

   * Definition: A specific SEI generated by the merge and push server\-side. The data structure is defined by BytePlus.

   * Trigger conditions: This SEI information follows each I frame by default. If the user has enabled volume indicator mode, the SEI information may be encoded into a normal video frame. If the passthrough client\-side passes an SEI, the server\-side will also generate an SEI.


<span id="server-side-merge-and-push-sei-structure"></span>
### **Server\-side merge and push SEI structure**

The server\-side will add encoding information about the current video stream in the SEI by default in Push to CDN and recording scenarios. The information is a JSON\-formatted string, as shown below:

```json
{
    "app_data": "Your_AppData",
    "canvas": {
        "bgnd": "#ff0000",
        "h": 480,
        "w": 640
    },
    "infos": [
        {
            "talk": 0,
            "uid": "Your_UserId_1",
            "volume": 10
        },
        {
            "talk": 0,
            "uid": "Your_UserId_2",
            "volume": 20
        }
    ],
    "regions": [
        {
            "alpha": 1.0,
            "contentControl": 0,
            "h": 1.0,
            "renderMode": 2,
            "uid": "Your_UserId_1",
            "w": 0.5,
            "x": 0.0,
            "y": 0.0,
            "zorder": 0
        },
        {
            "alpha": 1.0,
            "contentControl": 0,
            "h": 1.0,
            "renderMode": 2,
            "uid": "Your_UserId_2",
            "w": 0.5,
            "x": 0.5,
            "y": 0.0,
            "zorder": 1
        }
    ],
    "ts": 1687920756747
}
```


The parameters are defined as follows:


|**Parameter** |**Description** |
|---|---|
|canvas |Canvas information. The returned information depends on the parameters passed in at the start of the OpenAPI task. The parameter information of the canvas is as follows:<br><br><br>* `w`: The width of the canvas, corresponding to Canvas.Width.<br><br>* `h`: The height of the canvas, corresponding to Canvas.Height.<br><br>* `bgnd`: The background color of the canvas, formatted as a hexadecimal integer defined in RGB, corresponding to Canvas.Background. |
|regions |The information of all merge users (including layout information). The data returned depends on the parameters passed in when the OpenAPI task is started. `Alpha`: The transparency of the image, corresponding to `Region.Alpha`. `contentControl`: The media type of the stream in the mixed stream, corresponding to `Region.MediaType`. `w`: The normalized width of the user's view, ranging within [0.0, 1.0]. The default value is 1.0. We recommend setting this value, corresponding to `Region.`**`WidthProportion`**. `h`: The normalized height of the user's view, ranging within [0.0, 1.0]. The default value is 1.0. We recommend setting this value, corresponding to `Region.`**`HeightProportion`**. `x`: The normalized horizontal coordinate of the top\-left corner of the user's view, ranging within [0.0, 1.0). The default value is 0.0. We recommend setting this value, corresponding to `Region.LocationX`. `y`: The normalized vertical coordinate of the top\-left corner of the user's view, ranging within [0.0, 1.0). The default value is 0.0. We recommend setting this value, corresponding to `Region.LocationY`. `renderMode`: The rendering mode of the image, corresponding to `Region.RenderMode`. `uid`: The ID of the user who owns the stream, corresponding to `Streams.Stream.UserId`. `zorder`: The layer order of the image, corresponding to `Region.Zorder`. |
|infos |Volume information. Only when the volume indicator mode is enabled will this field be returned. uid: The ID of the user who owns the stream. talk: Whether the user spoke. `0` indicates that the user's actual volume does not exceed the setting value of `TalkVolume`. `1` indicates that the user's actual volume exceeds the setting value of `TalkVolume`. volume: The actual volume of the user, with a range of `[0, 255]`. |
|ts |The Unix timestamp (msec) when this information is generated. |
|app_data |Custom information. The UserConfigExtraInfo field passed in by the user in `Control`. |

### **Volume Indicator Mode**

In Push to CDN scenarios, you may need to enable volume indicators to implement some business logic, such as displaying real\-time sound wave effects of a host on the viewer client\-side.

Step 1: Set `VolumeIndicationMode` to `true` to enable the volume indicator mode.

Step 2: Set the callback interval for the user's speaking volume through `VolumeIndicationInterval`.

Step 3: [Optional] Set the effective speaking volume through `talkVolume`.

Step 4: Parse the `infos` field in the server\-side merged SEI to obtain the user's volume information.

After the volume indicator mode is enabled, you can choose to carry different SEI information in non\-key frames by setting `SeiContentMode` and `AddVolumeValue`, but key frames will carry the complete SEI information.


* If `SeiContentMode =`ByteRTCMixedStreamSEIContentModeDefault(0) and `AddVolumeValue = false`, the SEI does not include user speaking volume information, but all other standard information is present.

<span id="set-sei-payloadtype"></span>
### **Set SEI PayLoadType**

You can set the `PayLoadType` of SEI information to `5` or `100` to be compatible with your client player. The default value is `100`. During the push to CDN, the parameter cannot be changed.


* If you set the `SEIPayLoadType` parameter, it applies to both server\-side merged SEI and RTC passthrough SEI.
