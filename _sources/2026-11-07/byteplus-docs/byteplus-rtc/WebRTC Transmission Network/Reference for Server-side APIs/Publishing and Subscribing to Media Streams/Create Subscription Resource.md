To subscribe to a media stream on the WebRTC\-based Transport Network (WTN), you must first create a subscription resource.

For more information on subscription resources, refer to [Set Publishing and Subscription Configurations](https://docs.byteplus.com/docs/byteplus-rtc/docs-1553594).

<span id="usage-instructions"></span>
## Usage Instructions

<span id="api-behavior"></span>
### API Behavior

By calling this API, you send an SDP Offer to the WTN server. If the call is successful, the WTN server creates subscription resources and returns an SDP Answer to the client.

<span id="subscription-authentication"></span>
### Subscription Authentication

Subscription authentication is configured using the token provided when creating publishing resources. For detailed settings, refer to [Authentication](https://docs.byteplus.com/docs/byteplus-rtc/132442).

<span id="prerequisites"></span>
### Prerequisites

Before creating subscription resources, you must first create the corresponding publishing resources; otherwise, you will receive a `404` response code. For information on how to create publishing resources, refer to [Create Publishing Resource](https://docs.byteplus.com/docs/byteplus-rtc/132482).

<span id="request-description"></span>
## Request Description


* Request Method: **POST**

* Request URL: `<Domain Name>/sub/<AppID>/<StreamID>`

> Refer to [API Request Domain Name](https://docs.byteplus.com/docs/byteplus-rtc/wtn-domain) for `URL`.


<span id="request-parameters"></span>
## **Request Parameters**

<span id="path"></span>
### Path


|Parameter |Type |Required |Example Value |Description |
|---|---|---|---|---|
|AppID |String |Yes |`Your_AppId` |Application ID. Get this from the WTN console. |
|StreamID |String |Yes |`Stream123` |Stream ID. This must match the StreamID used when creating the publishing resource. |


<span id="header"></span>
### Header


|Parameter |Type |Required |Example Value |Description |
|---|---|---|---|---|
|Content\-Type |String |Yes |`application/sdp` |Request content type. Fixed value: `application/sdp` |
|Authorization |String |Yes |`{TokenType} {Token}` |Set this parameter only when subscription authentication is enabled.<br><br><br>* `TokenType`: Fixed value: `Bearer`.<br><br>* `Token`: See [Authentication](https://docs.byteplus.com/docs/byteplus-rtc/132442). |
|Feedback\-<br><br>Info |String |No |/ |Information about the media server node.<br><br>If the created `PeerConnection` returns `RTCPeerConnection.connectionState == failed`, which means the ICE connection failed, you can call this API again to create a publishing resource. Populate this field with the `Feedback-Info` from the header and the `ClientID` from the query of the previous response. The server will automatically switch to a different media server node. For more information, see [Building a Basic Application](https://docs.byteplus.com/docs/byteplus-rtc/132450). |


<span id="query"></span>
### Query


|Parameter |Type |Required |Example Value |Description |
|---|---|---|---|---|
|BusinessID |String |No |www\-byteplus\-com |A custom identifier used to uniquely identify a business within the same AppId.<br><br><br>* Must be unique within the same AppId.<br><br>* Maximum length of 64 characters.<br><br>* Allowed characters: numbers, letters, `_`, `-`, `@`, and `.`. |
|SessionID |String |No |`Session123` |An ID generated by the client for troubleshooting. |
|MuteAudio |Bool |No |`false` |Whether to subscribe to audio data.<br><br><br>* `true`: Do not subscribe to audio data;<br><br>* `false`: Subscribe to audio data.<br><br><br>Default is `false`. |
|MuteVideo |Bool |No |`false` |Whether to subscribe to video data.<br><br><br>* `true`: Do not subscribe to video data;<br><br>* `false`: Subscribe to video data.<br><br><br>Default is `false`. |
|ClientIP |String |No |`192.0.2.1` |The client's public IP address (IPv4 or IPv6). The WTN server uses this address to allocate the optimal media server node for the client.<br><br>Defaults to the source IP address of the HTTP request. |
|RID |String |No |`High` |The RTP Stream ID of the Simulcast media stream published using the WebRTC protocol.<br><br>You can use this parameter to subscribe to a specific stream among multiple Simulcast media streams. If this parameter is omitted, the client subscribes to the highest\-quality Simulcast stream by default.<br><br><br>* If the publisher's RID changes, the original subscriber will be disconnected and must re\-subscribe to receive the newly published stream;<br><br>* If the publisher publishes a new media stream using the same RID, the original subscriber will not be disconnected and can receive the newly published stream without re\-subscribing. |


<span id="body"></span>
### Body


|Parameter |Type |Required |Example Value |Description |
|---|---|---|---|---|
|data\-raw |String |Yes |`<SDP Offer>` |The SDP Offer to send to the server. |

<span id="request-example"></span>
## Request Example

```Plain
curl --location --request POST 'https://wtn.rtcplus.com/sub/<AppID>/<StreamID>'  \
--header 'Authorization: Bearer <Token>' \
--header 'Content-Type: application/sdp' \
--data-raw '<SDP Offer>'
```

## Return Example


<span id="follow-up-actions"></span>
### Follow\-up Actions

When creating subscription resources and starting to subscribe, note:


* If you do not start subscribing within 15 seconds of creating a subscription resource, it is deleted and you must create it again;

* If multiple clients need to subscribe to the same publishing resource, you must create a separate subscription resource for each client.


Connecting to a subscription resource does not guarantee that you will receive audio and video streams. You can only receive audio and video streams when the publishing client publishes them.
