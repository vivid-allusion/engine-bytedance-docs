To publish a local media stream to WTN and subscribe to another stream simultaneously, you must first call this API to create a publish\-subscribe resource.

This endpoint initiates the WebRTC negotiation by sending an SDP Offer to the WTN server. Upon successful creation of the resource, the server returns an SDP Answer, which is essential for establishing the peer connection for media streaming.

> For publish\-subscribe resources, see [Publish Resource and Subscription Resource](https://docs.byteplus.com/docs/byteplus-rtc/132443).


<span id="precautions"></span>
## Precautions


* If the connection is not established within 30 seconds after the publish\-subscribe resource is created, the publish\-subscribe resource will be deleted, and you must create the publish\-subscribe resource again.

* If a connection has been established, but the connection to the publish\-subscribe resource is disconnected due to network abnormalities or other reasons, and the connection is not re\-established for more than 30 seconds, the publish\-subscribe resource will be deleted.

* If the subscribed stream does not exist for 15s, the server will disconnect.

* If a publish\-subscribe resource with the same AppID, PubStreamID, and SubStreamID has been created before creating the publish\-subscribe resource, the previous publish\-subscribe resource will be cleared, the client cannot establish a connection with the previous publish\-subscribe resource, and the established connection will be disconnected.


<span id="request-description"></span>
## Request Description


* Request method: **POST**

* Request address: **`https://wtn.rtcplus.com/webrtc/pub-sub/<AppID>/<PubStreamID>/<SubStreamID>`** 


<span id="request-parameters"></span>
## Request Parameters

<span id="path"></span>
### Path


|Parameter |Type |Required |Example Value |Description |
|---|---|---|---|---|
|AppID |String |Yes |`Your_AppId` |Application ID. Get it on the WTN console. |
|PubStreamID |String |Yes |`PubStream123` |ID of the stream to be published. Custom value, only supports numbers + letters, up to 64 characters. |
|SubStreamID |String |Yes |`SubStream123` |ID of the stream to be subscribed to. Custom value, only supports numbers + letters, up to 64 characters. |


<span id="header"></span>
### Header


|Parameter |Type |Required |Example Value |Description |
|---|---|---|---|---|
|Content\-Type |String |Yes |`application/sdp` |Request content type. Fixed value: `application/sdp`. |
|Authorization |String |Yes |`{TokenType} {Token}` |Authorization information.<br><br><br>* `TokenType`: Fixed value: `Bearer`.<br><br>* `Token`: See [Authentication](https://docs.byteplus.com/docs/byteplus-rtc/132442). |
|Feedback\-Info |String |No |/ |Media server node related information. If the created PeerConnection returns `RTCPeerConnection.connectionState == failed` this time, that is, the ICE connection fails, you can fill in the value of `Feedback-Info` in the `Header` of the response of the last call to this interface and `ClientID` in the `Query` to call this interface again to create a publish\-subscribe resource, and the server will automatically switch media server nodes.<br><br><div data-tips="true" data-tips-type="default" data-tips-is-title="true">Tip</div><br><br><br><div data-tips="true" data-tips-type="default">When using this parameter, you do not need to pay attention to the content in this field, just pass in the <code>Feedback-Info</code> value returned from the last request.</div><br> |


<span id="query"></span>
### Query


|Parameter |Type |Required |Example Value |Description |
|---|---|---|---|---|
|SessionID |String |No |`Session123` |ID generated by the client for log investigation. |
|ClientIP |String |No |`192.0.2.1` |The public IP address of the client (IPV4 or IPV6). The WTN server will assign the best media server node for the client according to it, it is recommended to carry it.<br><br>The default value is the IP that initiates the HTTP request. |
|ClientID |String |No |`Client123` |Client ID, used to identify a user.<br><br><div data-tips="true" data-tips-type="default" data-tips-is-title="true">Tip</div><br><br><br><div data-tips="true" data-tips-type="default">It is recommended to fill in the client ID in every request for log investigation.</div><br> |
|PubMuteAudio |Bool |No |`false` |Whether to publish audio data.<br><br><br>* `true`: Do not send audio data.<br><br>* `false`: Send audio data.<br><br>   The default value is `false`. |
|PubMuteVideo |Bool |No |`false` |Whether to publish video data.<br><br><br>* `true`: Do not send video data.<br><br>* `false`: Send video data.<br><br>   The default value is `false`. |
|SubMuteAudio |Bool |No |`false` |Whether to subscribe to audio data.<br><br>`true`: Do not subscribe to audio data.<br><br><br>* `false`: Subscribe to audio data.<br><br>   The default value is `false`. |
|SubMuteVideo |Bool |No |`false` |Whether to subscribe to video data.<br><br><br>* `true`: Do not subscribe to video data.<br><br>* `false`: Subscribe to video data.<br><br>   The default value is `false`. |


<span id="body"></span>
### Body


|Parameter |Type |Required |Example Value |Description |
|---|---|---|---|---|
|data\-raw |String |Yes |`<SDP Offer>` |Send SDP Offer to the server |

<span id="request-example"></span>
## Request Example

```Plain
curl --location --request POST 'https://wtn.rtcplus.com/webrtc/pub-sub/<AppID>/<PubStreamID>/<SubStreamID>' \
--header 'Authorization: Bearer <Token>' \
--header 'Content-Type: application/sdp' \
--data-raw '<SDP Offer>'
```


<span id="return-example"></span>
## Return Example

```Plain
<SDP Answer>
```
