This document introduces the basic concepts of BytePlus Global Traffic Management (GTM).

<span id="address"></span>
## Address

An address is the destination address of traffic routing. An address can be included in multiple pools.

An address is typically an IP address or domain name of a data center. IP address types can be IPv4 or IPv6. A domain name usually represents a resource address, like a website domain, a load balancer CNAME, or a CDN CNAME.

<span id="pool"></span>
## Pool

A pool contains one or more addresses. A pool can be included in multiple pool sets.

In the capacity routing mode of intelligent routing policy, a pool has a capacity attribute.

In the basic routing policy or capacity routing mode of intelligent routing, addresses in the pool have weight or capacity attributes. You can set the flow of traffic among addresses in the pool through weights, achieving address\-level traffic routing. For instance, you can manage addresses from the same ISP in one pool, adding remarks to record its business attributes.

The pool is only used for the classification of addresses. BytePlus GTM does not determine the availability of the pool.

<span id="pool-set"></span>
## Pool set

A pool set contains one or multiple pools. A pool set can only be included by one rule. A rule may contain multiple pool sets.

In a rule, only one pool set can be active. BytePlus GTM routes user requests only to the addresses in the active pool set.

The pool set has a threshold for the number of available addresses. When the number of available addresses is below this threshold, the pool set is considered unavailable. The default threshold is 1, meaning that the pool set is available as long as there is at least one available address.

For the ultimate edition GTM instances, the pools in a pool set have a weight attribute. You can set the flow of traffic among the pools in the pool set through weights, achieving pool\-level traffic routing.

<span id="rule"></span>
## Rule

Rules define how user traffic is routed to addresses.

A rule includes a line, one or more associated pool sets, and the weight configuration related to the line. A rule may contain multiple pool sets.

A rule can contain multiple pool sets, but only one pool set can be effective at a time. Pool sets take effect in ascending order of priority. If the currently active pool set fails and becomes unavailable, BytePlus GTM will automatically switch to an available pool set under the same rule according to priority.

The same line can be included in multiple rules. At the same time, rules have a weight attribute, and for different rules with the same line, traffic can be allocated through the weight of the rules.

The logic of traffic routing is as follows:


* For multiple lines, the line with finer granularity has a higher priority. For example, `China - Telecom - Shanghai`, `China - Telecom`, and `Default` are lines with granularity from fine to coarse.

* For a certain line, traffic is routed according to the weight of each rule that includes that line.

* For a specific rule, traffic is routed according to the weight of the addresses within that rule.


Under the intelligent routing policy, rules are automatically generated by BytePlus GTM. Generally, you do not need to manually add them. If you need to customize rules, you can also create rules under an intelligent routing policy. The priority of your created rules is higher than that of the automatically generated ones.

<span id="gtm-instance"></span>
## GTM instance

A GTM instance includes the configuration to route user requests for your domain. One GTM instance corresponds to one domain. You need to configure a policy for each GTM instance.

The following diagram shows the hierarchical structure of a GTM instance:


* Each GTM instance includes a policy.

* Each policy includes one or multiple rules.

* Each rule includes one or multiple pool sets.

* Each pool set includes one or multiple pools. A pool can be included in multiple pool sets.

* Each pool includes one or multiple addresses. An address can be included in multiple pools.

<span id="policy"></span>
## Policy

A policy defines the overall routing logic of user requests for a GTM instance. Only one policy can take effect in a GTM instance. BytePlus GTM supports basic routing and intelligent routing policies:


* **Basic routing**: A routing policy based on geographical location. You need to manually create rules.

* **Intelligent routing**: A routing policy based on latency, and capacity. BytePlus GTM automatically generates rules. You can set the intelligent routing policy to any of the following routing modes:

   * **Performance**: When a user sends a DNS query to a recursive DNS server, BytePlus GTM will return the address with the lowest access latency to the user.

   * **Capacity**: When a user sends a DNS query to a recursive DNS server, BytePlus GTM will return the address with the lowest user access latency while meeting the capacity constraints of the address.


<span id="target"></span>
## Traffic target

You need to configure traffic targets for the intelligent routing policy. Traffic targets can include one or several address pools in a GTM instance.

Under the intelligent routing policy, GTM instances generate rules automatically based on the traffic targets.

<span id="7e2fd2fd"></span>
## Routing domain

The CNAME domain used to connect your domain to BytePlus GTM.

<span>![图片](https://sf16-resources.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/upload_31719edc4251ce8183b3ce8f30ec9636.jpeg) </span>

When creating a GTM instance, if you set the **Connection method** to **CNAME**, after entering the domain name, you'll need to select a suffix for the routing domain. The suffix of the routing domain can only be a second\-level domain that you have hosted in BytePlus DNS. BytePlus GTM will automatically generate the corresponding routing domain in the **Routing domain** field based on the domain name you entered and the routing domain suffix you selected. For example, if the domain name you entered is `example.com` and the selected routing domain suffix is `byteplus.com`, then the routing domain automatically generated by BytePlus GTM will be `example.com.byteplus.com`. You need to add a CNAME record at your DNS service provider to point your domain to the routing domain of the GTM instance.

If the **Connection method** is **Domain from BytePlus**, BytePlus GTM will not generate a routing domain. Moreover, you do not need to add a CNAME record. BytePlus DNS will automatically connect your domain to BytePlus GTM.

<span id="line"></span>
## Line

Lines indicate the source of user requests. A line can be defined by ISPs, geolocations, IP ranges, or combinations of ISPs, geolocations, and IP ranges.

If your domain can be resolved to different service IP addresses, and user requests are expected to be routed to an IP address that meet the following requirements to reduce user access latency:


* The ISP of the user's IP address is the same as the ISP of the service IP address.

* The geolocation of the user's IP address is as close to the geolocation of the service IP address.


You can assign a line to a record set that contains one or multiple service IP addresses. Each line represents the ISP, geolocation, or IP range of the service IP addresses in the record set.

There is a default line in BytePlus GTM, which represents the user traffic that does not match the geographical location, ISP, and CIDR address block you specified. A GTM instance must include a rule with a line set as the default line.

For detailed information about lines, see [DNS-based Routing With Lines](https://docs.byteplus.com/docs/byteplus-dns-suite/docs-intelligent-dns-based-routing).

<span id="weight"></span>
## Weight

Under the basic routing policy, if you have enabled load balancing, you can set weights for rules, pools, and addresses.

BytePlus GTM first routes user traffic to the nearest data center based on the user's geographical location and ISP, and then distributes user traffic proportionally to multiple data centers based on load balancing.

<span id="capacity"></span>
## Capacity

Under the capacity and load feedback routing modes of the intelligent routing policy, you can set capacity for pools or addresses.

Capacity is a positive integer used to indicate the traffic capacity of a pool or address. You can set a reasonable capacity value for the data center based on parameters like bandwidth and concurrent connections. Capacity is a relative value, so you do not need to input the actual data of the address, but you need to ensure unity of the capacity unit among different addresses or pools.

<span id="health-check-probe"></span>
## Health check probe

A health check probe refers to nodes distributed across various global regions, used for performing health check requests on target addresses.

<span id="f9e1191d"></span>
## Health check

BytePlus GTM conducts health checks on target addresses through one or multiple health probes based on various protocols. Depending on the results of the health checks, the target address is determined to be available or unavailable.

<span id="10e2c505"></span>
## Health check task

In each health check task, a health probe periodically performs health checks to a specified target address according to the active health check configuration and returns the health check results.

<span id="37a3bb59"></span>
## Health check task set

BytePlus GTM includes health check tasks with identical target addresses and health check parameters in a health check task set. Within a health check task set, identical health check tasks are deduplicated.

<span id="failover"></span>
## Failover

The health check feature of BytePlus GTM also affects how users requests are directed. The failover logic is as follows:


* When an address becomes unavailable, BytePlus GTM will stop directing user requests to that address. If the address becomes available in subsequent health checks, BytePlus GTM will automatically direct user requests back to that address.

* When the primary pool set is unavailable, BytePlus GTM will direct the requests to the addresses of another available pool set within the same rule according to the priority of pool sets.
