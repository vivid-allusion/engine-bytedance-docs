This document introduces how to enable DNSSEC (DNS Security Extension) for your domain name.

As an extension protocol of DNS, DNSSEC provides an authentication mechanism for the source and integrity of DNS data, which can verify whether the DNS response comes from the authoritative DNS server, thus preventing attacks such as DNS cache poisoning. Refer to [DNSSEC](https://docs.byteplus.com/docs/byteplus-dns-suite/docs-basicconcepts#dnssec) for more information.

<span id="dnssec-how-to-authenticate-dns-responses"></span>
## How DNSSEC authenticates DNS responses

DNSSEC introduces the following record types:


* **RRSIG**: Contains a digital signature, which can be a digital signature generated by the ZSK (Zone Signing Keys) private key for the RRSet in the Zone, or a digital signature generated by the KSK (Key Signing Keys) private key for the RRSet of the DNSKEY record.

* **DNSKEY**: Contains a public key, which can be a ZSK public key or a KSK public key.

* **Delegation Signer**: Contains the hash value of the KSK public key in the DNSKEY record.

* **NSEC** and **NSEC3**: Used to prove that the requested DNS record does not exist (Explicit Denial of Existence).

* **CDNSKEY** and **CDS**: Used by the current zone to request the parent Zone to update the DS record.


When the recursive DNS server sends a DNS query request, the DNSSEC verification process is as follows:


1. When the recursive DNS server obtains the authoritative DNS server address of the current zone, it also obtains the DS record from the parent Zone. This DS record proves that the current zone has enabled DNSSEC. The recursive DNS server calculates the hash value of the KSK public key of the current zone and compares it with the hash value contained in the DS record. If the two hash values are the same, the recursive DNS server can consider the KSK public key to be valid.

2. The recursive DNS server requests the DNS record (such as an A record) from the authoritative DNS server. The DNS server returns the RRSIG record generated by the RRSet of the DNS record along with the DNS record. At the same time, the recursive DNS server requests the DNSKEY record containing the ZSK public key, the DNSKEY record containing the KSK public key, and the RRSIG record generated by the RRSet of the DNSKEY record from the authoritative DNS server.

3. The recursive DNS server uses the ZSK public key to verify the RRSIG record generated by the RRSet of the requested DNS record; uses the KSK public key to verify the RRSIG record generated by the RRSet of the DNSKEY record.


<span id="prerequisites"></span>
## Prerequisites

Your domain name must meet the following conditions to enable DNSSEC.


* The edition of your domain name is enterprise edition, ultimate edition, or exclusive edition.

   <div data-tips="true" data-tips-type="danger" data-tips-is-title="true" data-wrapper-indent="1">danger   </div>
   

   <div data-tips="true" data-tips-type="danger" data-wrapper-indent="1">If your domain name has enabled DNSSEC and the paid edition of the domain name expires, your domain name resolution will fail. If you plan not to renew the paid edition of your domain name, you need to delete the DS record at the domain registrar and then disable DNSSEC in BytePlus DNS.   </div>
   

* Your domain registrar must support DNSSEC.

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">If your domain name has enabled DNSSEC but the user's Local DNS server does not support DNSSEC, the domain name may not be resolved correctly.   </div>
   

* Only the root domain name can enable DNSSEC. Subdomains hosted in BytePlus DNS cannot enable DNSSEC.


<span id="steps"></span>
## Steps

<span id="step-1-enable-dnssec-in-trafficroute-dns"></span>
### Step 1: Enable DNSSEC in BytePlus DNS

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">If your domain name has a CNAME DNS record with the domain name prefix <code>@</code>, your domain name cannot enable DNSSEC. If your domain name has enabled DNSSEC, you cannot add a CNAME DNS record with the domain name prefix <code>@</code>.</div>


Follow the steps below to enable DNSSEC for your domain name in BytePlus DNS.


1. Open the [BytePlus DNS Console](https://console.byteplus.com/dns-suite/dns/public-zone).

2. In the **Domain management** page, click your domain name in the **Domain** column.

3. Select the **DNS security** tab, and click **Enable DNSSEC** in the **DNSSEC** section.

4. After enabling, BytePlus DNS will sign the DNS data of the domain and display the information required to add the DS record at the domain registrar in the **DNSSEC** section.



|Parameter |Description |
|---|---|
|DS record |DS (Delegation Signer) record. This record contains the hash value of the KSK public key in the DNSKEY record. |
|Key tag |Key Tag is a 16\-bit number used to identify a DNSKEY record from the RRSet of DNSKEY records. This parameter identifies the DNSKEY record containing the KSK public key. |
|Algorithm |The algorithm used to calculate the hash value of the KSK public key. |
|Digest type |The type of the hash value of the KSK public key. |
|Digest |The hash value of the KSK public key. |
|Public key |The KSK public key. |
|Flags |The type of the public key. This parameter is 257 (KSK). |


<span id="step-2-add-ds-record-at-your-domain-registrar"></span>
### Step 2: Add DS Record at Your Domain Registrar

Refer to the product documentation of your domain registrar and use the information obtained from Step 1 to add the DS record for your domain.


* **Godaddy**: Refer to Godaddy's [product documentation](https://ph.godaddy.com/help/add-a-ds-record-23865).

* **AWS Route 53**: Refer to AWS Route53's [product documentation](https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/domain-configure-dnssec.html).


<span id="step-3-verify-dnssec"></span>
### Step 3: Verify DNSSEC

After adding the DS record, you can verify whether DNSSEC is effective.

<span id="use-dnsviz-to-verify-dnssec"></span>
#### Use DNSViz to Verify DNSSEC

DNSViz is an online, open\-source DNS analysis tool. The following steps use DNSViz as an example to illustrate how to verify whether DNSSEC is effective for your domain.


1. Open [DNSViz](https://dnsviz.net/).

2. Enter the domain name you need to verify, such as **example.com**, and then click **Go\>\>** .

3. If the domain has not been analyzed, click **Analyze** to analyze the domain. After the analysis is complete, click **Continue**.

4. You will be redirected to the verification page. After waiting for a while, you can see the DNSSEC trust chain of the domain.

5. Check whether there are errors or warning signs in the DNSSEC trust chain:

   * If each level of the domain has a DNSKEY, the arrows are all blue, and there are no error or warning signs, i.e., RRset status, DNSKEY/DS/NSEC status, and Delegation status are all SECURE, it means that DNSSEC is effective for your domain. The following image shows a valid DNSSEC for `example.com`.

      <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_fbc61ad0ee8be8f40c8a3b406f288b1c.png) </span>

   * If there are black arrows, red arrows, or error signs, it means that DNSSEC is not active. You can move the mouse to the corresponding position to view the error or warning information and troubleshoot the problem based on the error or warning information. The following image shows an example of `brokendnssec.net`, where the authoritative DNS server lacks DNSKEY records, causing it to fail to match the DS records of the top\-level domain DNS server, resulting in a broken trust chain.

      <span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_3ecf397137954b300cdd9b2a990dc708.png) </span>


<span id="use-dig-to-verify-dnssec"></span>
#### Use dig to verify DNSSEC

You can use the `dig +dnssec` command to verify DNSSEC.

```shell
$ dig +dnssec www.example.com

;; global options: +cmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 59330
;; flags: qr rd ra ad; QUERY: 1, ANSWER: 2, AUTHORITY: 0, ADDITIONAL: 1

;; OPT PSEUDOSECTION:
; EDNS: version: 0, flags: do; udp: 512
;; QUESTION SECTION:
;www.example.com.      IN   A

;; ANSWER SECTION:
www.example.com.   19439   IN   A   93.184.216.34
www.example.com.   19439   IN   RRSIG   A 13 3 86400 20240207154702 20240117103421 60960 example.com. nZz4JmYshN2qjQtcgt5Lfh9AXE04X7jp3p/ORq5j7m8JWEqtuqlEOzr7 W4DOBmrPg7NFiP7Ij+t3+YxtgW89iQ==
```


If the DNS response contains an RRSIG record, it means that the DNS response has been verified by DNSSEC. Additionally, the `ad` flag in the returned information also indicates that the DNS response has been verified by DNSSEC.

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">If the dig +dnssec command does not return an RRSIG record, it may be because the recursive DNS server (public DNS server or Local DNS server) you are using does not support DNSSEC. You can use a public DNS server that supports DNSSEC for verification, such as 1.1.1.1 or 8.8.8.8.</div>


<div data-tips="true" data-tips-type="tip">```shell
$ dig +dnssec www.example.com @1.1.1.1
```
</div>
