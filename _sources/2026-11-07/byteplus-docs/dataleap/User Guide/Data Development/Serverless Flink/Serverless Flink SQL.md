DataLeap has integrated **Serverless Flink**. After associating Flink projects and resource pools, you can develop Flink jobs. You can use Serverless Flink SQL jobs to perform ETL and more between different storage systems. This article uses a simple example to introduce the development process for Serverless Flink SQL jobs.

<span id="158b01d6"></span>
## 1 Usage restrictions

After enabling **Professional (Big data analytics)**  services, you can bind the **Serverless Flink engine**. For details on binding engine operations, see [Create a Project](https://docs.byteplus.com/docs/dataleap/create_project).

<span id="_2-使用前提"></span>
## 2 Prerequisites for use


1. When a sub\-account binds a Flink engine instance to a project:

   1. The main account must first import IAM users into the [Serverless Flink Console](https://console.byteplus.com/flink/region:flink+ap-southeast-1/overview). For operation details, see: [Accounts Management](https://docs.byteplus.com/en/docs/flink/Accounts).

   2. And add the sub\-account to the corresponding engine project. For operation details, see: [Engine project member management](https://docs.byteplus.com/en/docs/flink/Member_Management).

2. Currently, the Flink 1.17 execution engine version is available only through a whitelist. You can [submit a ticket](https://console.byteplus.com/workorder/create?ref=L2hvbWU%3D) to contact us. After we add you to the whitelist, you will be able to use it.

## 3 Task configuration description

<span id="_3-1-新建任务"></span>
### 3.1 Create a task


1. Log in to the [DataLeap Tenant Console](https://console.byteplus.com/dataleap/console/region:dataleap-console+ap-southeast-1/project/list?administrator=mine&current=1&isMine=true&pageSize=20&projectName=&projectOrOwnerName=&sortColumn=createTime&sortOrder=desc).

### 3.2 Edit tasks

After successfully creating a new task, enter the code development editing interface and edit SQL using DDL and DML. Sample code:

For detailed syntax, refer to the [Flink official documentation](https://nightlies.apache.org/flink/) for each version.

<span id="_3-2-1-编辑sql代码"></span>
#### 3.2.1 Edit SQL code

The following is a demo: Random numbers generated by the Datagen connector are printed to standard output (stdout).

```SQL
CREATE TABLE datagen_source (
     siteid INT,
     citycode SMALLINT,
     username STRING,
     pv BIGINT
     )
WITH (
  'connector' = 'datagen',
  'rows-per-second' = '{{project_param_rows}}',                
  'fields.username.length' = '30',            
  'fields.siteid.max' = '1000000000',   
  'fields.siteid.min' = '10000'        
);
CREATE TABLE print_sink (
    siteid INT,
    citycode SMALLINT,
    username STRING,
    pv BIGINT
    )
WITH (
     'connector' = 'print',
     'print-identifier' = 'out'            
);
insert into print_sink
select * from datagen_source;
```


DataLeap allows you to use project or custom parameter variables directly in SQL scripts, such as {{project_param_rows}}, to improve task execution efficiency in different environments. For detailed instructions on using project or custom parameter variables, see [3.4.5 Task input parameters](https://docs.byteplus.com/docs/dataleap/serverless_flink_sql#_3-4-4-%E4%BB%BB%E5%8A%A1%E8%BE%93%E5%85%A5%E5%8F%82%E6%95%B0).

* <div data-tips="true" data-tips-type="tip">When a running Flink SQL job contains resource references, if a resource file is updated in the resource repository, you need to go to the Operations Center to <strong>restart</strong> the streaming job so that the resource changes take effect.</div>



In the dropdown menu, select Jar and File resources that have been uploaded via the resource repository. Multiple selection is supported. If you have not uploaded any resources yet, you can click the "**New Resource**" button to go to the resource library and create resources. <span id="_3-4-4-任务输入参数"></span>
#### 3.4.5 **Task input parameters**

If you want the same codebase to automatically distinguish between different types of parameters—such as engine environment parameters, project parameters, custom parameters, and so on—across various execution environments, you can achieve this scenario by configuring the input parameters of the task.

Task input parameters allow you to pass custom parameters and project parameters into streaming tasks as variables or constants. You can reference them in code using the {{parameter name}} format:

In the **Parameter Settings \> Task Input Parameters** section, click the **Add Manually** button to open the Add Input Parameter interface.

Input parameters are specifically classified into the following two categories:

<span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/59eef71f02da4530b6ee5e9b236096e0~tplv-goo7wpa0wc-image.image) </span>


* Project parameters: Use the parameter information set in the project console as input. The procedure is as follows:

   1. In the upper\-right corner of the interface, click **Project Console,**  to enter the project configuration page.

   2. Click the **Parameter info \> New parameter** button in the right navigation bar to add project parameters.

   3. Set the project parameter name, development environment parameter value, production environment parameter value, description, and other information in the popup window, then click the **OK** button to create the parameter. For configuration details, see [Parameter Information Settings](https://docs.byteplus.com/docs/dataleap/parameter_information_setting).

      <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/424589da06e445a59ef62b8804d14f20~tplv-goo7wpa0wc-image.image) </span>

   4. After creating a new project parameter in the console, return to the data development parameter settings window and add an input parameter. Set the parameter type to **Project,**  and for Source, select the name of the parameter you just created above.

   5. Click the **OK** button to complete the addition of project input parameters.

* Custom parameters: Use user\-defined parameters as input. The procedure is as follows:

   1. In the data development parameter settings window, add an input parameter, then sequentially set the parameter name, select the **custom** parameter type from the dropdown list, and enter the parameter value. Both constant and variable forms are supported as input.

   2. Click the **OK** button to complete the addition of custom input parameters.


After configuring the task input parameters, submit, publish, and start the task. Then, go to **Real\-time Operations Center \> Logs \> Application Url \> Job Manager \> Stdout** to view the code that was actually executed after replacement:

<span id="_3-4-5-数据源登记"></span>
#### 3.4.6 **Data source registration**

Record the Source and Sink information used by this task for subsequent monitoring configuration and lineage construction. Support is available via **automatic parsing** and **manual addition**.


* Auto parse: After saving the SQL logic, click the **Auto parse** button to automatically register upstream and downstream data sources based on the SQL logic.

   * Source/target: Supports selecting Source and Sink as source or target options.

   * Data source types: Automatic parsing is supported for data sources using the DataGen, Rmq, Bmq, JDBC, Abase, or Volcano Kafka or self\-managed Kafka connectors.

      <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="2">tip      </div>
      

      <div data-tips="true" data-tips-type="tip" data-wrapper-indent="2">The Abase and Rmq data source types only support parsing operations and do not yet support running after being published online. Moreover, Abase data sources are typically used during <strong>the cloud migration of Volcengine's internal businesses</strong>.      </div>
      

   * For each data source type, you need to provide the corresponding information. You can configure according to your actual scenario. For example, for the Kafka data source type, you need to specify the Bootstrap Servers, Topic name, consumer group, and other relevant information.

   * Direct upstream tasks: The direct upstream tasks are automatically parsed based on data source matching logic. You can also use the **Manual Add** option below to search for upstream task names. Then, click the **Add** button to add them manually.

   * Direct downstream tasks: These tasks are automatically parsed based on data source matching logic and cannot be **manually added**. Only the results obtained through data source matching are displayed.

   * For automatically parsed data sources, you can turn off the **automatic parsing** button and then **delete** the registered data source.

* Manual addition: You can also register a data source manually.

* To batch delete data sources **manually added**, select the registered data sources, then click the **Delete** or **Batch Delete** button on the right to remove the selected data sources.

* View upstream and downstream tasks: For upstream dependency tasks parsed from data source registration, you can edit, add, delete, or disable them. Downstream tasks can only be viewed.

After data configuration is complete, click the **Start Test** button in the window to immediately start debugging and running. In the **Test Record window** below, view information such as the **task run overview, results, and startup log**.

On the **results** interface, you can dynamically view the final results and the status of detailed data, pause or terminate tests, view the **Flink UI** interface, and perform other operations.
