DataLeap has integrated **Serverless Flink**. After associating the Flink project and resource pool with the DataLeap project, you can develop Flink jobs. By creating a Flink Batch SQL task and using its Flink Engine, you can execute Batch SQL statements. You can use the same SQL statements as those used in streaming Serverless Flink SQL tasks to perform offline data correction through Flink Batch SQL batch jobs, enabling unified stream\-batch operations and significantly reducing development and maintenance costs.

This article will introduce development procedures related to Flink Batch SQL jobs.

<span id="06742210"></span>
## 1 Usage limitations


* Only after enabling the **Professional (Big data analytics)**  services in the DataLeap product can you bind the **Serverless Flink Engine**. For details about the bind engine action, see [Create a Project](https://docs.byteplus.com/docs/dataleap/create_project).

* Currently, the Flink 1.17 execution engine version is only available to users on the allowlist. You can [submit a ticket](https://console.byteplus.com/workorder/create?ref=L2hvbWU%3D) to request that the DataLeap support staff add you to the allowlist. Once you have been added, you can use this version.

* If a task references Jar or File resources, and a custom connector and a built\-in connector in the resource type have the same name, using them in the same task is not supported; otherwise, a conflict exception may occur during the task run. For details about built\-in connectors, see the [connector list](https://docs.byteplus.com/en/docs/flink/Connector_Overview).

## 3 New task


1. Log in to the [DataLeap Tenant Console](https://console.byteplus.com/dataleap/console/region:dataleap-console+ap-southeast-1/project/list?administrator=mine&current=1&isMine=true&pageSize=20&projectName=&projectOrOwnerName=&sortColumn=createTime&sortOrder=desc).

## 4 Task configuration

<span id="_3-2-编辑任务"></span>
### 4.1 Edit Task

After successfully creating a New Task, enter the code development editing interface and edit SQL using DDL and DML. For detailed syntax, refer to the [Flink Official Documentation](https://nightlies.apache.org/flink/) for each version.

The following is a demo example:

Output the random numbers generated by the Datagen connector and write them to the specified MySQL database table.

```sql
CREATE  TABLE datagen_source (id INT, age INT)
        WITH (
            'connector' = 'datagen',
            'number-of-rows' = '10',
            'rows-per-second' = '1'
        );

CREATE  TABLE jdbc_sink (id INT, age INT)
        WITH (
            'connector' = 'jdbc',
            'url' = 'jdbc:mysql://mysql*****.rds.ivolces.com/teat_db',
            'table-name' = 'datagen_table',
            'username' = 'user_*****',
            'password' = '*****',
            'scan.partition.column' = 'id',
            'scan.partition.num' = '2',
            'scan.partition.lower-bound' = '0',
            'scan.partition.upper-bound' = '100',
            'scan.fetch-size' = '1'
        );

INSERT INTO jdbc_sink
SELECT  *
FROM    datagen_source;
```

### 4.3 Schedule settings

After you finish editing the task script, from the right navigation bar, go to the **Scheduling Configuration** window. Here, you can set the task's **basic information, scheduling attributes, dependencies, task input and output**, and other details. For detailed parameter settings, see [Schedule Settings](https://docs.byteplus.com/en/docs/dataleap/scheduling_settings).

<span id="_3-4-1-高级参数"></span>
#### 4.3.1 Advanced parameters

In a Flink Batch SQL task, you can set **advanced parameters,**  in the scheduling attribute parameters. You can enter the parameters required for the Flink task here, and the following two ways to add them are supported:


* Single line edit mode: Fill in key\-value pairs. Only letters, numbers, decimal points, underscores, and hyphens are supported for the Key.

   1. Add row of parameters

   2. Delete the current parameter row

* Script edit mode: Fill in operation parameters in JSON or YAML format.


<span id="b5b94e3e"></span>
#### 4.3.2 Dependencies

Here, you can configure upstream and downstream dependencies for batch tasks to build data lineage. This ensures that, during downstream execution, the data output by upstream tasks can be accurately obtained, thereby ensuring data quality and improving data development efficiency.

For details on configuring upstream and downstream dependencies, see [Task scheduling depends on](https://docs.byteplus.com/docs/dataleap/scheduling_dependencies).

<span id="b9907819"></span>
#### 4.3.3 Input and output parameters

After configuring upstream dependencies for a task, you can set the task's input and output parameters to enable parameters to be passed between upstream and downstream tasks. The content value of these parameters can come from the output results of upstream tasks, project parameters, or custom parameter values.

For details on actions for input and output parameters, see [Input and Output Parameter Settings](https://docs.byteplus.com/docs/200/66965).

<span id="645ba601"></span>
#### 4.3.4 Import resources

Flink Batch SQL tasks support the introduction of Jar package and File file resource types, allowing custom connectors to be defined within Jar packages and File files to meet more complex business scenarios.

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>



* <div data-tips="true" data-tips-type="tip">If a custom connector and a built\-in connector have the same name under the Jar or File resource type, you cannot use them for the same task; otherwise, a conflict exception will occur during task execution. For details about built\-in connectors, see the <a href="https://docs.byteplus.com/en/docs/flink/Connector_Overview">connector list</a>.</div>


* <div data-tips="true" data-tips-type="tip">When a production Flink SQL task is running and involves resource references, if a resource file is updated, after the Resources Library updates the file, you must manually <strong>re\-Commit for Deploy</strong> and <strong>re\-Restart</strong> the streaming task to make the resource change take effect. If you do not perform a manual restart after submitting, or if the system restarts automatically, the old resource file will still be used.</div>



In the dropdown box, choose Jar and File resources that have been uploaded to the Resources Library and approved. You can select multiple items. If you have not yet uploaded a resource, you can click the “**New Resource**” button to create a resource in the Resources Library. For details, see [Resources Library](https://docs.byteplus.com/docs/200/682aa9fee638492ec7c94266).

## 5 **Debug Task**

After the task code logic and parameter configuration are complete, you can click the **Save** and **Debug** buttons in the Action bar at the top of the editor to perform Task Debugging.

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>



* <div data-tips="true" data-tips-type="tip">Directly use online data for debugging. Please operate with caution. You may use a small amount of data for output and requirement verification.</div>


* <div data-tips="true" data-tips-type="tip">Debug log data in the Data Development interface is retained for 15 days. You can view the corresponding debug log details within this 15\-day period.</div>



After the debug execution is complete, you can view logs, results, and other details in the **Debug records** below. In the execution log, you can also view log details for the corresponding module based on which module (JobManager, TaskManager, or Client) the engine log belongs to.

<span id="_5-提交任务"></span>
## 6 Submit tasks

After completing the configuration of SQL statements and the required task parameters, you can commit the task for release to Batch Task Maintenance in the Operations Center for periodic execution.

Click the **Save** and **Commit for Deploy** buttons in the Action bar above. In the **Commit for Deploy** dialog box, choose parameters such as **Backfill data, Monitor Settings, and Commit settings**. Finally, click the **Confirm** button to submit the job. For details on the deploy instructions, see [4 Commit for Deploy](https://docs.byteplus.com/docs/dataleap/data-development-overview#_5-%E6%8F%90%E4%BA%A4%E4%B8%8A%E7%BA%BF).

For details on subsequent task operations, see [Task Operation](https://docs.byteplus.com/docs/dataleap/task_operation).
