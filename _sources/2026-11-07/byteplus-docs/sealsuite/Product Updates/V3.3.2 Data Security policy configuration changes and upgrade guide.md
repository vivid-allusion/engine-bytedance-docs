SealSuite version 3.3.2 introduces a comprehensive overhaul of the Data Security (DLP) module — restructuring policy configuration workflows and the menu architecture. This upgrade addresses pain points from previous versions, such as scattered configuration entries and unintuitive feature discovery, delivering a more unified and efficient data security governance workflow.

This document walks you through the key changes in policy configuration and menu paths between the old and new versions, helping you quickly build a mental model of the new experience and ensuring a smooth transition.

# Consolidating and decoupling configuration paths

This upgrade restructures the business logic that was previously embedded within "File exfiltration control policies," unifying configuration entries and decoupling independent control scenarios.

<span id="5a2dfa95"></span>
## 1. Unified entry for exfiltration control


* **Before 3.3.2**: When creating a file exfiltration control policy, administrators had to choose a control mode ("Audit exfiltration" or "Block exfiltration") in a dialog box upfront, which then led to two separate configuration paths.

* **3.3.2 and later**: The upfront selection step has been removed. Administrators simply click **New Rule** to open a unified form, where they choose a **Control action** (Allow / Deny) to define the policy type. This eliminates the fragmented configuration experience. For detailed instructions, see [Configuring file outbound control policies](https://docs.byteplus.com/docs/sealsuite/docs-configure-the-data-distributed-auditing-rule).

   * Additionally, the "Allow (Audit)" policy now has the same enforcement capabilities as the "Block" policy, including support for **endpoint notifications**. When an allow\-audit alert is triggered on an endpoint, administrators can configure a pop\-up notification to warn the employee.


<span id="b9e422b7"></span>
## 2. Clipboard control promoted to a top\-level policy


* **Before 3.3.2**: "Clipboard copy/paste" was treated as an exfiltration method and nested within the file exfiltration control policy configuration.

* **3.3.2 and later**: Because clipboard operations flow across applications and do not always produce a physical file, clipboard control has been fully separated from file exfiltration policies and promoted to a standalone policy — **Clipboard control policy** — at the same level as "File exfiltration control" and "Channel control." For detailed instructions, see [Configuring clipboard control policies](https://docs.byteplus.com/docs/sealsuite/configuring-clipboard-control-policies).

   * Accordingly, in the investigation and audit module, copy/paste alert records for end users have also been separated from "File exfiltration logs" and moved to a dedicated **Clipboard log** page for centralized review and tracing.


<span id="0f622c49"></span>
## 3. Streamlined exfiltration method categories

To make policy forms more concise, the new version consolidates similar exfiltration channels:


* **Computer peripherals**: The "External storage" and "Printer" methods from the previous version are now merged into a single "Computer peripherals" category.

* **Desktop application**: The standalone "Code repository upload" method has been removed. Its control capabilities are now covered under the "Desktop software" category.

# Centralized management of global capabilities

Version 3.3.2 adds two major modules to the Policy Center, centralizing DLP channel capabilities and allowlist resources that were previously scattered across multiple configuration entries.

<span id="abd2fb82"></span>
## 1. New "Channel list" page


* **Before 3.3.2**: There was no global view of the channels SealSuite supports (for example, whether a specific cloud drive supports blocking, or the minimum client version required). The "Custom channel" configuration entry was also buried inside the policy form, making it hard to find.

* **3.3.2 and later**: A new **Channel list** page has been added to the Policy Center. For detailed instructions, see [Channel lookup and custom configuration](https://docs.byteplus.com/docs/sealsuite/channel-lookup-and-custom-configuration).

   * **Capability matrix**: This page displays a matrix of all mainstream built\-in channels and their corresponding control capabilities (audit/block) along with version requirements, giving you a reference for assessing policy feasibility before configuration.

   * **Custom channel management**: The "Custom channel" entries that were previously scattered across various exfiltration methods in the policy configuration flow have been consolidated here. Administrators can now manage all enterprise\-specific desktop applications and websites in one place.


<span id="e798d3a4"></span>
## 2. New "Internal address" management


* **Before 3.3.2**: To apply differentiated controls for internal versus external data flows, administrators had to configure IM allowlists, internal website addresses, code repository allowlists, and so on separately within each exfiltration method's policy form. This was costly to maintain and prone to omissions.

* **3.3.2 and later**: A new **Internal address** page has been added to the Policy Center. This page serves as a global "trusted resource pool," consolidating all the channel allowlist configurations that were previously scattered across the product. After you predefine your enterprise's internal addresses here (such as internal code hosting platforms and trusted domains), you can reference them directly when configuring file exfiltration control policies. For detailed instructions, see [Internal address configuration](https://docs.byteplus.com/docs/sealsuite/internal-address-configuration).

### 2.1 Internal address configuration path mapping

To help you quickly locate where your previous allowlist configurations now live, refer to the following table:


|**Previous allowlist / configuration entry** |**New unified entry (Policy Center** \> **Internal addresses)**  |
|---|---|
|Feishu / Lark allowlist |Switch to the **Instant Messaging** tab |
|Website allowlist |Switch to the **WebSites** tab |
|Email allowlist (Email client & Webmail) |Switch to the **Email** tab |
|File transfer tool destination allowlist |Switch to the **Command line/Remote control/File transfer** tab |
|Code repository upload allowlist |Switch to the **Code repository** tab |
