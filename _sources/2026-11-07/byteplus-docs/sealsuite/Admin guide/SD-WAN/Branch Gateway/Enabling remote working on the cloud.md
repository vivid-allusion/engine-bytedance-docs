The remote working function of using SealSuite SD\-WAN can be used to build a remote working environment for enterprise users based on a client VPN connection to the enterprise intranet or to build a remote working environment without client access to enterprise applications.

The description of remote working on the cloud is as follows:


* Method 1: Enterprise employees can access the internal network of the enterprise for remote working through a VPN connection through a SealSuite client.

   SealSuite provides a cloud VPN gateway for enterprise employees by configuring a cloud access gateway automatically generated by SealSuite. Later, employees can access the enterprise intranet by connecting to the VPN node through the SealSuite client.

* Method 2: Enterprise employees access enterprise applications for remote working through a clientless web format

   Enterprises can achieve proxy access to seven layers of applications (application layers) on the cloud by configuring a cloud application gateway automatically generated by SealSuite. Later, enterprise users can access internal applications of the enterprise through a clientless web format for remote working.


<span id="5d747329"></span>
# Prerequisite


* The enterprise SD\-WAN has been set up, and at least one branch gateway is running. For specific operations, please refer to [Adding a software-based branch gateway](https://docs.byteplus.com/docs/sealsuite/docs-adding-a-branch-gateway-software-version-).

* If you need to use the remote working function of the SealSuite office network, please contact SealSuite technical support or submit a work order to apply for activation.


<span id="99bf1477"></span>
# Procedure


1. Log in to the Admin Console.

2. In the left navigation bar, click **SD\-WAN** \> **Branch Gateway**.

3. In the upper right corner of the **Branch Gateway** page, click **Remote working**.

4. On the pop\-up pane on the right side of the screen, click **Start**.

   After clicking **Start**, the page will automatically redirect to the **Remote Working** page, and the function switch has been turned on by default.

   <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/6e0a0fbec07b4e22a5a5d5580cb6e32e~tplv-goo7wpa0wc-image.image) </span>

   After enabling the remote working function, SealSuite will automatically generate the following resources.

   * In the Zero **Trust Access** \> **Gateway Config** \> **VPN Gateway** of the Admin Console, it automatically generates a cloud access gateway (cloud VPN gateway) that is not online.

   * In the **Trust Access** \> **Gateway Config** \> **App Gateway** of the Admin Console, it automatically generates a cloud application gateway that is not online.

5. Select and configure one or more of the following remote working methods based on actual business needs.

   * [Building a client-based remote working environment](https://arcosite.bytedance.net/sites/1673322421329/64b8d299f46a1b022f9c183b/editor/654c774e2c51d802f9447353?docLang=en&bv=652fd8f3fb401502ea5effe0#d41be92a)

   * [Building a clientless remote working environment](https://arcosite.bytedance.net/sites/1673322421329/64b8d299f46a1b022f9c183b/editor/654c774e2c51d802f9447353?docLang=en&bv=652fd8f3fb401502ea5effe0#3bf4c989)

# Building a client\-based remote working environment

By configuring the cloud access gateway, users can access the enterprise private network by connecting cloud VPN gateways with the SealSuite client.


1. Log in to the Admin Console.

2. In the left navigation bar, click **SD\-WAN** \> **Branch Gateway**.

3. In the upper right corner of the **Branch Gateway** page, click **Remote Working**.

4. In the **Cloud Access Gateway** area of the **Remote working** interface, complete the following operations in sequence according to the prompts on the page.

   <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/2d68611ed69a4a16b69ed093dfa39484~tplv-goo7wpa0wc-image.image) </span>

   1. Launch a cloud access gateway.

      1. In the **Enable Cloud VPN Gateway** area, click **Configure**.

      2. On the **VPN Gateway** page, locate **Cloud** **VPN**.

      3. In the **Change state** drop\-down list on the right side of the page, select **Publish**.

         <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/6b6fcdd69b62498589912e73e2041376~tplv-goo7wpa0wc-image.image) </span>

      4. In the confirm pop\-up box, click **OK**.

   2. Configure the usage permissions of the cloud access gateway.

      1. Return to the **Cloud VPN Gateway** area of the **Remote working** interface.

      2. In the **Configure VPN Permission** area, click **Configure**.

      3. On the **VPN Management** \> **Access Permission** page, click  **+**  **Add Permissions** to set the **Scope** and **Effective duration** of usage permissions.

         For more detailed instructions on VPN usage permissions, please refer to [Adding VPN access permissions](https://arcosite.bytedance.net/sites/1673322421329/64b8d299f46a1b022f9c183b/editor/64c1e45265389e0d5a5633fe?docLang=en&bv=652fd8f3fb401502ea5effe0).

   3. Configure access permissions for the cloud access gateway.

      1. Return to the **Cloud VPN Gateway** area of the **Remote working** interface.

      2. In the **Configure Resource Permission** area, click **Configure**.

      3. On the **VPN Management** \> **VPN Access** page, set the VPN's open mode, accessible network resources, and access rules.

         For more detailed instructions on VPN access, please refer to [Managing access control rules](https://docs-cms.byteintl.net/space/sealsuite/en/document/327/24459).

         After configuration is completed, users within the effective scope of cloud access gateway usage permissions can connect to the corresponding cloud VPN gateway of the cloud access gateway through the SealSuite client to achieve remote working.

# Building a clientless remote working environment

By configuring a cloud application gateway, users can remotely access enterprise applications through a clientless web format.


1. Log in to the Admin Console.

2. In the left navigation bar, click **SD\-WAN** \> **Branch Gateway**.

3. In the upper right corner of the **Branch Gateway** page, click **Remote working**.

4. In the **Remote working** interface, expand the **Cloud Application Gateway (Without Client)**  area.

5. Enable Cloud Application Gateway.

   1. In the **Enable Cloud Application Gateway** area, click **Configure**.

   2. On the **Gateway** tab of the **Application Gateway** page, locate the **Cloud Gateway**.

   3. In the **Change state** drop\-down list on the right side of the page, select **Publish**.

      <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/2349077ecd1849b4b318f194628e5145~tplv-goo7wpa0wc-image.image) </span>

6. Configure a cloud application gateway for enterprise applications.

   If you have added an enterprise application in application management, you can associate it with a cloud application gateway. If you have not added an enterprise application in application management yet, you can add an enterprise application and associate it with a cloud application gateway. The specific operation instructions for different scenarios are as follows:

   * **Scenario 1: Associate a cloud application gateway with existing applications, allowing users to access the application in a clientless Web form**

      1. In the left navigation bar, select **Applications List**.

      2. On the **Applications List** page, locate the application that needs to add a cloud application gateway.

      3. Click on the application name to enter the application details page.

      4. On the **Application Gateway** tab of the application details page, click **Start**.

         <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/c455aab1df5b4724a974c91f0f291d95~tplv-goo7wpa0wc-image.image) </span>

      5. On the pop\-up **Add New Application Gateway** interface on the right side, complete the following configuration and click **Confirm**.

         After configuration is completed, users with access to the application do not need to connect to the VPN through the client and can directly access the specified application address to use the application.

         <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/885786fcafc2400b929d5b33bcfe8fd4~tplv-goo7wpa0wc-image.image) </span>

         The description of configuration items is as follows:

         
         |**Configuration Item** |**Description** |
         |---|---|
         |**App Domain Name** |Enter the front\-end domain name address of the proxy application. For example, `https://www.example.com:8080`. |
         |**Actual Server Address** |Enter the actual address of the server to which the application belongs. Format as domain name or IP address and port number. For example,`https://www.example.com:80`. |
         |**Certificate** |If you have configured the HTTPS protocol for your application domain name, you also need to add the corresponding SSL certificate. You can choose to add the corresponding SSL certificate to this configuration item. If the certificate has not been uploaded to SealSuite yet, you need to upload the certificate first. For specific operations, please refer to [Adding SSL certificates](https://docs.byteplus.com/docs/sealsuite/docs-ssl-certificates-management). |
         |**DNS parameters** |Click **Add Pulish Gateway**, and select the publishing gateway for the associated application. If the application gateway has not been added to SealSuite yet, you need to add the application gateway first. For specific operations, please refer to [Managing application gateway](https://docs.byteplus.com/docs/sealsuite/docs-application-gateway-management). |
         

         <div data-tips="true" data-tips-type="warning" data-tips-is-title="true" data-wrapper-indent="3">warning         </div>
         

         <div data-tips="true" data-tips-type="warning" data-wrapper-indent="3">After filling in the application gateway configuration items, you also need to go to the domain name resolution service provider console and direct the application resolution address to the application gateway. For specific operations, please refer to <a href="https://docs-cms.byteintl.net/space/sealsuite/en/document/327/24547#%E5%BA%94%E7%94%A8%E5%9F%9F%E5%90%8D%E8%A7%A3%E6%9E%90%E5%9C%B0%E5%9D%80%E6%8C%87%E5%90%91%E5%BA%94%E7%94%A8%E7%BD%91%E5%85%B3%E6%93%8D%E4%BD%9C%E7%A4%BA%E4%BE%8B">Directing a domain name resolution address to application gateway</a>.         </div>
         

   * **Scenario 2: Add an application and associate it with a cloud application gateway, allowing users to access the application in a clientless Web form**

      1. In the left navigation bar, click **Application List**.

      2. On the Application List page, click **Application Marketplace** in the upper right corner.

         If you are adding an application for the first time, click access App in the middle of the page.

      3. On the **Add New Application** page, create a new application through preset application templates or in a custom way.

         <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="3">tip         </div>
         

         <div data-tips="true" data-tips-type="tip" data-wrapper-indent="3">For specific operations on using preset application templates or creating custom applications, please refer to <a href="https://docs.byteplus.com/docs/sealsuite/docs-add-application">Adding applications</a>.         </div>
         

      4. On the **Fill in the application information** page, complete the application configurations according to the actual situation and click **Confirm**.

         Different types of applications may need to configure different parameters. Please configure according to the actual situation. For example, after selecting the GitLab application template, you need to configure the **General** and **Application** **type** of the application.

         <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/acdb1983f573463bbaebf6d8483e7563~tplv-goo7wpa0wc-image.image) </span>

         Taking accessing GitLab application as an example, the configuration instructions are as follows:

         1. In the \*\*General \*\*area, fill in **Application Name**, **Application Address** and **Application Description**.

         2. In the **Application Type** area, complete the following configurations.

            1. In the **Single Sign\-on** area, select an authentication protocol or automatic login configuration item and complete the corresponding parameter configuration.

               The description of configuration items is as follows:

               
               |**Configuration Item** |**Description** |
               |---|---|
               |**OAuth 2.0** |After selecting this configuration item, you need to continue configuring the GitLab single sign on callback address. The format example is: `http://HOST_NAME:PORT/users/auth/oauth2_generic/callback` . Please configure it according to the actual situation. |
               |**CAS** |After selecting this configuration item, you need to continue configuring the GitLab single sign\-on callback address. The format example is: `http://HOST_NAME:PORT/users/auth/cas3/callback`. Please configure it according to the actual situation. |
               |**LDAP** |After selecting this configuration item, you need to continue configuring the password format, which can be **Static Password**, **OTP**, and **Static Password+OTP**. |
               |**Password Autofill** |After selecting this configuration item, users can automatically log in to the application through the password autofill function. |
               

            2. (Optional) In the **Application Gateway** area, check the **Application Gateway** box and fill in the corresponding configuration items.

               <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="5">tip               </div>
               

               <div data-tips="true" data-tips-type="tip" data-wrapper-indent="5">For specific instructions on application gateway configuration items, please refer to <strong>step 5</strong> of scenario 1.               </div>
               

      5. After configuration is completed, the page will automatically redirect to the **Authorization** page of the newly created application.

      6. On the **Authorization** tab, configure the scope of application usage.

         <span>![图片](https://p9-arcosite.byteimg.com/tos-cn-i-goo7wpa0wc/5cbcc18ec0a849a7b06f28bdd7cae05d~tplv-goo7wpa0wc-image.image) </span>

         Confugure **Full** or **Restricted**.

         * **Full**: This application is available to all users within the enterprise.

         * **Restricted**: Authorize the scope of use from the dimensions of **department**, **employee**, and **role**. For example, if a **Research and development** department is added in the **Department permissions** area, the application only supports the use of users within the **Research and development** department.

            <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="4">tip            </div>
            

            <div data-tips="true" data-tips-type="tip" data-wrapper-indent="4">When configuring <strong>Restricted</strong>, it is supported to select <strong>Allow employees to apply</strong>. After selecting this configuration item, users with permission to use the application can copy the application link and share it with other unauthorized users. Users without permission can apply to use the application after accessing the link.            </div>
            

         After configuration is completed, users with access to the application do not need to connect to the VPN through the client and can directly access the application address to use the application.
