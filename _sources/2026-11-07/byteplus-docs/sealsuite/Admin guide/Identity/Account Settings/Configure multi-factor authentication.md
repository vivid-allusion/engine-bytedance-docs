## What is multi\-factor authentication

Multi\-factor authentication (MFA) verifies a user's identity by combining different authentication factors. For example, in addition to an account password, employees must enter a verification code sent to their phone. This reduces the risk of account misuse after a password leak.

In SealSuite, administrators can enable secondary authentication for operations such as logging in to SealSuite, connecting to a VPN, connecting to a proxy, and obtaining network access credentials. Administrators can specify authentication methods for each operation. Employees can continue only after completing the required verification.

<span id="支持的认证方式"></span>
## Supported authentication methods

SealSuite MFA supports the following four authentication methods. Select methods based on the services configured for your enterprise and how employees use SealSuite.

> Log in to the Admin Console and choose **Identity** \> **Account Setup** \> **MFA Setup**. In the **Authentication Method** area, click **Example** to view the verification interface. Expand **Supported scenarios description** to view the applicable scope of each method.


&nbsp;


|Authentication method |Verification process |Prerequisites |
|---|---|---|
|OTP |Employees enter a passcode generated by SealSuite or a custom OTP service. |The built\-in SealSuite service is used by default. You can also integrate a custom OTP service. |
|SMS verification code |Employees enter the verification code sent to their phone number. |The enterprise has configured an SMS service, and the employee account has a valid phone number. |
|Email verification code |Employees enter the verification code sent to their email address. |The enterprise has configured an email service, and the employee account has a valid email address. |
|Push authentication |Employees approve a push notification on their mobile client when connecting to a VPN or enabling a proxy on their desktop client. When the mobile client itself connects to a VPN, an SMS verification code or email verification code is used. |Employees can receive and process SealSuite push authentication on their mobile phones. |


<span id="配置前准备"></span>
## Before you begin

Before enabling secondary authentication, confirm that employee account information and client versions meet the following requirements.


* When using SMS or email verification codes, confirm that the phone number or email address in the employee account is available. We recommend preparing another authentication method so employees can switch when the primary method is unavailable.

* Before enabling VPN secondary authentication for mobile clients, confirm that employee client versions meet the requirements. The minimum version is to be confirmed.

## Step 1: Configure authentication services

This step prepares the authentication services required for identity verification, such as sending verification codes through an SMS or email gateway, or using an OTP service to verify passcodes. Complete the required configuration based on the authentication methods you plan to use.

Log in to the Admin Console and choose **Identity** \> **Account Setup** \> **MFA Setup**. In the **Authentication Method** area, view and configure the authentication services that you need to use. Configured services do not need to be configured again. If you use the built\-in OTP service with its default settings, go to Step 2.

<span id="配置短信服务"></span>
### Configure the SMS service


1. In the **Authentication Method** area, view the **SMS Verification Code** card and confirm whether the SMS service is available.

2. To configure an SMS gateway, choose **Settings** \> **System Settings** \> **Notifications** and configure **SMS Configuration**. Then return to the **MFA Setup** page.


For details, see [Manage SMS configuration](https://docs.byteplus.com/en/docs/SealSuite/docs-overview-of-notifications#e10840ea).

<span id="配置邮件服务"></span>
### Configure the email service

In the **Email Verification Code** card, click **Configure** to go to **Email Configuration** and configure the enterprise email gateway. For details, see [Manage email configuration](https://docs.byteplus.com/en/docs/SealSuite/docs-overview-of-notifications#598a8170).

### Configure the OTP service

SealSuite provides a built\-in OTP service by default. Complete the configuration in this section only when you need to adjust passcode generation rules, allow employees to bind third\-party authenticators, or integrate a custom OTP service.

In the **OTP** card, click **Configure**. Select one of the following configuration methods based on the service used by your enterprise.


* **OTP Code**: Use the built\-in SealSuite service. You can set passcode generation rules and third\-party authenticator binding policies.

* **Custom OTP**: Select this option when the enterprise has imported its directory from a third\-party identity source and wants to use third\-party one\-time passwords. The custom service verifies employees from the corresponding third\-party data source. Other accounts can continue to use the built\-in SealSuite service as configured below.

## Step 2: Enable secondary authentication by scenario

This step sets which operations require employees to complete secondary authentication, and which method is used to verify their identity. You can enable authentication separately for logging in to SealSuite, connecting to a VPN, connecting to a proxy, and obtaining network access credentials. After the configuration takes effect, employees must pass verification before they can continue when authentication is triggered in the corresponding scenario.

In the **Authentication Scenarios** area on the **Identity** \> **Account Setup** \> **MFA Setup** tab, enable the following scenarios as needed. Each scenario is configured independently. After employees complete login verification, operations such as connecting to a VPN are still evaluated against their respective policies to determine whether authentication is required.

<span>![图片](https://lf3-static.bytednsdoc.com/obj/eden-cn/809eh7uhkbd/feilian/mfa-en-20260928/en-scenarios-final.png) </span>


* **Primary Authentication Method**: The method used first when employees trigger secondary authentication.

* **Alternative MFA**: Another method that employees can switch to. It cannot be the same as the primary method.


 &nbsp;

<span id="员工登录飞连"></span>
### Login to SealSuite

After this option is enabled, employees must complete secondary authentication when logging in to SealSuite. Mobile clients (iOS and Android), desktop clients (Windows, macOS, and Linux), and browsers are supported. Authentication methods include one\-time password, SMS verification code, and email verification code.


1. In the **Login to SealSuite** scenario card, enable secondary authentication.

2. In the pop\-up window, select a **Primary Authentication Method** and set an **Alternative MFA** as needed.

3. Set the following options as needed, and save the configuration.

&nbsp;

   
   |Configuration item |Description |
   |---|---|
   |Set allowlist |Specify employees, departments, or roles that do not trigger secondary authentication during login. |
   |Manual Disablement |Allow or prohibit employees from disabling login secondary authentication in the Portal. |
   


 &nbsp;

<span id="员工连接-vpn"></span>
### Connect to VPN

After this option is enabled, employees must complete secondary authentication when connecting to a VPN. Desktop clients support Windows, macOS, and Linux. Mobile clients support iOS, Android, and Harmony. The two client types have separate switches and authentication methods. The available methods are as follows.

&nbsp;


|Client |Available authentication methods |
|---|---|
|Desktop client |OTP, SMS verification code, email verification code, and push authentication. |
|Mobile client |SMS verification code and email verification code. |


<span id="配置步骤"></span>
#### Configuration steps


1. In **Authentication Scenarios** on the **Connect to VPN** card, enable the **Desktop** or **Mobile** switch.

2. In the pop\-up window, select a **Primary Authentication Method**, set an **Alternative MFA** as needed, and click **Confirm**.

   The alternative method cannot be the same as the primary method. For desktop clients, you can select another available method. For mobile clients, you can select the other verification code method or leave the alternative method unset.

   **Note:**  For mobile clients, if the SMS or email service is not configured, the corresponding authentication method cannot be selected. Click **Configure** to complete service configuration, and then select the method.

3. Click **Edit** next to **Authentication Frequency**, set the authentication validity period, and save the configuration.

4. To enable authentication for the other client type, repeat steps 1–2.

   After authentication is enabled, click **Edit** next to the corresponding client in **Authentication method** to modify the configuration.


<span id="生效规则"></span>
#### How the settings take effect


* **Primary and alternative methods:**  The primary method is used first, and the alternative method is available for employees to switch to. Employees only need to pass verification with one of the methods.

* **Authentication Frequency**: When set to **Every time**, authentication is required for every connection. When set to a specified duration, employees do not need to repeat authentication for this scenario if they reconnect within the validity period after successful authentication. Desktop and mobile clients share this validity period setting, but authentication must be completed separately. For example, after verification succeeds on a computer, verification is still required when the employee connects to a VPN on a mobile phone for the first time.

* **Mobile client verification codes:**  When authentication is triggered, the system automatically sends the verification code for the primary method. Employees can also switch to the configured alternative method. If the phone number or email address corresponding to the primary method is missing, the system tries to use an available alternative method. If no method is available, employees cannot complete authentication or connect to the VPN.


<span id="移动端配置效果"></span>
#### Mobile client example

The following example uses **SMS Verification Code** as the primary method, **Email Verification Code** as the alternative method, and **Authentication Frequency** set to **2 hours**. It applies when no Dynamic Control rule that requires reauthentication is matched:


* When an employee connects to a VPN for the first time, the employee can connect after entering the SMS verification code to complete authentication.

* After authentication succeeds, the employee can reconnect to the VPN within 2 hours without repeating authentication.

* If the employee has both a phone number and an email address linked to their account, the employee can switch to email verification to complete authentication. If the employee has only an email address linked to their account, the employee uses the email verification code to complete authentication.


If the primary method is set to **Email Verification Code**, the employee uses the email verification code for authentication during the first connection. After authentication succeeds, the configured authentication validity period also applies.

<span id="与动态控制配合使用"></span>
#### Use with Dynamic Control

To require VPN secondary authentication for specific employees or risk scenarios, configure [Dynamic Control rules](https://docs.byteplus.com/en/docs/SealSuite/docs-dynamic-policies).

When a mobile client matches a Dynamic Control rule that requires secondary authentication, the mobile primary and alternative methods saved on this page are used. Even if the mobile authentication switch on this page is disabled, Dynamic Control rules can still require authentication. If employees still frequently receive authentication requests within the authentication validity period, check the related rules.

For example, set **Authentication Frequency** to **2 hours** for all employees, and configure a Dynamic Control rule that executes **Require MFA** during VPN connection for employees who require stronger verification. The effective behavior is as follows:


* Employees who match the rule must complete secondary authentication every time they connect to a VPN. The authentication methods are the mobile primary and alternative methods saved on this page.

* After an employee is removed from the effective scope of the rule, authentication returns to the 2\-hour authentication validity period if no other rule requiring secondary authentication is matched.

* Administrators can view triggers and remediation records for the corresponding Dynamic Control rule group.


<span id="员工连接代理"></span>
### Employee Proxy

After this option is enabled, employees must complete authentication when enabling proxy mode on desktop clients (Windows, macOS, and Linux). OTP, SMS verification code, email verification code, and push authentication are supported.


1. In the **Employee Proxy** scenario card, enable secondary authentication.

2. In the pop\-up window, select a **Primary Authentication Method** and an **Alternative MFA**, and save the configuration.

3. Set **Authentication Frequency** to specify the authentication validity period.


 &nbsp;

<span id="员工获取入网凭证"></span>
### Employees obtain network access credentials

After this option is enabled, employees must complete authentication when viewing Wi\-Fi or wired network passwords, or when configuring network access credentials with one click on a desktop client or browser. OTP, SMS verification code, and email verification code are supported.


1. In the **Employees can view network access credentials (Wi\-Fi, Wired)**  scenario card, enable secondary authentication.

2. In the pop\-up window, select a **Primary Authentication Method** and an **Alternative MFA**, and save the configuration.

3. Set **Authentication Frequency** to specify the authentication validity period for obtaining network access credentials.
