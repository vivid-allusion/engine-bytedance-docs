This topic describes how to upload and mount input files in ModelArk Managed Agents, manage file resources while a session is running, and query artifacts generated by agents.

Managed Agents supports mounting files uploaded through [Files API tutorial](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/file-api) or [TOS](https://docs.byteplus.com/en/docs/tos/docs-what-is-tos), and then mounting them as session resources into a sandbox environment directory. Agents can read these input files and write final artifacts to `/mnt/session/outputs/`.

> **Note**

> Before mounting TOS files, make sure TOS and Managed Agents are under the same BytePlus account.

## Upload a file

You can use the Files API or TOS to upload files that need to be read by agents.

* **Use the Files API**:

   First upload the local file to the Files API. After the upload succeeds, the platform returns a `file_id`. You need to use this ID when creating a session or adding file resources to a running session later.

   > **Tip**

   > Set `purpose=agent` to specify that the file is for agent use.

   ```Bash
   file=$(
     curl -sS --fail-with-body "https://ark.ap-southeast.bytepluses.com/api/v3/files" \
       -H "Authorization: Bearer $ARK_API_KEY" \
       -F 'purpose=agent' \
       -F 'file=@path/of/your/file'
   )
   
   FILE_ID=$(jq -er '.id' <<<"$file")
   
   echo "File ID: $FILE_ID"
   ```

## Mount files when creating a session

When creating a session, declare the files to mount in the `resources` array.

> **Tip**

> You can also create a session on the [Sessions page](https://ai.byteplus.com/ark/region:ap-southeast-1/managed-agents/sessions?projectName=default).

* **Mount by file ID**:

Each file resource must include at least `type` and `file_id`.

`mount_path` is optional. We recommend setting `mount_path` so that agents can access files from a stable, readable path. If you do not explicitly specify a path, make sure the uploaded file name is clear enough for agents to identify the file purpose.

```bash
session=$(
  curl -sS --fail-with-body "https://ark.ap-southeast.bytepluses.com/api/v3/sessions" \
    -H "Authorization: Bearer $ARK_API_KEY" \
    -H "Content-Type: application/json" \
    -d @- <<EOF
{
  "agent": "$AGENT_ID",
  "environment_id": "$ENVIRONMENT_ID",
  "resources": [
    {
      "type": "file",
      "file_id": "$FILE_ID",
      "mount_path": "target/mounting/path/of/the/file"
    }
  ]
}
EOF
)

SESSION_ID=$(jq -er '.id' <<<"$session")

echo "Session ID: $SESSION_ID"
```

> **Tip**

> `mount_path` is the target mount path in the cloud sandbox. Files passed through `file_id` are mounted to the `/mnt/session/uploads/` directory according to the specified path.

> If you specify the path `my-skills/skill-1.md` when mounting, the mounted file path is `/mnt/session/uploads/my-skills/skill-1.md`.

After mounting, the platform generates a new `file_id` for the file instance in this session. These in\-session copies do not count toward the user's file storage quota.

* **Mount from TOS**:

```bash
session=$(
  curl -sS --fail-with-body "https://ark.ap-southeast.bytepluses.com/api/v3/sessions" \
    -H "Authorization: Bearer $ARK_API_KEY" \
    -H "Content-Type: application/json" \
    -d @- <<EOF
{
  "agent": "$AGENT_ID",
  "environment_id": "$ENVIRONMENT_ID",
  "resources": [
    {
      "type": "tos",
      "tos_bucket": "<BUCKET_NAME>",
      "tos_key": "path/of/the/tos/directory/"
    }
  ]
}
EOF
)

SESSION_ID=$(jq -er '.id' <<<"$session")

echo "Session ID: $SESSION_ID"
```

> **Tip**

* > `tos_key` must be a directory in the TOS bucket and must end with `/`. For example, `project-resources/`.

* > Files are mounted to the `/mnt/session/storage/` directory in the cloud sandbox.

## Mount multiple files

If a task requires multiple input files, you can add multiple entries to `resources`. A single session supports mounting up to 100 files.

The following example uses file ID:

```json
{
  "resources": [
    { "type": "file", "file_id": "<FILE_ID_1>" },
    { "type": "file", "file_id": "<FILE_ID_2>" },
    { "type": "file", "file_id": "<FILE_ID_3>" }
  ]
}
```

## Add and query files while a session is running

After a session is created, you can continue to add files and query currently mounted resources through the Session Resources API.

The following example continues to use `$SESSION_ID` written after creating the session above. When adding a Files API file, it also continues to use `$FILE_ID` written during the upload step.

### Add file resources

```bash
resource=$(
  curl -sS --fail-with-body "https://ark.ap-southeast.bytepluses.com/api/v3/sessions/$SESSION_ID/resources" \
    -H "Authorization: Bearer $ARK_API_KEY" \
    -H "Content-Type: application/json" \
    -d @- <<EOF
{
  "type": "file",
  "file_id": "$FILE_ID"
}
EOF
)

RESOURCE_ID=$(jq -er '.id' <<<"$resource")

echo "Resource ID: $RESOURCE_ID"
```

### Query file resources

```Bash
# List session resources
curl -sS --fail-with-body "https://ark.ap-southeast.bytepluses.com/api/v3/sessions/$SESSION_ID/resources" \
  -H "Authorization: Bearer $ARK_API_KEY"
```

> **Tip**

> Only adding and querying file resources are currently supported; updating or removing mounted resources is not supported. To change the set of mounted files, create a new session and mount only the files that are still needed.

## Get session runtime artifacts

After the agent writes the files to deliver to `/mnt/session/outputs/`, the platform registers these files as files with `purpose=agent` under the current session. When you need to display or download artifacts such as reports, images, videos, documents, or code in your service, get them through the Files API:

1. Call `GET /files?scope_id=<session_id>&purpose=agent` to query the agent artifacts of the session by page.

2. Get the file ID, file name, file size, MIME type, and `download_url` from the list response.

3. Use `download_url` to download the file content.

```Bash
# List files associated with a session.
curl -sS --fail-with-body \
  "https://ark.ap-southeast.bytepluses.com/api/v3/files? scope_id=$SESSION_ID&purpose=agent" \
  -H "Authorization: Bearer $ARK_API_KEY"
```

> **Tip**

> `scope_id` only filters output artifacts that have been registered as `purpose=agent` under the current session. It does not include input file copies mounted to `/mnt/session/uploads/` through `resources`, nor does it perform a directory scan on user TOS objects in `/mnt/session/storage/`. To query mounted input files, call [List session resources](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/list-resources-api).

The `download_url` in the list response is a presigned download URL issued by the server and is time\-limited.

Before creating a session, choose a storage method based on the artifact retention requirements:

|Your configuration |Artifact location |What you need to do |
|---|---|---|
|Do not configure `config.tos` |ModelArk managed TOS bucket |You need to download the required files before the platform TTL expires. When a session is deleted, the platform cleans up associated artifacts in the default storage. |
|Configure `config.tos` in environment or session overrides |Your TOS bucket. When the platform registers artifacts from the outputs directory, the Files API writes them with the prefix `{prefix}outputs/{env-id}/{session-id}/`; the final object path is based on `tos.object_key` in the response. |Manage the object lifecycle in TOS. Deleting a session does not delete objects in the bucket. |

For details about how to configure environment artifact storage and temporary overrides by session, see [Configure artifact storage](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/configure-cloud-environment#configure-output-storage) and [Override output storage](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/start-session#override-output-storage).

> **Tip**

> Configure `config.tos` when you need to save agent artifacts. Its value is the storage location of output artifacts registered by the Files API. Configure `type: tos` in `resources` when you need to mount input or shared data. This corresponds to `/mnt/session/storage/` in the sandbox.

## Supported file types

Agents can process multiple file types. Common types include:

* Source code files, such as `.py`, `.js`, `.ts`, `.go`, `.rs`, etc.

* Data files, such as `.csv`, `.json`, `.xml`, and `.yaml`.

* Text documents, such as `.txt` and `.md`.

* Archive files, such as `.zip` and `.tar.gz`; the agent can process them after extracting them with bash in the sandbox.

* Binary files; whether they can be processed correctly depends on whether the corresponding tools are available in the sandbox.

## Usage tips

* Files mounted to the sandbox are read\-only copies. The agent can read these files, but cannot directly modify the original uploaded files.

* If the task needs to produce a modified version, write the result to a new path in the sandbox.

* For output files that need to be returned, require the agent to write them to `/mnt/session/outputs/` in the task instructions. For long\-term storage, configure your own TOS bucket for the environment and manage the object lifecycle in TOS.

* Before creating a session, confirm the input files required for the task. Mounted file resources cannot be removed while the session is running.
