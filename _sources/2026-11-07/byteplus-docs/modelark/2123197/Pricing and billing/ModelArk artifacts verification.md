## 1. Overview

ModelArk provides official artifact verification APIs to query the model version associated with image or video artifacts generated by the ModelArk platform.

> **Note**

> This feature analyzes identifiable technical characteristics in images and videos to provide clues about their source. Query results are for reference only and do not constitute official certification, legal authentication, or ownership determination.

## 2. Enablement

To enable this feature, go to **ModelArk Console** \> **Model Activation** \> [Application Component Library](https://ai.byteplus.com/ark/region:ap-southeast-1/openManagement?&advancedActiveKey=component&tab=Application). You can use trial package to try it out for free.

> You can view your account type on the [Account management - Basic information](https://console.byteplus.com/user/basics/) page.

## 3. Guide

### 3.1 Verify artifacts using the API

The artifact verification APIs require [Access Key authentication](https://docs.byteplus.com/en/docs/byteplus-platform/docs-creating-an-accesskey) and use asynchronous queries.

> For detailed information about the APIs, see the API references for [CreateArkOfficialResultQuery](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/create-ark-official-result-query-api) and [GetArkOfficialResult](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/get-ark-official-result-api).

1. **Submit a query task**: Call the `CreateArkOfficialResultQuery` API to create a query task, upload the image or video artifact file, and obtain the task `query_id`.

2. **Get the result**: Call the `GetArkOfficialResult` API to retrieve the query result. Use the returned `query_id` to poll for the processing status and final recognition result, including whether the artifact was generated by the ModelArk platform, the model version, and the resource type.

> **Note**

> The final analysis result may be affected by compression, transcoding, editing, or other secondary processing applied to the artifact. We recommend using the original file without secondary processing for verification.

### 3.2 Supported scope and rate limits

* **Supported model versions for artifact verification**:

   * **Image generation**: Seedream 5.0 series and later models.

   * **Video generation**: Seedance 2.0 / 2.0 fast / 2.0 mini series and later models.

* **Query time limit**: Supports queries for artifacts generated within the last **30 days**.

* **Upload file limits**:

   * **Images**: File size ≤ 20 MB. Supported formats: `png`, `jpg` (`jpeg`), `heic`, and `webp`.

   * **Videos**: File size ≤ 100 MB. Supported formats: `mp4`, `mov`, and `avi`.

* **Account\-level rate limits**:

   * Maximum calls per day: **1000**

   * Single\-account QPS: **1**

## 5. FAQ

**Q1. What does "Technical characteristics related to ModelArk artifacts were detected" mean?**

This indicates that the artifact you submitted was very likely generated by ModelArk. In this case, the API identified technical characteristics associated with the ModelArk generation process in the artifact and parsed the corresponding model version information. Matches based on these characteristics are generally highly reliable.

> **Note**

* > This result only indicates that the artifact itself may have been generated by ModelArk. It does not constitute official certification, legal authentication, or ownership determination.

* > This result cannot assess whether the content shown in the image or video is truthful or accurate, and cannot determine whether the visual information is misleading.

* > This result cannot confirm whether the artifact was edited, modified, or forwarded after it was created.

**Q2. What does "No obvious technical characteristics related to ModelArk artifacts were detected" mean?**

This indicates that the API completed recognition of the submitted artifact, but did not find technical characteristics associated with the ModelArk generation process.

A "no hit" result does not necessarily mean that the artifact was not generated by ModelArk. Possible reasons include:

* The traceability information in the artifact was affected during transmission or post\-processing: Various forms of processing or rework during distribution may affect the traceability characteristics that the artifact carries, which in turn affects recognition.

* The artifact was generated earlier than the current time range covered by the API: Some older artifacts did not include traceability information recognizable by this API when they were generated.

* The artifact was generated by a model that is not covered by this feature: This API currently covers only the ModelArk models listed in [Supported scope and rate limits](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/verify_modelark_artifact#supported-artifacts-and-limits). Artifacts generated by ModelArk models outside this list or by non\-ModelArk models are outside the recognition scope.

**Q3. Can this feature identify whether image or video content is false or misleading?**

No. Successfully detecting relevant characteristics can only indicate that the artifact was generated by ModelArk. It cannot determine whether the information conveyed by the image or video is accurate, nor can it assess whether the depicted context is factual.

**Q4. Why can the model version sometimes be identified for the same image or video, while sometimes not?**

Model version recognition depends on the traceability characteristics available in the artifact. In general:

* Recognition is most stable when you use the original file generated by ModelArk directly.

* During transmission and post\-processing, the traceability characteristics may be affected, making recognition difficult.

If the same artifact repeatedly cannot be recognized, we recommend first checking whether you still have the original file.

**Q5. How are the uploaded images and videos handled?**

The files you upload are used only for this artifact source and model version query, and will not be used for model training.

To meet audit and compliance requirements, uploaded files are temporarily retained for no more than 24 hours after processing is completed and are then automatically deleted. Unless otherwise required by law, the files are not retained or used in any other way.

**Q6. How accurate are the query results? Can the returned results be used as legal evidence?**

Query results are generated based on automated analysis and are for reference only. They do not constitute official certification, legal authentication, or ownership determination. "No obvious technical characteristics related to ModelArk artifacts were detected" cannot be used as evidence that the artifact is not a ModelArk artifact, because traceability characteristics may be lost during transmission. Do not use the query results from this API for scenarios requiring legal validity, such as copyright ownership determination, authenticity verification, or compliance judgment.

**Q7. Why might the returned content be incomplete?**

* The task has not finished running: The query task is asynchronous. When `status = running`, only `query_id` and `status` are returned. Read business fields such as `is_official` and `model_name` only when `status = succeeded`.

* The artifact exceeds the query time limit:

   * `is_official` / `model_name`: Only artifacts generated within the last 30 days are supported.

   * `resolution`: Only artifacts generated on or after July 21, 2026 are supported, and the query must be made within 7 days after generation.
