## Managed Agents error codes

This section lists the error codes for Managed Agents related APIs. Managed Agents errors are divided into two types by delivery channel:

* **HTTP stage error codes**: Returned synchronously by the HTTP request, with an HTTP status code and a structured error body. This applies to all synchronous APIs, such as POST create and POST events.

* **SSE stage error codes**: After the request enters the event stream, the server delivers the error through a `data.type = "session.error"` event. There is **no HTTP status code**. This appears only in `RunFailed` / `SessionError` and SSE resume/lag scenarios.

### SSE stage error codes

Errors that occur after the request enters the event stream are sent through the established SSE channel as `data.type = "session.error"` events, **without an HTTP status code**. They occur only in the following scenarios: runtime determines `RunFailed` / `SessionError`, or the SSE resume / lag channel itself has an error. Event example (SSE wire format, snippet):

```text
...

id: sevt-...
data: {"type": "session.error", "id": "sevt-...", "processed_at": "2026-07-17T15:02:00+08:00", "error": {"type": "unknown_error", "message": "Tool execution failed due to a runtime issue."}}

...
```

The JSON payload after `data:` is expanded as follows:

```json
{
  "type": "session.error",
  "id": "sevt-...",
  "processed_at": "2026-07-17T15:02:00+08:00",
  "error": {
    "type": "unknown_error",
    "message": "Tool execution failed due to a runtime issue."
  }
}
```

**Client classification rule**: Use `error.type` as the only parameter for programmatic classification. All branches carry this parameter.`error.message` is only for display and is not used for programmatic classification.

|error.type |Meaning |
|---|---|
|model_overloaded_error |Typed branch. It does not carry `error.code`. The upstream model is overloaded. |
|model_rate_limited_error |Typed branch. It does not carry `error.code`. The model triggered rate limiting. |
|model_request_failed_error |Typed branch. It does not carry `error.code`. The model request failed, such as when the upstream returns 5xx or connection establishment fails. |
|billing_error |A variant specific to `SessionError`. It does not carry `error.code`. Billing\-related error. |
|unknown_error |Multiple fatal scenarios that have not yet converged to a typed branch currently fall under this type. Use the context and logs for further troubleshooting. Possible scenarios include:<br><br><br>* The provider snapshot or provider HTTP call fails, and runtime enters `RunFailed` after exhausting retries;<br><br>* A turn\-level fatal error occurs during tool service execution, such as no response from exec, failure to decode a 2xx response, or abnormal termination of the foreground bash stream. HTTP non\-2xx during exec is usually handled by the model as a model\-visible tool error and **does not enter the ** **`session.error`** ** channel**;<br><br>* A fatal error occurs during MCP tool execution;<br><br>* The request is invalid after the command enters runtime. The validation rules in the POST stage do not apply to this stage. Do not reuse the decision rules for codes with the same name;<br><br>* Runtime protocol mismatch;<br><br>* Kernel turn occupied;<br><br>* Runtime internal error;<br><br>* Credential host unreachable. The typed schema has been declared, but the `vault_id` / `credential_id` parameters have not yet been completed, so it currently still falls under `unknown_error`;<br><br>* The SSE resume position is outside the retention window. This is a stream error and is unrelated to runtime, tool, or provider;<br><br>* The subscriber is disconnected by the server because consumption lags behind. This is a stream error. |
