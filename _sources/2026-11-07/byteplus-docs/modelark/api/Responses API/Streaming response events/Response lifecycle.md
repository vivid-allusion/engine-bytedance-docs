When you create a response with `stream` set to `true`, the server sends Server\-Sent Events (SSE) as the response is generated. This topic describes the response lifecycle from creation to completion or failure.

> **tip**

> For streaming request and response examples, see [Streaming output](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/streaming-output).

## Response lifecycle

### response.created

> Event triggered when the response is created.

**response** `object`  |  Response object

`response.created.response`

Response in created status. The included parameters are consistent with the parameters returned by non\-streaming calls.

**created_at** `integer`  |  Creation timestamp

`response.created.response.created_at`

The Unix timestamp (in seconds) when this response was created.

**id** `string`  |  Response ID

`response.created.response.id`

The unique identifier of this response. You can use it to query, continue, or delete the response later.

**model** `string`  |  Model ID

`response.created.response.model`

The model identifier used to generate this response. This echoes the `model` parameter in the request.

**object** `string`  |  Object type

`response.created.response.object`

The type identifier of the returned object, used to distinguish response object types.

Value is fixed to `response`.

**output** `object[]`  |  Output content

`response.created.response.output`

The list of items produced by the model in this response, ordered by generation sequence. It may include different types of items, such as messages, tool calls, and reasoning.

Message output `object`

Message output generated by the model, including text content.

**content** `object[]`  |  Output content

`response.created.response.output.content`

Output content list.

The final answer text generated by the model.

**type** `string` `Default output_text`  |  Type

`response.created.response.output.content.type`

The content type discriminator parameter is used to distinguish union variants.

Value is fixed to `output_text`.

**annotations** `object[]`  |  Annotation list

`response.created.response.output.content.annotations`

List of annotation information attached to the text (such as citation sources).

**text** `string`  |  Text content

`response.created.response.output.content.text`

Text content generated by the model.

Unique identifier of the output item.

Role of the message sender.

**status** `string`  |  Status

* `completed`: The message generation is completed.

* `failed`: The message generation failed.

**type** `string`  |  Type

`response.created.response.output.type`

Type identifier of the output item.

Value is fixed to `message`.

**partial** `boolean`  |  Incremental chunk

`response.created.response.output.partial`

Whether this is a streaming incremental chunk.

**phase** `string`  |  Message phase

`response.created.response.output.phase`

Indicates whether an assistant message is intermediate commentary or the final answer. When replaying historical assistant messages, we recommend preserving this parameter and passing it back unchanged. Options: `commentary`, `final_answer`.

**effort** `string`  |  Reasoning effort

`response.created.response.reasoning.effort`

Limits the amount of reasoning work. Reducing the reasoning depth can increase speed and reduce token consumption.

* `none`: Turn off reasoning.

* `minimal`: Turns off reasoning and answers directly.

* `low`: Light reasoning, focused on fast responses.

* `medium`: Balanced mode, considering both speed and depth.

* `high`: Deep analysis for handling complex problems.

* `xhigh`: Higher level of reasoning.

* `max`: Maximum level of reasoning, suitable for highly difficult reasoning tasks.

> **Note**

> For models that support this parameter, default values, parameter compatibility mapping rules, and the relationship with the `thinking.type` parameter, see [Deep reasoning](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/responses-api-deep-thinking#dc4c1547).
