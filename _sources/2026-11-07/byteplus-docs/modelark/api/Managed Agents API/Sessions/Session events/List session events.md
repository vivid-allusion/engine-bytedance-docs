`GET https://ark.ap-southeast.bytepluses.com/api/v3/sessions/{session_id}/events`

Paginate through events that have been generated in the main session thread, and return events in sub\-agent threads that require client handling. Filtering by event processing time and event type is supported. The return scope is as follows:

* Events in the main session thread are returned in full.

* For sub\-agent threads, lifecycle events, collaboration messages, custom tool calls, and tool authorization events that require client handling are returned.

* Built\-in tool calls that the host needs to execute in a self\-hosted environment are also returned.

Thoughts, regular replies, spans, and preview frames in sub\-agent threads are not fully expanded by this API, and tool execution results generated by the server are not expanded either. Use [List thread events](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/list-thread-events-api) to query them. Tool results and tool authorization replies sent back by the client are still returned, so you can verify whether the results have been delivered.

> **Tip**

* > By default, events are returned in ascending order by the time they are generated (oldest to newest).

* > Thread\-related events use `session_thread_id` to identify the thread they belong to.

* > A self\-hosted worker sends back built\-in tool results by `tool_use_id` and does not depend on `session_thread_id`.

* > To receive events in real time, use [Stream session events](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/stream-events-api).

* > Returned parameters vary by event type. For details, see [Session event structure reference](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/sessions-events-reference-v2).

## Authentication

This API supports the following authentication method(s). For details, see [Base URL and authentication](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/base-url-and-authentication).

* API Key authentication. Go to the [API Key Management](https://ai.byteplus.com/ark/region:ap-southeast-1/apiKey) page. Obtain a long\-lived API key.

## Request parameters

### Path parameters

**session_id** `string` `Required`  |  Session ID

Enter the ID of the session whose events you want to query, in the format `sesn-...`.

### Query parameters

> Passed as URL query string.

**created_at[gt]**  `string`  |  Start time (exclusive)

The start boundary (exclusive) of the event processing time, in RFC 3339 format. When multiple time boundaries are provided, only events that meet all boundary conditions are returned.

**created_at[gte]**  `string`  |  Start time (inclusive)

The start boundary (inclusive) of the event processing time, in RFC 3339 format. When multiple time boundaries are provided, only events that meet all boundary conditions are returned.

**created_at[lt]**  `string`  |  End time (exclusive)

The end boundary (exclusive) of the event processing time, in RFC 3339 format. When multiple time boundaries are provided, only events that meet all boundary conditions are returned.

**created_at[lte]**  `string`  |  End time (inclusive)

The end boundary (inclusive) of the event processing time, in RFC 3339 format. When multiple time boundaries are provided, only events that meet all boundary conditions are returned.

**limit** `integer` `Default 50`  |  Events per page

Number of events returned per page.

> **Tip**

> When `limit` is greater than 200, the server processes it as 200 and does not return a parameter error.

**Range**: `[1, 200]`

**order** `string` `Default asc`  |  Sort order

Sort order. `asc` sorts by event generation time in ascending order (oldest to newest), and `desc` sorts in descending order.

**page** `string`  |  Next page identifier

Next page identifier. Pass the `next_page` returned from the previous page as is; if omitted, pagination starts from the first page.

**types** `string[]`  |  Event type filter

Filter by event type. You can pass this parameter multiple times, for example, `types=user.message&types=agent.message`. For supported values, see [Session event structure reference](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/sessions-events-reference-v2).

## Response parameters

**data** `object[]`  |  Event list

This API returns events from the main session thread. The return scope is as follows:

* Events in the main session thread are returned in full.

* For sub\-agent threads, lifecycle events, collaboration messages, custom tool calls, and tool authorization events that require client handling are returned.

* Built\-in tool calls that the host needs to execute in a self\-hosted environment are also returned.

Each event object contains `id`, `type`, `processed_at`, and business parameters that vary by `type`.

`session_thread_id` is returned only when it is explicitly included in the corresponding event structure. Regular messages in the main thread of the session usually do not contain this parameter.

For the complete event types and parameter structures, see [Session event structure reference](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/sessions-events-reference-v2).

**id** `string`  |  Event ID

`data.id`

Unique event identifier, in the format `sevt-...`.

**processed_at** `string`  |  Processing time

`data.processed_at`

Event processing time in RFC 3339 format

**type** `string`  |  Event type

`data.type`

Event type (such as `user.message`, `agent.message`, `session.status_idle`, and so on).

**next_page** `string`  |  Next page identifier

Next page identifier. Pass it as is to the `page` parameter of the next request. This parameter is not returned when there is no more data.
