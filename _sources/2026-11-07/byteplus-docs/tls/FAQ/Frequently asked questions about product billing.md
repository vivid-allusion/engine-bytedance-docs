## How to delete data within a log topic?

You need to delete data by modifying the **Log storage period** in the log topic. When the data retention time reaches the **Log storage period** that you have set, the data will be deleted. For detailed steps, please refer to [Modify log storage time](https://docs.byteplus.com/docs/tls/Managing_topics#.5L-u5pS55pel5b-X5a2Y5YKo5pe26Ze0).

## How to stop billing for TLS?

After enabling TLS, if you no longer need to use TLS, you can clear TLS resources to stop billing.

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">If a project contains resources such as log topics and log data, deleting the project on the day of deletion will still incur related fees, including log storage and Shard rental. Deleted expense details generated on the current day can be viewed in the bill received the next day.</div>

### Cloud product logs

For projects and log topics related to cloud product logs, including the following situations, please assess based on your specific circumstances.


* It is recommended to disable the logging feature in the corresponding cloud product console, and then delete the corresponding project and log topic in the TLS console.

* You must first disable the logging feature in the corresponding cloud product console before you can delete the corresponding project and log topic in the TLS console.

* After the logging feature is disabled in the corresponding cloud product console, the system will automatically delete the corresponding project and log topic.


Relevant reference documents are as follows:


1. Disable the logging feature in the corresponding cloud product console. For detailed steps, please refer to the [Cloud product log collection guide](https://docs.byteplus.com/docs/tls/cloud_logs_overview).

2. Delete log topics. For detailed steps, refer to [the Delete log topic](https://docs.byteplus.com/docs/tls/Managing_topics#.5Yig6Zmk5pel5b-X5Li76aKY).

3. Delete project. For detailed steps, refer to [Delete project](https://docs.byteplus.com/docs/tls/Managing_projects#.5Yig6Zmk5pel5b-X6aG555uu).

### Service logs

Service logs are used to record status information, behavioral data of business operations, and other information during the operation of various functions of TLS. Projects and log topics generated by the service log feature cannot be deleted. You can disable the service log feature and wait for the log data to expire and be deleted.

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">Log resources generated by service logs do not incur any storage fees.</div>

## Does querying and analyzing logs generate read traffic?

TLS supports querying or analyzing logs through the console or API, and neither method generates read traffic or incurs related charges.

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>



* <div data-tips="true" data-tips-type="tip">Public network read traffic for TLS refers to the downstream traffic generated when data is accessed via the TLS public network domain name. This includes activities such as downloading logs over the public network and consuming logs via programs over the public network, both of which generate public network read traffic.</div>


* <div data-tips="true" data-tips-type="tip">Intranet read traffic for TLS refers to the downstream traffic generated when data is accessed through the TLS intranet domain name. This includes actions such as downloading logs via the intranet or consuming logs through applications over the intranet, both of which generate intranet read traffic.</div>

## How to reduce the cost of index traffic?

Index traffic is billed based on the data volume before compression, and the associated resource and cost consumption is higher than that of other billing items. You can refer to the following methods to optimize index configuration and reduce index traffic costs.


|Optimization solutions |Description |
|---|---|
|Disable full\-text index, enable key\-value index |For scenarios where both full\-text index and field index are enabled, it is recommended to disable the full\-text index to reduce costs. The reasons are as follows:<br><br><br>* Key\-value index can also be used for query and analysis in multiple scenarios.<br><br>* Compared with the key\-value index, the full\-text index will generate greater index traffic.<br><br>   In the full\-text index, both field names and field values are stored as the "text" type, and both generate index traffic. In a key\-value index, fields of the long and double types do not generate index traffic for their field names, and each field value of these types occupies 8 bytes in the index. |
|Index only the necessary fields |Specify the fields used for query and analysis, and set the key\-value index only for these fields. |

## How to reduce data storage costs?

You can optimize data storage costs in the following ways.


* Shorten data storage duration and delete data that is no longer needed. For detailed steps, please refer to [Modify log storage time](https://docs.byteplus.com/docs/tls/Managing_topics#.5L-u5pS55pel5b-X5a2Y5YKo5pe26Ze0).

   Before deleting data, you can download it to your local device or upload it to TOS for storage. For detailed steps, refer to [Download logs](https://docs.byteplus.com/docs/tls/Download-logs-2), [Deliver in JSON format](https://docs.byteplus.com/docs/tls/ship_log_in_json_format), and [Deliver in CSV format](https://docs.byteplus.com/docs/tls/ship_log_in_csv_format).

* Enable low\-frequency storage. For detailed steps, please refer to [Create log topic](https://docs.byteplus.com/docs/tls/Managing_topics#.5Yib5bu65pel5b-X5Li76aKY).

## Why are the fees for indexing, delivery, and processing traffic several times higher than read/write traffic fees?

In TLS, index traffic, delivery traffic, and processing traffic are calculated based on the volume of uncompressed data, while read and write traffic are calculated based on the volume of compressed data. For example, when creating a delivery task, if the original data is 10GB and the compression rate is 20%, the compressed data size is 2GB. In this case, the delivery traffic is 10GB, and the read/write traffic is 2GB.

## Does a JSON subfield without an index generate index traffic?

JSON subfields without indexes in JSON\-type fields will generate index traffic.

The specific reasons are as follows:

After creating an index for a JSON\-type field, both the field names and field values, including child nodes, will generate index traffic. Among them,


* If no index is created for a JSON subfield, and this subfield is the value of a JSON type field, TLS calculates the index traffic as text type.

* When JSON subfield is indexed, TLS calculates index traffic based on the data type of subfield, such as text, long, and double type.

## Why do I still receive bills after deleting all TLS resources?

On the day you delete all TLS resources, TLS will calculate resource usage from `00:00` to the time of deletion, and will send you the related bill on the following day.

## Why is there an order from the Shanghai Region when activating the TLS for the first time?

East China 2 (Shanghai) is the central region for TLS. When TLS is enabled for the first time, TLS will simultaneously create a zero\-cost order in the Shanghai region. Order type: New purchase, configuration details: `TLS Standard Edition - Pay-as-you-go - Shanghai`.

You do not need to pay attention to the order region for the first launch; simply ensure that log data is uploaded to the correct target Region.

## Why do I receive bills without using the TLS?

TLS will send the bill for the corresponding expenses to your BytePlus account on the day after the charges are incurred. You can view TLS bills in the Billing Center. You can view the consumption details for TLS in the bill, where the billing unit column indicates the items that actually incur charges. Typically, scenarios where TLS is not used but there is still usage and consumption include the following:


* Note: Charges for the number of log shards are incurred because there are log topics under your TLS account for the billing date. TLS bills based on the number of shards in a log topic. If you no longer need to use TLS, it is recommended to delete these log topics and delete all TLS resources.

* Note: Additional charges, such as log storage space, are charged. This means that log data still exists in your TLS account during the billing period. If you have cleared all resources and data, no charges will be incurred on the following day.
