This topic describes how to monitor the status of LogCollector through Torch Log Service(TLS) Alarm function.

<span id="7dfc502c"></span>
## Background information

After enabling the LogCollector service log function in the creation of a machine group, TLS will record the status logs generated by LogCollector and store them in the `ls_log-collector-status` topic under the `tls_service-project` project. The LogCollector status logs record information such as the LogCollector version number, CPU usage, the number of log entries sent, the number of failed send requests, and files being bound to multiple collection configurations. For more information, please refer to the [LogCollector status logs](https://docs.byteplus.com/docs/tls/service_log_fields#logcollector-%E7%8A%B6%E6%80%81%E6%97%A5%E5%BF%97).

You can create alarm tasks based on these fields to monitor the status of LogCollector.

<span id="172cb0d9"></span>
## An alert for a file bound to multiple collection configurations

By default, a log file can only correspond to one collection configuration. If there are multiple collection configurations pointing to the same file, the system will follow the most recent collection configuration, and all other collection configurations will become invalid. This means that the logs within the log file will only be collected into the topic specified by the latest collection configuration.

To help you monitor this situation, the LogCollector service logs provide the `DuplicateFilePathCnt` field, which is used to determine whether a log file has been bound to multiple collection configurations. When the value of the `DuplicateFilePathCnt` field is greater than 0, it indicates that there is a log file that has been bound to two or more collection configurations. By monitoring the `DuplicateFilePathCnt` field through the alarm feature, you can promptly detect and address the issue of a log file being bound to multiple collection configurations.


1. Log on to the [TLS console](https://console.byteplus.com/tls).

2. In the top navigation bar, select the region where TLS is located.

3. In the left\-side navigation pane, choose **Common functions** \> **Log alarm \> Alarm policy**.

4. On the upper\-left corner of the page, click **Create alarm policy**.

5. Specify **Basic information** for the alarm policy.

   The detailed description of alarm policy configuration, please refer to [Create alarm policies](https://docs.byteplus.com/docs/tls/create_alarm_policies).

   1. Set up basic information.

      Set the **alarm policy name** and **Project**, with the **Project** selected as `tls_service -project`.

   2. Set up monitoring tasks.

6. Received an alarm notification.

   You will receive an alert notification when there are log files specified by multiple capture configurations.

   You can open the query and analysis page for the `tls_log-collector-status` topic. On this page, under the original logs, you can view the names of the log files that have been bound to multiple collection configurations, as well as the information about the machines they are on.
