Torch Log Service (TLS) offers the console page embedding feature to allow you to embed query and analysis pages and dashboard pages of TLS resources into your self\-managed website. You can visit the specific pages of the TLS console in the external system without password and perform related operations. This document describes how to embed the TLS console into an external system.

<span id=".6IOM5pmv5L-h5oGv"></span>
## Background

TLS supports the security token service (STS) offered by Identity and Access Management (IAM) for custom identity proxy. To use the console page embedding feature, you must grant the IAM user that you use the permissions on the resources and pages that you want to access, and use the STS to create temporary credentials and get temporary tokens. When you access an embedded console page from a self\-managed web page, a temporary token encapsulated in the URL is used for authentication. This way, you enjoy a seamless logon experience without being required to provide the username or password of the IAM user. For more details, see [Use Security Token Service to access Torch Log Service](https://docs.byteplus.com/en/docs/tls/use_sts_access_tls)

## Procedure

<span id=".XzEt6I635Y-W5Li05pe25a6J5YWo5Luk54mM"></span>
### 1. Get a temporary STS token

To log on from a self\-managed system, you must use the BytePlus STS to issue a temporary token to the self\-managed system. To obtain a temporary STS token, the server of your self\-managed system uses the credentials of the configured IAM user to call AssumeRole for assuming the specified IAM role. The temporary STS token enables you to access the cloud resources on which the IAM role is granted permissions.


1. Create an IAM role.

2. Grant TLS permissions to the IAM role.

   To access pages of the TLS console from an external system, attach the `TLSReadOnlyAccess` system permissions policy to the IAM role. This grants the IAM role the permissions to view TLS resources and console pages. You can also create custom permission policies based on the list of authorizable actions and resources in TLS. For more information, refer to [Authorizable actions](https://docs.byteplus.com/docs/tls/Authorizable_actions) and [Authorizable resources](https://docs.byteplus.com/docs/tls/Authorizable_resources).

3. Create an IAM user.

4. Grant the IAM user the permission to assume the IAM role.

   1. Configure a trust policy for the IAM role to allow the IAM user to assume the role.

   2. Attach the `STSAssumeRoleAccess` policy to the IAM user.

5. Call [AssumeRole](https://docs.byteplus.com/en/docs/byteplus-platform/reference-assumerole) to obtain a temporary STS token.

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">The request parameter DurationSeconds of <a href="https://docs.byteplus.com/en/docs/byteplus-platform/reference-assumerole">AssumeRole</a> specifies the validity period of each temporary STS token. After a token expires, you must call AssumeRole to obtain a new token for requesting a sign\-in token.   </div>

### 2. Get a sign\-in token

A sign\-in token is a temporary access token generated by the STS. The server of the external system uses sign\-in tokens to create URLs for accessing TLS resources without the password of the IAM user used.

Call getSigninTokenWithSTS to get a sign\-in token. To call getSigninTokenWithSTS, set the values of the accessKeyId, secretAccessKey, and sessionToken request parameters to the corresponding values returned by [AssumeRole](https://docs.byteplus.com/en/docs/byteplus-platform/reference-assumerole).

<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>



* <div data-tips="true" data-tips-type="tip">The default validity period of each sign\-in token is 15 minutes, and the validity period cannot be changed. After a sign\-in token is generated, create an access URL and complete the authentication before the token expires. After the token expires, you must call getSigninTokenWithSTS again to get a new sign\-in token.</div>


* <div data-tips="true" data-tips-type="tip">Once a sign\-in token is used, it becomes invalid. After you refresh the page that you access, you must request a new sign\-in token for logging on again.</div>



Sample request:

```xml
https://console.byteplus-embed.com/api/passport/login/getSigninTokenWithSTS
                    &accessKeyId=<Temporary AccessKey ID returned by AssumeRole>
                    &secretAccessKey=<Temporary AccessKey Secret returned by AssumeRole>
                    &sessionToken=<Temporary token returned by AssumeRole>
                    &sessionDuration=<Validity period of the logon session. If it expires, log on again. Unit: seconds. Valid values: 900–43,200>
```

### 3. Create a URL for password\-free access

Create a URL for accessing a page of the TLS console without password\-based authentication as follows.

URL format:

```xml
https://console.byteplus-embed.com/api/passport/login/loginWithSigninToken?signinToken=${signinToken}&redirectURI=${target_console_url}
```


The following table describes the parameters included in the URL:


|Parameter |Description |

|signinToken |The sign\-in token returned by getSigninTokenWithSTS that is called in Step 2. |

### 4. Embed the specified console page into an external system

Embed the specified page of the TLS console into a self\-managed web page as an iFrame. The following sample code demonstrates how to embed a page of the TLS console into an external system. You must set the value of `src` to the URL created in Step 3.

```xml
<body>   
    <iframe src="target_url" width="1200" height="800" id="tlsIframePage"></iframe> 
</body>
```

### How to set logon session duration for an embedded page

After you log on to the embedded page of the TLS console in password\-free mode from your self\-managed system, the logon session remains for the specified period of time. After the logon session expires, the server of your self\-managed system must request a new token and use the new token to log on again.

The logon session duration is specified by the sessionDuration parameter of the getSigninTokenWithSTS API operation. When you call getSigninTokenWithSTS, specify the logon session duration of the embedded page with the sessionDuration parameter. The session duration is measured in seconds. Valid values: 900–43,200.

By default, the sessionDuration parameter inherits the value of for the DurationSeconds parameter configured in the AssumeRole request. The default value of DurationSeconds is 1 hour. This means that the value of the ExpiredTime parameter returned by AssumeRole indicates the expiration time of both the temporary STS token and the logon session.
