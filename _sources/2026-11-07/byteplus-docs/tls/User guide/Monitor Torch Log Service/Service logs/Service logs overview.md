BytePlus Torch Log Service (TLS) supports product\-level service logs that record the status information and business behavior data of each TLS feature in the running process. Service logs display the TLS running status, feature status, and data change in real time to help you increase operations efficiency.

<span id=".5Yqf6IO95qaC6L-w"></span>
## Feature overview

After you use TLS features such as data import, TLS monitors the running status and business behavior of the feature. In addition, TLS records relevant data in the form of service logs in the TLS projects and topics. Key\-value indexes are also predefined to help you view, retrieve, and query log data to get statistics.

Service logs are applicable to product and feature operations scenarios. For example, the LogCollector service log feature is suitable for collecting host or container logs. On the LogCollector client, view the LogCollector status, troubleshoot errors in case of collection exceptions, and count the collected log data on the client.

<span id=".5rOo5oSP5LqL6aG5"></span>
## Precautions


* For all features except LogCollector, the service log feature is enabled by default. No manual configuration is needed. If LogCollector service log data is not required, manually disable the LogCollector service log feature. The expired data is deleted automatically. For more information, refer to [Enable or disable the LogCollector service log feature](https://docs.byteplus.com/docs/tls/enable_or_disable_the_service_log_feature).

* The dedicated resources of service logs cannot be modified, including projects, topics, and indexes.

* The dedicated topics of service logs store the log data generated in the TLS running process. PutLogs and other methods are not supported to write data.

* Project and topic resources generated by service logs do not consume any TLS resource quota.

## Default configurations


|Parameter |Description |
|---|---|
|Region |By default, TLS creates projects and topics in this Region. |
|Project |TLS offers a dedicated project. The basic information includes:<br><br><br>* Name: tls_service\-project<br><br>* Tag: tls\-service\-project |
|Topic |TLS offers the following dedicated topics to store various types of log data generated by features such as Torch Object Storage (TOS) log import.<br><br><br>* tls_import\-task: stores TOS data import logs and error logs.<br><br>* ls_log\-collector\-status: stores LogCollector status logs.<br><br>* tls_log\-collector\-business: stores LogCollector collection logs.<br><br>* tls_etl\-log: stores data transformation logs.<br><br>* tls_shipper\-log: stores data shipping logs.<br><br>* tls_consumergroup\-log: stores consumer group lag logs.<br><br>* tls_schedule\-sql\-log: stores scheduled SQL logs.<br><br>* tls_alarm\-log: stores alarm policy execution logs and alarm event logs. |
|Shard |Each topic supports one shard for use. By default, automatic sharding is enabled for this shard. The shard configuration cannot be modified. |
|Log storage period |Log data is retained for 7 days. The retention period cannot be changed. |
|Index |TLS enables the full\-text index and key\-value index for all collected log data. The index configuration cannot be modified. |
|Dashboard |The following dashboards are predefined:<br><br><br>* tls\-service\-etl\-dashboard: data transformation dashboard<br><br>* tls\-service\-shipper\-dashboard: data shipping dashboard<br><br>* tls\-service\-alarm\-dashboard: alarm history dashboard |
