This topic explains how to configure Feishu authorized login in the AI\-native BaaS platform Supabase version.

## Prerequisites

* A workspace using the Supabase engine is created, and its status is Running. For details on creating a workspace, refer to [Creating a workspace](https://docs.byteplus.com/en/docs/aidap/Supabase-Creating_a_workspace).

* You have logged in to the Target workspace's Supabase console. For more details on logging in to the console, refer to [Logging into Supabase console](https://docs.byteplus.com/en/docs/aidap/Supabase-Logging_in_to_the_Supabase_console).

* You have created an enterprise self\-built application on the [Feishu Open Platform](https://open.feishu.cn/) and obtained the App ID and App Secret of the application.

* You have configured the available scopes for the Feishu application according to business needs and completed application publishing.

## Precautions

* App secret is a sensitive credential; keep it secure and do not expose it in client code, public repositories, or logs.

* The OAuth callback URL generated by the Supabase console must be accurately and fully configured in the Feishu app's security settings. Inconsistencies in the protocol, domain name, path, or port will cause the callback to fail.

* If `Allow users without an enterprise email` is disabled, only Feishu users with an enterprise email can log in. Enabling this switch allows Feishu users without an enterprise email to log in as well.

## Configure Feishu app authentication through the console

### Step 1: Obtain the OAuth callback address

1. Logging in to the Supabase console.

2. Select **Authentication** \> **Sign In / Providers** in the left navigation bar.

3. Find Feishu in the Auth Providers list and open its configuration page.

4. Copy the address in the Callback URL (for OAuth) field. This field is read\-only; the system automatically generates the callback address based on the current workspace.

### Step 2: Configure Feishu app

1. Log in to the Feishu Open Platform and enter the enterprise self\-built app for login.

2. In the app’s security settings, configure the Callback URL obtained in step one as the OAuth redirect URL.

3. Confirm that the app has applied for the user identity permissions required for login and publish the app according to Feishu Open Platform requirements.

4. Copy the App ID and App Secret from the app credentials page.

> **tip**

> More details on configuring redirect URL in Feishu apps, refer to [Configure redirect URL](https://open.larkoffice.com/document/develop-web-apps/configure-redirect-urls).

### Step 3: Enable Feishu provider

1. Return to the Feishu provider configuration page in the Supabase console.

2. Turn on the Enable Feishu provider switch.

3. After modifying the following configurations, click **Save** to complete the configuration changes.

|**Dashboard configuration item name** |**Configuration item Key** |**Configuration item Value type** |**Is it required?**  |**Configuration item description** |
|---|---|---|---|---|
|Enable Feishu provider |EXTERNAL_FEISHU_ENABLED |bool |Yes |Whether to enable Feishu registration and login.<br><br><br>* `true`: enable.<br><br>* `false`: disable, default value. |
|Feishu App ID |EXTERNAL_FEISHU_CLIENT_ID |string |Yes (when enabled) |App ID of the enterprise\-built application in Feishu Open Platform. |

Set this field to the developer domain name's service callback interface as a relay address, which will redirect to the Supabase Auth callback interface.<br> |

### Set feishu app authentication via admin API

### Query configuration

```Bash
curl -X GET "$SUPABASE_BASE_URL/auth/v1/config" \
  -H "apikey: ${SERVICE_ROLE_KEY}" \
  -H "Authorization: Bearer ${SERVICE_ROLE_KEY}" \
  -H "Content-Type: application/json"
```

### Modify configuration

```Bash
curl -X PATCH "$SUPABASE_BASE_URL/auth/v1/config" \
  -H "apikey: ${SERVICE_ROLE_KEY}" \
  -H "Authorization: Bearer ${SERVICE_ROLE_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "EXTERNAL_FEISHU_ENABLED": true,
    "EXTERNAL_FEISHU_CLIENT_ID": "cli_xxxxxxxxxxxxxxxx",
    "EXTERNAL_FEISHU_SECRET": "xxxxxxxxxxxxxxxx",
    "EXTERNAL_FEISHU_REDIRECT_URI": "https://br-xxxx.supabase.aidap-global.cn-beijing.volces.com/auth/v1/callback",
    "EXTERNAL_FEISHU_EMAIL_OPTIONAL": true,
    "URI_ALLOW_LIST": "http://www.app1.com/home,https://www.app2.com"
  }'
```

## Verify configuration

1. Initiate feishu authorized login from the web page.

2. Complete login and authorization on the feishu authorization page.

3. Confirm the page can return to the application and the corresponding user is generated in the Users list of Supabase Authentication.

## FAQ

### Callback address mismatch

If a callback address is invalid or redirect_uri does not match after login, confirm that the redirect URL in the security settings of the Feishu app matches the Callback URL shown in the Supabase console exactly.

### Users without an enterprise email cannot log in

Check the `Allow users without an enterprise email` switch. If your business allows users without an enterprise email to log in, enable this switch and save the configuration again.

### The app is not available to the target users

Check the availability range and release status of the Feishu app, and confirm that the target users are included in the app’s availability range.
