After the SSL certificate is issued, you can download it from the BytePlus Certificate Center console. Once you have the certificate, you must install it on the server to enable HTTPS connections. This tutorial will guide you through installing the SSL certificate on an Internet Information Services (IIS) server.

<span id="prerequisites"></span>
## Prerequisites


* You have submitted an SSL certificate request through BytePlus Certificate Center, and the SSL certificate has been issued.

   If you have not yet submitted an SSL certificate request, please refer to [Quick start](https://docs.byteplus.com/byteplus-certificate-center/docs/get-started-with-ssl-certificate-service).

* Port 443 is open on your server.

   The default port for HTTPS communication is 443, so your server must have port 443 open to handle incoming HTTPS connection requests from clients.


<span id="environment"></span>
## Environment

This tutorial uses the following environment as an example:


* Server:

   * Operating system: Windows Server 2012 R2

   * Web service software: Internet Information Services 8

   <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">The actual configuration steps may vary depending on your server environment. In such cases, please refer to your actual environment, and use this tutorial as a reference only.   </div>
   

* Example domain: `ssl.example.com`

<span id="step-1-prepare-the-pfx-format-ssl-certificate"></span>
## Step 1: Prepare the PFX format SSL certificate

The SSL certificate that IIS server requires for installation is in PFX format. The PFX certificate file contains both the certificate and the private key. You can download the PFX certificate file from BytePlus Certificate Center only when you have both the certificate and the private key hosted in BytePlus Certificate Center. This can be done in the following cases:


* The certificate request uses the CSR automatically generated by BytePlus Certificate Center.

* The certificate request uses the CSR manually entered by you, and you provide the corresponding private key.


When you meet the above conditions, after your certificate is issued, you can download the PFX certificate. If you do not meet the above conditions, after your certificate is issued, you can download the PEM certificate, and then use tools to convert the certificate to PFX format.

For specific operations on downloading certificates, see [Downloading an SSL certificate](https://docs.byteplus.com/byteplus-certificate-center/docs/downloading-certificates).

<span id="download-the-pfx-certificate"></span>
### Download the PFX certificate

Download the certificate package that is compatible with the **IIS** server to your local computer from the BytePlus Certificate Center console.

After downloading the certificate package, extract it to your local computer. The certificate package name is `<CommonName>_iis`. Here, `<CommonName>` represents the domain name that the certificate is issued to. After extraction, you will get the following files:


* `<CommonName>.pfx`: Certificate file containing the certificate and private key.

* `keyStorePass.txt`: Certificate password file containing the certificate password.

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">Every time you download a certificate, the system generates a certificate password that matches the current certificate. The certificate password is saved in <code>keyStorePass.txt</code>.   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">Currently, you cannot specify the certificate password.   </div>
   


<span id="download-the-pem-certificate"></span>
### Download the PEM certificate

Download the certificate package that is compatible with **other** types of servers from the BytePlus Certificate Center console. After downloading the certificate package, extract it to your local computer.

The certificate package name is `<CommonName>_other`. Here, `<CommonName>` represents the domain name that the certificate is issued to. After extraction, you will get the following files:


* `<CommonName>.crt`: Certificate file.

* `<CommonName>.pem`: Certificate file (PEM encoded).


Then, you need to use the corresponding tool (such as OpenSSL, Keytool, etc.) to convert the certificate file and the private key file you keep to a PFX format certificate file.

<span id="step-2-upload-the-certificate-to-the-iis-server"></span>
## Step 2: Upload the certificate to the IIS server

To upload a certificate from a local Windows computer to an IIS server, follow these steps:


1. Press the **Win+R** key on your local computer.

2. In the **Run** window, type **mstsc** and click **OK**.

3. In the **Remote Desktop Connection** dialog box, click **Show Options**.

4. Complete the following connection settings, and then click **Connect**:

   * **General**: Enter the public IP address of the IIS server you want to connect to and the login username.

   * **Local Resources**: Click **More**, then select the disk where the certificate file is located from the **Drives** menu, and click **OK**.

5. (Optional) If the **Remote Desktop Connection** dialog box appears, click **Connect Anyway**.

6. In the **Enter your credentials** dialog box, enter the password for the server user and click **OK**.

7. (Optional) If the dialog box asking if you trust the server certificate appears, click **Connect**.

8. On the remote desktop, click the folder icon in the bottom menu bar.

9. You will see the local disk you selected in the **Devices and Drives** list. Open the disk and copy the certificate file to the remote desktop.


After uploading the certificate to the IIS server, you can proceed to the next step of the tutorial.

<span id="step-3-import-the-certificate-on-mmc"></span>
## Step 3: Import the certificate on MMC


1. On the remote desktop, open the Windows Server Control Panel MMC (Microsoft Management Console).

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">If you are not sure how to open MMC, try searching for <code>mmc</code>.   </div>
   

2. Add the Certificate Management Unit.

   1. On the top menu bar of the console, select **File \> Add/Remove Snap\-in**.

   2. In the **Add or Remove Snap\-ins** dialog box, click **Certificates** from the **Available snap\-ins** list on the left, and click **Add**.

   3. In the **Certificates snap\-in** dialog box, select **Computer account**, and click **Next**.

   4. In the **Select Computer** dialog box, select **Local computer (the computer this console is running on)** , and click **Finish**.

   5. In the **Add or Remove Snap\-ins** dialog box, click **OK**.

3. In the **Console Root** directory, expand **Certificates (Local Computer)** , right\-click **Personal**, and select **All Tasks \> Import**.

4. Follow the prompts in the wizard to complete the certificate import.

   1. **Welcome to the Certificate Import Wizard**: Click **Next**.

   2. **File to Import**: Click **Browse**, open the PFX format certificate file, and click **Next**.

      <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="2">tip      </div>
      

      <div data-tips="true" data-tips-type="tip" data-wrapper-indent="2">When opening the file, you must first set the file type to <strong>Personal Information Exchange (</strong><strong><em>.pfx;</em></strong><strong>.p12)</strong> and then select the certificate file.      </div>
      

   3. **Password**: Enter the certificate password in the **Password** text box, and click **Next**.

      <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="2">tip      </div>
      

      <div data-tips="true" data-tips-type="tip" data-wrapper-indent="2">You can get the certificate password from the downloaded <code>keystorePass.txt</code> file. If you generated the PFX certificate yourself, use the password you set when generating the certificate.      </div>
      

   4. **Certificate Store**: Select **Automatically select the certificate store based on the type of certificate**, and click **Next**.

   5. **Completing the Certificate Import Wizard**: Click **Finish**.

   6. After receiving the **Import was successful** prompt, click **OK**.


<span id="step-4-bind-the-certificate-on-iis"></span>
## Step 4: Bind the certificate on IIS

To add a website binding in IIS for a certificate that has already been imported, follow these steps:


1. Open Internet Information Services (IIS) Manager.

2. Expand the **Start Page** on the left and click on the name of the website where you want to bind the certificate.

3. On the right\-hand side, click on **Bindings** in the **Actions** navigation bar.

4. In the **Site Bindings** dialog box, click on **Add**.

5. In the **Add Site Binding** dialog box, complete the website's relevant configuration and click **OK**. The specific configuration for the website binding is as follows:

   * **Type**: Select **https**.

   * **IP Address**: Select the IP address of the server.

   * **Port**: The default is **443** and does not need to be modified.

   * **Hostname**: Enter the website domain name.

   * **SSL Certificate**: Select the imported certificate.

6. After completing the configuration, you can view the added website binding in the **Site Bindings** list.

7. Click **Close** in the **Site Bindings** dialog box.


<span id="step-5-verify-the-certificate-configuration"></span>
## Step 5: Verify the certificate configuration

To verify that the certificate is configured successfully, follow these steps:


1. Make sure that the server has opened port 443. If the server has not allowed access to port 443 due to security policies such as firewalls, modify the corresponding policies first.

2. Open a browser on the local computer and use the HTTPS format address to access the domain name: `https://ssl.example.com`. If the connection is successfully established, a lock icon will appear in the browser address bar, indicating that the connection is secure.

3. Click on the lock icon to view the connection details, which include certificate information.


<span id="optional-force-http-requests-to-https"></span>
### (Optional) Force HTTP requests to HTTPS

After enabling HTTPS communication on the website, you can use the URL rewrite tool to force HTTP requests to HTTPS requests for end\-users, ensuring that end\-users always access your web service through HTTPS.


1. Download and install the [URL Rewrite tool](https://www.iis.net/downloads/microsoft/url-rewrite) on the IIS server.

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">You can download the URL rewrite tool installation package to your local computer and then upload it to the server through a remote desktop connection.   </div>
   

   After installing the URL rewrite tool, you can see the **URL Rewrite** button in the IIS panel.

2. Add a URL rewrite rule.

   1. In the IIS panel, double\-click **URL Rewrite**.

   2. In the right\-hand action bar, click **Add Rule**.

   3. In the **Add Rule** dialog box, click **Blank Rule** in the **Inbound Rules** area, and then click **OK**.

3. Edit the inbound rule.

   1. Set a name for the new inbound rule, such as `redirect http to https`.

   2. Configure **Match URL** as follows:

      * **Requested URL**: **Matches the Pattern**

      * **Using**: **Regular Expressions**

      * **Pattern**: `(.*)`

   3. Add **Conditions** as follows:

      * **Condition Input**: `{HTTPS}`

      * **Check if input string**: **Matches the Pattern**

      * **Pattern**: `^OFF$`

   4. Configure **Action** as follows:

      * **Action Type**: **Redirect**

      * **Redirect URL**: `https://{HTTP_HOST}{REQUEST_URI}`

      * **Append query string**: Deselect

      * **Redirect type**: **Permanent (301)** 

4. In the right\-hand action bar, click **Apply**.

5. Open a browser on your local computer and access the domain name using the HTTP format: `http://ssl.example.com`.


If the address is automatically converted to the HTTPS format, it means that the HTTP request has been forced to redirect to the HTTPS request.
