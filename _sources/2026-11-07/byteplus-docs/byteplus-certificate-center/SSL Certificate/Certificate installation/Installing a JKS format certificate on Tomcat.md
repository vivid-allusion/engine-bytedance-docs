After the SSL certificate is issued, you can download the SSL certificate from the BytePlus Certificate Center console. Once you have obtained the SSL certificate, you need to install it on your server to enable HTTPS connections. This tutorial will guide you through the process of installing a JKS format SSL certificate on a Tomcat server.

<span id="background-information"></span>
## Background information

Tomcat is a popular Java\-based web server that supports multiple certificate formats for configuring SSL/TLS encryption. The certificate formats supported by Tomcat include:


* PEM (Privacy\-Enhanced Mail): This is a widely used format that stores the certificate and private key in separate text files. The certificate file usually has the `.crt` or `.pem` extension, while the private key file has the `.key` or `.pem` extension.

* PKCS12: This is a binary format that can store the certificate and private key in a single file. The file has the `.p12` or `.jks` extension. PKCS12 files are password\-protected and can be used for importing/exporting certificates and private keys.

* JKS (Java KeyStore): This is a proprietary format used by Java applications, including Tomcat. It is a binary file that can store multiple certificates and private keys. The file has the `.jks` extension and is password\-protected.


When configuring SSL/TLS on Tomcat, you can choose the appropriate certificate format to generate or manage certificates based on your needs and the tools you are using.

<span id="prerequisites"></span>
## Prerequisites


* You have submitted an SSL certificate request through BytePlus Certificate Center and the SSL certificate has been issued.

   If you have not yet submitted an SSL certificate request, please refer to [Quick start](https://docs.byteplus.com/byteplus-certificate-center/docs/get-started-with-ssl-certificate-service).

* The 8443/443 port of your server is open.

   The default port for HTTPS communication is 8443/443, so the server can only handle client\-initiated HTTPS connection requests if the 8443/443 port is open.

## Tutorial overview

This tutorial will guide you through modifying the main configuration file `server.xml` of the Tomcat server to enable listening on port 8443/443 and associating a JKS format certificate.

<span id="step-1-prepare-a-jks-format-ssl-certificate"></span>
## Step 1: Prepare a JKS format SSL certificate

A JKS format certificate file contains both the certificate and private key. You can only download a JKS format certificate file from BytePlus Certificate Center if you have both the certificate and private key hosted in BytePlus Certificate Center. There are two specific scenarios:


* The certificate request used a CSR automatically generated by BytePlus Certificate Center.

* The certificate request used a CSR manually entered by you, and you provided the corresponding private key.


If either of the above scenarios is met, you can download a JKS format certificate after your certificate is issued. If neither of the above scenarios is met, you can download a PEM format certificate after your certificate is issued and then use a tool to convert the certificate to JKS format.

For specific operations on downloading certificates, please refer to [Downloading an SSL Certificate](https://docs.byteplus.com/byteplus-certificate-center/docs/downloading-certificates).

<span id="download-a-jks-format-certificate"></span>
### Download a JKS format certificate

Download the **Tomacat (JKS format)**  certificate package to your local computer from the BytePlus Certificate Center Console. After downloading the certificate package, extract it on your local computer.

The certificate package is named `<CommonName>_jks`, where `<CommonName>` represents the domain name the certificate is issued to.

After extraction, you will get the following files:


* `<CommonName>.jks`: The certificate file that contains the certificate and private key.

* `keyStorePass.txt`: The certificate password file that contains the certificate password.

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">Each time you download a certificate, the system generates a random certificate password that matches the current certificate. The certificate password is saved in <code>keyStorePass.txt</code>.   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">Currently, you cannot specify the certificate password.   </div>
   


<span id="download-a-pem-format-certificate"></span>
### Download a PEM format certificate

Download the certificate package for **Other** types of servers from the BytePlus Certificate Center Console. After downloading the certificate package, extract it on your local computer.

The certificate package is named `<CommonName>_other`, where `<CommonName>` represents the domain name the certificate is issued to.

After extraction, you will get the following files:


* `<CommonName>.crt`: The certificate file.

* `<CommonName>.pem`: The certificate file in PEM encoding.


Then, you need to use the corresponding tools (such as OpenSSL, Keytool, etc.) to convert the certificate file and the private key file you have stored to the JKS format certificate file.

<span id="step-2-upload-the-certificate-to-the-tomcat-server"></span>
## Step 2: Upload the certificate to the Tomcat server

There are many ways to upload local files to a remote server. This tutorial uses the `scp` command as an example to demonstrate how to upload the certificate from a local Windows computer to the Tomcat server.


1. Remote login to the Tomcat server.

2. Create a folder named `cert` in the Tomcat installation directory to store the certificate.

   The Tomcat installation directory may vary depending on the version of Tomcat you are using. In this tutorial, the Tomcat installation directory is `/opt/tomcat`.

   ```Plain
   cd /opt/tomcat
   mkdir cert
   ```
   

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">You can use the <code>find / -name server.xml</code> command to find the path of the <code>server.xml</code> configuration file. This path is the Tomcat installation directory.   </div>
   

3. Open the Shell tool on your local computer.

   For example, on Windows 10, right\-click the Start icon in the lower\-left corner of the desktop, and then click **Windows PowerShell**.

4. Use the `scp` command to upload the certificate file to the server.

   ```Shell
   scp <path of the file on the local computer> root@<remote server IP>:/opt/tomcat/cert
   ```
   

   After executing the `scp` command, enter the password of the root account of the remote server as prompted.

   Example:

   ```PowerShell
   scp C:\ssl.example.com.jks root@<remote_server_IP>:/opt/tomcat/cert
   ```
   

5. Verify if the file has been uploaded successfully.

   On the Tomcat server, execute the `ll /opt/tomcat/cert` command to list the files in the `cert` directory.

   If the certificate file is listed in the file list, it means that the certificate has been uploaded successfully.


<span id="step-3-configure-the-certificate-on-tomcat"></span>
## Step 3: Configure the certificate on Tomcat

The main configuration file of the Tomcat server is `server.xml`, which is located in the `conf` directory of the Tomcat installation directory. The command you need to execute may vary depending on the installation directory of Tomcat on your server.

In this tutorial, the complete path of `server.xml` is `/opt/tomcat/conf/server.xml`.


1. Edit `server.xml`.

   ```Plain
   vim /opt/tomcat/conf/server.xml
   ```
   

2. Locate the following section:

   ```Shell
   <!-- Define an SSL/TLS HTTP/1.1 Connector on port 8443 with HTTP/2
   ……
   -->
   ```
   

3. Remove the comments for the `<Connector></Connector>` code below this section, and modify the `<Connector></Connector>` code as follows:

   ```Shell
   <Connector
       port="443"
       protocol="org.apache.coyote.http11.Http11NioProtocol"
       maxThreads="150"
       SSLEnabled="true">
   
       <SSLHostConfig>
           <Certificate
               certificateKeystoreFile="/opt/tomcat/cert/ssl.example.com.jks"
               certificateKeystorePassword="U******1"
               type="RSA"/>
       </SSLHostConfig>
   </Connector>
   ```
   

   In the above code, you need to modify the following:

   * `port`: Specifies the port for listening to HTTPS. Tomcat defaults to using port 8443, but you can use port 443.

      <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="2">tip      </div>
      

      <div data-tips="true" data-tips-type="tip" data-wrapper-indent="2">If you use port 443, you also need to modify the <code>redirectPort</code> in the <code><Connector></Connector></code> configuration for port 80 or 8080 to 443.      </div>
      

   * `certificateKeystoreFile`: Specifies the complete storage path of the certificate file on the server.

   * `certificateKeystorePassword`: Specifies the password for the certificate.

      You can obtain the certificate password from the downloaded `keystorePass.txt` file. If you generated the JKS certificate yourself, use the password you set when generating the certificate.

      The modified content is shown in the following image.

      <span>![图片](https://sf16-resources.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/upload_7af2953807f0aa94c804f298202e842c.png) </span>

4. Restart Tomcat to apply the configuration changes.

   1. Go to the `bin` directory. The `bin` directory is located in the Tomcat installation directory.

      ```Plain
      cd /opt/tomcat/bin
      ```
      

   2. Shut down Tomcat.

      ```Plain
      ./shutdown.sh
      ```
      

   3. Start Tomcat again.

      ```Plain
      ./startup.sh
      ```

<span id="optional-force-http-requests-to-redirect-to-https"></span>
## (Optional) Force HTTP requests to redirect to HTTPS

After enabling HTTPS communication for your website, you can also modify the `web.xml` configuration of Tomcat to force HTTP requests from end users to redirect to HTTPS requests, ensuring that end users always access your web service via the HTTPS protocol.

The `web.xml` file is located in the `conf` directory of the Tomcat installation directory. The command you need to execute may vary depending on the installation directory of Tomcat on your server.

In this tutorial, the complete path of `web.xml` is `/opt/tomcat/conf/web.xml`.


1. Edit the configuration file.

   ```Shell
   vim /opt/tomcat/conf/web.xml
   ```
   

2. Locate the end of the configuration file and add the following content on the line before `</web-app>`:

   ```Shell
   <security-constraint>
   <web-resource-collection>
   <web-resource-name>Entire Application</web-resource-name>
   <url-pattern>/*</url-pattern>
   </web-resource-collection>
   <user-data-constraint>
   <transport-guarantee>CONFIDENTIAL</transport-guarantee>
   </user-data-constraint>
   </security-constraint>
   ```
   

   The modified content is shown in the following image.

   <span>![图片](https://sf16-resources.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/upload_e28e9ab7ec31ad880e770b6c82c7a825.png) </span>

3. Open a browser on your local computer and access the domain in HTTP format: `http://ssl.example.com`.

   If the address is automatically converted to HTTPS format, it means that HTTP requests have been forced to redirect to HTTPS requests.
