After the SSL certificate is issued, you can download the SSL certificate from the BytePlus Certificate Center console. Once you have obtained the SSL certificate, you need to install it on your server to enable HTTPS connections. This tutorial will guide you on how to install a PFX format SSL certificate on your Tomcat server.

<span id="background-information"></span>
## Background information

Tomcat is a popular Java\-based web server that supports multiple certificate formats for configuring SSL/TLS encryption. The supported certificate formats in Tomcat include:


* PEM (Privacy\-Enhanced Mail): This is a widely used format that stores the certificate and private key in separate text files. The certificate file typically has a `.crt` or `.pem` extension, while the private key file has a `.key` or `.pem` extension.

* PKCS12: This is a binary format that can store both the certificate and private key in a single file. The file has a `.p12` or `.pfx` extension. PKCS12 files are password\-protected and can be used for importing/exporting certificates and private keys.

* JKS (Java KeyStore): This is a proprietary format used by Java applications, including Tomcat. It is a binary file that can store multiple certificates and private keys. The file has a `.jks` extension and is password\-protected.


When configuring SSL/TLS in Tomcat, you can choose the appropriate certificate format based on your requirements and the tools you are using to generate or manage the certificates.

<span id="prerequisites"></span>
## Prerequisites


* You have submitted an SSL certificate request through BytePlus Certificate Center, and the SSL certificate has been issued.

   If you have not yet submitted an SSL certificate request, please refer to [Quick start](https://docs.byteplus.com/byteplus-certificate-center/docs/get-started-with-ssl-certificate-service).

* Port 8443 or 443 of your server is open.

   The default ports for HTTPS communication are 8443 and 443, so the server needs to have port 8443 or 443 open in order to handle incoming HTTPS connection requests.

## Tutorial overview

This tutorial will guide you through modifying the main configuration file `server.xml` of Tomcat to enable listening on port 8443/443 and associating a PFX format certificate.

<span id="step-1-prepare-the-pfx-format-ssl-certificate"></span>
## Step 1: Prepare the PFX format SSL certificate

The PFX format certificate file contains both the certificate and private key. You can only download the PFX format certificate file from BytePlus Certificate Center if you have both the certificate and private key managed in BytePlus Certificate Center. There are two specific scenarios:


* The certificate request used a CSR generated by BytePluse Certificate Center.

* The certificate request used a CSR manually input by you, and you provided the corresponding private key.


If you meet the above scenarios, after your certificate is issued, you can download the PFX format certificate. If you don't meet the above scenarios, after your certificate is issued, you can download the PEM format certificate and then use a tool to convert the certificate to PFX format.

For specific instructions on downloading the certificate, please refer to [Downloading an SSL Certificate](https://docs.byteplus.com/byteplus-certificate-center/docs/downloading-certificates).

<span id="download-pfx-format-certificate"></span>
### Download PFX format certificate

Download the **Tomcat (PFX format)**  certificate package to your local computer from the BytePlus Certificate Center Console. After downloading the certificate package, extract it on your local computer.

The certificate package is named `<CommonName>_tomcat`, where `<CommonName>` represents the domain name the certificate is issued to.

After extraction, you will have the following files:


* `<CommonName>.pfx`: Certificate file containing the certificate and private key.

* `keyStorePass.txt`: Certificate password file containing the certificate password.

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">Each time you download the certificate, the system will generate a random certificate password that matches the current certificate. The certificate password is saved in <code>keyStorePass.txt</code>.   </div>
   

   * <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">Currently, specifying a certificate password is not supported.   </div>
   


<span id="download-pem-format-certificate"></span>
### Download PEM format certificate

Download the certificate package for **Other** types of servers from the BytePlus Certificate Center Console. After downloading the certificate package, extract it on your local computer.

The certificate package is named `<CommonName>_other`, where `<CommonName>` represents the domain name the certificate is issued to.

After extraction, you will have the following files:


* `<CommonName>.crt`: Certificate file.

* `<CommonName>.pem`: Certificate file (PEM encoded).


Then, you need to use the corresponding tools (such as OpenSSL, Keytool, etc.) to convert the certificate file and the private key file you have stored into a PFX format certificate file.

<span id="step-2-upload-the-certificate-to-the-tomcat-server"></span>
## Step 2: Upload the certificate to the Tomcat server

There are many ways to upload files from a local computer to a remote server. In this tutorial, we will use the `scp` command as an example to demonstrate how to upload the certificate from a local Windows computer to the Tomcat server.


1. Log in to the Tomcat server remotely.

2. In the Tomcat installation directory, create a folder named `cert` to store the certificate.

   The Tomcat installation directory may vary depending on the version of Tomcat you are using. In this example, the Tomcat installation directory is `/opt/tomcat`.

   ```Plain
   cd /opt/tomcat
   mkdir cert
   ```
   

   <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="1">tip   </div>
   

   <div data-tips="true" data-tips-type="tip" data-wrapper-indent="1">You can use the <code>find / -name server.xml</code> command to find the path of the <code>server.xml</code> configuration file. This path is the Tomcat installation directory.   </div>
   

3. Open the Shell tool on your local computer.

   For example, on Windows 10, right\-click the Start icon in the lower\-left corner of the desktop, and then click **Windows PowerShell**.

4. Use the `scp` command to upload the certificate file to the server.

   ```Shell
   scp <path of the file on the local computer> root@<remote server IP>:/opt/tomcat/cert
   ```
   

   After executing the `scp` command, enter the password of the root account of the remote server according to the command prompt.

   Example:

   ```PowerShell
   scp C:\ssl.example.com.pfx root@<remote server IP>:/opt/tomcat/cert
   ```
   

5. Verify if the file is uploaded successfully.

   On the Tomcat server, execute the `ll /opt/tomcat/cert` command to list the files in the `cert` directory.

   If the certificate file is listed in the file list, it means that the certificate has been uploaded successfully.


<span id="step-3-configure-the-certificate-on-tomcat"></span>
## Step 3: Configure the certificate on Tomcat

The main configuration file of the Tomcat server is `server.xml`, which is located in the `conf` directory of the Tomcat installation directory. The commands you need to execute may vary depending on the installation directory of Tomcat on your server.

In this tutorial, the complete path of `server.xml` is `/opt/tomcat/conf/server.xml`.


1. Edit `server.xml`.

   ```Plain
   vim /opt/tomcat/conf/server.xml
   ```
   

   Locate the following section:

   ```Shell
   <!-- Define an SSL/TLS HTTP/1.1 Connector on port 8443 with HTTP/2
   ……
   -->
   ```
   

2. Remove the comments for the `<Connector></Connector>` code below this section and modify the `<Connector></Connector>` code as follows:

   ```Shell
   <Connector
       port="443"
       protocol="org.apache.coyote.http11.Http11NioProtocol"
       maxThreads="150"
       SSLEnabled="true">
   
       <SSLHostConfig>
           <Certificate
               certificateKeystoreFile="/opt/tomcat/cert/ssl.example.com.pfx"
               certificateKeystorePassword="3******n"
               type="RSA"/>
       </SSLHostConfig>
   </Connector>
   ```
   

   In the above code, you need to modify the following:

   * `port`: The port on which to listen to HTTPS requests. Tomcat defaults to port 8443, but you can modify it to 443.

      <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="2">tip      </div>
      

      <div data-tips="true" data-tips-type="tip" data-wrapper-indent="2">If you use port 443, you also need to modify the <code>redirectPort</code> in the <code><Connector></Connector></code> configuration for port 80 or 8080 to 443.      </div>
      

   * `certificateKeystoreFile`: The complete storage path of the certificate file on the server.

   * `certificateKeystorePassword`: The password of the certificate.

      <div data-tips="true" data-tips-type="tip" data-tips-is-title="true" data-wrapper-indent="2">tip      </div>
      

      <div data-tips="true" data-tips-type="tip" data-wrapper-indent="2">You can obtain the certificate password from the downloaded <code>keystorePass.txt</code> file. If you generated the PFX certificate yourself, use the password you set when generating the certificate.      </div>
      

   The modified content is shown in the following figure.

   <span>![图片](https://sf16-resources.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/upload_8c6bd17b7a5384ed9a4a20312ade988f.png) </span>

3. Restart Tomcat to apply the configuration changes.

   1. Go to the `bin` directory. The `bin` directory is located in the Tomcat installation directory.

      ```Plain
      cd /opt/tomcat/bin
      ```
      

   2. Shut down Tomcat.

      ```Plain
      ./shutdown.sh
      ```
      

   3. Start Tomcat again.

      ```Plain
      ./startup.sh
      ```

<span id="optional-force-http-requests-to-redirect-to-https"></span>
## (Optional) Force HTTP requests to redirect to HTTPS

After enabling HTTPS communication for your website, you can also modify the `web.xml` configuration of Tomcat to force HTTP requests from end users to redirect to HTTPS requests, ensuring that end users always access your web service via the HTTPS protocol.

The `web.xml` file is located in the `conf` directory of the Tomcat installation directory. The commands you need to execute may vary depending on the installation directory of Tomcat on your server.

In this tutorial, the complete path of `web.xml` is `/opt/tomcat/conf/web.xml`.


1. Edit the configuration file.

   ```Shell
   vim /opt/tomcat/conf/web.xml
   ```
   

2. Locate the end of the configuration file and add the following content on the line before `</web-app>`:

   ```Shell
   <security-constraint>
   <web-resource-collection>
   <web-resource-name>Entire Application</web-resource-name>
   <url-pattern>/*</url-pattern>
   </web-resource-collection>
   <user-data-constraint>
   <transport-guarantee>CONFIDENTIAL</transport-guarantee>
   </user-data-constraint>
   </security-constraint>
   ```
   


The modified content is shown in the following figure.

<span>![图片](https://sf16-resources.bytepluscdn.com/obj/byteplus-public-aiso/cloud-universal-doc/upload_4823a665c2a511bbc5c77fb2ecbd6129.png) </span>

3. Open a browser on your local computer and access the domain name in HTTP format: `http://ssl.example.com`.

If the address is automatically converted to HTTPS format, it means that HTTP requests have been forced to redirect to HTTPS requests.
