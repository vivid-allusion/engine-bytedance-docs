This topic explains how to share the Classic Load Balancer (CLB) service within a cloud VPC with an on\-premises IDC using the PrivateLink service.

## Scenarios

PrivateLink enables the sharing of service resources within a VPC to other VPCs via a private network, ensuring business security and helping to reduce costs. By leveraging PrivateLink in conjunction with Cloud Enterprise Network (CEN), Virtual Private Network (VPN) connection, or Transit Router, the CLB service resources within a VPC can be shared with an on\-premises data center.

This topic describes how to share the CLB service resources within a VPC for use by an on\-premises data center. The specific network scenario is illustrated in the figure below.

## Prerequisites

* The VPCs vpc\-01 and vpc\-02 have been created. For detailed actions, see [Building an IPv4 Virtual Private Cloud](https://docs.byteplus.com/en/docs/vpc/Building-an-IPv4-VPC).

* The required Elastic Compute Service (ECS) instances have been created and backend server configurations have been completed. For detailed actions, see [Purchasing an ECS instance](https://docs.byteplus.com/en/docs/ecs/Using-the-wizard-to-buy-ECS-instances) and [Configuring backend service](https://docs.byteplus.com/en/docs/clb/Creating-an-HTTP-static-page#.5q2l6aqk5LqM77ya5pCt5bu65ZCO56uv5pyN5Yqh).

* The security group of the Elastic Compute Service (ECS) ecs\-01 has been configured to allow access from the IDC network segment and the relevant business ports.

* The CLB service configuration has been completed. For detailed operations, see [Classic Load Balancer Getting Started](https://docs.byteplus.com/en/docs/clb/Layer-4-CLB-01).

* The IP address of the on\-premises IDC server has been obtained, and it has been confirmed that this server is operational and available.

## Configuration procedures

1. [Create endpoint service](https://docs.byteplus.com/en/docs/privatelink/Sharing-CLB-in-a-VPC-with-a-data-center#.5q2l6aqk5LiA77ya5Yib5bu657uI56uv6IqC54K55pyN5Yqh): Create an endpoint service, which acts as the instance carrier for the shared CLB resources.

2. [Create interface endpoint](https://docs.byteplus.com/en/docs/privatelink/Sharing-CLB-in-a-VPC-with-a-data-center#.5q2l6aqk5LqM77ya5Yib5bu65o6l5Y-j57uI56uv6IqC54K5): Create an endpoint, which serves as the access point for the on\-premises IDC to access the shared cloud service resources.

3. [Connect VPC and on-premises IDC](https://docs.byteplus.com/en/docs/privatelink/Sharing-CLB-in-a-VPC-with-a-data-center#.5q2l6aqk5LiJ77ya6L-e6YCaVlBD5LiO5LqR5LiLSURD): Use VPN Connection, Direct Connect with CEN, or Direct Connect with Transit Router to establish connectivity between the VPC (where the endpoint resides) and the on\-premises IDC.

4. [Verification](https://docs.byteplus.com/en/docs/privatelink/Sharing-CLB-in-a-VPC-with-a-data-center#.5q2l6aqk5Zub77ya57uT5p6c6aqM6K-B): Use the `ping` command to target the private IP address of the ECS instance ecs\-01 to verify that the on\-premises IDC can communicate with vpc\-01; Use the `curl` command to access the PrivateLink endpoint domain name to verify that the on\-premises IDC can successfully access the shared service resource via PrivateLink.

## Configuration procedures

### Step 1: Create endpoint service

1. Log in to the [Endpoint Service console](https://console.byteplus.com/pl/endpointServices) using account A.

   > **tip**

   > If cross\-service role authorization has not been performed, please complete the authorization first according to the prompts on the page.

2. In the top menu bar, select the target project and region.

3. Click **Create Endpoint Service** and see the table below to configure the relevant parameters.

   |Parameter |Value |
   |---|---|
   |**Basic information** ||
   |Regions |China (Guangzhou) |
   |Name |Automatically generated by the system. No manual entry is required.​​ |
   |IP address type |IPv4 |
   |**Service Resource** ||
   |Topic |Classic Load Balancer (CLB) |
   |Service Resource |Select clb\-01 |
   |**Advanced option** ||
   |Auto accept connection |Yes |

4. Click **Create** to complete the creation of the endpoint service.

5. In the endpoint service list, click the ID of the target endpoint service. On the details page, view and record its name, as it will be required when [Creating endpoint](https://docs.byteplus.com/en/docs/privatelink/Sharing-CLB-in-a-VPC-with-a-data-center#.5q2l6aqk5LqM77ya5Yib5bu65o6l5Y-j57uI56uv6IqC54K5). In this example, we use com.volces.privatelink.cn\-guangzhou.epsvc\-2fe630gurkl37k5gfuy33\*\*\*\*.

### Step 2: Create interface endpoint

1. In the left\-side navigation tree, click **Endpoint**.

   > **tip**

   > If cross\-service role authorization has not been performed, please complete the authorization first according to the prompts on the page.

2. On the **Interface Endpoint** tab, click **Create Endpoint**, and configure the relevant parameters as per the table below.

   |Parameter |Value |
   |---|---|
   |**Basic information** ||
   |Regions |China (Guangzhou) |
   |Name |endpoint\-01 |
   |Topic |Interface |
   |**Endpoint service resources** ||
   |Add method |Add by Service Name |
   |Endpoint Service |com.volces.privatelink.cn\-guangzhou.epsvc\-2fe630gurkl37k5gfuy33\*\*\*\* |
   |**Network Configuration** ||
   |VPC |vpc\-01 |
   |IP address type |IPv4 |
   |AZs and Subnets |Availability Zone A, subnet\-01 \| Auto\-assign IP, 192.168.1.0/24 |
   |Security group |Default\-sg<br><br>> **tip**<br><br><br>> PrivateLink health check requests originate from the private IP range `100.64.0.0/10`. Ensure that the security group(s) associated with the endpoint network interface allows traffic from `100.64.0.0/10`. Otherwise, the health status of the endpoint network interface may become abnormal.<br> |

3. Click **Buy now**. Follow the console guidance to review and accept the Legal.

4. Click **Agree and buy** to complete the action.

5. Click **Go to console** to view and record the domain name of the created endpoint instance, which will be needed during [Verification](https://docs.byteplus.com/en/docs/privatelink/Sharing-CLB-in-a-VPC-with-a-data-center#.5q2l6aqk5Zub77ya57uT5p6c6aqM6K-B).

### Step 3: Establish connectivity between VPC and on\-premises IDC

Depending on the service used to connect the VPC and the on\-premises IDC, refer to the corresponding documentation to establish connectivity between VPC vpc\-01 and the local data center.

* **Direct Connect and Cloud Enterprise Network**: Refer to [DC Quick Start](https://docs.byteplus.com/en/docs/directconnect/Accessing-a-Direct-Connect-connection).

* **Virtual Private Network (VPN)** : Please refer to [Setting up interconnection between a VPC and multiple data center networks](https://docs.byteplus.com/en/docs/vpn/Connecting-a-virtual-private-cloud-to-multiple-data-centers).

* **Direct Connect and Transit Router**: Please refer to [Realizing independent interconnection between different VPCs and IDCs with Direct Connect](https://docs.byteplus.com/en/docs/transitrouter/Best-Practices-02).

### Step 4: Result verification

1. ​Log in to a server within your on\-premises IDC.​​

2. Execute the `ping` command targeting the private IP address of ECS ecs\-01.

   A successful ping reply indicates that the network between the local IDC and vpc\-01 is successfully established.

3. Execute the command `curl http://Endpoint Domain:CLB listening port` to verify whether the PrivateLink service is available.

   If the result returns the service deployment page of the backend server, it confirms that the server in the on\-premises IDC can access the CLB resources in vpc\-02, and the PrivateLink service is functioning correctly.
