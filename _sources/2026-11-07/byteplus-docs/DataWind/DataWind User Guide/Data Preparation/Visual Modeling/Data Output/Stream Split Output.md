# 1. Overview

In the visual modeling module of Intelligent Data Insight, the output operator category supports the real\-time stream split output operator. With the stream split operator, users can directly process a single real\-time stream into multiple output streams. During the splitting process, rules are configured so that real\-time streams meeting the specified conditions are routed to the corresponding substream for output. The stream split operator can be connected directly to data cleansing or output operators, or it can run independently. When running independently, it outputs to a built\-in Topic for system consumption. A single real\-time stream can be split into multiple streams based on event behavior or application AppID. Only one Flink task is initiated during this process, making it an operator capability that efficiently utilizes computing resources.

# 2. Feature introduction

<span id="_2-1-添加分流输出算子"></span>
## 2.1 Add a stream split output operator

In a visual modeling task, click the add operator button to see "Stream split output" under the output operator category, then click to select it. Feature notes are as follows:

(1) Input restrictions: read nodes and data cleansing nodes.

(2) Output restrictions: as the final operator, it cannot connect to downstream operators.

<span id="_2-2-配置分流输出算子"></span>
## 2.2 Configure the stream split output operator

With the stream split operator, a single real\-time stream can be directly processed into multiple output streams. During the splitting process, rules are configured so that real\-time streams meeting the specified conditions are routed to the corresponding substream for output. The output is provided as a dataset, and you can set the dataset lifecycle as needed to avoid duplicate data storage.

After selecting and adding the stream split output operator, you can configure each split in detail, as well as add or delete split configurations. Caution: There is a split limit—currently, up to 10 splits are supported. The specific configuration is as follows:

(1) Create a new output dataset. You can also edit dimension metrics.

(2) Configure filtering conditions: Build AND/OR relationships using field conditions to output data that meets the criteria. Click "AND" or "OR" in the logic tree to switch between AND/OR relationships.

(3) You can click Add Routing to continue creating and configuring.

(4) Click the Delete button in the upper right corner to delete.

**Notes**

(1) Routing configuration restrictions: After adding, it must not be left empty. If it is empty, you will be prompted with "There are empty configuration items" when saving.

(2) Output dataset:

a. Naming rules: Only English letters, numbers, and underscores are allowed. Spaces and other special characters are not permitted. The maximum length is 50 characters, and names must be unique.

b. Add switch configuration (or reuse offline switch): Supports editing kafka topic/CK database name and table name. After enabling, you can customize the database name, table name, and topic name.

c. When the switch is off, it is recommended to add a prefix to topics generated by routing to facilitate identification.
