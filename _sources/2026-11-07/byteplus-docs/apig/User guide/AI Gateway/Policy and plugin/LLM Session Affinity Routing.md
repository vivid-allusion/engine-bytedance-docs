LLM Session affinity routing supports model inference scenarios.It enables requests with the same Session id in multi\-turn conversations to be forwarded to the same instance, while requests with different Session ids are distributed as evenly as possible. This article introduces how to configure LLM Session affinity routing.

<span id="JBPznl4p"></span>
## Background Information

The API gateway supports session persistence based on stateful sessions, allowing requests with specific headers or cookies to be forwarded to designated instances to achieve session affinity routing. For details, refer to [Official documentation](https://www.envoyproxy.io/docs/envoy/latest/configuration/http/http_filters/stateful_session_filter).

The technical principles of Session affinity routing:


* Upon first access, the API gateway selects the backend service instance with the fewest requests based on the load balancing algorithm.

* The response message for the first access will additionally carry a header generated by the API gateway, such as `x-upstream-session-id:xxxx`.

* In subsequent requests, the request message must carry the `x-upstream-session-id:xxxx` information.

* The API gateway forwards requests to the corresponding backend Service based on the `x-upstream-session-id:xxxx` information in the request message, enabling session affinity routing.

## Prerequisites


* An APIG instance has been created. For details, refer to [Create an instance](https://docs.byteplus.com/en/docs/apig/Creating_an_instance).

* APIG instances have been upgraded to version 3.3.0 or above. For details, refer to [Version Management](https://docs.byteplus.com/en/docs/apig/Version_Management).

* The Service has been created. For details, refer to [Create service](https://docs.byteplus.com/en/docs/apig/Creating_a_service#.5Yib5bu65pyN5Yqh).

* The route has been created. For details, refer to [Creating a route](https://docs.byteplus.com/en/docs/apig/Creating_a_route).


<span id="ocRY0FFx"></span>
## Limit


* The same Plugin can only be bound once to the same resource.

* Within the same route, the LLM load\-aware routing Plugin, the LLM session affinity routing Plugin, and the MCP session persistence Plugin are mutually exclusive and cannot be enabled at the same time.


<span id="KESoeOVT"></span>
## Procedure


1. Log in to the [API Gateway console](https://console.byteplus.com/veapig).

2. In the left navigation bar, select **Plugin management \> ** **LLM Session Affinity Routing Plugin**, click **Create Plugin**, and configure Plugin parameters.

   
   |**Parameter** |Description |
   |---|---|
   |Effective level |Select the effective level for the LLM Session Affinity Routing Plugin. Currently, only **Routing level** is supported. |
   |Instance |Select the APIG instance for the Plugin from the dropdown menu. |
   |Service |In the Plugin dropdown menu, select the associated service. |
   |owning route |In the dropdown menu, select the Plugin, then select its associated route. |
   |Notes/comments |You can choose whether to edit the notes/comments based on your business needs, for example, to include the purpose of the Plugin or other relevant details, which will help with future identification. |
   

3. Click **OK** to complete the configuration.

## Result validation

<span id="WFpqUETN"></span>
### View configuration

After configuration is complete, in the Plugin list, view the configured Plugins. If the Plugin status is **enabled**, the Plugin is now effective.

<span id="glZ0vARk"></span>
### Access verification

When your client carries the correct `x-upstream-session-id:xxxx` information when accessing, it can reach the correct backend service, enabling session affinity routing.
