[Apache Celeborn](https://celeborn.apache.org/) is a unified intermediate data service for big data computing engines. It supports decoupling intermediate data such as shuffle and spilled data generated by the engine from the engine itself to external media storage, and provides read, write, and management services for these data, thereby truly eliminating the dependency of compute nodes on large\-capacity disks.

<span id="_1-组件说明"></span>
## 1 Component Note

<span>![图片](https://portal.volccdn.com/obj/volcfe/cloud-universal-doc/upload_52b527055ec6fba33e7676c2bdba7293.png) </span>

The Celeborn architecture, as shown in the figure above, is divided into three types of components: Master, Worker, and Client:


* **Master**: Cluster management node, provides cluster state management and resource allocation capabilities, and supports HA deployment based on the Raft protocol.

* **Worker**: Cluster worker node, primarily provides storage, read, write, and management capabilities for shuffle data. It also offers cluster flow control, health checks, and graceful degradation features.

* **Client**: Cluster access client. Big data engines interact with the Celeborn cluster through the Client to read and write shuffle data. The Client also provides lifecycle management capabilities for application shuffle data.


In the deployment topology, EMR deploys Celeborn Master nodes on the master node group, Worker nodes on the core node group, and provides corresponding Celeborn Client out\-of\-the\-box support for big data engines according to their versions. Additionally, for EMR clusters with HA enabled, Celeborn is deployed in HA mode by default, that is, Celeborn Master nodes are deployed on all nodes in the master node group.
