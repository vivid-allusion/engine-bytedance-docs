After the previous chapters, you should now have a basic understanding of Primus. Therefore, this chapter will mainly share some more advanced ways to use Primus.

<span id="1"></span>
## 1. Create a local Python virtual environment

Since TensorFlow itself is a Python application, preparing a Python virtual environment is very important. Therefore, in the [Basic usage](https://docs.byteplus.com/docs/E-MapReduce/109529) chapter, we demonstrated how to create a Python virtual environment on the primary node of the EMR DataScience cluster via the public network.

However, in daily use, you may not be able to create a Python virtual environment on the primary node of the EMR DataScience cluster for various reasons. Therefore, this section shares a method for creating a Python virtual environment locally using a docker container. The example will create a Python virtual environment with TOS dependencies.

```bash
# [HOST] Start a continer with a shared directory (any directory will do)
#NOTE: Have to start docker deamon first on host machine.
$ mkdir shared
$ docker run --rm -it --name python-3.9.9 --mount type=bind,source="$(pwd)"/shared,target=/mnt python:3.9.9 bash

# [Container] Install the needed toolings
$ apt-get update
$ apt-get install python3-venv

# [Container] Create venv and install needed packages
$ cd /mnt
$ /usr/bin/python3.9 -m venv venv # Important! have to use the python with the exact path on EMR machines
$ source venv/bin/activate

$ pip install --upgrade pip
$ pip install 'tensorflow==2.7.0'
$ pip install 'tensorflow-io==0.24.0'

$ git clone https://github.com/volcengine/ve-tos-python-sdk # TOS dependencies, follows https://www.volcengine.com/docs/6349/93479
$ cd ve-tos-python-sdk
$ python3 setup.py install
$ cd ..

$ deactivate

# [Container] Package the venv
$ tar -zcf venv.tar.gz venv

# [Container] Quit the container
$ exit

# [Host] Locate the venv.tar.gz
$ ls shared
ve-tos-python-sdk
venv
venv.tar.gz # Upload to /home/yarn/primus-playground/examples/tos
```

## 2. TOS integration

Object storage TOS (Tinder Object Storage) is one of the main storage options for Volcano Engine EMR. Compared to the previous example running on HDFS, TOS allows the EMR DataScience cluster to exchange data more directly with other EMR clusters. Therefore, the integration of EMR DataScience and TOS is very important. This chapter also provides an example as a reference for real\-world use.

<span id="_2-1-准备工作"></span>
### 2.1 Preparation

<span id="_2-1-1-python-虚拟环境"></span>
#### 2.1.1 Python virtual environment

First, you need to create a Python virtual environment that supports TOS. For detailed steps, please refer to: [1. Create a local Python virtual environment](https://docs.byteplus.com/docs/E-MapReduce/109528#1).

<span id="_2-1-2-训练资料"></span>
#### 2.1.2 Training data

As with the HDFS\-based example, you need to prepare data on TOS.


1. Upload `<PrimusExamples>/shared/mnist/data` to TOS (`/examples/mnist`)

2. Create `/examples/mnist/models/` to store the models generated by the example


<span id="_2-1-3-训练资源"></span>
#### 2.1.3 Training resources

As shown in the following list, you need to upload the previously created Python virtual environment with TOS dependencies and extract it for use by subsequent model validation scripts. At the same time, you must modify the training scripts (main.py and evaluate.py) to specify the relevant TOS information.

```bash
~/primus-playground/examples
 |...
 |-- shared
 |   |...
 |   `-- venv.tos        # Create a new directory
 |       |-- venv        # untar from -zxf venv.tar.gz
 |       `-- venv.tar.gz # upload the venv.tar.gz generated in the previous step
 `-- tos
     |-- evaluate.py
     |-- main.py # manual modification needed!
     |-- main.sh # manual modification needed!
     |-- mnist.py
     `-- primus_config.json
```


```python
#!/usr/bin/env python3
...
AK = <CUSTOMIZED_VALUES>
SK = <CUSTOMIZED_VALUES> REGION = <CUSTOMIZED_VALUES> ENDPOINT = <CUSTOMIZED_VALUES>
BUCKET = <CUSTOMIZED_VALUES>
...
```

### 2.2 Start training

Similar to the HDFS\-based example, the example also submits the training task via primus\-submit, and finally uses another Python script to validate the output model. The only difference is that both the training data and the output model are stored on TOS.

```bash
# Change to yarn user
$ su --shell=/bin/bash - yarn

# Submit a Primus application
$ cd ~/primus-playground
$ primus-submit --primus_conf examples/tos/primus_config.json
```
