The one\-click real\-time full database synchronization solution of DataSail supports integrated full and incremental synchronization. It first synchronizes and migrates all MySQL data, and then synchronizes incremental data in real time to the target StarRocks database.

You can also choose to perform real\-time incremental data synchronization only. This scenario is suitable when all data has already been synchronized to StarRocks by other means. This article describes how to create a one\-click real\-time synchronization task for StarRocks.

<span id="_1-前置操作"></span>
## **1 Prerequisites**


1. The DataLeap project has been activated and created. All full and incremental tasks created will be synchronized under this project. For details, see [Creating a project](https://www.volcengine.com/docs/6260/144941).

2. A dedicated data integration resource group with appropriate resource specifications has been created and bound to the successfully created DataLeap project. For purchase operations, see [Resource group management](https://www.volcengine.com/docs/6260/71656). For project binding operations, see [Data integration resource group](https://www.volcengine.com/docs/6260/65366).

3. The DataSail (global data integration) product has been enabled. For details, see [Service activation](https://www.volcengine.com/docs/6984/486135).

4. Preparation of the data source and target has been completed, with the source MySQL instance created and the target Volcano Engine E\-MapReduce (EMR) StarRocks cluster set up. For details, see [Create MySQL instance](https://www.volcengine.com/docs/6313/74512) and [Create clusters (version 3.18.0 and earlier)](https://docs.byteplus.com/docs/E-MapReduce/105456) .


<span id="_2-方案关键步骤概述"></span>
## **2 Overview of key solution steps**


1. Target table creation: Source table data is written into the target table. Target table creation can be done in the following two ways:

   1. Existing table: In the target database environment, a table with the same name as the source table has already been manually created to receive data. In this case, the table creation process will be skipped during solution execution.

   2. Automatic table creation: In the target database environment, if there is no target table with the same name as the source data table, the solution will automatically create a target table with the same name during execution.

2. Incremental real\-time task position initialization: When started for the first time, the initial position for the incremental streaming task will be automatically specified.

3. Task creation: The real\-time full database synchronization solution for MySQL_to_StarRocks will create the following two types of tasks:

   1. One\-time full batch task creation: During full synchronization, the one\-time full batch task will synchronize historical full data to the target StarRocks table.

   2. Incremental streaming task creation: After the full batch task has been completed, incremental data will be synchronized in real time to the target StarRocks table by initiating a streaming task.


<div data-tips="true" data-tips-type="tip" data-tips-is-title="true">tip</div>


<div data-tips="true" data-tips-type="tip">The number of one\-time full batch tasks generated by the synchronization solution depends on the number of source tables set in the solution.</div>


<span id="_3-注意事项"></span>
## **3 Important notes**


1. The synchronization solution currently supports selecting up to 1,000 tables, but it is recommended to start with fewer than 100 tables for trial use.

2. Currently, the target StarRocks database must be created in the cluster in advance; automatic creation within the solution is not supported at this time.

3. When selecting existing tables as the method for table creation, ensure that the schema names and counts of the target and source tables are consistent.

4. Currently, real\-time multi\-table synchronization only supports cases where the source and target table names are exactly the same.

5. When synchronizing data to StarRocks using the solution, only writing to non\-partitioned tables is supported; writing data to partitioned tables is not supported at this time.

## **4 Data synchronization solution**

<span id="_4-1-数据源配置"></span>
### **4.1 Data source configuration**

Before configuring the real\-time full\-database synchronization solution, you need to configure the corresponding data sources for the MySQL source and StarRocks target in the **Data Source Management** interface. For details, see [MySQL data source configuration](https://www.volcengine.com/docs/6260/126105) and [StarRocks data source configuration](https://www.volcengine.com/docs/6260/1119920).
