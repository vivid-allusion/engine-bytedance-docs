This document primarily introduces the best practices for using PyProton. It covers tips related to usability and performance, as well as special notes regarding stability and robustness.

<span id="6e1d4343"></span>
## Usability section

<span id="ff9ee796"></span>
### Obtaining and setting access credentials

To access TOS with PyProton, TOS authentication is required. Currently, two authentication types are supported: Assume Role and Access Key ID/Secret Access Key (AK/SK). For detailed information about these credentials, refer to: [Assume Role acquisition documentation](https://www.volcengine.com/docs/6723/133859) and [Access Key (key) management](https://www.volcengine.com/docs/6291/65568). After obtaining these credentials, PyProton supports two methods for setting them: environment variables and code configuration. It is recommended to use environment variables. The following example demonstrates how to initialize `ProtonFileSystem` using AK/SK:

```Python
from pyproton.protonfs import (
    ProtonFileSystem
)

fs = ProtonFileSystem(
    endpoint_url="http://tos-cn-beijing.volces.com",
    key="",            # access key id (ak)
    secret="",         # secret access key (sk)
    session_token="",  # 参考assume role的指引文档获取"SessionToken"
)
fs.ls("tos://bucket/to/path/", detail=False)
```


<span id="a7744130"></span>
### Note on logs

Overall, the logs visible to users in PyProton are the result of logs from both PyProton and the Proton SDK being aggregated in one place. The following explains each in detail:


* PyProton logs: Generated by PyProton itself through Python code.

* Proton SDK logs: Generated by the Proton SDK using the log4j logging framework via Java code. Currently, the relevant log configuration is not open for external adjustment.


Although the output methods for these two types of logs differ, they share some commonalities:


* Both are aggregated to the console by default.

* The log level for both can be controlled uniformly via a single environment variable. For details, see the next section "Log level setting."


<span id="a85df822"></span>
### Log level setting

PyProton supports setting its own and the built\-in Proton SDK log level via an environment variable named `PROTONFS_LOGGING_LEVEL`. By default, if the user does not set this environment variable, PyProton uses the `INFO` level. When users need to debug issues, they can explicitly set it to `DEBUG`. The environment variable can be set in two ways:


* Directly in the OS shell: `export PROTONFS_LOGGING_LEVEL='DEBUG'` to take effect.

* Indirectly in the compute engine, with Ray as the most common example.

   Method one:

   ```Python
   import ray
   
   runtime_env = {"env_vars": {"PROTONFS_LOGGING_LEVEL": "DEBUG"}}
   
   ray.init(runtime_env=runtime_env)
   
   @ray.remote
   def f():
     # user business
   
   print(ray.get(f.remote()))
   ```
   

   Method two:

   ```Python
   import ray
   from ray.runtime_env import RuntimeEnv
   
   runtime_env = RuntimeEnv(env_vars={"PROTONFS_LOGGING_LEVEL": "DEBUG"})
   
   ray.init(runtime_env=runtime_env)
   
   @ray.remote
   def f():
     # user business
   
   print(ray.get(f.remote()))
   ```

### JVM memory tuning

Since PyProton by default calls the Proton SDK interface, launching the JVM is unavoidable. The main tuning parameters for the JVM are the maximum (`Xmx`) and minimum (`Xms`) memory thresholds. PyProton has already set a batch of JVM parameters for Proton that have been proven stable in production practice. Specifically, the default value of `Xms` is `64m`, and the default value of `Xmx` is `2g`. In most cases, users do not need to make additional adjustments. However, in extreme scenarios, you can configure the `PYPROTON_JVM_XMX` environment variable to adjust the `Xmx` parameter of the Proton SDK. For configuration instructions, refer to the "Log Level settings" section above.

## Performance optimization

<span id="fa7e6169"></span>
### ls API

When calling the ls API, to retrieve only the list of files or folders under a path, explicitly set the detail parameter to `False` (the default value is `True`) to improve performance. Usage example:

```Python
from pyproton.protonfs import (
    ProtonFileSystem
)

fs = ProtonFileSystem(
    endpoint_url="http://tos-cn-beijing.volces.com",
    key="",
    secret="",
    session_token="",
)
fs.ls("tos://bucket/to/path/", detail=False)
```


Note: To align with the semantics of the `fsspec#ls` API, when calling the ls API, if `detail=True` and the resource type is "directory", an additional request will be made to obtain the total storage usage of all resources under that directory.

<span id="699c124f"></span>
### rm API

When calling the rm API, for optimal deletion performance, do not explicitly specify the `maxdepth` parameter or override its default value (the default value is `None`). Usage example:

```Python
from pyproton.protonfs import (
    ProtonFileSystem
)

fs = ProtonFileSystem(
    endpoint_url="http://tos-cn-beijing.volces.com",
    key="",
    secret="",
    session_token="",
)

# 是否需要将recursive设置为True，取决于是否需要递归删除子目录
fs.rm("tos://bucket/to/path/", recursive=True)
```


Note: If the user explicitly sets `maxdepth`, the internal call will fall back to the default implementation of `fsspec#rm`: expanding and walking (listing) the path. For scenarios involving the deletion of massive numbers of files, this may result in extremely long deletion times and out of memory (OOM) in the Proton SDK.

If maxdepth is not explicitly specified, a more efficient batch delete method will be used by default. This optimization for deleting massive numbers of files significantly improves both stability and performance.

### File Operation: read/write API

<span id="30233029"></span>
#### write API

For write optimization of a single large file (such as files at the GB level), the following practices help reduce write time, increase throughput, and improve stability:


* **Split into chunks and batch multiple writes**: It is recommended to set chunk_size to "5MB" to match the default buffer size of fsspec, which can prevent memory fragmentation and improve memory utilization. This also prevents stability issues caused by accumulating large amounts of data at once and resulting in OOM. Please refer to the following sample code:

   ```Python
   from pyproton.protonfs import (
       ProtonFileSystem
   )
   
   fs = ProtonFileSystem(
       endpoint_url="http://tos-cn-beijing.volces.com",
       key="",
       secret="",
       session_token="",
   )
   
   def write_in_chunks(file_object, content, chunk_size):
       for i in range(0, len(content), chunk_size):
           file_object.write(content[i : i + chunk_size])
   
   
   def write_via_pyproton(dest_folder, size_of_byte_per_file, file_name, content, chunk_size=0):
       full_file_path = f"{dest_folder}/{file_name}"
       if chunk_size != 0:
           with fs.open(full_file_path, "wb", block_size=chunk_size) as f:
               write_in_chunks(f, content, chunk_size)
       else:
           with fs.open(full_file_path, "wb") as f:
               f.write(content)
       assert fs.exists(full_file_path), f"File {full_file_path} does not exist."
   ```
   

* Optimize Proton parameters to leverage the write advantages of multi\-disk Staging MPU during write operations, thereby improving write performance (reducing write latency). For detailed parameter descriptions, please refer to the official Proton documentation[[1]](https://docs.byteplus.com/docs/E-MapReduce/109404). The following example demonstrates how to configure these optimizations (note that all configuration values only support string types; if the value is a number, please enclose it in `""`):

   ```Python
   from pyproton.protonfs import (
       ProtonFileSystem
   )
   
   fs = ProtonFileSystem(
       endpoint_url="http://tos-cn-beijing.volces.com",
       key="",
       secret="",
       session_token="",
       # proton sdk支持的参数设置
       config_dict = {
           # other args...
           "fs.tos.multipart.staging-dir": "",
           "fs.tos.multipart.size": "",
           "fs.tos.multipart.thread-pool-size": "",
           "fs.tos.multipart.staging-buffer-size": "",
           "fs.tos.multipart.threshold": "",
           "fs.tos.task.thread-pool-size": "",
       }
   )
   ```
   


<span id="1e511d1f"></span>
#### read API

For optimizing the reading of a single large binary file (such as GB\-level files), the following best practices can help reduce read latency, and improve throughput and stability:


* **Split into chunks and batch multiple reads**: It is recommended to set chunk_size to "5MB" to prevent stability issues caused by out\-of\-memory (OOM) errors when reading large amounts of data at once. Please refer to the following sample code:

   ```Python
   from pyproton.protonfs import (
       ProtonFileSystem
   )
   
   fs = ProtonFileSystem(
       endpoint_url="http://tos-cn-beijing.volces.com",
       key="",
       secret="",
       session_token="",
   )
   
   def read_from_chunks(file_handle, chunk_size=0):
       total_bytes_read = 0
       if chunk_size == 0:
           total_bytes_read = len(file_handle.read(-1))
       else:
           while True:
               data_chunk = file_handle.read(chunk_size)
               bytes_read = len(data_chunk)
               if not data_chunk:
                   break  # End of file reached
               total_bytes_read += bytes_read
   
       return total_bytes_read
       
   def read_via_pyproton(full_file_path, size_in_bytes, chunk_size=0):
       with fs.open(full_file_path, "rb") as f:
           assert read_from_chunks(f, chunk_size) == size_in_bytes
   ```
   

* For text files with explicit line breaks and well\-formed formatting, it is recommended to use the `readline` or `readlines` API.

## Stability

<span id="fa5c7ac3"></span>
### About connection stability

Users can be assured that when performing read and write operations with PyProton, there is no need to worry about connection stability issues. When using PyProton, users often follow patterns such as "processing while reading" or "processing while writing". The processing time may be long or short, and even if the processing takes a very long time, users do not need to worry about connection interruptions causing read or write exceptions. This is because Proton has built\-in logic for connection reconstruction, connection recovery, resumable uploads, and resumable reads. These stability optimizations are transparent to users.
